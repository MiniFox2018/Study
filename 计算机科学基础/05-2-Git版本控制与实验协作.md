# Git 版本控制与实验协作

先修：能够创建文件并在项目目录运行终端命令。软件工程主线见[生产级软件工程](./05-生产级软件工程.md)。本章让实验可以恢复、比较和协作，而不是把 Git 当“上传按钮”。

## 1. 四个位置与三种差异

| 位置 | 内容 | 主要检查 |
|---|---|---|
| 工作区 | 当前正在编辑的文件 | `git diff` 看未暂存变化 |
| 暂存区/索引 | 这次准备提交的快照 | `git diff --cached` |
| 本地提交历史 | 已提交的树和父关系 | `git log`、`git show` |
| 远端引用 | 服务器上的历史及本地缓存引用 | `git fetch`、分支追踪状态 |

`git add file` 暂存该文件当时的版本。之后继续编辑，新的变化不自动进入暂存区。`git commit` 创建本地提交，不会自动上传；`git push` 上传引用所需的提交和对象，不代表远端已经部署或验证。

Git 提交通常表示项目快照；底层会复用未变的对象，不是每次完整复制全部字节。分支是可移动的提交引用，不是另建一份文件夹。`HEAD` 表示当前检出的状态，通常指向当前分支。

## 2. 在新练习目录做第一个提交

以下只用于你新建的练习仓库，不对 Study 历史做实验：

```bash
mkdir git-lab
cd git-lab
git init -b main
git config user.name '练习者'
git config user.email 'learner@example.invalid'
printf 'learning_rate=0.01\n' > config.txt
git status --short
git add config.txt
git diff --cached
git commit -m '建立学习率基线'
```

配置是此仓库局部设置；已有仓库不要为了练习修改全局身份。提交前看暂存差异，确保只含本次想保留的内容。

再改 `config.txt` 为0.02，只执行 `git diff`；你看到工作区修改，历史仍保留0.01。执行 add/commit 后，历史才新增这个状态。

## 3. 分支、快进与合并图

```bash
git switch -c experiment/lr
printf 'learning_rate=0.02\n' > config.txt
git add config.txt
git commit -m '尝试更大学习率'
git switch main
git merge --ff-only experiment/lr
git log --oneline --graph --all
```

若 main 没有独立新增提交，它可沿原父链快进到实验提交，无需合并提交。若两个分支都前进，一般合并可能创建有两个父提交的新提交，或者需要处理冲突。源图的分叉→双父合并只是其中一种情况，不是每次 merge 都必然发生。

分支隔离版本状态，不隔离所有外部副作用：训练脚本仍可能改同一数据库或输出目录。实验数据和运行目录也要明确分开。

## 4. 远端、fork、fetch 与 pull

`origin` 是一个约定名称，不是 GitHub 固定关键字。先用 `git remote -v` 核对它指向谁。没有源仓库写权限时可在服务上 fork，再 clone 自己的仓库；本地分支不会自动授予上游权限。

```bash
git fetch origin
git log --oneline main..origin/main
git diff main..origin/main
git merge --ff-only origin/main
```

fetch 获取历史并更新远端追踪引用，不直接合并当前工作区。pull 通常包含 fetch 后再合并或rebase，其行为受参数和配置影响；不能只把它记成“下载文件”。快进失败时读分叉历史，保留双方提交，不能通过强制覆盖来假装同步成功。

提交代码前检查：工作区是否有自己的未提交内容、暂存区是否混入他人变化、远端是否更新、修改是否经过对应验证。协作 PR 说明问题、最终行为、测试与限制。

## 5. 模型和数据为什么不随便进普通 Git

```gitignore
.venv/
__pycache__/
.env
models/
checkpoints/
```

依据项目需要选择规则；不能把所有 `.csv` 都忽略，因为小型教学输入可能正是复现所需。模型通常可重新获取，但自采集数据、特定训练 checkpoint 未必可重新生成，仍需明确备份与版本策略。

`.gitignore` 只影响未跟踪文件，已入历史的文件不会自动删除。LFS/DVC 的指针也不包含实际对象，细节见[数据版本管理](../数据科学基础/12-数据版本缓存与流式处理.md)。

## 6. 从历史找回信息

```bash
git log --oneline -- config.txt
git show HEAD:config.txt
git diff HEAD~1 HEAD -- config.txt
```

比较配置和数据/模型版本，才能解释“指标为何变化”；一个提交中同时改五种因素，无法可靠归因。每个实验至少记录代码提交、数据版本、参数、输入、环境和结果。

未提交的编辑不在提交历史里。恢复文件、切分支、reset 等会影响当前内容，先看 status 和差异；本文不要求通过丢弃真实工作来学习命令。

## 7. 自查与实践

1. add 后又修改文件，直接 commit 包含哪个版本？答案：暂存时版本；看工作区与暂存区两份diff。
2. push 成功是否意味着训练结果正确？答案：只说明远端接收了相关对象/引用，结果仍要验证。
3. 创建分支是否复制一整套项目？答案：分支引用和历史结构被新增，当前工作区按检出状态呈现。
4. 在新练习仓库比较0.01和0.02配置，画父关系，说明为何这次是快进而不是双父合并；改为两个分支都编辑同一行，先预测冲突，再在练习仓库解决并读差异。
