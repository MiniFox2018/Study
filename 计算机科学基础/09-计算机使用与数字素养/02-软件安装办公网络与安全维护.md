# 02｜软件安装、办公网络与安全维护

## 1. 安装软件前先回答三个问题

不要先点“下载”。先问：

1. 这是不是我要的软件？
2. 下载来源能否确认？
3. 安装包在改变系统什么？

优先级通常应是：官方网站 / 官方应用商店 / 官方代码仓库发布页 → 可信软件仓库 → 其他第三方站点。

第三方下载站最常见风险之一，是页面用多个巨大按钮把广告下载器、捆绑器伪装成真正下载入口。

## 2. 常见安装介质

Windows 软件常见形式：

- .exe 安装器；
- .msi 安装包；
- 商店应用；
- .zip/.7z 解压即用的便携版；
- .iso 镜像中的安装程序。

“便携版”不代表一定更安全；“安装版”也不等于一定臃肿。要看来源和行为。

安装时重点关注：

- 是否捆绑其他软件；
- 是否修改首页、搜索引擎或文件关联；
- 安装范围是当前用户还是全系统；
- 安装位置是否有必要自定义；
- 是否要求管理员权限；
- 是否增加开机自启、服务、驱动或浏览器扩展。

## 3. 安装路径：不要形成机械规则

旧教程常把“软件全部装 D 盘”当作优化手段，这并不普适。

更合理的原则：

- 系统和软件可放系统盘，只要容量规划合理；
- 大型游戏、素材库、模型、缓存等大体积数据可放大容量盘；
- 不要随意移动程序目录；
- 不要为了省 C 盘把软件装到桌面或杂乱目录；
- 对开发环境，路径过长、特殊字符、权限边界可能影响工具，应按项目官方要求选择。

## 4. 正版、自由软件与破解

应区分商业软件、免费软件、开源/自由软件与破解软件。

“开源”不等于“免费用于任何场景”，许可证才是规则。破解软件同时带来授权、供应链和恶意代码风险。

## 5. 卸载不是删除文件夹

正规卸载过程除了删除主程序，还可能移除服务、驱动、开始菜单项、文件关联、注册信息和升级组件。

因此优先使用系统“已安装应用”或软件自身卸载器。删除桌面快捷方式只删除入口；手工删除安装目录可能留下大量系统配置。

## 6. UAC 与管理员权限

Windows 的管理员用户平时仍应以普通权限运行大多数程序，需要高权限操作时再通过 UAC 提权。

看到 UAC 弹窗时不要形成“条件反射式点是”。至少检查：

- 发起程序是谁；
- 文件来自哪里；
- 发布者是否可信；
- 这个动作为什么需要管理员权限。

最小权限原则：能不用管理员权限完成的任务，就不要以管理员身份运行。

## 7. 安全软件与系统更新

安全软件的核心能力通常包括实时恶意软件检测、下载/执行扫描、防篡改、网络与信誉判断、隔离和恢复。

不要同时堆很多实时杀毒工具，它们可能互相冲突、重复扫描并显著影响性能。

系统和常用软件更新的重要价值是修复漏洞和兼容性问题。个人设备一般不应长期停留在已失去安全支持的版本。

## 8. 远离恶意软件：重点是行为习惯

高风险信号包括：

- 来源不明的破解器、外挂、激活工具；
- 诱导关闭杀毒软件；
- 要求关闭系统更新或证书检查；
- 邮件/群聊突然发来的可执行文件；
- 双重扩展名或伪装图标；
- “验证码”“对账单”“发票”附件要求启用宏；
- 远程控制工具被陌生人诱导安装；
- 索要短信验证码、恢复码、私钥或远程桌面权限。

安全不是靠一个软件解决，而是来源可信、最小权限、及时更新、备份和身份保护共同完成。

## 9. 电信诈骗的技术共同点

诈骗话术不断变，但常见技术路径相对稳定：

1. 建立权威感或紧迫感；
2. 让你离开正常平台；
3. 诱导打开链接、安装软件或共享屏幕；
4. 获取身份信息、支付授权、验证码或设备控制权；
5. 制造“必须立即执行”的时间压力。

遇到钱、验证码、账户异常和远程协助请求，应通过已知官方渠道重新验证，不使用对方提供的联系电话或链接。

## 10. Office / WPS：学习“文档格式和协作”，不是背版本史

办公套件的长期概念包括文字处理、表格、演示、本地文件与云协作、格式兼容、模板、样式、公式与自动化。

常见 OOXML 格式有 .docx、.xlsx、.pptx。

不同办公套件之间通常兼容，但复杂排版、字体、宏、插件、公式和脚本可能出现差异。

提交正式材料时：

- 使用对方指定格式；
- 保留可编辑源文件；
- 对版式要求高时同时导出 PDF；
- 打开导出结果重新检查。

## 11. 浏览器：理解内核、配置文件和权限

现代浏览器承担 DNS/HTTP(S) 通信、HTML/CSS/JavaScript 执行、沙箱、Cookie/Storage、密码与同步、网站权限以及扩展程序。

选择浏览器时比品牌故事更重要的是安全更新、扩展生态、隐私设置、跨设备需求和企业兼容性。

不要安装来源不明的浏览器扩展，它拥有的网页读取权限可能比普通软件更敏感。

## 12. 电子邮件：地址、域名和钓鱼

电子邮件地址形式为 local-part@domain。

域名往往比显示名称更能帮助识别发件来源，但“看起来像官方域名”也不能完全证明邮件可信。

处理可疑邮件：

- 不急着点链接；
- 核对真正发件域名；
- 悬停查看链接目标；
- 对付款、账号、附件要求用其他渠道验证；
- 不把“通过某种技术校验”误解为“邮件内容一定真实”。

邮件附件属于文件，仍遵循下载与执行的全部安全原则。

## 13. 即时通信：方便不等于适合长期归档

聊天工具适合高频沟通，但存在搜索差异、撤回/过期、群文件生命周期、平台锁定、设备迁移和权限变化。

重要项目资料不应只存在聊天记录中，应进入明确的文档、代码仓库、项目存储或档案系统。

## 14. 压缩格式和工具

常见格式：

- ZIP：兼容性最好；
- 7z：通常压缩率较好；
- RAR：生态中常见，但创建能力受专有格式/工具约束；
- tar：Unix/Linux 常见的归档容器，常与 gzip/xz/zstd 组合。

选择压缩工具重点看格式支持、安全更新、广告/捆绑、加密、大文件/分卷、命令行自动化和许可证。

来源不明压缩包存在路径穿越、压缩炸弹等风险，不要自动解压到重要目录。

## 15. 无损压缩为什么能变小

无损压缩依赖“数据中存在可预测和重复结构”。

常见思想包括：

- Dictionary/LZ：把重复字符串替换成“之前出现过的位置和长度”；
- Run-length encoding：连续重复值改成“值 + 次数”；
- Entropy coding：让高频符号使用更短编码，低频符号使用更长编码，例如 Huffman 思路。

因此：

- 纯文本、日志、未压缩位图通常更容易压；
- JPEG、MP4、ZIP 等已经高度压缩的数据，再压一次收益往往很小；
- 加密后的密文接近随机分布，通常也很难再压缩。

实际流程若同时需要压缩和加密，通常先压缩再加密，但必须使用成熟协议和工具，而不是自己拼接密码学步骤。

## 16. 工具软件：用“任务”而不是“榜单”管理

PDF 推荐了文本编辑、PDF 阅读、媒体播放、下载、磁盘分析、文件搜索和 PowerToys 等工具。具体软件会变化，长期策略是：

先写任务 → 看系统自带工具能否完成 → 选长期维护、来源可信、权限合理的工具 → 定期淘汰不用的软件。

典型任务类别包括纯文本编辑、PDF 阅读、媒体播放、下载任务、磁盘空间分析、本地文件快速搜索，以及批量改名、颜色取样、窗口管理等效率工具。

## 17. 最小练习

1. 选一个软件，找到其官方主页、官方安装包和数字签名信息。
2. 查看电脑上三个自启动软件，解释是否需要它们。
3. 选择一个 Office 文档导出为 PDF，检查分页、字体和图片。
4. 检查浏览器扩展权限，删掉一个不再需要的扩展。
5. 制作 ZIP 和 7z 归档，比较大小和兼容性，而不是只看压缩率。
