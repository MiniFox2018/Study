# 09｜程序、算法与机器执行

## 1. 程序像“菜谱”，但执行者不是人

程序可以先理解为一系列明确步骤。

假设做番茄炒蛋：

1. 洗番茄；
2. 打鸡蛋；
3. 切番茄；
4. 热锅加油；
5. 炒鸡蛋；
6. 炒番茄；
7. 合并调味。

人可以理解“炒到断生”这类模糊语言，机器不行。机器需要更精确、有限、可编码的基本动作。

因此编程的第一层能力就是：

> 把大任务拆成机器能够执行的小步骤。

## 2. 顺序、分支与循环

大量程序都能由三类控制结构组成。

### 顺序

A → B → C

前一步完成后做下一步。

### 分支

如果条件成立做 A，否则做 B。

例如：

如果余额 ≥ 价格 → 扣款  
否则 → 提示余额不足

### 循环

重复某个步骤，直到满足条件。

例如遍历文件夹中的每个文件，检查扩展名。

“重复代码很多次”通常提示你应该考虑循环、函数或更高层抽象。

## 3. 编程语言是给人写的

高级语言让人能用变量、函数、对象、类型和控制结构描述任务。

但 CPU 不直接理解 Python、C++ 或 Java。

最终需要把程序变成目标处理器指令集可以执行的形式。

## 4. 指令与机器码

CPU 支持一组有限的基本操作，例如：

- 从内存读数据；
- 写内存；
- 加减、位运算；
- 比较；
- 跳转；
- 调用/返回；
- SIMD/向量运算。

每条机器指令有二进制编码。

一段程序在机器层面可看成：

指令 1  
指令 2  
指令 3  
……

“机器码”就是这些指令及其相关数据的二进制表示。

## 5. CPU 的基本执行循环

简化模型：

内存中的指令 → Fetch 取指 → Decode 译码 → Execute 执行 → 更新状态 → 下一条指令

现代 CPU 还会加入流水线、乱序执行、分支预测、缓存等机制，但理解 fetch/decode/execute 已经足够建立第一层模型。

## 6. 为什么程序存硬盘，却要进内存才能运行

磁盘负责持久保存程序文件。

启动程序时，操作系统的 loader 会把可执行文件需要的部分映射到进程虚拟地址空间，并准备：

- 代码；
- 数据；
- 动态库；
- 栈；
- 堆；
- 入口点。

CPU 随后从内存地址空间取指执行。

注意：现代系统不一定一次性把整个可执行文件完整复制进 RAM，分页和内存映射会按需装入。

## 7. ISA：软件与处理器的契约

Instruction Set Architecture 规定：

- 有哪些指令；
- 寄存器；
- 指令编码；
- 数据类型；
- 地址方式；
- 异常/特权机制等。

常见 ISA 包括 x86-64、Arm、RISC-V 等。

这解释了为什么：

- 同一个 Windows x86-64 程序不能天然在任意架构 CPU 上直接跑；
- 软件发布时会区分 x64、Arm64；
- 虚拟机/模拟器有时需要翻译指令。

ISA 与具体 CPU 微架构不是同一个概念：很多不同型号 CPU 可以实现同一 ISA。

## 8. 编译器

编译器把一种程序表示转换为另一种表示，常见目标是机器码或中间表示。

典型 AOT 流程：

源代码 → 词法/语法分析 → 中间表示 → 优化 → 目标代码 → 链接 → 可执行文件

编译器能做：

- 类型检查；
- 常量折叠；
- 消除无用代码；
- 循环优化；
- 向量化；
- 寄存器分配。

所以“源码写法差不多”不代表最终机器码完全一样。

## 9. 解释器、字节码与 JIT

“编译型/解释型语言”只是入门近似。

现实常混合多种策略。

### CPython

Python 源码通常先被编译为 bytecode，再由 Python 虚拟机执行。

### Java/.NET

源代码先变成中间字节码/IL，运行时再解释或 JIT 编译为本机代码。

### JavaScript

现代引擎也会解释、分析热点并 JIT 优化。

因此更准确的问题是：

> 这个语言实现使用了怎样的执行管线？

## 10. 编译器自举

编译器本身也是程序。

早期编译器可以用机器码或其他语言写。等编译器足够成熟后，就可以用目标语言编写新版编译器，再由旧版编译新版。

这叫 bootstrap / self-hosting。

它说明“谁编译编译器”并不是逻辑悖论，而是一个逐步建立工具链的过程。

## 11. 可执行文件不是“只有机器码”

现代可执行文件还可能包含：

- 节/段；
- 导入表；
- 符号；
- 重定位信息；
- 资源；
- 调试信息；
- 数字签名相关结构。

操作系统 loader 读取这些结构，建立进程运行环境。

所以把 .exe 简化成“机器码文件”适合入门，但并不完整。

## 12. 算法是什么

算法是解决一类问题的明确步骤。

同一个任务可以有很多算法。

例如在 100 万个已排序数字里找目标：

- 从头逐个找：最坏约 1,000,000 次比较；
- 二分查找：约 20 次比较。

这是 O(n) 与 O(log n) 的数量级差异。

但二分查找有前提：

- 数据有序；
- 能高效访问中间位置。

如果为了只查一次而先把无序数据排序，排序成本也必须计入。

## 13. 算法、程序和实现的区别

可以用三层理解：

问题：我要解决什么？  
算法：用什么步骤解决？  
程序：怎样把步骤表达成可执行软件？  
实现：具体语言、数据结构、库和系统接口是什么？

“会 Python 语法”不等于“会设计算法”。

反过来，理解算法也不意味着能写出健壮的生产程序；还要处理输入校验、异常、并发、I/O、测试和安全。

## 14. 一个最小性能实验

任务：计算 1 到 n 的和。

方法 A：循环累加，做 n 次左右加法。

方法 B：使用公式：

n(n+1)/2

两者都正确，但计算量不同。

当 n 很大时，公式仍是常数级计算。

这个例子说明：

> 优化首先应该考虑“是否有更好的算法”，而不是只想“换更快 CPU”。

## 15. 学习编程的正确顺序

1. 先会把任务拆成输入、处理、输出；
2. 掌握变量、分支、循环、函数；
3. 学会数据结构；
4. 学会测试和调试；
5. 学会复杂度；
6. 再补操作系统、编译、网络、并发；
7. 通过真实小项目把它们串起来。

不要一开始就追求框架数量。

## 17. 最小练习

1. 选一个日常任务，写成顺序/分支/循环结构。
2. 解释“程序在 SSD 里，为什么 CPU 不能直接从 SSD 一条条执行”。
3. 查自己电脑 CPU 架构，并找一个软件的 x64/Arm64 下载选项。
4. 用两种算法解决一个小问题，比较输入规模增大时的操作次数。
5. 用自己的话解释编译器、解释器、JIT 的区别，不能只说“一个快一个慢”。
