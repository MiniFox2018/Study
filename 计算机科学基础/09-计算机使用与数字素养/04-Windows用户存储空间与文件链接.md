# 04｜Windows 用户、存储空间与文件链接

## 1. “用户”是安全与数据隔离边界

操作系统中的用户不是单纯的头像和名字。

它关联用户配置目录、文件所有权与访问控制、应用设置、凭据、注册表用户配置、云同步、加密密钥和登录方式。

多人共用一台电脑时，应使用独立用户，而不是共享同一个桌面和密码。

## 2. 标准权限、管理员和提权

现代 Windows 使用 UAC，把“账户属于 Administrators 组”和“当前进程已高权限运行”分开。

因此日常程序以普通权限运行，必要时显式提权。不要长期使用内置高权限 Administrator 作为日常账户。

## 2.1 SID：系统真正识别的身份标识

Windows 给安全主体分配 SID（Security Identifier）。

文件 ACL 等权限记录依赖 SID，而不是只看用户名字符串。这解释了：

- 改“显示名称”不等于创建了新身份；
- 删除用户再创建同名用户，SID 仍可能不同；
- 某些旧文件会显示未知 SID，是因为原账户已不存在。

用户名适合人阅读，SID 更接近系统内部的身份主键。

## 3. 本地账户与在线账户

本地账户的身份主要存在设备本身；Microsoft 账户可以与云服务、同步、商店和恢复机制结合。

选择时考虑跨设备同步、OneDrive/商店、组织策略、隐私偏好和恢复方式。

账户显示名、登录邮箱和 C:\Users\ 下的配置目录名并不是同一个概念。

## 4. 设备加密和恢复密钥

设备加密/BitLocker 的核心价值是：设备丢失时，即使攻击者拆下磁盘，也不能直接读取数据。

但加密会带来恢复责任。必须明确：

- 恢复密钥保存在何处；
- 组织设备是否由公司托管；
- 更换主板、固件配置或某些启动设置时可能触发恢复；
- 没有恢复密钥时，数据可能无法找回。

不要把唯一恢复密钥只放在被加密的同一台设备中。

## 5. 不要随意重命名用户配置目录

直接把 C:\Users\Alice 改名，可能破坏软件硬编码路径、注册表记录、环境变量、服务、同步程序和开发工具。

若只是想改显示名称，应优先改账户显示名。

若确实要迁移配置目录，更稳妥的策略通常是：

新建目标用户名用户 → 迁移个人数据 → 逐步验证应用 → 最后删除旧用户。

比“离线改目录 + 改注册表 + 建符号链接”更容易回滚。

## 6. C 盘为什么会自己变满

常见来源：

- Windows 本体与组件存储；
- 更新缓存；
- 用户配置目录；
- Downloads/Desktop/Documents；
- AppData 中应用缓存；
- 浏览器和聊天软件缓存；
- 开发环境；
- Docker/WSL/虚拟机；
- 页面文件；
- 休眠文件；
- 临时文件；
- 崩溃 dump。

排查空间时先测量，不要直接删。

## 7. 页面文件与休眠文件

页面文件用于虚拟内存机制的一部分。即使物理内存很多，系统和应用仍可能依赖页面文件的存在和容量策略。

不要因为看到 pagefile.sys 很大就机械禁用。

hiberfil.sys 与休眠、快速启动等功能相关。是否禁用应基于是否使用这些功能和系统当前机制，不应为了几 GB 空间盲目删除系统文件。

## 8. 清理空间的安全顺序

推荐：

1. 系统“存储/临时文件”；
2. Downloads；
3. 回收站；
4. 聊天/浏览器/应用缓存；
5. 不再使用的软件；
6. 大型项目、游戏、模型、虚拟机；
7. 重复文件；
8. 再考虑高级系统项。

不推荐手工删除 Windows、Program Files、WinSxS，使用来路不明的注册表清理，看到大文件就删，或为省空间破坏恢复分区。

## 9. 用磁盘分析工具“先找最大的”

空间排查的第一性原则是：先知道容量去哪了，再决定清理方法。

可以使用系统存储分析或可信的树图/目录统计工具，按目录大小逐层定位。

## 9.1 已知文件夹迁移

Desktop、Documents、Pictures、Downloads 等“已知文件夹”可能位于用户配置目录，也可能被 OneDrive 等同步软件重定向。

如果要迁移，应优先使用 Windows/应用提供的正式位置迁移机制，而不是手工剪切整个用户目录。

迁移前检查：

- 云同步是否正在接管；
- 目标卷是否长期可用；
- 路径权限；
- 应用是否写死旧路径；
- 是否已经有备份。

## 10. 符号链接

符号链接保存目标路径，语义类似：

link → target

特点：

- 删除链接通常不删除目标；
- 删除目标后链接可能悬空；
- 对多数应用透明；
- 权限与网络访问有额外语义。

它适合兼容旧路径、开发环境、把大目录迁到其他位置等，但不应成为掩盖混乱目录的默认手段。

## 11. 硬链接

硬链接不是“指向另一个文件名”，而是多个目录项引用同一文件数据对象。

因此：

- 修改任一名字看到的内容都会变化；
- 只有最后一个硬链接删除后数据才真正失去该目录引用；
- 通常不能跨文件系统/卷；
- 对目录的硬链接通常受限制或不允许。

这解释了为什么“文件看起来有两个，但实际上只存一份数据”。

## 12. 目录联接 Junction

Windows 的 junction 是面向目录的重解析点，常用于把一个目录位置映射到另一个目录。

它与目录符号链接很像，但历史、解析和网络语义不同。

对普通用户，只在明确知道程序路径兼容需求时使用；创建前备份并记录目标；删除时确认删的是链接还是实际目标。

## 13. Windows 11 “修整”为什么不固化

原 PDF 第 18 章包含任务栏、旧右键菜单、旧资源管理器、F1 行为等修改。

这些属于高度版本相关的 UI/注册表技巧。Windows 更新后键值可能失效，Explorer 行为可能变化，第三方 patch 可能导致崩溃。

长期方法是：

1. 先使用系统公开设置；
2. 再使用维护活跃、可回滚的工具；
3. 修改注册表前导出相关项；
4. 记录改动；
5. 大版本更新后重新验证。

## 14. 最小练习

1. 找出当前用户配置目录，并解释它与账户显示名是否相同。
2. 查看系统盘最大的 10 个目录，不删除任何东西，先分类。
3. 创建一个普通测试文件和一个符号链接，验证删除链接不删除目标。
4. 解释硬链接为何不能用“快捷方式”模型完全理解。
5. 确认设备加密恢复密钥不是只有单一副本。
