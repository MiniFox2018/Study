# 06｜密码学、身份与网络信任

## 1. 先分清安全目标

密码学不是只有“把东西变乱码”。

常见目标：

- Confidentiality：机密性，别人看不到；
- Integrity：完整性，内容没被篡改；
- Authentication：认证，对方是谁；
- Accountability：在适用协议中提供可验证责任证据；
- Key establishment：安全建立共享秘密。

不同工具解决不同目标。

## 2. 古典替换密码为什么不安全

凯撒、单表替换等古典密码的核心是字符替换。

它们容易被频率分析、已知明文和穷举破解。

它们适合理解“密钥决定变换”，不适合现代安全。

## 3. 对称加密

对称密码使用同一个秘密密钥，或双方共享的等价秘密，完成加密/解密。

优势是速度快、适合大量数据。难点是双方如何安全得到同一密钥。

现代常用核心算法是 AES。AES 分组为 128 bit，常见密钥长度 128/192/256 bit。

重要纠正：AES S-box 的代数构造并不意味着“AES 被数学证明绝对安全”。工程安全来自公开分析、密钥长度、算法设计、实现质量和正确使用模式共同作用。

## 4. 分组模式与 AEAD

不能只说“我用了 AES”就认为安全。

错误模式或 nonce 使用会破坏安全。

现代应用优先使用经过验证的 AEAD 构造，例如 AES-GCM 或 ChaCha20-Poly1305，它们同时提供加密与完整性认证。

nonce/IV 的唯一性规则必须严格遵守。不要自己设计加密模式。

## 5. DES / 3DES 的历史意义

DES 曾是重要标准，但 56-bit 密钥已不足以抵抗现代穷举。

3DES 通过重复 DES 延长安全寿命，但性能差且安全余量不足，现代新系统不应继续采用。

理解它们用于学习密码学演进，不用于新项目选型。

## 6. 非对称密码

非对称密码使用密钥对：

- 公钥可以公开；
- 私钥必须保密。

公钥加密可以用于“别人用你的公钥加密，你用私钥解密”。

现实协议通常不会用 RSA 等直接加密整段大文件，而是先用公钥机制建立或保护会话密钥，再用高速对称密码加密大量数据。这就是混合加密。

## 7. 单向函数与陷门函数

密码学利用“正向容易、反向困难”的数学问题构建安全原语。

RSA 与整数分解相关；现代椭圆曲线体系基于不同困难问题。

不要把“某个数学问题目前很难”理解为“永远不可破”，密码安全还依赖参数长度、实现、随机数和侧信道。

## 8. 哈希函数

哈希把任意长度输入映射为固定长度摘要。

密码学哈希希望具有：

- preimage resistance；
- second-preimage resistance；
- collision resistance。

常见用途包括文件完整性、内容寻址、数字签名中的摘要，以及构建 MAC/KDF 等。

普通哈希不能直接证明“文件来自谁”。

## 9. 密码不能直接用快速哈希保存

用户密码存储需要：

- 每个用户独立 salt；
- 专门的 password hashing / KDF；
- 高计算或内存成本；
- 可升级参数。

例如 Argon2id、scrypt、bcrypt、PBKDF2 等由具体平台和标准决定。

不要存明文密码，也不要直接 SHA-256(password)。

## 10. MAC：有共享密钥的完整性认证

Message Authentication Code 使用共享秘密验证消息未被篡改且来自持有密钥的一方。

HMAC 是常见构造。

MAC 与数字签名不同：MAC 双方共享秘密，签名使用私钥生成、公钥验证。

## 11. 数字签名

签名解决的核心问题是：

拿到消息和公钥的人，可以验证该签名是否由对应私钥生成，以及消息是否被改动。

不要把“私钥加密、公钥解密”当作所有数字签名算法的准确数学描述；签名是独立密码学原语。

## 12. 证书和 PKI

最大的现实问题是：“这个公钥到底是不是 example.com 的？”

数字证书把身份信息、公钥、有效期、用途等绑定在一起，并由证书颁发机构签名。

浏览器/系统维护信任根，通过证书链把站点证书追溯到受信任根。

证书不是“网站绝对可信”的证明，它主要证明当前连接使用的公钥与该域名的身份绑定经过相应 PKI 验证。

## 13. HTTPS / TLS 在做什么

TLS 连接大致解决：

- 验证服务器身份；
- 协商会话密钥；
- 对后续通信加密；
- 验证数据完整性。

HTTPS 可以防止网络路径上的被动窃听和大多数中间人篡改，但不能阻止：

- 你自己访问诈骗网站；
- 服务器本身被入侵；
- 浏览器扩展窃取页面；
- 终端感染恶意软件。

“小锁图标”不是内容真实性认证。

## 14. 多元化安全：Defense in Depth

安全应分层：

- 账号：强密码、密码管理器、MFA；
- 设备：补丁、磁盘加密、锁屏；
- 应用：最小权限、可信来源；
- 网络：TLS、防火墙、网络隔离；
- 数据：备份、访问控制、加密；
- 人：识别社工、钓鱼；
- 恢复：恢复码、离线备份、应急流程。

如果攻击者已经控制终端，传输加密也保护不了屏幕上已经解密的数据。

## 15. 最小练习

1. 下载一个公开文件，计算 SHA-256，再修改一个字节比较结果。
2. 打开浏览器证书查看器，找到域名、颁发者、有效期和公钥算法。
3. 解释“HTTPS 网站也可能是诈骗网站”的原因。
4. 解释为什么加密大量文件通常使用对称密码，而非全部用 RSA。
5. 给密码存储写一条安全规则：salt + 专用 KDF，而不是快速哈希。
