# 01｜电脑、文件与显示基础

## 1. 先建立一张“电脑在做什么”的图

一台个人电脑可以先粗略理解成：

输入设备 → CPU / GPU 计算 → RAM 临时承载 → SSD/HDD 长期存储 → 显示器/扬声器等输出

操作系统位于应用和硬件之间，负责进程、文件、设备、权限和界面。应用一般不直接操纵硬件，而是调用操作系统提供的接口。

这张图很重要，因为以后排障时，“慢”“卡”“打不开”“没空间”“画面掉帧”分别可能来自不同层。

## 2. bit、Byte 与容量单位

最小的二进制信息单位是 bit，取值 0 或 1。8 bit 通常组成 1 Byte（字节）。

需要区分两套容量前缀：

- 十进制：1 kB = 1000 B，1 MB = 1000² B，1 GB = 1000³ B；
- 二进制：1 KiB = 1024 B，1 MiB = 1024² B，1 GiB = 1024³ B。

硬盘厂商通常按十进制标称容量；有些操作系统界面历史上按 1024 换算却仍显示 GB 标签，所以“1 TB 硬盘为什么系统里看起来更小”首先是单位口径问题，不代表容量凭空丢失。

网络带宽常用 bit/s，而文件大小常用 Byte；100 Mb/s 理论上不是 100 MB/s，而约为 12.5 MB/s，实际还要扣协议开销。

## 3. 重启为什么不总等于“关机再开机”

在启用 Fast Startup 等机制的 Windows 上，关机可能保存部分系统会话状态，而“重启”通常会更完整地重新加载系统内核与驱动。

因此排查驱动、更新、系统状态问题时，明确选择“重启”比“关机后再按电源键”更可靠。

“睡眠”“休眠”“关机”“重启”是不同的电源状态，不应混为一谈。

## 4. F1～F12 与 Fn 键

笔记本常把 F1～F12 与音量、亮度、飞行模式等硬件功能复用。到底直接按 F5 得到“F5”还是亮度键，取决于厂商设置和 Fn Lock。

遇到快捷键无效时，应先检查：

- 是否需要同时按 Fn；
- 是否启用了 Fn Lock；
- BIOS/厂商控制软件是否改变了功能键模式。

## 5. Settings 与 Control Panel

Windows 的现代设置正在逐步集中到 Settings，但部分传统管理项仍可能通过 Control Panel、MMC 或专用系统工具呈现。

长期原则：优先使用系统公开的现代设置入口；只有在功能尚未迁移或需要高级管理时，再进入传统工具。不要把某一版本的菜单路径当成永久知识。

## 6. CPU：执行指令，不等于“核越多就一定越快”

CPU 的核心职责是取指令、译码、执行并读写数据。

看 CPU 时至少区分：

- 架构与指令集，例如 x86-64、Arm；
- 核心数与线程数，影响可并行工作量；
- 单核性能，很多交互和串行任务仍受它影响；
- 频率、缓存、功耗与散热，共同决定持续性能；
- 工作负载，不同软件对核心数、缓存、向量指令的利用完全不同。

因此“i7 一定比 i5 快”“八核一定比四核快”都不是可脱离代际、功耗和任务成立的结论。

## 7. RAM：工作台，不是长期仓库

RAM 用来保存正在运行程序所需的代码与数据。它速度快、容量相对有限、断电后内容消失。

内存不足时，操作系统会频繁回收、换页或压缩内存，体感可能表现为切应用变慢、大量磁盘活动、浏览器标签重载、大型程序卡顿甚至退出。

容量是否够用取决于任务集合，不应把 PDF 中 2024 年的 8/16/32 GB 建议当作永久购买标准。

## 8. SSD/HDD：长期存储

长期文件、应用、系统本身都存储在非易失介质上。

- SSD 随机访问延迟低，日常启动程序和系统响应通常明显更快；
- HDD 机械结构导致随机访问慢，但大容量冷数据场景仍可能有成本优势；
- 二者都不是永久档案介质，都需要备份；
- “盘符”不是物理硬盘本身，一个物理盘可以有多个分区。

## 9. GPU：并行处理器

GPU 最初围绕图形流水线发展，但大量并行计算单元也适合矩阵、向量和张量运算，因此广泛用于科学计算与 AI。

需要区分集成 GPU、独立 GPU、显存容量和实际算力。显存大不等于 GPU 一定快，GPU 快也不等于任何应用都会受益。

## 10. 文件、文件名与扩展名

文件是持久化数据的基本组织形式。Windows 常用扩展名帮助判断类型和默认打开方式，例如 .txt、.pdf、.jpg、.zip、.exe。

扩展名只是文件名的一部分，不是可靠的安全认证。恶意文件可以伪装名称，因此应让系统显示扩展名，并结合来源、数字签名和安全扫描判断。

把 image.jpg 手工改名为 image.png 并不会把 JPEG 数据真正转换成 PNG。

## 11. 文件夹、路径和当前位置

路径回答“文件在哪里”。

例如 C:\Users\Alice\Documents\report.pdf 包含盘符、层级目录和文件名。

需要理解：

- 绝对路径从根位置完整描述；
- 相对路径相对于当前工作目录；
- 路径中的空格和特殊字符有时需要引号；
- 同名文件可以存在于不同目录；
- “桌面上的文件”实际也有磁盘路径。

这与之后的命令行、编程、Git、Python 环境和 Docker 路径直接相关。

## 12. 可执行文件、快捷方式和文件关联

.exe 等可执行文件包含可由操作系统装载的程序代码与相关数据。

Windows 的 .lnk 快捷方式只是“指向目标”的元数据。删除快捷方式通常不会删除程序本体。

文件关联决定双击某种扩展名时用哪个应用打开。改变默认应用不改变文件内容。

因此：

- 删除桌面图标 ≠ 卸载软件；
- 改默认打开方式 ≠ 转换文件格式；
- 快捷方式损坏 ≠ 原文件一定丢失。

## 13. 压缩文件的基本观念

压缩包通常同时解决两件事：将很多文件封装为一个归档，以及利用压缩算法减少冗余。

要区分无损压缩和有损压缩，也要知道归档格式与压缩算法并不总是一回事。

不要在压缩包内部直接长期编辑重要文件；先解压到明确目录，再工作，再决定是否重新打包。

## 14. 文件组织：重点不是“分几个盘”，而是可找到、可备份

一个实用文件系统应满足：

- 路径有意义；
- 临时下载与长期资料分开；
- 项目资料按项目归档；
- 大文件知道放在哪里；
- 备份范围清晰；
- 不把唯一副本放在 Downloads 或聊天缓存目录；
- 不依赖“桌面越乱越方便”。

可以按“领域 / 项目 / 年月 / 状态”组合分类，但不要创建过深层级。

建议至少定期清理 Downloads、聊天软件接收目录、桌面、临时导出文件、安装包和大体积重复文件。

### 14.1 先生成清单：文件名、路径与内容身份分开

下载目录整理可以拆成四阶段：只读清点→解释分类→提出不冲突的目标名→审核并重核源内容。最后一步产生的是文件管理器可以消费的计划，**还没有移动任何文件**。把计划、批准、实际执行、结果回读分开，才能解释“计划看起来正确，但文件为什么还在原地”，也才能处理操作中途失败。

每份清单记录至少含`path`、`size`、`sha256`、`suffix`：

- path是相对于选定根目录的POSIX形式路径，例如`notes/handout.txt`，让计划不依赖某台电脑的绝对用户目录。
- size按字节计，不能把字符串字符数当大小。例如UTF-8的é是2字节。
- sha256根据实际文件字节计算，同名文件可能不同哈希，异名文件也可能相同。
- suffix是分类用的扩展名线索，不是文件格式认证，更不是恶意内容检测。

来源清单对根目录和递归发现的符号链接拒绝处理，只纳入普通文件；对每份文件按64KiB分块更新SHA-256，避免一次把整个大文件读入内存。文件列表仍会排序并保存所有记录，因此分块哈希不等于整个流程内存恒定、耗时受限。读取字节不会执行文件里的Python、SVG、文档宏等内容。

有意义的小例子是四份作者样本：

| 源路径 | 大小/B | 分类线索 | 内容关系 |
|---|---:|---|---|
| attendance.csv | 21 | .csv | 一份表格文本 |
| duplicate.txt | 26 | .txt | 与下一份字节完全相同 |
| handout.txt | 26 | .txt及文件名handout | 与上一份字节完全相同 |
| sketch.svg | 100 | .svg | 20×20画布内一个圆的SVG文本 |

两个txt的SHA-256均为`c5e182bfe7c7f409d7128051129d3754ea33770b04aef586dba1f92aedf522a7`。这说明固定样本字节相同，不表示应该删掉其中一个：它们可能有不同目录语境、备注、访问权限或保留要求。报告重复组、保留原路径，删除决策另做；该项目从未删除重复文件。

清单生成并不是文件系统快照。来源先判断链接/文件类型，再打开读取，最后另取size；其间文件可能被替换或继续写入，因此hash与稍后stat所得size也可能不对应同一时点。硬链接不会被is_symlink识别成符号链接；根目录的父级链接、Windows junction和各种重解析点也不能由一项检查概括为全部隔离。[文件链接语义见04章](./04-Windows用户存储空间与文件链接.md)

CLI还先resolve用户给的folder，之后再传给inventory：若folder原本是指向目录的符号链接，resolve已经把它变成目标目录，核心入口的“拒绝根链接”就没有验证用户原始写法。正式工具应明确选定根身份及链接政策，不能同时声称既跟随入口别名又完全拒绝所有入口链接。

### 14.2 分类要能解释，也要允许“证据不足”

来源使用透明的启发式分类，不调用模型或网络：

| 类别 | 扩展名，每次命中得3分 |
|---|---|
| documents | .txt、.md、.pdf、.docx |
| images | .png、.jpg、.jpeg、.svg |
| tables | .csv、.tsv、.xlsx |
| archives | .zip、.gz、.tar |

再查看**文件名去掉最后扩展名后的部分**，转小写；包含workshop给documents加1，包含handout再加1。只按有没有包含计算，每个词最多加一次；不搜索文件正文。类别按分数高优先，同分按类别字母顺序；所有分数均0时返回other，而不是任挑一个类别。

对`workshop-handout.csv`，tables=3、documents=2，所以选tables，并保留两条命名证据与扩展名证据。对handout.txt，documents=4。duplicate.txt虽然正文也写了Workshop，但文件名没有这个词，只有.txt贡献的documents=3。这样可以区分“分类解释来自哪里”，避免看见文件正文后反推代码做了正文理解。

来源实际用的是子字符串包含，不是按完整词分词：`notworkshopish.bin`也会得到documents=1。中文“工作坊资料.bin”不会因语义相近自动命中；`.tar.gz`只按最后的.gz识别，换后缀也不会转换格式。因此类别只是整理提案，不能由它判断内容专业性、文件可打开、安全或用户已读过。

默认规则中每种扩展名只属于一类，非documents类别得3分，而两个命名词最多贡献2分，所以许多正分相同的情形在当前固定规则下根本不会出现。保留确定性的平局规则有利于以后扩展，但不能用演示滑块制造的任意分数，冒充真实文件特征必然产生的结果。

### 14.3 提出目标名：占位集合要包含已有目标和本轮计划

清单和分类确定后，先生成`类别/源basename`目标提案，例如`documents/handout.txt`。若目标的casefold形式已经在used集合里，就在最后扩展名前加`-2`，再试`-3`，直到找到未占用项。每生成一个目标，立即把它加入本轮used集合，否则两条提案仍可能指向同一个位置。

完整规划逻辑可以写成不访问文件系统的伪代码：

```text
used = 用户提供的occupied路径经既定比较规则转换后的集合
对稳定顺序的每条源记录：
    校验源是安全相对路径，拒绝重复源ID
    算分类与解释
    候选 = 类别 / basename
    序号 = 2
    当候选的比较键已占用：
        候选 = 类别 / (stem + '-' + 序号 + suffix)
        序号递增
    used加入候选比较键
    保存原path/hash/size、分类证据、候选目标、approved=false
按内容摘要聚合全部源路径，保留至少两成员的重复组
```

occupied是传入的字符串清单，不是执行器在磁盘上实际保留的名字。casefold是该教学规则的无大小写比较，也不是所有文件系统的完整等价规则。Unicode规范化、Windows保留名、末尾空格/点、实际目录占用和权限都需目标系统政策；不要把“字符串集合里无冲突”叫“文件系统已经保证不会覆盖”。

在作者样本中，occupied预先含`documents/handout.txt`，所以完整提案为：

| 源 | 提议目的地 | 解释 |
|---|---|---|
| attendance.csv | tables/attendance.csv | 表格扩展名3分 |
| duplicate.txt | documents/duplicate.txt | 文档扩展名3分 |
| handout.txt | documents/handout-2.txt | 文档4分，原目标已占用 |
| sketch.svg | images/sketch.svg | 图片扩展名3分 |

两个txt仍都在计划中，同时出现在同一重复组；没有哪个被自动省略或删除。对于`A.txt`与`sub/a.txt`，在当前比较规则下会得到`documents/A.txt`、`documents/a-2.txt`。若`a.txt`与`a-2.txt`都已占用，就试a-3.txt。

占用数不等于后缀数字。已有`handout.csv`与`handout-3.csv`时，第一空位是handout-2.csv；不能看到“已有两个”就直接选择handout-3.csv。多重后缀也要说明：对report.tar.gz，最后suffix是.gz，冲突名成为report.tar-2.gz，而不是算法自动理解的report-2.tar.gz。

计划稳定性取决于输入顺序。inventory提供排序结果，但外部调用plan_moves若传入不同顺序，谁获得无数字名字、谁获得-2可能不同；顺序变化也应让旧批准失效。

### 14.4 审核不是执行：用内容重核与计划指纹拒绝陈旧批准

review_plan先要求schema_version=1，把全部moves的approved归零，从计划字段移除旧fingerprint后生成SHA-256指纹，再读当前清单核每条源path与SHA。决策文件必须带同一fingerprint，approved是已知源路径的不重复子集；返回结果只有被选中的源approved=true。没有决策时，输入计划即使人为写了approved=true，也会被重置为false，这一点应保留。

按明确样本字段自行重建得到指纹：

```json
{
  "fingerprint": "fa9b96887ca3ab0cdd4e977d6f2bb640bd5821613005601635c6164cd63b4672",
  "approved": ["handout.txt"]
}
```

该决策只表示批准这份计划里handout.txt对应的`documents/handout-2.txt`提案，不批准另外三个。指纹是在固定样本数据上自写复算的，未调用原程序，也不是文件已经移动的回执。

来源会重新核**所有计划项**的源SHA，包含未批准项；未批准文件变动也会使整份旧计划失败。CLI重新扫描并重建计划后再比较决策指纹，所以文件新增、删改或目的提案改变，都可能使旧决策陈旧。直接调用review_plan校验旧计划则只遍历旧moves：新加入而未列入旧计划的文件不会自动导致失败，必须由消费者决定是否要求整个目录集合完全一致。

指纹基于Python `json.dumps(sort_keys=True)`的具体序列化，不是签名或身份认证。它没有包含根目录身份，因此不同目录中若有相同相对路径与字节，就可生成同一计划指纹；哈希也不证明哪个人批准。源核查只比较SHA，不验证计划size/suffix仍准确，不能把所有元数据当成已经重新取证。

对外部计划还必须补足schema校验。来源生成器会拒绝重复源路径，但review_plan本身没有：同一个源path若列两次且目的不同，可以穿过它的known集合和逐条SHA核查。执行器若逐项照做，第一项移动后第二项可能失败；这不是两个独立合法动作。

review_plan也不重算分类分数、evidence或duplicate_groups，所以外部计划中的解释字段不是重新核实的结论。若允许审核者改目标目录，应把改动后的完整提案重新交给相同约束校验并重新批准；不能因源SHA吻合，就信任计划里其余任意字段。

目的路径的现有检查也只是POSIX词法上的“不是绝对路径、不含..、raw casefold不重复”。空字符串、点路径，以及`documents//a.txt`与`documents/a.txt`这类规范化别名没有完整拒绝。`C:/outside/file`在POSIX下不是绝对路径，却有Windows盘符语义；反斜线也会在两种路径风格下产生不同解释。应先固定计划路径语法与目标平台，再验证规范相对形式、非空basename、保留名、边界及等价比较，而不是把PurePosixPath检查直接搬到Windows。[Python pure path与绝对路径规则](https://docs.python.org/3.10/library/pathlib.html#pathlib.PurePath.is_absolute)

HTML中的表格文本与JSON编辑框采用转义，下载时只做JSON语法检查；依赖可信导入器检查计划和决策。页面搜索只隐藏不匹配行，不修改计划或扩大批准。这个项目没有真正的move执行器、操作日志、失败恢复或撤销功能。

### 14.5 文件管理器怎样消费计划，哪些保证仍待实现

即便审核刚通过，执行前仍可能出现竞争：另一个程序修改源文件或创建同名目标。下面是需要另行设计与验证的执行合同，不是来源已经实现的能力：

1. 固定源根和目标根身份，明确相对路径如何解释；重新校验完整plan与批准绑定，按支持的链接/重解析点政策解析父目录和叶子文件。
2. 在实际操作前重核源对象及内容，原子保留目标名字或使用明确不覆盖的发布机制；不能用“先exists，再普通rename”声称没有竞争。
3. 分别处理同文件系统与跨文件系统。标准库rename的覆盖行为依平台不同；Unix中既有目标文件可能被替换，成功原子也不等于禁止覆盖。shutil.move在同文件系统可用rename，跨文件系统则通常复制后删除，不是一个整体原子动作。[os.rename](https://docs.python.org/3.10/library/os.html#os.rename)、[shutil.move](https://docs.python.org/3.10/library/shutil.html#shutil.move)
4. 对跨盘过程记录复制、内容校验、目的发布、源删除的各阶段，明确空间不足、权限、元数据/ACL与中断策略。不能把复制成功的字节数当完整验证，也不能把上次计划直接当重试授权。
5. 每项留下实际动作和结果回读：源/目标、内容身份、开始/完成/失败/未知状态、目标实际存在且符合预期的证据。只在有依据时提供撤销；撤回时也要核目的文件未被后来修改、原路径可用，不能盲目反向覆盖。

SHA和计划版本解决部分内容变化问题，不解决TOCTOU、操作系统权限、磁盘故障或跨端同步。尤其是自动整理云同步目录时，还须由目标产品的实际机制验收，不能从这个本地计划器推导任何同步承诺。

CLI把输出目录置于输入folder外，防止本次生成的moves.json和review.html被下一轮当成待整理源。这是必要的局部边界；它没有完整防护输出叶子符号链接/硬链接别名或输入JSON/decisions文件覆盖，三个产物也不是事务式发布。正式工具应采用私有新输出目录与完整发布，并将审核文件和执行回执分别保存。

### 14.6 练习、图示与本次验证边界

不用移动真实文件也能完成前三阶段练习：给出四条自造记录，先手算分数、目标名和重复组，再改一个占用名或内容摘要，预测哪些批准应失效。第四阶段练习要明确返回的approved不等于执行成功。

参考问题与答案：

- 改名为.pdf是否证明它是PDF？**不能。** 扩展名仅分类线索，转换格式与安全检查另做。
- 两个26B文件大小相同，是否足以称内容重复？**不足。** 固定样本还有相同字节SHA证据；即便内容相同也不等于可自动删除。
- workshop-handout.csv为什么归tables？**tables=3，documents=2。** 内容里的Workshop不额外计分。
- 当前占用handout.csv和handout-3.csv，第一空位是什么？**handout-2.csv。** 占用数不能替代集合检查。
- 计划里一个未批准文件内容变动，原review是否通过？**不会。** 来源重核全部moves；但直接review不会强制发现未列入的新增文件。
- fingerprint匹配且approved=true是否说明文件已经归位？**不能。** 这里只校验计划与源字节；实际移动和效果回读尚未发生。
- PurePosixPath判C:/outside为相对，Windows消费者就可直接接受吗？**不能。** 需要明确路径风格、盘符及目标根边界。

来源四幅交互图共用同一个calculate：比较可调的tables扩展名分数和documents命名分数，并按一个occupied数量显示handout-N.csv。它不扫描文件、不哈希、不导入批准；extension=0且words=0时还显示documents，而真实categorize应other。它假定同名槽连续占用，不能处理上述“原名与-3占用、-2为空”的情况。图只用于理解评分和简单序号，不能当实际冲突与审核实现。

## 15. 常用快捷键应该按“动作”记

不必死背全部快捷键，优先掌握复制、剪切、粘贴、撤销、全选、查找、切换窗口、关闭窗口、系统搜索、截图、锁屏和浏览器标签操作。

快捷键的价值不是炫技，而是把高频动作变成稳定肌肉记忆。

## 16. 显示器：五个经常被混淆的指标

### 分辨率与 PPI

分辨率是横向像素数 × 纵向像素数。PPI 是每英寸像素数：

PPI = sqrt(W² + H²) / D

W、H 是像素宽高，D 是屏幕对角线英寸数。

例如 27 英寸 2560×1440 屏幕的 PPI 约为 109。

### 色域

色域描述设备能覆盖的颜色范围，常见参考包括 sRGB、Display P3、Adobe RGB。“100% sRGB”不能与“100% P3”当成同一个指标。

### 色准

色准描述显示出来的颜色离目标颜色有多远。常用 Delta E 表示误差，但评价仍取决于测量标准、亮度和校准条件。

### 色深

色深决定每个颜色通道可表示的级数。更高色深有助于减少渐变断层，但内容、系统、接口、GPU 和面板链路都要支持才有意义。

### 刷新率

刷新率单位 Hz，表示屏幕每秒可更新多少次。高刷新率可以改善运动流畅度和交互延迟，但应用帧率、接口带宽和系统设置也必须跟上。

## 17. 面板类型：不要只用“好/坏”排序

常见面板路线各有取舍：

- IPS/LCD：可视角度与色彩表现通常均衡，应用广泛；黑位和对比度通常不如 OLED；
- VA/LCD：常见优势是对比度较高，但不同产品响应速度差异明显；
- TN/LCD：传统优势是响应快、成本低，但色彩和可视角度通常较弱，如今更多见于特定低成本或电竞场景；
- OLED：像素自发光，可实现极高对比度和快速响应，但要考虑烧屏风险、亮度策略、子像素结构和价格；
- Mini-LED 不是独立面板材料，而是一种 LCD 背光方案，通过大量局部调光区改善 HDR 和对比度，但可能出现 blooming。

真正选屏应把分辨率/PPI、色域、色准、色深、刷新率、响应、亮度、HDR、调光方式和使用场景一起看。

## 18. 最小练习

1. 找出自己电脑 CPU、RAM、磁盘和 GPU 的型号/容量，并用一句话解释各自职责。
2. 选一个文件，写出完整路径、主文件名和扩展名。
3. 创建一个快捷方式，删除快捷方式，确认原文件仍存在。
4. 计算当前显示器 PPI，并解释它为什么不能单独决定画质。
5. 把 Downloads 中一批文件按“临时/长期”分类，长期文件移动到明确目录。
