# 02｜计算机体系结构与操作系统

## 1. 从程序到硬件

程序最终要经历：

```text
源代码
→ 编译/解释
→ 指令
→ CPU/GPU 执行
→ Cache/内存
→ I/O
```

性能问题必须同时看“计算量”和“数据在哪里”。

## 2. 数字表示

必须掌握：

- binary / hexadecimal；
- two's complement；
- fixed point；
- IEEE 754 浮点；
- overflow / underflow；
- rounding error。

AI 中 FP32、BF16、FP16、INT8 等差异，本质都来自“有限位宽如何表示数”。

## 3. 逻辑门与组合/时序电路

AND、OR、NOT、XOR 是硬件的布尔基础。

进一步形成：

- adder；
- multiplexer；
- register；
- finite state machine；
- clocked sequential logic。

不必成为芯片工程师，但要知道 ISA 之下不是“魔法”。

## 4. CPU 与 ISA

CPU 的典型数据通路包括：

- fetch；
- decode；
- execute；
- memory access；
- write back。

ISA 定义软件与硬件之间的契约，包括指令、寄存器、地址方式和内存模型。

## 5. Pipeline 与乱序执行

流水线通过让多条指令处于不同阶段提高吞吐。

会受到：

- data hazard；
- control hazard；
- branch misprediction；
- dependency chain；

限制。

现代 CPU 还会使用 superscalar、out-of-order、speculation 来提高指令级并行度。

## 6. Memory Hierarchy

```text
register
→ L1
→ L2
→ L3
→ DRAM
→ SSD / network storage
```

越靠近计算单元：

- 容量越小；
- 延迟越低；
- 单位成本越高。

因此缓存局部性常常比“少几次算术”更重要。

## 7. Virtual Memory

虚拟内存提供：

- 每进程独立地址空间；
- page-based mapping；
- protection；
- demand paging。

TLB 缓存虚拟地址到物理地址的映射。大规模模型中的 page、pin memory、mmap 等都与这套机制相关。

## 8. I/O 与 DMA

DMA 允许设备直接在内存与设备之间搬数据，减少 CPU 逐字节参与。

高性能训练中的数据加载、NIC、GPU DMA、zero-copy 等概念都建立在这个基础上。

## 9. 进程与线程

- process：独立地址空间和资源边界；
- thread：共享进程地址空间的执行流。

需要理解：

- context switch；
- user/kernel mode；
- system call；
- scheduler。

## 10. 调度与同步

操作系统要在多个任务之间分配 CPU。

典型问题：

- race condition；
- deadlock；
- starvation；
- priority inversion。

同步工具：

- mutex；
- semaphore；
- condition variable；
- atomic。

## 11. 文件系统与存储

文件系统提供：

- namespace；
- metadata；
- permissions；
- buffering；
- journaling；
- consistency。

生产系统需要额外考虑 fsync、缓存、随机/顺序 I/O 和故障恢复。

## 12. 网络与容器

网络至少要理解：

- TCP/IP 分层；
- socket；
- latency vs bandwidth；
- connection / congestion。

容器不是轻量虚拟机，而是主要依靠 namespaces、cgroups 和文件系统隔离构造进程级环境。

## 13. 安全边界

操作系统通过：

- privilege level；
- process isolation；
- access control；
- capability；
- sandbox；

控制资源访问。

来源：Compendium Chapter 13 / computer architecture + operating systems。

## 15. 从一次文件读取串起系统层次

设一个进程读取 1 MiB 文件：程序调用库函数 → 库可能使用自身缓冲 → 系统调用进入内核 → 检查文件描述符与访问权限 → 在页缓存命中时复制数据，未命中则等待存储设备 → 返回用户空间。第二次读取更快可能来自页缓存，不能直接推断硬盘变快。

虚拟地址也不等于物理内存地址；页表建立映射，TLB 缓存映射结果。page fault 表示所需映射/页面需处理，不一定需要磁盘 I/O，更不自动等于程序崩溃。进程有独立地址空间，但显式共享内存仍可跨进程共享数据。

自测：两个线程为什么能共享一个 vector，却各有局部调用栈？答：它们共享进程地址空间，但每个线程有自己的执行上下文和栈；共享对象的修改仍需同步。把文件 write 成功当作断电后数据必在也不成立，持久性需要额外同步与存储保证。
