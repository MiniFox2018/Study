## 使用原则

这里不把某个 IDE、云控制台、安装 UI 或短期工具版本当作永久知识。长期需要掌握的是：抽象、复杂度、内存、并发、接口、测试、构建、部署、隔离、可观测性、安全与性能模型。

软件工程中的“定律”需要按证据强度理解：CAP、Amdahl 等有明确条件或形式化约束；YAGNI、DRY、KISS 等是工程设计原则；Conway、Brooks、Bus Factor 等主要用于组织和项目风险判断；Goodhart、确认偏误、沉没成本等是决策检查工具。不要因为名称带 Law 就把经验启发式当作精确公式。

## 按实际能力选择起点

第一次学习建议先读 02 建立程序运行模型，再用 04 的二分查找练习具体算法；01 的逻辑和递推可穿插补齐，03 在能写基本程序后学习。Linux 01～03 与 08 是日常操作入口，Docker 放在能解释文件权限和进程之后；GPU 与 Kubernetes 可留到有明确任务时。目录顺序用于分类，不要求把全部内容读完才开始实践。

如果已经能写基本程序、但对“为什么工程项目常在接口兼容、估时、扩编、指标、技术债和重构上反复踩坑”缺少系统认识，可以先读 05，再进入 05-1，把每条原则当成一次设计评审问题，而不是记忆卡片。

每篇新增了具体推演或练习。学习时先写自己的预测，运行或手算后解释差异，再改变一个边界条件。能完成练习并解释限制才记录“已完成”；收藏、AI 整理和文档存在均不代表已经掌握。
