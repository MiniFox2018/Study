# 01｜核心模型与生命周期

## 1. Docker 解决什么问题

Docker 的价值不是“把程序装进一个盒子”，而是把运行所需的用户态环境变成标准化、可重复分发的交付物。

它主要缓解：

- 开发、测试、生产环境不一致；
- 依赖安装和环境配置难以复现；
- 应用迁移成本高；
- CI/CD 中构建环境不稳定；
- 多服务依赖难以快速启动与销毁。

镜像并不包含宿主机内核，因此“一次构建，到处运行”有前提：CPU 架构、内核能力、外部服务、网络、卷和运行时配置必须兼容。

## 2. 容器不是虚拟机

传统虚拟机：

```text
App
↓
Guest OS + Kernel
↓
Hypervisor
↓
Host
```

容器：

```text
App
↓
用户空间 + 隔离边界
↓
共享宿主机 Kernel
```

因此容器通常：

- 启动更快；
- 额外资源开销更小；
- 更适合高密度部署；
- 隔离强度低于完整硬件虚拟机。

选择虚拟机的典型场景：运行不受信任代码、要求独立内核、强多租户隔离或特殊内核模块。

## 3. 三个核心对象

### Image

镜像是只读模板，通常包含：

- 应用代码和二进制；
- 运行时；
- 用户空间库；
- 配置默认值；
- 启动元数据。

镜像使用分层文件系统，多个镜像可以共享相同层。

### Container

容器是镜像的运行实例：

```text
只读镜像层
+
容器可写层
+
namespace 隔离
+
cgroup 资源控制
+
启动进程
```

容器的关键事实：**它首先是一个进程，而不是一台小型虚拟机。**

### Registry

Registry 是镜像分发服务；Repository 是某一软件/项目的镜像集合；Tag 是可变的版本标签。

生产追踪应优先依赖 digest，而不是只依赖可被重新指向的 tag。

## 4. 容器与 PID 1

容器生命周期通常绑定其主进程：

- PID 1 仍运行 → 容器运行；
- 主进程退出 → 容器退出。

因此服务进程应在前台运行，不要在容器内部再把主服务 daemonize 到后台。

```text
错误心智模型：容器启动 = 启动一台机器
正确心智模型：容器启动 = 启动一个被隔离的主进程
```

## 5. 生命周期

常见状态：

```text
create
  ↓
created
  ↓ start
running
 ↙   ↓    ↘
pause stop  kill
 ↓    ↓
paused exited
   ↘  ↓
     remove
       ↓
     deleted
```

关键操作语义：

- `run`：create + start；
- `stop`：先尝试优雅终止，再超时强制结束；
- `kill`：直接发送终止信号；
- `exec`：在正在运行的容器里额外启动进程；
- `attach`：连接到已有主进程的输入输出流，调试时需谨慎；
- `rm`：删除容器对象。

## 6. 容器存储层

容器启动后，会在只读镜像层之上增加可写层。修改镜像层已有文件时通常采用 Copy-on-Write：

1. 把要修改的文件复制到容器可写层；
2. 在可写层修改；
3. 原镜像层保持不变。

因此：

- 容器层适合短期状态；
- 容器被删除后，可写层也随之消失；
- 业务数据不要依赖容器可写层持久化。

## 7. `docker commit` 的正确定位

`docker commit` 能把容器当前文件变化提交成新镜像，但不应作为标准构建方式。

原因：

- 操作不可审计；
- 步骤不可重复；
- 容易夹带临时文件、缓存和秘密；
- 难以 code review。

它适合理解镜像分层或临时调试，不适合生产镜像流水线。

## 8. 安装与运行环境的长期决策规则

不要把某个系统的安装命令当作知识本体。长期需要记住的是：

- Linux 生产环境优先使用官方软件仓库和包管理器，方便升级、回滚与安全更新；
- 一次性测试环境才考虑官方便捷脚本；
- macOS / Windows 运行 Linux 容器需要虚拟化层；
- Windows 常见后端是 WSL 2 或 Hyper-V；
- ARM 平台必须确认镜像架构；
- 离线生产环境应准备完整依赖和离线仓库，不要用跳过依赖检查的方式强装；
- 加入 `docker` 用户组近似授予主机 root 能力，多用户环境应考虑 Rootless。

## 9. 最小操作闭环

```bash
docker pull nginx
docker run -d --name web -p 8080:80 nginx
docker ps
docker logs web
docker exec -it web sh
docker stop web
docker rm web
```

命令不是重点。重点是理解每一步对应的对象变化：镜像获取 → 容器创建 → 进程运行 → 网络映射 → 观察 → 调试 → 终止 → 删除。
