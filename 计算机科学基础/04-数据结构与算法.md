# 04｜数据结构与算法

## 1. 先看复杂度，再看代码

最常用的渐进符号：

- O：上界；
- Ω：下界；
- Θ：同阶。

分析时区分：

- time complexity；
- space complexity；
- worst / average / amortized。

## 2. 递归、回溯与动态规划

递归适合树形结构和分治，但要注意调用栈。

Backtracking：

```text
选择
→ 递归
→ 不可行则撤销
```

Dynamic Programming 的核心是：

> overlapping subproblems + optimal substructure

两种写法：

- top-down memoization；
- bottom-up tabulation。

## 3. Array 与 Hash Table

Array：

- O(1) random access；
- 连续内存；
- 中间插入删除昂贵。

Hash table：

- 平均 O(1) lookup；
- 依赖 hash function、load factor 和 collision strategy；
- 最坏情况可能退化。

## 4. Linked List、Stack、Queue

Linked list 适合已知节点位置时的局部插删，但随机访问差、缓存局部性弱。

Stack：LIFO，用于递归、解析、单调栈等。

Queue：FIFO，用于 BFS、调度、生产者消费者等。

## 5. Tree

常见树：

- binary tree；
- BST；
- balanced BST；
- heap；
- trie。

Heap 提供快速取极值，适合 priority queue、top-k、调度。

## 6. Graph Algorithms

最基础：

- BFS；
- DFS；
- topological sort；
- connected components；
- union-find。

加权最短路径：

- Dijkstra：非负权；
- Bellman-Ford：可处理负权；
- Floyd-Warshall：全点对，复杂度高。

MST：

- Kruskal；
- Prim。

## 7. Sorting

需要理解而不是死背：

- bubble / insertion：简单、小规模或近乎有序时有价值；
- merge sort：稳定，O(n log n)，需要额外空间；
- quicksort：平均 O(n log n)，原地友好；
- heap sort：O(n log n)，额外空间小；
- counting/radix：利用键的结构突破比较排序下界。

## 8. Binary Search

Binary search 不只是“找某个值”，更常用于：

> 在单调条件上找第一个/最后一个满足条件的位置。

因此它可以解“答案空间上的搜索”。

## 9. 选择数据结构的顺序

先问：

1. 最频繁操作是什么？
2. 是否需要顺序？
3. 是否需要随机访问？
4. 是否频繁插删？
5. 是否需要按优先级取元素？
6. 是否需要前缀/区间/关系查询？
7. 数据能否全部放内存？

## 10. 工程视角

Big O 相同不等于实际一样快。还要看：

- cache locality；
- allocation；
- branch prediction；
- constant factor；
- data distribution。
