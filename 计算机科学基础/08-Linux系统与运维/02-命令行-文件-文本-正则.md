# 02｜命令行、文件、文本与正则

## 1. 命令行的核心价值

命令行不是为了“看起来专业”，而是因为它具备：

- 可组合；
- 可自动化；
- 可远程；
- 可记录；
- 资源占用低；
- 适合批处理。

Linux 命令行最重要的思想是：让小工具通过文本流、管道和退出状态组合成更大的操作。

## 2. 命令结构

典型形式：

~~~text
command [options] [arguments]
~~~

先区分：

- shell builtin：cd、export、read 等由 shell 自己实现；
- 外部命令：ls、grep、find 等通常是文件系统中的可执行程序。

查找命令：

~~~bash
type cd
command -v grep
whereis grep
~~~

which 在常见环境中仍可用，但 command -v 对 shell 脚本更通用。

## 3. 路径与目录

必须熟练：

~~~bash
pwd
ls -lah
cd /path
cd ..
cd -
mkdir -p a/b/c
rmdir empty-dir
tree
~~~

路径规则：

- / 开头：绝对路径；
- 不以 / 开头：相对路径；
- .：当前目录；
- ..：父目录；
- ~：shell 展开的用户家目录。

文件名可以包含空格和特殊字符，因此脚本中变量表示路径时通常要加双引号。

## 4. 文件创建、复制、移动与删除

常用命令：

~~~bash
touch file
cp source target
cp -a dir backup
mv old new
rm file
rm -r dir
~~~

风险点：

- rm 默认不可恢复；
- 不要把 rm -rf 当常规手段；
- 使用变量拼接删除路径前先检查变量是否为空、目标是否正确；
- 批量覆盖前使用 dry-run 思维或先列出匹配结果。

## 5. 文件类型、元数据与链接

~~~bash
file target
stat target
ln source hardlink
ln -s target symlink
~~~

硬链接：

- 与原文件指向同一个 inode；
- 通常不能跨文件系统；
- 删除其中一个名字不会立即删除数据，只要仍有链接存在。

符号链接：

- 保存目标路径；
- 可以跨文件系统；
- 目标不存在时会成为悬空链接。

## 6. 查找文件

### find

find 直接遍历目录树，可按名称、类型、大小、时间、权限等过滤。

~~~bash
find . -type f -name '*.log'
find /var/log -type f -mtime -1
find . -type f -size +100M
~~~

对结果执行命令时优先考虑安全的 -exec 或 NUL 分隔：

~~~bash
find . -type f -name '*.tmp' -exec printf '%s\n' {} +
~~~

### locate / plocate

基于索引，速度快，但结果依赖数据库更新时间。适合快速定位，不适合要求“此刻绝对准确”的场景。

## 7. 查看文件内容

~~~bash
cat file
less file
head -n 20 file
tail -n 50 file
tail -f app.log
~~~

选择原则：

- 小文件：cat；
- 大文件交互浏览：less；
- 只看开头：head；
- 实时日志：tail -f，systemd 服务更常直接用 journalctl -f。

## 8. 标准输入、标准输出和标准错误

进程通常有三个标准文件描述符：

| FD | 名称 | 默认目标 |
|---|---|---|
| 0 | stdin | 键盘/上游管道 |
| 1 | stdout | 终端 |
| 2 | stderr | 终端 |

常见重定向：

~~~bash
command > out.txt
command >> out.txt
command 2> err.txt
command > all.txt 2>&1
command < input.txt
~~~

需要 root 权限写文件时：

~~~bash
printf '%s\n' 'value' | sudo tee /etc/example.conf
~~~

sudo echo ... > file 常失败，是因为重定向由当前 shell 在 sudo 之前执行。

## 9. 管道

~~~bash
producer | filter | consumer
~~~

管道把前一个进程 stdout 接到后一个进程 stdin。

常见组合：

~~~bash
journalctl -u nginx | grep -i error
ps aux | sort -k4 -nr | head
~~~

脚本中需要关注管道失败传播，详见 08 的 pipefail。

## 10. 文本统计与比较

~~~bash
wc -l file
diff -u old new
sort file
uniq -c
sort file | uniq -c | sort -nr
~~~

uniq 只合并相邻重复行，因此常与 sort 配合。

## 11. grep：筛选文本

常用能力：

~~~bash
grep 'pattern' file
grep -i 'error' file
grep -n 'TODO' file
grep -R 'token' src/
grep -E 'foo|bar' file
grep -v 'debug' file
grep -A 3 -B 3 'panic' log
~~~

在脚本条件判断中，grep -q 只依赖退出状态，不需要输出。

## 12. sed：流式编辑

sed 适合简单的替换、删除、选择输出。

~~~bash
sed 's/old/new/' file
sed 's/old/new/g' file
sed -n '10,20p' file
~~~

使用 -i 直接修改文件前，建议先不带 -i 验证结果或创建备份。

复杂结构化数据不要强行用 sed 解析，应使用对应格式工具，例如 jq、yq 或真正的解析器。

## 13. awk：按字段处理

awk 适合：

- 按列取值；
- 条件过滤；
- 简单聚合；
- 格式化输出。

示例：

~~~bash
awk '{print $1, $NF}' file
awk '$3 > 100 {print $1, $3}' file
~~~

复杂业务逻辑应升级为 Python、Go 等更可维护的程序。

## 14. sort、uniq、cut、tr、xargs

这些工具构成高效的数据处理组合：

- sort：排序；
- uniq：相邻去重/计数；
- cut：固定分隔符取列；
- tr：字符转换/删除；
- xargs：把标准输入转换为命令参数。

文件名可能包含空格或换行时，优先使用 NUL 分隔版本，例如 find -print0 配合 xargs -0。

## 15. glob 与正则表达式不是一回事

Shell glob：

~~~text
*.log
file?.txt
[abc]*
~~~

主要用于文件名展开。

Regex：

~~~text
^error
[0-9]+
(foo|bar)
$
~~~

用于文本模式匹配。

不要把 shell 的 * 与正则的 * 混为一谈。

## 16. 正则表达式体系

常见三类：

- BRE：基础正则；
- ERE：扩展正则；
- PCRE/PCRE2：Perl 兼容正则，能力更强。

核心结构：

- ^ / $：行首、行尾；
- .：任意字符；
- []：字符类；
- * / + / ?：重复；
- {m,n}：次数；
- ()：分组；
- |：分支。

高级特性可能包括：

- 捕获组；
- 后向引用；
- 贪婪/懒惰；
- lookahead / lookbehind；
- 零宽断言。

这些能力是否支持取决于具体 regex 引擎。

### 性能风险

某些复杂回溯正则会出现灾难性回溯。面对不受信任输入时：

- 避免高度嵌套、含糊的量词；
- 设定输入大小限制；
- 优先线性或可预测的匹配方式；
- 对高流量服务进行性能测试。

## 17. tar 与压缩

tar 主要负责归档，gzip/xz/zstd 等负责压缩。

常见：

~~~bash
tar -cf archive.tar dir/
tar -xf archive.tar
tar -czf archive.tar.gz dir/
tar -xzf archive.tar.gz
~~~

ZIP：

~~~bash
zip -r archive.zip dir/
unzip archive.zip
~~~

解压不可信归档时注意路径穿越、覆盖文件和超大解压体积。

## 18. 命令帮助系统

从快到深：

~~~bash
command --help
help builtin
man command
info command
whatis command
apropos keyword
~~~

man section 常见含义：

1. 用户命令；
2. 系统调用；
3. 库函数；
5. 文件格式；
7. 杂项；
8. 管理命令。

因此 printf(1) 与 printf(3) 可能是不同文档。

## 19. 阅读 man 的方法

不要逐字背诵。优先看：

1. NAME；
2. SYNOPSIS；
3. DESCRIPTION；
4. 常用 OPTIONS；
5. EXIT STATUS；
6. FILES；
7. EXAMPLES；
8. SEE ALSO。

遇到系统调用、配置文件格式和库函数时，明确 man section。

## 20. Markdown 作为技术记录格式

Linux101 的 Markdown 附录属于通用技术文档能力，保留最小实用集：

~~~~markdown
# 标题
## 二级标题

- 列表
- 列表

> 引用

**强调**

[链接](https://example.com)

~~~bash
command
~~~
~~~~

知识库中的 Markdown 目标是可读、可检索、可长期维护，不追求复杂装饰。

## 21. 一条重要原则

先让命令“把结果打印出来”，确认正确后，再加入：

- 删除；
- 覆盖；
- sudo；
- 批量执行；
- 自动化。

这比记住更多参数更重要。

## 22. 可复现练习：统计失败请求

下面只在新建临时目录写入三行练习数据，Bash 在 Linux/macOS 均可运行：

~~~bash
study_dir=$(mktemp -d)
printf '200 /home\n500 /api\n500 /api\n' > "$study_dir/access.log"
awk '$1 >= 500 {print $2}' "$study_dir/access.log" | sort | uniq -c
printf '练习目录：%s\n' "$study_dir"
~~~

结果应是 `/api` 出现 2 次（前导空格因实现而异）。先单独运行 awk 看筛选结果，再接 sort，再接 uniq，能逐段定位问题。输入按空白分字段，这不是通用 Web 日志解析器。

自测：把日志中的 `/api` 改成 `/api/v2` 会影响状态码筛选吗？答：不会，筛选条件只读第一列。若字段带空格或引号，简单 awk 字段切分就未必适用，应换结构化日志/解析器。

GNU 与 BSD 的 `sed -i`、`stat` 等参数不同；本章示例优先输出结果，原地修改前先查本机 man。
