# 01｜系统基础、发行版与运行环境

## 1. Linux 到底是什么

严格地说，Linux 是内核。日常所说的“Linux 系统”通常由多层组成：

~~~text
应用程序
→ shell / 桌面环境 / 系统服务
→ C library 与用户空间工具
→ system call
→ Linux kernel
→ CPU / 内存 / 磁盘 / 网卡 / 设备
~~~

内核负责进程调度、虚拟内存、文件系统、网络、设备驱动、安全边界等；发行版负责把内核、用户空间工具、包管理器、默认配置和软件仓库组合成可安装系统。

GNU/Linux 这个名称强调大量常用用户空间工具来自 GNU 项目。理解这一点有助于区分“内核能力”和“发行版工具”。

## 2. 发行版不是不同的 Linux 内核世界

常见差异主要来自：

- 软件包格式与包管理器；
- 默认桌面与系统工具；
- 发布节奏；
- 安全策略；
- 配置文件默认值；
- 社区与企业支持模式。

主要家族：

| 家族 | 常见系统 | 包管理心智模型 | 典型特点 |
|---|---|---|---|
| Debian | Debian、Ubuntu | apt / dpkg | 稳定、资料丰富 |
| Fedora / RHEL | Fedora、RHEL、Rocky、Alma 等 | dnf / rpm | 企业生态、SELinux 常见 |
| Arch | Arch、部分衍生版 | pacman | 滚动更新、强调用户理解系统 |
| openSUSE | Leap、Tumbleweed | zypper / rpm | YaST、Btrfs 等集成较成熟 |
| Gentoo | Gentoo | Portage | 源码构建与高度可定制 |
| NixOS | NixOS | Nix | 声明式、可复现、回滚能力强 |

没有“永远最好的发行版”。选择时看稳定性、软件生态、硬件支持、运维能力、团队经验和生命周期。

## 3. 如何识别当前系统

优先使用发行版标准信息：

~~~bash
cat /etc/os-release
uname -a
uname -m
~~~

关注：

- ID / VERSION_ID：发行版；
- kernel release：内核版本；
- machine：x86_64、aarch64 等 CPU 架构。

lsb_release 在一些发行版上并非默认安装，不应作为唯一方式。

## 4. CPU 架构与二进制兼容

常见架构：

- x86_64 / amd64；
- aarch64 / arm64；
- riscv64 等。

二进制程序必须与目标架构和 ABI 兼容。下载软件前要先确认架构；容器镜像、编译器、动态库也存在架构差异。

跨架构运行可能依赖：

- 交叉编译；
- QEMU 用户态模拟；
- 多架构容器镜像；
- 虚拟机。

## 5. 获取 Linux 环境的几种方式

### 5.1 原生安装

优点：

- 直接使用真实硬件；
- 性能和设备支持最完整；
- 最适合长期作为主要系统。

代价是需要处理分区、驱动、引导和数据备份。

### 5.2 虚拟机

适合学习、实验和隔离。

常见网络模式：

- NAT：虚拟机通过宿主机访问外部网络，最省事；
- Bridged：虚拟机像局域网独立主机；
- Host-only：主要用于宿主机与虚拟机内部通信。

虚拟机提供完整内核，与容器不同。

### 5.3 WSL 2

WSL 2 提供真实 Linux 内核环境，适合 Windows 上进行 Linux CLI、开发与容器相关工作。

使用原则：

- 把 Linux 项目文件优先放在 Linux 文件系统内，减少跨文件系统性能和权限差异；
- Windows 与 Linux 工具链混用时明确路径和换行符边界；
- 涉及内核模块、低层网络或硬件访问时，确认 WSL 是否支持该能力；
- VS Code、JetBrains 等可以通过远程/WSL 集成直接使用 Linux 工具链。

旧版 WSL 安装 UI、商店截图和历史手动步骤不作为永久知识保存。

### 5.4 远程服务器

生产和云环境大量使用无桌面的远程 Linux 主机。核心入口通常是 SSH。

远程环境要求你掌握：

- 主机身份验证；
- SSH 密钥；
- 用户权限；
- 日志和服务；
- 防火墙；
- 远程文件传输。

详见 06。

### 5.5 容器

容器适合提供隔离的用户空间，但共享宿主内核，因此不能把它等同于完整虚拟机。

需要完整容器知识时进入 [容器化与 Docker](../07-容器化与Docker/README.md)。macOS 上运行 Linux 容器时，共享的是运行容器的 Linux 虚拟机内核，而非 macOS 内核。

## 6. 桌面环境、终端与 shell

这三个概念不要混淆：

- Desktop Environment：GNOME、KDE Plasma、Xfce 等图形桌面；
- Terminal Emulator：显示命令行会话的图形程序；
- Shell：解释命令的程序，如 Bash、Zsh、Fish。

服务器可以没有桌面环境，但仍通过 shell 正常工作。

桌面环境的选择主要影响：

- 资源占用；
- 工作流；
- 可定制性；
- Wayland/X11 兼容性；
- 远程桌面需求。

学习 Linux 的长期核心不在主题、图标和窗口装饰，而在 CLI、文件系统、权限、进程、网络和服务。

## 7. shell 的角色

shell 既是交互式命令解释器，也是脚本语言运行环境。

一个命令大致经历：

~~~text
输入字符串
→ shell 解析
→ 变量/通配符/命令替换
→ 重定向与管道建立
→ 查找可执行文件或 builtin
→ 创建/执行进程
→ 收集退出状态
~~~

因此很多“Linux 命令问题”其实是 shell 解析问题，例如：

- 引号；
- 通配符；
- 管道；
- 重定向；
- 环境变量；
- 当前工作目录。

## 8. Login shell 与非 Login shell

不同启动方式可能读取不同配置文件。

常见 Bash 配置：

- /etc/profile：系统级 login shell；
- `~/.bash_profile`、`~/.bash_login`、`~/.profile`：Bash 登录时按此顺序读取首个存在且可读的文件，并非三个都读；
- ~/.bashrc：交互式非 login shell 常用配置。

不要机械记文件名；遇到环境变量“终端里有、脚本里没有”的问题时，应先判断 shell 类型和启动路径。

## 9. Linux 与 Android

Android 使用 Linux 内核，但用户空间、应用模型、权限体系和传统 GNU/Linux 桌面/服务器差别很大。

“使用 Linux 内核”不意味着系统管理方式完全相同。

## 10. SELinux：不要为了省事关闭

SELinux 是强制访问控制机制，常见于 RHEL/Fedora 系。

学习重点：

- Enforcing：策略实际生效；
- Permissive：记录违规但不阻止；
- Disabled：完全关闭。

旧教程常通过关闭 SELinux 解决服务访问问题，这会掩盖真实权限配置错误。现代做法应：

1. 先查看审计日志；
2. 判断文件标签、端口类型或策略是否错误；
3. 修复上下文或策略；
4. 仅在诊断阶段短暂使用 permissive。

## 11. 开机介质与 Ventoy

Ventoy 一类工具可以让一个 U 盘保存多个系统镜像并启动安装。

这类工具属于安装辅助层，不影响 Linux 核心知识。使用时应从发行版官方渠道验证镜像校验和与签名。

## 12. 学习发行版差异的正确方式

需要掌握的是“同一任务在不同发行版中的实现差异”。

例如安装软件：

~~~text
目标：从可信软件仓库安装并维护依赖

Debian 系 → apt
Fedora/RHEL 系 → dnf
Arch → pacman
openSUSE → zypper
NixOS → 声明式配置/Nix
~~~

不要把某一发行版的具体命令误认为 Linux 内核本身的能力。

## 13. 最小系统认知清单

第一次进入陌生主机，先回答：

~~~bash
whoami
id
pwd
cat /etc/os-release
uname -a
hostnamectl
ip addr
ip route
df -h
free -h
uptime
systemctl --failed
~~~

这组信息能够快速建立“我是谁、这是什么系统、网络怎样、资源怎样、服务是否异常”的初始视图。

## 14. 本机与练习环境先分清

本专题默认 **Linux + Bash + GNU 用户空间**。macOS 的 Zsh、BSD sed/stat/date，以及缺失的 `/proc`、systemd、iproute2，不能当作 Linux 等价环境。macOS 使用者可先在已有 Linux 虚拟机/远程测试机学习系统服务；容器适合练文本、权限、包管理，但普通容器未必运行 systemd。

先只运行 `uname -s`、`uname -m`、`id`、`pwd`。Linux 通常显示 `Linux`，macOS 显示 `Darwin`；确认是 Linux 后再读 `/etc/os-release`。若 `systemctl` 报“未以 systemd 启动”，先核对 PID 1：`ps -p 1 -o comm=`，不要通过反复安装 systemd 解决环境不匹配。

自测：容器里 `uname` 与镜像发行版名称为何可能不同？答：uname 观察内核，os-release 描述镜像用户空间，二者来自不同层。
