# 远程实验、进程与日志管理

本章融合远端 AI 工作台常用操作。Linux 的文件/权限/包管理分别见[02 命令行](./02-命令行-文件-文本-正则.md)、[03 权限](./03-用户-权限-文件系统.md)、[05 开发环境](./05-软件包-构建-开发环境.md)；本章不重复把相同命令另列成一套课程。

## 1. 知道代码在哪台机器运行

连接后先看 `hostname`、`pwd`、`id`、`uname -s`、`uname -m`，再确认项目、解释器、磁盘和设备。`$SHELL` 常表示账号配置的登录shell，不能独立证明当前正在执行哪一种shell；需要时查看当前进程或 shell 特有版本变量。

Linux目录：`/home` 常放用户文件，`/etc` 放系统配置，`/var/log` 常放服务日志，`/proc` 和 `/sys` 暴露内核信息，挂载点可以在任意管理员选择的目录。`/tmp` 可被系统策略清理，不能存唯一长期数据；Linux也可以创建 `/Volumes`，不要把macOS常见目录当成Linux不允许的名字。

远端文件/环境与本机不同。编辑器 Remote SSH 的界面在本机，项目执行主要在远端；SSH连接成功不表示该端有模型、Python包或GPU权限。

## 2. 标准输入输出与日志管道

```bash
printf 'epoch=1 loss=0.8\nepoch=2 loss=0.4\n' > practice.log
awk -F'loss=' '/loss=/{print $2}' practice.log
```

输出0.8和0.4。每一环节读上一环节的stdout；普通管道不自动传递stderr。字段格式变更时需修改解析，不能把源图中的“第8列”当通用日志协议。

重定向从左向右解释：

```bash
python -u train.py > train.log 2>&1
# 下面顺序不同：stderr先指向原stdout，随后stdout才改为文件。
python -u train.py 2>&1 > train.log
```

`>` 覆盖，`>>` 追加。`tee` 可同时查看和保存stdout；Bash的 `set -o pipefail` 能使训练失败不被后端tee的成功退出掩盖：

```bash
set -o pipefail
python -u train.py 2>&1 | tee train.log
```

`train.py` 是你实际准备的程序，上述是调用方式。`tail -f` 跟随日志，实时 `grep` 可能因缓冲延迟；确认所用实现支持行缓冲选项。结构化JSON日志应由对应解析器处理，不用脆弱字符串切列。

## 3. 后台与会话存活的区别

| 方式 | 保留什么 | 不保证什么 |
|---|---|---|
| `command &` | shell后台作业 | 不保证断开后仍存活或输出有保存 |
| `nohup command >log 2>&1 &` | 忽略SIGHUP并重定向输出 | 不自动重启失败、不应对机器重启/资源终止 |
| tmux/screen | 服务器端终端会话、可重新附着 | 主机关闭、调度器终止后仍不会存活 |
| systemd/调度平台 | 由服务策略管理进程与重启 | 正确结果、checkpoint恢复仍由程序保证 |

终端关闭后的行为还受shell和会话策略影响，不把所有 `&` 行为写成固定一律。`Ctrl+C` 常向前台进程组发SIGINT；默认 `kill PID` 通常是SIGTERM，不是SIGINT。程序可处理信号，退出码也依shell和程序约定。

## 4. 在 tmux 里管理一个练习

已有tmux时：

```bash
tmux new -s study-run
# 在会话内运行：
python3 -u -c 'import time; print("练习开始"); time.sleep(30); print("练习结束")'
# Ctrl+B 后按 d，分离会话；再执行：
tmux ls
tmux attach -t study-run
```

分屏常用Ctrl+B后按双引号或百分号，方向键移动面板；依当前按键配置核对。一个面板运行程序，另一个只读日志/资源，不用反复启动同一训练。

会话能继续不代表训练可恢复。长期作业要另存checkpoint、数据位置、运行参数与日志；云资源回收后需程序恢复机制。

## 5. 识别和结束正确的进程

先用 `ps` 或进程查看器确认PID、用户、命令和工作目录，再向明确对象发信号。源教程的 `pkill -f 'python.*train'` 会匹配多个任务，不作为通用安全快捷键；尤其不要把批量终止函数加入日常shell配置后盲用。

`jobs` 只显示当前shell作业；系统进程和另一个tmux里的作业不一定在其中。`Ctrl+Z` 暂停不是结束，`fg` 恢复前台运行。退出前确认进程实际状态，不从terminal消失推断设备内存已释放。

Linux systemd服务管理见[04 进程与调度](./04-进程-systemd-任务调度.md)。容器或WSL不一定以systemd作PID1，先观察再使用systemctl。

## 6. SSH、文件传输与端口转发

使用现有有权限的账号/密钥；验证主机指纹，不为消除报错禁用主机身份检查。示意：

```sshconfig
Host study-gpu
    HostName 203.0.113.50
    User learner
    IdentityFile ~/.ssh/study_key
```

地址是文档示例，需要改成你的服务器。默认无需 `ForwardAgent yes`；代理转发增加远端借用身份的能力，应按实际需要开启。

```bash
ssh study-gpu
scp ./metrics.json study-gpu:~/experiments/
rsync -av --dry-run ./data/ study-gpu:~/data/
# 看过计划后再去掉 --dry-run。
```

尾斜杠影响复制“目录内容”还是目录本身。rsync是否增量、高效或恢复部分传输取决于选项、协议和目标状态，不能把任何一次运行都说成自动续传。

远端Jupyter只监听远端回环地址时，用本地转发：

```bash
ssh -N -L 127.0.0.1:8888:127.0.0.1:8888 study-gpu
```

在本机访问本地8888进入远端服务。若本地端口占用可改本地端口；服务仍应保留认证。转发负责通道，不自动启动Jupyter。

## 7. 磁盘、权限和平台差异

先 `df -h` 看对应文件系统容量，再 `du -sh` 看项目/缓存占用。剩余空间应计入下载临时文件、解压、缓存、checkpoint与产物；`du` 与 `df` 差异也可能来自删除但仍被进程打开的文件。

Permission denied 不一定由缺执行位引起：目录遍历、ACL、只读挂载、noexec、用户身份等都可能影响。先查[权限模型](./03-用户-权限-文件系统.md)，不以sudo和chmod777作为默认排错。

macOS常见BSD工具与Linux常见GNU工具参数不同，`sed -i`、`stat`、`du --max-depth`等先看本机帮助。不同文件系统的大小写行为是格式/挂载属性，不是操作系统的绝对规则。Windows CRLF可使shebang尾部带回车，先检查实际文件再有目标地转换，避免全仓库盲改。

WSL2提供Linux环境；NVIDIA GPU路径需要支持的Windows驱动/WSL和库版本，不能在WSL内照搬Linux主机驱动安装。具体GPU与容器条件见[AI容器](../07-容器化与Docker/09-AI容器与硬件运行边界.md)。

## 7.1 让常见操作可复查，而不是积累不透明别名

实验目录按运行ID保存配置、日志、checkpoint和指标；代码提交、模型/数据版本也写入清单。比较两次结果前先确认指标定义相同，再用`diff`等工具看差异，而不只截取支持结论的日志行。

寻找大文件可以按扩展名与大小过滤；路径带空格时使用可靠的逐文件参数或NUL分隔方式。`find ... -o ...`需要括号表达正确的组合条件，不能让“是否是文件”只作用于一半分支。下载模型按明确URL/revision与校验；解压前知道目标目录与文件内容，别用来源中的浮动main权重当固定输入。

自定义别名只包装已经理解且边界明确的命令；GPU查询、进入项目环境等适合短化，批量结束进程、删除checkpoint等不应隐藏在模糊名字后。源站提醒或邮件示例里的“DONE”应在退出码和产物验证后才生成，不能无条件跟在流水线末尾；是否发送外部通知还需要具体任务授权。

## 8. 一次练习留下哪些证据

新目录写两行日志并提取loss → 在tmux中运行30秒程序再附着 → 查询准确PID → 看本地磁盘 → 如果已有远端权限，试一份小文件的dry-run同步。结果记录命令、运行位置、预期/实际输出；无远端权限的部分明确未做。

自查：tmux断开后程序继续，机器重启后还能继续吗？答案：不能自动保证，需checkpoint与重新调度。

自查：`command | tee log`最后退出0是否证明command成功？答案：默认常只反映最后命令，应结合pipefail与任务结果。
