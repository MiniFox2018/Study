## 4. 明确筛除或现代化替换的内容

### 4.1 CentOS 旧生态

不直接保存为新实践：

- CentOS 5/6/7 repo 文件；
- 大量固定 yum 源替换脚本；
- chkconfig、旧 runlevel、rc.local 作为新服务部署方式；
- network-scripts / ifcfg-* 作为现代默认网络配置；
- 固定版本中间件的一键安装脚本。

保留其背后的任务目标，并用当前通用模型重写。

### 4.2 网络与防火墙

不再把以下内容作为首选：

- ifconfig / route / netstat；
- 直接维护 iptables 作为新系统默认；
- “关闭防火墙后就好了”；
- 为省事禁用 SELinux。

主线采用 iproute2、ss、firewalld/nftables、最小权限和安全上下文排障。

### 4.3 时间同步

旧 ntpd/ntpdate 的配置过程不固化为默认。保留 NTP 原理，并以 chrony/system time sync 的现代模型理解。

### 4.4 软件安装

筛除：

- 固定下载链接；
- 已老化的 JDK8/Tomcat8/ELK/Kafka 等版本绑定；
- 未验证的一键 curl/wget + root 执行；
- apt-key 旧信任模型。

保留软件源信任、验证、部署、systemd、健康检查、备份、升级和回滚方法。

### 4.5 UI 与截图

Linux101 中大量虚拟机、桌面、商店和软件界面截图具有较强版本性。

主知识库只保留：

- 选择和操作原理；
- 网络/磁盘/架构等系统概念；
- 可迁移的命令与决策框架。

原始图片仍可从对应基准提交恢复。

## 5. Docker 去重策略

两个来源都含 Docker 内容，但 Study 已有独立且更新的：

- ../07-容器化与Docker/README.md

因此：

- Docker 生命周期、镜像、Dockerfile、Compose、Kubernetes 不重复写；
- Linux 主体只保留“容器依赖 Linux kernel 能力”的连接关系；
- Linux101 特有的 LXC/systemd-nspawn 作为容器生态补充进入现有 Docker 专题；
- dunwu 的旧 Docker 安装脚本和旧 Kubernetes 指南不覆盖当前基线。

## 6. 完整性标准

本次“完整吸收”不是复制每个旧字节，而是：

1. 两个仓库的知识目录、正文主题、脚本类别、运维类别全部建立映射；
2. 长期有效知识进入主学习路径；
3. 高重复内容合并到唯一维护入口；
4. 已失效实现明确记录筛除原因；
5. 重要来源 URL、许可证、commit SHA、规模与恢复路径保留；
6. 主库提供主体学习路径和最小练习；产品配置、内核细节与故障处置仍需目标系统手册和专项实践；
7. 如果要核验原句、图片或历史脚本，可按 commit 精确恢复。

## 7. 当前主学习覆盖

~~~text
Linux 与发行版
→ 命令行 / 文件 / 文本 / 正则
→ 用户 / 权限 / FHS
→ 进程 / 信号 / systemd / cron
→ 包管理 / 构建 / Python 环境 / 链接 / 交叉编译
→ IP / DNS / SSH / 防火墙 / SMB / 时间同步
→ CPU / 内存 / 磁盘 / I/O / 日志 / 排障

→ Docker / OCI / Kubernetes（链接现有专题）
~~~

这构成一套从入门到实际服务器操作与故障诊断的 Linux 主干。
