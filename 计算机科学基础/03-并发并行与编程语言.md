# 03｜并发、并行与编程语言

## 1. Concurrency 与 Parallelism

- **Concurrency**：多个任务在时间上交错推进；
- **Parallelism**：多个任务在同一时刻真正同时执行。

单核可以并发，多核/多设备才产生真正并行。

## 2. 共享状态的风险

两个执行流同时读写同一状态，会出现：

- race condition；
- lost update；
- torn read/write；
- visibility / ordering 问题。

关键不是“加锁就行”，而是尽量减少共享可变状态。

## 3. Locks 与 Atomics

Mutex 保护临界区；atomic 对特定读改写操作提供不可分割语义。

需要理解：

- lock granularity；
- contention；
- lock ordering；
- spin vs sleep；
- compare-and-swap。

## 4. Memory Model

编译器和 CPU 可能重排操作。多线程程序必须依赖语言和硬件定义的 happens-before / memory ordering，而不能只凭源码视觉顺序推理。

## 5. Deadlock

经典四条件：

1. mutual exclusion；
2. hold and wait；
3. no preemption；
4. circular wait。

工程中常用：

- 固定锁顺序；
- timeout；
- try-lock；
- 减少多锁临界区；

降低风险。

## 6. 高层并发模型

除了共享内存，还可以使用：

- message passing；
- channels；
- actor model；
- async/await；
- event loop；
- futures/promises。

选择模型时看任务是 CPU-bound、I/O-bound 还是分布式。

## 7. 数据并行与任务并行

- data parallel：同一操作处理不同数据；
- task parallel：不同操作同时执行；
- pipeline parallel：不同阶段流水执行。

这直接连接深度学习多卡训练和 GPU kernel。

## 8. 编程语言实现

语言通常通过：

- compiler；
- interpreter；
- bytecode VM；
- JIT；

把高级语义映射到机器执行。

## 9. Type System

类型系统的作用不仅是“防止传错参数”，还可表达：

- 数据表示；
- 接口契约；
- 所有权/生命周期；
- nullability；
- effect。

静态类型提高提前验证能力，动态类型提高运行时灵活性；两者不是简单优劣关系。

## 10. 内存管理

主要路线：

- manual allocation；
- RAII / deterministic destruction；
- reference counting；
- tracing GC；
- arena / region allocation。

C++ 的 RAII 与所有权模型应在 C++ 目录继续深入。

## 11. ABI 与 FFI

真实系统经常跨语言。ABI 定义二进制调用约定，FFI 让不同语言互调。

ML 框架常见：

```text
Python API
→ C/C++ runtime
→ CUDA/Metal/Vulkan kernel
```

因此理解语言边界对排查性能和内存问题很重要。
