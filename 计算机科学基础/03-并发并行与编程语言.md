# 03｜并发、并行与编程语言

## 1. Concurrency 与 Parallelism

- **Concurrency**：多个任务在时间上交错推进；
- **Parallelism**：多个任务在同一时刻真正同时执行。

单核可通过时间片让多个任务并发推进；多核更容易实现线程级并行。但单核内部也可能有流水线、SIMD 和指令级并行，不能把“一切并行”都限定为多核。

## 2. 共享状态的风险

两个执行流同时读写同一状态，会出现：

- race condition；
- lost update；
- torn read/write；
- visibility / ordering 问题。

关键不是“加锁就行”，而是尽量减少共享可变状态。

## 3. Locks 与 Atomics

Mutex 保护临界区；atomic 对特定读改写操作提供不可分割语义。

需要理解：

- lock granularity；
- contention；
- lock ordering；
- spin vs sleep；
- compare-and-swap。

## 4. Memory Model

编译器和 CPU 可能重排操作。多线程程序必须依赖语言和硬件定义的 happens-before / memory ordering，而不能只凭源码视觉顺序推理。

## 5. Deadlock

经典四条件：

1. mutual exclusion；
2. hold and wait；
3. no preemption；
4. circular wait。

工程中常用：

- 固定锁顺序；
- timeout；
- try-lock；
- 减少多锁临界区；

降低风险。

## 6. 高层并发模型

除了共享内存，还可以使用：

- message passing；
- channels；
- actor model；
- async/await；
- event loop；
- futures/promises。

选择模型时看任务是 CPU-bound、I/O-bound 还是分布式。

## 7. 数据并行与任务并行

- data parallel：同一操作处理不同数据；
- task parallel：不同操作同时执行；
- pipeline parallel：不同阶段流水执行。

这直接连接深度学习多卡训练和 GPU kernel。

## 8. 编程语言实现

语言通常通过：

- compiler；
- interpreter；
- bytecode VM；
- JIT；

把高级语义映射到机器执行。

## 9. Type System

类型系统的作用不仅是“防止传错参数”，还可表达：

- 数据表示；
- 接口契约；
- 所有权/生命周期；
- nullability；
- effect。

静态类型提高提前验证能力，动态类型提高运行时灵活性；两者不是简单优劣关系。

## 10. 内存管理

主要路线：

- manual allocation；
- RAII / deterministic destruction；
- reference counting；
- tracing GC；
- arena / region allocation。

C++ 的 RAII 与所有权模型应在 C++ 目录继续深入。

## 11. ABI 与 FFI

真实系统经常跨语言。ABI 定义二进制调用约定，FFI 让不同语言互调。

ML 框架常见：

```text
Python API
→ C/C++ runtime
→ CUDA/Metal/Vulkan kernel
```

因此理解语言边界对排查性能和内存问题很重要。

来源：Compendium Chapter 13 / concurrency, parallelism, programming languages。

## 12. 纸上模拟一次丢失更新

初始 `count=0`，任务 A、B 都执行“读取 → 加 1 → 写回”：

| 顺序 | A | B | 共享 count |
|---|---|---|---:|
| 1 | 读取 0 | | 0 |
| 2 | | 读取 0 | 0 |
| 3 | 写入 1 | | 1 |
| 4 | | 写入 1 | 1 |

业务想要 2，结果却是 1。这里用抽象操作说明竞态；在 C++ 普通变量上无同步地这样并发读写还构成未定义行为，真实机器不能限定为只输出 1 或 2。

修复应保护**完整读改写**：同一把锁包住三步，或用适当原子 `fetch_add`。若涉及“余额扣减 + 账本追加”两个状态，单独把余额改 atomic 仍不能保证事务一致。

自测：async/await 是否必然让 CPU 计算更快？答：不必然，它主要组织可等待的控制流；CPU 任务要有真实执行资源并行，还需计入调度、共享和同步成本。C++ 可运行练习见 [线程与同步](../C++/Core/14-Multithreading.md)。
