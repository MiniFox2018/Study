# 字节码与托管容器

同一个`grade`函数，放进ELF、Python pyc、JVM class、Wasm或.NET程序集以后，能直接读到的信息不同。反编译器输出中的名字，有些来自容器，有些来自调试资料，还有些只是工具猜测。先确定格式、版本与元数据来源，才能评价输出是否可信。

本章接续[文件布局](01-二进制布局与装载地址.md)、[控制流](03-控制流与中间表示.md)、[类型恢复](04-数据布局与类型恢复.md)与[证据边界](05-静态与动态证据.md)。下面采用固定教材提交`1a8c4fd`的受控案例，原构建/工具捕获为作者2026-10-14记录；本库2026-10-19只做静态读取和自编格式核对，没有运行这些字节码或来源工具。

## 1. 先识别容器，再问它保留了什么

| 容器 | 身份与解释规则 | 本例保留的重要信息 |
|---|---|---|
| 无debug的ELF对象 | ELF身份、架构与重定位规则 | 普通符号中的函数名，机器码与数据引用 |
| CPython pyc | 完整magic、失效校验flags、版本相关marshal/操作码 | code object中的名字、常量、变量名、行号等 |
| JVM class | CAFEBABE、major/minor、大端结构 | 常量池、成员名、描述符、Code及可选属性 |
| Wasm | `00 61 73 6d 01 00 00 00`，节与功能集合 | 类型、导入导出、结构化控制流及可选custom资料 |
| CLI程序集 | PE目录14、CLI header、BSJB metadata | 类型/方法/参数表、签名、方法体和引用 |

这些是需要继续核对的格式线索，不是只匹配几个字节就接受所有输入。CAFEBABE也可能出现在其他格式语境中，pyc不能只认末尾CRLF，PE的MZ也不独立证明含托管代码。未知版本、未支持的扩展和范围错误应明确返回，不继续猜。

“格式版本”也不总能精确定位生产工具版本。class major 65表示相应Java目标格式，不证明一定由某个JDK21补丁版本生成；新JDK也可以面向较旧目标。CLI的metadata版本字符串同样不能单独推出SDK发行版。

## 2. pyc的16字节头：缓存有效性与程序可信度分开

PEP552扩展后的头包含四个32位word：完整magic、flags，以及由flags解释的后8字节。timestamp模式存源码mtime和size；hash模式存源码hash，低位表示hash-based，第二位在hash模式下表示check_source。校验是否实际执行还受解释器配置影响。[PEP552规范](https://peps.python.org/pep-0552/)。

本例CPython3.14格式文件：

| 范围 | checked-hash文件 | timestamp文件 |
|---|---|---|
| 0–3 | `2b 0e 0d 0a` | 相同magic |
| 4–7 | `03 00 00 00` | `00 00 00 00` |
| 8–15 | `c7 16 c7 fc c5 1d 81 01` | mtime=1791975565，source size=497 |

magic低16位为0x0e2b=3627；官方CPython v3.14.0头定义了这个值。它标识格式，不足以从文件本身恢复“3.14.6”这一精确补丁版本，后者来自作者构建记录。[固定版本magic定义](https://github.com/python/cpython/blob/v3.14.0/Include/internal/pycore_magic_number.h)。

同版本的checked-hash和timestamp文件，本例头之后的正文逐字节相同；跨四个解释器版本的checked-hash却分别为`1b5a702842c9735e`、`061caab0af109ffd`、`c90c8ed16ba16dce`和`c716c7fcc51d8101`，不能说“除了magic整个header都相同”。这类hash用于缓存与源码一致性，不是作者签名，也不证明程序可信或已经执行。

## 3. code object里的名字不是源码本身

本例marshal正文首字节为0xe3，即`c`类型加FLAG_REF。类型标记后按该版本布局读取code object：参数计数、stack size和flags，代码bytes、consts、names、localsplus名字/类别、filename/name/qualname、first line、line table与exception table等。嵌套函数code object位于常量中，引用标记允许重复对象通过索引表示。

| 信息 | 本例用途 | 不能混淆的概念 |
|---|---|---|
| co_code | 操作码与操作数字节 | 不等于跨版本稳定ISA，也不保证就是当前执行的自适应流 |
| co_consts | 数值、字符串、tuple及嵌套code等 | 不是只存简单字面量 |
| co_names | 全局/属性等名字索引 | 不是所有局部变量的统一名字表 |
| localsplusnames/kinds | 局部、cell与free等分类 | closure变量和普通参数不一定可按简单切片区分 |
| co_qualname/filename | 函数限定名和记录的源码路径 | 路径是元数据，不证明文件在当前机器存在 |
| 行号/异常表 | 调试映射与异常控制流 | 只看显式jump不等于恢复完整CFG |

marshal的code格式不承诺跨Python版本兼容。正确读取一个已知子集，不等于能将未知文件直接交给本机marshal或构造可执行code object。递归引用要在读子对象前安排好身份，限制长度、深度与引用索引，并核预期类型和完整消费；把“尚未完成的引用”占位为None后当成真实对象返回会产生错误结构。

本库仅用自编数据容器解读本例8个pyc，没有生成真实Python code object、调用原marshal/dis或执行其中代码。四版本都能静态读到grade的`score/bucket`、filename=`ledger.py`与首行10；不代表原源码的注释、所有名称和声明类型全部还原。注解与相关类型表达式也可能作为其他元数据/代码存在，不能概括所有pyc“一概没有任何类型信息”。

### 操作码版本与inline cache

本例grade的co_code大小依次为80、62、70、96字节，对应3.11–3.14；历史dis捕获列出31、26、26、35条非cache指令。3.12/3.13使用RETURN_CONST等形态，3.14案例出现LOAD_SMALL_INT、LOAD_FAST_BORROW和NOT_TAKEN。它们解释旧反编译器为何可能报不支持，不构成“文件一定混淆”的证据。

3.11以后某些操作带inline caches，默认dis视图可隐藏这些位置。分析跳转时必须使用对应版本的偏移单位和cache规则，不能把打印行数乘2就当完整字节位置。`show_caches`用于看缓存，`adaptive=True`用于看可能不同于原始流的特化指令；公开co_code可能由解释器按需生成，不一定等于实际执行的内部字节流。原课“特化形式就在同一个co_code里”的说法应作此修正。[Python3.14 dis](https://docs.python.org/3.14/library/dis.html)、[code object接口说明](https://docs.python.org/3.14/c-api/code.html#c.PyCode_GetCode)。

## 4. JVM class：从常量池引用链读出方法

class按大端读取：magic、minor/major、constant_pool_count及池，再读access flags、this/super、interfaces、fields、methods、attributes。本例`Ledger-g.class`前10字节为`ca fe ba be 00 00 00 41 00 5e`，major65，池计数94；计数包含保留的0号位置，并非94个普通条目。[JVMS第4章](https://docs.oracle.com/javase/specs/jvms/se25/html/jvms-4.html)。

| 常量tag | 数据与用途 |
|---|---|
| 1 Utf8 | 长度＋Modified UTF-8字符串 |
| 3/4 Integer/Float | 4字节数值编码 |
| 5/6 Long/Double | 8字节，并占两个常量池位置 |
| 7 Class、8 String | 指向相应字符串条目的索引 |
| 9/10/11 Fieldref/Methodref/InterfaceMethodref | class索引＋NameAndType索引 |
| 12 NameAndType | 名字索引＋descriptor索引 |
| 15 MethodHandle | reference_kind＋reference_index |
| 16 MethodType | 方法descriptor索引 |
| 17/18 Dynamic/InvokeDynamic | bootstrap索引＋NameAndType索引 |
| 19/20 Module/Package | 名字索引 |

不能用普通UTF-8加replace吞掉Modified UTF-8差异：其中NUL和补充字符编码不同。还要按tag核索引指向的条目类型，避免把一个有效数字索引指向错误对象仍称解析成功。

本例#13是Methodref，指向Class #8与NameAndType #14；#14再指向#15=`grade`与#16=`(I)I`。由此得到`Ledger.grade:(I)I`：参数int，返回int。descriptor中B/C/D/F/I/J/S/Z分别表示byte/char/double/float/int/long/short/boolean，V表示void返回，`[I`是int数组，`Ljava/lang/String;`是引用类型。源泛型信息和普通descriptor不是同一层，应另看相关属性。

Code属性保存max_stack、max_locals、代码数组、异常表及其属性。max_locals按slot计算，long/double占两slot；实例方法还要考虑this。仅按LocalVariableTable某行start=0，就将它当参数是不可靠的，应联合descriptor、access flags、slot宽度和作用域。

`javac -g`的本例有局部变量表，默认构建保留行号/源文件而没有该表，`-g:none`去除这些debug属性。本库独立核过四个构建的全部7个方法Code数组相同；属性和常量池仍不同。这是当前fixture结果，不是所有编译器/选项组合的保证。形参名字还可能来自MethodParameters属性，不能将它与LocalVariableTable或`-g`绑定为同一件事。StackMapTable、BootstrapMethods等承担验证/链接所需的信息，不能全当可随便删除的调试垃圾。

## 5. JVM tableswitch：坐标基准与padding都要正确

grade代码先将score除10；pc4处opcode0xaa表示tableswitch。其后补3字节，使后续32位字段在方法code坐标中4字节对齐，随后大端读取default、low、high和目标位移。

| 字段 | 原始值 | 实际目标 |
|---|---|---|
| default | 44 | pc4+44=48 |
| low/high | 6/10 | 共5个case |
| case6 | 42 | 46 |
| case7 | 40 | 44 |
| case8 | 38 | 42 |
| case9/10 | 36/36 | 都到40 |

该指令长36字节，下一条位于40。JVM branch/switch位移相对opcode起点，不能套x86“下一指令＋位移”。lookupswitch使用key/offset对，wide扩展特定局部变量操作的索引/增量，二者均需按真实格式读取。还需核目标是合法指令边界、switch数量与键条件、操作数栈及异常表；列出操作码不是完成JVM验证。[JVMS tableswitch](https://docs.oracle.com/javase/specs/jvms/se25/html/jvms-6.html#jvms-6.5.tableswitch)。

作者四份javap-c捕获各列108条指令；本库这里直接核容器中的Code数组和上述switch字段。多份工具拼写相同、或原课程自报108/108，不能替代对照材料是否完整、是否来自同一个摘要文件的检查。按方法顺序zip比较还需核名字和descriptor，避免同名重载或重排被错配。

## 6. Wasm：先读节，再读结构化分支

Wasm先是8字节preamble，再重复“section id、u32 LEB长度、payload”。custom节id0可以放在允许位置，其余节按规范规定的顺序至多出现一次；**顺序不总是id大小顺序**。例如DataCount(id12)在Code(id10)前，Tag(id13)在Global(id6)前。Function与Code中的定义数量需相同。[Wasm模块编码](https://webassembly.github.io/spec/core/binary/modules.html)。

本例有Type、Import、Function、Memory、Export、Code、Data七节。导入`env.log`占函数索引0，因此四个定义函数从1开始，grade为2。Function节给类型索引，Code节给各函数体；不要把“第几个定义”直接当全模块函数索引。

| 信息 | 本例内容 |
|---|---|
| 类型 | `(i32)->无返回`、`(i32,i32)->i32`、`(i32)->i32` |
| 线性内存 | 最小1页，本例无最大值声明 |
| 导出 | memory及四个函数名 |
| Data | 从线性内存偏移1024放`F\0D\0C\0B\0A\0` |
| name custom | 仅带名字版本额外保存函数/局部变量名 |

grade的body从文件0x8b开始，包含locals声明；第一条opcode在0x8e。body长度63包括3字节locals声明，真正指令区60字节。不同工具若分别显示body、locals或code起点，地址不同并不自动是错误；原文将0x8b称为size字段位置应纠正，大小字段在它之前。

### LEB128不是所有格式共用的一种“变长整数”

无符号LEB每字节低7位参与数值，高位表示后续字节；例如`80 01`为128。Wasm u32最多5字节，第5字节剩余位受约束。signed LEB还需按终止字节的符号位扩展，`7f`可表示−1。浮点常量则是固定宽小端IEEE字节，不能说Wasm所有数值都用LEB。

下面的自写函数只读Wasm式u32 LEB及声明边界，返回值和下一个位置，允许规范范围内的非最短编码；它不读signed LEB，也不适用于CLI压缩整数。

```python
def read_u32_leb(data, offset=0, limit=None):
    """只读一个有界u32 LEB；不解释或执行字节码。"""
    limit = len(data) if limit is None else limit
    if not 0 <= offset <= limit <= len(data):
        raise ValueError("读取范围无效")
    value = 0
    for index in range(5):
        if offset == limit:
            raise ValueError("LEB被截断")
        byte = data[offset]
        offset += 1
        if index == 4 and byte & 0xF0:
            raise ValueError("超过u32位宽或字节数")
        value |= (byte & 0x7F) << (7 * index)
        if byte < 0x80:
            return value, offset
    raise ValueError("LEB超过5字节")
```

这避免了“用Python大整数读到终止字节就算合法u32”的错误；外层仍须核section/函数体/子节范围、数量与资源限制。[Wasm整数和浮点编码](https://webassembly.github.io/spec/core/binary/values.html)。

### br_table里的数字是深度

grade在0xa3有14字节`0e 0b 04 04 04 04 04 04 03 02 01 00 00 04`：0e是br_table，0b表示11个索引项，随后是11个label depth和default depth。bucket0–5去depth4，6/7/8分别去3/2/1，9/10去0，default去4。

depth0是当前最内层label，数字不是文件地址。对应block的end后放不同返回值，再跳出结果block；loop label又有自己的跳转含义。结构已编码仍需做类型与控制栈验证：深度合法、不同分支的结果类型一致、else/end配对和终止表达式完整。本课读取器对若干节直接跳过、对扩展prefix明确不支持，不能将其“能列本例77条指令”当成完整Wasm验证器。

无name节的模块仍有export名字grade，局部score/bucket则缺失。带name版本从290增到425字节，核心节保持一致。custom也可承载DWARF/source map等资料，不能说所有局部名字只可能来自name节，或wasm-strip一定只删它。wasm2wat便于恢复表达式结构，不自动承诺保留原始WAT排版、所有custom、非最短整数编码和每个NaN位模式；往返的语义、元数据和逐字节一致要分别定义。

## 7. CLI程序集：PE中的元数据数据库

本例LedgerNet.dll是PE32，目录14指向RVA0x2008的72字节CLI header。它再给metadata RVA0x2178、size1924、ILONLY flags和入口token0x06000005。Machine=0x14c不独立证明一定AnyCPU或可在所有平台运行，还要核CLI flags、原生混合内容及运行时条件。

metadata根以BSJB开始，带版本字符串与stream目录；本例有`#~`、`#Strings`、`#US`、`#GUID`、`#Blob`。这些stream的offset以metadata根为基准，不是RVA，也不是文件偏移。RVA换文件位置沿用[完整file-backed范围规则](07-链接装载与无符号分析.md#从rva找到真正的文件范围)。

| 表/heap | 内容 |
|---|---|
| Module/Assembly/AssemblyRef | 模块与程序集身份、引用 |
| TypeRef/TypeDef/NestedClass | 类型名字、定义与关系 |
| Field/FieldRva/ClassLayout | 字段、初始化数据位置和布局 |
| MethodDef/Param | 方法RVA/flags/名字/签名、参数记录 |
| MemberRef/CustomAttribute | 外部成员引用与属性 |
| StandAloneSig | 如局部变量类型签名 |
| #Strings/#US | 元数据UTF-8名字与用户字符串；不能混用索引 |
| #GUID/#Blob | GUID与长度前缀二进制blob |

表row size由schema、heap索引宽度和row counts计算。本例HeapSizes=0，所以S/G/B索引均2字节；普通表索引在目标row数达到65536时需4字节；带b个tag位的coded index，在候选表最大row数达到`2^(16−b)`时需4字节。先算所有表的行宽和起点，再读取具体行，否则一个错位会污染后面的每张表。

token高8位表示表，低24位是1起始row；`0x06000002`是MethodDef第2行。它的RVA为0x2060、Name为Grade，签名blob`00 01 08 08`表示本例的静态int32(int32)。ParamList定位到Param表中的score；实际处理需按Sequence识别形参及可能的返回值记录，不能只把所有名字顺序切出来。

blob中的压缩整数是ECMA335规定的1/2/4字节前缀编码，**不是LEB128**。例如128编码为`80 80`，而非Wasm的`80 01`。泛型参数数、形参数和TypeDefOrRef等编码也要按它们的具体规则读取；用一个u8或通用ULEB替代，只在小值fixture里碰巧成立。这里以ECMA335第II部分的metadata/signature定义为基础；完整实现还应区分规范与运行时补充规则。[ECMA335入口](https://ecma-international.org/publications-and-standards/standards/ecma-335/)、[.NET运行时规范补充](https://github.com/dotnet/runtime/blob/main/docs/design/specs/Ecma-335-Augments.md)。

### tiny/fat方法头与CIL switch

Grade的fat头前两字节`13 30`给flags0x13及header长度3个dword，接着MaxStack=2、CodeSize=45、LocalVarSigTok=0x11000001。局部签名`07 01 08`表示一个int32局部变量，名字不在这个签名里。本例DebugType=none，没有保存bucket名字；其他构建的PDB可能独立存在或嵌入映像，不能仅凭外面没有.pdb就断定没有debug资料。

PercentChange使用tiny头，首字节0x3a，即长度14左移2再加类型2，隐含MaxStack=8、没有局部签名。fat头实际长度应按字段读取，可能还有对齐后的附加section/异常区域；不能把“本例12字节”硬编码成所有方法头的总长度。

Grade的CIL先除10再减6，IL偏移8的0x45是switch。之后u32 count=5，五个i32位移为8、6、4、2、2；基准是整张表之后IL0x21，所以目标为0x29、0x27、0x25、0x23、0x23。这里与JVM opcode-relative基准不同。普通短/长CIL branch也要核其各自操作数长度与下一指令基准，prefix、token类型和异常边不能忽略。

本库自编读取核了本例14张表的宽度/范围及6个方法的全部IL字节，与作者MetaDump捕获一致；没有运行MetaDump、.NET程序集或课程原reader。原课程“246/246 checks”还包含8个被跳过的prefix占位，数量不等于每项都做了同样深度的验证，更不能将reference为空时的无冲突当作完整通过。

## 8. 横向比较要写清范围

| 固定本例 | 函数/方法名 | 参数与返回类型 | 参数名/局部名 | 控制流形态 |
|---|---|---|---|---|
| 无debug ELF | 普通符号可有 | 不由该表完整提供 | 未保存于此例debug资料 | 机器分支、值表或间接跳转 |
| pyc | qualname等 | 动态对象语义；该例未存声明类型 | score/bucket等 | 版本相关比较与jump |
| javac -g class | 成员名 | descriptor | 参数/局部名见作用域表 | tableswitch等字节码 |
| 普通Wasm | export可命名 | 参数/结果valtype | 本例需额外name节才有局部名 | block/loop/if与深度label |
| CLI，无PDB | MethodDef | 签名blob | Param有score，局部只知类型 | switch与branch，另有异常区域 |

字节长度不可直接横比效率：Wasm的63字节body含locals声明，JVM50和CIL45指的是各自Code数组；运行时JIT、解释器、原生代码和内存布局更不在同一个尺度。

元数据比较也不意味着跨语言全输入等价。原Python版用`bucket >= 9`，score110时返回4；C/JVM/CIL/Wasm的switch只接受9和10，110落default返回0。Python负数`//`向下取整，其他例中的有符号整数除法通常向零；固定宽整数、溢出、除零与trap/异常也不同。Wasm grade_label还调用导入env.log，带有额外可观察效果。只比较0–100常见分数或一条成功输出，不能抹掉这些边界。

## 9. 从文件到可审查结论

1. 绑定完整摘要、格式、版本事实、生产命令和输入域；文件名只辅助定位。
2. 按声明范围读取header、表、heap和代码，拒绝未知形态，记录跳过内容与不支持的features。
3. 对函数逐项说明名字、类型、局部、行号和控制流来自哪个表，哪些是工具推断。
4. 核对应版本的操作码、分支坐标、cache/locals/异常区域；解析、验证与执行分开。
5. 使用同一文件的reference，核方法/descriptor或函数索引、必需集合、完整性与extra项；不要只用zip或空mismatch列表判断全覆盖。
6. 解码错误先区分版本不支持、格式损坏、扩展未实现与真实混淆，不凭一条报错下结论。
7. 修改解释器/JDK/SDK/assembler后按新摘要重新登记，不将旧capture改日期当新验证。
