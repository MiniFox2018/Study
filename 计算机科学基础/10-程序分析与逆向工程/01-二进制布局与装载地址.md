# 二进制布局与装载地址

读一个编译后的程序，第一步是回答“哪些字节属于什么结构、这些数值使用什么坐标”。机器码反汇编、函数识别和反编译都依赖这一步。把符号值误当文件偏移，后续即使生成漂亮的控制流图，也可能分析了错误的字节。

先修是十六进制、位运算、字节序，以及[体系结构与操作系统](../02-计算机体系结构与操作系统.md)中的地址空间、进程和编译链接。这里以明确允许分析的教学文件为对象，只解释文件结构；读取文件不需要执行它。原作者编译过样本，不代表本库或学习者已经在自己的环境复现。法律适用因对象、行为和法域而异，本章不把原课列举的外国例外当普遍许可。

## 1. 一个文件的三种坐标

| 坐标 | 意义 | 使用前必须知道什么 |
|---|---|---|
| 文件偏移 file offset | 从文件第0字节起的位置 | 对应哪一份完整文件及其长度 |
| 节内偏移 section offset | 从某个section起点计算的位置 | section索引；不同节的0并非同一位置 |
| 链接虚拟地址 linked VA | 链接布局中的地址 | 对应映像及装载段，不能直接当运行时地址 |
| 运行时地址 runtime VA | 当前进程实际地址空间的位置 | 装载偏移、映射、进程与时间点 |

例如，`.text`在文件偏移`0x40`开始，函数在该节内偏移`0x10`，它的文件位置为`0x50`。如果映像在另一个基址装载，运行时地址改变，这两个文件偏移不因此改变。记录地址时同时记录坐标种类、目标文件摘要和section/映像身份；“函数在0x10”不是完整描述。

同一源码也不是同一产物。目标架构、优化等级、编译器和链接器版本、SDK、编译选项、链接依赖都可能改变字节。比较工具结果前先确认它们分析的是相同文件，或明确记录工具装载后应用了哪些重定位。

## 2. ELF为什么有section和segment两套表

ELF把面向链接的内容组织成section，例如`.text`、`.rodata`、符号表和重定位表；装载时则用program header描述segment，例如哪些文件字节映射到哪些虚拟地址、授予什么访问权限。一个segment可包含多个section。section不是操作系统分页单位，segment也不是一个函数。

常见`e_type`：

- `ET_REL=1`：可重定位目标文件，通常是尚待链接的`.o`；不能把它直接当已有完整运行地址的可执行程序。
- `ET_EXEC=2`：可执行映像。
- `ET_DYN=3`：共享对象类型，也常用于位置无关可执行文件；仅凭这个枚举不能断定它是普通共享库。
- `ET_CORE=4`：进程核心转储，需要按转储语境解释。

文件开头固定放ELF header，其他结构通过header或表项中的偏移找到，不能假设永远紧跟某个结构。某些可执行映像没有section header仍能装载；因此“节表为空”不能推出“没有代码”。装载也涉及解释器、动态链接信息和运行环境，不能把“program header是映射入口”夸张成装载器只读这些字段就足够。[ELF header定义](https://refspecs.linuxfoundation.org/elf/gabi4%2B/ch4.eheader.html)、[program header与装载](https://gabi.xinuos.com/elf/07-pheader.html)。

## 3. 先读身份，再选结构布局

前16字节是`e_ident`：前4字节`7f 45 4c 46`表示ELF，索引4给class，索引5给字节序，索引6给格式版本，索引7/8给OSABI与ABI版本。class为2才是ELF64，data为1才是小端。本章的小端64位例不能直接用于ELF32、大端或其他容器。

ELF64基础header共64字节。去掉16字节身份后，Python标准库的显式小端布局是`<HHIQQQIHHHHHH`：

| 字段 | 宽度 | 解释 |
|---|---:|---|
| e_type、e_machine | 各2字节 | 文件种类与指令集；x86-64的machine为62 |
| e_version | 4字节 | ELF版本 |
| e_entry | 8字节 | 入口的链接虚拟地址；0可表示无入口 |
| e_phoff、e_shoff | 各8字节 | program/section header表的文件偏移 |
| e_flags | 4字节 | 处理器相关标志，按对应ABI解释 |
| e_ehsize | 2字节 | header自身大小 |
| e_phentsize、e_phnum | 各2字节 | program header表项大小与数量 |
| e_shentsize、e_shnum | 各2字节 | section header表项大小与数量 |
| e_shstrndx | 2字节 | 节名字符串表的section索引 |

`<`除了选择小端，还避免按运行本机的C布局插入对齐。ELF64不等于所有成员都8字节，也不等于所有C指针模型都相同。x86-64还有不同数据模型，不能仅凭CPU名称忽略文件class。

第一来源的固定O1教学对象中，`e_type=1`、machine=62、`e_phnum=0`、`e_shoff=0x428`、`e_shentsize=64`、`e_shnum=11`、`e_shstrndx=1`。节表区间是`[0x428, 0x428+11×64)`，即到`0x6e8`，共1768字节文件的末尾。这里的数值来自作者固定样本和静态记录，不是本轮执行其reader得到的新输出。

### 一个可单独理解的header读取例

下面是本库自写的窄教学函数：只读ELF64小端基础header，检查表的文件范围，明确拒绝扩展编号。它不解析节内容、字符串、指令或动态链接，也不会启动文件。

```python
import struct

def elf64le_header(data):
    if len(data) < 64:
        raise ValueError('ELF64 header不足64字节')
    if data[:4] != b'\x7fELF' or data[4:7] != b'\x02\x01\x01':
        raise ValueError('本例只接受ELF64、小端、版本1')
    keys = ('type', 'machine', 'version', 'entry', 'phoff', 'shoff',
            'flags', 'ehsize', 'phentsize', 'phnum', 'shentsize',
            'shnum', 'shstrndx')
    h = dict(zip(keys, struct.unpack_from('<HHIQQQIHHHHHH', data, 16)))
    if h['version'] != 1 or h['ehsize'] != 64:
        raise ValueError('不支持的header版本或大小')
    if (h['phnum'] == 0xffff or h['shstrndx'] == 0xffff or
            (h['shoff'] != 0 and h['shnum'] == 0)):
        raise ValueError('本例未实现扩展编号，不能当作空表')
    for off, count, width, expected in (
        (h['phoff'], h['phnum'], h['phentsize'], 56),
        (h['shoff'], h['shnum'], h['shentsize'], 64),
    ):
        if count:
            if off < 64 or width != expected or off > len(data):
                raise ValueError('表位置或表项尺寸不支持')
            if count > (len(data) - off) // width:
                raise ValueError('表超出文件范围')
        elif off != 0:
            raise ValueError('本例要求不存在的表使用零偏移')
    if h['shstrndx'] != 0 and h['shstrndx'] >= h['shnum']:
        raise ValueError('节名表索引越界')
    return h
```

使用时把已获准读取的文件字节传入，返回字段字典。不要先对不受控偏移调用`unpack_from`再用异常猜格式。函数对64/56/64的严格限定是教学子集，不是声称未来所有ELF控制结构都不得扩展；完整实现应按支持的格式版本处理额外信息。没有program header时，`e_phentsize`可以是0，不能无条件要求它为56。

不需要原文件也能练习这个函数。在定义之后运行下面的自造header样本；它只是一段64字节结构数据，不是完整可执行文件。预期返回type=1、machine=62、shnum=0。再把class改为1或删去最后一个字节，应分别触发格式拒绝和长度拒绝。

```python
sample = bytearray(64)
sample[:7] = b'\x7fELF\x02\x01\x01'
struct.pack_into('<HHIQQQIHHHHHH', sample, 16,
                 1, 62, 1, 0, 0, 0, 0, 64, 0, 0, 0, 0, 0)
print(elf64le_header(sample))
```

## 4. 节表、字符串表与范围验证

ELF64节表项是64字节，布局`<IIQQQQIIQQ`。字段依次是`sh_name/type/flags/addr/offset/size/link/info/addralign/entsize`。其中：

- `sh_offset/size`描述文件内容区间；`sh_addr`描述映像地址，二者不能互换。
- `sh_name`是节名字符串表中的字节偏移；字符串在该表内遇到NUL结束。不能越过字符串表继续找终止符。
- `sh_link/sh_info`含义取决于section类型，不能统一当地址。符号表的link指符号名字符串表；RELA的link指所用符号表，info指被修改的节。
- `sh_entsize`是表项大小，0可表示该节不是固定记录数组；`sh_addralign`是对齐约束。

不要按名字硬找`.strtab`或`.shstrtab`代替索引关系。固定样本恰好由第1节`.strtab`兼任节名与符号名字符串表；另一文件可能分开存放。多个符号表或多个重定位表也不能都强行连接到遇到的第一张表。

`.text`常放指令，`.rodata`常放只读数据，`.data`常放可写初值，`.bss`通常用`SHT_NOBITS`表示不占文件内容的存储。NOBITS的size可非0，仍不能切出同样多的文件字节。节的语义首先看type/flags与引用关系，名字只是辅助。[section字段与NOBITS](https://gabi.xinuos.com/elf/03-sheader.html)。

固定O1样本的关键区间为：header`[0,0x40)`，`.text`从`0x40`起长`0x9f`，`.rodata`从`0xe0`起长`0x50`，`.symtab`从`0x170`起长`0x138`，节表从`0x428`起长`0x2c0`。`.text`结束于`0xdf`，到`.rodata`有1字节间隙；这份样本的生产过程支持将其解释为对齐。对未知文件，未被表覆盖只表示尚未归属，不能自动称为“安全padding”或“无用数据”。

解析器至少检查非负范围、偏移不超过文件长、长度不超过剩余字节、记录尺寸与整除关系、索引范围和字符串终止。Python切片越界会静默截短，所以`data[off:off+size]`不构成边界检查。数量特别大还需要资源上限；文件格式层面的有效不保证后续任意算法不会耗尽内存。

## 5. 符号值何时是偏移，何时是地址

`Elf64_Sym`是24字节，布局`<IBBHQQ`：name、info、other、section索引、value、size。info的高4位是binding，低4位是type；常见binding为LOCAL/GLOBAL/WEAK，type为NOTYPE/OBJECT/FUNC/SECTION/FILE。符号名通过该符号表的link取得，不从任意同名字符串表读取。

普通已定义符号的换算分两种：

| 文件语境 | st_value含义 | 文件偏移计算 |
|---|---|---|
| ET_REL | 所属节内偏移 | `section.sh_offset + symbol.st_value` |
| ET_EXEC/ET_DYN的普通地址符号 | 链接虚拟地址 | 先定位文件支撑的section/segment，再减其VA起点并加文件起点 |

原教材把`sh_offset+st_value-sh_addr`写成通用公式；它在示例ET_REL的sh_addr=0时碰巧成立。ET_REL应依据“st_value本身就是节内偏移”计算，不因为某字段恰为0才推导规则。`SHN_UNDEF`、`SHN_ABS`、`SHN_COMMON`、TLS及其他特殊符号另有含义，不能直接当普通节内函数；size为0还可能表示未知大小。[gABI符号值规则](https://gabi.xinuos.com/elf/05-symtab.html#symbol-value)。

固定样本的`grade`：`.text.sh_offset=0x40`、st_value=`0x10`、st_size=46，因此字节区间为`[0x50,0x7e)`。后面的`66 90`是这份样本的对齐指令，不能多算进函数使其变为48字节。原`percent_change`位于文件`0x40`，size为16；它在symbol表中value=0，绝非文件开头16字节。

符号是有用的边界证据，仍不是源码恢复的唯一真值。剥离符号、别名、热冷分割、内联及零size会使“下一符号减当前符号”失效。即使有FUNC类型，也需要核section归属和范围；函数地址相同的别名不能让覆盖游标倒退。

## 6. 重定位：零占位不是最终操作数

可重定位对象里的跨节/外部引用常尚未定址。RELA记录显式给addend，ELF64布局为`<QQq`，共24字节；REL不含显式addend，需按对应规则从被修改字段取得。`r_info >> 32`是符号索引，低32位是重定位类型。

ET_REL的r_offset是被修改节内的偏移；可执行/共享映像中的r_offset按虚拟地址解释。先跟该重定位节的link/info找符号表和目标节，再读被修改位置。未知类型应保留数值、报告未支持，不能猜“都是4字节补丁”。[gABI重定位结构与坐标](https://gabi.xinuos.com/elf/06-reloc.html)。

在本章x86-64 LP64例中，S表示符号值，A是addend，P是被修改存储字段的位置，L是相应PLT入口：

| 类型 | 字段 | 计算 |
|---|---|---|
| R_X86_64_64 | 64位 | S+A |
| R_X86_64_PC32 | 32位 | S+A−P |
| R_X86_64_PLT32 | 32位 | L+A−P |

这些规则属于架构ABI，不能移植成任意CPU的统一表；还要检查对应结果范围及链接器允许的解析/松弛行为。[x86-64 psABI原始定义](https://gitlab.com/x86-psABIs/x86-64-ABI/-/raw/master/x86-64-ABI/object-files.tex)。

### 为什么addend是0x10，目标却在0x14

固定样本的LEA在节内`0x33`，字节为`48 8d 0d 00 00 00 00`。四字节位移字段起点是`P=0x36`，下一条指令在`0x3a`。目标是`.rodata+0x14`，CPU实际计算“下一指令地址＋位移”：

`0x3a + (S + 0x10 − 0x36) = S + 0x14`。

相差的4来自位移字段到下一指令的距离；不能把每个重定位的addend无条件加4，也不能仅看到四个零就说“引用本指令附近”。如果目标节尚无链接地址，只能给符号表达式；不要伪造已确定的最终位移。

这份源码在O0使用跳转表选择case、五个绝对指针表示labels；在O1改用值表`1,2,3,4,4`、相对字符串表，并内联grade。值表返回数据，跳表产生控制流，两者不能混称。优化后的函数更长也不必更慢：total在样本中从O1的31字节增长到O2的140字节，后续需结合向量循环和尾部处理分析。

## 7. 通过PT_LOAD换算装载地址

ELF64 program header为56字节，布局`<IIQQQQQQ`，字段是type、flags、offset、vaddr、paddr、filesz、memsz、align。对PT_LOAD，文件大小不得大于内存大小，多出的内存部分补零；对齐为0/1表示无需额外约束，其他值按要求核幂次和同余关系。

给一个链接VA，先找包含它的PT_LOAD：

- 在`[p_vaddr, p_vaddr+p_filesz)`内，文件偏移为`p_offset+(VA-p_vaddr)`。
- 只在`[p_vaddr+p_filesz, p_vaddr+p_memsz)`内，属于零填充内存，没有对应文件内容字节。
- 不在相关映射内，报告未映射；有歧义则保留歧义，不能随便挑第一项。

教学tiny文件的PT_LOAD从文件0、VA`0x400000`开始，filesz=memsz=`0x2e0`。入口`0x4000b0`对应文件`0xb0`。这是地址算术，不表示本库运行过该Linux x86-64程序。若运行时装载偏移为B，应先从运行时地址中扣除B再作映射；若当前地址属于新分配或改写内存，更不能保证原文件仍有一一对应字节。

固定tiny还用PT_GNU_STACK描述栈权限；它不是第二段文件代码。将整个文件映射为RX是该小样本的简化构造，不是生产链接布局建议。正式执行权限还由平台和策略落实，不能从标志表反推运行环境已经正确配置。

## 8. 把同样的问题带到Mach-O

Mach-O先读32字节的mach_header_64，再按ncmds与sizeofcmds遍历load commands。每条command有cmd/cmdsize，下一条从当前起点加cmdsize找到。检查cmdsize至少能装下基本头、整条位于声明命令区内、section数组能装进其父命令，不能只检查整个文件长度。

| ELF概念 | Mach-O对应入口 | 注意 |
|---|---|---|
| 文件身份/目标 | mach_header_64 | magic、CPU、filetype与thin/universal分别判 |
| section与装载布局 | LC_SEGMENT_64及其section_64数组 | section以segment名和section名共同标识 |
| 符号/名字表 | LC_SYMTAB的symoff/nsyms/stroff/strsize | nlist_64没有函数size字段 |
| 重定位 | 每个section的reloff/nreloc | 编码和类型依CPU，不能套ELF公式 |
| 本地/外部符号分区 | LC_DYSYMTAB | 依据实际索引/数量，不靠名字猜 |
| 构建平台 | LC_BUILD_VERSION | 平台、最低系统与SDK影响重建字节 |

来源arm64对象同时有`__DATA,__const`与`__TEXT,__const`，只用`__const`当字典key会覆盖一个。其`_percent_change`从文件648，即`0x288`开始，下一符号在同section内偏移`0x18`，可给出24字节候选跨度；由于nlist_64没有size，这仍可能包含padding、数据或别名，必须与指令和其他元数据交叉检查，不能宣布它是所有Mach-O函数的精确边界算法。

arm64引用常用ADRP与ADD等组合，相应PAGE21/PAGEOFF12重定位成对协作；同源码的x86 RIP-relative LEA可能只需一处PC32。绝对指针、相对表及其依赖在不同架构/优化等级都可能变化。Mach-O universal容器应先定位所选架构slice，未支持时明确拒绝；不能把外层fat magic当thin header继续解析。[Apple loader.h](https://github.com/apple-oss-distributions/xnu/blob/main/EXTERNAL_HEADERS/mach-o/loader.h)、[nlist.h](https://github.com/apple-oss-distributions/xnu/blob/main/EXTERNAL_HEADERS/mach-o/nlist.h)。

## 9. 练习与判断依据

| 练习 | 应能得到的判断 |
|---|---|
| 读上述O1 header，计算节表末尾 | 0x428+11×64=0x6e8；先核文件够长再读取 |
| 从grade符号算文件区间 | ET_REL用0x40+0x10=0x50，长46，到0x7e；不加后面padding |
| 从PC32记录定位值表 | 同时核字段起点0x36、指令末0x3a与addend0x10，目标相对S为0x14 |
| 将tiny入口换成文件偏移 | 先核在file-backed PT_LOAD内，再得0xb0；不能用同函数处理ET_REL假地址 |
| 给PT_LOAD增加memsz而不增加filesz | 多出的内存是零填充，没有可返回的原文件切片 |
| 比较两个同名__const | 用segment/section身份，保留两个不同内容区 |
| 处理未知重定位和零size函数 | 输出未支持/边界未知，不能猜宽度或相邻函数差后称证明 |

进一步实现共享对象读取时，SHT_DYNSYM沿用符号记录布局，但导入/导出、动态标签、重定位和装载应一起核。未定义符号不全是函数；JUMP_SLOT记录标的是待修补槽位，不是所有调用指令的地址。按PT_LOAD验证已知函数的文件区间，再用独立工具记录交叉核对；一致只覆盖该样本和比较字段，不能证明恶意或任意格式输入都正确。

链接后的外部调用、PE/COFF导入、Mach-O链式修复与剥离后的函数定位，继续阅读[链接装载与无符号分析](07-链接装载与无符号分析.md)。其中沿用本章的完整范围校验和地址坐标规则。
