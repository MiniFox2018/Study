# 程序分析与逆向工程

本专题把程序文件、机器指令、控制流、类型、动态观察和重建验证连成一条学习路线。先修是[体系结构与操作系统](../02-计算机体系结构与操作系统.md)、[数据结构与算法](../04-数据结构与算法.md)中的图，以及基本C/Python阅读能力。

目前按顺序阅读：

1. [二进制布局与装载地址](01-二进制布局与装载地址.md)：通过字段、范围和重定位算例，理解函数字节的位置。
2. [指令、ABI与编译惯用法](02-指令ABI与编译惯用法.md)：手解指令，比较三类调用约定，再推导乘移除法、取余及循环/调用变形。
3. [控制流与中间表示](03-控制流与中间表示.md)：区分扫描与静态可达，学习支配、自然循环、IR、SSA与内存别名，再沿八阶段合同组织小型反编译器。
4. [数据布局与类型恢复](04-数据布局与类型恢复.md)：从访问事实推候选布局，核数组步长、DWARF索引与重定位、C++虚表、工具对照与优化SSA签名恢复。
5. [静态与动态证据](05-静态与动态证据.md)：绑定目标、问题与环境，学习调试计划/命令映射、三态覆盖、core/trace边界及缓存与摘要的限制。
6. [差分重建与等价边界](06-差分重建与符号执行.md)：用反例设计网格，结合依赖/匹配/重定位，手解符号路径、模型、反例及截断输入集合，并检查反编译器网格/报告的准入条件。
7. [链接装载与无符号分析](07-链接装载与无符号分析.md)：追踪PLT/IAT/stub与修复槽，比较剥离前后元数据，处理函数起点和签名碰撞。
8. [字节码与托管容器](08-字节码与托管容器.md)：识别pyc/class/Wasm/CLI的版本与元数据，手解表引用、分支坐标和变长整数。

9. [AI协作与重建报告评估](09-AI协作与重建报告评估.md)：分开评价候选代码与解释，学习六栏范围、反例、命名预测、工具权限与可比较的成本记录。

10. [实现可审计的二进制检查器](10-实现可审计的二进制检查器.md)：沿六阶段实现格式、区域、符号、链接、起点与报告，区分可检查事实和启发式。

当前十篇覆盖第32～45课、逆向手册和两个逆向项目的有效知识，已完成本固定版本下的主题整合与局部验收；具体[覆盖、主动分类和验证边界](../../维护/来源更新/2026-10-16/89-逆向专题整体知识验收.json)分开记录。整个来源更新仍有其它新增项目和配套待处理，不能把本专题验收写成整站更新完成。

第一次学习先完成01～04的手算：找到字节、解一条指令、画CFG和phi、提出布局候选；再读05～07，练习给结论绑定证据、设计反例并追踪一次链接调用。08扩展到托管容器，09学习AI协作评估。最后用10的六阶段检查器或03第10节的小型反编译器作为项目路线，验证方法回到06第16节。各章练习有参考判断；个人实作另记，收录与验收不表示你已经掌握。

选择工具时先明确要得到哪类产物。下表说明职责，不推荐某个当前版本，也不要求安装整套工具。

| 工具类别 | 适合回答的问题 | 应核的限制 |
|---|---|---|
| 反汇编器 | 哪些字节可解成什么指令 | 指令集/模式、边界、未解字节；批量listing与交互分析库不是同一层 |
| 反编译器 | 如何用高层表达式解释已恢复的过程 | 类型/CFG/效果假设、goto与未知；伪C未必是可编译候选 |
| 调试器 | 某次运行到此处的寄存器、内存与事件 | 目标/环境/输入、停顿扰动和覆盖时段 |
| 分析框架 | 批量组织loader、IR、图、数据流和符号问题 | 入口模型、库摘要、路径与资源上限 |
| 格式/解码/模拟库 | 实现某个底层组成部分 | 能parse、decode、assemble或emulate各是不同能力，不等完整反编译 |
| 差分器 | 两个构建的哪些投影相同或不同 | 匹配身份、范围、归一化和数据依赖；相似不等价 |
| 编译器侧查看器 | 这段自有源码在固定选项下产生什么 | 这是源码到机器码的正向实验，不能证明未知目标必由该源码生成 |

一个产品可跨多类；多个前端也可能复用同一后端。比较时对齐对象摘要、装载地址、重定位、块划分和观察合同，再调查差异；多数票不能充当真值。商业功能、支持架构、版本和许可证应在实际选用时另核，来源的2026-10-14工具清单不作为当前推荐表。

学习时只使用明确允许分析的材料，区分原作者工具输出、本库静态核对和你亲自完成的实践。记住三条判断：能解码不等可达，伪代码可读不等行为正确，有限样例一致不等全输入等价。
