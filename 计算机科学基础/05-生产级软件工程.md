# 05｜生产级软件工程

## 1. 目标

生产软件不是“能跑”，而是：

- 可读；
- 可测试；
- 可部署；
- 可观测；
- 可回滚；
- 可维护。

## 2. Linux 与命令行

长期需要掌握的是抽象：

- process / signal；
- stdin/stdout/stderr；
- pipe；
- file permission；
- environment variable；
- shell composition；
- process inspection；
- network diagnostics。

不固化某个发行版或工具的短期 UI。

## 3. Git

核心对象：

```text
working tree
→ index
→ commit
→ branch/ref
→ remote
```

重要实践：

- 小而完整的 commit；
- 清晰 commit message；
- branch 生命周期短；
- review 前先自检；
- 能解释 merge/rebase 的差别；
- 不把生成物、密钥和大文件误提交。

## 4. Codebase Design

高质量代码库要控制：

- module boundaries；
- dependency direction；
- public interface；
- configuration；
- error handling；
- side effects。

原则：

> 让局部修改尽量保持局部影响。

避免“方便起见”的跨层引用逐步把系统耦合成一团。

## 5. Testing

测试金字塔可理解为：

- unit：便宜、定位快；
- integration：验证组件边界；
- end-to-end：验证关键用户路径。

此外还应有：

- property / invariant test；
- regression test；
- contract test；
- performance test。

测试不是追求覆盖率数字，而是保护高风险行为。

## 6. CI/CD

CI 负责持续验证：

```text
lint
→ type/static checks
→ tests
→ build
→ security scan
```

CD 再负责：

- artifact；
- staging；
- canary / blue-green；
- rollout；
- rollback。

## 7. Container

容器解决的是可重复运行环境和隔离，不等于完整运维系统。

生产中还要关心：

- image provenance；
- resource limit；
- secret；
- network；
- persistent storage；
- health check。

完整容器知识已独立整理到 [容器化与 Docker](./07-容器化与Docker/README.md)，这里不再重复维护。

## 8. Observability

三类信号：

- logs：发生了什么；
- metrics：系统总体状态；
- traces：一次请求跨组件经历什么。

关键原则是让异常可以被定位，而不是只知道“出错了”。

## 9. Configuration 与 Secret

配置应与代码分离；秘密信息不应硬编码或提交 Git。

需要明确：

- environment；
- validation；
- default；
- ownership；
- rotation。

## 10. Coding Agent 的正确位置

AI 编码 Agent 可以加速：

- 搜索代码；
- 生成候选补丁；
- 测试；
- 重构；
- 文档；

但不能替代：

- 需求边界；
- architecture ownership；
- correctness verification；
- security review；
- production accountability。

使用 Agent 时，应给出明确上下文、验收标准和测试闭环。
