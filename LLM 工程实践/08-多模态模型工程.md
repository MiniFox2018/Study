# 08｜多模态模型工程

## 1. 多模态不是“文本模型多一个图片参数”

多模态系统通常增加：

- modality encoder；
- processor；
- projector / connector；
- 不同输入 Token；
- 多模态位置编码；
- 不同数据 collator；
- 更复杂的显存预算。

## 2. 典型输入

### Vision-Language

```text
Image
  ↓
Vision Encoder
  ↓
Visual Tokens
  ↓
LLM
  ↓
Text
```

### Audio-Language

```text
Audio
  ↓
Audio Encoder
  ↓
Audio Representation
  ↓
LLM / Decoder
```

## 3. 数据结构

多模态 SFT 数据必须同时管理：

- 文本；
- 图片/音频路径；
- media 与 message 的绑定；
- Prompt；
- Target；
- Processor；
- Token 长度。

## 4. OCR 是很好的入门任务

例如 LaTeX OCR：

```text
公式图片 → 模型 → LaTeX 字符串
```

它具备：

- 清晰输入；
- 明确目标；
- 可进行语法、字符和渲染对比，但语法正确不等于识别正确；
- 易构造训练集；

适合做范围受控的入门实验，但字体、版式、分辨率和标注质量仍会显著影响难度。

## 5. 多模态 LoRA

是否只适配 LLM、Vision Encoder 或 Projector，应按任务决定。

如果数据量小，一开始不宜同时训练所有模态模块。

## 6. 多模态长度问题

图片和视频可能展开为大量视觉 Token。

因此要同时关注：

- 原图分辨率；
- patch 数；
- frame 数；
- 文本长度；
- max sequence length；
- truncation 是否误删 media token。

## 7. 评测

不能只看最终文本。

例如 OCR 可评估：

- exact match；
- edit distance；
- syntax validity；
- rendering consistency。

VQA / Caption / Grounding 需要分别设计指标。

## 8. 工程原则

多模态任务更容易出现“数据管线比模型本身更难”的情况。

优先验证：

```text
media 是否加载正确
→ processor 是否匹配
→ template 是否正确
→ label 是否对齐
→ loss mask 是否正确
→ 再开始长时间训练
```

来源：<https://github.com/datawhalechina/self-llm>

## 9. 一个能定位问题的 OCR 样本

输入图片写的是 `x²+1`，标准 LaTeX 为 `x^2+1`。模型输出 `x_2+1` 能成功编译，却把平方识别成下标。因此要分开看：是否加载了正确图片、LaTeX 能否解析、字符是否一致、渲染后的结构是否匹配。`x^{2}+1` 与 `x^2+1` 文本不同但通常渲染等价，exact match 又可能过严。

在第一批训练前展示原图、预处理图像尺寸、模板中的媒体占位符、有效 label 范围。视频样本额外记录抽帧时间，音频记录采样率和片段边界；同一来源的近重复帧/图片应放在同一数据划分，避免训练测试泄漏。

**自检**：输入图过大时只截断最终 Token 序列，为什么可能失败？

**核对**：可能截掉图片占位符、视觉表示或回答标签，使媒体与文本失配。应采用该模型支持的分辨率/帧数策略，再检查实际有效样本。


## 10. 流式语音项目：轮次、取消与用户实际听到的内容

本节承接[语音识别与流式交互](../AI%20算法基础/感知与多模态专题/13-语音识别与流式交互.md)与[语音合成](../AI%20算法基础/感知与多模态专题/14-语音合成生成与音频语言模型.md)。ASR/TTS基础已有维护入口，这里补把它们接到会话里的状态合同。目标是让用户能自然轮流说话，同时能说明哪里在等、哪里被取消、哪些内容实际播放过。

输入音频时钟、ASR partial/final、语义轮次检测、模型生成、TTS合成、网络传输与客户端已播放位置属于不同流水段。VAD只判断语音活动，不能保证说话者完成语义，也不能识别所有背景说话；短反馈词与真正打断需分别标注。

以用户真实语音末端到客户端首次可听音频为用户等待延迟；另报到server first-packet和turn-commit到first-packet。已有500ms静音门槛下，示意LLM140+TTS180至少820ms后才有server音频，不计网络；不能把commit后320ms说成用户末端320ms。未完成/取消记录None，不用0同时代表缺失与真实起点。

中断以session_id/turn_id/generation_epoch关联LLM、TTS、工具、媒体缓冲。取消是请求停止而非已停止的证明；迟到的旧epoch音频/结果必须丢弃，客户端队列同步清理，历史仅保留用户实际听到部分。已有真正工具效果不可因取消对话自动回滚，需effect ledger/幂等键及补偿。

工具结果未回时可以短确认，但不能提前播出结果；确认句也要支持取消和去重。同步等工具不等全部应用阻塞，异步边信道仍需总deadline/异常/权限/恢复合同。

链路按有界队列与producer/consumer速率管理背压；丢包/抖动不推出必须提升VAD阈值，先测jitter/PLC/重传和上游ASR策略，阈值变化可能漏掉轻声。语种、设备、噪声、PSTN/WebRTC codec分别切片。

### 从概念到一个可验收的语音链路

先在可控音频上确认采样率、声道、frame timestamp、重排/丢帧政策及ASR partial/final协议；再接轮次判定，记录真实末端、静音等待、语义判定与commit。模型输出按可合成的文本片段交TTS，不把每个token机械当完整朗读片段。最后接网络与播放回执，并以用户实际听到的时间检验体验。并行流水能减少等待，但依赖尚未完成的工具结果不能提前作为事实朗读。

建立人工标注的小语音集，覆盖噪声、电话codec、长停顿、短“嗯”、语速、语言和轻声。WER以参考词数为分母：替换＋删除＋插入再除参考词数；turn提前结束、误判用户打断、播放取消成功率另用相应标注case作分母。MOS人工听评与NISQA预测分别报告。固定100calls、800ms、50并发是教材作业预算，不能推出硬件已达或统计充分。

[LiveKit轮次与打断官方文档](https://docs.livekit.io/agents/build/turns/)于2026-10-11选读确认：server侧realtime detection与client VAD/turn模式的可配置范围不同；打断后历史应包含用户已听部分，另有false-interruption与恢复策略。此处只保留机制，不沿用旧版本构造器。对工具先判是否可取消、结果能否继续复用、是否发生副作用，再执行相应政策；停止声音不是撤销预约的证明。

### 可运行合同探针：epoch和三个时间起点

下例输入都是人工给定毫秒和字符串，不含音频或模型。第一轮真实语音末端0ms、提交500ms、server首次音频820ms、用户首次听到900ms，三种延迟分别320/820/900ms。下一轮使旧epoch失效并清队列；旧结果晚到必须拒绝。尚未播放保None，首时戳0ms合法。

```python
from dataclasses import dataclass, field
from copy import deepcopy

def milliseconds(x):
    if type(x) is not int or x < 0:
        raise ValueError('时间必须是非负整数毫秒')
    return x

def valid_epoch(x, allow_zero=False):
    if type(x) is not int or x < (0 if allow_zero else 1):
        raise ValueError('epoch必须是非bool整数，调用轮次必须为正')
    return x

@dataclass
class Turn:
    epoch: int
    speech_end: int
    commit: int
    server_first: int | None = None
    played_first: int | None = None
    cancelled: bool = False
    heard_until: int | None = None

@dataclass
class Session:
    epoch: int = 0
    turns: dict[int, Turn] = field(default_factory=dict)
    audio_queue: list[tuple[int, str]] = field(default_factory=list)

    def __post_init__(self):
        valid_epoch(self.epoch, allow_zero=True)

    def new_turn(self, speech_end, commit):
        valid_epoch(self.epoch, allow_zero=True)
        speech_end, commit = milliseconds(speech_end), milliseconds(commit)
        if commit < speech_end:
            raise ValueError('提交不能早于真实语音末端')
        if self.epoch in self.turns:
            self.cancel(self.epoch)
        self.epoch += 1
        self.turns[self.epoch] = Turn(self.epoch, speech_end, commit)
        return self.epoch

    def cancel(self, epoch):
        epoch = valid_epoch(epoch)
        t = self.turns[epoch]
        t.cancelled = True
        self.audio_queue[:] = [x for x in self.audio_queue if x[0] != epoch]
        # 工具的实际副作用需另查 effect ledger；这里没有工具执行。

    def audio(self, epoch, sent_at, text):
        epoch = valid_epoch(epoch)
        t = self.turns.get(epoch)
        if t is None or t.cancelled or epoch != self.epoch:
            return False  # 迟到的旧生成结果不能再播放
        sent_at = milliseconds(sent_at)
        if sent_at < t.commit:
            raise ValueError('首音频不能早于生成提交')
        if t.server_first is None:
            t.server_first = sent_at
        self.audio_queue.append((epoch, text))
        return True

    def played(self, epoch, first_at, heard_until):
        epoch = valid_epoch(epoch)
        t = self.turns[epoch]
        first_at, heard_until = milliseconds(first_at), milliseconds(heard_until)
        if t.server_first is None or first_at < t.server_first or heard_until < first_at:
            raise ValueError('播放必须晚于发送，已听终点不能回退')
        if t.heard_until is not None and heard_until < t.heard_until:
            raise ValueError('播放回执不能回退')
        if t.played_first is None:
            t.played_first = first_at
        # 参数是可信的播放发生时间，不是回执抵达时间；旧轮迟到回执只补历史。
        t.heard_until = heard_until

    def latencies(self, epoch):
        epoch = valid_epoch(epoch)
        t = self.turns[epoch]
        return {
            'commit_to_server': None if t.server_first is None else t.server_first - t.commit,
            'speech_end_to_server': None if t.server_first is None else t.server_first - t.speech_end,
            'speech_end_to_heard': None if t.played_first is None else t.played_first - t.speech_end,
        }

s = Session()
a = s.new_turn(0, 500)
assert s.audio(a, 820, '短确认')
s.played(a, 900, 960)
b = s.new_turn(1000, 1400)  # 使旧生成失效，并清播放队列
assert not s.audio(a, 1600, '旧轮迟到答案') and s.audio_queue == []
assert s.latencies(a) == {'commit_to_server': 320, 'speech_end_to_server': 820, 'speech_end_to_heard': 900}
assert s.latencies(b)['speech_end_to_heard'] is None
assert s.turns[a].heard_until == 960
try:
    s.new_turn(True, 2)
except ValueError:
    pass
else:
    raise AssertionError('布尔时间必须拒绝')
# 初始epoch和所有按轮次索引的入口都拒绝bool；拒绝前不得改状态。
for bad in (True, False, 0, -1, '1'):
    before = deepcopy((s.epoch, s.turns, s.audio_queue))
    for invoke in (
        lambda: s.cancel(bad),
        lambda: s.audio(bad, 1600, '不可接受'),
        lambda: s.played(bad, 900, 960),
        lambda: s.latencies(bad),
    ):
        try:
            invoke()
        except ValueError:
            assert (s.epoch, s.turns, s.audio_queue) == before
        else:
            raise AssertionError('非法epoch必须在访问或修改状态前拒绝')
for bad in (True, False, -1, '0'):
    try:
        Session(epoch=bad)
    except ValueError:
        pass
    else:
        raise AssertionError('初始epoch也必须严格检查')
# 旧轮的可信已听事实可以迟到，此调用不让旧音频进入新输出队列。
s.played(a, 900, 960)
assert s.audio_queue == [] and s.epoch == b
print('epoch隔离通过；非法epoch拒绝且状态不变；旧轮320/820/900ms；新轮未播放=None；已听历史960ms')
```

2026-10-11在Python 3.12.13的标准库运行成功，输出：

```text
epoch隔离通过；非法epoch拒绝且状态不变；旧轮320/820/900ms；新轮未播放=None；已听历史960ms
```

`played`参数表示可信回执中报告的实际播放发生时间，不是回执到达服务器的时间；旧轮回执可以迟到，仅补充已听历史，不触发当前输出。所有轮次入口先拒绝bool或非正整数，初始epoch只允许非bool的非负整数。

此例不实现VAD、ASR、模型、TTS、网络时钟同步或side-effect rollback；playout回执假定可信，生产还需队列背压、时间单调、迟到回执及会话身份检查。

### 原综合项目的实现范围与图示

Python barge-in判断仅SPEAKING/THINKING，TOOL态忽略语音；TS用THINKING覆盖tool但只有同步伪事件。两者都无generation epoch，旧job返回无法安全丢弃。

Python中断未重置silence/final_partial/tool/filler/metrics；TS虽清部分状态但metrics单组first时间与后来turn_complete混合，缺每轮计量。首speech_frame在IDLE不更新partial，continue可丢打断第一帧。

Python假定每循环20ms，TS同样；未校验非单调时戳、重复包、缺帧。不应将frame个数等同真实静音duration。

TS WebSocket server只是连接后同步发送日志和summary并关闭，非WebRTC音频client；测试只断言event/标量，不测PCM/TTS、网络、取消和实际播放。

WER是(替换+删除+插入)/参考词数；MOS人工评价与NISQA代理另报。false-turn-closure和false-interruption不同；源false-cutoff含义混用，Hamming VAD基准名称未追溯，固定50并发/800ms/100calls不作为事实或充分统计保证。

### 五项原练习的中文实践判断

1. **ASR替换对照**：在相同音频、参考转写与真实硬件上比较ASR，计采集末端、首partial、final、WER、网络与CPU/GPU排队，不能用模型名推延迟；未执行。
2. **工具运行中打断**：打断during tool分别定义硬取消、完成但不发旧答、排队下一轮，测迟到结果/副作用/用户等待/授权撤销；生成epoch与工具effect ledger是关键，不能把hard cancel当rollback。
3. **长停顿轮次调参**：用人工标注的长停顿、短反馈、犹豫词及噪声，扫endpoint/语义score；测错误提前结束与延迟的联合分布，没有固定500ms/.6最优。
4. **PSTN与WebRTC对照**：PSTN/WebRTC对照同用户末端至可听声定义，记录codec/采样率/jitter buffer/网关地域，不能从协议名推确定差值。
5. **多语言VAD**：多语种VAD先标注语音活动而非词识别，按声学条件与turn语义误判分别测；不自动说明VAD需语言微调。

这些真实实践均未在本轮执行；上面的标准库验证只覆盖标出的合同。

### 七道原测验的中文核对

1. **为什么要做端到端流式？**：串联blocking批处理会累加等待；流水流式常能降低首音频，800ms是作业目标而非REST理论下限。
2. **VAD旁边为什么还要轮次检测？**：语义turn detector结合partial/上下文估完成；VAD只给活动线索。
3. **用户打断时怎样处理？**：中断要停生成/播放、清队列、丢旧epoch、更新已听历史；实际工具副作用另核，不能只有cancel日志。
4. **等待工具时确认句起什么作用？**：确认句告知等待，不代表工具已成功，300ms仅政策示例。
5. **200ms预算从哪里起算？**：200ms是此题的LLM首token至server首音频预算，未覆盖VAD/网络/播放。
6. **怎样定义错误切断？**：错误提前commit与错误停止agent播放应有两个指标/人工标注；总称false-cutoff可能混分母。
7. **丢包时是否必提升VAD阈值？**：源码没有实现包丢失适配；提高阈值不是普适方法，抖动、PLC、ASR/VAD鲁棒性需独立实验。

## 11. 视频问答项目：先把证据绑定到原视频时间

先修是本章媒体绑定、视觉token预算和[视频时序](../AI%20算法基础/感知与多模态专题/09-视觉生成与视频时序.md)。面对长视频库，索引能避免每次重新读全部视频，并帮助定位证据；同时评估直接长上下文阅读作为基线，不把索引当所有任务的强制条件。

video_id/source_revision、presentation timestamp(PTS)/time_base、音频offset、cut/downscale映射是总合同；统一视频原始坐标，局部clip时间先显式加offset，不能将frame_index/FPS在可变帧率中当真时戳。

镜头shot边界不必语义scene；连续事件跨cut需相邻scene扩展。caption/keyframe只摘要单帧/文本，动作顺序/计数需多帧或clip，抽帧rate要配duration与可见性，100h场景数不固定。

ASR word intervals与shot按intersection切片，跨边界word可保同wordID并重叠引用，不能复制文本后当不同证据；speaker ID≠真实姓名Alice，身份需授权外部映射。

Qdrant named vectors使同point有不同向量/维度/距离；multivector通常矩阵＋MaxSim是另一个概念。文本query要用与各caption/transcript/visualencoder匹配的空间，不是任意一个qv共用所有空间。

RRF sum w/(c+rank)按rank合并不同空间，不把分数当confidence概率；k/c/weights任务验证、去重同video/scene、缺表示先保missing，不擅零向量。

grounding约束0≤start<end≤duration，selectedscene.start≤window.start<window.end≤scene.end；若跨shot回答则选择多scene并明确不是单scene refinement。tIoU=overlap/union，point与空区间非法，引用时间有效不等事实正确。

计数需定义实例与事件（distinct car还是passing event）、跟踪跨帧去重、遮挡/重复入场规则；action先后证据要带time/camera coverage。strict mode列每实例证据与unknown；人工可验证提高可审查性，不保证无幻觉。

### 入库、检索和回答之间的证据合同

原视频元数据先记录duration、PTS/time-base、音视频offset、转码/裁剪映射和revision。镜头切分输出同原视频坐标；多帧caption/visual表示与ASR可以局部并行，但必须等待相应scene或时间范围。统一point身份`(video_id, revision, scene_id)`，附媒体权利与缺失表示，不把相同scene的多个命中当多个独立证据。

[Qdrant向量官方概念](https://qdrant.tech/documentation/concepts/vectors/)于2026-10-11选读：named vectors可在同point存不同维度/类型；multivectors是矩阵表示和指定comparator，例如MaxSim。三类caption/frame/transcript named向量不自动等同矩阵multivector。各查询要用其encoder配套空间；VLM会生成caption并不意味着它同时提供可用visual embedding接口。先分别校验检索，再用名次RRF融合，分数不标成校准confidence。

单keyframe看不到完整动作，ASR也不能证实视觉中的车辆数量。检索到的场景需扩展邻接clip、抽帧或多视角，grounding给受约束的窗口；模型回答接受真实frames/clip与对齐转写，引用写原视频坐标。若事件跨cut，明确引用多个区间，不硬塞一个selected scene。若可见性不足，输出“无法从这些片段确定”，不编一个计数。

计数例先定“不同车辆数”还是“经过线的事件数”：同车连续出现在五帧并不等于五车，折返第二次经过是否重新计数由任务约定。每实例/事件附时间证据，记录遮挡、同一对象去重、重复进出及unknown。动作先后需要同一时间轴的证据与覆盖；描述、计数、动作分别报准确率、定位tIoU、引用有效率和未答率。点击可审查并不等于模型已正确。

### 可运行合同探针：局部时间与原视频时间

下例只验证整数毫秒合同。selected scene在原视频[92,114)s，其局部[2,12)s映射为原[94,104)s；与真值[98,108)s的交集6s、并集14s，tIoU=3/7。源示例把[92,114)s细化为原[12,58)s应拒绝；若[12,58)s是局部时间，也超22s场景。跨scene的同一个ASR词分出两交集，仍要保同word_id。

```python
from dataclasses import dataclass
from fractions import Fraction

@dataclass(frozen=True)
class Window:
    start: int
    end: int

    def __post_init__(self):
        if type(self.start) is not int or type(self.end) is not int or not 0 <= self.start < self.end:
            raise ValueError('必须是非负整数ms的非空区间')

    def within(self, outer):
        return outer.start <= self.start < self.end <= outer.end

def global_window(local, scene, video_duration):
    if type(video_duration) is not int or video_duration <= 0 or scene.end > video_duration:
        raise ValueError('scene超出原视频')
    out = Window(scene.start + local.start, scene.start + local.end)
    if not out.within(scene):
        raise ValueError('局部grounding超出selected scene')
    return out

def tiou(a, b):
    overlap = max(0, min(a.end, b.end) - max(a.start, b.start))
    union = (a.end - a.start) + (b.end - b.start) - overlap
    return Fraction(overlap, union)

scene = Window(92000, 114000)
assert global_window(Window(2000, 12000), scene, 240000) == Window(94000, 104000)
assert tiou(Window(94000, 104000), Window(98000, 108000)) == Fraction(3, 7)
assert not Window(12000, 58000).within(scene)  # source示例原时间越界
try:
    global_window(Window(12000, 58000), scene, 240000)
except ValueError:
    pass
else:
    raise AssertionError('局部/全局混淆必须拒绝')
# ASR词跨scene边界：同word_id，可有两条交集，不能当两个词/独立证据。
word = Window(113500, 114500)
segments = [scene, Window(114000, 130000)]
slices = [(max(word.start, x.start), min(word.end, x.end)) for x in segments if min(word.end, x.end) > max(word.start, x.start)]
assert slices == [(113500, 114000), (114000, 114500)]
try:
    Window(True, 2)
except ValueError:
    pass
else:
    raise AssertionError('bool/点区间非法')
print('局部[2,12)s→原视频[94,104)s；tIoU=3/7；越界拒绝；跨镜头词保同word_id')
```


此例不做视频decode、可变帧率映射、ASR、视觉检索、grounding模型或计数；时间合法仅是引用必要条件，不证明视觉事实。

### 七道原测验的中文核对

1. **长上下文为什么还考虑索引？**：大语料可用分片索引减少重复费用并精确定位，longcontext也可任务替代，并非唯一必需。
2. **三类向量与multivector的区别？**：caption/frame/transcript三named representations；维度/空间可不同，不等Qdrantmultivector矩阵。
3. **RRF为什么融合名次？**：RRF以名次融合可避原cosine不同标度；需同实体ID去重。
4. **时间窗口能越出selected scene吗？**：单scene细化必须在其原时间区间内，不然换多scene evidence。
5. **哪些问答需单独报告？**：计数/action易被single keyframe或转写误导，分层报真值/unknown/证据，不只overall。
6. **tIoU要满足什么坐标合同？**：tIoU必须同原视频时间坐标，报告localization和QA准确率分别。
7. **带时间引用是否证明答案？**：引用便于点击审核，不自动证明答案/时间是正确真值。
