# 08｜多模态模型工程

## 1. 多模态不是“文本模型多一个图片参数”

多模态系统通常增加：

- modality encoder；
- processor；
- projector / connector；
- 不同输入 Token；
- 多模态位置编码；
- 不同数据 collator；
- 更复杂的显存预算。

## 2. 典型输入

### Vision-Language

```text
Image
  ↓
Vision Encoder
  ↓
Visual Tokens
  ↓
LLM
  ↓
Text
```

### Audio-Language

```text
Audio
  ↓
Audio Encoder
  ↓
Audio Representation
  ↓
LLM / Decoder
```

## 3. 数据结构

多模态 SFT 数据必须同时管理：

- 文本；
- 图片/音频路径；
- media 与 message 的绑定；
- Prompt；
- Target；
- Processor；
- Token 长度。

## 4. OCR 是很好的入门任务

例如 LaTeX OCR：

```text
公式图片 → 模型 → LaTeX 字符串
```

它具备：

- 清晰输入；
- 明确目标；
- 可程序验证；
- 易构造训练集；

非常适合理解 VLM 微调链路。

## 5. 多模态 LoRA

是否只适配 LLM、Vision Encoder 或 Projector，应按任务决定。

如果数据量小，一开始不宜同时训练所有模态模块。

## 6. 多模态长度问题

图片和视频可能展开为大量视觉 Token。

因此要同时关注：

- 原图分辨率；
- patch 数；
- frame 数；
- 文本长度；
- max sequence length；
- truncation 是否误删 media token。

## 7. 评测

不能只看最终文本。

例如 OCR 可评估：

- exact match；
- edit distance；
- syntax validity；
- rendering consistency。

VQA / Caption / Grounding 需要分别设计指标。

## 8. 工程原则

多模态任务更容易出现“数据管线比模型本身更难”的情况。

优先验证：

```text
media 是否加载正确
→ processor 是否匹配
→ template 是否正确
→ label 是否对齐
→ loss mask 是否正确
→ 再开始长时间训练
```
