# 18｜模型演示界面与交互合同

把模型函数交给别人试用，至少要回答：允许输入什么，多久能知道它在工作，怎样判断回答已经结束，失败后该做什么，以及谁承担调用成本。界面把这些约定交给用户，服务器负责真正执行它们。

先修是 Python 函数、生成器、JSON 与 HTTP；相关入口是 [Python 高级特性](../Python/Core/10-Advanced-Features.md)、[推理与服务化](03-推理与服务化.md)和[结构化输出](13-结构化输出与对话状态.md)。这里讲面向试用者的小应用；服务调度、模型吞吐、网关重试继续由03维护。

## 1. 先写一张输入、调用与输出合同

假设做一个短评分类演示。教学模型只数正负关键词，输出 positive、negative 或 neutral，不能理解否定、反讽和语言外的知识。

| 合同部分 | 可执行的约定 | 对用户的解释 |
|---|---|---|
| 输入 | JSON 对象，`text` 为非空字符串；分别限制请求字节数和解码后长度；允许哪些换行与控制字符有明文规则 | 最多可输入多少，拒绝时指出实际大小和限制 |
| 调用 | 明确模型/版本、最大等待、最大输出、允许的同时运行数及预算；每个实际尝试计量 | 显示等待状态、取消入口和预期行为 |
| 输出 | 分类、分数含义、文本及终态；失败含稳定错误码与请求编号 | 分数不是正确概率；部分结果会标记未完成 |

一个合法请求是 `{"text":"The screen is bright."}`。`{"text":42}` 是字段类型错误；空白字符串清理后仍为空，应拒绝。“The screen is not good.” 是合法输入但可能被关键词模型误判为正面；应把它保留为反例并解释能力限制，不能通过输入校验把所有模型错误排除。

**先保同一合同，再换后端。** 来源的 `predict`、`generate` 与流末 `done` 都另外调用了关键词分类器；只替换 `generate` 并不能让最终分类、分数和非流式接口自动变成真实模型输出。迁移时抽出共同的模型适配器，核对普通/流式两条路径、元数据和错误；API Key 保留在服务端。

### 1.1 “500个字符”必须说清计量单位

请求的 UTF-8 字节数、Python `len(str)` 的码点数、浏览器字符串长度的 UTF-16 代码单元数、用户看到的字素数以及模型 token 数是不同量。一个常见 emoji 在 Python 中可算1个码点，在 JavaScript 字符串中通常占2个代码单元；组合字符和家庭 emoji 又更复杂。

因此浏览器 `maxlength` 与服务端 `len` 可能并不一致。选择一个服务端权威单位，把限制显示清楚；前端尽量采用相同规则。无论前端怎样限制，API 都可被独立调用，服务器必须再验。字节上限防大请求，模型 token 上限控制上下文与成本，两者都不能由“最多500字”代替。

校验按外到内进行：限制头部与请求体 → 检查认证/准入 → 完整读取有上限的正文 → 解码与 JSON 根类型 → 字段类型/长度/允许值 → 预留全局资源 → 调模型。具体顺序可因网关而异，但未经认证的慢正文也应受连接数、总读取时间和大小约束。

来源小服务器先读正文再鉴权，`timeout=10` 主要是套接字操作等待，不是整个模型请求的总截止时间；反复及时送少量字节仍可能长时间占连接。读取返回时还应确认实际字节数与声明长度一致。来源用 `int(Content-Length)` 解析，不能当完整 HTTP 报文校验器：重复/冲突长度、Transfer-Encoding 和代理解析必须交给可靠 HTTP 栈。HTTP/1.1 的长度与报文分界关系见 [RFC 9110 §8.6](https://httpwg.org/specs/rfc9110.html#field.content-length)。

## 2. 给等待过程一个能看懂的状态

建议状态为：就绪 → 校验 → 排队/运行 → 接收部分内容 → 完成，旁路进入失败、取消或连接中断。状态应由当前请求身份驱动，过期回调不能覆盖下一次请求。

提交后禁用按钮可以减少误点；它不能防刷新、多窗口、脚本或重试造成重复调用。费用或副作用需要服务端请求身份、幂等/对账策略。取消按钮也要同时处理浏览器读取、服务端工作和上游推理，不能只改按钮文字。

等待时显示已过去时间，必要时显示队列状态；没有可信进度就不编造“已完成90%”。记录两种不同时间：

- 用户端首个**有效内容**出现的时间：包括网络、准入、排队、模型和呈现；收到心跳或空片段不算内容。
- 服务端处理时长：取决于计时点，可能包括整段生成和写回，不等于用户端首内容时间，也不应与它相减当纯网络时间。

例如浏览器在提交后800ms显示首内容、2800ms确认结束，只能说这次端到端首内容800ms、完成2800ms。来源关键词程序先构造完整回复再按空格切片，另加每片40ms人为等待；这能演示界面反馈，不能证明真实模型的 TTFT、分词速度或并发性能。多个片段也不一定等于多个模型 token。

可访问性也属于反馈：标签关联输入框，状态区使用适当的 live region，错误可被键盘和读屏定位；不要每个字符都触发冗长播报。

## 3. 流式传输：把网络分块、事件与业务完成分开

一种常见做法是 POST JSON，用 `fetch` 读取响应的 `text/event-stream`。本文约定三种应用事件：

```text
event: token
data: {"index":0,"text":"你好"}

event: token
data: {"index":1,"text":"！"}

event: done
data: {"tokens":2}

```

空行结束一个事件；JSON 是本文选择的数据格式，SSE 本身不强制 JSON。`token`、`done`、`error` 也是应用命名，不是 SSE 自带的“成功”语义。

原生 `EventSource` 适合 GET 订阅，构造参数不能直接指定 POST 正文或任意认证头。输入随 POST 正文发送时可用 `fetch` 手工消费流；这不意味着 GET 必须把私密输入写进 URL，也可先创建受控任务再用不含输入的任务地址订阅。POST 正文仍可能被代理、APM、服务端或模型供应商记录，应另外核查。

### 3.1 可靠消费至少分四层

1. **字节到文本**：使用增量 UTF-8 解码，处理中文/emoji被分在两个网络块的情况，结束时完成解码检查。
2. **文本到事件**：保留未完整行和未完整事件；一个网络块可能半个事件，也可能多个事件。支持约定的行结束、多行 `data` 和心跳注释，限制未结束行/事件的最大字节数。
3. **事件到合同**：解析 JSON，核类型、字段、序号、大小和已知事件。无 `done` 的 EOF 标记未完成；`error` 后的文本不能继续默默追加。
4. **合同到页面**：部分文本保持“未完成”标签；只在合法终态后显示完成。失败、超时、JSON 错和用户取消分别提示，保留请求编号。

WHATWG 规定 UTF-8、CRLF/CR/LF 行结束和空行派发；EOF 之前尚未由空行结束的事件不会派发。来源 `split("\n\n")` 及页面只找两个 LF 的实现适合它自发的有限格式，不是通用 SSE 解析器。正式规范入口为 [WHATWG §9.2.5–9.2.6](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)。

来源页面也没有检查 `index`、最终计数或正常 EOF 是否缺 `done`，因此可能留下半句却不明确报中断。来源流中模型异常发送 `error`，但 `send_stream` 返回值没有把这个错误写回请求日志，HTTP日志仍可能是200/code为空。应将传输状态与应用终态分别记录。

### 3.2 完整CPU例：已解码事件的有限状态校验

下面程序只接收**已经正确解析的事件**，不实现网络、UTF-8 或 SSE 解析。其窄合同是 `token(index,text)`、`done(tokens)`、`error(code)`；真实应用若添加标签、usage或模型停止原因，应升级合同后再使用，不能直接把额外字段扔掉。

`parts` 保留不超过字符预算的部分结果；事件预算包含终态，因此最多8个事件时不能发送8个增量后再免费补第9个终态。发生协议错误后状态为 invalid，不能因之前见过 done 就忽略后续矛盾事件。

```python
"""自有教学例：已解码事件的有限状态校验，无网络与模型。"""
from dataclasses import dataclass, field

@dataclass
class ReplyState:
    max_chars: int = 40
    max_events: int = 8
    status: str = field(default="receiving", init=False)
    parts: list[str] = field(default_factory=list, init=False)
    count: int = field(default=0, init=False)
    chars: int = field(default=0, init=False)
    events: int = field(default=0, init=False)

    def __post_init__(self):
        for limit in (self.max_chars, self.max_events):
            if type(limit) is not int or not 1 <= limit <= 10_000:
                raise ValueError("限制须为1至10000的整数")

    def push(self, kind, data):
        if self.status != "receiving":
            self.status = "invalid"
            raise ValueError("终态后事件")
        try:
            if type(kind) is not str or type(data) is not dict:
                raise ValueError("事件形状")
            if self.events >= self.max_events:
                raise ValueError("事件数超限")
            if kind == "token":
                if set(data) != {"index", "text"}:
                    raise ValueError("增量字段")
                index, text = data["index"], data["text"]
                if type(index) is not int or index != self.count:
                    raise ValueError("增量缺失或重复")
                if type(text) is not str or not text:
                    raise ValueError("增量文本")
                if len(text) > self.max_chars - self.chars:
                    raise ValueError("文本超限")
                self.parts.append(text)
                self.chars += len(text)
                self.count += 1
            elif kind == "done":
                if (set(data) != {"tokens"} or type(data["tokens"]) is not int
                        or data["tokens"] != self.count):
                    raise ValueError("终态计数")
                self.status = "complete"
            elif kind == "error":
                if set(data) != {"code"} or type(data["code"]) is not str or not data["code"]:
                    raise ValueError("错误合同")
                if len(data["code"]) > 64:
                    raise ValueError("错误代码超限")
                self.status = "failed"
            else:
                raise ValueError("未知事件类型")
            self.events += 1
        except ValueError:
            self.status = "invalid"
            raise

    def eof(self):
        if self.status == "receiving":
            self.status = "incomplete"
        return self.status, "".join(self.parts)


def rejected(fn):
    try:
        fn()
    except ValueError:
        return
    raise AssertionError("应拒绝")

ok = ReplyState()
ok.push("token", {"index": 0, "text": "你好"})
ok.push("token", {"index": 1, "text": "！"})
ok.push("done", {"tokens": 2})
assert ok.eof() == ("complete", "你好！")
rejected(lambda: ok.push("token", {"index": 2, "text": "多余"}))
assert ok.eof()[0] == "invalid"  # 终态后继续发内容是协议错误
partial = ReplyState()
partial.push("token", {"index": 0, "text": "半句"})
assert partial.eof() == ("incomplete", "半句")
failed = ReplyState()
failed.push("token", {"index": 0, "text": "半句"})
failed.push("error", {"code": "model_error"})
assert failed.eof() == ("failed", "半句")
for kind, data in [("token", {"index": True, "text": "错"}),
                   ("token", {"index": 1, "text": "缺首项"}),
                   ("done", {"tokens": 1}), ("mystery", {})]:
    state = ReplyState()
    rejected(lambda: state.push(kind, data))
    assert state.eof()[0] == "invalid"
short = ReplyState(max_chars=2)
rejected(lambda: short.push("token", {"index": 0, "text": "超三个"}))
assert short.parts == []
few = ReplyState(max_events=1)
few.push("token", {"index": 0, "text": "x"})
rejected(lambda: few.push("done", {"tokens": 1}))
rejected(lambda: ReplyState(max_chars=True))
print("完整终态/断流保留/流中错误/终态后拒绝/索引与bool/字符和事件上限通过")
```

2026-10-16 在 CPython 3.12.13 以隔离模式实际执行该新自有程序，输出：

```text
完整终态/断流保留/流中错误/终态后拒绝/索引与bool/字符和事件上限通过
```

这是合同机制验证；数据进入本类前仍须限制原始帧与解码对象大小。上面的字典本身是调用方已有的内存对象，字符预算不能倒过来防止此前已经分配巨大的 JSON。对网络断包、HTTP、浏览器、真实模型和多用户压力，本程序没有运行证明。

### 3.3 断流、取消与恢复

响应头发送200后，服务端不能重新发500状态行；尽可能发送应用错误事件，写失败则记录“客户端是否收到未知”。连接关闭而缺终态时保留部分文本并提示中断，不能自动补完成。

浏览器中止读取或服务端看到 BrokenPipe，说明本条连接不能继续正常写；不证明远端模型已经取消或未计费。关闭当前生成器还需要正确传播到内部迭代器、SDK与工作线程，并执行清理；同步阻塞的下一次读取可能尚未返回。实际结束与实际账单需要上游确认/观测。

恢复必须先选择产品语义：重新生成一个新回答、读取同一任务的持久事件，还是明确告诉用户不能恢复。重新生成不能直接接在旧半句后冒充一条回答；自动重试可能再扣一次钱。SSE 的 `id`/`Last-Event-ID` 是续传的基础机制，仍需服务端保留、鉴权和去重策略，不能自动获得 exactly-once。

## 4. 限速、并发、队列和总费用是四件事

**令牌桶**用容量控制突发，用补充速度控制持续平均速率。设容量为 $B$，补充速率为 $r$ 次/秒，上次更新时间为 $t_0$，本次单调时间为 $t$，已有额度为 $b$：

$$
b' = \min(B, b + r(t-t_0)).
$$

一次请求耗费 $c$ 个额度；当 $b'\ge c$ 时接收并扣除，否则拒绝，理论最短补足等待为 $(c-b')/r$ 秒。这里 $B,r,c$ 必须为有限正值，通常要求 $c\le B$，否则它永远无法等到足够额度。限制参数应拒绝 bool、NaN、无穷和不合理上限；用单调时钟，不把时钟回拨当正常补充。

**手算**：容量2、每秒补1，在 $t=0$ 同时到来7次，先2次接收，后5次拒绝；到 $t=0.5$ 的一次仍拒绝，理论再等0.5秒；到 $t=1$ 才有一个新额度。真实命令循环如果每次耗时较长，可能在循环内已经补回额度，不能硬断言总是 `200 200 429 429 429 429 429`。

来源互动图固定24次到达：开头8次突发、中间每秒一次、结尾再8次突发。拖动容量/补充速度会改变接收数；图中的“接收=模型运行”建立在其模拟假设上，不包含认证失败、字段校验失败、全局预算拒绝、模型错误或真正并发。它解释额度曲线，不能用来推断服务器吞吐。

| 控制 | 管什么 | 单独不能保证什么 |
|---|---|---|
| 每用户令牌桶 | 一段时间内可尝试的频率与突发 | 单次长期不结束时的资源占用 |
| 并发上限 | 当前实际工作数 | 等候队列长度与累计费用 |
| 有界队列和队列截止时间 | 可等待的数量与时长 | 各用户公平和模型单次费用 |
| 全局调用/费用预算 | 所有用户合计可消耗的资源 | 请求大小、合法性与具体授权 |

拒绝的过快请求可用429并给 `Retry-After`；该字段可为秒数或HTTP日期，不能总用 `Number(header)` 解析。全局服务额度暂不可用可按产品合同返回503等适当状态，消息说明预计恢复和下一步。等待时间只是允许稍后尝试，不承诺届时一定有容量。

来源的限速字典有锁且按客户端淘汰旧桶，但淘汰后重建满桶可能被身份轮换利用；容量上限防字典无限长，并不等于强身份限流。来源用 IP 作为键，直连、可信反向代理及多人共享出口的行为不同；不能信任任意调用者传来的 `X-Forwarded-For`。只在连接来自明确可信代理时按固定规则取身份，其他请求忽略伪造头，用户级规则优先使用认证身份。

来源调用上限带锁，按 Unix 时间除以86400分窗，是进程内固定窗口；它不是从第一次请求起滚动24小时，也不自动是用户本地自然日。重启/多进程不共享状态，边界前后可集中耗费两窗额度；它数调用次数，不数真实输入输出 token、重试、工具费用或模型价格。真实预算要跨实例原子预留、实际尝试记账和结算；未知费用保持待对账，不随断流随意退款。服务端ThreadingHTTPServer没有因此获得并发上限。

## 5. 错误要帮助恢复，也要避免误导重试

一个最小应用错误可以是：

```json
{"error":{"code":"text_too_long","message":"输入为620个码点，最多500个。","hint":"缩短到500个码点后再提交。","request_id":"r-42"}}
```

`code` 供程序稳定分支；`message` 给出本次事实；`hint` 给一个可行动作；`request_id` 便于定位。输入错提示修改，认证错提示检查凭据，过快请求提示等待；应用错误不能统一成“请求没到服务器”。来源前端把所有异常归到这句提示，会把JSON解析错、读流失败和客户端代码错也误报成连接失败。

错误中不返回堆栈、内部路径、凭据或上游敏感正文。本文形状是自定义合同，不因引用RFC 9457就成为标准Problem Details。HTTP状态、应用错误、模型完成原因和最终业务验收分别记录。

来源共享 `blockedUntil` 的计时器也只适合简单单请求：旧计时器可能在新请求运行中重新启用按钮。可按 request ID 管理状态、取消旧计时器，在回调中重新计算禁用条件；`AbortController` 和总截止时间也要属于同一请求。

## 6. 渲染与隐私：模型输出按不可信内容处理

纯文本结果写 `textContent`，不要拼进 `innerHTML`。如果需要Markdown/富文本，使用明确的解析与消毒策略；HTML属性、URL、脚本数据各有不同边界，一次文本转义不能覆盖全部上下文。

来源用SHA-256摘要只允许指定内联脚本与样式，配合 `connect-src 'self'` 等CSP约束。它能缩小可执行代码范围，但已允许脚本的逻辑缺陷、错误数据出口和不当权限仍然存在；不要承诺“浏览器必定阻止所有攻击”。修改脚本/样式后重新生成摘要并检查实际响应头与页面行为。

日志建议保请求ID、规范化路由、HTTP状态、应用终态、输入大小、耗时与有限错误码。不要直接记录输入、输出、含查询的完整URL或原始地址；反向代理、框架调试日志、异常采样、分析SDK与模型端留存也要同样检查。对“服务器只保存长度”的提示，必须核所有实际写入路径，而非只看自定义 logger。

来源把地址经过带密钥HMAC后截取短摘要，适合减少直接标识暴露；这是可关联的假名，不是匿名。持有密钥的人可验证已知地址，短摘要也可能碰撞。应决定用途、访问者、轮换、保存期限与删除机制，不把它当身份认证或无需保护的数据。

## 7. Gradio与Streamlit如何保住同一合同

两者可省去表单、组件与部分反馈代码，但调用限额、用户身份、上游密钥和真实完成判定仍需应用承担。

| 方案 | 适合的组织方式 | 关键易错点 |
|---|---|---|
| 自写HTML与HTTP | 想学习每一层协议，界面和服务需精确控制 | 手写解析、连接与错误路径多；来源标准库服务器仅为教学 |
| Gradio | 输入组件 → Python函数/生成器 → 输出组件 | 通用文本输出的yield是当前组件值；若要逐步展示句子，通常yield累积文本，而不是每次只给新片段 |
| Streamlit | 按脚本组织控件、数据和结果，表单一次提交一组值 | 默认交互触发重跑；把昂贵调用放在明确提交分支，避免改一个控件就重复调用 |

**Gradio读法**：`Interface`定义输入与输出，生成器提供一系列更新；`queue(max_size=20)`一类参数限制等待数量，事件并发上限是另一维。不要把队列上限20解释成允许20个并行模型任务。框架产生的API、文件和管理入口要逐个检查认证/限流，隐藏API说明不等于取消权限。

2026-10-16查官方仓库 `de986c72372e233ffaaa7abe1b93608d4d115065`，Interface的 `flagging_mode` 按显式参数、环境变量、默认manual选择，manual/auto可能保存输入输出，never关闭这条flagging路径；自定义回调、示例缓存或其它组件仍需独立核查。本文不固化临时分享链接的有效期，也没有安装Gradio。依据：[官方streaming说明](https://github.com/gradio-app/gradio/blob/de986c72372e233ffaaa7abe1b93608d4d115065/guides/04_additional-features/02_streaming-outputs.md)、[Interface配置与实现](https://github.com/gradio-app/gradio/blob/de986c72372e233ffaaa7abe1b93608d4d115065/gradio/interface.py)。

**Streamlit读法**：`st.form`合并一组控件的提交；`st.write_stream`接收增量输出。模型/连接可缓存，但默认global的资源可能跨用户与重跑共享可变对象；不能把用户聊天历史存进共享模型对象。2026-10-16官方v1.66.0文档已经区分global和session资源作用域，global要求线程安全；不要把“所有缓存必定对所有会话共享”写成永远成立。依据：[执行流](https://docs.streamlit.io/develop/api-reference/execution-flow)、[资源缓存](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_resource)。认证接入仍需配置身份提供方及授权边界，显示登录按钮不等于对所有后端入口完成授权。

Python官方明确 `http.server` 不建议用于生产，见[3.12文档](https://docs.python.org/3.12/library/http.server.html)。有了持续外部用户、可用性承诺、账户/历史、明确费用预算或受约束数据时，应重新设计认证授权、持久状态、作业管理、追踪和费用，而不能把演示链接直接当生产交付。

## 8. 五项实践与参考判据

1. **调整额度**：容量2、补充1/秒，先假设7请求同时到达，手算2接收5拒绝；再明确真实循环的到达时间。测试0秒、半秒、1秒、长空闲、不同用户及并发原子扣除，拒绝不能扣成负数。
2. **增加language字段**：只接受字符串`en`；缺失、`zh`、布尔值和列表各明确拒绝政策及422错误，不因Python注解存在就认为已校验。有效`en`继续遵守原text合同。
3. **保留能力反例**：增加“The screen is not good.”并标明关键词模型忽略否定；同时放三类正常例子。分数是关键词差的归一化，不能标为模型置信概率。
4. **可信代理身份**：来自非代理的连接无论怎样伪造X-Forwarded-For，仍不能选择别人的桶；代理链如何挑地址有固定规则，多人共享出口和多实例状态分别核。不启动代理也可先写出这几组输入/期望身份。
5. **替换真实流后端**：先约定普通/流式共同输出、取消传播、费用和完整终态，再用固定事件模拟首片、迟到错误、EOF缺done、重复序号和上限。真实API实验另记模型/SDK、环境、用户端TTFT和服务端计时口径，不用来源的人为等待输出作结果。

## 9. 六题自检与发布前证据

| 问题 | 判断标准 |
|---|---|
| 页面有限长，还要服务器再验吗？ | 要。API可绕过界面，且浏览器、码点、字节与token计量可能不同。 |
| 合同是否只包含前端样式？ | 包含输入、调用、输出与失败；超时、成本和终态都是具体约定。 |
| SSE一定得用EventSource吗？ | 不。POST正文与认证头可使用fetch手工读流；EventSource的GET订阅也可指向已创建的受控任务。 |
| 记录带密钥地址摘要就是匿名吗？ | 不是。是可关联假名，不能代替身份、权限或数据最小化。 |
| 200后模型失败怎样提示？ | 尽可能发应用错误事件；写失败和缺终态记录未完成/未知，不重发HTTP头。 |
| 百个用户各自不过限会不会耗光预算？ | 会。单用户速率和全局调用/费用预算必须分别设置，还要管并发、队列和实际重试。 |

来源发布检查单20项被归入本章九节：类型/大小/例子/超时，重复提交/反馈/首内容/中途失败，错误码/脱敏，限速/代理键/总预算/身份/API旁路/渲染，日志/保存功能/告知，以及产品化信号。每项记录通过、失败或未知及代码/配置证据；没有证据不能记通过。流式不是每种模型输出的强制要求，例如极快的小分类器可一次返回；应说明选择与体验，而不机械照抄检查单的“必须流式”。
