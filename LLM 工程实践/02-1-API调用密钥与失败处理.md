# API 调用、密钥与失败处理

先修：Python 字典、JSON、异常与环境变量。本章解释一次请求的生命周期，先用本地响应样本学习，再按需要连接服务。模型文件与环境记录见[模型获取](./02-模型获取与环境管理.md)，工具循环见[工具使用](../Agentic%20Design%20Patterns/01-核心章节/05-工具使用.md)。

## 1. 把一次调用拆成五件事

1. **端点**：服务地址和资源路径。主机存在不代表具体端点可用。
2. **身份与授权**：API Key、短期令牌等证明调用方身份/能力；不是所有 API 都必须用同一种密钥。
3. **请求契约**：方法、头、内容类型、模型标识、消息或参数。
4. **响应契约**：状态码、内容块、用量、结束原因；成功 HTTP 不等于业务答案正确。
5. **运行策略**：超时、重试、日志、成本限制、幂等和取消。

SDK 包装 HTTP、对象转换和部分重试，不能消除权限、配额、服务故障或输出校验。不同供应商的字段、认证头、流式事件和能力不同，不能直接把一家的请求原样改 URL 使用。

## 2. 密钥怎样进入程序

```python
import os

configured = bool(os.environ.get("ANTHROPIC_API_KEY"))
print("密钥已配置" if configured else "尚未配置密钥")
```

这只检查有无值，不验证权限，也不打印密钥的一部分。环境变量是传递方式，不是密码保险箱；可被进程环境、错误日志或调试器暴露。

开发机可以用不入 Git 的 `.env`；Python 不会自动读取它，需明确加载方式。项目已有变量和文件变量谁优先必须写清。简易 `KEY=VALUE` 解析器不一定支持转义、多行、变量展开，不能假装等同完整 dotenv 实现。

提交的 `.env.example` 只写名称与假值：

```text
ANTHROPIC_API_KEY=请在本地配置真实值
AI_MODEL_ID=使用账户实际支持的模型标识
```

把 `.env` 写入 `.gitignore` 只阻止新文件被跟踪；已提交的凭据仍可能在历史里。泄露后应撤销/轮换凭据，再按仓库流程处理历史。详细配置策略见[Python Core 17](../Python/Core/17-DevOps.md)。

## 3. 先用本地响应理解解析

下面是教学构造的样本，不是一次真实 API 返回，也不是模型能力结果：

```python
fixture = {
    "content": [
        {"type": "text", "text": "神经网络由可训练的函数层组成。"},
        {"type": "tool_use", "id": "示例工具调用", "name": "lookup", "input": {}},
    ],
    "usage": {"input_tokens": 12, "output_tokens": 18},
    "stop_reason": "tool_use",
}
text = "\n".join(
    block["text"] for block in fixture["content"]
    if block.get("type") == "text" and isinstance(block.get("text"), str)
)
assert text == "神经网络由可训练的函数层组成。"
assert fixture["stop_reason"] == "tool_use"
print(text)
```

响应可能含多个文本块、工具请求或其他内容，不能默认 `content[0].text` 总存在。结束原因是工具调用时，显示文本不等于任务结束；程序是否执行工具还受业务权限控制。

Token 是模型分词单位，不等于一个词、一个字或一个流式事件。输入/输出用量要按服务定义解释；缓存、推理或其他计费项目可能单独列出，不用虚构免费额度或固定价格估算。

## 4. 原始 HTTP 与 SDK 对照

以 Anthropic Messages API 作有版本说明的例子。运行前需要自己配置有权限的真实 key 与模型 ID；本文没有执行真实计费请求。模型名没有默认回退，避免把过时别名固化进教材。

```python
import json
import os
import urllib.error
import urllib.request

key = os.environ["ANTHROPIC_API_KEY"]
model = os.environ["AI_MODEL_ID"]
request = urllib.request.Request(
    "https://api.anthropic.com/v1/messages",
    method="POST",
    headers={
        "Content-Type": "application/json",
        "x-api-key": key,
        "anthropic-version": "2023-06-01",
    },
    data=json.dumps({
        "model": model,
        "max_tokens": 128,
        "messages": [{"role": "user", "content": "用一句话解释矩阵乘法。"}],
    }).encode("utf-8"),
)
try:
    with urllib.request.urlopen(request, timeout=30) as response:
        payload = json.load(response)
except urllib.error.HTTPError as exc:
    # 状态码可诊断；日志不复制敏感请求头或任意完整响应体。
    raise RuntimeError(f"服务返回 HTTP {exc.code}") from exc
else:
    for block in payload.get("content", []):
        if block.get("type") == "text":
            print(block.get("text", ""))
    print("用量：", payload.get("usage", {}))
```

等价 SDK 片段（需安装匹配版本的 `anthropic`，不是完整独立程序）：

```python
import anthropic
client = anthropic.Anthropic(api_key=key, timeout=30.0)
message = client.messages.create(
    model=model, max_tokens=128,
    messages=[{"role": "user", "content": "用一句话解释矩阵乘法。"}],
)
for block in message.content:
    if block.type == "text":
        print(block.text)
```

比较时看相同消息、模型与参数，分别保存状态、结束原因、用量和请求关联 ID；输出文字未必逐字相同。SDK 可能有自动重试，叠加应用重试会放大次数，因此先了解实际重试策略。`timeout=30` 也不一定限制从第一次尝试到所有重试结束的总墙钟时间，端到端预算应另外管理。

TypeScript 用 `process.env` 取配置，使用 `fetch` 后须检查 `response.ok` 再解析 JSON；静态 `as SomeResponse` 类型断言不验证远端数据。可用运行时 schema 或逐字段检查建立相同契约。

## 5. 错误分类决定处理方式

| 观察 | 先核对 | 合理行动 |
|---|---|---|
| 400 或契约错误 | 字段、模型 ID、消息结构、上下文限制 | 修请求；原样重试通常无益 |
| 401 | 凭据有无、过期、认证方式 | 修身份；不打印 key 诊断 |
| 403 | 模型/端点/组织权限 | 核对授权，不从密钥有值推断权限 |
| 429 | 速率或配额、响应提示 | 限速，遵循可用的 Retry-After，有限退避 |
| 5xx | 服务状态、请求是否已受理 | 在剩余预算和幂等条件内有限重试 |
| 超时/连接中断 | DNS/TLS/网络/服务/客户端总预算 | 状态可能未知，查询或去重后再决定 |
| 200 但缺字段/错误答案 | 实际响应类型与任务验收 | 格式验证和业务验证分别失败 |

退避可使用 `min(上限, 基准×2^次数)+少量随机扰动`，设置总尝试数、总时限和成本上限。可取消错误必须及时结束，不能捕获所有异常后无限睡眠。

尤其是会写外部系统的工具：请求超时不能证明“没有执行”。用业务幂等键、状态查询和执行日志避免重复创建。纯模型生成重试也可能再次计费，不能无界处理。

## 6. 流式返回

流式返回是逐段收到事件；片段可能切开字词、JSON 或 UTF-8 数据，不能每个事件都当成完整答案。程序应累积内容、解释终止事件、记录取消和中途错误，再校验最终结果。

第一块响应更早可以改善交互，但不保证总完成时间更短。区分首 Token/事件时间、完整结束时间与持续生成速度，测量说明是否包括网络和排队。

## 7. 练习与核对

1. 把本地样本的第一个块换成 `tool_use`，文本提取还会成功吗？答案：按类型过滤仍能成功；直接读第一个块的 `text` 会失败。
2. `.env` 已加入忽略规则，为什么历史仍可能泄露？答案：忽略不是撤销已跟踪文件，也不会改已有提交。
3. 模型 API 429 与外部创建订单超时，能使用同一重试逻辑吗？答案：不能，后者可能已创建，需要幂等和状态核对。
4. 设计诊断记录：时间、端点类型、错误类别、关联 ID、模型标识、重试次数、脱敏输入特征；说明你没有保存哪类敏感数据。
