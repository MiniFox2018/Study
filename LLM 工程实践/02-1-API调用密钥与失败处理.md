# API 调用、密钥与失败处理

先修：Python 字典、JSON、异常与环境变量。本章解释一次请求的生命周期，先用本地响应样本学习，再按需要连接服务。模型文件与环境记录见[模型获取](./02-模型获取与环境管理.md)，工具循环见[工具使用](../Agentic%20Design%20Patterns/01-核心章节/05-工具使用.md)。

## 1. 把一次调用拆成五件事

1. **端点**：服务地址和资源路径。主机存在不代表具体端点可用。
2. **身份与授权**：API Key、短期令牌等证明调用方身份/能力；不是所有 API 都必须用同一种密钥。
3. **请求契约**：方法、头、内容类型、模型标识、消息或参数。
4. **响应契约**：状态码、内容块、用量、结束原因；成功 HTTP 不等于业务答案正确。
5. **运行策略**：超时、重试、日志、成本限制、幂等和取消。

SDK 包装 HTTP、对象转换和部分重试，不能消除权限、配额、服务故障或输出校验。不同供应商的字段、认证头、流式事件和能力不同，不能直接把一家的请求原样改 URL 使用。

## 2. 密钥怎样进入程序

```python
import os

configured = bool(os.environ.get("ANTHROPIC_API_KEY"))
print("密钥已配置" if configured else "尚未配置密钥")
```

这只检查有无值，不验证权限，也不打印密钥的一部分。环境变量是传递方式，不是密码保险箱；可被进程环境、错误日志或调试器暴露。

开发机可以用不入 Git 的 `.env`；Python 不会自动读取它，需明确加载方式。项目已有变量和文件变量谁优先必须写清。简易 `KEY=VALUE` 解析器不一定支持转义、多行、变量展开，不能假装等同完整 dotenv 实现。

提交的 `.env.example` 只写名称与假值：

```text
ANTHROPIC_API_KEY=请在本地配置真实值
AI_MODEL_ID=使用账户实际支持的模型标识
```

把 `.env` 写入 `.gitignore` 只阻止新文件被跟踪；已提交的凭据仍可能在历史里。泄露后应撤销/轮换凭据，再按仓库流程处理历史。详细配置策略见[Python Core 17](../Python/Core/17-DevOps.md)。

## 3. 先用本地响应理解解析

下面是教学构造的样本，不是一次真实 API 返回，也不是模型能力结果：

```python
fixture = {
    "content": [
        {"type": "text", "text": "神经网络由可训练的函数层组成。"},
        {"type": "tool_use", "id": "示例工具调用", "name": "lookup", "input": {}},
    ],
    "usage": {"input_tokens": 12, "output_tokens": 18},
    "stop_reason": "tool_use",
}
text = "\n".join(
    block["text"] for block in fixture["content"]
    if block.get("type") == "text" and isinstance(block.get("text"), str)
)
assert text == "神经网络由可训练的函数层组成。"
assert fixture["stop_reason"] == "tool_use"
print(text)
```

响应可能含多个文本块、工具请求或其他内容，不能默认 `content[0].text` 总存在。结束原因是工具调用时，显示文本不等于任务结束；程序是否执行工具还受业务权限控制。

Token 是模型分词单位，不等于一个词、一个字或一个流式事件。输入/输出用量要按服务定义解释；缓存、推理或其他计费项目可能单独列出，不用虚构免费额度或固定价格估算。

## 4. 原始 HTTP 与 SDK 对照

以 Anthropic Messages API 作有版本说明的例子。运行前需要自己配置有权限的真实 key 与模型 ID；本文没有执行真实计费请求。模型名没有默认回退，避免把过时别名固化进教材。

```python
import json
import os
import urllib.error
import urllib.request

key = os.environ["ANTHROPIC_API_KEY"]
model = os.environ["AI_MODEL_ID"]
request = urllib.request.Request(
    "https://api.anthropic.com/v1/messages",
    method="POST",
    headers={
        "Content-Type": "application/json",
        "x-api-key": key,
        "anthropic-version": "2023-06-01",
    },
    data=json.dumps({
        "model": model,
        "max_tokens": 128,
        "messages": [{"role": "user", "content": "用一句话解释矩阵乘法。"}],
    }).encode("utf-8"),
)
try:
    with urllib.request.urlopen(request, timeout=30) as response:
        payload = json.load(response)
except urllib.error.HTTPError as exc:
    # 状态码可诊断；日志不复制敏感请求头或任意完整响应体。
    raise RuntimeError(f"服务返回 HTTP {exc.code}") from exc
else:
    for block in payload.get("content", []):
        if block.get("type") == "text":
            print(block.get("text", ""))
    print("用量：", payload.get("usage", {}))
```

等价 SDK 片段（需安装匹配版本的 `anthropic`，不是完整独立程序）：

```python
import anthropic
client = anthropic.Anthropic(api_key=key, timeout=30.0)
message = client.messages.create(
    model=model, max_tokens=128,
    messages=[{"role": "user", "content": "用一句话解释矩阵乘法。"}],
)
for block in message.content:
    if block.type == "text":
        print(block.text)
```

比较时看相同消息、模型与参数，分别保存状态、结束原因、用量和请求关联 ID；输出文字未必逐字相同。SDK 可能有自动重试，叠加应用重试会放大次数，因此先了解实际重试策略。`timeout=30` 也不一定限制从第一次尝试到所有重试结束的总墙钟时间，端到端预算应另外管理。

TypeScript 用 `process.env` 取配置，使用 `fetch` 后须检查 `response.ok` 再解析 JSON；静态 `as SomeResponse` 类型断言不验证远端数据。可用运行时 schema 或逐字段检查建立相同契约。

## 5. 错误分类决定处理方式

| 观察 | 先核对 | 合理行动 |
|---|---|---|
| 400 或契约错误 | 字段、模型 ID、消息结构、上下文限制 | 修请求；原样重试通常无益 |
| 401 | 凭据有无、过期、认证方式 | 修身份；不打印 key 诊断 |
| 403 | 模型/端点/组织权限 | 核对授权，不从密钥有值推断权限 |
| 429 | 速率或配额、响应提示 | 限速，遵循可用的 Retry-After，有限退避 |
| 5xx | 服务状态、请求是否已受理 | 在剩余预算和幂等条件内有限重试 |
| 超时/连接中断 | DNS/TLS/网络/服务/客户端总预算 | 状态可能未知，查询或去重后再决定 |
| 200 但缺字段/错误答案 | 实际响应类型与任务验收 | 格式验证和业务验证分别失败 |

退避可使用 `min(上限, 基准×2^次数)+少量随机扰动`，设置总尝试数、总时限和成本上限。可取消错误必须及时结束，不能捕获所有异常后无限睡眠。

尤其是会写外部系统的工具：请求超时不能证明“没有执行”。用业务幂等键、状态查询和执行日志避免重复创建。纯模型生成重试也可能再次计费，不能无界处理。

## 6. 流式返回

流式返回是逐段收到事件；片段可能切开字词、JSON 或 UTF-8 数据，不能每个事件都当成完整答案。程序应累积内容、解释终止事件、记录取消和中途错误，再校验最终结果。

第一块响应更早可以改善交互，但不保证总完成时间更短。区分首 Token/事件时间、完整结束时间与持续生成速度，测量说明是否包括网络和排队。

## 7. 练习与核对

1. 把本地样本的第一个块换成 `tool_use`，文本提取还会成功吗？答案：按类型过滤仍能成功；直接读第一个块的 `text` 会失败。
2. `.env` 已加入忽略规则，为什么历史仍可能泄露？答案：忽略不是撤销已跟踪文件，也不会改已有提交。
3. 模型 API 429 与外部创建订单超时，能使用同一重试逻辑吗？答案：不能，后者可能已创建，需要幂等和状态核对。
4. 设计诊断记录：时间、端点类型、错误类别、关联 ID、模型标识、重试次数、脱敏输入特征；说明你没有保存哪类敏感数据。

## 文档里的HTTP示例怎样持续验证

API教程会随字段和服务契约改变而失效。把网页段落交给模型概括，不能发现“第一步拿到的ID能否用于第二步”“文档仍断言旧字段”这类错误。一个实用做法是从作者明确声明的请求块生成manifest，按依赖顺序检查请求，再输出带源码位置的结果与修订提案。

### 第一阶段：只提取明确声明的请求

先规定一个小合同：只有独立的request代码围栏才表示可运行示例，普通json或展示用代码保持资料性质。每一步至少保存id、method、path、期望status、可选body、assert、capture和起始行；多文件时还要保存文件名与教程摘要。

例如下面是已经提取出的教学manifest；它是数据，不会自行发送请求：

```json
[
  {"id":"create","method":"POST","path":"/tasks","body":{"title":"整理笔记"},"status":201,"capture":{"taskId":{"path":"id","type":"number"}},"line":5},
  {"id":"read","method":"GET","path":"/tasks/{{taskId}}","status":200,"assert":{"name":"整理笔记"},"line":11},
  {"id":"remove","method":"DELETE","path":"/tasks/{{taskId}}","status":200,"assert":{"removed":true},"line":15}
]
```

方法、路径、状态类型、唯一id、变量声明和数量都在提取时检查，错误附具体行号。示例项目限制最多20步、方法为GET/POST/PUT/PATCH/DELETE、状态为100～599；这些是它的子集和资源政策，不是完整HTTP合法性定义。

解析Markdown还要跟踪围栏状态：一个普通代码块内部可以展示字面量request围栏，不能仅逐行匹配到它就执行。明确缩进/尾空格规则，拒绝未闭合块、非对象JSON和过深/过大输入。TypeScript类型声明不能代替读取外来文件时的运行校验。

### 第二阶段：保留变量类型和来源

假设POST返回`{"id":7,"title":"整理笔记"}`。声明taskId取id且类型为number，捕获结果必须是数字7；`{"task":"{{taskId}}"}`中的完整占位值应替换成`{"task":7}`，不能一律变成字符串。嵌在`"任务{{taskId}}"`里的值才转成文本。

按递归规则处理数组和对象，输出新值，保原输入。仅允许声明过的变量，不求值表达式；未知变量、类型不符、非有限数字和覆盖旧变量都失败。读取响应的点路径时，每一层只访问对象自己的属性；数组索引也要按合同解释，不能沿原型链找值。

一次捕获可以先写到临时映射，全部通过后再发布到已确认变量表，避免前几个成功、后一个失败留下半更新。独立调用capture接口时也要核名称和类型，不能假设调用方一定经过了教程提取器。

URL中的值需要按位置编码后重新解析和检查。相同origin只约束协议、主机与端口，不保证还在同一个业务路径；点段可缩短路径，需要路径范围时单独验证。不能用字符串以某域名开头替代结构化URL校验。[WHATWG路径与点段规则](https://url.spec.whatwg.org/#url-path-segment)，2026-10-19只核相关定义与path解析步骤。

### 第三阶段：有界请求与失败后的真实状态

先声明端点和允许范围。示例项目默认只接受解析后限定的loopback地址，外部测试端点需显式开启；base不含凭据、业务路径、query或fragment。每个解析后的请求再次核origin，拒绝重定向，避免通过后续响应悄悄扩大访问范围。这些限制不是通用网络沙箱，也不证明服务业务行为安全。

请求的生命周期应按顺序处理：

```text
校验步骤与变量 → 形成URL/JSON body → 启动请求期限
 → 接收状态与有界响应流 → 解码/解析JSON
 → 核期望status → 核各断言 → 原子发布捕获变量
 → 保存本步收据 → 决定能否进入下一步
```

期限覆盖读完整响应，字节上限按每个到达的chunk累计；仅限制连接建立或只信Content-Length不够。示例默认1500毫秒/65536字节，允许上限30000毫秒/1048576字节，是教学参数。fetch交给应用的内容字节、线上压缩字节、请求体大小与解析后的对象内存不是同一个口径；同步JSON解析和深比较也不会被事件循环timer硬抢占，CPU/深度限制另设。

状态、传输、解析和业务断言分别记录。即使JSON无效或超出限额，也尽可能保存状态码、已收长度和有界且脱敏的诊断；不要只留下“不是JSON”而丢掉必要上下文。204等合法的无内容响应需要自己的合同，不能因为期望状态在100～599就假设它一定有JSON body。

假设manifest第二步的真实JSON仍是`{"id":7,"title":"整理笔记"}`，却断言name字段，则流程为：

| 步骤 | 结果 | 发生了什么 |
|---|---|---|
| create | pass | 状态、断言和类型捕获通过，taskId=7 |
| read | fail | name不存在；保留请求、响应、行11与失败原因 |
| remove | skip | 没发送DELETE；没有新响应，也不能把跳过当成功 |

失败即停适用于这个有序教程合同，不表示回滚此前POST。远端任务可能已经创建，后续重跑要考虑幂等键、资源归属和清理安排。静态fixture只按method/path返回固定JSON，即使通过真实HTTP通信，也未必检查请求体或实现真实服务的业务状态。

### 第四阶段：报告和修订分别验收

输出可包含请求manifest、逐步results、JUnit与本地HTML。JUnit按本例应为3个testcase、1失败、1跳过；报告命令退出0只说明产物写出成功，不能据此让CI认定例子全通过。CI需要核必需步骤集合、实际发送与跳过、非空案例及每项终态。

报告生成器接受手写Receipt时，不应无条件宣称它们来自真实HTTP。检查id/行号与manifest一一对应、数量/顺序/枚举、请求和响应身份、运行完成与截断范围；用教程、manifest、配置和收据摘要绑定一次运行。HTML按上下文转义，嵌入脚本中的JSON单独处理`<`等字符；XML还需拒绝不允许的控制字符。

修订草稿可以是`id、line、issue、proposal、approved`。默认未批准，读者填写建议并审阅；重新导入时核schema版本、当前失败步骤、行号/问题一致、批准值严格为布尔、已批准提案非空及id不重复。批准仅代表一次明确的审阅状态，不证明建议正确；提案也不直接修改源文档。

仅匹配id/line/错误文字还不够：教程换了内容却恰好仍在同一行报同样错误时，旧批准可能误用。补教程/manifest版本、原文片段与本次收据摘要，真正应用补丁前核上下文，应用后再验证。将审批意图、补丁执行和例子通过分成三件事，避免“建议已批准”被当成“文档已修好”。

自检：完整占位数字与嵌入文本怎样不同？第二步失败后第三步是否收到响应？报告exit0能否作为全通过门槛？同id/行号/错误文字能否识别整个教程版本？参考答案分别是保留数字/转文本、没有发送所以没有、不能、不能，还需内容与运行身份。

## 离线Batch：提交、逐项完成与结果对账

Batch提交后由服务方异步处理，continuous batching在推理引擎内调度活跃请求，应用异步queue则是自己排任务。三者可能组合，不应混称“异步所以50%便宜”。按用户实际交付期限/互动、数据保留与地域、支持能力、失败/过期容忍、任务依赖、流量和完整费用决定lane；分钟期限不因后台处理而自动适合vendor的小时窗口。

2026-10-10选读[OpenAI Batch](https://developers.openai.com/api/docs/guides/batch)、[Claude Message Batches](https://platform.claude.com/docs/en/build-with-claude/batch-processing)和[Google batch文档](https://cloud.google.com/vertex-ai/generative-ai/docs/multimodal/batch-prediction-gemini)：OpenAI输入为JSONL文件，每条请求有唯一custom_id和endpoint/body；Claude创建时传requests列表、每条含custom_id与params，输出结果是逐项JSONL，不能把输出格式写成“创建上传JSONL”。两者允许部分成功/错误/取消/过期，结果次序不能按输入下标配对。Google还区分排队与运行窗口，并明确该路径不在SLA SLO覆盖；“所有厂商24h内保证每条成功”不成立。

保存稳定的business item ID、input digest/data/model/template/schema revision、attempt、供应商batch ID和提交/状态/结果receipt。提交前检查重复ID、大小和字段；提交后用持久store恢复poll/event游标，失败/取消不丢已经完成项。下载就绪仍要逐item核custom_id、结果类别、输出schema与证据；missing保持unknown，不自动写failed然后重做全batch。用户读取结果时重新核当前权限，不能因为旧提交允许就永久公开新文件。

sourceTS的deferred Promise演示“现在拿句柄、以后得到值”，但Promise不跨进程持久；`closeBatch`未检查重复close，并可能同job重复处理；逐jobreject后batch仍completed，说明批次终止与每item成功是两回事。生产应定义有限状态、唯一提交/去重、分项终态与持久恢复；对具外部效果的后续步骤先核业务幂等回执，不把模型API custom_id误当供应商保证的全流程exactly-once。

本完整标准库例使用**应用规范化回执**，不是某厂商原始schema。输入三item，结果乱序到达，其中成功、过期和费用未知错误分别入账；重复相同回执忽略，冲突回执拒绝，不替unknown释放预留。它不调用API、没有poll/webhook、持久store或真正费用结算，当前读取权限由实际应用另核。

```python
import copy, hashlib, json

def digest(obj):
    return hashlib.sha256(json.dumps(obj,sort_keys=True,separators=(',',':'),
                                    allow_nan=False).encode()).hexdigest()
class ResultLedger:
    def __init__(self, inputs):
        if type(inputs) is not list or not inputs:
            raise ValueError('输入须为非空列表')
        for r in inputs:
            if type(r) is not dict or set(r) != {'id','input'}:
                raise ValueError('输入item字段')
            if type(r['id']) is not str or not r['id']:
                raise ValueError('item ID须为非空字符串')
        if len({r['id'] for r in inputs}) != len(inputs):
            raise ValueError('输入ID重复')
        self.expected={r['id']:digest(r['input']) for r in inputs}
        self.results={}
    def receive(self, row):
        if type(row) is not dict or set(row) != {'id','input_digest','attempt','status','body','cost_units'}:
            raise ValueError('规范化回执字段')
        if type(row['id']) is not str or not row['id']:
            raise ValueError('回执ID须为非空字符串')
        if row['id'] not in self.expected or row['input_digest'] != self.expected[row['id']]:
            raise ValueError('未知ID或输入版本不匹配')
        if type(row['attempt']) is not int or row['attempt'] != 1:
            raise ValueError('attempt版本不匹配')
        if row['status'] not in {'succeeded','errored','canceled','expired'}:
            raise ValueError('item未终结')
        c=row['cost_units']
        if c is not None and (type(c) is not int or c < 0):
            raise ValueError('费用无效')
        if row['status']=='succeeded' and (not isinstance(row['body'],dict) or
                                         set(row['body']) != {'label'} or
                                         row['body']['label'] not in {'yes','no'}):
            raise ValueError('输出schema未通过')
        if row['status']!='succeeded' and row['body'] is not None:
            raise ValueError('失败回执不得含已接纳结果')
        old=self.results.get(row['id'])
        if old is not None:
            if digest(old)!=digest(row): raise ValueError('重复ID回执冲突')
            return 'duplicate'
        self.results[row['id']]=copy.deepcopy(row)
        return 'recorded'
    def summary(self):
        return {'missing':sorted(set(self.expected)-set(self.results)),
                'accepted':sorted(k for k,v in self.results.items() if v['status']=='succeeded'),
                'known_cost':sum(v['cost_units'] for v in self.results.values() if v['cost_units'] is not None),
                'unsettled':sorted(k for k,v in self.results.items() if v['cost_units'] is None)}
```

### 原15课五项练习的参考判断

1. **10万文档、3K prefix、500 output的叠加费用？** 还缺每文档动态input、缓存命中、各价和write次数，先列C=N[(shared+dynamic)pi+output po]/1e6，对缓存拆read/write/miss并加batch倍率。题设取dynamic=2000、pi=3/百万、po=15、read=.3、write=3.75、N100000：sync2250，batch+cache约720.005，约32%，不是默认10%；均教学假设。
2. **三个产品功能怎样分lane？** 即时对话走同步；用户分钟内检查的文档处理走有deadline的异步队列；无即时交互且交付/保留政策容许的离线标签可考虑vendor batch。异步队列只是调度不自动50%折扣，vendorbatch的排队、过期和数据条件也需可接受。

4. **24h窗口但P99为20h怎样说明？** 明确提交/排队/运行/就绪时间和产品交付期限，进度显示processing不虚构ETA；持久轮询/事件账本，成功/失败/取消/过期逐item对账。期限前合法升级需保证无重复结果副作用和费用记录；Google排队窗口还可能另计，不称统一24h保证。
5. **共享prefix多长比预留GPU便宜？** 先得GPU每小时含空闲容量/运行人工/存储费、任务吞吐/质量/SLO、batch读写命中价和动态输入输出。把相同时间窗vendor total与GPU total相等求prefix长度；两边都依赖traffic，不存在无输入通用交叉点。

### 原15课六题中文自检

1. **跨供应商统一50%和24h保证？** 分别核API/型号/区域/计费。已核OpenAI/Claude描述50%，Google还有排队最多72h、运行窗口且排除SLA SLO；不是统一成功保证。
2. **24h内每item都成功吗？** 不一定，expired/canceled/errored和成功可并存；batch终态和item终态分别对账。
3. **叠加可到10%吗？** 有特定前缀占比/命中/读写价格时可能，不能当默认；用实际usage分项算。
4. **离线任务应默认同步吗？** 由真实期限、数据与失败政策分lane；async queue不自动享vendorbatch折扣。
5. **三方输入格式完全相同吗？** OpenAI JSONL文件上传；Claude create requests列表、结果JSONL；Google按GCS/BigQuery具体适配，不把结果格式当创建格式。
