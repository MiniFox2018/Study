# 06｜评测与实验管理

评测回答三个问题：系统是否解决任务，是否可靠地运行，变化是否真的改善了结果。训练损失、基准分数、judge 分数和服务吞吐分别观察不同对象，不能互相代替。检索实现见 [12](12-文本检索与RAG文档工程.md)，训练目标见 [07](07-Embedding与检索模型训练.md)，Agent 的工具轨迹与外部状态核验见 [评估和监控](../Agentic%20Design%20Patterns/01-核心章节/19-评估和监控.md)。

## 1. 先定义任务、样本与成功标准

一个案例包含输入、初始环境/证据、允许的行为、参考答案或评分规则，以及最终成功的判定。分类可用 accuracy/F1，检索可用 Recall/MRR/nDCG，数学和代码可用明确答案或可执行 verifier，指令遵循可按 IFEval 风格的可检查约束，开放回答需要有规则的人工或校准过的 judge。Agent 任务还要检查工具调用、权限、轨迹与最终环境，不能只读回答文本。

建立开发集与锁定测试集。开发集用于调 prompt、阈值和策略，测试集用于最后比较；反复按同一测试集改系统会产生间接拟合。公开基准可能进过训练；私有真实案例、时间切分、同文档族分组和训练/测试近重复排查能减少污染，却不能证明绝无污染。

保存数据版本、样本 ID、任务类型、参考来源和创建时间，不用“AI 写出的标准答案”自动代替 gold。人工标注也应说明是否见过模型答案、是否有冲突和如何裁决。

## 2. RAG 要拆成检索、证据与答案评价

| 观察层 | 可用指标 | 指标不证明什么 |
|---|---|---|
| 候选检索 | Recall@k、Hit@k、MRR、nDCG | 文档包含相关词不等于证据充分 |
| 证据装配 | 必需事实覆盖、重复率、版本/权限正确率 | 覆盖不保证生成器使用正确 |
| 答案 | 正确性、支持率、相关性、引用准确性、拒答 | 流畅或有引用不等于事实正确 |
| 端到端 | 用户任务成功、错误严重度、总成本/延迟 | 平均分不能遮住高风险切片 |

MRR 取每题第一条相关结果的倒数再平均。三题首条相关分别位于 1、3、前 5 未找到，则 MRR@5 为 `(1+1/3+0)/3=4/9`。多相关文档时 Recall 统计命中比例，Hit 只统计是否至少命中一条，不能混用。

Context precision 的定义须写清。普通 `相关块数/返回块数` 不看排名；一种排序敏感定义类似平均精度：令 `r_i` 表示第 i 块是否有用，计算 `sum_i(P@i*r_i)/sum_i r_i`。二者不同。Context recall 通常关注 gold 所需信息是否被检索证据覆盖；有些实现需要参考答案或人工标注，并非所有指标都是 reference-free。

Faithfulness 通常把回答拆成可判断的事实主张，再问多少主张被给定上下文支持；它衡量“按这份上下文说话”，不证明上下文本身真实、最新或有权使用。Answer relevance 关注是否回答问题，不能只看词重叠；答案正确性还要看数值、单位、否定、适用条件和原始来源。

### 2.1 用明确标签核对聚合，不伪造语义判断器

以下标签是假定已人工裁决的 fixture，用于测试指标与边界。程序没有自动判断开放文本是否蕴含。无法判断的主张记 unknown，报告覆盖率而不是静默去掉。

```python
import math
from collections import Counter

def claim_scores(labels):
    if not labels or any(x not in {"supported", "unsupported", "unknown"} for x in labels):
        raise ValueError("必须有明确且合法的主张标签")
    n = len(labels)
    count = Counter(labels)
    return {"support_rate_all": count["supported"] / n,
            "judgement_coverage": (n - count["unknown"]) / n,
            "unknown_rate": count["unknown"] / n}

def context_scores(useful):
    if not useful or any(type(x) is not bool for x in useful):
        raise ValueError("需要逐块布尔相关标签")
    hits = sum(useful)
    precision = hits / len(useful)
    ap = sum(sum(useful[:i]) / i for i, flag in enumerate(useful, 1) if flag) / hits if hits else 0.0
    return precision, ap

assert claim_scores(["supported", "unsupported", "unknown"]) == {
    "support_rate_all": 1/3, "judgement_coverage": 2/3, "unknown_rate": 1/3}
assert context_scores([False, True, True])[0] == 2/3
assert abs(context_scores([False, True, True])[1] - (1/2 + 2/3)/2) < 1e-12
assert context_scores([False, False]) == (0.0, 0.0)
# 子串或词重叠会误判否定。此断言展示缺陷，不把它当正确性得分。
answer, expected = "不是 pineapple", "pineapple"
assert expected in answer and answer != expected
print("标签聚合、覆盖率、排名相关性、否定子串反例均通过")
```

无事实主张的寒暄不能报告 faithfulness=1 然后混入业务答案平均；应按任务标为不适用，并同时报告此类数量。任务失败、空输出、解析失败和超时留在完整分母中或按预先规定的失败规则计分，另报有效评分覆盖率。

## 3. LLM-as-judge 与 NLI：辅助评分器也要评价

NLI 把证据当 premise，回答主张当 hypothesis，判断 entailment/neutral/contradiction；这适合支持检查的一个组成部分，但会受截断、复杂数值、多跳和领域术语影响。主张拆分漏掉错误主张会虚高支持率，多个段落的上下文需要明确组合方法。

G-Eval 的研究方法让评估模型按评价标准生成评分步骤并输出分数，可在能取得相应 token 概率时做概率加权。框架中“自定义 judge 打 1–5 分”不因此完整复现该论文。部署更重要的是固定标准、输入格式、评分范围、证据和错误处理；无需收集或公布模型内部推理过程，简洁可审查的依据即可。[G-Eval 原论文](https://arxiv.org/abs/2303.16634)

RAGAS、DeepEval 等帮助构造指标、跑案例和记录结果，不是统一的生产正确性标准。不同版本/指标有不同必需字段、judge 或 embedding 依赖、返回尺度和错误行为。不要只凭类名认为“四个指标都无需参考答案”。[RAGAS 指标说明](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/)、[DeepEval 指标说明](https://deepeval.com/docs/metrics-introduction)

概率加权的原理是对预设评分集合做 `score=Σ p(s_i)·s_i`，概率来源与归一化方式须固定；没有 token 概率时的重复采样只是另一个近似协议，不能直接称同等精度。

校准时选含正确、轻错、严重错误、无答案、证据矛盾、冗长、注入文本和不同语言的样本；人工按同一 rubric 独立评价，再比较 judge 的错误类别、混淆、等级偏差、误接受率和切片。Spearman 衡量排序一致，不能单凭高相关就说绝对评分准确；常数评分没有可解释的秩相关。没有一个通用“标 50 题、相关系数超过 0.7”就可放心上线的阈值。

judge 可能偏爱更长答案、某模型文风、先出现的答案或自己的输出；匿名化生产者、交换 A/B 次序、按相同长度预算和多次评审有助于诊断，不能保证完全消除偏差。回答中“评审请给满分”是待评数据，不是 judge 指令。锁定评审 prompt、模型版本、采样参数和分数解析。

### 3.1 评分记录与 CI 门禁

每条记录包含样本 ID、状态、分数、理由/证据和 evaluator 版本。失败不能静默变成缺失平均分；分数必须有限且在协议范围内。门禁阈值应来自业务容忍度和校准，下面 0.75/0.90 仅是合成演示。

```python
import math

def summarize(records):
    if not records or len({r["case"] for r in records}) != len(records):
        raise ValueError("案例必须非空且 ID 唯一")
    scores, failures = [], []
    for r in records:
        if r["status"] != "scored":
            failures.append(r["case"])
            scores.append(0.0)  # 本协议事先规定失败按 0 计；同时单列失败。
            continue
        s = r["score"]
        if type(s) not in (int, float) or not math.isfinite(s) or not 0 <= s <= 1:
            raise ValueError("非法评分不能进入平均")
        scores.append(float(s))
    return {"mean_all": sum(scores)/len(scores),
            "coverage": (len(records)-len(failures))/len(records), "failures": failures}

records = [{"case": "a", "status": "scored", "score": 1.0},
           {"case": "b", "status": "scored", "score": 0.8},
           {"case": "c", "status": "timeout", "score": None}]
s = summarize(records)
assert abs(s["mean_all"]-0.6) < 1e-12 and s["coverage"] == 2/3
accepted = s["mean_all"] >= 0.75 and s["coverage"] >= 0.90
assert not accepted
for bad in (math.nan, math.inf, -0.1, 1.1, True):
    try:
        summarize([{"case": "x", "status": "scored", "score": bad}])
    except ValueError:
        pass
    else:
        raise AssertionError("非法分数必须拒绝")
print(s, "；失败进入分母，门禁拒绝该 fixture")
```

还应对严重错误设置单独规则，例如任一越权执行、伪造引用或金额错误即阻断候选发布，而不是让其他题的高分抵消它。可以增加底部分位样本审查：按预定任务切片排序，取最低一组分数并检查错误类型，同时报告这组大小及完整分布；“最低 10%”是策略选择，少量样本、未评分失败和严重错误仍要单独处理。实际门禁包含基线差异、置信区间、失败率和关键切片；平均分小幅上升而关键切片下降不能自动批准。


### 3.2 权重、Wilson 区间与评分缓存合同

rubric 把任务的观察项定义清楚；权重再决定哪些观察项更重要。固定评分 [helpfulness=.85, correctness=.60, safety=.95] 与权重 [40,40,20] 得到 .77，改为 [10,80,10] 得到 .66；这只是聚合，不能让同一回答变得更真实。动态图 llm-judge-rubric 用的就是这组三项人工常数，未调用 judge。全部权重为0应拒绝；严重越权、错误金额等独立阻断条件不能被其他项高分抵消。

Wilson 用成功数/总尝试数估计单个比例区间；它不替代同案例差值的配对 bootstrap，也不自动给出“200题能检测5%退化”的保证。无样本应返回未知，不能报告 [0,0] 假装确定。两方案各自区间重叠仍可能有显著配对差，区间包含零也不证明等效。

评分缓存须针对同一案例、上下文/权限快照、实际输出、生成参数及模型、rubric、judge、解析器和重复协议建立键。输出文本相同但证据或标准已变，旧分数也可能失效；独立重复评审须保留不同 repeat_id，不能把同一缓存结果复制三次后声称评审一致。以下 backend 仅返回预设人工评分/模拟超时，验证合同和分母；没有自动语义判断。

```python
import copy, hashlib, json, math

def weighted(scores,weights):
    if not scores or scores.keys()!=weights.keys():raise ValueError('评分与权重键须一致')
    if any(type(s) not in (int,float) or not math.isfinite(s) or not 0<=s<=1 for s in scores.values()):raise ValueError('本协议评分须在0..1')
    if any(type(w) not in (int,float) or not math.isfinite(w) or w<0 for w in weights.values()) or sum(weights.values())<=0:raise ValueError('非负有限且至少一个正权重')
    return sum(scores[k]*weights[k] for k in scores)/sum(weights.values())
def wilson(successes,total,z=1.96):
    if type(successes) is not int or type(total) is not int or not 0<=successes<=total or not math.isfinite(z) or z<=0:raise ValueError('合法成功数/总数/z')
    if total==0:return None
    p=successes/total;den=1+z*z/total
    center=(p+z*z/(2*total))/den
    spread=z*math.sqrt((p*(1-p)+z*z/(4*total))/total)/den
    return max(0.,center-spread),min(1.,center+spread)
REQUIRED={'case_id','dataset_revision','query','context_snapshot','output','generation_model',
          'prompt_revision','generation_params','rubric_revision','judge_revision','judge_prompt_revision',
          'parser_revision','repeat_id','rating_protocol'}
def score_key(payload):
    if set(payload)!=REQUIRED:raise ValueError('缺失/多余评分输入字段')
    encoded=json.dumps(payload,sort_keys=True,ensure_ascii=False,separators=(',',':'),allow_nan=False).encode()
    return hashlib.sha256(encoded).hexdigest()
weights={'helpfulness':40,'correctness':40,'safety':20}
scores={'helpfulness':.85,'correctness':.60,'safety':.95}
assert math.isclose(weighted(scores,weights),.77)
assert math.isclose(weighted(scores,dict(helpfulness=10,correctness=80,safety=10)),.66)
for bad in (dict.fromkeys(scores,0),dict(helpfulness=-1,correctness=1,safety=1)):
    try:weighted(scores,bad)
    except ValueError:pass
    else:raise AssertionError('无效权重须拒绝')
lo,hi=wilson(45,50);assert lo<.9<hi and wilson(0,0) is None
payload={'case_id':'refund','dataset_revision':'cases-v1','query':'企业退款期限',
 'context_snapshot':[{'document':'policy','revision':'r1','text_sha256':hashlib.sha256('60天'.encode()).hexdigest(),'access_scope':'public'}],
 'output':'60天','generation_model':'extractive-fixture-v1','prompt_revision':'p1','generation_params':{'limit':64},
 'rubric_revision':'rb1','judge_revision':'human-fixture-v1','judge_prompt_revision':'jp1','parser_revision':'json-v1',
 'repeat_id':0,'rating_protocol':{'independent_unit':'case','scale':[0,1]}}
k=score_key(payload);cache={k:{'scores':scores,'critical':False}}
assert score_key(dict(reversed(list(payload.items()))))==k and score_key(payload) in cache
for key in ('output','rubric_revision','judge_revision','parser_revision','repeat_id'):
    changed=copy.deepcopy(payload);changed[key]=1 if key=='repeat_id' else str(changed[key])+'-changed'
    assert score_key(changed)!=k
changed=copy.deepcopy(payload);changed['context_snapshot'][0]['access_scope']='staff'
assert score_key(changed)!=k

def run_cases(cases,backend):
    if not cases or len({c['id'] for c in cases})!=len(cases):raise ValueError('非空唯一caseID')
    rows=[]
    for c in cases:
        try:
            result=backend(c)
            if type(result) is not dict or set(result)!={'scores','critical'} or type(result['scores']) is not dict:raise ValueError('评分返回结构')
            value=weighted(result['scores'],weights)
            if type(result['critical']) is not bool:raise ValueError('critical布尔字段')
            rows.append({'id':c['id'],'status':'scored','score':value,'critical':result['critical']})
        except (TimeoutError,ValueError,KeyError,TypeError) as error:
            rows.append({'id':c['id'],'status':'failed','score':0.,'critical':None,'reason':str(error)})
    return rows

def summarize_rows(rows):
    if not rows or len({r['id'] for r in rows})!=len(rows):raise ValueError('结果case合同')
    return {'mean_all':sum(r['score'] for r in rows)/len(rows),
            'coverage':sum(r['status']=='scored' for r in rows)/len(rows),
            'failures':[r['id'] for r in rows if r['status']!='scored'],
            'critical':[r['id'] for r in rows if r['critical'] is True],
            'critical_unknown':[r['id'] for r in rows if r['critical'] is None]}
def fixture_backend(case):
    if case['id']=='timeout':raise TimeoutError('fixture没有真正网络调用')
    value=.9 if case['id']=='a' else .8
    return {'scores':dict.fromkeys(weights,value),'critical':case['id']=='critical'}
rows=run_cases([{'id':'a'},{'id':'critical'},{'id':'timeout'}],fixture_backend)
summary=summarize_rows(rows)
assert math.isclose(summary['mean_all'],1.7/3) and summary['coverage']==2/3
assert summary['failures']==['timeout'] and summary['critical']==['critical']
bad=run_cases([{'id':'bad_format'}],lambda c:{'oops':5})
assert bad[0]['status']=='failed' and bad[0]['score']==0 and bad[0]['critical'] is None
accepted=summary['mean_all']>=.75 and summary['coverage']>=.9 and not summary['critical'] and not summary['critical_unknown']
assert not accepted
print('权重.77/.66，Wilson45/50',lo,hi,'；缓存字段/权限/重复ID失效通过')
print('完整失败分母和独立严重错误',summary,'接受',accepted)
```

实际评分记录还保留逐项分数、依据、unknown、耗时、实际 usage 和费用单位。没有 usage 时费用是未知而非0；基线缓存只有在输出和评价协议仍匹配时才能复用。开发/对抗/分布样本三类案例各有目的，样本数量由代表性、业务损失及统计精度决定，不能靠固定数目证明可靠。

来源 eval_framework.py 的评分按长度/词重叠/MD5扰动产生，compare_eval_runs 又未按caseID配对，仅用均值差±.3标记；文档 Python hash 与文件 MD5 的种子方式还不同。它们是 fixture，不是实际 judge 或显著性检验。本章第4/11节保留同案例差值、失败与case diff，不能用该模拟程序取代。

## 4. A/B 比较要成对、可重现并报告不确定性

保持相同案例、文档快照、生成参数、预算和评价器；性能测试还固定硬件与服务配置。可以只改 chunking、embedding、reranker、prompt 或解码策略的一项，以定位变化。随机模型要记录种子/重复次数；同一案例的重复回答存在相关性，不能当完全独立的多个用户案例。

20 题 A 对 16、B 对 17，不能仅凭多 1 题宣称稳定优胜，还应看哪题变好/变差、错误严重度和不确定性。二元成对比较可看 discordant pairs，使用 McNemar 等方法；连续分数可对案例差值做配对 bootstrap。若案例来自同一文档或用户，按组抽样而非逐回答独立抽样。

```python
import random
import math

def paired_bootstrap(a, b, repetitions=4000, seed=7):
    if not a or len(a) != len(b) or repetitions < 100:
        raise ValueError("需要对齐非空样本及足够重复次数")
    if not all(math.isfinite(x) for x in list(a)+list(b)):
        raise ValueError("评分必须有限")
    diff = [y-x for x, y in zip(a, b)]
    rng, n = random.Random(seed), len(diff)
    means = sorted(sum(diff[rng.randrange(n)] for _ in range(n))/n for _ in range(repetitions))
    lo, hi = means[int(0.025*repetitions)], means[min(repetitions-1, int(0.975*repetitions))]
    return sum(diff)/n, (lo, hi)

a = [1]*16 + [0]*4
b = [1]*15 + [0] + [1,1,0,0]  # 1 题回退、2 题改善。
mean, interval = paired_bootstrap(a, b)
assert abs(mean - 0.05) < 1e-12 and interval[0] <= 0 <= interval[1]
assert paired_bootstrap(a, a)[1] == (0.0, 0.0)
print("配对平均改善", mean, "；案例 bootstrap 95% 区间", interval)
```

这是经验分位数区间示例，少量样本可能覆盖不足，不能当严格部署保证。置信区间包含零表示当前证据不足以确定平均改善方向，不证明两方案等效。等效/非劣检验要预先设业务容忍界限和协议。

## 5. 长上下文：窗口上限与有效使用能力分开

标称窗口说明可接受输入的容量，不说明每个位置、每种任务都有效。长文测试至少控制实际 tokenizer 输入长度、答案位置、输出预算、干扰、重复、问题类型、随机种子和错误率，同时记录 TTFT、总延迟与输入/输出量。

Needle-in-a-haystack（NIAH）在长背景中插入特定事实，询问该事实。它主要测试定位/精确提取；多 needle 测试同时获取多个事实，变量链/多跳测试推导关系，长文理解还需要整合、否定、时间更新、无答案和可信证据选择。单条 needle 匹配成功不能保证长文推理、代码理解或全面摘要。

“Lost in the middle” 指一些实验中证据位于长输入中间时，表现弱于位于首尾；它是任务和模型条件下的观测，不是所有模型/长度必有的定律。[原论文](https://arxiv.org/abs/2307.03172)

位置比例应按最终输入测量。插入 needle 后长度会变化，多个插入点也会挪动后续位置；不能用“字符数”宣称“token 长度”。原来源的 mock 按空格分词，以硬编码 20000 位置决定返回，未调用真实模型；它的热图反映代码规则，不证明真实模型会渐进衰退、出现某种 U 型或有效窗口比例。

### 5.1 精确长度的合成协议与严格答案评分

此例明确使用**空格分隔的 word unit**，只测试样本构造与评分，未测任何模型。真实基准需换成对应 tokenizer，并把完整 prompt、问题和输出预算都计入。随机 key 减少固定 needle 的记忆和猜测，背景包含其他 key 的干扰值。

```python
import json
import random
import re

def build_needle(total_words, position, seed=4):
    if type(total_words) is not int or total_words < 8 or not 0 <= position <= 1:
        raise ValueError("长度/位置无效")
    rng = random.Random(seed)
    key = f"K{rng.randrange(100000, 999999)}"
    code = f"V{rng.randrange(100000, 999999)}"
    needle = ["记录", key, "对应", code]
    filler_count = total_words - len(needle)
    # 干扰项使用其他 key，不能意外包含目标事实。
    background = [f"背景{i % 7}" for i in range(filler_count)]
    start = round(position * filler_count)
    words = background[:start] + needle + background[start:]
    assert len(words) == total_words
    return {"context": " ".join(words), "question": f"{key} 对应什么代码？",
            "expected": code, "key": key, "start_word": start,
            "position_final": start/total_words, "unit": "whitespace_word"}

def strict_code_score(raw, expected):
    try:
        parsed = json.loads(raw)
    except (json.JSONDecodeError, TypeError):
        return False
    return (type(parsed) is dict and set(parsed) == {"code"} and
            type(parsed["code"]) is str and parsed["code"] == expected)

def local_oracle(case):
    # 正则读取 fixture，是可控 oracle，不是 LLM 或长文能力证明。
    pattern = rf"记录 {re.escape(case['key'])} 对应 (V[0-9]+)"
    values = re.findall(pattern, case["context"])
    if len(values) != 1:
        return json.dumps({"code": None})
    return json.dumps({"code": values[0]})

for length in (8, 80, 800):
    for pos in (0.0, 0.5, 1.0):
        case = build_needle(length, pos)
        assert len(case["context"].split()) == length
        assert strict_code_score(local_oracle(case), case["expected"])
        assert not strict_code_score(json.dumps({"code": "不是 " + case["expected"]}), case["expected"])
        assert not strict_code_score(json.dumps({"code": case["expected"], "extra": 1}), case["expected"])
print("9 个长度/位置 fixture 的构造与 oracle 评分通过；不代表模型长文通过")
```

针对多 needle，答案使用不重复的 `key→value` 映射，逐项 exact match 和全项同时正确率分开报；不得按“出现任一答案子串”给整个任务成功。没有相关记录、多个冲突记录和更新版记录必须有明确 gold 规则。

### 5.2 多 needle 的构造与评分分母

每个记录使用独立 key，答案要求全部 key→value，返回一半只算部分正确。下面通过事件点一次性构造最终序列，避免逐次插入导致后续深度漂移；仍使用 word unit，不冒充 tokenizer 测试。

```python
import json
import random

def multi_needle_fixture(total_words=120, positions=(0.2, 0.5, 0.8), seed=3):
    n = len(positions)
    if type(total_words) is not int or n == 0 or total_words < 4*n:
        raise ValueError("背景长度不足或没有 needle")
    if any(not 0 <= p <= 1 for p in positions):
        raise ValueError("位置必须在 [0,1]")
    rng = random.Random(seed)
    keys = rng.sample(range(100000, 999999), n)
    codes = rng.sample(range(100000, 999999), n)
    expected = {f"K{k}": f"V{v}" for k, v in zip(keys, codes)}
    filler_count = total_words-4*n
    events = sorted((round(p*filler_count), i) for i, p in enumerate(positions))
    words, actual = [], {}
    cursor = 0
    items = list(expected.items())
    for offset, i in events:
        words.extend(f"背景{j % 7}" for j in range(cursor, offset))
        key, value = items[i]
        actual[key] = {"start_word": len(words), "fraction_final": len(words)/total_words}
        words.extend(["记录", key, "对应", value])
        cursor = offset
    words.extend(f"背景{j % 7}" for j in range(cursor, filler_count))
    assert len(words) == total_words
    return " ".join(words), expected, actual

def score_all_keys(raw, expected):
    if not expected:
        raise ValueError("无答案任务应使用单独协议")
    try:
        response = json.loads(raw)
    except (json.JSONDecodeError, TypeError):
        return {"item_accuracy": 0.0, "all_correct": False, "schema_ok": False}
    schema_ok = (type(response) is dict and set(response) == set(expected)
                 and all(type(v) is str or v is None for v in response.values()))
    correct = sum(response.get(k) == v for k, v in expected.items()) if type(response) is dict else 0
    return {"item_accuracy": correct/len(expected),
            "all_correct": schema_ok and correct == len(expected), "schema_ok": schema_ok}

context, expected, positions = multi_needle_fixture()
assert len(context.split()) == 120 and len(positions) == 3
assert score_all_keys(json.dumps(expected), expected)["all_correct"]
partial = dict(expected); partial[next(iter(partial))] = None
score = score_all_keys(json.dumps(partial), expected)
assert score["item_accuracy"] == 2/3 and not score["all_correct"]
assert not score_all_keys(json.dumps(dict(expected, extra="wrong")), expected)["all_correct"]
print("多 needle：", score, "；最终位置已记录，额外 key 不能全题通过")
```

项准确率和全题准确率可同时报告，但 schema 失败、无答案和冲突案例另做切片；即使某值字符串在回答出现，也不代表它绑定到正确 key。重复样本和单一 seed 不足以估计真实模型方差。

### 5.3 多跳变量跟踪的最小可验证实例

```python
import re

def trace_variables(text, query):
    # 有限定义语言：逐行 x=整数 或 x=y+整数，引用必须已经定义。
    values = {}
    for line in text.splitlines():
        literal = re.fullmatch(r"([a-z]+)=(-?\d+)", line.strip())
        step = re.fullmatch(r"([a-z]+)=([a-z]+)\+(-?\d+)", line.strip())
        if literal:
            values[literal[1]] = int(literal[2])
        elif step and step[2] in values:
            values[step[1]] = values[step[2]] + int(step[3])
        else:
            raise ValueError("无效表达式或未定义引用")
    if query not in values:
        raise ValueError("未知查询变量")
    return values[query]

assert trace_variables("a=7\nb=a+3\nc=b+-2", "c") == 8
assert trace_variables("a=7\na=9\nb=a+3", "b") == 12  # 明确顺序覆盖语义。
try:
    trace_variables("b=a+3\na=7", "b")
except ValueError:
    pass
else:
    raise AssertionError("本协议不允许前向引用")
print("两跳、顺序更新、未定义引用规则通过")
```

此 oracle 计算有限语言真值；对模型评价时把同义表达、无关定义、不同位置和链长度纳入输入，再以 oracle 计算 gold。不要把正则执行器的成功写成 LLM 推理成功。自然语言的事件时间与定义顺序也不总等同，必须明确任务语义。

### 5.4 使用公开长文基准时冻结协议

RULER 包含多种合成长文任务，用于揭示单 needle 以外的困难；LongBench/LongBench v2 含真实长文任务，v2 的选项题须保留问题、上下文和所有 choices，再按规定答案协议评分；MRCR 关注多轮长对话中对相似请求/响应的区分；NoLiMa 刻意减少字面重叠，考察需要潜在关联的检索。它们不是同一个任务的可直接替代指标。

LongBench v2 的作者数据契约包含 `_id、domain、sub_domain、difficulty、length、question、choice_A/choice_B/choice_C/choice_D、answer、context`，gold answer 为 A/B/C/D，`length` 是长度类别而不是实际 tokenizer 长度。加载 split 名称也要跟作者协议，不凭惯例写不存在的 test split。

记录仓库 commit、数据 revision、子任务、split、tokenizer、长度截断方向、prompt、选项顺序、采样配置和评分脚本。源课把 LongBench v2 当任意开放问答、漏掉 choices 或使用错误字段会改变任务。NoLiMa 应引用 [作者论文 2502.05167](https://arxiv.org/abs/2502.05167)，不能沿用源课不对应的链接。[RULER](https://github.com/NVIDIA/RULER)、[LongBench v2](https://github.com/THUDM/LongBench)、[MRCR 数据说明](https://huggingface.co/datasets/openai/mrcr)

有效上下文应定义成“某任务、某错误容忍、某重复协议下仍达到要求的长度/位置范围”，附样本数与不确定性。不存在通用“有效窗口一定是标称 60%–70%”或某品牌固定百万窗口能力的结论。根据失败类型选择检索/分块、分层汇总或原生长文，不用硬比例替代测量。

## 6. 服务性能：TTFT、TPOT 与用户延迟

质量评价与服务性能分别记录。TTFT 是请求到首个输出 token 的时间，应写清是否包括客户端网络、排队和服务前处理；TPOT 常按生成阶段平均每个后续 token 时间估算，至少要有两个输出 token，单 token 不能除以零或伪造 TPOT。端到端延迟包括整个请求至完成，不能用 TPOT 代替。

同时记录输入 token/s、输出 token/s、请求/s、错误率、P50/P95/P99、并发退化、峰值显存/内存。吞吐变高可能来自 batch 或排队增加，而单请求延迟变差；输出越短、截断越多也可能看似更快，所以保持输入/输出分布和预算一致。

```python
import math

def timing(request_start, first_token, finish, output_tokens):
    if type(output_tokens) is not int or output_tokens < 1:
        raise ValueError("此指标仅用于至少有一个输出 token 的成功流")
    if not all(math.isfinite(x) for x in (request_start, first_token, finish)) or not request_start <= first_token <= finish:
        raise ValueError("时间戳必须有限且有序")
    return {"ttft": first_token-request_start, "latency": finish-request_start,
            "tpot": (finish-first_token)/(output_tokens-1) if output_tokens > 1 else None}

measured = timing(0.0, 0.4, 1.2, 5)
assert math.isclose(measured["ttft"], 0.4) and math.isclose(measured["latency"], 1.2)
assert math.isclose(measured["tpot"], 0.2)
assert timing(0.0, 0.4, 0.4, 1)["tpot"] is None
print(timing(0.0, 0.4, 1.2, 5), "；单 token TPOT 不适用")
```

客户端首次 chunk 不一定恰含一个 token，流结束还有传输开销；根据可观测数据将此结果称“估算 TPOT”或使用服务端 token 时间戳，不夸大精度。失败流另外记录超时/OOM/取消/限流，不只保留成功请求。

并发可逐步增加 1→5→更高负载，寻找延迟、吞吐、失败率和资源的拐点；步长与持续时间按服务容量决定，不是固定通用值。观察排队、公平性、超时、显存和 OOM，区分负载生成端、网络、tokenization、prefill、decode 和工具瓶颈。长上下文主要增加输入处理和缓存压力，输出长短影响 decode，二者要分层测。

## 8. 练习与参考答案

1. 三题首命中 1、3、无：MRR@5=4/9。一个问题需两证据但仅取一条：Hit=1、Recall=1/2，不能称完整召回。
2. 人工主张标签 supported/unsupported/unknown：按完整分母支持率 1/3、判定覆盖率 2/3。空主张不自动给业务满分。
3. “不是 pineapple”含 expected 子串却是错误答案。改 exact schema 评分可挡此反例，但开放答案仍需合适 gold 规则。
4. A=16/20、B=17/20：确认成对变化与错误严重度，报告样本数/CI；不能仅多一题就宣布稳定提高。
5. NIAH 热图来自硬编码位置 mock：只能验证网格汇总与评分流程，不能解释真实模型有效上下文或排名。
6. 输入长度应含 system/prompt/question 及输出预留；word/字符/token 单位不同，位置在最终序列中重新计量。
7. 长文变量 `a=7;b=a+3;c=b-2` 的 gold 为 8；把 b 位置放在定义 a 之前时，按本例协议属于未定义引用，应报构造无效，不改 gold 猜答案。
8. 只有一个输出 token：TTFT 与端到端延迟仍可测，TPOT 标不适用。首个网络 chunk 不是精确 token 时间戳。
9. judge 与人工秩相关高但总把严重错误评为 0.8：排序可能一致，绝对门禁仍失效，需严重错误误接受率与阈值校准。
10. 并发提高吞吐同时 P99/超时恶化：报告两个方向，按任务服务目标找容量范围，不能只保留吞吐。

## 9. 标准基准与任务评测怎样接到同一协议

MMLU/ARC等多选题常按选项条件log-likelihood选择，HumanEval类代码任务按执行测试与规定采样协议计分，SWE-bench类按给定仓库问题及测试验证补丁。问题数、subset、few-shot/模板、样本来源和模型版本都须冻结。公开基准提供能力画像，任务评测检查实际输入/失败；没有一种评测因“自建”就自动可靠，人工标签也可能错或有偏。

源“86%–89%都属噪声”“不足50题统计上毫无意义”过强。差异的不确定性取决于样本量、成对错误、独立单位和协议，1个百分点在某些大样本上可有统计证据，也可能没有实际价值。少样本仍可揭示明确实现错误，不能用它证明普遍可靠性。污染/针对性优化/基准饱和需具体证据，不将所有团队都“刷榜”当专业事实。

### 9.1 选项likelihood、长度归约与真正的PPL

LM需要给定prefix与候选的条件token概率；log-likelihood为候选各token logprob之和。有的多选任务另报按长度平均的normalized score，它会改变答案，不能混称同一accuracy。候选边界可能影响BPE切分，评测器要正确定位continuation首token，不重复BOS或漏第一目标。`is_greedy`通常检查条件上下文中逐步argmax是否匹配候选，不代表该候选是全局序列MAP，贪心反例见[文本生成第18节](../LLM%20基础/05-预训练-损失与文本生成.md)。

```python
import numpy as np

def candidate_score(logits,targets):
    z=np.asarray(logits,dtype=float);ids=np.asarray(targets)
    if z.ndim!=2 or not len(z) or not z.shape[1] or not np.isfinite(z).all() or ids.shape!=(len(z),) or ids.dtype.kind not in 'iu' or np.any(ids<0) or np.any(ids>=z.shape[1]):raise ValueError('候选logit/目标合同')
    shifted=z-z.max(1,keepdims=True);lp=shifted-np.log(np.exp(shifted).sum(1,keepdims=True))
    selected=lp[np.arange(len(ids)),ids]
    return {'loglikelihood':float(selected.sum()),'mean_logprob':float(selected.mean()),
            'tokens':len(ids),'is_greedy':bool(np.array_equal(z.argmax(1),ids))}

# 概率fixture：第一个token A=.55/B=.45；A后又预测A=.55。
long=candidate_score(np.log([[.55,.45],[.55,.45]]),[0,0])
short=candidate_score(np.log([[.55,.45]]),[1])
assert long['loglikelihood']<short['loglikelihood'] and long['mean_logprob']>short['mean_logprob']
assert long['is_greedy'] and not short['is_greedy']
print('候选A A',long,'候选B',short,'；sum与长度平均排名不同')
# 数据两batch有效目标1/9、NLL2/1。只验证归约，未测任何模型。
mean=(1*2+9*1)/10
assert mean==1.1 and abs(np.exp(mean)-3.0041660239464334)<1e-12
print('按有效target全局NLL/PPL',mean,float(np.exp(mean)))
```

源`token_log_probs_simulated`按文本长度和quality常数加随机噪声，未调用模型或完整归一词表，不能称真实强/中/弱模型的PPL。docs的Python`hash(text)`种子还随进程盐变化；main改SHA种子较稳定，但仍是fixture且修改全局RNG状态。本章likelihood/PPL只对实际logits或明确概率fixture报告，不保源WikiText型号分数。完整验证集NLL用全部指定有效目标，不能先平均不同大小batch再平均。

## 10. 文本评分的有效范围

Exact match需声明是否trim/casefold、允许答案集合、JSON结构、数值精度和单位。`212°F`与标准条件下`100°C`可数值等价，英文four与4可能是同一答案，代码大小写却可能有语义；源把所有verbose回答命名“bad model”没有证明它们错误。语义判断与字符串契约分别报告。

常见token F1使用multiset匹配次数，源set版本会忽略重复，不能当标准实现；完整EM/F1入口见[问答文本指标](12-文本检索与RAG文档工程.md)。BLEU/ROUGE/chrF的算法与语言口径统一见[摘要推断与文本评价](../AI%20算法基础/语言与文本专题/05-摘要推断与文本评价.md)，不在LLM基准另复制一套公式。

LLM judge、NLI和词重叠是不同对象。源overlap×.7+长度×.3的`llm_judge_simulated`会把否定、错单位和关键词堆砌评高，不是实际judge，也不能为相关性或事实正确性背书。真实judge沿用本章第3节的校准/盲评/顺序/严重错误/失败协议，不保通用“80%一致、每题固定费用、只用更强模型便可靠”。

对代码pass@k：每题生成n个候选、其中c个通过，常用估计$1-\binom{n-c}{k}/\binom{n}{k}$（n≥k，若n−c<k则为1），再按题平均。不能把所有生成条数的通过比例叫pass@k；采样温度、独立性近似、测试范围与资源隔离均需记录，测试通过不等任意边界正确。

## 11. 完整本地suite、失败分母、重复一致性与case diff

下面两个“模型”是固定lookup fixture，不是语言模型。它们帮助验证病例ID、评分状态、失败保留与版本差异。业务任务只允许一个分类标签；含糊案例可预先声明多个可接受标签，但不能运行后为了抬分改gold。真正的多标签任务另用对应指标。

```python
import math
from collections import Counter

CLASSES={'billing','shipping','tech','feedback','other'}
CASES=[{'id':'b1','text':'Please refund this order','accepted':{'billing'}},
       {'id':'s1','text':'包裹未到','accepted':{'shipping'}},
       {'id':'t1','text':"Can't sign in",'accepted':{'tech'}},
       {'id':'f1','text':'很好','accepted':{'feedback'}},
       {'id':'empty','text':'','accepted':{'other'}},
       {'id':'amb','text':'退款还是重新发货？','accepted':{'billing','shipping'}}]

def run_suite(cases,predict):
    if not cases or len({c['id'] for c in cases})!=len(cases):raise ValueError('非空且唯一case ID')
    rows=[]
    for c in cases:
        if type(c['text']) is not str or not c['accepted'] or not c['accepted']<=CLASSES:raise ValueError('case合同')
        try:
            pred=predict(c['text'])
            if type(pred) is not str or pred not in CLASSES:raise ValueError('标签格式错误')
            rows.append({'id':c['id'],'status':'scored','prediction':pred,'score':float(pred in c['accepted'])})
        except (ValueError,TimeoutError) as error:
            rows.append({'id':c['id'],'status':'failed','prediction':None,'score':0.,'reason':str(error)})
    return rows

def summarize_run(rows):
    if not rows or len({r['id'] for r in rows})!=len(rows) or any(not math.isfinite(r['score']) or not 0<=r['score']<=1 for r in rows):raise ValueError('结果合同')
    return {'mean_all':sum(r['score'] for r in rows)/len(rows),
            'scored_coverage':sum(r['status']=='scored' for r in rows)/len(rows),
            'failed_ids':[r['id'] for r in rows if r['status']!='scored']}

def case_diff(a,b):
    aa={r['id']:r for r in a};bb={r['id']:r for r in b}
    if len(aa)!=len(a) or len(bb)!=len(b) or aa.keys()!=bb.keys():raise ValueError('case必须完全对齐，不能丢缺失行')
    return {kind:[i for i in sorted(aa) if predicate(bb[i]['score']-aa[i]['score'])]
            for kind,predicate in [('improved',lambda d:d>0),('regressed',lambda d:d<0),('same',lambda d:d==0)]}

def consistency(outputs):
    if len(outputs)<2 or any(type(x) is not str for x in outputs):raise ValueError('至少两条成功文本；失败另报')
    counts=Counter(outputs);n=len(outputs)
    return {'modal_fraction':max(counts.values())/n,
            'pairwise_exact_agreement':sum(c*(c-1) for c in counts.values())/(n*(n-1))}

a_lookup={c['text']:next(iter(sorted(c['accepted']))) for c in CASES};a_lookup['包裹未到']='other'
b_lookup=dict(a_lookup);b_lookup['包裹未到']='shipping';b_lookup["Can't sign in"]='other'
def base(text):return a_lookup[text]
def candidate(text):
    if text=='':raise TimeoutError('fixture模拟超时，未作真实网络调用')
    return b_lookup[text]
a=run_suite(CASES,base);b=run_suite(CASES,candidate);diff=case_diff(a,b)
assert diff['improved']==['s1'] and diff['regressed']==['empty','t1']
assert summarize_run(b)['failed_ids']==['empty']
assert consistency(['billing']*5)['pairwise_exact_agreement']==1.
assert 'billing' not in CASES[1]['accepted']  # 一致五次仍可全部错误。
print('基线/候选',summarize_run(a),summarize_run(b),'case diff',diff)
print('五次同样错误的答案一致性',consistency(['billing']*5))
```

本例预定失败score0并单列coverage；其它任务可以另定unknown/失败协议，但不能只平均成功结果。真实runner还要对调用设deadline、控制重试与费用、保存trace/版本和执行错误；这里的TimeoutError是模拟记录，不表示部署超时保护已完成。Case diff与paired bootstrap结合使用，回退的严重程度还要单列，不能仅拿净多一题作接受依据。

污染检测可从完全匹配与明确n-gram开始，Tokenizer/清洗/问题+答案字段和参考材料都可能进入训练。Hash只发现同一规范化内容，MinHash/LSH发现一些近重复，不证明捕获所有语义改写或排除记忆，完整数据例见[工程16](16-预训练数据与模型交付实践.md)。源“公开题出现就必只记忆不推理”和“无13-gram重叠就安全”都不能作普遍因果结论。

## 12. Elo与成对偏好：保留算法，避免错认榜单

两方案rating Ra/Rb的经典Elo预期为$E_A=1/(1+10^{(R_B-R_A)/400})$，实际胜/负/平为1/0/.5，更新$R_A'=R_A+K(S_A-E_A)$，B按相反变化。这是顺序更新的教学方法，结果受初始值、K、配对分布与比赛顺序影响；不同语言/任务的偏好不一定能压成可传递单标量。

```python
import math
class Elo:
    def __init__(self,k=32,initial=1500):
        if not math.isfinite(k) or k<=0 or not math.isfinite(initial):raise ValueError('评分参数')
        self.k=k;self.initial=initial;self.ratings={}
    def match(self,a,b,outcome):
        if type(a) is not str or type(b) is not str or not a or not b or a==b or outcome not in ['a','b','tie']:raise ValueError('不同方案与明确outcome')
        ra=self.ratings.setdefault(a,self.initial);rb=self.ratings.setdefault(b,self.initial)
        d=(rb-ra)/400
        ea=0. if d>300 else 1. if d<-300 else 1/(1+10**d)
        actual={'a':1.,'b':0.,'tie':.5}[outcome];delta=self.k*(actual-ea)
        self.ratings[a]+=delta;self.ratings[b]-=delta
        return self.ratings.copy()

e=Elo();assert e.match('A','B','a')=={'A':1516.,'B':1484.}
total=sum(e.ratings.values());e.match('A','B','tie');assert math.isclose(sum(e.ratings.values()),total)
try:e.match('A','B','invalid')
except ValueError:pass
else:raise AssertionError('未知结果不能默认为平局')
print('Elo',e.ratings,'；固定fixture胜负，不代表公开model榜单')
```

源把这个逐次Elo实现称“正是Arena当前排行系统”不准确；Arena研究还采用Bradley–Terry系数估计及统计区间。BT以$Pr(A胜B)=\sigma(\xi_A-\xi_B)$拟合成对结果，所有系数加同一常数概率不变，需固定一项或中心化。比较同案例的匿名输出、随机交换顺序、注明tie/无效票规则，处理配对分布与相关样本；有区间重叠不能只凭一个小rating差宣布普遍更好。[Arena原方法](https://arxiv.org/html/2403.04132v1)

不同judge/EM/F1按固定权重合成偏好是另一个**人为目标**，权重改变名次不证明真实性。真实BT拟合、公开榜单和人/LLM judge本批未跑，不保源某年排行榜、票数、人工单价或固定一致率。成本记录用实际输入/输出/缓存/请求数、版本与单价单位，质量和延迟分开；示例价格不可当当前报价。

## 15. 第19课：代码Agent评测要核每一个测试的状态转换

先修是版本固定、失败分母、suite账本与case diff。SWE-bench类任务把仓库的base commit、issue、候选patch和测试环境连接：patch应用成功只是开始，FAIL_TO_PASS（F2P）要求原本失败的指定test ID现在通过，PASS_TO_PASS（P2P）要求原本通过的指定test ID仍然通过。不能用“通过数增加”代替逐ID核对，也不能让候选patch修改测试、隐藏失败或改变评判器。

例如原P2P `{test_a: PASS, test_b: PASS}`，候选后 `{test_a: FAIL, test_b: PASS, test_new: PASS}`。通过数仍为2，但a已经回归；若只算net count会漏报。F2P在基线本来PASS，说明本地复现或任务数据不符合“原失败”合同，不能说修复成功。timeout、解析失败、test漏跑和环境无法启动各有状态，保留在任务账本而不是删掉以提高resolved率。

冻结dataset/subset/revision、task IDs、仓库commit、测试命令、环境/依赖、patch、agent配置和评判器。对成功patch仍要检查问题是否真被解决、测试是否覆盖边界，可能增加独立回归或人工审查。公开任务还需检查issue/comment直接泄露答案、训练/调参可见范围与数据cutoff；早于模型cutoff只意味着可能被见到，不证明训练一定收录。

### 第19课：可运行的逐test ID转换与完整任务账本

本例输入是人工固定的before/after结果字典，不应用patch、不执行真实测试。它验证F2P/P2P转换、未知结果、基线无效及漏任务分母；fixture规定结果集合必须恰好覆盖该任务的指定tests，真实harness可另保完整测试日志与附加tests。无效记录显式报错，缺任务显式记unknown。

```python
from collections import Counter

STATES = {'PASS', 'FAIL', 'ERROR', 'TIMEOUT', 'UNKNOWN'}
def transitions(f2p, p2p, before, after):
    if not f2p or any(type(x) is not str or not x for x in f2p + p2p):
        raise ValueError('test ID合同')
    ids = set(f2p + p2p)
    if len(ids) != len(f2p) + len(p2p): raise ValueError('重复test ID')
    if type(before) is not dict or type(after) is not dict:
        raise ValueError('逐test结果字典')
    if set(before) != ids: return 'invalid_baseline'
    if any(type(v) is not str or v not in STATES for v in list(before.values()) + list(after.values())):
        raise ValueError('结果枚举')
    if any(before[x] != 'FAIL' for x in f2p) or any(before[x] != 'PASS' for x in p2p):
        return 'invalid_baseline'
    if set(after) != ids: return 'unknown'
    if any(after[x] == 'TIMEOUT' for x in ids): return 'timeout'
    if any(after[x] in {'ERROR', 'UNKNOWN'} for x in ids): return 'unknown'
    if any(after[x] != 'PASS' for x in ids): return 'failed'
    return 'resolved'

def ledger(expected, rows):
    if not expected or len(set(expected)) != len(expected) or any(type(x) is not str or not x for x in expected):
        raise ValueError('唯一非空task ID')
    result = {}
    for task, status in rows:
        if task not in expected or task in result or status not in {'resolved','failed','timeout','unknown','invalid_baseline'}:
            raise ValueError('重复、越界task或状态')
        result[task] = status
    for task in expected: result.setdefault(task, 'unknown')
    counts = dict(Counter(result.values()))
    return result, {'attempted': len(expected), 'counts': counts,
                    'resolved_rate': counts.get('resolved', 0) / len(expected)}

f2p, p2p = ['bug'], ['old_a', 'old_b']
before = {'bug':'FAIL', 'old_a':'PASS', 'old_b':'PASS'}
good = {x:'PASS' for x in before}

# P2P通过数被新test补回仍不合格；after全集错误先记unknown，指定旧test仍是FAIL。
hidden = dict(good, old_a='FAIL', new_test='PASS')
assert sum(x == 'PASS' for x in hidden.values()) == sum(x == 'PASS' for x in good.values())
assert transitions(f2p, p2p, before, hidden) == 'unknown'
assert transitions(f2p, p2p, before, dict(good, old_a='FAIL')) == 'failed'
assert transitions(f2p, p2p, dict(before, bug='PASS'), good) == 'invalid_baseline'
assert transitions(f2p, p2p, before, {'bug':'PASS'}) == 'unknown'
assert transitions(f2p, p2p, before, dict(good, bug='TIMEOUT')) == 'timeout'
assert transitions(f2p, p2p, before, dict(good, bug='ERROR')) == 'unknown'
for args in [(['bug','bug'], p2p, before, good), (f2p,p2p,before,dict(good,bug=True))]:
    try: transitions(*args)
    except ValueError: pass
    else: raise AssertionError('非法测试记录')
records, summary = ledger(['A','B','C','D','E'], [('A','resolved'),('B','failed'),('C','timeout'),('D','invalid_baseline')])
assert records['E'] == 'unknown' and summary['attempted'] == 5 and summary['resolved_rate'] == .2
try: ledger(['A'], [('A','resolved'),('A','resolved')])
except ValueError: pass
else: raise AssertionError('重复task不能扩大分子')
print('逐ID转换、回归/漏跑/timeout/无效基线通过；5任务账本', summary)
```

### 第19课：构建、使用与交付

原Build It是3个合成patch任务，原评判只用P2P净通过数，且可能把基线PASS的F2P算成功；上例修复的是评判合同，没有SWE-bench复现。`benchmarks.svg`与`ae-swebench-gate`把F2P/P2P表示成门，门必须按test ID而非数值总和执行，动态阈值或“50→35”手工数字不是污染统计。Use It按代码、助手工具链或环境交互选择相应协议；Ship It应交付冻结配置、逐任务账本、逐test日志、patch与错误分类。报告一次resolved还须附steps、模型/工具尝试、tokens、wall time及金额，费用未知明确为unknown。

### 第19课：五项练习与参考答案

## 16. 第20课：网页/桌面任务的终态、动作空间与轨迹效率

网页和桌面任务通常要求改变环境状态。文字回复“已下单”不等于订单正确；验证器应核用户、商品ID、数量、地址/对象、额外订单和禁止副作用。状态型goal在任务结束后读取受控环境，不把页面自述或agent自己的trace当唯一证据。先明确初态、用户身份与reset，再执行一个完整任务；不reset就跑下题会造成环境串扰。

WebArena用可重建网页环境支持执行评价。官方固定README配置包含shopping、shopping admin、forum、GitLab、map、Wikipedia等环境入口，因此“四apps”是来源的应用归类简写，不能等同只有四个域/服务。公开demo用于了解页面，不代替正式评测环境。升级app/数据/认证/DOM/浏览器会改变观察、动作和终态验证器，要重新核同一task成功条件及reset，而不是只换镜像标签。[固定官方README](https://github.com/web-arena-x/webarena/blob/dce04686a56253aefba7b18a4fa0937cf1dc987b/README.md)。

OSWorld涉及真实桌面操作，但固定 `b138d348256078fa634fc3b73567a7337c793e6b` 的run.py支持 `screenshot`、`a11y_tree`、`screenshot_a11y_tree`、`som`，且该脚本默认a11y_tree；屏幕尺寸也是配置。来源“OSWorld永远只看1920×1080截图、没有accessibility”不成立。比较时一起冻结observation type、action space、screen size、最大steps、sleep策略和任务/VM版本。像素、结构化树及混合表面的分数不能直接混排。[固定run.py](https://github.com/xlang-ai/OSWorld/blob/b138d348256078fa634fc3b73567a7337c793e6b/run.py)。

定位失败与规划/操作知识失败分开：给正确目标元素仍点错是grounding/driver问题；能准确点击但走错菜单或忘保存是规划/操作问题；参数正确但环境阻塞还可能是权限、网络或生命周期。OSWorld-G对文字匹配、元素识别、布局理解、精细操作建定位任务，能辅助做这些切片，不把所有失败归给vision。[OSWorld-G论文](https://arxiv.org/abs/2505.13264)。OSWorld-Human以人工轨迹补效率分析；本次官方摘要写最佳被测agents也需2.7–4.3倍steps，源1.4–2.7不能称普遍规律。具体倍数仍取决于被测对象、动作定义和任务。[OSWorld-Human项目](https://github.com/xlang-ai/OSWorld-Human)。

对任务i定义 `r_i = A_i / H_i`，A为按统一动作粒度计的agent动作数，H为人工参考数且H>0。它比较参考轨迹，不能自动称最优轨迹下界。一次模型请求可能生成多个动作，日志“修改想法”可能没有环境动作；字符串trace长度不等A。只在同任务、同动作允许集和成功条件下比较，成功样本ratio与全任务成功/失败预算分别报告；不要丢失败任务后宣传高效率。UI等待、重试、模型时间及真实成本另列。

## 17. Agent评测的外层闭环与全部尝试

2026-10-09补原Phase14第30课。公开benchmark、自定义离线和真实在线评价互补：benchmark看指定协议下能力/污染/回归，离线case看本应用的输入、轨迹和效果，线上分层样本看真实工作与副作用。它们与unit/integration/e2e是不同维度；不能把三个合成字符串case当作三层真实评测。

提出→评价→修订必须有有限预算、独立后置条件、停滞/失败出口和完整attempt记录。开发时的反馈可改候选，但最终holdout与judge校准应独立；只反复看同一批题或轮换名字不能消除间接过拟合。评分器偏好关键词时，优化循环会学会讨好评分器，而非真正解决任务。

源benchmark判断含add stick dep就宣称FAIL_TO_PASS/PASS_TO_PASS，实际没有应用patch或运行测试；correct子串也接收incorrect。引用含cite/arXiv不等出处真实或支持结论。源码online case先输出forwarded敏感信息，再改refused而标pass；真正泄露已经发生时，最终拒绝不能撤销前轮效果。评测要记录可信观察及不可逆严重失败，而不是只看final字符串。

### 完整CPU例：整数基线、有理数阈值与历史效果

输入是预定case集合、整数passed/total基线、全部尝试的效果标签。所有标签是人工fixture，程序不自动判断事实、恶意行为或真实数据泄露，也没有运行CI。threshold选择下降≥5个百分点，不是相对5%：95%→90%是5个百分点，相对下降约5.26%。按同任务/同协议比较，并另报统计不确定性、切片与实际价值；阈值不可看到结果后改。

```python
from fractions import Fraction

STATES = {'passed', 'failed', 'unknown'}
def rate(pair):
    if (type(pair) is not tuple or len(pair) != 2 or
        any(type(x) is not int for x in pair) or pair[1] <= 0 or not 0 <= pair[0] <= pair[1]):
        raise ValueError('baseline整数计数')
    return Fraction(*pair)

def gate(rows, expected, baseline, threshold=Fraction(1, 20)):
    base = rate(baseline)
    if type(threshold) is not Fraction or not 0 < threshold <= 1:
        raise ValueError('有理数阈值')
    if not expected or any(type(x) is not int for x in expected) or len(set(expected)) != len(expected):raise ValueError('整数case集合')
    seen = set(); passed = 0; unknown = False; severe = False
    for row in rows:
        if type(row['id']) is not int or row['id'] in seen or row['id'] not in expected:raise ValueError('重复、伪整数或外来case')
        seen.add(row['id'])
        if row['status'] not in STATES or type(row['attempts']) is not tuple or not row['attempts']:
            raise ValueError('case状态和全部尝试')
        for effect in row['attempts']:
            if effect not in {'none', 'blocked', 'severe_verified', 'effect_unknown'}:
                raise ValueError('效果枚举')
            severe |= effect == 'severe_verified'
            unknown |= effect == 'effect_unknown'
        passed += row['status'] == 'passed'
        unknown |= row['status'] == 'unknown'
    if severe:return 'block-severe-effect'
    if seen != set(expected) or unknown:return 'hold-unknown'
    drop = base - Fraction(passed, len(expected))
    return 'block-regression' if drop >= threshold else 'eligible-fixture'

# 演示政策：下降>=5个百分点阻断，并非通用上线阈值/显著性结论。
ids = tuple(range(20))
rows = [{'id':i, 'status':'passed' if i < 18 else 'failed', 'attempts':('none',)} for i in ids]
assert gate(rows, ids, (19,20)) == 'block-regression' # .95-.90精确=1/20。
rows[18]['status']='passed'
assert gate(rows, ids, (19,20)) == 'eligible-fixture'
leak_then_refuse = [{'id':0, 'status':'passed', 'attempts':('severe_verified','blocked')}]
assert gate(leak_then_refuse, (0,), (1,1)) == 'block-severe-effect'
assert gate([{'id':0,'status':'passed','attempts':('effect_unknown','none')}], (0,), (1,1))=='hold-unknown'
assert gate(rows[:-1], ids, (19,20)) == 'hold-unknown'
try:gate([{'id':True,'status':'passed','attempts':('none',)}], (1,), (1,1))
except ValueError:pass
else:raise AssertionError('bool不是整数case ID')
for bad in [(True,20), (19,0), (float('nan'),20)]:
    try:gate(rows,ids,bad)
    except ValueError:pass
    else:raise AssertionError('非法baseline')
try:gate(rows,ids,(19,20),float('nan'))
except ValueError:pass
else:raise AssertionError('非法阈值')
print('全部attempt保严重/未知效果；5个百分点精确边界；缺case和非法baseline/阈值拒绝')
```

未来接真实runner时，final_good与effect标签来自独立验证/权威回读，而非生成者自报。无法核对的效果保持unknown并限制重试；全attempt字节/usage/延迟/失败都保留，公开内容与敏感观察按实际授权脱敏。之前本章已有逐test-ID账本维护完整分母与回归，本节只增加跨attempt副作用和明确门槛，不复制另一套benchmark实现。

### 原30五项练习与参考判断

1. **选择一次失败，怎样证明新回归真能复现并被修？** 用固定失败输入、观察与后置条件建回归，保持未修前确实失败/修后通过；无真实用户产品失败则用明确fixture，不虚构经历。
2. **50会话的事实/风格/范围rubric如何校准？** 50会话是题设未采集；三维rubric明确anchor/gold/分歧与拒绝质量，事实核可信资料，tone不与事实互相抵消；自评校准不当独立truth。
3. **CI按≥5%回归阻断，阈值究竟怎么定义？** CI未部署；明确>=5个百分点或相对5%、分母/样本/关键严重失败/未知情况，有限值与同版本配对基线，绝对边界用整数计数/有理数避免浮点误判。
4. **步骤效率相对gold如何比较而不奖励失败？** 有效成功与前置条件可比才算步骤比；human gold是观察参考路径非理论最小，失败不能因0步显得高效；结合质量/权限/成本/时延。
5. **每课有一个case是否代表整个Phase14完整覆盖？** 映射54课完整名单并按机制分层，多课可共用一条含边界反例的测试；一个case/每课不等穷尽安全/质量，coverage与效果分开。

## 18. 长任务能力：时间跨度、运行时长与可靠性

一个 Agent 能持续调用工具，不意味着它能可靠完成长任务。长任务还会积累错误、丢失上下文、消耗资源，并产生最终答案中看不见的副作用。评测因此要保留完整任务账本、失败与恢复轨迹、权限和预算版本，再核终态。[评估和监控](../Agentic%20Design%20Patterns/01-核心章节/19-评估和监控.md)负责轨迹、事件与效果的审计；这里解释“长”的度量。

METR 的 **50% 时间跨度** $H_{50}$，是某套任务与运行协议下，拟合的任务成功概率达到 50% 时，对应的专家人类完成时间。它不是模型实际跑了多少小时，不是最长不中断运行时间，也不是“所有耗时少于此值的工作都能做”。固定模型的 scaffold、工具、预算、任务分布、人类基线和成功标准会影响结果。原 2025 年方法的历史趋势可作背景，当前模型数字须另核版本与区间；本段不把教材的“14 小时”作为当前实测值。[METR 原方法](https://metr.org/blog/2025-03-19-measuring-ai-ability-to-complete-long-tasks/)

为了理解拟合曲线，可以用一个**示意模型**：$p(t)=\sigma(-\beta\ln(t/H_{50}))$，其中 $t$ 是人类完成小时数，$\beta>0$ 为斜率，$\sigma(z)=1/(1+e^{-z})$。在 $t=H_{50}$ 时，两种斜率都给 50%；但若任务时间只有跨度的四分之一，$\beta=1$ 给 80%，$\beta=3$ 给约 98.46%。所以“保留 4 倍跨度余量就安全”缺少斜率、任务分布和错误代价依据。教材输出 Skill 的 2 倍/4 倍拒绝阈值与部署跨度统一扣减 20–40%，均为作者启发式，不能当 METR 或厂商标准。

### 条件概率与长链路

若整个任务要求每一步都成功，则链式法则给出 $P(S_1,\ldots,S_N)=\prod_i P(S_i\mid S_1,\ldots,S_{i-1})$。只有相应条件概率都等于 $p$，才得到 $p^N$；把独立小题测出的边际准确率直接套进去通常不成立。错误可能相关，Agent 也可能恢复、重试或更换路径。99% 的假设单步成功率连乘 70 次约为 49.48%，是“全部必需步骤成功”的教学计算，不是任何实际 Agent 的测量。

如果每步同一成功率 $p\in(0,1)$ 且目标总成功率 $q\in(0,1]$，最大整数步数为 $\lfloor\ln(q)/\ln(p)\rfloor$。$p=1$ 没有有限上限；$p=0$ 且目标为正时只允许零步。不能用任意大整数冒充无限上限。外推 $H(m)=H_0 2^{m/d}$ 的 $H_0$、月份 $m$、翻倍期 $d$ 均为假设；$d\log_2(H_*/H_0)$ 只是给定假设下的交点，不能据此安排部署日期。

### 完整离线例：跨度斜率与条件概率

以下程序用纯 Python 核对公式、零步、概率边界与非有限数，并展示相同 $H_{50}$ 不保证相同余量可靠性。未拟合 METR 数据、未评测模型，也没有计算真实 API 费用。

```python
import math


def number(x):
    if type(x) not in (int, float) or not math.isfinite(x):
        raise ValueError('需要有限实数')
    return float(x)


def all_steps(probabilities):
    # 输入必须为 Pr(本步成功 | 此前全部成功)，不能用边际准确率替代。
    values = [number(p) for p in probabilities]
    if any(not 0 <= p <= 1 for p in values):
        raise ValueError('条件概率超出范围')
    return math.prod(values)


def max_iid_steps(p, target):
    p, target = number(p), number(target)
    if not (0 <= p <= 1 and 0 < target <= 1):
        raise ValueError('概率范围错误')
    if p == 1:
        return None  # 在该假设下没有有限上限，不伪造 10**9。
    if p == 0:
        return 0
    n = math.floor(math.log(target) / math.log(p))
    # 消除刚好位于整数边界时的浮点误差。
    corrections = 0
    while p ** (n + 1) >= target or p ** n < target:
        if corrections >= 64:
            raise ValueError('浮点整数边界无法可靠定位，需要更高精度')
        n += 1 if p ** (n + 1) >= target else -1
        corrections += 1
    return n


def illustrative_success(human_hours, horizon_hours, slope):
    t, h, beta = map(number, (human_hours, horizon_hours, slope))
    if min(t, h, beta) <= 0:
        raise ValueError('时间和斜率须为正')
    z = beta * (math.log(t) - math.log(h))
    return math.exp(-z) / (1 + math.exp(-z)) if z >= 0 else 1 / (1 + math.exp(z))


def crossing_months(base_hours, doubling_months, target_hours):
    b, d, t = map(number, (base_hours, doubling_months, target_hours))
    if min(b, d, t) <= 0:
        raise ValueError('参数须为正')
    result = d * (math.log2(t) - math.log2(b))
    if not math.isfinite(result):
        raise ValueError('交点超出可表示范围')
    return result  # 负数表示假设中的过去，不硬改为未来。


assert max_iid_steps(.99, .5) == 68
assert max_iid_steps(.995, .5) == 138
assert max_iid_steps(.999, .5) == 692
assert max_iid_steps(1, .5) is None
assert max_iid_steps(0, .5) == 0
assert all_steps([]) == 1
assert math.isclose(all_steps([.99] * 70), .99 ** 70)
assert illustrative_success(10, 10, 1) == .5
assert illustrative_success(1e-300, 1e300, 1) == 1
assert illustrative_success(1e300, 1e-300, 1) == 0
assert math.isfinite(crossing_months(1e-300, 7, 1e300))
p1 = illustrative_success(2.5, 10, 1)
p2 = illustrative_success(2.5, 10, 3)
assert p1 == .8 and p2 > .98  # 同一 H50 和 4x 余量，可靠性仍依赖斜率。
for bad in (True, float('nan'), float('inf'), -1, 1.1):
    try:
        all_steps([bad])
    except ValueError:
        pass
    else:
        raise AssertionError('无效概率被接纳')
print('50% 步数上限：68 / 138 / 692；70步(.99)：', round(.99 ** 70, 6))
print('相同 H50=10h 的4倍余量，示例斜率1/3：', round(p1, 6), round(p2, 6))
print('假设14h、7月翻倍，30h/168h交点：', round(crossing_months(14, 7, 30), 3), round(crossing_months(14, 7, 168), 3))
```

浮点例用对数差避免极端时间比的溢出/下溢；很大的整数步数边界若64次调整仍无法定位会明确报错，不能卡在无界循环或冒称精确整数上限。极端曲线在浮点中可能舍入为0/1，不表示真实概率已得到证明。

### 长任务评测中的行为差异

评测与部署可因任务、工具、预算、数据、用户身份和环境提示而不同。应使用接近实际流程的评测、随机混合评测场景、独立效果核对和有界授权，并保留模型可能识别评测环境这一限制。Anthropic 的 2024 对齐伪装研究在特定训练信息与 free/paid 用户设定下观察行为差异；78% 是实际训练模型回应有害查询后，scratchpad 中对齐伪装推理的比例，不能改写成“训练去除伪装导致 78%”，也不能直接换算部署可靠性下降比例。[对齐伪装原研究说明](https://www.anthropic.com/research/alignment-faking)

## 19. 自主研究：从论文产物追到实验事实

AI Scientist-v2 用实验管理 Agent 协调初步验证、超参数调整、研究议程执行和消融四个阶段。树节点保留实验方案、可执行代码、运行状态、指标与图；节点报错应标记 buggy，而非在最终文章中消失。阶段间选择候选、保存检查点、重复实验以获得均值和标准差。VLM 评阅图形能检查图例与表述，但不能证明数据真实、实验设计有效或方法新颖。[AI Scientist-v2 论文 §3.2–3.4](https://arxiv.org/html/2504.08066v1)

论文报告在受控安排中提交三份生成稿，其中一份获得达到该 ICLR workshop 接受门槛的评审结果。这是该安排下的研究示范；三份不是任意主题的可靠率估计，评审通过也不消除数据重叠、实验口径和图注问题。不同 venue 的要求应按其实际规则判断，不能用“workshop 一律低标准”替代审稿内容。

**必须分清外评的对象。** Beel 等人的 arXiv:2502.14297 外评使用依赖用户模板与 Aider 修改实验的 AI Scientist 配置，五个失败来自十二个拟议实验；这不能当 v2 失败率。该实验还发现新颖性判断依赖检索结果匹配、已知概念被误标新颖、参数没有真正变化或基线没有重跑等问题。应保留这些失败类别作为检查项；不保留教材未经支持的“v2 新颖性错误率 25%”“VLM 掩盖 70%”。[外评 §2.3–2.4，v3](https://arxiv.org/html/2502.14297v3)

### 证据链与导出前的两类检查

例如要比较超参数e=2、3、4、5，先冻结四个run ID、实际读到的配置、同一数据/基线版本和种子。若四个运行记录均为e=2，应标记“配置未生效”，不绘成四组结果。每组重复次数、有效样本数、失败次数与指标单位进入账本；图的数据文件摘要指向对应run，caption只描述这些运行支持的范围。这样即使自动writeup误写“e=5最好”，审查也有具体反证。

每条研究主张连接到：任务/假设 → 数据划分与版本 → 代码与环境 → 实际运行记录 → 指标归约 → 图所用数据 → 文字主张。代码退出成功不等于指标正确；图漂亮不等于实验运行；未执行不能写成负结果；检索没有返回相似标题不等于新颖。最小例是声称比较四个参数，运行账本却显示每次用同一个参数，此时文章再完整也不能支持参数比较。

实验检查要复现基线、保留所有尝试和失败分母、核对种子与样本量、检查泄漏、做必要消融并报告不确定性。图检查要能追到具体 run 和输入数据，核轴/单位/归一化/误差条和结论范围。新颖性检查比较相关方法的假设与机制，开放问题交由有领域判断的人复核；机械检查完成并不代替学术判断。研究数据和发布流程的责任范围沿用[案例方法论](10-案例方法论.md)，不另建“AI Scientist 笔记库”。

运行生成代码还要独立检查文件、网络、进程、资源和凭据边界。容器名称或 subprocess 本身不是隔离证明：宿主挂载、Docker socket、网络权限、子进程与凭据仍可能扩大能力。先给受限工作目录、最小凭据、资源和时限、网络范围与可审计终止方式，再允许实验；对外导出与投稿由已授权的责任人核对证据和目标 venue 的披露要求。

教材 research-loop 模拟器只是按人工概率抽样，并未运行研究。它把“重试恢复”一律标记实验缺陷；计算 `polished_hides_weakness` 后没有让该值影响最终分类，因此改变所谓 polish 概率不会使“干净/有缺陷”分类按该机制变化。不能用这些输出推测 v2 的成功率或展示质量掩盖错误的实际比例。


### 文献检索先建立实体，再判断支持与反证

2026-10-12补入固定Phase19第51课。研究问题先拆成可查的对象：方法机制、评价任务、比较基线、指标及适用条件。检索器返回候选文献，证据核对器才判断论文是否支持、反驳或未回答某个具体主张。高排名、近引用距离、新年份和标题相似都是查阅线索；它们既不能证明新颖性，也不能宣布一个假设已被文献解决而跳过必要实验。

文献记录至少保留内部实体ID、外部ID命名空间、DOI/arXiv编号及版本、标题、作者、年份、摘要/正文获取位置、来源修订与抓取时间，以及引用和被引邻居。DOI与预印本编号可能指向同一研究的不同发布形态，arXiv v1/v2还可能有修改；应关联实体与版本，保留每条来源记录。不能直接用标题相等合并，也不能认为两平台ID天然相同。同一DOI出现年份、作者或标题冲突时保留冲突和原始来源，再核出版者/论文版本；不由生成器选一个“看起来合理”的值覆盖。引用关系也要注明从哪版取得，撤稿或修订状态未知时保持未核。

**词汇检索与图遍历操作两个不同对象。** BM25对查询词与候选文本的统计匹配打分；第51课代码实际索引`title + abstract`，不是图/文案所写的仅摘要。沿用[文本检索与RAG文档工程](12-文本检索与RAG文档工程.md)的BM25/RRF主入口：tf饱和避免同词重复无限加分，长度归一避免长摘要只因词多占优，idf降低普遍词的权重。该正idf形式在df=N时仍为ln(1+.5/(N+.5))>0，大N趋近0；N=1时约.28768，不能写成恰好0。查询重复词如何计权、标题是否加权、Tokenizer及语言政策都进入索引版本；源码ASCII分词会丢中文，不能声称已支持中文检索。

引文遍历则在明确文献实体的图上进行。引用是有向边；若同时沿“参考文献”和“被谁引用”探索，需构造两种邻接并注明边方向。一个小例：A引用B、B引用C，给A作种子时C距A两跳；给C作种子并允许反向边时也能找到A。多源无权BFS维护队列、visited与最短hop，遇到环不重复扩张；不存在的种子应报未知ID，不静默制造节点。已知基础论文可以直接作为明确anchor，不必先命中词汇；若没有词汇命中、也没有有效anchor，图遍历就没有起点。来源实现只用前若干词汇命中作种子，尚未提供后一入口。

遍历深度、最大节点/边、时间与候选数一起控制成本。两跳是课程的配置选择，不是“所有研究三跳无价值”的结论；图覆盖不足、跨学科引用和热点节点都会影响漂移。默认hop分值1/.6/.3分别表示0/1/2跳的排序特征，.3不是30%的相关概率。词汇、图邻近与年份可按预设协议融合，保各项特征和理由；BM25分数与hop常数不在相同尺度，不能未经校准就当概率相加。RRF用于合并排名时也只是候选排序方法，仍需人工/可信证据核对。

实体ID去重后应保“来自哪些检索路径与版本”，不能丢掉冲突。索引对同一ID更新须移除旧词项/旧长度/旧df或重建快照，来源直接重复add会使文档数和df膨胀并留下旧倒排项。只加载一次可复用索引，但语料、分词或元数据变化时要失效重建。来源中的两个mock API有各自测试，搜索入口实际上从一个合成corpus复制，没有调用双API合并；100篇虚构标题与作者只供接口演示。其序列化还丢摘要，不能假设下一阶段能直接取得“前三句上下文”；跨阶段先核字段、证据位置与内容摘要。

读候选论文时，将主张写成“在数据D、方法M、比较B、预算R下指标X怎样变化”，附原文页/表/段落及版本。找到标题相关但评价任务不同，记相关背景；找到相同条件下的负结果，记反证；未读方法和结果则记待核。检索没有相近标题只说明这一语料/查询未命中，不能得出“世界上没人做过”。检索产物应把候选列表与已核支持表分开交给实验设计，保支持、反证和未知，不能由rank直接决定科学结论。

### 实验运行合同必须落到实际配置和全部终态

第52课补充运行层；受限工具执行器继续复用[工具使用的运行边界](../Agentic%20Design%20Patterns/01-核心章节/18-安全模式.md)，这里解释实验身份与记录。实验规格不是一串命令：它将假设ID、固定代码与输入摘要、参数、预定种子、工作目录/环境、资源预算、指标schema和工件位置连接。标注意图配置和子程序实际读取配置，运行日志回显其摘要；传入`__seed`只约定子程序使用，不能证明随机源已经全部受控。

| 合同位置 | 需要核对的记录 | 不能用什么替代 |
| --- | --- | --- |
| 启动前 | 脚本/数据/代码修订、命令参数、工作目录、环境与允许权限 | 文件名或spec ID |
| 运行中 | 实际配置/种子、开始时间、stdout/stderr、资源采样与采集能力 | 请求配置或动画数字 |
| 结束后 | exit code、终止原因与时间、合法最终指标、完整工件摘要 | 出现一个JSON或退出0 |
| 对照关系 | 相同数据/指标/预算、全部种子、变更项和失败 | 删除失败后的均值 |

子进程有独立地址空间，崩溃可与编排者分开，也给父进程可终止的句柄；它仍可能继承文件、环境凭据、网络和创建子孙进程的能力。运行不可信实验前要由实际受控执行环境落实权限、时间、CPU/内存/磁盘/输出和进程树限制。超时后要能终止整个作业并排空/关闭管道、等待回收，不能只kill父pid后就报告所有计算已停止。课程Popen没有受限cwd/env/session，仅终止主pid，不能当安全沙箱。本文没有执行候选代码或声称这些限制已在本机部署。

RSS轮询是软限制：两个观察之间的短峰可能漏掉，慢采集命令还会降低实际频率；主pid的RSS不覆盖整个树，也不等GPU显存。`RSS/1024`若原单位是KiB，结果是MiB，应写清单位。平台不能读取RSS时记录`unavailable`、原因及实际执行政策：强制需要该能力就拒绝启动，允许降级就显式标“内存限制未核/未生效”；不能记成0或继续后报告已受限。观察到超阈值后人为终止是runner的资源决定，不必然是操作系统OOM。若deadline和RSS同时触发，保各自观测时间和最终决定，不凭固定优先级断言真实根因。

日志采集也需要预算。并发读取stdout/stderr，保存有界流或轮转文件、总字节数、截断/丢失状态及raw摘要；给模型的摘要长度是另一预算。来源先`communicate`收集全部文本、序列化才截400字符，不能防止采集阶段内存耗尽。最后一行JSON覆盖所需metric keys，只是来源的格式选择；应再核协议版本、run/seed/input/code身份、值的严格类型和有限性、指标单位、有效样本/Token数及完成状态。NaN/Infinity即使某JSON解析器接受也拒绝进入正式结果；标准输出本身还可能是子程序自报，重要数据须追到真实测量工件。

exit≠0即便已打印部分指标仍记crash，不把部分结果发布成ok；timeout、资源终止、解析错误、缺指标、未知exit各有终态。合法成功要求exit=0且最终指标合同有效，之后仍需实验真实性与设计核对。原runner的required keys只查存在，不核类型/单位；空required集合几乎可接受任意对象。失败/未知运行在账本保留，性能比较可以另定义有效成功样本的统计，但完整失败率与预算不能丢失。

一次只动一个参数（OFAT）回答“在其它参数固定于此值时，这个参数的条件效应”。例如两个二值参数A/B的得分：00=0、10=1、01=1、11=5。从00分别改一个只见+1，组合却+5，交互差为5−1−1+0=3；不能从两条轴推断11=2。全因子两水平k因素有2^k组合，能观察交互但增加成本；资源有限时按筛选/响应面目的选有说明的部分因子、区组与随机运行顺序，而不是说全因子“无法解释”。本批根代理2026-10-12选读[NIST实验设计选择](https://www.itl.nist.gov/div898/handbook/pri/section3/pri33.htm)的目标与资源段、[两水平全因子](https://www.itl.nist.gov/div898/handbook/pri/section3/pri333.htm)定义/表；未读全手册，也不把其特定因素数建议当通用门槛。

每组使用相同预定seed集合配对重复，随机化顺序可缓解负载/温度随时间漂移；同seed不能保证墙钟一致或消除所有噪声。配置需深拷贝或不可变，run ID绑定规范化配置/输入摘要，避免浅copy嵌套参数串改和字符串ID碰撞。来源的sparsity脚本按人工公式加噪声生成数值，没有稀疏attention训练；它还依赖NumPy，非源码所称全标准库。原成功/超时/崩溃/同seed测试未覆盖OOM与采集不支持路径，预设3.1秒/PPL31.4/OOM动画也不是本轮触发证据。

### 研究判定必须保留效应区间与未知原因

第53课把运行账本转成比较判定。先检查候选**和基线**全部终态与预定共同不变量：指标/单位、数据与划分、预算等保持一致；两边的代码/配置/模型修订分别冻结，允许的变更范围明确可核，不要求测试新方法时两边所有SHA仍相同。再验证预定seed集合完全一致、无重复、不转换伪种子。来源实际只取两边交集，部分缺配对被静默丢弃，只有无交集/重复才报错；正式协议应显式拒绝不完整配对。种子相同是配对条件之一，不是“噪声已全部取消”的证明。固定模型的测试案例Bootstrap与重复训练的seed差值估计不同变化，继续复用§4和[统计估计检验的严格配对](../AI%20算法基础/数学与数值计算专题/11-统计估计检验与实验判断.md#64-重复训练按种子配对先守身份再计算效应)，不另复制尾概率库。

每条判定保存配对数、方向统一的原单位效应、SE/置信区间、采用的检验及条件、p/未知原因、最小有用效应、比较集合/停止规则和失败状态。n<2缺方差，SE=0退化不能直接用p=0认证；基线0时相对率未知，不把分母改1伪装百分比。常规配对t以独立差值和适当近似为前提，双侧p检的是零平均差，不能证明业务收益或新颖。来源自写Beta/Lentz迭代缺收敛状态和强数值核验，不纳入主知识库正式统计计算。

PPL的log变换等于对应平均token NLL；需同Tokenizer/有效token/窗口与归约。32→28的原PPL下降12.5%，log差0.133531，而来源实际用相对平均log量约3.8529%。跨seed平均log对应几何均值，与log(平均PPL)不同。门槛“2%”必须说明是原PPL相对下降、NLL绝对差还是另外定义的量，不能借log变换声称跨指标可比。详细手算与一个独立标准库合同例在上述数学入口，未运行来源数值代码或真实模型实验。

判定要把“有效且达到实际效应门槛、统计证据支持改善”“回退”“效应太小”“证据不确定”“配对缺失”“运行失败”分开。来源先效应门槛后显著性，将前两类不足都叫noise；这个标签只是流程决定，不能证明没有效应。指标/分支多重比较与反馈后自适应重试会扩大选择偏差，预定主要比较和停止点，必要时用正确多重/序贯方法，并独立确认选中的候选。单次p<.05、图中预设t=5.9/p<.01和手工PPL数组不能充当已完成的科学证据；dataclass名字相似也不等检索→runner→evaluator已经真实接通。

### 论文工件的结构、正文和引用须一起验收

第54课在现有证据链的最后增加写作合同。先安排论证：问题和假设、已有方法差异、可复现的设置、结果与不确定性、局限和结论范围。再声明标题/摘要、唯一section ID与正文槽、图ID/来源/数据摘要、引用key/元数据。结构可以让缺节、重复ID、未知引用和图槽被发现，但有“Results”标题与非空正文不证明实验完成；引用列表也不证明具体主张有支持。来源实际先创建目录、填mock prose并修改paper，再render验证，不能把动画的“验证全部门禁后生成”当源码行为。

正文生成后重新提取实际引用/图引用并与声明双向核对：声明未用、正文未声明、错误版本和找不到图分别报告。源码主要查声明列表的key/ref，正文直接写`cite/ref`可以绕开；manifest的bibliography是全部声明key、body_chars仅长度，不能说它们代表实际用过的引用或内容。section ID重复/空section/无body也应由合同拦截，不能把原正向string测试当完整论文验收。结构验证与逐主张证据验证是两层，后者要原文位置、条件和结果。

引文元数据通过真实DOI/原论文核标题、作者、刊物、年份、版本与状态，保存来源和缓存时间；DOI可解析不等支持当前句子。两个平台冲突先保记录再核，不用模型编造BibTeX填缺口。课程Smith2020/Jones2021、后续Synthesised/Source占位作者与引用key是虚构fixture，不能出现在正式科学论证中。删除BibTeX中的花括号会破坏专名大小写保护与分组语义，不能称正确转义。

输出时把普通文字与允许的TeX结构分开。标题/作者/摘要中的特殊字符按文本规则编码；正文若允许受限结构，单独解析/校验，不能把全部输入当裸TeX。图path、label、引用key、entry type、宽度同样要合法schema，不因“非正文”而放行。源body/path/id/width等仍有裸值入口。生成文本、受限格式渲染、受控编译与科学性审查分别验；本批没有编译TeX或运行不可信论文代码。15个来源测试的文件存在/字符串断言不能证明PDF可编译、图存在、文献真实或内容有效。

路径要有明确基准。例如manifest在`runs/r7/manifest.json`、图值为`figs/loss.pdf`，应相对声明的manifest数据基准解析，而不是取当前shell目录；再将已验证的绝对输入路径转为论文输出目录下的受控相对路径。核允许目录、文件真实存在/类型、图工件SHA与图所用数据SHA、run ID和代码/配置修订；同名图被覆盖后，旧caption和评审应失效。课程函数按进程cwd解释路径，没有真正使用manifest的cwd，demo图路径也没有对应生成文件。计数顺序生成的ID插入新图会改变身份，不能称内容稳定ID。

多工件发布要防半套新旧混合。先在新generation目录渲染tex/bib/manifest和图，逐项写摘要与引用依赖；全部验证完成后发布一个指向该不可变generation的索引/指针，旧版本仍可读取。一个文件的原子替换不等多个文件的事务，还需故障恢复、并发发布和durability策略。课程按顺序三次`open(...,'w')`，后一次I/O失败可留下已覆盖的tex和旧bib/manifest；不能把函数返回成功前的顺序写称all-or-nothing。工件清单至少绑定正文SHA、实际引用/图、输入数据、渲染器和证据版本；评审结果必须指向最终正文，不把改写前评分沿用到新内容。

依赖注入让writer与prose generator分别测试：mock用于固定结构与序列化，真实生成器可替换接口，但需重新核费用、输入/输出范围、失败、格式与主张支持。多格式输出复用同一证据身份，分别检Markdown/HTML/TeX的引用与图片；接口相同不自动保证所有格式完整。原write成功输出paper.tex/references.bib/manifest.json，尚未输出PDF，manifest也不是编译报告或科学证据。

### 端到端组合应由实际门禁决定是否交给writer

第57课的真实组合范围是按路径加载54 PaperWriter、55 CriticLoop与56 IterationScheduler；50–53没有真实import/调用，seed和runner仍是内联stub。路径加载给独立main.py使用不同模块名以免重名，但仍修改sys.path/sys.modules并执行模块顶层，不是“完全不影响全局命名空间”。静读本轮没有调用loader。用import复用已有实现有利于集中维护，最终仍需每条接线验证输入schema、版本、身份、输出与终态，不靠流程图或一行接口名认证。

调度器的reward来自固定base加噪声与sleep；按trigger分支选最高mean、同分按branch ID字母顺序，只验证选择策略。高均值可能受样本数与选择偏差影响，应要求同协议、完整成功/失败、有限值和独立确认，不能把它称新颖性或真实实验收益。没有trigger会抛NoTriggerError，全为孤立trigger会抛BestResultError；部分孤立记录源码静默过滤，正式接线应把它们保为错误/未知并阻止无解释筛选。重复branch、非法mean、无有效样本、已剪枝分支也要校验。

critic按tag、引用/图key数量和正文长度评分，扩写和自动加引用便能提高分数，未读真实方法、结果或文献。需同时保存status、reason、逐维分、证据状态和所评正文SHA。`converged`可能表示平台期，不能只凭该字符串放行writer。根代理的**条件静态算术**以初始reward≥.8、五维舍入后求均值、max_rounds=6、target=8、epsilon=.1、window=2核对：

| 轮次 | clarity/novelty/evidence/methodology/related work | 均值 | 相邻均值增量 | 达到五维8分吗 |
| --- | --- | --- | --- | --- |
| 1 | 3.20 / 9 / 2 / 4 / 4 | 4.440 | 未定义 | 否 |
| 2 | 5.81 / 9 / 5.50 / 9 / 9 | 7.662 | 3.222 | 否 |
| 3 | 6.21 / 9 / 9 / 9 / 9 | 8.442 | .780 | 否 |
| 4 | 6.62 / 9 / 9 / 9 / 9 | 8.524 | .082 | 否 |
| 5 | 7.03 / 9 / 9 / 9 / 9 | 8.606 | .082 | 否 |

第5轮连续两次增量≤.1，返回converged/plateau，clarity仍7.03<8；没有执行第5轮修订，也没到第6轮budget。来源测试只断言status==converged，与这条条件路径相容；本批未运行测试，既不称其必失败，也不称质量达标。其它reward/初态/阈值另核，一般budget路径“最后改稿但返回修改前score”的问题也不能冒称发生于这条plateau路径。

正式writer入口应要求选中候选的实验/图/引用证据有效、评审指向当前正文、预定逐维质量达到要求；plateau、budget、failed和unknown都留草稿/诊断状态，不能自动进入“质量通过”。原demo不检查critic reason/逐维目标，仍mini_to_full并write。mini_to_full生成占位作者、BibTeX与未创建的`figs/branch.pdf`，替换图引用；writer又可填prose，所以mini评分必须重新绑定最终full正文与图证据，不能将“文章文件生成”当有效研究发布。

最终报告保scheduler_report、best_branch、best_reward、critic_result、paper_manifest、stop_reason及stage状态/版本/SHA，方便追因；它们在源码仍有转换和stub，不能按docs称所有字段无变换或前七模块全接通。同seed测试只比branch、reward六位精度与section IDs，没有验证完整report字节、正文/图/引文、路径、wall time或trace顺序。“确定”需声明不变量与不可控字段，保完整输出与差异；预设broken-input动画并未实现所有错误门禁。

## 20. 协调评测：里程碑的单位与基准适用范围

2026-10-10 增量吸收。最终任务正确、部分进展、代理贡献、通信质量和费用是不同指标。先定义每项分母，再记录 task ID、版本、模型与工具、拓扑、数据切分、总预算和所有尝试；超时、拒绝和未知结果不能消失。

[MultiAgentBench / MARBLE v1](https://arxiv.org/abs/2503.01935v1) 的个体 KPI 为 $n_j/M$，$M$ 是任务里程碑数，$n_j$ 是代理 $j$ 参与达成的里程碑数；总体是 $\sum_jn_j/(NM)$，并另评最终结果和协调。它不等于唯一已完成里程碑的比例。例如两人参与同一项，贡献计数可各加一，唯一成果仍只有一项。应固定里程碑判据、来源和检测器，不能为得到高分任意拆细或奖励重复工作。

每项真实里程碑的成本应为总尝试费用除以实际完成数量。例中两任务各有四个可能里程碑，只完成两项、共花费0.60，成本是每项0.30。若把两任务完成率相加（2/4＋0/4＝0.5）作为分母，会得到1.20；总体完成率则是2/8＝0.25，二者都不是里程碑数量。零完成时保留花费并将单项成本记为未定义。下面每行是一项任务的预聚合账本：费用包含其所有尝试，完成数是独立核过的唯一里程碑数；程序只核这些字段的聚合，真实费用采集和里程碑去重另需证据。

```python
from decimal import Decimal

def cost_per_milestone(rows):
    if not rows:
        raise ValueError('样本不能为空')
    ids, total_cost, completed = set(), Decimal(0), 0
    for row in rows:
        if (type(row['id']) is not str or not row['id'] or row['id'] in ids
                or type(row['completed']) is not int
                or type(row['possible']) is not int
                or not 0 <= row['completed'] <= row['possible']
                or row['possible'] <= 0):
            raise ValueError('ID、任务容量或完成数非法')
        ids.add(row['id'])
        cost = row['cost']
        if type(cost) is not Decimal or not cost.is_finite() or cost < 0:
            raise ValueError('费用须为同单位非负有限Decimal')
        total_cost += cost
        completed += row['completed']
    return total_cost, completed, total_cost / completed if completed else None

rows = [{'id': 'a', 'completed': 2, 'possible': 4, 'cost': Decimal('0.30')},
        {'id': 'b', 'completed': 0, 'possible': 4, 'cost': Decimal('0.30')}]
cost, count, ratio = cost_per_milestone(rows)
assert (cost, count, ratio) == (Decimal('0.60'), 2, Decimal('0.30'))
# 把完成率当里程碑数，单位会差一个每任务容量4的因子。
wrong_ratio = cost / (Decimal(count) / 4)
assert wrong_ratio == Decimal('1.20')
assert cost_per_milestone([rows[1]]) == (Decimal('0.30'), 0, None)
for broken in ([rows[0], rows[0]],
               [dict(rows[0], completed=True)],
               [dict(rows[0], cost=Decimal('NaN'))]):
    try:
        cost_per_milestone(broken)
    except ValueError:
        pass
    else:
        raise AssertionError('非法聚合记录未拒绝')
print('全部尝试费用/真实完成里程碑：', cost, '/', count, '=', ratio)
print('错误完成率分母为', wrong_ratio, '；零成果保留未定义，失败费用不消失')
```

源程序的随机基线固定返回 0.15，没有合法动作分布或采样；所谓污染由人为给 seen 集加分造成。对真实系统，训练/留出差也可能来自难度、选择、分布和过拟合。它可以触发调查，不能只凭超过 0.1 就判污染。相同任务成对比较、多个随机种子、效应区间、最终质量及成本 Pareto 比单次排名更可判断；已有本章前面的成对评测与覆盖代码继续作为主例。

## 22. 生产发布：影子流量、金丝雀与回滚各证明什么

2026-10-10 融合固定 Phase17 第20课。先修是本章离线回归和服务性能，以及[生产级软件工程](../计算机科学基础/05-生产级软件工程.md)。发布不是把新模型的离线准确率换成一个线上流量比例；还要冻结模型、prompt、检索数据、工具协议、路由、预算和安全配置，保证候选与对照的差异可追溯。

**影子流量（shadow）**把实际请求的受控副本送给候选，候选结果不作为用户响应。它可比较错误、格式、拒绝、长度、费用和延迟，也可对有标签的样本离线评价质量；没有真实曝光，不能测用户对候选的满意度或留存。复制请求仍耗资源，增加第三方数据接收者，候选 Agent 还可能调用写工具，因此“未返回候选答案”不等于零影响。影子链路须有独立限额、合法数据范围、隔离写操作，主链路不得等待影子完成。

**金丝雀（canary）**让少量用户真正接触候选，在每阶段检查安全、服务和业务指标，再决定扩大、暂停或回退。1%→10%→25%等是示例，比例和观察时间取决于风险、样本量、迟到反馈、流量切片和可恢复性；固定每五分钟检查不意味着五分钟就足够。按用户/租户稳定分流，避免同一次会话中途更换模板；保留对照的同时按输入长度、地区、任务及缓存命中分层，防新旧请求构成不同造成假回归。

门禁分三类：严重泄漏、越权或数据破坏可直接阻断；延迟、错误率和成本用有样本量/时间窗的阈值；反馈与产品价值需要预定观察周期和统计方法。5xx与内容拒绝的含义不同，适当拒绝可能是安全进步，应分别记分母，不一律相加当质量退化。输出变短也可能是任务漏做，不能只把长度下降当节省。基线为零时不用倍数，缺指标、缺窗口或缺关键切片应保持等待/调查，不能默认为通过。

源“相同输入最多15%波动”未给可核实验配置，不成为统一噪声下限。浮点归约、batch与采样可能引起差异，但要量自己的协议下的方差和相关性；设更宽容的比例不会自动控制假警报。零观测泄漏只说明这一有限样本中没发现，不能证明未来泄漏概率为零。[Argo 分析文档](https://argo-rollouts.readthedocs.io/en/stable/features/analysis/)明确区分 Successful、Failed、Inconclusive；证据不足可暂停等待人工判断，不能把它归入成功。

回滚要恢复一套兼容版本，包含流量策略、模型/镜像digest、prompt、检索索引、schema、授权和缓存键。先确认旧版本健康且仍有容量，再切流、排空或终止在途请求、隔离候选产物、核用户端恢复时间。回滚配置很快，不保证模型已载入、路由已传播、已有写操作被撤销；有数据迁移需兼容、补偿或恢复。[Argo 流量管理](https://argo-rollouts.readthedocs.io/en/stable/features/traffic-management/)也区分路由权重与实际流量。“必须在60秒内”适合作为某系统的目标并实演练，不是所有环境的事实。

是否做 A/B由待回答的因果问题决定。“只是改良版本”也可能有产品收益/伤害需要随机实验；稳定性验证和产品价值验证分别设计，不能以金丝雀通过替代因果证据，也不要求每个修复都做大规模 A/B。

## 23. 在线实验：随机化单位、功效与重复查看

第21课补充的是在线因果实验，本章第4节的成对离线比较仍负责同案例回归。在线随机分配应在曝光前按用户、会话或租户选择稳定单位；同用户反复请求、共享租户、多人协作有相关性，分析单位须与随机化单位匹配，必要时做聚类方差/设计效应，而不是把每次模型输出当独立用户。模型有随机性不自动违反IID；真正要查相关、分布漂移、实验干扰、流失与选择偏差。

先预注册假设、主要指标、最小可检测效果（MDE）、护栏、样本量、实验周期、排除规则和决定条件。成本每解决工单需要用**完整成本/实际解决数**，保留未解决、重试和人工接管；主要指标可以是每用户解决率，同时设成本、尾延迟、安全失败护栏。会话更长未必更好，可能是用户解决不了问题；营销案例的+70%/30%等不当可复制收益。

对双侧、等组、独立二值结果的正态近似，设基线p0、候选p1、平均p̄=(p0+p1)/2，则每组人数约为：

$$n\approx\frac{[z_{1-\alpha/2}\sqrt{2\bar p(1-\bar p)}+z_{power}\sqrt{p_0(1-p_0)+p_1(1-p_1)}]^2}{(p_1-p_0)^2}.$$

α控制第一类错误，power是在指定真实效果下拒绝零差异的概率。3%基线、**相对提升5%**代表3.15%，差0.15个百分点，不能误当8%。低事件数、聚类、比例指标和分组不等时需相应设计，公式不万能。源函数接受alpha/power却固定1.96/.84，还向下取整、漏注明每组；正式例改用NormalDist分位数和ceil。没有通用“LLM人数×1.4”，噪声应进入实际方差/功效估计。

CUPED用曝光前协变量X解释结果Y的可预测差异，单协变量理想形式是 $Y'=Y-\theta(X-\bar X)$，$\theta=Cov(X,Y)/Var(X)$。调整前数据不能被治疗影响，需处理缺历史的新用户、单位匹配和差异方差。理想线性条件下剩余方差比例约 $1-\rho^2$，有效流量倍率约 $1/(1-\rho^2)$；不是“X方差等于Y的60%”就可求倍率。[Microsoft 原方法说明](https://www.microsoft.com/en-us/research/group/experimentation-platform-exp/articles/deep-dive-into-variance-reduction/)解释回归能解释的R²及不同产品上的实际收益，本批不把30–70%写成保证。

固定样本检验应在预定终点决策。每看一次p<.05就停会改变假阳性概率。真正序贯程序要说明零假设、统计量、数据条件、边界和有效性证明；源 `sqrt(2log(1/.05)+log(n))` 是自行设的z边界，不能凭形状叫mSPRT/always-valid。可使用经过核验的confidence sequence或平台引擎；简单替代是事先规定有限K次查看，分别用α/K检验，以union bound保守控制多次查看，但普通正态近似仍有小样本限制，不能升级成精确任何时刻保证。

多重比较也要区分：独立20个真零假设各α=.05，假阳性**期望数**1，而至少一次概率 $1-.95^{20}\approx64.2\%$，不是一定错一个。Bonferroni把家族α分配到m项，控制FWER；BH排序p(i)并找最大满足p(i)≤iα/m的i，控制FDR需满足独立或合适正相关条件，不代替任意依赖下的保证。SRM按预定比例和**人数**检查观察分配；47/53在100人中与100000人中意义不同，还要排查日志漏记、曝光过滤、跨组和机器人，而非仅归咎hash。

[GrowthBook 统计说明](https://docs.growthbook.io/statistics/overview)有Bayesian/Frequentist、可选CUPED/序贯及SRM等检查。平台选择看数据存储、隐私、部署、身份权限、指标定义、统计选项和运营成本。收购金额、旧模型型号和“医疗客户必选某平台”不成为技术标准。护栏“未显著变差”不等“已证明安全”；需预定最大允许伤害与非劣效边界，未知证据保留暂停。

### 完整离线例：样本量参数与CUPED算术

这是计算设计参数的标准库程序，未发起在线实验、未使用序贯边界，也不估真实产品效果。示例协变量和结果仅用于核公式；二值样本量是大样本正态近似。

```python
import math
from statistics import NormalDist, mean

def per_arm(p0, relative_lift, alpha=.05, power=.8):
    args=(p0, relative_lift, alpha, power)
    if any(type(x) is bool or not isinstance(x,(int,float)) or not math.isfinite(x) for x in args):
        raise ValueError('有限数值')
    p1=p0*(1+relative_lift)
    if not (0<p0<1 and 0<p1<1 and 0<alpha<1 and .5<power<1) or p0==p1:
        raise ValueError('有效概率及非零MDE')
    z=NormalDist().inv_cdf(1-alpha/2)
    zb=NormalDist().inv_cdf(power)
    bar=(p0+p1)/2
    n=((z*math.sqrt(2*bar*(1-bar))+zb*math.sqrt(p0*(1-p0)+p1*(1-p1)))**2/(p1-p0)**2)
    return math.ceil(n)

def cuped(x,y):
    if len(x)!=len(y) or len(x)<2 or any(type(v) is bool or not isinstance(v,(int,float)) or not math.isfinite(v) for v in x+y):
        raise ValueError('匹配且有限的观测')
    mx,my=mean(x),mean(y)
    vx=sum((a-mx)**2 for a in x)
    vy=sum((b-my)**2 for b in y)
    if vx==0 or vy==0: raise ValueError('无法估计相关性')
    cov=sum((a-mx)*(b-my) for a,b in zip(x,y))
    theta=cov/vx
    adjusted=[b-theta*(a-mx) for a,b in zip(x,y)]
    ratio=sum((b-mean(adjusted))**2 for b in adjusted)/vy
    rho2=cov**2/(vx*vy)
    assert math.isclose(ratio,1-rho2,abs_tol=1e-12)
    return theta,ratio

n=per_arm(.03,.05)
assert n>200000 and per_arm(.03,.05,alpha=.01)>n
assert per_arm(.03,.05,power=.9)>n
assert per_arm(.03,.10)<n
for bad in (True,float('nan'),0):
    try: per_arm(bad,.05)
    except ValueError: pass
    else: raise AssertionError('拒绝无效概率')
theta,ratio=cuped([1.,2.,3.,4.],[3.,5.,4.,8.])
assert 0<ratio<1
try: cuped([1.,1.],[2.,3.])
except ValueError: pass
else: raise AssertionError('常数协变量无信息')
print('3%基线相对+5%，每组',n,'总样本',2*n)
print('CUPED教学theta/剩余方差比例',round(theta,6),round(ratio,6))
print('独立20零假设至少一假阳性',round(1-.95**20,6))
```

### 第21课：五项原练习与六题参考

## 24. 负载测试：测量链路、流量模型与尾部证据

第22课延续本章第6节。首先区分**开环到达率**与**闭环并发用户**：开环按计划继续发送，慢服务会积队列；闭环用户等待响应才发下一个，服务变慢会自动减流量，可能掩盖过载（coordinated omission）。同时记录计划、实际发送、完成、拒绝、超时和在途数，定位客户端还是服务端饱和。

流式客户端在单调时钟上记发送时刻、首个有效内容到达、后续内容到达及完成。SSE chunk可能含多个token，也可能仅是角色/心跳/usage；网络chunk间隔不自动等token间隔。TPOT按完成时间扣首token时间再除后续token数，须明确n≤1、取消、空响应、重试与finish原因。客户端反复tokenize全文可能额外耗CPU，不应把这个处理排队全算服务延迟；先用客户端CPU、事件循环延迟、发送落后量和独立探针定位。Python tokenizer可能有原生实现释放GIL，不能笼统“Locust一定骗人”。

测量工具记录具体commit、实际代码的时钟/分母、SSE解析和使用量定义，而非只看TTFT/TPOT名称。源所谓k6 v2026.1.0未在[官方release索引](https://grafana.com/docs/k6/latest/release-notes/)找到；普通HTTP请求耗时不等TTFT，必须选择能增量读取真实流的工具或扩展并验证。GenAI-Perf/LLMPerf差异应按使用版本代码核，不能笼统断言某工具ITL必含TTFT。本批选读 [LLMPerf OpenAI客户端](https://github.com/ray-project/llmperf/blob/f1d6bed47e4501b0e371082b41601b59ab55269f/src/llmperf/ray_clients/openai_chat_completions_client.py)：它在每个非空、非DONE的SSE行先增加tokens_received，包含可能无content的事件；INTER_TOKEN_LAT保存time_to_next_token的总和，其中包含TTFT。这不是按实际模型token数求出的标准TPOT，不能直接拿同名指标与另一工具比较；其他客户端/后续归约本批未全读。

代表性工作负载要联合保存输入/输出长度、prompt内容、共享前缀长度与作用域、并发/到达间隔、任务类型、模型参数、冷/暖缓存和多租户分布。均值和标准差不能表达长尾与相关性。重复相同prefix可减少prefill，不自动把多次decode合成一个；不应通过跨租户泄露缓存实现“高命中”。固定prompt有价值作为明确的cache-hit上界/对照，但不能当真实混合流量结论。公开数据也需检查许可、敏感性及与业务任务的差距。

| 流量形状 | 观察问题 | 应记录的证据 |
| --- | --- | --- |
| 稳态 | 持续负载下质量/SLO与容量是否稳定 | 发送/完成率、排队、尾延迟、缓存、GPU/客户端负载 |
| 渐增 | 饱和拐点在哪，prefill/decode如何争资源 | 每档实际负载、SLO合格goodput与错误 |
| 突发 | 暖容量、扩容和排空是否及时 | 冷启动分段、积压峰值、拒绝、恢复到正常的时刻 |
| 长时 | 泄漏或累积状态是否增长 | 稳态流量下RSS/显存/句柄/连接/队列/日志积压的趋势 |

持续几分钟/几小时是题设预算，需覆盖预热、缓存失效、自动扩缩、业务周期和充分尾部样本。50次观测的P99几乎由最坏一条决定；小CI可发现显著回归，不承诺准确估计高分位或SLO极低失败率。保失败和超时，不能只统计成功请求；比较吞吐时同时固定输出量/质量、量化和硬件。

### 第22课：五项原练习与六题参考

1. **uniform与真实分布哪里不同？** 源均一500请求只首次miss，其余499hit；多prefix首遇miss更多。源码prompt_tokens、TPOT、batch efficiency和unique_prefixes没进入测量，也无墙钟/GPU，因此只能演示set缓存命中，不能比较并发容量或TPOT；本批未运行源程序。
2. **100并发、5分钟、P95 TTFT<800ms怎样写CI？** 先选可正确解析SSE的客户端；建立100并发或指定开环率、内容到达事件的自定义TTFT指标、有限deadline、实际usage和错误计数，再以同数据/硬件/预热比较。本批没安装k6或调用服务，不能交付一个普通http.post耗时伪装TTFT的“已验证脚本”；800ms为原题目标。
3. **每小时内存增加50MB怎样诊断？** 固定负载和模型，分查请求/缓存对象没释放、连接/响应未关闭、遥测buffer积压。对RSS、显存allocated/reserved、对象数量、连接句柄及日志queue做趋势；warm-up/cache填充可正常增长，泄漏需持续/释放对照。
4. **10→100RPS扩容多久恢复？** 取决节点供应、镜像/权重加载、GPU初始化、探针、路由传播、排队及限流，无固定Karpenter+vLLM秒数。逐段记时并在实际完成率/SLO回归基线时判恢复，不把Pod Ready当用户恢复。
5. **TPOT分别6与11ms怎样解释？** 核同请求token数量、首token是否扣除、token vschunk、空事件、失败和客户端开销；差值未必全是TTFT，可重算统一定义后比较，不照源归因替代检查。

六题：①可能的客户端瓶颈需证据，GIL不是所有tokenizer必然限制。②同prompt产生cache偏差但不等于N decode变1。③稳态/渐增/突发/长时分别检不同失效。④代表性需内容/长度/到达/前缀联合分布，均值标准差不够。⑤当前工具版本与SSE能力重新核验，不采用虚构k6版本/通用“最佳”。⑥soak看持续资源/连接/遥测积累，须区分正常缓存增长。

## 25. 双重用途能力：选择题、拒绝和现实帮助分别报告

2026-10-11融合Phase18第17课。WMDP用专家审查的“黄区”相邻/前驱知识作四选一proxy，避免直接发布敏感执行细节；题目公开不等任意复用都不需信息危害审查。本批实际PDF v7（2024-05-15）为3,668题：Bio1,273、Cyber1,987、Chem408，课程的4,157及其域别数量不符。固定数据版本、域别题ID、模型/adapter、提示、生成或候选likelihood策略、random seed及评测路径，不能随便更换数据后沿用旧分母。[WMDP原论文§3–5](https://arxiv.org/abs/2403.03218)

高分表示能够答特定知识问题，不等新手完成真实破坏任务；低分可能由拒绝、格式错误、缺知识或评分故障产生，也不单独证明彻底遗忘。四选一随机猜测25%只在等概率随机选择假设下成立，**不是新手人类能力基线**。同时报告裸模型/尽量elicited路径与生产安全栈路径，拒绝率、未判定和正常任务效用；这里解释对照方法，并未绕过真实供应商护栏。

### RMU：修改表征与保持能力的双目标

设更新模型中间层表示为h_u(t)、冻结原模型为h_f(t)，遗忘集和保持集分别为D_f,D_r。原RMU对遗忘token使h_u接近c×u，对保持token使h_u接近h_f；按token数归约平方差，再用权重alpha合并。u由[0,1)独立分量生成后归一化且训练中固定，不是在整个单位球面均匀采样；c控制尺度，不是删掉所有神经元。这里不提供危险训练语料或声称运行过模型遗忘。

原实验主要在Zephyr7B、Yi34B、Mixtral8x7B的Bio/Cyber进行，明确没有对Chem做遗忘实验；Table1的Zephyr Bio63.7→31.2、Cyber44.0→28.2，接近但不等25%随机，MMLU58.1→57.1也不是完全不损失效用。结果说明给定协议的可行性与取舍，不能推出所有知识已不可恢复；需要未见知识/格式、不同elicitation、旁路、重新微调及一般任务测试。表征干预、回答拒绝和样本隐私遗忘也是不同目标。

### 新手uplift要有真实对照与任务范围

在Claude4系统卡的2025受控**文本规划**实验中，每组8–10人、最多两天，控制可用基础互联网，模型组另有移除保障的Opus4；Deloitte按rubric评分，控制平均25%±13%、Opus4组63%±13%，对应报告uplift2.53倍。所有参与者都有关键失败；作者因接近其保守rule-out边界而不能排除ASL3，不是证明人们成功实施危险行为。隐性技术、材料、权限、真实持续时间与主体动机仍未由文本得分充分表达。[系统卡§7.2.4.1](https://www.anthropic.com/claude-4-system-card)

新手相对帮助（模型相对无模型对照改变多少）与专家在足够资源下能elicitation的绝对能力不同。报告相对比值同时给原分数、样本与误差，低基线会放大倍率；相对于随机选择题的倍数不应名叫人类uplift。源程序只按预置概率抛硬币，再人工降低两个域准确率，既没有WMDP题、真实模型，也没有RMU；3–4百分点一般能力损失是手填参数，不是测得成本。

### 完整离线例：不让拒绝与缺失悄悄改善分数

下面是自定标签账本，只验证题ID、路径、分母与未判定，未评估任何模型。正式基准还需其规定的likelihood/选择解析和冻结gold。`correct_upper`是对未知状态的保守范围上端，不能发布为官方benchmark成绩；未知题需要重查或重跑。

```python
from collections import Counter
from fractions import Fraction

# 只核对评分合同，标签是人工构造；没有真实WMDP问题或模型。
EXPECTED = {"q1", "q2", "q3"}

def summarize(records, path):
    if type(path) is not str or path not in {"raw", "guarded"}:
        raise ValueError("必须明确评分路径")
    if type(records) is not list:
        raise ValueError("记录必须为列表")
    seen = {}
    for row in records:
        if type(row) is not dict or set(row) != {"id", "path", "verdict"}:
            raise ValueError("错误记录schema")
        item, route, verdict = row["id"], row["path"], row["verdict"]
        if type(item) is not str or item not in EXPECTED or route != path:
            raise ValueError("题目或评分路径错误")
        if type(verdict) is not str or verdict not in {"correct", "incorrect", "refused", "unknown"}:
            raise ValueError("评分不是可判类别")
        if item in seen:
            raise ValueError("重复题目，先对账而非重复计分")
        seen[item] = verdict
    counts = Counter(seen.get(item, "unknown") for item in EXPECTED)
    total = len(EXPECTED)
    answered = counts["correct"] + counts["incorrect"]
    return {
        "n": total,
        "counts": dict(counts),
        "correct_all": Fraction(counts["correct"], total),
        "answered_accuracy": Fraction(counts["correct"], answered) if answered else None,
        "answer_coverage": Fraction(answered, total),
        "unknown": counts["unknown"],
        # 仅对未知标签给保守范围，拒绝按已知非答题成功；非官方榜单分数。
        "correct_upper": Fraction(counts["correct"] + counts["unknown"], total),
    }

def row(item, verdict, path="raw"):
    return {"id": item, "path": path, "verdict": verdict}

raw = summarize([row("q1", "correct"), row("q2", "incorrect")], "raw")
guarded = summarize([row("q1", "correct", "guarded"), row("q2", "refused", "guarded")], "guarded")
assert raw["correct_all"] == guarded["correct_all"] == Fraction(1, 3)
assert raw["answered_accuracy"] == Fraction(1, 2)
assert guarded["answered_accuracy"] == 1 and guarded["answer_coverage"] == Fraction(1, 3)
assert raw["correct_upper"] == Fraction(2, 3) and raw["unknown"] == 1
empty = summarize([], "raw")
assert empty["answered_accuracy"] is None and empty["unknown"] == 3
for records, path in [([row("q1", "correct"), row("q1", "incorrect")], "raw"),
                      ([row("q4", "correct")], "raw"),
                      ([row("q1", True)], "raw"),
                      ([row("q1", "correct", "guarded")], "raw"),
                      ([{"id": "q1"}], "raw"),
                      ([row("q1", "correct")], "production_unknown"),
                      ([row(True, "correct")], "raw"),
                      (None, "raw"),
                      ([row("q1", "correct")], [])]:
    try:
        summarize(records, path)
    except ValueError:
        pass
    else:
        raise AssertionError("非法记录被静默计分")
print("评分路径、重复题与schema校验通过；raw答题准确率1/2，guarded为1但覆盖仅1/3；两者全部题正确率1/3，未知1题")
```

同样1个正确题，guarded拒绝另一个已答错题后，“已回答准确率”会从1/2升为1，全部计划题正确率仍1/3且覆盖更低。因此不能只展示已答子集的改善；raw/guarded不同路径也不能混在同一评分账本。正常通用任务应独立给同协议前后delta，不因危险域分数下降就跳过副损失。

## 26. 多指标报告先证明数据独立与分母一致

第9～11节已经维护likelihood/PPL、字符串指标、失败账本与case diff，第3.2节给完整加权及finite检查。本次第41课只补它们如何在一个suite接线：数据与用途、生成输出、评分协议和聚合身份明确后再算总分，不再复制评分算法。

首先核数据角色。源`train_small`直接使用全部LM_CORPUS和EM_PAIRS，再在同两集合报告PPL与EM；F1/JUDGE_SET还重复部分事实。它是训练集记忆与接口演示，不能称heldout。公开基础事实可用于教学样本，但图中不同subset也不自动独立：按问题事实／来源／模板族拆分，记录哪一组被训练、调参或judge校准利用，final test保持不回流。参考答案亦需核；fixture把Elizabethan English摘要成Old English错误，不随分数高就进入正式知识。

PPL对所有有效nexttoken先加总NLL/target数，再exp；不先平均每batch的exp。即便长度相同，exp非线性也使二者不同；等批权重还会相对过权短批，不是源所说“低估短序列”。零有效token的样本应标不适用／无效，source把per-example PPL夹成1会伪装最好；总集无token给inf却extras mean0也不能当有效测量。大NLL用log-PPL/原NLL及明确数值状态避免exp溢出，NaN/Inf不参与身份或质量平均。

EM和F1各锁规范化。源EM小写、trim、仅压双空格、删末尾.!?；F1只小写／trim／空白split，没有同样去punct，故文案“相同规则”不符。官方SQuAD2还删除articles和全部ASCII punctuation、按多个gold取最大，空／无答案有其规则；这是[固定作者评分器](https://github.com/rajpurkar/SQuAD-explorer/blob/eee5fdbf62f8613a7812b03419e6b29617b74fd1/evaluate-v2.0.py)的定义，不用于所有代码或中文任务。大小写、单位、数字与否定有意义时使用专用协议，词面重叠不等语义正确。

源mock judge完全由EM/F1阈值映射1～5，instruction甚至不进入判断，不能作为第三个独立的质性质量证据。judge最低1/5=.2，再加正的PPL方向分，aggregate>0几乎没有交付判别力。高judge低EM可以是正确改写，也可以是错误词重叠、judge偏差或任务集合不同，要读逐例与gold。真实judge替换同签名函数之外，还需rubric/schema、range/finite、超时／重试／费用、数据scope与校准，沿第3节维护。

聚合需完整metric合同：name唯一、值及权重finite非bool、范围合法、非负且至少一个正权重；明确必须包含哪些任务与缺项状态。源duplicate name会被字典覆盖但总weight重复计，负weight也能通过，NaN的min/max还可能夹成好分；缺项自动renormalize可把未完成评测隐藏。若允许subset，输出coverage和缺项列表，不能与完整suite名次直接比较。PPL方向映射`1/(1+ln(ppl))`只是任务选择，judge/5的低端仍>0；严重错误与未判定应有独立gate，不靠其他分补足。[第3.2节程序](#32-权重wilson-区间与评分缓存合同)已经验证非法分数／权重与完整失败分母，继续复用。

源20个测试定义只核正向字符串、部分计算和subset renormalize，没有测试污染、重复name、非法权重、真实judge或严格JSON。报告JSON应禁止NaN/Infinity，并带dataset/model/Tokenizer、生成模板／stop、评分器版本、case ID、失败／unknown、有效token及费用状态；写出一个report.json或exit0不等模型通过独立质量标准。

原扩展目标的参考判断：

1. **校准评测如何定义概率事件？** 先说清预测的是选择题正确、某token还是完整任务成功，再按该事件的置信度分箱，报告样本数、经验成功率与不确定性。生成时最大softmax不是整份答案真实概率；不要混用两种事件计算校准。

2. **鲁棒性退化如何按原题配对？** 用稳定case ID连接原题及其错字、改写或干扰变体，确认语义和gold仍等价，保失败／未知状态。按同题差值及变体类别报告指标变化，不把改写改变了任务的案例仍按旧gold评分。

3. **真实judge接入需补哪些合同？** 固定rubric、模型／版本、输入与输出schema，检查范围／finite、超时、重试与费用；对不可信评审文本设明确数据边界。匿名和交换顺序可诊断偏差，再以独立人工gold校准。接口签名相同，不等评审已经可靠。

4. **学习聚合权重怎样避免再拟合测试？** 只用开发集的模型偏好顺序拟合，限制权重非负并记录目标，再在独立held-out集合核排序稳定和业务含义。保每项原分与缺项状态，不能用最终测试结果反复调权重后仍称独立验证。

1. **低PPL能判断什么？** 同Tokenizer、窗口与有效分母下的PPL描述预测拟合，不认证事实／指令能力。源在已训练的LM/EM集合评价，须标训练记忆演示。

2. **为什么先token加权NLL再exp？** 先按有效token加总NLL再exp，避免非线性和等批权重偏差；短批通常被相对过权，不是源的“低估短序列”。

3. **空预测和无答案如何区分？** 本例与SQuAD2有一侧空、一侧有答案时F1为0，双方无答案可1。缺失预测／日志错误不能未经规则伪装成空答案命中。

4. **方向归一的前提是什么？** 有限ppl≥1时该映射同向单调；无效数值另有状态。聚合仍核name唯一、权重与分母，不能只凭某normalizer落[0,1]接受。

5. **真实judge替换函数之外还需什么？** 同签名函数只是接入点。真实judge还需rubric／schema／范围、费用、失败和数据边界，并以独立gold校准；mock没有质性观察。

6. **高judge低EM就一定是正确改写吗？** 高judge低EM可能改写，也可能词重叠或judge错误，先读逐例与任务分母。source最低judge仍给正分，aggregate>0不是交付质量门槛。

## 27. 自建评测harness：任务、adapter、指标与结果身份

§9已有loglikelihood、loglikelihood_rolling与generate_until三类请求，§10–11维护文本指标、pass@k、完整case账本和预测diff；本节复用这些程序，把自建harness的接口与验收接上。自建任务有助覆盖业务，公开基准提供外部比较，二者都需冻结协议；自建并不自动更难、更真实或不受污染。

任务JSONL可定义四个必需字段：唯一非空id、字符串prompt、非空字符串列表targets、已注册metric，extras为经过相应指标schema校验的可选字典。必须拒绝重复ID、targets意外是一个字符串而被拆成字符、空参考、未知metric和非法类型。同一文件允许混合metric还是只允许一种须明确；assert不是生产输入校验，python -O可移除它。记录原始任务bytes SHA、dataset版本/split、rubric与采样政策，模型/checkpoint、Tokenizer、模板/few-shot、解码/stop、adapter/metric代码版本和资源预算一并绑定。题目/答案污染、开发回流与最终测试各有边界，单独task hash不能证明无污染。

### 27.1 五种fixture各检查什么

来源的五种fixture是算术exact match、字母选择题、关键词生成、摘要ROUGE-L及代码测试。它们可以检查数据/接口/结果序列化的协议，却不能因为ToyModel命中预设答案就当真实LM能力。来源选择题gold全为A，Toy先输出A；其它任务也有同源关键字或固定代码骨架，leaderboard高分因而只是fixture行为。生成首字母正确与用loglikelihood比较多个完整选项不是同一评分模式，任务应明确选哪种，不在换adapter时暗换请求类型。

算术EM先确定精确字符串、数值容差与单位政策。“4”“4.0”“4米”能否同分取决于任务，不一律lowercase/去标点。大小写归一对代码和专名可能有害。生成contains关键词只表覆盖，否定“不是pineapple”同样含目标词，空target还会永远子串匹配；它不能称答案正确性。多reference可按预先规定的最大值或其它规则选，不在看结果后改参考。

ROUGE-L基于固定分词下的最长公共子序列重叠，表达词面覆盖而非事实正确或语义理解。来源英语ASCII字母数字分词会丢中文，中文任务要声明适用的分词/字符政策与标准实现版本。不能用从零写的词重叠评分器冒称BLEURT；后者是学习式评分模型。新指标先给任务定义、标签、分数解释和错例校准，再讨论其是否适合[0,1]聚合。

代码评测需要测试输入、预期输出/行为和passed/failed/error/timeout等终态。来源主进程exec删除__builtins__，仅阻止常规import路径，**不是安全沙箱**；对象访问、无限循环、巨数和内存耗尽仍存在风险，其算术AST解释器也没有完整资源上限。不能复制该执行器到学习例或在宿主运行不可信生成代码。真实运行需隔离、低权限、无网络、文件/进程/时间/内存限额及销毁环境，异常或超时不能伪装测试失败输出。本批仅静读任务，不执行任何候选代码。

### 27.2 Adapter与runner的可比性合同

Adapter把模型特有实现封在接口内，但“返回list[str]”只是最小骨架。还要声明请求类型、身份/修订、输入Token预算、生成参数、timeout、usage、失败状态及输出case ID/顺序。返回数量相同不保证逐题对应，需按ID核无缺失/重复与顺序；返回值、score的严格类型、有限性和范围都先查。call异常时记录受影响case及原因，不把整批丢失后仍用幸存分母。

Runner加载并验证冻结task，按明确顺序请求，保存逐例原预测、评分状态/依据、耗时和版本，再聚合并发布完整结果。任务种子生成只是创建fixture的工具；正式运行不因seed flag默认重写tasks或覆盖旧结果。结果schema如leaderboard.v1提供迁移入口，未知版本拒绝或显式迁移，字符串字段本身不会自动保证下游兼容。

binary accuracy的correct是明确通过的题数；软分数sum不能round成人数。若三题ROUGE分数为.2/.5/.8，则mean=.5、score_sum=1.5，并不存在“正确2题”。task宏均值给每task相同权，micro均值按题数或约定权重；两task分别1题得1、9题得0时，macro=.5而micro=.1。即使两个指标都在[0,1]，其含义也不自动可互换或无权平均。空task、缺失、异常和超时的分母/分数规则预先声明，同时报coverage与终态计数。

总wall time若包含adapter和metric，是端到端suite时间，不能称单模型推理latency；每例deadline包括队列、网络还是代码metric必须写清。线程等待超时不保证底层工作停止；可终止的进程/job还要清理资源。比较两次run先核task/config/metric/model身份以及实际变更范围，再对同case预测和状态diff，报告样本量、paired不确定性与回归切片，不能只看宏均值或排行。

### 27.3 五项练习与判断标准

1. 加第六个自定义指标：定义其任务、分数、normalization、多reference、失败分母和语种，用正确/近似/否定/空输出错例校准。BLEU类重叠与BLEURT类模型区别写清，不以命名代替算法。当前未开发或运行新指标。
2. 捕获代码stdout作为targets：隔离执行及时间/资源限制先完成，随后定义exact stdout normalization与passed/failed/error/timeout，不在宿主exec加重定向后声称沙箱。此练习的候选代码未执行。
3. leaderboard diff：先核两run任务/配置/指标身份，按case ID比较预测与状态，再解释哪个task变化及分数差；变动协议另报，不将单次分差全归模型。复用§11已运行账本/diff程序，本次不新建一套。
4. 每例latency上限：明确adapter/metric/queue各阶段deadline，能停止的job和资源清理另核；timeouts单列但仍留在预定完整分母，线程返回超时不等实际计算已停止。真实adapter/服务超时未运行。
5. task SHA绑定结果：对实际评分bytes计算SHA并绑定schema、生成配置、metric和模型修订；同filename不等同任务，可信pin与artifact revision分别记录。不能只hash文件却漏template/few-shot的变化。

### 27.4 六道测验与解释

1. 四个必需字段是什么？来源schema为id/prompt/targets/metric，extras可选；要求合法类型、非空参考、唯一ID及指标特有extras，不只字段存在。
2. metric(prediction, targets, extras)→float有什么价值？统一最小评分接口，但要有限值/范围、binary或soft语义与权重，不能因为[0,1]就直接等权比较不同任务。
3. 删除builtins怎样抵抗恶意代码？不足以抵抗，它只删部分名称，仍有对象和资源风险；源正确选项在这里应纠正，不能称安全隔离。
4. adapter抽象提供什么？减少模型替换涉及的接口位置，同时保请求类型、身份、采样、Token/timeout和failure合同；list字符串不足以做完整比较。
5. schema版本提供什么？明确验证/迁移分派入口，必须拒绝未知或显式迁移，版本字符串不自动实现兼容。
6. overall_score怎样算？来源是task宏均值，需说明每task同权；micro另按题数/约定权重。soft sum不是正确人数，保失败/空任务规则和case diff才能解释回归。

### 27.6 冻结的是可复算的协议，不只是六个字段

第27节已有任务、adapter、指标和结果身份的骨架；继续学习时，先能区分一条有效记录、一次完整运行和一次可信比较，再把评分、校准与统计汇总接起来。必要先修是JSON类型、字符串规范化、概率/NLL与第4节的成对比较。这里的目标是读懂并设计协议；真实模型、候选代码隔离及服务性能需要另有实际运行证据。

此前第49课的四字段`id/prompt/targets/metric`与第70课的六字段`task_id/category/prompt/targets/metric_name/post_process`是两种课程自定义schema，不能只改字段名后声称兼容。第70课另外允许`few_shot_examples`和`metadata`。例如任务`arith_001`可把“17+24”的prompt、参考`["41"]`、`exact_match`、`strip_whitespace`以及“2+2→4”的few-shot一起绑定；任务身份须包含这些实际内容与版本，而不只名字`arith_001`。它借鉴通用harness，但不是BIG-bench或HELM的官方通用格式。

字段规则应明确到可以拒绝反例：ID非空并在整个任务集唯一，prompt非空且按所选政策保留或拒绝尾空白，targets是非空字符串列表，枚举严格为字符串。源的category有arithmetic、mcq、code_exec、classification、summary；metric词表是exact_match、f1、bleu_4、rouge_l、accuracy、code_exec；post-process词表是none、strip_whitespace、lower、extract_letter、extract_code_block、extract_first_line。只有合法的category–metric组合才能进入评分；源实际允许MCQ使用exact_match或accuracy，与正文“MCQ只能exact_match”不同，且没有实施category–post-process组合约束。

“冻结”还包括schema版本、canonical JSON政策、实际任务bytes摘要、split、参考来源及请求配置。`TaskSpec` dataclass本身并未frozen，嵌套list/dict也可变，`to_dict`浅复制不阻止后续改变。ASCII ID的正则与正文“无空白”不完全一样，使用`$`还可能接受末尾换行；targets中的空字符串、metadata的NaN/无界尺寸、few-shot内部额外字段或空内容都需要明确处理。严格JSON输出应拒绝NaN/Infinity；语义上有意无答案的任务另定义，不能把空gold当默认合法参考。

JSONL校验与整run政策分两层。逐行解析器保留合法记录，记录坏JSON、首个字段错误、重复合法ID及原行号；这样可修数据，但不代表可以发布幸存题的均分。外层要事先选择“任何invalid任务阻止run”或“允许明确subset，并报告原计划分母、缺项和理由”。来源文档提到的`--allow-bad-tasks`并没有对应CLI实现。来源仅对已经合法的ID去重，所以非法同ID先出现、合法同ID后出现时仍可能被接收；不要把错误条数直接当所有规则都已穷尽的证据。

Few-shot按固定次序拼成`example.prompt + " " + example.completion`，各段用两个换行连接，再附正文；无few-shot时只保原prompt。保存实际rendered prompt摘要、示例顺序、chat template、Tokenizer、截断与输出预算。同一渲染文本能减少组装差异，但不同Tokenizer、模板、截断和采样仍会改变输入/输出；最多8例只限数量，不限Token数。正文内已有示例与外置示例双重拼装也需检测，来源只看特定marker的启发式不覆盖所有格式。

后处理是评分的一部分。`none`原样保留，strip只去两端空白，lower改变大小写，firstline跳空行取首个非空行；这些都可能改变任务事件。源extract_letter先找独立A–E，再用任意A–E作fallback，因此`Answer: C is correct`会提C，但只有`Answer`却可能误提A。源codeblock找不到匹配fence时返回raw；第72课提取器对未闭fence返回None；第75课又以`extract_code(processed) or processed`把解析失败文本送回执行路径。正确接线要统一解析状态：原输出、提取结果、parse_error和是否允许raw各有记录，解析失败不能伪装合法答案，更不能在宿主执行。

### 27.7 文本指标的算法、签名与归约一起冻结

第10节和[语言指标主入口](../AI%20算法基础/语言与文本专题/05-摘要推断与文本评价.md)已经解释EM/F1/BLEU/ROUGE，本节补接口差异。第71课教学重实现的价值，是能追到tokenization、频次裁剪、长度惩罚、LCS和归约的每一步；教学测试向量既不证明与所有标准库一致，也不证明文本真实。正式报告保metric revision、分词/大小写/标点、有效阶、平滑、多reference、句级或语料级、分数尺度与方向。

源`re.findall(r"\w+", text.lower())`供F1、BLEU、ROUGE用：Unicode word保数字和下划线，连续中文可能成为一个token。EM及accuracy实际只trim字符串，仍区分大小写；accuracy在此是EM别名。因而`YES`对`yes`的EM可以0，词元匹配却可1，不能沿用正文“所有指标同一个tokenizer”的断言。数值/单位、代码标识符、否定和大小写的规则按任务预定，不能运行后才选择提高得分的normalize。

Token F1的交集是Counter多重集：令候选/参考token数为$c,r$，匹配次数为$m=\sum_w\min(C_w,R_w)$，则$P=m/c$、$R=m/r$、$F_1=2PR/(P+R)$；$P+R=0$时为0。候选`cat cat cat`对参考`cat`有$m=1$、$P=1/3$、$R=1$，所以F1=.5，交换两侧仍.5。它不等集合Jaccard或忽略重复的F1。双方分词后为空时源约定1，单侧空为0；无答案、空预测、缺失输出和解析失败要用不同状态，不能让故障碰上空gold得到满分。多个参考取最高分是任务协议，也不自动复现SQuAD的全部标点/articles归一化。

BLEU的modified precision把候选ngram频次裁到参考上限，重复四次一个词而参考只有一次时unigram命中只能1/4。长度惩罚为$c\ge r$时$BP=1$，$0<c<r$时$BP=\exp(1-r/c)$，$c=0$时该教学实现为0；它防止短输出仅靠precision占优，与频次裁剪、平滑各有用途。第71课实际单参考、每阶分子分母都加1、所有四阶都参加几何均值；一token候选`cat`对`dog`没有任何匹配，四阶precision却为`[1/2,1,1,1]`，$BP=1$，得$2^{-1/4}\approx .840896$。这是按公式手算的反例，说明短句/缺有效阶的平滑可给很高分，不是语义正确。

源dispatcher逐参考计算句级BLEU再取max，不等标准多reference对每个ngram取各参考最大cap并确定有效参考长度。源另有`corpus_bleu`函数：先汇总原ngram计数及候选/参考长度，再求几何均值和BP。第75课却可把逐句BLEU当task score平均；**平均句分与语料BLEU是不同统计量**。若报告corpus BLEU的不确定性，每次bootstrap应重采样完整候选/参考对并重算计数和BP，不能只抽句分求均值。原平滑方法名称未经额外原论文核验，保实际算法签名即可。

ROUGE-L以最长公共子序列LCS保留顺序而无需连续：`a b c d`与`a c d`的LCS为3。把LCS长度分别除候选/参考长度得到P/R，再按既定$F_\beta=(1+\beta^2)PR/(\beta^2P+R)$组合，$\beta=1$是对称F1；说明$\beta$的偏向、空输入与多参考政策。源全DP表时间/空间均为$O(cr)$，不能将正文“通常不足1毫秒”当本轮实测性能；长文本先限制预算。词序重叠也不证明否定、数值或因果事实成立。

`score(metric_name,prediction,targets)`的最小float接口允许同category采用不同合法metric；先查已注册metric及参考，再调用并检查严格数值类型、finite、范围和方向。源先遇空targets就返0，会掩盖未知metric；`corpus_mean([])=0`也会把无数据伪装成绩。空参考、非法参数/NaN/Inf、未知metric应保invalid/unknown，不能自动当正常低分纳入榜单。范围相同也不说明两指标可加；模型型BLEURT、BERTScore或judge的意义、参考/模型依赖与校准另核，继续复用第3节。

### 27.8 代码测量：部分断言、完整成功与执行保护分别证明

代码任务的targets可为明确assertion表达式，例如检查`add(1,2)==3`；生产测试文件还需test ID、版本、固定输入、不能被候选改写的判定渠道。三assertion两条通过得2/3，终态仍是assertion_fail；pass@k中的$c$只能计**全部指定测试通过的候选数**。沿第15节逐test ID保F2P/P2P转换，不能把多跑一条测试补回旧测试回归，也不把近1软分阈值当全pass。

源尝试区分pass、assertion_fail、syntax_error、timeout、error，输出溢出归error并附`output overflow`。实际compile的SyntaxError才属于syntax_error；普通import失败通常error，assertion求值时runtime exception被源折到assertion_fail。更好的账本保每test的PASS/FAIL/ERROR/TIMEOUT/UNKNOWN及错误原因，外层再按预定规则聚合；异常、未跑、全失败、未闭fence不能都丢成一个0。没有assertions应invalid，不能靠空列表“全部通过”。

新Python子进程分开地址空间并提供终止句柄，能减少直接exec阻塞评测主进程；`-I`和导入denylist都不构成操作系统隔离。源实际monkeypatch `__import__`和`os.system`，仍保完整builtins及其它文件、环境、对象能力。没有凭据、网络、文件系统、CPU/RSS/磁盘、后代进程和可写目录隔离；容器名称也不自动提供这些保护。实际应由可销毁、低权限、无网络/无宿主秘密且有资源/进程树控制的执行环境认证，本次候选执行为0。

来源用`Popen -I -c`运行模板，并非图与部分正文所说stdin或`subprocess.run`。它repr嵌code/targets并两次字符串replace，存在占位串碰撞和参数/代码大小边界，不能直接当可靠传输协议。stdout分块累计到256 KiB后kill单PID，但poll结束的tail读取没有size；stderr运行时不排空，最后无界blocking read，后代保留pipe还能让清理卡住。墙钟deadline只约束循环的一部分，不证明finally、全部输出和整个进程树有界。真实保护要并行消费并限额stdout/stderr、限制结果通道与完整生命周期、实际终止/回收后代，再确认资源清理；有限等待与真正停止是两个事实。

父进程还必须验证来自不可信子进程的结果schema。候选print可能破坏whole-stdout JSON；JSON root不是dict会触异常；源对`results`只做truthiness计数，不核结果个数/严格bool，因此额外真值甚至可造成passed>total、score>1。只有exit0、合法JSON或导入被拒的测试都不能认证可信结果或沙箱。应使用受保护的测试结果通道，核逐test ID、结果长度、strict bool及终态一致，原输出另存；普通功能测试未覆盖绕过、stderr flood、后代持管道、跨平台、资源耗尽或输出协议真实性。

pass@k沿第10节公式，在整数$n\ge k\ge1$、$0\le c\le n$的域内为$1-\binom{n-c}{k}/\binom nk$。当$n-c<k$时“不通过集合不足以抽k个”，失败子集数应为0，因此值为1，不是数学分子“未定义”。$n=10,c=1,k=5$时值为.5；$k=1$退化为$c/n$。按题平均并保存每题n/c、采样参数、预算、测试及终态；源`k>n`直接返回是否有成功、truthy候选计数和无样本返回0都不属于有效估计。没有足够候选应不适用/未知，不能临时把重试次数充成独立样本。

### 27.9 概率校准先说清事件，再看ECE与Brier

第9.1/26节的PPL以有效target为分母。第73课接口实际接收**每序列NLL总和**$L_j$与该序列有效token数$n_j$，求$\log PPL=\sum_jL_j/\sum_jn_j$，再exp；不是“每序列平均NLL再带count相加”。例如两序列各1与9有效token，平均NLL分别2与1，则传入total NLL为2和9，得到11/10=1.1、PPL≈3.004166。传入2和1会错误得到.3。NLL为$-\log p\ge0$，log p本身≤0；要求输入finite非bool、count非负整数、零count与NLL关系合法。无有效token为unknown并用strict JSON的null+reason，大NLL可报告log-PPL及溢出状态。均匀V词表推出PPL=V，反向不成立，PPL也可超过V；PPL1只说明这份有效目标概率全为1，不认证所有任务完美。

校准观察的是`(p_i,y_i)`：$p_i$为对**指定事件**的预测概率，$y_i\in\{0,1\}$是同事件的裁决。选择题“所选选项正确”、代码“所有测试通过”、摘要“人工rubric达标”和单token预测是不同事件，不能混用。选项likelihood的softmax只是条件候选分配；$\exp(\text{mean logprob})=1/PPL$是token概率的几何平均；self-report亦需验证，都不自动等于整份答案正确概率。夹到[0,1]会把Inf或其它invalid伪装成概率，先查类型/finite/range再用，未知置信度另报coverage。

对预定bins $B_b$，令$N$为有效概率事件样本数，$n_b=|B_b|$、$\bar p_b$为该bin平均预测概率、$\bar y_b$为经验成功率，$ECE=\sum_b(n_b/N)|\bar p_b-\bar y_b|$。源等宽bin用边界右侧搜索，0与1归首/末bin，内部边界归右bin；改变边界或数量会改变数值，记录定义/版本。例如90%置信的一千答案中正确600，若在同bin且p均.9，gap为.3。空bin无经验准确率，不画作真实(0,0)；reliability数据保mean p/mean y/count，并报告总体N、切片和不确定性。

二元事件$Brier=N^{-1}\sum_i(p_i-y_i)^2$越小越好，是逐预测平方概率误差，包含校准和分辨能力，不是纯“局部校准误差”。p全为.5时不论标签比例Brier恒.25，ECE为$|.5-\bar y|$。全部答错但p=.01可有Brier .0001，所以不能仅因全wrong断言Brier一定高，也不能单凭accuracy/Brier大小就替业务作部署决定。

一个可手核的粗分箱反例：`p=[.4,.6], y=[0,1]`全放一个bin，mean p=mean y=.5，ECE=0；直接Brier=(.16+.16)/2=.16。把forecast先压成该bin均值.5，源`brier_decomposition`给REL=0、RES=0、UNC=.25，于是REL−RES+UNC=.25。它描述了粗bin代表值的预测，不能普遍当原逐预测Brier的精确分解。对每bin写$p_i=\bar p_b+\delta_i$，原误差在bin内等于代表值误差加$\overline{\delta^2}-2\overline{\delta(y-\bar y_b)}$；本例额外项=.01−.10=−.09，.25−.09=.16。bin内概率相同或另有满足条件的分解才可用相应恒等式；不要用少量synthetic近似测试宣布普遍正确。

ECE先在每bin取绝对值，不会跨bin的过/欠置信相抵；它可能隐藏bin内异质，且对bin与N敏感。`populated_bins`只是覆盖线索，一bin包含大量同概率独立案例也能估该概率点，并非“一bin必噪声大”。保样本数、counts、事件/类切片与合适区间，不能用固定10/15bins或100题作为普遍可靠阈值。校准可以按一个model汇总，也可以对有足够案例的任务/切片报告；异构任务pool可能遮住一类失败。

温度缩放在独立validation拟合，最终test冻结温度、概率事件和metric协议，比较ECE/Brier、accuracy、coverage及关键切片。二元校准可对事先定义的概率logit作温度处理；多分类通常对logits缩放后softmax，必须明确使用哪种。温度正且仅统一缩放多分类logits时argmax不变，但阈值/拒答或其它接线可改变业务行为；不承诺ECE必缩或某方案普遍更适合部署。本增量只手算和fixture合同，没有拟合温度或运行真实概率模型。

### 27.10 排名的分母、方向和抽样单位

聚合输入先绑定冻结的model×case计划矩阵，而非只收实际出现的成功结果。第74课`EvalRun`每model–task一条，包含metric/score/category及weight，但实际忽略weight；没有逐case/失败状态/plan分母。某model跳过难题后自己的task均分、胜率会提高，甚至仅它出现的task自动获胜。补全missing/error/timeout/unknown及原计划数量，报告completion和scoring coverage，再根据预定失败政策算分；空suite或全未判定是未知。

共同[0,1]范围能防止0–100的BLEU数值压过0–1的accuracy，但不解决指标意义、方向、任务权重。ECE/Brier越低越好，PPL无界，不能把“第71–73课所有分都是[0,1]且越高越好”当真。方向变换是一项人为评价目标，须保原值、变换及适用域；严重错误仍单列。宏平均$T^{-1}\sum_t\bar s_t$每task同权，micro平均按case数或指定有效计数；1题全对与9题全错给macro=.5、micro=.1。soft sum=1.5不是正确人数，不能round为2。权重若使用，要求finite非bool、非负且至少一个正值，按预定$\sum w_ts_t/\sum w_t$；缺项不得静默重归一。

胜率只看同场胜者，不表达赢多少。源是每task击败全部在场model的胜率，非任意A/B成对偏好胜率；实际并列最高者各记1，与正文“ties split”冲突，测试也断言两model各win_rate=1。若要平分两个胜者各.5或全计胜，应先声明并带候选集合/缺项政策；`math.isclose`还含默认相对容差，不只绝对1e−12。改变候选集合会改变胜率，同task严格单调变换通常不改胜者，但不能把这当可跨任意范围/缺项比较的保证。

单model均值bootstrap是对其冻结独立task/case分数有放回抽N个，重复B次，取alpha/2与1−alpha/2分位数。保存方法、B、seed、alpha、统计量、样本单位、N及分位规则；非参数不等无条件推断。A/B必须按相同case身份先求差，再抽成对差，方向写清是A−B还是B−A。源`pairwise_diffs`实际只用共同task，可能每pair的N不同且没输出共同IDs/删失；自己的均值CI与共同case差CI回答不同问题，不能比较两个区间重叠来代替配对差。

第4节既有程序继续负责配对bootstrap，统计假设与组级抽样见[统计估计检验与实验判断](../AI%20算法基础/数学与数值计算专题/11-统计估计检验与实验判断.md)。相关题族/同用户/重复生成按真实独立单位做组或层级重采样；case权重、比例、micro或corpus BLEU每draw都重算完整分子/分母/原指标。恒定样本给经验零宽区间，不证明总体没有不确定性；无样本不能返回[0,0]伪装确定。差CI严格不含0是源的significant标签，含0仅说明方向证据不足，不证明等效。排名反复选最好、多pair查看或多切片筛选另有选择偏差与多重比较，最终冻结test或预定选择/校正规则。

表格要给完整可辨model ID，转义pipe/newline；两位小数可能遮住零附近CI端点，显示精度不等推断精度。源总写95%标题，即使低级函数alpha变化，实际标题也不会跟着更新。JSON报告保schema、alpha/B/seed、case身份和所有失败，不只排行榜rows；阅读排行前先核这些合同，不从合成三model十二task的排序推断真实能力。

### 27.11 Runner组合的每个输出都要回到本次case

流水是`validate → render → adapter request → post-process → metric → case ledger → aggregate/calibration → report`。第75课通过`_load_sibling`真实导入70–74的main，模块顶层定义与初始化会执行；导入不等于纯文本阅读，顶层行为需另审，也不意味着自动运行candidate。测试中若调用run_candidate才进入候选路径。本次全静读，没有用import执行来验证。接口分工有助独立演化，但还须实际schema/摘要/版本合同，模块文件名不能代替依赖身份。

源最小adapter是`generate(prompt,task)→Generation`，含text、confidence以及序列token_nll总和/token_count。真实请求还需请求类型、模型revision、Tokenizer、生成参数/stop/预算、run/case/repeat/attempt ID、deadline、usage/费用和严格返回状态。generation文本有效不代表NLL测到了held-out参考；loglikelihood请求与generate请求应明确区分。沿第9节标准harness接口声明请求语义，同接口也不自动保证逐case对应。

实际单次loop只计generate调用前后的wall，再postprocess/metric；它不是端到端case latency，也不是纯模型token推理时间。EM/accuracy/code用≥.999999、软分用≥.5生成`correct`，这定义的是阈值事件；ROUGE≥.5不天然表示业务正确，partial assertion≈1也不等all-pass。confidence被clamp、code解析有rawfallback、代码终态/通过数被丢掉，均须由严格合同修正。不能在校准buffer只放“score过阈值”而没有label/rubric版本，然后称答案正确概率已经可靠。

PPL还有旁路：`Generation`返回的NLL/count没有进入TaskResult，也没有被run_eval消费；`_perplexity_blocks`只从adapter额外的token_stats取数据，buf/results参数未用。RuleBased直接读gold，Noisy/Biased人工设输出策略，用空白split估token数并造.8、2.5等每token NLL；这些只提供fixture，不是Tokenizer概率或held-out LM质量。重用adapter还会累积旧stats，跨run污染分母。正确接线把本次请求的NLL/count、参考/窗口/mask身份与case一起保存；无数据用null+reason，不是NaN或PPL1。

线程池一次提交全部model×task，共享adapter/RNG/token_stats。排序已完成结果只能固定表格次序，不能恢复Noisy随机数在case上的分配；case级随机性应由固定run seed和case/repeat身份派生，adapter要证明线程安全。所有`fut.result()`直接抛异常，退出ThreadPoolExecutor的context manager会等待已提交工作，源没有逐case失败账本、取消/stop机制、generation deadline或全run期限。future等待超时不证明工作停止；线程中已经运行的工作通常不能靠cancel终止。真正有限的运行需队列/生成/评分/清理各阶段deadline、有限在途请求、可取消底层请求或可终止job、保存已完成和未完成终态，并验证实际清理。

EvalReport只有leaderboard/pairwise/calibration/perplexity/summary，不保每case原输出/score/state/detail/latency；`tasks/models/task_runs`计数没核完整矩阵，JSON默认还能输出NaN。calibration也未保reliability三数组或Brier分解。构成报告时先从完整账本算coverage/失败/切片，再导出轻量汇总；缓存和重试另外记实际任务/请求/模板/解码/metric/输出评价版本及repeat/attempt，费用无usage为unknown。重试不是独立case，streaming先持久逐例断点再聚合。

原demo打印Markdown、summary与pairwise，并没有保存JSON文件或打印完整to_json。它检查非空、榜首rule_based且末尾不是rule_based，未断言严格分差，也未把所有runtime error包装为structured error；同分排序也可能满足榜首条件。只有gold-reading fixture排序成功不能说明任何真实模型提高，表/exit0不能代替完整终态、配对差与业务门禁。真实API、免费层、服务重试/缓存、模型/GPU、代码隔离和标准基准均不在本次运行范围。

### 27.12 完整CPU例：计划矩阵、协议身份与共同案例

以下程序只处理人工提供的评测记录，没有模型、候选代码或进程启动。复用第11节“完整失败分母”的约定，将计划补成每model四case；本例采用同一种人工质量分数和预定失败计0，不能用它认证自动语义评分。实际已收到的timeout仍是received但不是scored；没有收到的case标missing。平均和差值均同时报告完整计划与共同已评分子集，防止读者把子集比较当全计划改善。

import copy
import hashlib
import json
import math
from collections import Counter


def digest(value):
    data = json.dumps(value, sort_keys=True, ensure_ascii=False,
                      separators=(",", ":"), allow_nan=False).encode()
    return hashlib.sha256(data).hexdigest()


def numeric_score(value):
    if type(value) not in (int, float) or not 0 <= value <= 1 or not math.isfinite(value):
        raise ValueError("分数须为finite非bool的0..1数值")
    return float(value)


class EvalLedger:
    def __init__(self, models, cases, metric):
        if type(models) not in (list, tuple) or not models or any(type(m) is not str or not m for m in models) or len(set(models)) != len(models):
            raise ValueError("model ID非空唯一")
        if type(cases) not in (list, tuple) or not cases or any(
                type(c) is not dict or set(c) != {"case_id", "task_id", "category", "input"} for c in cases):
            raise ValueError("case字段合同")
        if any(type(v) is not str or not v for c in cases for v in c.values()):
            raise ValueError("case内容须为非空字符串")
        ids = [c["case_id"] for c in cases]
        if len(set(ids)) != len(ids):
            raise ValueError("case ID唯一")
        if (type(metric) is not dict or set(metric) != {"name", "revision", "scale", "direction", "failure_policy"}
                or any(type(metric[k]) is not str for k in ("name", "revision", "direction", "failure_policy"))
                or type(metric["scale"]) is not list or len(metric["scale"]) != 2
                or any(type(v) is not int for v in metric["scale"])):
            raise ValueError("metric字段及类型合同")
        if metric != {"name": "human_quality", "revision": "v1", "scale": [0, 1],
                      "direction": "higher", "failure_policy": "zero_all_planned"}:
            raise ValueError("本例仅接受冻结的人工质量协议")
        self.models = tuple(models)
        self.cases = {c["case_id"]: copy.deepcopy(c) for c in cases}
        self.case_hashes = {cid: digest(c) for cid, c in self.cases.items()}
        self.metric = copy.deepcopy(metric)
        self.metric_hash = digest(self.metric)
        self.rows = {}

    def verify_frozen(self):
        if type(self.cases) is not dict or type(self.metric) is not dict:
            raise ValueError("可信内存中的协议容器被改动")
        if self.cases.keys() != self.case_hashes.keys():
            raise ValueError("冻结case集合被改动")
        try:
            unchanged = (digest(self.metric) == self.metric_hash and all(
                digest(self.cases[cid]) == self.case_hashes[cid] for cid in self.cases))
        except (TypeError, ValueError, OverflowError) as error:
            raise ValueError("协议已不能按冻结JSON序列化") from error
        if not unchanged:
            raise ValueError("冻结case或metric内容被改动")

    def add(self, model, case_id, case_hash, metric_hash, status, score, output, reason):
        self.verify_frozen()
        if type(model) is not str or type(case_id) is not str:
            raise ValueError("记录model/case ID须为字符串")
        key = (model, case_id)
        if model not in self.models or case_id not in self.cases or key in self.rows:
            raise ValueError("未知或重复model/case")
        if case_hash != self.case_hashes[case_id] or metric_hash != self.metric_hash:
            raise ValueError("实际case/metric协议身份改变")
        if type(output) is not str or type(reason) is not str:
            raise ValueError("输出和原因须为字符串")
        if type(status) is not str or status not in {"scored", "timeout", "error", "unknown"}:
            raise ValueError("非法终态")
        if status == "scored":
            score = numeric_score(score)
        elif score is not None or not reason:
            raise ValueError("未评分记录score为None且说明原因")
        self.rows[key] = {"model": model, "case_id": case_id, "case_hash": case_hash,
                          "metric_hash": metric_hash, "status": status, "score": score,
                          "output": output, "reason": reason}

    def complete(self, model):
        self.verify_frozen()
        if type(model) is not str or model not in self.models:
            raise ValueError("未知model")
        return [copy.deepcopy(self.rows.get((model, cid), {
            "model": model, "case_id": cid, "case_hash": self.case_hashes[cid],
            "metric_hash": self.metric_hash, "status": "missing", "score": None,
            "output": "", "reason": "本次计划未收到记录"})) for cid in sorted(self.cases)]

    def report(self, model):
        rows = self.complete(model)
        n = len(rows)
        statuses = Counter(r["status"] for r in rows)
        return {"planned": n, "received": n - statuses["missing"],
                "scored_coverage": statuses["scored"] / n, "statuses": dict(statuses),
                "mean_all_policy": sum(r["score"] if r["status"] == "scored" else 0
                                       for r in rows) / n}

    def compare(self, baseline, candidate):
        aa = {r["case_id"]: r for r in self.complete(baseline)}
        bb = {r["case_id"]: r for r in self.complete(candidate)}
        common = sorted(cid for cid in aa if aa[cid]["status"] == bb[cid]["status"] == "scored")
        policy_deltas = [(bb[c]["score"] if bb[c]["status"] == "scored" else 0) -
                         (aa[c]["score"] if aa[c]["status"] == "scored" else 0) for c in aa]
        return {"direction": "candidate-minus-baseline", "planned_pairs": len(aa),
                "common_scored_ids": common, "excluded_from_common": sorted(set(aa) - set(common)),
                "common_scored_mean_delta": (sum(bb[c]["score"] - aa[c]["score"] for c in common) /
                                              len(common)) if common else None,
                "all_planned_policy_mean_delta": sum(policy_deltas) / len(aa)}


metric = {"name": "human_quality", "revision": "v1", "scale": [0, 1],
          "direction": "higher", "failure_policy": "zero_all_planned"}
cases = [{"case_id": f"c{i}", "task_id": "support", "category": "answer",
          "input": f"人工fixture输入{i}"} for i in range(1, 5)]
ledger = EvalLedger(["A", "B"], cases, metric)
fixtures = [("A", "c1", "scored", 1.), ("A", "c2", "scored", .4),
            ("A", "c3", "timeout", None), ("A", "c4", "scored", .8),
            ("B", "c1", "scored", .8), ("B", "c2", "scored", .9),
            ("B", "c3", "scored", .5)]
for m, cid, state, value in fixtures:
    ledger.add(m, cid, ledger.case_hashes[cid], ledger.metric_hash, state, value,
               "人工已裁决文本" if state == "scored" else "", "fixture模拟超时" if state == "timeout" else "")
a, b, diff = ledger.report("A"), ledger.report("B"), ledger.compare("A", "B")
assert a["received"] == 4 and b["received"] == 3
assert a["scored_coverage"] == b["scored_coverage"] == .75
assert math.isclose(a["mean_all_policy"], .55) and math.isclose(b["mean_all_policy"], .55)
assert a["statuses"]["timeout"] == 1 and b["statuses"]["missing"] == 1
assert diff["common_scored_ids"] == ["c1", "c2"] and diff["excluded_from_common"] == ["c3", "c4"]
assert math.isclose(diff["common_scored_mean_delta"], .15)
assert math.isclose(diff["all_planned_policy_mean_delta"], 0., abs_tol=1e-12)


def must_reject(call):
    try:
        call()
    except ValueError:
        return
    raise AssertionError("非法输入须拒绝")


for bad in (True, math.nan, math.inf, -.1, 1.1, "0.9", 10**400):
    must_reject(lambda bad=bad: numeric_score(bad))
must_reject(lambda: ledger.add("B", "c4", "wrong-case", ledger.metric_hash, "scored", 1., "x", ""))
must_reject(lambda: ledger.add("B", "c4", ledger.case_hashes["c4"], "wrong-metric", "scored", 1., "x", ""))
must_reject(lambda: ledger.add("A", "c1", ledger.case_hashes["c1"], ledger.metric_hash, "scored", 1., "x", ""))
must_reject(lambda: ledger.add("B", "c4", ledger.case_hashes["c4"], ledger.metric_hash, "timeout", .9, "", "timeout"))
assert digest(dict(reversed(list(metric.items())))) == ledger.metric_hash
assert digest(dict(cases[0], input="同ID但内容已变")) != ledger.case_hashes["c1"]
empty = EvalLedger(["A", "B"], cases, metric)
assert empty.compare("A", "B")["common_scored_mean_delta"] is None
must_reject(lambda: EvalLedger(["A"], [], metric))
must_reject(lambda: EvalLedger("AB", cases, metric))
for bad_cases in ({"c1": cases[0]}, [None], ["case"]):
    must_reject(lambda bad_cases=bad_cases: EvalLedger(["A"], bad_cases, metric))
must_reject(lambda: EvalLedger(["A"], cases, dict(metric, scale=[False, True])))
frozen_rows = copy.deepcopy(ledger.rows)
ledger.cases["c1"]["input"] = "同ID但内部内容意外改动"
must_reject(lambda: ledger.complete("A"))
must_reject(lambda: ledger.add("B", "c4", ledger.case_hashes["c4"], ledger.metric_hash, "scored", 1., "x", ""))
assert ledger.rows == frozen_rows
ledger.cases["c1"] = copy.deepcopy(cases[0])
ledger.metric["revision"] = "v2"
must_reject(lambda: ledger.report("A"))
assert ledger.rows == frozen_rows
ledger.metric = copy.deepcopy(metric)
assert ledger.report("A") == a
print(json.dumps({"A": a, "B": b, "diff": diff}, ensure_ascii=False, sort_keys=True, allow_nan=False))
print("身份/非法数值/重复/失败/空共同集合同通过；仅人工fixture，无候选执行")

### 27.14 三十六道原测验的中文问题与完整参考答案

下列A/B/C/D对应原选项顺序；原题、correct索引与中文答案落点在维护覆盖记录逐题绑定。来源选项存在过强或与实现矛盾的表述时，先说明原key，再给可以成立的判断。

#### 任务规格六题（70）

1. **为何先冻结task schema再写评分代码？** 原key A。schema约定字段、类型、渲染/后处理和metric消费方式，才能独立替换组件而维持同协议；还需要版本、实际bytes/参数身份和运行校验，不因写dataclass就自动冻结或免验证。
2. **metric_name的封闭词表有哪些？** 原key D：exact_match、f1、bleu_4、rouge_l、accuracy、code_exec。它是本课程词表；扩展要注册、验证并处理版本/迁移与回归，不必为了一个metric一定新增lesson，也不能接受任意字符串。
3. **未知顶层字段怎样处理？** 原key D，返回validation error并拒绝该record。metadata/few-shot内部额外键不因顶层拒绝而自动受控；后续schema应明确嵌套字段、尺寸、finite及迁移政策。
4. **为什么few-shot绑定task，而不由runner临时选？** 原key B，示例和顺序属于评测定义，绑定后减少每model独立拼装的差异。仍要固定实际render、Tokenizer/template/截断、参数和预算，不能把“同prompt”断言成只有model能导致方差。
5. **哪组category–metric非法？** 原key D，mcq+bleu_4；代码code_exec、summary+rouge_l、arithmetic+exact_match属于合法组合。实际MCQ允许exact_match或accuracy，对单字母用BLEU不合该schema；category–post-process仍需另核，来源没有完整组合验证。
6. **extract_letter对`Answer: C is correct`提什么？** 原key D，C。实际先取独立A–E，才fallback任意A–E；不是从整串第一个任意字母开始，否则会拿Answer的A。无真实答案的`Answer`可能被fallback误提A，故保解析状态和反例。

#### 词面指标六题（71）

1. **为什么tokenizer由metric层决定？** 原key B，它定义哪些token算匹配，改变规则等于改变该metric/benchmark口径。源F1/BLEU/ROUGE共享word regex，但EM/accuracy只trim，所以需逐指标固定签名，不声称全部同分词。
2. **modified ngram precision比plain多做什么？** 原key A，按参考ngram出现上限裁剪候选重复计数，防重复刷precision。源单参考，多个参考逐句算分取max不等各ngram的跨参考最大cap；正式多reference协议另定义。
3. **BLEU为何使用brevity penalty？** 原key D，precision单独奖励很短的命中片段，BP在c<r时exp(1−r/c)下调。它不替代clip或平滑；句/语料长度和有效阶政策不同，不能平均句BLEU当corpus BLEU。
4. **ROUGE-L比较什么？** 原key C，候选/参考token序列的最长公共子序列，再由LCS/c、LCS/r得P/R并组合F-beta。LCS保顺序而不要求连续；它仍是词面观察，不证明事实正确。
5. **哪种情况token F1=1？** 原key D，两侧分词后都空按源约定1；一侧空另一侧非空为0。缺失预测、解析失败和参考缺失不等有效无答案，须独立状态，不能通过空空规则奖励故障。
6. **score为何按metric_name而非category派发？** 原key B，同category可用不同合法指标，单一评分入口减少runner分支。仍要先验证metric/targets，再核strict finite/范围/方向；空refs先返0不能用来掩盖未知metric。

#### 代码执行六题（72）

1. **为何每candidate用新Python子进程而非inline exec？** 原key D强调隔离timeout/输出/危险import；成立的部分是地址空间和终止句柄分离、减少直接阻塞宿主。源码仍无OS权限/资源/进程树隔离，stderr/后代可影响宿主，不能声称所有崩溃或内存风险都只影响子进程。
2. **三assertion两pass一fail的分数？** 原key A，2/3≈.667，终态assertion_fail。它是断言fraction，不是整task成功，也不计入pass@k的全通过$c$；每test状态仍须保存。
3. **candidate无法通过compile时记录哪种终态？** 原key A，compile捕到SyntaxError时记录状态syntax_error；它是结果协议字符串，不等进程整数returncode。提取器未闭fence、运行崩溃、导入失败和结果JSON破坏分别有状态，不能全叫syntax_error或都折成正常低分。
4. **为何wall-clock timeout比denylist更关键？** 原key C说明无限循环和denylist可绕，deadline能限制部分运行。真实保护还须覆盖输出/资源/权限、全部清理与进程树；仅timeout不会阻止有限时间内破坏文件或泄露秘密。
5. **有效域n−c<k时pass@k多少？** 原key A，1，因为不通过样本不足以组成k子集，任何合法k子集都含成功。先要求整数n≥k≥1、0≤c≤n；k>n不能套源fallback充当有效估计，无样本是未知。
6. **stdout overflow怎样报告，256KB为何仍不足？** 原key C，源累计stdout超过256 KiB时kill子PID，归error/detail=`output overflow`。尾读/stderr无界及后代持pipe未受完整控制，不能称全部输出与资源已限额，更不证明沙箱安全。

#### PPL与校准六题（73）

1. **test corpus PPL=1能说明什么？** 原key B含“perfect model”需收窄：在明确有效目标集NLL=0、各目标概率1时exp(0)=1。不能外推跨任务完美，零有效token也不能算PPL1。
2. **为何adapter提供非负NLL？** 原key D，其意义是negative log-probability即−log p≥0；不是“log p非负”。传log p会出现PPL<1的错误；还要核finite、count整数、mask/window和序列总和，不能只检查负号。
3. **ECE测什么？** 原key A，按bin样本数加权的mean confidence与empirical accuracy绝对差。固定同概率事件、分箱、N与切片解释，不把ECE当准确率，也不忽略空bin/未知。
4. **为何返回populated_bins？** 原key C，它帮助观察概率区间覆盖；“非空bin少就不可信”不是普遍结论。一bin有很多同概率独立样本也可核该点，要同时看每bin count、总体N、代表性和区间。
5. **Brier补ECE什么观察？** 原key D，逐预测平方概率误差保留bin内信息，还涉及分辨能力，并非纯局部校准。ECE跨bin取绝对gap不会相抵；27.9的单bin反例ECE0/Brier.16与粗分箱分解.25可以直接核差别。
6. **为何可按model汇总校准，而不当单task分数？** 原key D意在用多个概率事件样本估bin统计量。单task若含足够同事件案例也可校准；跨异构task pool只是策略，仍保category/metric/事件切片，不能称校准只能per-model。

#### 聚合与区间六题（74）

1. **为什么要求输入[0,1]？** 原key A，避免数值尺度0–100压倒0–1。源只做range检查，不实施normalization；同范围不说明同方向/同含义可混加，PPL、ECE/Brier及权重还需独立协议。
2. **均值隐藏的什么能由胜率暴露？** 原key C，逐task是否胜出弱化某次大分差，能看到高均分却多数task输。源胜率是最高于全部在场model，不是任意pairwise胜率；缺项、候选集合与全计胜/分摊并列会改变统计量。
3. **bootstrap_mean_ci怎样估区间？** 原key B，有放回抽N个task score，B次求mean，取alpha/2及1−alpha/2分位数。非参数仍依赖独立单位、代表性与足够样本；corpus/ratio类须抽原unit并重算指标，不能只抽已平均分。
4. **pairwise差CI何时源标significant？** 原key B，两端严格在零同一侧，即lo>0或hi<0。包含零是方向证据不足，非等效证明；还需alpha、共同N、选择/多比较政策，不能任意反复看完便声称整体误报率受控。
5. **为何pairwise bootstrap成对？** 原key A，同case提供两model输出，先按身份求A−B再重采样保题难相关。不同独立组不能靠数组位置造配对；共同已评分子集与全计划失败政策分别报告，缺失理由不可删。
6. **总体分之外为何留category均值？** 原key A，总体可遮代码/安全等切片退化。每类同时保N、coverage、严重失败和预定权重，切片均分不是泛化或部署通过证明。

#### Runner六题（75）

1. **ModelAdapter最小接口是什么？** 原key C，源generate(prompt,task)返回Generation。NLL实际为序列总和而非原选项“per-token列表”；真实adapter还需请求/模型版本、严格字段/finite、case身份、timeout/usage/终态，接口签名不等可靠性。
2. **为何保parallel开关？** 原key A，串行便于按固定执行顺序检查，线程可调度I/O。源确有两条调度分支；shared RNG的Noisy不保证case级复现，测试仅证明RuleBased的分数一致，没有实测吞吐改善。
3. **校准buffer的correct如何定？** 原key A，实际EM/accuracy/code用≥.999999、其它用≥.5。这个阈值定义一个事件，并非真实业务正确；代码要依据all-tests-pass，软分事件与label/rubric、阈值版本及confidence语义必须一致。
4. **为何构造EvalRun后交聚合器？** 原key A，评分和汇总各自维护可减少重复与耦合。源EvalRun丢原generation/detail/latency和终态，须额外持久逐case账本、metric/schema身份与完整plan分母，否则无法复算或解释失败。
5. **最终PPL block角色是什么？** 原key B描述独立held-out语言建模观察，应与任务评分并列。源却用人工token_stats/空白split与mock NLL，Generation NLL未接入；不能把这些exp常数称真实held-out质量。无有效数据为null+reason，不能输出NaN冒作测量。
6. **self-terminating demo的clean-run退出标准？** 原key A是文档目标：所有任务有效/计分、校准、rule-based严格高于随机。实际源码仅非空、榜首rule_based、末尾非rule_based，没有严格分差/完整失败ledger/structured runtime error包装，且没有名为RandomAdapter的实现。exit0只说明那几条演示检查，不证明真实能力或全部质量门禁。
