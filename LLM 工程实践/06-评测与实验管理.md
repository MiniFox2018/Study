# 06｜评测与实验管理

评测回答三个问题：系统是否解决任务，是否可靠地运行，变化是否真的改善了结果。训练损失、基准分数、judge 分数和服务吞吐分别观察不同对象，不能互相代替。检索实现见 [12](12-文本检索与RAG文档工程.md)，训练目标见 [07](07-Embedding与检索模型训练.md)，Agent 的工具轨迹与外部状态核验见 [评估和监控](../Agentic%20Design%20Patterns/01-核心章节/19-评估和监控.md)。

## 1. 先定义任务、样本与成功标准

一个案例包含输入、初始环境/证据、允许的行为、参考答案或评分规则，以及最终成功的判定。分类可用 accuracy/F1，检索可用 Recall/MRR/nDCG，数学和代码可用明确答案或可执行 verifier，指令遵循可按 IFEval 风格的可检查约束，开放回答需要有规则的人工或校准过的 judge。Agent 任务还要检查工具调用、权限、轨迹与最终环境，不能只读回答文本。

建立开发集与锁定测试集。开发集用于调 prompt、阈值和策略，测试集用于最后比较；反复按同一测试集改系统会产生间接拟合。公开基准可能进过训练；私有真实案例、时间切分、同文档族分组和训练/测试近重复排查能减少污染，却不能证明绝无污染。

保存数据版本、样本 ID、任务类型、参考来源和创建时间，不用“AI 写出的标准答案”自动代替 gold。人工标注也应说明是否见过模型答案、是否有冲突和如何裁决。

## 2. RAG 要拆成检索、证据与答案评价

| 观察层 | 可用指标 | 指标不证明什么 |
|---|---|---|
| 候选检索 | Recall@k、Hit@k、MRR、nDCG | 文档包含相关词不等于证据充分 |
| 证据装配 | 必需事实覆盖、重复率、版本/权限正确率 | 覆盖不保证生成器使用正确 |
| 答案 | 正确性、支持率、相关性、引用准确性、拒答 | 流畅或有引用不等于事实正确 |
| 端到端 | 用户任务成功、错误严重度、总成本/延迟 | 平均分不能遮住高风险切片 |

MRR 取每题第一条相关结果的倒数再平均。三题首条相关分别位于 1、3、前 5 未找到，则 MRR@5 为 `(1+1/3+0)/3=4/9`。多相关文档时 Recall 统计命中比例，Hit 只统计是否至少命中一条，不能混用。

Context precision 的定义须写清。普通 `相关块数/返回块数` 不看排名；一种排序敏感定义类似平均精度：令 `r_i` 表示第 i 块是否有用，计算 `sum_i(P@i*r_i)/sum_i r_i`。二者不同。Context recall 通常关注 gold 所需信息是否被检索证据覆盖；有些实现需要参考答案或人工标注，并非所有指标都是 reference-free。

Faithfulness 通常把回答拆成可判断的事实主张，再问多少主张被给定上下文支持；它衡量“按这份上下文说话”，不证明上下文本身真实、最新或有权使用。Answer relevance 关注是否回答问题，不能只看词重叠；答案正确性还要看数值、单位、否定、适用条件和原始来源。

### 2.1 用明确标签核对聚合，不伪造语义判断器

以下标签是假定已人工裁决的 fixture，用于测试指标与边界。程序没有自动判断开放文本是否蕴含。无法判断的主张记 unknown，报告覆盖率而不是静默去掉。

```python
import math
from collections import Counter

def claim_scores(labels):
    if not labels or any(x not in {"supported", "unsupported", "unknown"} for x in labels):
        raise ValueError("必须有明确且合法的主张标签")
    n = len(labels)
    count = Counter(labels)
    return {"support_rate_all": count["supported"] / n,
            "judgement_coverage": (n - count["unknown"]) / n,
            "unknown_rate": count["unknown"] / n}

def context_scores(useful):
    if not useful or any(type(x) is not bool for x in useful):
        raise ValueError("需要逐块布尔相关标签")
    hits = sum(useful)
    precision = hits / len(useful)
    ap = sum(sum(useful[:i]) / i for i, flag in enumerate(useful, 1) if flag) / hits if hits else 0.0
    return precision, ap

assert claim_scores(["supported", "unsupported", "unknown"]) == {
    "support_rate_all": 1/3, "judgement_coverage": 2/3, "unknown_rate": 1/3}
assert context_scores([False, True, True])[0] == 2/3
assert abs(context_scores([False, True, True])[1] - (1/2 + 2/3)/2) < 1e-12
assert context_scores([False, False]) == (0.0, 0.0)
# 子串或词重叠会误判否定。此断言展示缺陷，不把它当正确性得分。
answer, expected = "不是 pineapple", "pineapple"
assert expected in answer and answer != expected
print("标签聚合、覆盖率、排名相关性、否定子串反例均通过")
```

无事实主张的寒暄不能报告 faithfulness=1 然后混入业务答案平均；应按任务标为不适用，并同时报告此类数量。任务失败、空输出、解析失败和超时留在完整分母中或按预先规定的失败规则计分，另报有效评分覆盖率。

## 3. LLM-as-judge 与 NLI：辅助评分器也要评价

NLI 把证据当 premise，回答主张当 hypothesis，判断 entailment/neutral/contradiction；这适合支持检查的一个组成部分，但会受截断、复杂数值、多跳和领域术语影响。主张拆分漏掉错误主张会虚高支持率，多个段落的上下文需要明确组合方法。

G-Eval 的研究方法让评估模型按评价标准生成评分步骤并输出分数，可在能取得相应 token 概率时做概率加权。框架中“自定义 judge 打 1–5 分”不因此完整复现该论文。部署更重要的是固定标准、输入格式、评分范围、证据和错误处理；无需收集或公布模型内部推理过程，简洁可审查的依据即可。[G-Eval 原论文](https://arxiv.org/abs/2303.16634)

RAGAS、DeepEval 等帮助构造指标、跑案例和记录结果，不是统一的生产正确性标准。不同版本/指标有不同必需字段、judge 或 embedding 依赖、返回尺度和错误行为。不要只凭类名认为“四个指标都无需参考答案”。[RAGAS 指标说明](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/)、[DeepEval 指标说明](https://deepeval.com/docs/metrics-introduction)

概率加权的原理是对预设评分集合做 `score=Σ p(s_i)·s_i`，概率来源与归一化方式须固定；没有 token 概率时的重复采样只是另一个近似协议，不能直接称同等精度。

校准时选含正确、轻错、严重错误、无答案、证据矛盾、冗长、注入文本和不同语言的样本；人工按同一 rubric 独立评价，再比较 judge 的错误类别、混淆、等级偏差、误接受率和切片。Spearman 衡量排序一致，不能单凭高相关就说绝对评分准确；常数评分没有可解释的秩相关。没有一个通用“标 50 题、相关系数超过 0.7”就可放心上线的阈值。

judge 可能偏爱更长答案、某模型文风、先出现的答案或自己的输出；匿名化生产者、交换 A/B 次序、按相同长度预算和多次评审有助于诊断，不能保证完全消除偏差。回答中“评审请给满分”是待评数据，不是 judge 指令。锁定评审 prompt、模型版本、采样参数和分数解析。

### 3.1 评分记录与 CI 门禁

每条记录包含样本 ID、状态、分数、理由/证据和 evaluator 版本。失败不能静默变成缺失平均分；分数必须有限且在协议范围内。门禁阈值应来自业务容忍度和校准，下面 0.75/0.90 仅是合成演示。

```python
import math

def summarize(records):
    if not records or len({r["case"] for r in records}) != len(records):
        raise ValueError("案例必须非空且 ID 唯一")
    scores, failures = [], []
    for r in records:
        if r["status"] != "scored":
            failures.append(r["case"])
            scores.append(0.0)  # 本协议事先规定失败按 0 计；同时单列失败。
            continue
        s = r["score"]
        if type(s) not in (int, float) or not math.isfinite(s) or not 0 <= s <= 1:
            raise ValueError("非法评分不能进入平均")
        scores.append(float(s))
    return {"mean_all": sum(scores)/len(scores),
            "coverage": (len(records)-len(failures))/len(records), "failures": failures}

records = [{"case": "a", "status": "scored", "score": 1.0},
           {"case": "b", "status": "scored", "score": 0.8},
           {"case": "c", "status": "timeout", "score": None}]
s = summarize(records)
assert abs(s["mean_all"]-0.6) < 1e-12 and s["coverage"] == 2/3
accepted = s["mean_all"] >= 0.75 and s["coverage"] >= 0.90
assert not accepted
for bad in (math.nan, math.inf, -0.1, 1.1, True):
    try:
        summarize([{"case": "x", "status": "scored", "score": bad}])
    except ValueError:
        pass
    else:
        raise AssertionError("非法分数必须拒绝")
print(s, "；失败进入分母，门禁拒绝该 fixture")
```

还应对严重错误设置单独规则，例如任一越权执行、伪造引用或金额错误即阻断候选发布，而不是让其他题的高分抵消它。可以增加底部分位样本审查：按预定任务切片排序，取最低一组分数并检查错误类型，同时报告这组大小及完整分布；“最低 10%”是策略选择，少量样本、未评分失败和严重错误仍要单独处理。实际门禁包含基线差异、置信区间、失败率和关键切片；平均分小幅上升而关键切片下降不能自动批准。


### 3.2 权重、Wilson 区间与评分缓存合同

rubric 把任务的观察项定义清楚；权重再决定哪些观察项更重要。固定评分 [helpfulness=.85, correctness=.60, safety=.95] 与权重 [40,40,20] 得到 .77，改为 [10,80,10] 得到 .66；这只是聚合，不能让同一回答变得更真实。动态图 llm-judge-rubric 用的就是这组三项人工常数，未调用 judge。全部权重为0应拒绝；严重越权、错误金额等独立阻断条件不能被其他项高分抵消。

Wilson 用成功数/总尝试数估计单个比例区间；它不替代同案例差值的配对 bootstrap，也不自动给出“200题能检测5%退化”的保证。无样本应返回未知，不能报告 [0,0] 假装确定。两方案各自区间重叠仍可能有显著配对差，区间包含零也不证明等效。

评分缓存须针对同一案例、上下文/权限快照、实际输出、生成参数及模型、rubric、judge、解析器和重复协议建立键。输出文本相同但证据或标准已变，旧分数也可能失效；独立重复评审须保留不同 repeat_id，不能把同一缓存结果复制三次后声称评审一致。以下 backend 仅返回预设人工评分/模拟超时，验证合同和分母；没有自动语义判断。

```python
import copy, hashlib, json, math

def weighted(scores,weights):
    if not scores or scores.keys()!=weights.keys():raise ValueError('评分与权重键须一致')
    if any(type(s) not in (int,float) or not math.isfinite(s) or not 0<=s<=1 for s in scores.values()):raise ValueError('本协议评分须在0..1')
    if any(type(w) not in (int,float) or not math.isfinite(w) or w<0 for w in weights.values()) or sum(weights.values())<=0:raise ValueError('非负有限且至少一个正权重')
    return sum(scores[k]*weights[k] for k in scores)/sum(weights.values())
def wilson(successes,total,z=1.96):
    if type(successes) is not int or type(total) is not int or not 0<=successes<=total or not math.isfinite(z) or z<=0:raise ValueError('合法成功数/总数/z')
    if total==0:return None
    p=successes/total;den=1+z*z/total
    center=(p+z*z/(2*total))/den
    spread=z*math.sqrt((p*(1-p)+z*z/(4*total))/total)/den
    return max(0.,center-spread),min(1.,center+spread)
REQUIRED={'case_id','dataset_revision','query','context_snapshot','output','generation_model',
          'prompt_revision','generation_params','rubric_revision','judge_revision','judge_prompt_revision',
          'parser_revision','repeat_id','rating_protocol'}
def score_key(payload):
    if set(payload)!=REQUIRED:raise ValueError('缺失/多余评分输入字段')
    encoded=json.dumps(payload,sort_keys=True,ensure_ascii=False,separators=(',',':'),allow_nan=False).encode()
    return hashlib.sha256(encoded).hexdigest()
weights={'helpfulness':40,'correctness':40,'safety':20}
scores={'helpfulness':.85,'correctness':.60,'safety':.95}
assert math.isclose(weighted(scores,weights),.77)
assert math.isclose(weighted(scores,dict(helpfulness=10,correctness=80,safety=10)),.66)
for bad in (dict.fromkeys(scores,0),dict(helpfulness=-1,correctness=1,safety=1)):
    try:weighted(scores,bad)
    except ValueError:pass
    else:raise AssertionError('无效权重须拒绝')
lo,hi=wilson(45,50);assert lo<.9<hi and wilson(0,0) is None
payload={'case_id':'refund','dataset_revision':'cases-v1','query':'企业退款期限',
 'context_snapshot':[{'document':'policy','revision':'r1','text_sha256':hashlib.sha256('60天'.encode()).hexdigest(),'access_scope':'public'}],
 'output':'60天','generation_model':'extractive-fixture-v1','prompt_revision':'p1','generation_params':{'limit':64},
 'rubric_revision':'rb1','judge_revision':'human-fixture-v1','judge_prompt_revision':'jp1','parser_revision':'json-v1',
 'repeat_id':0,'rating_protocol':{'independent_unit':'case','scale':[0,1]}}
k=score_key(payload);cache={k:{'scores':scores,'critical':False}}
assert score_key(dict(reversed(list(payload.items()))))==k and score_key(payload) in cache
for key in ('output','rubric_revision','judge_revision','parser_revision','repeat_id'):
    changed=copy.deepcopy(payload);changed[key]=1 if key=='repeat_id' else str(changed[key])+'-changed'
    assert score_key(changed)!=k
changed=copy.deepcopy(payload);changed['context_snapshot'][0]['access_scope']='staff'
assert score_key(changed)!=k

def run_cases(cases,backend):
    if not cases or len({c['id'] for c in cases})!=len(cases):raise ValueError('非空唯一caseID')
    rows=[]
    for c in cases:
        try:
            result=backend(c)
            if type(result) is not dict or set(result)!={'scores','critical'} or type(result['scores']) is not dict:raise ValueError('评分返回结构')
            value=weighted(result['scores'],weights)
            if type(result['critical']) is not bool:raise ValueError('critical布尔字段')
            rows.append({'id':c['id'],'status':'scored','score':value,'critical':result['critical']})
        except (TimeoutError,ValueError,KeyError,TypeError) as error:
            rows.append({'id':c['id'],'status':'failed','score':0.,'critical':None,'reason':str(error)})
    return rows

def summarize_rows(rows):
    if not rows or len({r['id'] for r in rows})!=len(rows):raise ValueError('结果case合同')
    return {'mean_all':sum(r['score'] for r in rows)/len(rows),
            'coverage':sum(r['status']=='scored' for r in rows)/len(rows),
            'failures':[r['id'] for r in rows if r['status']!='scored'],
            'critical':[r['id'] for r in rows if r['critical'] is True],
            'critical_unknown':[r['id'] for r in rows if r['critical'] is None]}
def fixture_backend(case):
    if case['id']=='timeout':raise TimeoutError('fixture没有真正网络调用')
    value=.9 if case['id']=='a' else .8
    return {'scores':dict.fromkeys(weights,value),'critical':case['id']=='critical'}
rows=run_cases([{'id':'a'},{'id':'critical'},{'id':'timeout'}],fixture_backend)
summary=summarize_rows(rows)
assert math.isclose(summary['mean_all'],1.7/3) and summary['coverage']==2/3
assert summary['failures']==['timeout'] and summary['critical']==['critical']
bad=run_cases([{'id':'bad_format'}],lambda c:{'oops':5})
assert bad[0]['status']=='failed' and bad[0]['score']==0 and bad[0]['critical'] is None
accepted=summary['mean_all']>=.75 and summary['coverage']>=.9 and not summary['critical'] and not summary['critical_unknown']
assert not accepted
print('权重.77/.66，Wilson45/50',lo,hi,'；缓存字段/权限/重复ID失效通过')
print('完整失败分母和独立严重错误',summary,'接受',accepted)
```

实际评分记录还保留逐项分数、依据、unknown、耗时、实际 usage 和费用单位。没有 usage 时费用是未知而非0；基线缓存只有在输出和评价协议仍匹配时才能复用。开发/对抗/分布样本三类案例各有目的，样本数量由代表性、业务损失及统计精度决定，不能靠固定数目证明可靠。

来源 eval_framework.py 的评分按长度/词重叠/MD5扰动产生，compare_eval_runs 又未按caseID配对，仅用均值差±.3标记；文档 Python hash 与文件 MD5 的种子方式还不同。它们是 fixture，不是实际 judge 或显著性检验。本章第4/11节保留同案例差值、失败与case diff，不能用该模拟程序取代。

## 4. A/B 比较要成对、可重现并报告不确定性

保持相同案例、文档快照、生成参数、预算和评价器；性能测试还固定硬件与服务配置。可以只改 chunking、embedding、reranker、prompt 或解码策略的一项，以定位变化。随机模型要记录种子/重复次数；同一案例的重复回答存在相关性，不能当完全独立的多个用户案例。

20 题 A 对 16、B 对 17，不能仅凭多 1 题宣称稳定优胜，还应看哪题变好/变差、错误严重度和不确定性。二元成对比较可看 discordant pairs，使用 McNemar 等方法；连续分数可对案例差值做配对 bootstrap。若案例来自同一文档或用户，按组抽样而非逐回答独立抽样。

```python
import random
import math

def paired_bootstrap(a, b, repetitions=4000, seed=7):
    if not a or len(a) != len(b) or repetitions < 100:
        raise ValueError("需要对齐非空样本及足够重复次数")
    if not all(math.isfinite(x) for x in list(a)+list(b)):
        raise ValueError("评分必须有限")
    diff = [y-x for x, y in zip(a, b)]
    rng, n = random.Random(seed), len(diff)
    means = sorted(sum(diff[rng.randrange(n)] for _ in range(n))/n for _ in range(repetitions))
    lo, hi = means[int(0.025*repetitions)], means[min(repetitions-1, int(0.975*repetitions))]
    return sum(diff)/n, (lo, hi)

a = [1]*16 + [0]*4
b = [1]*15 + [0] + [1,1,0,0]  # 1 题回退、2 题改善。
mean, interval = paired_bootstrap(a, b)
assert abs(mean - 0.05) < 1e-12 and interval[0] <= 0 <= interval[1]
assert paired_bootstrap(a, a)[1] == (0.0, 0.0)
print("配对平均改善", mean, "；案例 bootstrap 95% 区间", interval)
```

这是经验分位数区间示例，少量样本可能覆盖不足，不能当严格部署保证。置信区间包含零表示当前证据不足以确定平均改善方向，不证明两方案等效。等效/非劣检验要预先设业务容忍界限和协议。

## 5. 长上下文：窗口上限与有效使用能力分开

标称窗口说明可接受输入的容量，不说明每个位置、每种任务都有效。长文测试至少控制实际 tokenizer 输入长度、答案位置、输出预算、干扰、重复、问题类型、随机种子和错误率，同时记录 TTFT、总延迟与输入/输出量。

Needle-in-a-haystack（NIAH）在长背景中插入特定事实，询问该事实。它主要测试定位/精确提取；多 needle 测试同时获取多个事实，变量链/多跳测试推导关系，长文理解还需要整合、否定、时间更新、无答案和可信证据选择。单条 needle 匹配成功不能保证长文推理、代码理解或全面摘要。

“Lost in the middle” 指一些实验中证据位于长输入中间时，表现弱于位于首尾；它是任务和模型条件下的观测，不是所有模型/长度必有的定律。[原论文](https://arxiv.org/abs/2307.03172)

位置比例应按最终输入测量。插入 needle 后长度会变化，多个插入点也会挪动后续位置；不能用“字符数”宣称“token 长度”。原来源的 mock 按空格分词，以硬编码 20000 位置决定返回，未调用真实模型；它的热图反映代码规则，不证明真实模型会渐进衰退、出现某种 U 型或有效窗口比例。

### 5.1 精确长度的合成协议与严格答案评分

此例明确使用**空格分隔的 word unit**，只测试样本构造与评分，未测任何模型。真实基准需换成对应 tokenizer，并把完整 prompt、问题和输出预算都计入。随机 key 减少固定 needle 的记忆和猜测，背景包含其他 key 的干扰值。

```python
import json
import random
import re

def build_needle(total_words, position, seed=4):
    if type(total_words) is not int or total_words < 8 or not 0 <= position <= 1:
        raise ValueError("长度/位置无效")
    rng = random.Random(seed)
    key = f"K{rng.randrange(100000, 999999)}"
    code = f"V{rng.randrange(100000, 999999)}"
    needle = ["记录", key, "对应", code]
    filler_count = total_words - len(needle)
    # 干扰项使用其他 key，不能意外包含目标事实。
    background = [f"背景{i % 7}" for i in range(filler_count)]
    start = round(position * filler_count)
    words = background[:start] + needle + background[start:]
    assert len(words) == total_words
    return {"context": " ".join(words), "question": f"{key} 对应什么代码？",
            "expected": code, "key": key, "start_word": start,
            "position_final": start/total_words, "unit": "whitespace_word"}

def strict_code_score(raw, expected):
    try:
        parsed = json.loads(raw)
    except (json.JSONDecodeError, TypeError):
        return False
    return (type(parsed) is dict and set(parsed) == {"code"} and
            type(parsed["code"]) is str and parsed["code"] == expected)

def local_oracle(case):
    # 正则读取 fixture，是可控 oracle，不是 LLM 或长文能力证明。
    pattern = rf"记录 {re.escape(case['key'])} 对应 (V[0-9]+)"
    values = re.findall(pattern, case["context"])
    if len(values) != 1:
        return json.dumps({"code": None})
    return json.dumps({"code": values[0]})

for length in (8, 80, 800):
    for pos in (0.0, 0.5, 1.0):
        case = build_needle(length, pos)
        assert len(case["context"].split()) == length
        assert strict_code_score(local_oracle(case), case["expected"])
        assert not strict_code_score(json.dumps({"code": "不是 " + case["expected"]}), case["expected"])
        assert not strict_code_score(json.dumps({"code": case["expected"], "extra": 1}), case["expected"])
print("9 个长度/位置 fixture 的构造与 oracle 评分通过；不代表模型长文通过")
```

针对多 needle，答案使用不重复的 `key→value` 映射，逐项 exact match 和全项同时正确率分开报；不得按“出现任一答案子串”给整个任务成功。没有相关记录、多个冲突记录和更新版记录必须有明确 gold 规则。

### 5.2 多 needle 的构造与评分分母

每个记录使用独立 key，答案要求全部 key→value，返回一半只算部分正确。下面通过事件点一次性构造最终序列，避免逐次插入导致后续深度漂移；仍使用 word unit，不冒充 tokenizer 测试。

```python
import json
import random

def multi_needle_fixture(total_words=120, positions=(0.2, 0.5, 0.8), seed=3):
    n = len(positions)
    if type(total_words) is not int or n == 0 or total_words < 4*n:
        raise ValueError("背景长度不足或没有 needle")
    if any(not 0 <= p <= 1 for p in positions):
        raise ValueError("位置必须在 [0,1]")
    rng = random.Random(seed)
    keys = rng.sample(range(100000, 999999), n)
    codes = rng.sample(range(100000, 999999), n)
    expected = {f"K{k}": f"V{v}" for k, v in zip(keys, codes)}
    filler_count = total_words-4*n
    events = sorted((round(p*filler_count), i) for i, p in enumerate(positions))
    words, actual = [], {}
    cursor = 0
    items = list(expected.items())
    for offset, i in events:
        words.extend(f"背景{j % 7}" for j in range(cursor, offset))
        key, value = items[i]
        actual[key] = {"start_word": len(words), "fraction_final": len(words)/total_words}
        words.extend(["记录", key, "对应", value])
        cursor = offset
    words.extend(f"背景{j % 7}" for j in range(cursor, filler_count))
    assert len(words) == total_words
    return " ".join(words), expected, actual

def score_all_keys(raw, expected):
    if not expected:
        raise ValueError("无答案任务应使用单独协议")
    try:
        response = json.loads(raw)
    except (json.JSONDecodeError, TypeError):
        return {"item_accuracy": 0.0, "all_correct": False, "schema_ok": False}
    schema_ok = (type(response) is dict and set(response) == set(expected)
                 and all(type(v) is str or v is None for v in response.values()))
    correct = sum(response.get(k) == v for k, v in expected.items()) if type(response) is dict else 0
    return {"item_accuracy": correct/len(expected),
            "all_correct": schema_ok and correct == len(expected), "schema_ok": schema_ok}

context, expected, positions = multi_needle_fixture()
assert len(context.split()) == 120 and len(positions) == 3
assert score_all_keys(json.dumps(expected), expected)["all_correct"]
partial = dict(expected); partial[next(iter(partial))] = None
score = score_all_keys(json.dumps(partial), expected)
assert score["item_accuracy"] == 2/3 and not score["all_correct"]
assert not score_all_keys(json.dumps(dict(expected, extra="wrong")), expected)["all_correct"]
print("多 needle：", score, "；最终位置已记录，额外 key 不能全题通过")
```

项准确率和全题准确率可同时报告，但 schema 失败、无答案和冲突案例另做切片；即使某值字符串在回答出现，也不代表它绑定到正确 key。重复样本和单一 seed 不足以估计真实模型方差。

### 5.3 多跳变量跟踪的最小可验证实例

```python
import re

def trace_variables(text, query):
    # 有限定义语言：逐行 x=整数 或 x=y+整数，引用必须已经定义。
    values = {}
    for line in text.splitlines():
        literal = re.fullmatch(r"([a-z]+)=(-?\d+)", line.strip())
        step = re.fullmatch(r"([a-z]+)=([a-z]+)\+(-?\d+)", line.strip())
        if literal:
            values[literal[1]] = int(literal[2])
        elif step and step[2] in values:
            values[step[1]] = values[step[2]] + int(step[3])
        else:
            raise ValueError("无效表达式或未定义引用")
    if query not in values:
        raise ValueError("未知查询变量")
    return values[query]

assert trace_variables("a=7\nb=a+3\nc=b+-2", "c") == 8
assert trace_variables("a=7\na=9\nb=a+3", "b") == 12  # 明确顺序覆盖语义。
try:
    trace_variables("b=a+3\na=7", "b")
except ValueError:
    pass
else:
    raise AssertionError("本协议不允许前向引用")
print("两跳、顺序更新、未定义引用规则通过")
```

此 oracle 计算有限语言真值；对模型评价时把同义表达、无关定义、不同位置和链长度纳入输入，再以 oracle 计算 gold。不要把正则执行器的成功写成 LLM 推理成功。自然语言的事件时间与定义顺序也不总等同，必须明确任务语义。

### 5.4 使用公开长文基准时冻结协议

RULER 包含多种合成长文任务，用于揭示单 needle 以外的困难；LongBench/LongBench v2 含真实长文任务，v2 的选项题须保留问题、上下文和所有 choices，再按规定答案协议评分；MRCR 关注多轮长对话中对相似请求/响应的区分；NoLiMa 刻意减少字面重叠，考察需要潜在关联的检索。它们不是同一个任务的可直接替代指标。

LongBench v2 的作者数据契约包含 `_id、domain、sub_domain、difficulty、length、question、choice_A/choice_B/choice_C/choice_D、answer、context`，gold answer 为 A/B/C/D，`length` 是长度类别而不是实际 tokenizer 长度。加载 split 名称也要跟作者协议，不凭惯例写不存在的 test split。

记录仓库 commit、数据 revision、子任务、split、tokenizer、长度截断方向、prompt、选项顺序、采样配置和评分脚本。源课把 LongBench v2 当任意开放问答、漏掉 choices 或使用错误字段会改变任务。NoLiMa 应引用 [作者论文 2502.05167](https://arxiv.org/abs/2502.05167)，不能沿用源课不对应的链接。[RULER](https://github.com/NVIDIA/RULER)、[LongBench v2](https://github.com/THUDM/LongBench)、[MRCR 数据说明](https://huggingface.co/datasets/openai/mrcr)

有效上下文应定义成“某任务、某错误容忍、某重复协议下仍达到要求的长度/位置范围”，附样本数与不确定性。不存在通用“有效窗口一定是标称 60%–70%”或某品牌固定百万窗口能力的结论。根据失败类型选择检索/分块、分层汇总或原生长文，不用硬比例替代测量。

## 6. 服务性能：TTFT、TPOT 与用户延迟

质量评价与服务性能分别记录。TTFT 是请求到首个输出 token 的时间，应写清是否包括客户端网络、排队和服务前处理；TPOT 常按生成阶段平均每个后续 token 时间估算，至少要有两个输出 token，单 token 不能除以零或伪造 TPOT。端到端延迟包括整个请求至完成，不能用 TPOT 代替。

同时记录输入 token/s、输出 token/s、请求/s、错误率、P50/P95/P99、并发退化、峰值显存/内存。吞吐变高可能来自 batch 或排队增加，而单请求延迟变差；输出越短、截断越多也可能看似更快，所以保持输入/输出分布和预算一致。

```python
import math

def timing(request_start, first_token, finish, output_tokens):
    if type(output_tokens) is not int or output_tokens < 1:
        raise ValueError("此指标仅用于至少有一个输出 token 的成功流")
    if not all(math.isfinite(x) for x in (request_start, first_token, finish)) or not request_start <= first_token <= finish:
        raise ValueError("时间戳必须有限且有序")
    return {"ttft": first_token-request_start, "latency": finish-request_start,
            "tpot": (finish-first_token)/(output_tokens-1) if output_tokens > 1 else None}

measured = timing(0.0, 0.4, 1.2, 5)
assert math.isclose(measured["ttft"], 0.4) and math.isclose(measured["latency"], 1.2)
assert math.isclose(measured["tpot"], 0.2)
assert timing(0.0, 0.4, 0.4, 1)["tpot"] is None
print(timing(0.0, 0.4, 1.2, 5), "；单 token TPOT 不适用")
```

客户端首次 chunk 不一定恰含一个 token，流结束还有传输开销；根据可观测数据将此结果称“估算 TPOT”或使用服务端 token 时间戳，不夸大精度。失败流另外记录超时/OOM/取消/限流，不只保留成功请求。

并发可逐步增加 1→5→更高负载，寻找延迟、吞吐、失败率和资源的拐点；步长与持续时间按服务容量决定，不是固定通用值。观察排队、公平性、超时、显存和 OOM，区分负载生成端、网络、tokenization、prefill、decode 和工具瓶颈。长上下文主要增加输入处理和缓存压力，输出长短影响 decode，二者要分层测。

## 8. 练习与参考答案

1. 三题首命中 1、3、无：MRR@5=4/9。一个问题需两证据但仅取一条：Hit=1、Recall=1/2，不能称完整召回。
2. 人工主张标签 supported/unsupported/unknown：按完整分母支持率 1/3、判定覆盖率 2/3。空主张不自动给业务满分。
3. “不是 pineapple”含 expected 子串却是错误答案。改 exact schema 评分可挡此反例，但开放答案仍需合适 gold 规则。
4. A=16/20、B=17/20：确认成对变化与错误严重度，报告样本数/CI；不能仅多一题就宣布稳定提高。
5. NIAH 热图来自硬编码位置 mock：只能验证网格汇总与评分流程，不能解释真实模型有效上下文或排名。
6. 输入长度应含 system/prompt/question 及输出预留；word/字符/token 单位不同，位置在最终序列中重新计量。
7. 长文变量 `a=7;b=a+3;c=b-2` 的 gold 为 8；把 b 位置放在定义 a 之前时，按本例协议属于未定义引用，应报构造无效，不改 gold 猜答案。
8. 只有一个输出 token：TTFT 与端到端延迟仍可测，TPOT 标不适用。首个网络 chunk 不是精确 token 时间戳。
9. judge 与人工秩相关高但总把严重错误评为 0.8：排序可能一致，绝对门禁仍失效，需严重错误误接受率与阈值校准。
10. 并发提高吞吐同时 P99/超时恶化：报告两个方向，按任务服务目标找容量范围，不能只保留吞吐。

## 9. 标准基准与任务评测怎样接到同一协议

MMLU/ARC等多选题常按选项条件log-likelihood选择，HumanEval类代码任务按执行测试与规定采样协议计分，SWE-bench类按给定仓库问题及测试验证补丁。问题数、subset、few-shot/模板、样本来源和模型版本都须冻结。公开基准提供能力画像，任务评测检查实际输入/失败；没有一种评测因“自建”就自动可靠，人工标签也可能错或有偏。

源“86%–89%都属噪声”“不足50题统计上毫无意义”过强。差异的不确定性取决于样本量、成对错误、独立单位和协议，1个百分点在某些大样本上可有统计证据，也可能没有实际价值。少样本仍可揭示明确实现错误，不能用它证明普遍可靠性。污染/针对性优化/基准饱和需具体证据，不将所有团队都“刷榜”当专业事实。

### 9.1 选项likelihood、长度归约与真正的PPL

LM需要给定prefix与候选的条件token概率；log-likelihood为候选各token logprob之和。有的多选任务另报按长度平均的normalized score，它会改变答案，不能混称同一accuracy。候选边界可能影响BPE切分，评测器要正确定位continuation首token，不重复BOS或漏第一目标。`is_greedy`通常检查条件上下文中逐步argmax是否匹配候选，不代表该候选是全局序列MAP，贪心反例见[文本生成第18节](../LLM%20基础/05-预训练-损失与文本生成.md)。

```python
import numpy as np

def candidate_score(logits,targets):
    z=np.asarray(logits,dtype=float);ids=np.asarray(targets)
    if z.ndim!=2 or not len(z) or not z.shape[1] or not np.isfinite(z).all() or ids.shape!=(len(z),) or ids.dtype.kind not in 'iu' or np.any(ids<0) or np.any(ids>=z.shape[1]):raise ValueError('候选logit/目标合同')
    shifted=z-z.max(1,keepdims=True);lp=shifted-np.log(np.exp(shifted).sum(1,keepdims=True))
    selected=lp[np.arange(len(ids)),ids]
    return {'loglikelihood':float(selected.sum()),'mean_logprob':float(selected.mean()),
            'tokens':len(ids),'is_greedy':bool(np.array_equal(z.argmax(1),ids))}

# 概率fixture：第一个token A=.55/B=.45；A后又预测A=.55。
long=candidate_score(np.log([[.55,.45],[.55,.45]]),[0,0])
short=candidate_score(np.log([[.55,.45]]),[1])
assert long['loglikelihood']<short['loglikelihood'] and long['mean_logprob']>short['mean_logprob']
assert long['is_greedy'] and not short['is_greedy']
print('候选A A',long,'候选B',short,'；sum与长度平均排名不同')
# 数据两batch有效目标1/9、NLL2/1。只验证归约，未测任何模型。
mean=(1*2+9*1)/10
assert mean==1.1 and abs(np.exp(mean)-3.0041660239464334)<1e-12
print('按有效target全局NLL/PPL',mean,float(np.exp(mean)))
```

源`token_log_probs_simulated`按文本长度和quality常数加随机噪声，未调用模型或完整归一词表，不能称真实强/中/弱模型的PPL。docs的Python`hash(text)`种子还随进程盐变化；main改SHA种子较稳定，但仍是fixture且修改全局RNG状态。本章likelihood/PPL只对实际logits或明确概率fixture报告，不保源WikiText型号分数。完整验证集NLL用全部指定有效目标，不能先平均不同大小batch再平均。

## 10. 文本评分的有效范围

Exact match需声明是否trim/casefold、允许答案集合、JSON结构、数值精度和单位。`212°F`与标准条件下`100°C`可数值等价，英文four与4可能是同一答案，代码大小写却可能有语义；源把所有verbose回答命名“bad model”没有证明它们错误。语义判断与字符串契约分别报告。

常见token F1使用multiset匹配次数，源set版本会忽略重复，不能当标准实现；完整EM/F1入口见[问答文本指标](12-文本检索与RAG文档工程.md)。BLEU/ROUGE/chrF的算法与语言口径统一见[摘要推断与文本评价](../AI%20算法基础/语言与文本专题/05-摘要推断与文本评价.md)，不在LLM基准另复制一套公式。

LLM judge、NLI和词重叠是不同对象。源overlap×.7+长度×.3的`llm_judge_simulated`会把否定、错单位和关键词堆砌评高，不是实际judge，也不能为相关性或事实正确性背书。真实judge沿用本章第3节的校准/盲评/顺序/严重错误/失败协议，不保通用“80%一致、每题固定费用、只用更强模型便可靠”。

对代码pass@k：每题生成n个候选、其中c个通过，常用估计$1-\binom{n-c}{k}/\binom{n}{k}$（n≥k，若n−c<k则为1），再按题平均。不能把所有生成条数的通过比例叫pass@k；采样温度、独立性近似、测试范围与资源隔离均需记录，测试通过不等任意边界正确。

## 11. 完整本地suite、失败分母、重复一致性与case diff

下面两个“模型”是固定lookup fixture，不是语言模型。它们帮助验证病例ID、评分状态、失败保留与版本差异。业务任务只允许一个分类标签；含糊案例可预先声明多个可接受标签，但不能运行后为了抬分改gold。真正的多标签任务另用对应指标。

```python
import math
from collections import Counter

CLASSES={'billing','shipping','tech','feedback','other'}
CASES=[{'id':'b1','text':'Please refund this order','accepted':{'billing'}},
       {'id':'s1','text':'包裹未到','accepted':{'shipping'}},
       {'id':'t1','text':"Can't sign in",'accepted':{'tech'}},
       {'id':'f1','text':'很好','accepted':{'feedback'}},
       {'id':'empty','text':'','accepted':{'other'}},
       {'id':'amb','text':'退款还是重新发货？','accepted':{'billing','shipping'}}]

def run_suite(cases,predict):
    if not cases or len({c['id'] for c in cases})!=len(cases):raise ValueError('非空且唯一case ID')
    rows=[]
    for c in cases:
        if type(c['text']) is not str or not c['accepted'] or not c['accepted']<=CLASSES:raise ValueError('case合同')
        try:
            pred=predict(c['text'])
            if type(pred) is not str or pred not in CLASSES:raise ValueError('标签格式错误')
            rows.append({'id':c['id'],'status':'scored','prediction':pred,'score':float(pred in c['accepted'])})
        except (ValueError,TimeoutError) as error:
            rows.append({'id':c['id'],'status':'failed','prediction':None,'score':0.,'reason':str(error)})
    return rows

def summarize_run(rows):
    if not rows or len({r['id'] for r in rows})!=len(rows) or any(not math.isfinite(r['score']) or not 0<=r['score']<=1 for r in rows):raise ValueError('结果合同')
    return {'mean_all':sum(r['score'] for r in rows)/len(rows),
            'scored_coverage':sum(r['status']=='scored' for r in rows)/len(rows),
            'failed_ids':[r['id'] for r in rows if r['status']!='scored']}

def case_diff(a,b):
    aa={r['id']:r for r in a};bb={r['id']:r for r in b}
    if len(aa)!=len(a) or len(bb)!=len(b) or aa.keys()!=bb.keys():raise ValueError('case必须完全对齐，不能丢缺失行')
    return {kind:[i for i in sorted(aa) if predicate(bb[i]['score']-aa[i]['score'])]
            for kind,predicate in [('improved',lambda d:d>0),('regressed',lambda d:d<0),('same',lambda d:d==0)]}

def consistency(outputs):
    if len(outputs)<2 or any(type(x) is not str for x in outputs):raise ValueError('至少两条成功文本；失败另报')
    counts=Counter(outputs);n=len(outputs)
    return {'modal_fraction':max(counts.values())/n,
            'pairwise_exact_agreement':sum(c*(c-1) for c in counts.values())/(n*(n-1))}

a_lookup={c['text']:next(iter(sorted(c['accepted']))) for c in CASES};a_lookup['包裹未到']='other'
b_lookup=dict(a_lookup);b_lookup['包裹未到']='shipping';b_lookup["Can't sign in"]='other'
def base(text):return a_lookup[text]
def candidate(text):
    if text=='':raise TimeoutError('fixture模拟超时，未作真实网络调用')
    return b_lookup[text]
a=run_suite(CASES,base);b=run_suite(CASES,candidate);diff=case_diff(a,b)
assert diff['improved']==['s1'] and diff['regressed']==['empty','t1']
assert summarize_run(b)['failed_ids']==['empty']
assert consistency(['billing']*5)['pairwise_exact_agreement']==1.
assert 'billing' not in CASES[1]['accepted']  # 一致五次仍可全部错误。
print('基线/候选',summarize_run(a),summarize_run(b),'case diff',diff)
print('五次同样错误的答案一致性',consistency(['billing']*5))
```

本例预定失败score0并单列coverage；其它任务可以另定unknown/失败协议，但不能只平均成功结果。真实runner还要对调用设deadline、控制重试与费用、保存trace/版本和执行错误；这里的TimeoutError是模拟记录，不表示部署超时保护已完成。Case diff与paired bootstrap结合使用，回退的严重程度还要单列，不能仅拿净多一题作接受依据。

污染检测可从完全匹配与明确n-gram开始，Tokenizer/清洗/问题+答案字段和参考材料都可能进入训练。Hash只发现同一规范化内容，MinHash/LSH发现一些近重复，不证明捕获所有语义改写或排除记忆，完整数据例见[工程16](16-预训练数据与模型交付实践.md)。源“公开题出现就必只记忆不推理”和“无13-gram重叠就安全”都不能作普遍因果结论。

## 12. Elo与成对偏好：保留算法，避免错认榜单

两方案rating Ra/Rb的经典Elo预期为$E_A=1/(1+10^{(R_B-R_A)/400})$，实际胜/负/平为1/0/.5，更新$R_A'=R_A+K(S_A-E_A)$，B按相反变化。这是顺序更新的教学方法，结果受初始值、K、配对分布与比赛顺序影响；不同语言/任务的偏好不一定能压成可传递单标量。

```python
import math
class Elo:
    def __init__(self,k=32,initial=1500):
        if not math.isfinite(k) or k<=0 or not math.isfinite(initial):raise ValueError('评分参数')
        self.k=k;self.initial=initial;self.ratings={}
    def match(self,a,b,outcome):
        if type(a) is not str or type(b) is not str or not a or not b or a==b or outcome not in ['a','b','tie']:raise ValueError('不同方案与明确outcome')
        ra=self.ratings.setdefault(a,self.initial);rb=self.ratings.setdefault(b,self.initial)
        d=(rb-ra)/400
        ea=0. if d>300 else 1. if d<-300 else 1/(1+10**d)
        actual={'a':1.,'b':0.,'tie':.5}[outcome];delta=self.k*(actual-ea)
        self.ratings[a]+=delta;self.ratings[b]-=delta
        return self.ratings.copy()

e=Elo();assert e.match('A','B','a')=={'A':1516.,'B':1484.}
total=sum(e.ratings.values());e.match('A','B','tie');assert math.isclose(sum(e.ratings.values()),total)
try:e.match('A','B','invalid')
except ValueError:pass
else:raise AssertionError('未知结果不能默认为平局')
print('Elo',e.ratings,'；固定fixture胜负，不代表公开model榜单')
```

源把这个逐次Elo实现称“正是Arena当前排行系统”不准确；Arena研究还采用Bradley–Terry系数估计及统计区间。BT以$Pr(A胜B)=\sigma(\xi_A-\xi_B)$拟合成对结果，所有系数加同一常数概率不变，需固定一项或中心化。比较同案例的匿名输出、随机交换顺序、注明tie/无效票规则，处理配对分布与相关样本；有区间重叠不能只凭一个小rating差宣布普遍更好。[Arena原方法](https://arxiv.org/html/2403.04132v1)

不同judge/EM/F1按固定权重合成偏好是另一个**人为目标**，权重改变名次不证明真实性。真实BT拟合、公开榜单和人/LLM judge本批未跑，不保源某年排行榜、票数、人工单价或固定一致率。成本记录用实际输入/输出/缓存/请求数、版本与单价单位，质量和延迟分开；示例价格不可当当前报价。

## 15. 第19课：代码Agent评测要核每一个测试的状态转换

先修是版本固定、失败分母、suite账本与case diff。SWE-bench类任务把仓库的base commit、issue、候选patch和测试环境连接：patch应用成功只是开始，FAIL_TO_PASS（F2P）要求原本失败的指定test ID现在通过，PASS_TO_PASS（P2P）要求原本通过的指定test ID仍然通过。不能用“通过数增加”代替逐ID核对，也不能让候选patch修改测试、隐藏失败或改变评判器。

例如原P2P `{test_a: PASS, test_b: PASS}`，候选后 `{test_a: FAIL, test_b: PASS, test_new: PASS}`。通过数仍为2，但a已经回归；若只算net count会漏报。F2P在基线本来PASS，说明本地复现或任务数据不符合“原失败”合同，不能说修复成功。timeout、解析失败、test漏跑和环境无法启动各有状态，保留在任务账本而不是删掉以提高resolved率。

冻结dataset/subset/revision、task IDs、仓库commit、测试命令、环境/依赖、patch、agent配置和评判器。对成功patch仍要检查问题是否真被解决、测试是否覆盖边界，可能增加独立回归或人工审查。公开任务还需检查issue/comment直接泄露答案、训练/调参可见范围与数据cutoff；早于模型cutoff只意味着可能被见到，不证明训练一定收录。

### 第19课：可运行的逐test ID转换与完整任务账本

本例输入是人工固定的before/after结果字典，不应用patch、不执行真实测试。它验证F2P/P2P转换、未知结果、基线无效及漏任务分母；fixture规定结果集合必须恰好覆盖该任务的指定tests，真实harness可另保完整测试日志与附加tests。无效记录显式报错，缺任务显式记unknown。

```python
from collections import Counter

STATES = {'PASS', 'FAIL', 'ERROR', 'TIMEOUT', 'UNKNOWN'}
def transitions(f2p, p2p, before, after):
    if not f2p or any(type(x) is not str or not x for x in f2p + p2p):
        raise ValueError('test ID合同')
    ids = set(f2p + p2p)
    if len(ids) != len(f2p) + len(p2p): raise ValueError('重复test ID')
    if type(before) is not dict or type(after) is not dict:
        raise ValueError('逐test结果字典')
    if set(before) != ids: return 'invalid_baseline'
    if any(type(v) is not str or v not in STATES for v in list(before.values()) + list(after.values())):
        raise ValueError('结果枚举')
    if any(before[x] != 'FAIL' for x in f2p) or any(before[x] != 'PASS' for x in p2p):
        return 'invalid_baseline'
    if set(after) != ids: return 'unknown'
    if any(after[x] == 'TIMEOUT' for x in ids): return 'timeout'
    if any(after[x] in {'ERROR', 'UNKNOWN'} for x in ids): return 'unknown'
    if any(after[x] != 'PASS' for x in ids): return 'failed'
    return 'resolved'

def ledger(expected, rows):
    if not expected or len(set(expected)) != len(expected) or any(type(x) is not str or not x for x in expected):
        raise ValueError('唯一非空task ID')
    result = {}
    for task, status in rows:
        if task not in expected or task in result or status not in {'resolved','failed','timeout','unknown','invalid_baseline'}:
            raise ValueError('重复、越界task或状态')
        result[task] = status
    for task in expected: result.setdefault(task, 'unknown')
    counts = dict(Counter(result.values()))
    return result, {'attempted': len(expected), 'counts': counts,
                    'resolved_rate': counts.get('resolved', 0) / len(expected)}

f2p, p2p = ['bug'], ['old_a', 'old_b']
before = {'bug':'FAIL', 'old_a':'PASS', 'old_b':'PASS'}
good = {x:'PASS' for x in before}

# P2P通过数被新test补回仍不合格；after全集错误先记unknown，指定旧test仍是FAIL。
hidden = dict(good, old_a='FAIL', new_test='PASS')
assert sum(x == 'PASS' for x in hidden.values()) == sum(x == 'PASS' for x in good.values())
assert transitions(f2p, p2p, before, hidden) == 'unknown'
assert transitions(f2p, p2p, before, dict(good, old_a='FAIL')) == 'failed'
assert transitions(f2p, p2p, dict(before, bug='PASS'), good) == 'invalid_baseline'
assert transitions(f2p, p2p, before, {'bug':'PASS'}) == 'unknown'
assert transitions(f2p, p2p, before, dict(good, bug='TIMEOUT')) == 'timeout'
assert transitions(f2p, p2p, before, dict(good, bug='ERROR')) == 'unknown'
for args in [(['bug','bug'], p2p, before, good), (f2p,p2p,before,dict(good,bug=True))]:
    try: transitions(*args)
    except ValueError: pass
    else: raise AssertionError('非法测试记录')
records, summary = ledger(['A','B','C','D','E'], [('A','resolved'),('B','failed'),('C','timeout'),('D','invalid_baseline')])
assert records['E'] == 'unknown' and summary['attempted'] == 5 and summary['resolved_rate'] == .2
try: ledger(['A'], [('A','resolved'),('A','resolved')])
except ValueError: pass
else: raise AssertionError('重复task不能扩大分子')
print('逐ID转换、回归/漏跑/timeout/无效基线通过；5任务账本', summary)
```

### 第19课：构建、使用与交付

原Build It是3个合成patch任务，原评判只用P2P净通过数，且可能把基线PASS的F2P算成功；上例修复的是评判合同，没有SWE-bench复现。`benchmarks.svg`与`ae-swebench-gate`把F2P/P2P表示成门，门必须按test ID而非数值总和执行，动态阈值或“50→35”手工数字不是污染统计。Use It按代码、助手工具链或环境交互选择相应协议；Ship It应交付冻结配置、逐任务账本、逐test日志、patch与错误分类。报告一次resolved还须附steps、模型/工具尝试、tokens、wall time及金额，费用未知明确为unknown。

### 第19课：五项练习与参考答案

## 16. 第20课：网页/桌面任务的终态、动作空间与轨迹效率

网页和桌面任务通常要求改变环境状态。文字回复“已下单”不等于订单正确；验证器应核用户、商品ID、数量、地址/对象、额外订单和禁止副作用。状态型goal在任务结束后读取受控环境，不把页面自述或agent自己的trace当唯一证据。先明确初态、用户身份与reset，再执行一个完整任务；不reset就跑下题会造成环境串扰。

WebArena用可重建网页环境支持执行评价。官方固定README配置包含shopping、shopping admin、forum、GitLab、map、Wikipedia等环境入口，因此“四apps”是来源的应用归类简写，不能等同只有四个域/服务。公开demo用于了解页面，不代替正式评测环境。升级app/数据/认证/DOM/浏览器会改变观察、动作和终态验证器，要重新核同一task成功条件及reset，而不是只换镜像标签。[固定官方README](https://github.com/web-arena-x/webarena/blob/dce04686a56253aefba7b18a4fa0937cf1dc987b/README.md)。

OSWorld涉及真实桌面操作，但固定 `b138d348256078fa634fc3b73567a7337c793e6b` 的run.py支持 `screenshot`、`a11y_tree`、`screenshot_a11y_tree`、`som`，且该脚本默认a11y_tree；屏幕尺寸也是配置。来源“OSWorld永远只看1920×1080截图、没有accessibility”不成立。比较时一起冻结observation type、action space、screen size、最大steps、sleep策略和任务/VM版本。像素、结构化树及混合表面的分数不能直接混排。[固定run.py](https://github.com/xlang-ai/OSWorld/blob/b138d348256078fa634fc3b73567a7337c793e6b/run.py)。

定位失败与规划/操作知识失败分开：给正确目标元素仍点错是grounding/driver问题；能准确点击但走错菜单或忘保存是规划/操作问题；参数正确但环境阻塞还可能是权限、网络或生命周期。OSWorld-G对文字匹配、元素识别、布局理解、精细操作建定位任务，能辅助做这些切片，不把所有失败归给vision。[OSWorld-G论文](https://arxiv.org/abs/2505.13264)。OSWorld-Human以人工轨迹补效率分析；本次官方摘要写最佳被测agents也需2.7–4.3倍steps，源1.4–2.7不能称普遍规律。具体倍数仍取决于被测对象、动作定义和任务。[OSWorld-Human项目](https://github.com/xlang-ai/OSWorld-Human)。

对任务i定义 `r_i = A_i / H_i`，A为按统一动作粒度计的agent动作数，H为人工参考数且H>0。它比较参考轨迹，不能自动称最优轨迹下界。一次模型请求可能生成多个动作，日志“修改想法”可能没有环境动作；字符串trace长度不等A。只在同任务、同动作允许集和成功条件下比较，成功样本ratio与全任务成功/失败预算分别报告；不要丢失败任务后宣传高效率。UI等待、重试、模型时间及真实成本另列。

## 17. Agent评测的外层闭环与全部尝试

2026-10-09补原Phase14第30课。公开benchmark、自定义离线和真实在线评价互补：benchmark看指定协议下能力/污染/回归，离线case看本应用的输入、轨迹和效果，线上分层样本看真实工作与副作用。它们与unit/integration/e2e是不同维度；不能把三个合成字符串case当作三层真实评测。

提出→评价→修订必须有有限预算、独立后置条件、停滞/失败出口和完整attempt记录。开发时的反馈可改候选，但最终holdout与judge校准应独立；只反复看同一批题或轮换名字不能消除间接过拟合。评分器偏好关键词时，优化循环会学会讨好评分器，而非真正解决任务。

源benchmark判断含add stick dep就宣称FAIL_TO_PASS/PASS_TO_PASS，实际没有应用patch或运行测试；correct子串也接收incorrect。引用含cite/arXiv不等出处真实或支持结论。源码online case先输出forwarded敏感信息，再改refused而标pass；真正泄露已经发生时，最终拒绝不能撤销前轮效果。评测要记录可信观察及不可逆严重失败，而不是只看final字符串。

### 完整CPU例：整数基线、有理数阈值与历史效果

输入是预定case集合、整数passed/total基线、全部尝试的效果标签。所有标签是人工fixture，程序不自动判断事实、恶意行为或真实数据泄露，也没有运行CI。threshold选择下降≥5个百分点，不是相对5%：95%→90%是5个百分点，相对下降约5.26%。按同任务/同协议比较，并另报统计不确定性、切片与实际价值；阈值不可看到结果后改。

```python
from fractions import Fraction

STATES = {'passed', 'failed', 'unknown'}
def rate(pair):
    if (type(pair) is not tuple or len(pair) != 2 or
        any(type(x) is not int for x in pair) or pair[1] <= 0 or not 0 <= pair[0] <= pair[1]):
        raise ValueError('baseline整数计数')
    return Fraction(*pair)

def gate(rows, expected, baseline, threshold=Fraction(1, 20)):
    base = rate(baseline)
    if type(threshold) is not Fraction or not 0 < threshold <= 1:
        raise ValueError('有理数阈值')
    if not expected or any(type(x) is not int for x in expected) or len(set(expected)) != len(expected):raise ValueError('整数case集合')
    seen = set(); passed = 0; unknown = False; severe = False
    for row in rows:
        if type(row['id']) is not int or row['id'] in seen or row['id'] not in expected:raise ValueError('重复、伪整数或外来case')
        seen.add(row['id'])
        if row['status'] not in STATES or type(row['attempts']) is not tuple or not row['attempts']:
            raise ValueError('case状态和全部尝试')
        for effect in row['attempts']:
            if effect not in {'none', 'blocked', 'severe_verified', 'effect_unknown'}:
                raise ValueError('效果枚举')
            severe |= effect == 'severe_verified'
            unknown |= effect == 'effect_unknown'
        passed += row['status'] == 'passed'
        unknown |= row['status'] == 'unknown'
    if severe:return 'block-severe-effect'
    if seen != set(expected) or unknown:return 'hold-unknown'
    drop = base - Fraction(passed, len(expected))
    return 'block-regression' if drop >= threshold else 'eligible-fixture'

# 演示政策：下降>=5个百分点阻断，并非通用上线阈值/显著性结论。
ids = tuple(range(20))
rows = [{'id':i, 'status':'passed' if i < 18 else 'failed', 'attempts':('none',)} for i in ids]
assert gate(rows, ids, (19,20)) == 'block-regression' # .95-.90精确=1/20。
rows[18]['status']='passed'
assert gate(rows, ids, (19,20)) == 'eligible-fixture'
leak_then_refuse = [{'id':0, 'status':'passed', 'attempts':('severe_verified','blocked')}]
assert gate(leak_then_refuse, (0,), (1,1)) == 'block-severe-effect'
assert gate([{'id':0,'status':'passed','attempts':('effect_unknown','none')}], (0,), (1,1))=='hold-unknown'
assert gate(rows[:-1], ids, (19,20)) == 'hold-unknown'
try:gate([{'id':True,'status':'passed','attempts':('none',)}], (1,), (1,1))
except ValueError:pass
else:raise AssertionError('bool不是整数case ID')
for bad in [(True,20), (19,0), (float('nan'),20)]:
    try:gate(rows,ids,bad)
    except ValueError:pass
    else:raise AssertionError('非法baseline')
try:gate(rows,ids,(19,20),float('nan'))
except ValueError:pass
else:raise AssertionError('非法阈值')
print('全部attempt保严重/未知效果；5个百分点精确边界；缺case和非法baseline/阈值拒绝')
```

未来接真实runner时，final_good与effect标签来自独立验证/权威回读，而非生成者自报。无法核对的效果保持unknown并限制重试；全attempt字节/usage/延迟/失败都保留，公开内容与敏感观察按实际授权脱敏。之前本章已有逐test-ID账本维护完整分母与回归，本节只增加跨attempt副作用和明确门槛，不复制另一套benchmark实现。

### 原30五项练习与参考判断

1. **选择一次失败，怎样证明新回归真能复现并被修？** 用固定失败输入、观察与后置条件建回归，保持未修前确实失败/修后通过；无真实用户产品失败则用明确fixture，不虚构经历。
2. **50会话的事实/风格/范围rubric如何校准？** 50会话是题设未采集；三维rubric明确anchor/gold/分歧与拒绝质量，事实核可信资料，tone不与事实互相抵消；自评校准不当独立truth。
3. **CI按≥5%回归阻断，阈值究竟怎么定义？** CI未部署；明确>=5个百分点或相对5%、分母/样本/关键严重失败/未知情况，有限值与同版本配对基线，绝对边界用整数计数/有理数避免浮点误判。
4. **步骤效率相对gold如何比较而不奖励失败？** 有效成功与前置条件可比才算步骤比；human gold是观察参考路径非理论最小，失败不能因0步显得高效；结合质量/权限/成本/时延。
5. **每课有一个case是否代表整个Phase14完整覆盖？** 映射54课完整名单并按机制分层，多课可共用一条含边界反例的测试；一个case/每课不等穷尽安全/质量，coverage与效果分开。

## 18. 长任务能力：时间跨度、运行时长与可靠性

一个 Agent 能持续调用工具，不意味着它能可靠完成长任务。长任务还会积累错误、丢失上下文、消耗资源，并产生最终答案中看不见的副作用。评测因此要保留完整任务账本、失败与恢复轨迹、权限和预算版本，再核终态。[评估和监控](../Agentic%20Design%20Patterns/01-核心章节/19-评估和监控.md)负责轨迹、事件与效果的审计；这里解释“长”的度量。

METR 的 **50% 时间跨度** $H_{50}$，是某套任务与运行协议下，拟合的任务成功概率达到 50% 时，对应的专家人类完成时间。它不是模型实际跑了多少小时，不是最长不中断运行时间，也不是“所有耗时少于此值的工作都能做”。固定模型的 scaffold、工具、预算、任务分布、人类基线和成功标准会影响结果。原 2025 年方法的历史趋势可作背景，当前模型数字须另核版本与区间；本段不把教材的“14 小时”作为当前实测值。[METR 原方法](https://metr.org/blog/2025-03-19-measuring-ai-ability-to-complete-long-tasks/)

为了理解拟合曲线，可以用一个**示意模型**：$p(t)=\sigma(-\beta\ln(t/H_{50}))$，其中 $t$ 是人类完成小时数，$\beta>0$ 为斜率，$\sigma(z)=1/(1+e^{-z})$。在 $t=H_{50}$ 时，两种斜率都给 50%；但若任务时间只有跨度的四分之一，$\beta=1$ 给 80%，$\beta=3$ 给约 98.46%。所以“保留 4 倍跨度余量就安全”缺少斜率、任务分布和错误代价依据。教材输出 Skill 的 2 倍/4 倍拒绝阈值与部署跨度统一扣减 20–40%，均为作者启发式，不能当 METR 或厂商标准。

### 条件概率与长链路

若整个任务要求每一步都成功，则链式法则给出 $P(S_1,\ldots,S_N)=\prod_i P(S_i\mid S_1,\ldots,S_{i-1})$。只有相应条件概率都等于 $p$，才得到 $p^N$；把独立小题测出的边际准确率直接套进去通常不成立。错误可能相关，Agent 也可能恢复、重试或更换路径。99% 的假设单步成功率连乘 70 次约为 49.48%，是“全部必需步骤成功”的教学计算，不是任何实际 Agent 的测量。

如果每步同一成功率 $p\in(0,1)$ 且目标总成功率 $q\in(0,1]$，最大整数步数为 $\lfloor\ln(q)/\ln(p)\rfloor$。$p=1$ 没有有限上限；$p=0$ 且目标为正时只允许零步。不能用任意大整数冒充无限上限。外推 $H(m)=H_0 2^{m/d}$ 的 $H_0$、月份 $m$、翻倍期 $d$ 均为假设；$d\log_2(H_*/H_0)$ 只是给定假设下的交点，不能据此安排部署日期。

### 完整离线例：跨度斜率与条件概率

以下程序用纯 Python 核对公式、零步、概率边界与非有限数，并展示相同 $H_{50}$ 不保证相同余量可靠性。未拟合 METR 数据、未评测模型，也没有计算真实 API 费用。

```python
import math


def number(x):
    if type(x) not in (int, float) or not math.isfinite(x):
        raise ValueError('需要有限实数')
    return float(x)


def all_steps(probabilities):
    # 输入必须为 Pr(本步成功 | 此前全部成功)，不能用边际准确率替代。
    values = [number(p) for p in probabilities]
    if any(not 0 <= p <= 1 for p in values):
        raise ValueError('条件概率超出范围')
    return math.prod(values)


def max_iid_steps(p, target):
    p, target = number(p), number(target)
    if not (0 <= p <= 1 and 0 < target <= 1):
        raise ValueError('概率范围错误')
    if p == 1:
        return None  # 在该假设下没有有限上限，不伪造 10**9。
    if p == 0:
        return 0
    n = math.floor(math.log(target) / math.log(p))
    # 消除刚好位于整数边界时的浮点误差。
    corrections = 0
    while p ** (n + 1) >= target or p ** n < target:
        if corrections >= 64:
            raise ValueError('浮点整数边界无法可靠定位，需要更高精度')
        n += 1 if p ** (n + 1) >= target else -1
        corrections += 1
    return n


def illustrative_success(human_hours, horizon_hours, slope):
    t, h, beta = map(number, (human_hours, horizon_hours, slope))
    if min(t, h, beta) <= 0:
        raise ValueError('时间和斜率须为正')
    z = beta * (math.log(t) - math.log(h))
    return math.exp(-z) / (1 + math.exp(-z)) if z >= 0 else 1 / (1 + math.exp(z))


def crossing_months(base_hours, doubling_months, target_hours):
    b, d, t = map(number, (base_hours, doubling_months, target_hours))
    if min(b, d, t) <= 0:
        raise ValueError('参数须为正')
    result = d * (math.log2(t) - math.log2(b))
    if not math.isfinite(result):
        raise ValueError('交点超出可表示范围')
    return result  # 负数表示假设中的过去，不硬改为未来。


assert max_iid_steps(.99, .5) == 68
assert max_iid_steps(.995, .5) == 138
assert max_iid_steps(.999, .5) == 692
assert max_iid_steps(1, .5) is None
assert max_iid_steps(0, .5) == 0
assert all_steps([]) == 1
assert math.isclose(all_steps([.99] * 70), .99 ** 70)
assert illustrative_success(10, 10, 1) == .5
assert illustrative_success(1e-300, 1e300, 1) == 1
assert illustrative_success(1e300, 1e-300, 1) == 0
assert math.isfinite(crossing_months(1e-300, 7, 1e300))
p1 = illustrative_success(2.5, 10, 1)
p2 = illustrative_success(2.5, 10, 3)
assert p1 == .8 and p2 > .98  # 同一 H50 和 4x 余量，可靠性仍依赖斜率。
for bad in (True, float('nan'), float('inf'), -1, 1.1):
    try:
        all_steps([bad])
    except ValueError:
        pass
    else:
        raise AssertionError('无效概率被接纳')
print('50% 步数上限：68 / 138 / 692；70步(.99)：', round(.99 ** 70, 6))
print('相同 H50=10h 的4倍余量，示例斜率1/3：', round(p1, 6), round(p2, 6))
print('假设14h、7月翻倍，30h/168h交点：', round(crossing_months(14, 7, 30), 3), round(crossing_months(14, 7, 168), 3))
```

浮点例用对数差避免极端时间比的溢出/下溢；很大的整数步数边界若64次调整仍无法定位会明确报错，不能卡在无界循环或冒称精确整数上限。极端曲线在浮点中可能舍入为0/1，不表示真实概率已得到证明。

### 长任务评测中的行为差异

评测与部署可因任务、工具、预算、数据、用户身份和环境提示而不同。应使用接近实际流程的评测、随机混合评测场景、独立效果核对和有界授权，并保留模型可能识别评测环境这一限制。Anthropic 的 2024 对齐伪装研究在特定训练信息与 free/paid 用户设定下观察行为差异；78% 是实际训练模型回应有害查询后，scratchpad 中对齐伪装推理的比例，不能改写成“训练去除伪装导致 78%”，也不能直接换算部署可靠性下降比例。[对齐伪装原研究说明](https://www.anthropic.com/research/alignment-faking)

## 19. 自主研究：从论文产物追到实验事实

AI Scientist-v2 用实验管理 Agent 协调初步验证、超参数调整、研究议程执行和消融四个阶段。树节点保留实验方案、可执行代码、运行状态、指标与图；节点报错应标记 buggy，而非在最终文章中消失。阶段间选择候选、保存检查点、重复实验以获得均值和标准差。VLM 评阅图形能检查图例与表述，但不能证明数据真实、实验设计有效或方法新颖。[AI Scientist-v2 论文 §3.2–3.4](https://arxiv.org/html/2504.08066v1)

论文报告在受控安排中提交三份生成稿，其中一份获得达到该 ICLR workshop 接受门槛的评审结果。这是该安排下的研究示范；三份不是任意主题的可靠率估计，评审通过也不消除数据重叠、实验口径和图注问题。不同 venue 的要求应按其实际规则判断，不能用“workshop 一律低标准”替代审稿内容。

**必须分清外评的对象。** Beel 等人的 arXiv:2502.14297 外评使用依赖用户模板与 Aider 修改实验的 AI Scientist 配置，五个失败来自十二个拟议实验；这不能当 v2 失败率。该实验还发现新颖性判断依赖检索结果匹配、已知概念被误标新颖、参数没有真正变化或基线没有重跑等问题。应保留这些失败类别作为检查项；不保留教材未经支持的“v2 新颖性错误率 25%”“VLM 掩盖 70%”。[外评 §2.3–2.4，v3](https://arxiv.org/html/2502.14297v3)

### 证据链与导出前的两类检查

例如要比较超参数e=2、3、4、5，先冻结四个run ID、实际读到的配置、同一数据/基线版本和种子。若四个运行记录均为e=2，应标记“配置未生效”，不绘成四组结果。每组重复次数、有效样本数、失败次数与指标单位进入账本；图的数据文件摘要指向对应run，caption只描述这些运行支持的范围。这样即使自动writeup误写“e=5最好”，审查也有具体反证。

每条研究主张连接到：任务/假设 → 数据划分与版本 → 代码与环境 → 实际运行记录 → 指标归约 → 图所用数据 → 文字主张。代码退出成功不等于指标正确；图漂亮不等于实验运行；未执行不能写成负结果；检索没有返回相似标题不等于新颖。最小例是声称比较四个参数，运行账本却显示每次用同一个参数，此时文章再完整也不能支持参数比较。

实验检查要复现基线、保留所有尝试和失败分母、核对种子与样本量、检查泄漏、做必要消融并报告不确定性。图检查要能追到具体 run 和输入数据，核轴/单位/归一化/误差条和结论范围。新颖性检查比较相关方法的假设与机制，开放问题交由有领域判断的人复核；机械检查完成并不代替学术判断。研究数据和发布流程的责任范围沿用[案例方法论](10-案例方法论.md)，不另建“AI Scientist 笔记库”。

运行生成代码还要独立检查文件、网络、进程、资源和凭据边界。容器名称或 subprocess 本身不是隔离证明：宿主挂载、Docker socket、网络权限、子进程与凭据仍可能扩大能力。先给受限工作目录、最小凭据、资源和时限、网络范围与可审计终止方式，再允许实验；对外导出与投稿由已授权的责任人核对证据和目标 venue 的披露要求。

## 20. 协调评测：里程碑的单位与基准适用范围

2026-10-10 增量吸收。最终任务正确、部分进展、代理贡献、通信质量和费用是不同指标。先定义每项分母，再记录 task ID、版本、模型与工具、拓扑、数据切分、总预算和所有尝试；超时、拒绝和未知结果不能消失。

[MultiAgentBench / MARBLE v1](https://arxiv.org/abs/2503.01935v1) 的个体 KPI 为 $n_j/M$，$M$ 是任务里程碑数，$n_j$ 是代理 $j$ 参与达成的里程碑数；总体是 $\sum_jn_j/(NM)$，并另评最终结果和协调。它不等于唯一已完成里程碑的比例。例如两人参与同一项，贡献计数可各加一，唯一成果仍只有一项。应固定里程碑判据、来源和检测器，不能为得到高分任意拆细或奖励重复工作。

每项真实里程碑的成本应为总尝试费用除以实际完成数量。例中两任务各有四个可能里程碑，只完成两项、共花费0.60，成本是每项0.30。若把两任务完成率相加（2/4＋0/4＝0.5）作为分母，会得到1.20；总体完成率则是2/8＝0.25，二者都不是里程碑数量。零完成时保留花费并将单项成本记为未定义。下面每行是一项任务的预聚合账本：费用包含其所有尝试，完成数是独立核过的唯一里程碑数；程序只核这些字段的聚合，真实费用采集和里程碑去重另需证据。

```python
from decimal import Decimal

def cost_per_milestone(rows):
    if not rows:
        raise ValueError('样本不能为空')
    ids, total_cost, completed = set(), Decimal(0), 0
    for row in rows:
        if (type(row['id']) is not str or not row['id'] or row['id'] in ids
                or type(row['completed']) is not int
                or type(row['possible']) is not int
                or not 0 <= row['completed'] <= row['possible']
                or row['possible'] <= 0):
            raise ValueError('ID、任务容量或完成数非法')
        ids.add(row['id'])
        cost = row['cost']
        if type(cost) is not Decimal or not cost.is_finite() or cost < 0:
            raise ValueError('费用须为同单位非负有限Decimal')
        total_cost += cost
        completed += row['completed']
    return total_cost, completed, total_cost / completed if completed else None

rows = [{'id': 'a', 'completed': 2, 'possible': 4, 'cost': Decimal('0.30')},
        {'id': 'b', 'completed': 0, 'possible': 4, 'cost': Decimal('0.30')}]
cost, count, ratio = cost_per_milestone(rows)
assert (cost, count, ratio) == (Decimal('0.60'), 2, Decimal('0.30'))
# 把完成率当里程碑数，单位会差一个每任务容量4的因子。
wrong_ratio = cost / (Decimal(count) / 4)
assert wrong_ratio == Decimal('1.20')
assert cost_per_milestone([rows[1]]) == (Decimal('0.30'), 0, None)
for broken in ([rows[0], rows[0]],
               [dict(rows[0], completed=True)],
               [dict(rows[0], cost=Decimal('NaN'))]):
    try:
        cost_per_milestone(broken)
    except ValueError:
        pass
    else:
        raise AssertionError('非法聚合记录未拒绝')
print('全部尝试费用/真实完成里程碑：', cost, '/', count, '=', ratio)
print('错误完成率分母为', wrong_ratio, '；零成果保留未定义，失败费用不消失')
```

2. **MARBLE 的拓扑结果怎样用于自己的任务？** 图拓扑可以是研究任务的候选，随后用相同任务、总预算和工具权限比较单代理、星形、树或图，核里程碑归属和最终质量。论文特定场景结果不自动决定自己的架构。

3. **SWE-bench Pro 怎样降低污染风险？** 它结合十一公开、十二留出仓库和十八私有商业仓库，减少广泛公开训练数据的风险，辅以专家补上下文与验证。私有/新构造、近重复排查可迁移到其他任务；许可证约束与技术上的未泄漏是不同证据，不能说绝无污染。

4. **怎样构造一个信息不对称的多模态协调任务？** 一个代理只见图像，另一个只见关键文字，要求共同回答完整状态；设联合信息的上界、无通信、完全共享、有限共享和合法随机基线，固定消息预算。核最终正确、局部信息约束与传递成本；未经核验的 COMMA 数字不充当本实验成绩。

5. **怎样审查近期论文的主要性能主张？** 记录论文与数据版本、任务及切分、脚手架、预算、种子和原始结果，分别给已知、未知及混杂因素。优先修错误分母、弱基线和污染归因，不能因为预印本或某个 p 值就机械发字母等级。

## 21. 案例主张怎样转成可检验的架构经验

2026-10-10 增量吸收。先区分供应商生产工程报告、公开研究原型和开放网络概况。案例可指导候选设计，但不直接给自己的系统盖章。

Anthropic 的 [Research 报告](https://www.anthropic.com/engineering/multi-agent-research-system) 说明监督者分解、子代理独立检索、压缩结果、再综合并由 CitationAgent 补引用。其内部研究集的 90.2% 相对提升限定于所用版本与实验；BrowseComp 回归中 token 用量解释 80% 方差，是相关性分析，不是因果贡献或所有任务的规律。**约 15 倍 token 相对聊天，单代理约 4 倍也相对聊天**，不能把它写成多代理比单代理花 15 倍。该报告还明确当时按子批同步等待，不能因使用并行子代理就称所有协作异步。

角色分工的 [MetaGPT v7](https://arxiv.org/abs/2308.00352v7) 将需求、架构、分工、代码与测试组织成 SOP，结构消息与订阅减少无关传播，执行反馈帮助修订。角色名字不自动赋予运行权限，QA 角色也可能遗漏要求；需产物合同、独立验证与停止条件。[ChatDev v5](https://arxiv.org/abs/2307.07924v5) 的主动澄清让回答者先问精确依赖、类名或要求，再给最终答案，能减少歧义但不保证答复事实正确。没有独立证据时，两人同意仍只是一致说法。

DAG 可以把已知依赖显式化，但 MacNet 的大规模研究设置不等于生产无限扩展。开放网络需要考虑伪身份、跨租户提示传播、恶意信誉和流量突增；这是可分析的威胁模型。本批未核实 OpenClaw/Moltbook 人口、星数、收购和监管事件，不用这些数字证明真实自主代理、经济活动或系统有效。

选参考案例时填写任务分解方式、可见信息、交接产物、实际权限、等待/取消、状态版本、评价与费用，再决定哪些机制适合自己的范围。框架兼容 MCP/A2A、审批恢复和迁移按具体版本分别测试；“所有框架都支持”“协议免费”“某品牌生产第一”都不是选型依据。实际跨协议测试沿已有通信章节维护，不在案例里建立第二套实现。

4. **开放人口网络有哪些需要单独处理的失败？** 无需依赖未经核实的人口数字，也可以分析跨租户提示传播、伪身份、信誉投毒和流量激增。外部主页和消息只作数据，身份、权限、限流与证据谱系分别管理。威胁模型不等于已经观察到某个平台事件。
