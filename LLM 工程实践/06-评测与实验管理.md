# 06｜评测与实验管理

## 1. 评测分成两条线

### 质量评测

回答：

> 模型做得对不对、好不好？

### 性能评测

回答：

> 模型跑得快不快、稳不稳、贵不贵？

两者必须分开。

## 2. 质量评测

按任务选择指标：

- 分类：accuracy / F1；
- 检索：Recall@k / MRR / nDCG；
- 生成：任务特定指标；
- 数学/代码：可执行 verifier；
- 指令跟随：规则或 IFEval 类验证；
- 开放回答：人工 / Judge；
- Agent：任务成功率 + trajectory。

## 3. 性能评测

在线服务重点关注：

- TTFT；
- TPOT；
- end-to-end latency；
- input throughput；
- output throughput；
- requests/s；
- error rate；
- P50/P95/P99；
- GPU/NPU utilization；
- 显存；
- 并发上升后的退化曲线。

## 4. 并发压测

不能只测单请求。

应逐步增加：

```text
1 → 5 → 10 → 20 → 50 → ...
```

观察：

- 延迟何时突然恶化；
- 吞吐何时到平台；
- OOM / timeout 从哪里开始；
- 调度是否公平。

EvalScope 当前仍支持 OpenAI-compatible 服务的性能压测，可以作为工具之一。

## 5. 训练实验管理

训练记录至少包含：

- train / eval loss；
- learning rate；
- throughput；
- gradient norm；
- GPU memory；
- hyperparameters；
- dataset；
- checkpoint；
- system info。

实验追踪工具可以使用 SwanLab、W&B、TensorBoard 等。

关键不是工具品牌，而是：

> **实验必须可比较、可复现、可追溯。**

## 6. A/B 和回归

每次模型更新都应该与前一个版本做：

- 相同数据；
- 相同生成配置；
- 相同硬件；
- 相同评估器；

对比。

## 7. 不要只看平均分

平均分会掩盖：

- 某领域严重退化；
- 长上下文失败；
- 特定语言失败；
- 多轮对话失败；
- 高并发尾延迟。

应分 slice 查看。

## 8. 评测污染

注意：

- 训练数据包含 benchmark；
- synthetic data 来自同一个 Judge；
- 测试集被调参反复使用；
- 模型可能记忆公开答案。

生产评估应增加私有、真实业务测试集。

## 9. Agent 与模型评测开始汇合

当前评测框架正在从“单轮问答”扩展到：

- tool use；
- 多轮 Agent loop；
- coding environment；
- trajectory；
- verifier。

因此长期应把“模型指标”和“任务完成指标”同时保留。
