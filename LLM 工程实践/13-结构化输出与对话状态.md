# 13｜结构化输出与对话状态

模型生成文字，程序执行的是有类型、有状态、有边界的操作。本篇把格式约束、聊天路由、关系图和对话状态放在同一条工程链上：模型提出候选 → 程序检查 → 更新状态或返回澄清 → 按授权调用工具 → 核验结果。文本检索与证据来源见 [12](12-文本检索与RAG文档工程.md)，语义正确性与运行评价见 [06](06-评测与实验管理.md)。

## 1. 结构化输出要经过四层检查

1. **语法**：JSON 是否能解析，括号、引号、转义是否正确。
2. **Schema**：字段、类型、枚举、长度、是否允许额外字段等是否满足要求。
3. **业务一致性**：开始时间是否早于结束时间，币种是否与金额单位对应，关系方向和实体类型是否相容。
4. **来源与授权**：数据是否有证据，是否是本轮真实请求，用户是否授权该对象和动作。

例如 `{"price":"cheap"}` 可以符合 schema，却与用户“不要便宜的，改成中等”相矛盾。给缺失信息强制填必填枚举，会使模型编出一个看似合法的值。应明确未知/未提供、允许为空的字段，以及缺失和 null 的差别。`null` 可表示已知为空或未知，必须在该任务中约定；“不限制价格”则是 don't-care，不能与未知混用。

JSON mode 通常只保证语法层；受支持的严格 schema 模式可以约束结构；客户端验证重试只在生成后拒绝错误。它们都不自动证明业务事实。不要把“输出符合 schema”宣传成“任何模型永不出错”。

## 2. 约束解码的原理：只保留可接受的前缀

在第 t 步模型给词表 logits。语法状态计算哪些 token 的字符或字节序列能使当前前缀继续完成合法对象：

$$p_t(v)=\operatorname{softmax}(z_t(v)+m_t(v)),\quad m_t(v)\in\{0,-\infty\}.$$

非法 token 被屏蔽，合法 token 仍按模型分数采样。一个 token 可能是多个字符，不能只检查它的第一个字符。EOS 只在接受状态允许；合法前缀不等于已经完成。输出预算用尽、中断、拒绝、合法集合为空或全部合法 logits 为负无穷都需要明确失败状态，不能返回截断片段并当作有效对象。

有限状态机适合有限状态模式，例如固定格式编号；任意深度嵌套的括号语言需要栈或其他更强的语法机制，不能用一个固定 FSM 表示无界递归。框架可以组合正则、语法、JSON schema 和专门约束后端，不应把某品牌的所有实现统称为 FSM。

### 2.1 可独立运行的多字符 token 状态机

以下只接受 `{"ok":true}` 或 `{"ok":false}` 两种完整字符串。使用合法目标串的前缀集合实现一个有限自动机；不是通用 JSON schema 编译器。它包含多字符 token、非法词、EOS、预算耗尽和无有限分数分支。

```python
import math

TARGETS = ('{"ok":true}', '{"ok":false}')
EOS = "<EOS>"
VOCAB = ('{', '"ok"', ':', 'true', 'false', '}', '"yes"', '42', EOS)

def advance(prefix, token):
    if token == EOS:
        return prefix if prefix in TARGETS else None
    candidate = prefix + token
    return candidate if any(s.startswith(candidate) for s in TARGETS) else None

def constrained_decode(score_fn, budget=12):
    if type(budget) is not int or budget <= 0:
        raise ValueError("budget 必须为正整数")
    prefix = ""
    for step in range(budget):
        logits = score_fn(step, prefix)
        options = []
        for token in VOCAB:
            nxt = advance(prefix, token)
            score = logits.get(token, -math.inf)
            if math.isnan(score) or score == math.inf:
                raise ValueError("logit 不能是 NaN 或正无穷")
            if nxt is not None and math.isfinite(score):
                options.append((score, token, nxt))
        if not options:
            return {"status": "no_finite_legal_token", "prefix": prefix}
        _, token, prefix = max(options, key=lambda x: (x[0], x[1]))
        if token == EOS:
            return {"status": "complete", "text": prefix}
    return {"status": "budget_exhausted", "prefix": prefix}

# 非法项虽有更高分也不能通过；固定分数 fixture 不是真实语言模型。
def scores(step, prefix):
    return {t: (100 if t in ('"yes"', '42') else 2 if t == 'false' else 1)
            for t in VOCAB}

out = constrained_decode(scores)
assert out == {"status": "complete", "text": '{"ok":false}'}
assert advance('{"ok":', 'true}') == '{"ok":true}'  # 多字符转移。
assert advance('{"ok":', 'trueX') is None
assert advance('{', EOS) is None
assert constrained_decode(scores, 2)["status"] == "budget_exhausted"
assert constrained_decode(lambda s, p: {})["status"] == "no_finite_legal_token"
print(out, "；预算、EOS、无合法有限分数分支通过")
```

输出约束有计算和缓存开销，也可能减少无效回答和重试。模型前向通常仍要计算词表 logits；不能据合法 token 少就声称每步 O(1)、总是更快。比较延迟须包含 schema 编译、首次请求、缓存命中和失败重试。

固定电话号码格式 `DDD-DDD-DDDD` 可用当前位置作为状态：位置 3、7 只允许连字符，其余 10 个数字位只允许 ASCII 0–9，第 12 个字符后才允许 EOS。正则 `\d` 在某些引擎还匹配 Unicode 数字，跨后端需核对约定。格式合法不证明号码存在、地区正确或可联系；`YYYY-MM-DD` 也不排除 2025-99-99，业务日期需单独解析并校验。无号码、日期未知时应允许协议中的未知状态，不能为满足正则编造。

### 2.2 选择约束方案时检查接口契约

| 方案 | 约束发生在哪里 | 需要核实 |
|---|---|---|
| 提示要求 JSON | 文字指令 | 可能有围栏、解释、缺字段，需要解析和校验 |
| 客户端类型验证与重试 | 生成之后 | 次数上限、超时、重复费用、错误是否可修复 |
| 本地 grammar/schema 解码 | token 采样前 | 支持的 schema 子集、tokenizer 对齐、递归、EOS、空合法集合 |
| 服务原生严格 schema | 服务端 | 模型与接口支持、拒绝和 incomplete 状态、字段要求 |

Outlines、Instructor、vLLM 等只是不同实现入口。验证重试不等于约束采样；服务端 schema 支持也不等于所有 JSON Schema 特性可用。当前 Outlines 文档列出 JSON Schema、正则与上下文无关文法，不能用旧的 FSM 局限概括全部后端。[Outlines 官方文档](https://dottxt-ai.github.io/outlines/latest/)字段顺序有时影响质量，是需实验的问题；不得要求暴露内部推理过程，也不能认定答案字段必须永远排在某个 reasoning 字段之后。需要解释时收集简洁、可核查的依据或证据跨度。

2026-10-04 核验：vLLM 官方入口使用 `structured_outputs`，不要沿用已移除的 `guided_json/guided_regex` 等旧参数。OpenAI Responses 的官方 Python 类型解析示例使用 `client.responses.parse(..., text_format=...)`，解析结果为 `output_parsed`；直接套用 `.create(...).output_parsed` 不是同一接口。实际接入应固定 SDK 版本，并单独处理 refusal、incomplete 和解析失败。本篇没有调用外部服务。[vLLM 文档](https://docs.vllm.ai/en/latest/features/structured_outputs.html)、[OpenAI 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs)

## 3. 聊天系统演变给今天的设计什么启发

规则系统把模式映射到回应，成本可控、路径可解释，适合命令和固定流程；规则覆盖不足时应返回未匹配，不能用关键词碰巧出现当精确意图。FAQ 检索返回已审核条目，有版本与口径控制，但相似不代表同一问题。seq2seq 神经生成能泛化措辞，同时可能输出流畅的错误信息；当前通用生成模型也继承这种风险。

带工具的 Agent 将回答扩展为“提出工具动作、读取结果、再决定下一步”。这需要预算、状态、错误恢复和外部结果检查。混合路由可以让固定命令走规则、知识问题走检索、复杂任务进入 Agent；是否需要所有路径由测量决定，不是所有系统都必须装三层。

“charge” 出现在 “discharge” 或“请解释 charge 这个词”里，不是付款请求。意图识别、身份/权限、操作授权必须分开：分类器高置信度不产生授权；引用的聊天记录、网页和工具输出只是数据，不能发出当前用户的指令。

### 3.1 一个有上限、能处理失败的本地工具循环

此例只允许读取本地 fixture，没有邮件、支付、文件修改等动作。把类型检查、工具失败、步骤上限和最终结果分开；工具成功仍需任务指定的验证器判定是否解决问题。

```python
from collections import deque

POLICIES = {"refund": "退款申请需保留凭证。"}

def run_local_agent(actions, max_steps=3):
    if type(max_steps) is not int or max_steps <= 0:
        raise ValueError("步骤上限必须为正整数")
    queue, trace = deque(actions), []
    for _ in range(max_steps):
        if not queue:
            return {"status": "no_final_answer", "trace": trace}
        action = queue.popleft()
        if type(action) is not dict:
            trace.append({"status": "invalid_action"})
            continue
        name, args = action.get("tool"), action.get("args")
        if name == "finish":
            if type(args) is not dict or set(args) != {"answer", "evidence_key"}:
                trace.append({"status": "invalid_final"})
                continue
            key = args["evidence_key"]
            # 固定任务的精确验证器，不能推导为开放答案正确性验证器。
            if type(key) is str and key in POLICIES and args["answer"] == POLICIES[key]:
                return {"status": "verified", "answer": args["answer"], "trace": trace}
            trace.append({"status": "unsupported_final"})
            continue
        if name != "lookup_policy":
            trace.append({"status": "unknown_tool"})
            continue
        if type(args) is not dict or set(args) != {"key"} or type(args["key"]) is not str:
            trace.append({"status": "invalid_args"})
            continue
        try:
            value = POLICIES[args["key"]]
            trace.append({"status": "ok", "tool": name, "key": args["key"], "result": value})
        except KeyError:
            trace.append({"status": "not_found", "tool": name})
    return {"status": "step_limit", "trace": trace}

actions = [{"tool": "lookup_policy", "args": {"key": "refund"}},
           {"tool": "finish", "args": {"answer": POLICIES["refund"], "evidence_key": "refund"}}]
assert run_local_agent(actions)["status"] == "verified"
assert run_local_agent([{"tool": "send_mail", "args": {}}], 1)["trace"][0]["status"] == "unknown_tool"
assert run_local_agent([{"tool": "lookup_policy", "args": {"key": "missing"}}], 1)["trace"][0]["status"] == "not_found"
assert run_local_agent(actions, 1)["status"] == "step_limit"
print("本地循环：成功、未知工具、工具失败、步骤上限均通过")
```

实际系统还要限制输出大小和总时间，将工具结果保留来源、错误类型、版本和执行 ID；有副作用的工具需幂等策略，不能在“结果未知”时直接重试造成重复操作。提示中的 plan/validate/execute 可以帮助组织流程，但不代替程序中的权限、参数和结果验证。

## 4. 对话状态：区分完整快照与增量补丁

状态是对当前任务有效条件的结构化记录。例如餐厅查询的 `price、area、cuisine`。一次话语可以新增、替换、取消一个条件，也可以表示某项不限。语言理解得到候选补丁，确定性更新器执行补丁；不能每轮随意把未提及槽位清空。

| 情况 | 操作 | 示例 |
|---|---|---|
| 未提到某槽位 | 保持 | “再加意大利菜”保持原地区 |
| 新设/替换 | set | “改为中等价位”只改价格 |
| 明确不限制 | dontcare | “区域不限”保留显式不限状态 |
| 撤销条件 | clear | “删掉菜系要求”回到未设 |
| 有歧义或指代无对象 | 不提交，澄清 | “换成那个”却没有稳定选项 ID |

“不要便宜的，改成中等”含否定与替换，应采用中等，不能因 cheap 先出现就提取 cheap。更正的是哪个槽位由语义决定，不是“最后一次修改的槽位”。“第二个”需要关联当前版本的候选列表及选项 ID；列表换了以后旧指代失效。

### 4.1 有类型、来源和原子性的状态更新

本例测试的是已解析补丁的执行，**不声称实现任意自然语言理解**。所有操作先验证再修改，任何一个不合法都不产生部分更新。每个被改变的槽位记录 turn/source，便于追溯。

```python
from copy import deepcopy

VALUES = {"price": {"cheap", "moderate", "expensive"},
          "area": {"north", "south", "centre"},
          "cuisine": {"italian", "chinese", "indian"}}

def apply_patch(state, patch, turn):
    if type(turn) is not int or turn < 1 or type(patch) is not list:
        raise ValueError("turn 或 patch 不合法")
    seen = set()
    for op in patch:
        if type(op) is not dict or set(op) != {"slot", "op", "value", "source"}:
            raise ValueError("操作字段不符合契约")
        slot, kind = op["slot"], op["op"]
        if slot not in VALUES or slot in seen or kind not in {"set", "clear", "dontcare"}:
            raise ValueError("未知或重复槽位/操作")
        if type(op["source"]) is not str or not op["source"]:
            raise ValueError("缺少补丁来源")
        value = op["value"]
        if kind == "set" and (type(value) is not str or value not in VALUES[slot]):
            raise ValueError("值超出闭合槽位域")
        if kind != "set" and value is not None:
            raise ValueError("clear/dontcare 的 value 应为空")
        seen.add(slot)
    updated = deepcopy(state)
    for op in patch:
        if op["op"] == "clear":
            updated.pop(op["slot"], None)
        else:
            updated[op["slot"]] = {"status": "value" if op["op"] == "set" else "dontcare",
                                   "value": op["value"], "turn": turn, "source": op["source"]}
    return updated

def op(slot, kind, value, source):
    return {"slot": slot, "op": kind, "value": value, "source": source}

def semantic_state(state):
    return {k: (v["status"], v["value"]) for k, v in state.items()}

def joint_goal_accuracy(predicted, gold):
    if not predicted or len(predicted) != len(gold):
        raise ValueError("必须逐轮一一对应，空集合不报告准确率")
    return sum(semantic_state(p) == semantic_state(g) for p, g in zip(predicted, gold)) / len(gold)

s1 = apply_patch({}, [op("price", "set", "cheap", "t1:便宜"), op("area", "set", "north", "t1:北边")], 1)
s2 = apply_patch(s1, [op("price", "set", "moderate", "t2:不要便宜，改中等")], 2)
s3 = apply_patch(s2, [op("area", "dontcare", None, "t3:地区不限"), op("cuisine", "set", "italian", "t3:意大利菜")], 3)
s4 = apply_patch(s3, [op("cuisine", "clear", None, "t4:删除菜系条件")], 4)
assert s2["area"] == s1["area"] and s2["price"]["value"] == "moderate"
assert s3["area"]["status"] == "dontcare" and "cuisine" not in s4
assert s1["price"]["value"] == "cheap"  # 未原地污染历史快照。
before = deepcopy(s2)
try:
    apply_patch(s2, [op("price", "set", "cheap", "x"), op("area", "set", "mars", "x")], 5)
except ValueError:
    pass
else:
    raise AssertionError("非法补丁应拒绝")
assert s2 == before
assert joint_goal_accuracy([s1, s1, s3], [s1, s2, s3]) == 2 / 3
print("状态更正、保持、不限、清空、原子拒绝、逐轮 JGA 均通过")
```

JGA 是所有槽位都正确才算该轮成功，对多槽位很严格。另报逐槽位准确率、set/clear/dontcare 分类、纠错成功率和错误持续轮数，以定位问题。必须逐轮而非只对话末轮计算；长度不等的预测/gold 不能用 `zip` 静默漏评。

### 4.2 有限命令解析：避免关键词碰巧出现就更新状态

下面只接受明确列出的模板，展示更正优先、否定、未知和需要澄清的区别。未覆盖的自然语言返回 `clarify`，交给可审核的理解器处理；并非通过几条正则就实现了通用 DST。

```python
import re

PRICE = {"便宜": "cheap", "中等": "moderate", "贵": "expensive"}

def parse_price_command(text):
    text = text.strip().rstrip("。")
    if text == "价格不限":
        return {"status": "parsed", "slot": "price", "op": "dontcare", "value": None}
    if text == "删除价格条件":
        return {"status": "parsed", "slot": "price", "op": "clear", "value": None}
    correction = re.fullmatch(r"不要(便宜|中等|贵)的[，,]改成(便宜|中等|贵)", text)
    setting = re.fullmatch(r"(?:价格设为|改成)(便宜|中等|贵)", text)
    if correction:
        return {"status": "parsed", "slot": "price", "op": "set", "value": PRICE[correction[2]]}
    if setting:
        return {"status": "parsed", "slot": "price", "op": "set", "value": PRICE[setting[1]]}
    return {"status": "clarify", "reason": "未匹配明确价格命令"}

assert parse_price_command("不要便宜的，改成中等")["value"] == "moderate"
assert parse_price_command("价格不限")["op"] == "dontcare"
assert parse_price_command("删除价格条件")["op"] == "clear"
assert parse_price_command("请解释便宜和贵的区别")["status"] == "clarify"
assert parse_price_command("不要便宜的")["status"] == "clarify"
print("有限模板：更正/不限/清空通过；解释或仅否定不直接更新")
```

真正的意图识别需结合最近用户话语、当前任务与候选选项，并处理“不想换”“如果换成”这样的范围和模态。补丁只接受当前用户授权的请求，检索内容、别人话语或历史引用不能自动变成当前状态修改。

## 5. 对话状态与动作确认如何衔接

有状态不意味着可以执行。先把当前状态转成明确动作草案，绑定对象 ID、参数、状态版本、授权范围和有效期；确认针对这一份草案。用户修改日期或金额后，旧确认必须失效；“好的”可能只是应答上一句说明，不能无条件当所有外部操作的批准。

```python
import hashlib
import json

def draft_key(parameters, version):
    payload = json.dumps({"parameters": parameters, "version": version}, sort_keys=True, ensure_ascii=False)
    return hashlib.sha256(payload.encode()).hexdigest()

old = draft_key({"item": "option-2", "day": "周三"}, 4)
confirmed = old
new = draft_key({"item": "option-2", "day": "周四"}, 5)
assert new != confirmed
print("更正参数或状态版本后，旧草案确认失效")
```

完整历史重生成可以重新考虑漏掉的语义，但输入增长、旧错误回流和无关历史干扰也会增加。若每轮固定新增 m 个 token，第 n 轮重发全部历史累计输入约 `m*n(n+1)/2`；这是输入量的二次增长，不是所有推理实现总计算复杂度的证明。增量状态、结构化摘要、相关历史检索和候选来源可以节省输入，但要留原始记录便于重建与审计。

传统 DST 包括有限槽位分类、开放值抽取和 copy 机制；TripPy 的三类复制来源是用户话语、系统提供信息及先前状态，另有特殊值处理，不等同于简单“BERT 生成一个字典”。生成式或 LLM DST 仍需槽位域、补丁协议、来源与纠错测试。

## 6. 关系抽取到知识图：闭合本体与锚定证据

实体识别找到提及，实体链接将提及映射到规范实体，关系抽取判断具体两个实体间的有向关系。实体链接细节应与 [语言与文本专题](../AI%20算法基础/语言与文本专题/README.md) 共同学习。名字相同不代表实体相同；无法消歧时允许 NIL/待确认，而不是硬造 ID。

模式抽取适合少量句式，监督模型学习实体对与上下文的关系标签，生成式模型可以输出多个三元组。REBEL 属于序列到序列的关系生成方法，不能拿 `AutoModelForSequenceClassification` 当带 `.generate()` 的序列生成器；其关系文字也不会天然变成某知识库的属性 ID。[REBEL 作者模型卡](https://huggingface.co/Babelscape/rebel-large)

闭合本体需要定义关系名、方向、主客体类型、可用限定词。例如本地 `founded_by` 是 `Organization → Person`，`ceo` 也是 `Organization → Person`。Wikidata 的 P112（founder，组织指向创办者）、P169（chief executive officer）采用这些方向；源课将人放在这些属性的 subject 位置会反转含义。P1830（owner of）不是任意收购事件的通用替代，不能仅靠“acquired”关键词套用。生产应用须核实实际属性及时间限定词。[P112](https://www.wikidata.org/wiki/Property:P112)、[P169](https://www.wikidata.org/wiki/Property:P169)、[P1830](https://www.wikidata.org/wiki/Property:P1830)

### 6.1 一个会拒绝倒置、否定和锚点错误的抽取器

该程序只支持中文合成句式“某人创办某组织”，用白名单实体、本体和精确跨度构建关系。它没有自动理解任意句式；未知、否定、计划或外部传闻进入待审，不写成已确认事实。结构检查和证据存在检查仍不等于通用蕴含判断。

```python
import re
import hashlib

ENTITIES = {"林禾": ("person:lin", "Person"), "星辰实验室": ("org:star", "Organization")}
ONTOLOGY = {"founded_by": ("Organization", "Person")}

def extract_founding(text, source_id):
    revision = hashlib.sha256(text.encode()).hexdigest()
    facts = []
    for match in re.finditer(r"(?P<person>林禾)创办了(?P<org>星辰实验室)", text):
        # 有限句式：出现否定、计划、据说等不直接确认为事实。
        sentence_start = max(text.rfind("。", 0, match.start()), text.rfind("；", 0, match.start())) + 1
        prefix = text[sentence_start:match.start()]
        if any(w in prefix for w in ("没有", "未", "计划", "据说")):
            continue
        person = ENTITIES[match["person"]][0]
        org = ENTITIES[match["org"]][0]
        facts.append({"subject": org, "relation": "founded_by", "object": person,
                      "subject_type": "Organization", "object_type": "Person",
                      "source": source_id, "revision": revision,
                      "span": match.span(), "subject_span": match.span("org"),
                      "object_span": match.span("person"), "evidence": match.group()})
    return facts

def validate_fact(fact, text, source_id):
    if fact["relation"] not in ONTOLOGY:
        return False
    if (fact["subject_type"], fact["object_type"]) != ONTOLOGY[fact["relation"]]:
        return False
    if fact["source"] != source_id or fact["revision"] != hashlib.sha256(text.encode()).hexdigest():
        return False
    a, b = fact["span"]
    if not (0 <= a < b <= len(text)) or text[a:b] != fact["evidence"]:
        return False
    for key, kind, span_key in (("subject", "subject_type", "subject_span"),
                                ("object", "object_type", "object_span")):
        x, y = fact[span_key]
        if not (a <= x < y <= b) or ENTITIES.get(text[x:y]) != (fact[key], fact[kind]):
            return False
    # 对本程序支持的句式，再重新解析并核对主客体与关系。
    return any(candidate == fact for candidate in extract_founding(text, source_id))

text = "林禾创办了星辰实验室。"
fact = extract_founding(text, "doc-1")[0]
assert validate_fact(fact, text, "doc-1")
reversed_fact = dict(fact, subject=fact["object"], object=fact["subject"],
                     subject_type="Person", object_type="Organization")
assert not validate_fact(reversed_fact, text, "doc-1")
assert not validate_fact(dict(fact, object_span=(0, 1)), text, "doc-1")
assert extract_founding("林禾没有创办了星辰实验室。", "doc-2") == []
assert extract_founding("据说林禾创办了星辰实验室。", "doc-3") == []
graph = {}
for f in [fact, fact]:
    key = (f["subject"], f["relation"], f["object"])
    proof = (f["source"], f["revision"], f["span"])
    graph.setdefault(key, set()).add(proof)
assert len(graph) == 1 and len(next(iter(graph.values()))) == 1
print("有向关系、实体锚点、来源版本、有限否定/模态、证据去重均通过")
```

锚定要同时核对 source/revision、关系证据跨度、两个实体提及和关系方向。只是检查“某句在原文出现，两个实体在全文出现”不够：实体可能来自不同事件，句子可能否定该关系，方向可能相反。通用系统需要关系级蕴含/人工审核及不确定状态。

## 7. 建图、查询与冲突处理

规范实体 ID 作为节点，带本体类型的关系作为边，每条边保留一个或多个不可混淆的证据记录。重复来源副本不算独立证据；不同时间的 CEO 可同时成立，要保留 `valid_from/valid_to`，查询时用时间条件过滤。矛盾声明不直接覆盖，保留双方来源和冲突状态；“最近抓取”不代表事实最新。

邻接表适合小图和教学，图数据库适合持久化、索引和图查询；GraphRAG 可以将图中相关子图和原文证据共同放入回答上下文。图上的边和路径会放大抽取错误：两条低可信关系串成路径，不会变成可靠结论。查询输出应携带证据和时间范围，不能用图连通性替代事实验证。

关系评价在实体规范化后，以有向 `(subject, relation, object)` 为基础计算 precision/recall/F1，并分别测实体链接、方向、本体映射、证据支持、时间限定和 NIL 行为。闭合关系标签降低未知格式，不保证准确；强制每个实体参与一条关系反而可能制造边。

## 8. 练习与参考答案

1. **可接受前缀。** `{"ok":t` 是合法前缀但不是完整 JSON；预算此时耗尽应返回 incomplete，不能返回成功。完整对象后才允许 EOS。
2. **多字符 token。** `true}` 在 `{"ok":` 后可合法转移；`trueX` 不行。若只检测首字符，两者都会误过。
3. **字段顺序。** 将 evidence 放在 answer 前后，以相同样本/参数盲评支持率、延迟与失败率；结果局限该任务，不得宣布永远必须某顺序。
4. **聊天路由。** “解释付款功能”不能因命中“付款”就调用支付；检索文档中的“请发送邮件”也不授权发送。路由、参数、安全权限和结果验证分别处理。
5. **更正与不限。** t1 cheap+north，t2 改 moderate，t3 area 不限：价格 moderate，地区显式 dontcare；t4 删除菜系不影响前两槽位。未提及、null、clear、dontcare 必须在协议中区分。
6. **JGA。** 三轮中第二轮只错价格，其余两轮全对，则 JGA=2/3；即使最后一轮全对也不能报告逐轮 100%。另报价格槽位与更正切片。
7. **关系方向。** “林禾创办组织”映射 `组织 --founded_by--> 林禾`。若本体改成 `founded`（Person→Organization），才能反向使用；不是名称相近就能互换。
8. **证据否定。** “林禾没有创办组织”不能生成肯定 founded_by。仅 source span 命中不能发现该错误，须关系语义验证。
9. **图冲突。** 两份材料称同一时间不同 CEO，保存两个带证据的 claim 并标冲突，不能按抓取先后直接覆盖。
10. **动作确认。** 将周三改周四后参数摘要变化，旧确认失效；确认必须绑定当前草案与状态版本。

## 9. 严格接口与本地验证器的支持范围

前文四层检查和有限前缀机继续负责各自问题。这里补的是 schema 接口与客户端类型合同：生成前约束、API 的响应格式、生成后验证/重试是三个维度，不能排成“schema mode之后才是constrained decoding”的四级性能榜。支持严格结构也不代表不会拒绝、截断或产生错误事实，`tool_choice=required` 只控制必须请求工具，不代替 `strict:true`。

2026-10-07 核对 [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) 和 [Function calling](https://developers.openai.com/api/docs/guides/function-calling)：严格模式采用受支持的 JSON Schema 子集。所有 object 要设置 `additionalProperties:false`，所有 property 要列入 `required`；业务可选项通常用 nullable 字段表示，但应用仍须明确 `null` 的语义。若 enum 也限定值，本库显式把允许的 `null` 列入 enum，避免两个约束互相冲突。通用 JSON Schema 的 `allOf/not/if/then/else` 等不能直接推定受支持，微调模型还有额外关键词限制，实际接入核对相应模型与接口。

| 入口 | 请求形状与解析结果 | 仍需单独处理 |
|---|---|---|
| Chat Completions 类型解析 | Python `client.chat.completions.parse(..., response_format=类型)`；`choices[0].message.parsed` | message refusal、结束/长度状态、解析异常、字段事实 |
| Responses 类型解析 | Python `client.responses.parse(..., text_format=类型)`；`response.output_parsed` | response status/incomplete details、refusal 内容、解析异常 |
| 手写 JSON Schema | Chat 的 `response_format` 与 Responses 的 `text.format` 包装不同 | 支持子集、strict、完整响应与业务验证 |
| 客户端验证重试 | 收到文本之后解析、拒绝、反馈错误 | 次数/时间/费用上限，原文与字段变化，最终失败 |

本表是官方文档核对结果，没有发送服务请求。不能把 `.create()` 的普通结果直接当 `.parse()` 的 `output_parsed`；也不能假设 JSON mode 永远返回完整对象。Responses 的 `incomplete` 与拒绝应先分类，不能把缺少 `parsed` 当空商品。Pydantic 和 Zod 的 coercion、额外字段、strict 配置各有合同；教学自制 DSL 不是这些库的完整实现。字段上写了 `float` 也不会自动加非负价格约束。

### 9.1 完整CPU例：拒绝bool、NaN、额外键与未知关键词

下面是**有意缩小的本地合同**：支持 object/array、基础类型、nullable、标量 enum、数值/数组范围和 description；不支持引用、组合、正则或任意 JSON Schema。enum 仅允许 `None/str/bool/有限数`，对象/数组 enum 在使用前拒绝，不实现嵌套 JSON 相等。有限 `int/float` 按数值比较，`1` 与 `1.0` 相等，bool 与数字严格区分；不能直接使用 Python 的 `True == 1`。未知关键词也在使用前报错，不静默跳过。本例的 integer 只接受 Python `int`，比通用 JSON Schema 接受数值为整数的 `3.0` 更窄，不冒称规范的一致实现。解析拒绝非有限 JSON 常量和重复键，业务核验仅比较固定人工 gold，不进行开放语义推断。

```python
import json
import math
from copy import deepcopy

KEYWORDS = {"type", "properties", "required", "additionalProperties", "items",
            "enum", "minimum", "maximum", "minItems", "maxItems", "description"}
TYPES = {"object", "array", "string", "number", "integer", "boolean", "null"}

def types_of(schema):
    value = schema.get("type")
    values = [value] if type(value) is str else value
    if (type(values) is not list or not values or any(type(v) is not str for v in values)
            or len(values) != len(set(values)) or not set(values) <= TYPES):
        raise ValueError("type不在本地支持范围")
    if len(values) > 1 and (len(values) != 2 or "null" not in values):
        raise ValueError("本地仅支持单类型加null")
    return set(values)

def check_schema(schema, depth=0):
    if depth > 6 or type(schema) is not dict or set(schema) - KEYWORDS:
        raise ValueError("未知schema关键词、非法对象或过深schema")
    types = types_of(schema)
    if "description" in schema and type(schema["description"]) is not str:
        raise ValueError("description须为字符串")
    object_keys = {"properties", "required", "additionalProperties"}
    array_keys = {"items", "minItems", "maxItems"}
    if "object" not in types and object_keys & set(schema):
        raise ValueError("对象关键词用在非对象类型")
    if "array" not in types and array_keys & set(schema):
        raise ValueError("数组关键词用在非数组类型")
    if not ({"number", "integer"} & types) and {"minimum", "maximum"} & set(schema):
        raise ValueError("数值范围用在非数值类型")
    for key in ("minimum", "maximum"):
        if key in schema and (type(schema[key]) not in (int, float) or not math.isfinite(schema[key])):
            raise ValueError("数值范围必须有限")
    for key in ("minItems", "maxItems"):
        if key in schema and (type(schema[key]) is not int or schema[key] < 0):
            raise ValueError("数组长度须为非负整数")
    if schema.get("minimum", -math.inf) > schema.get("maximum", math.inf):
        raise ValueError("数值范围倒置")
    if schema.get("minItems", 0) > schema.get("maxItems", math.inf):
        raise ValueError("数组范围倒置")
    if "enum" in schema and (type(schema["enum"]) is not list or not schema["enum"]):
        raise ValueError("enum须为非空列表")
    if "enum" in schema and any(
            not (value is None or type(value) in (str, bool) or finite_number(value))
            for value in schema["enum"]):
        raise ValueError("本地enum只支持标量；拒绝对象/数组/非有限数")
    if "object" in types:
        props, required = schema.get("properties"), schema.get("required")
        if (type(props) is not dict or type(required) is not list
                or any(type(k) is not str for k in props)
                or any(type(k) is not str for k in required)
                or len(required) != len(set(required)) or set(required) != set(props)
                or schema.get("additionalProperties") is not False):
            raise ValueError("本地严格对象须all required且禁止额外键")
        for child in props.values():
            check_schema(child, depth + 1)
    if "array" in types:
        check_schema(schema.get("items"), depth + 1)

def finite_number(value):
    if type(value) not in (int, float):  # bool不能当number。
        return False
    try:
        return math.isfinite(value)
    except OverflowError:
        return False

def same_scalar(left, right):
    if finite_number(left) and finite_number(right):
        return left == right  # 1与1.0相等；finite_number已经排除bool。
    return type(left) is type(right) and left == right

def validate(data, schema):
    check_schema(schema)
    def walk(value, spec, path):
        types = types_of(spec)
        matching = {"object": type(value) is dict, "array": type(value) is list,
                    "string": type(value) is str, "boolean": type(value) is bool,
                    "integer": type(value) is int and finite_number(value),
                    "number": finite_number(value), "null": value is None}
        if not any(matching[t] for t in types):
            return [path + ":type"]
        errors = []
        if "enum" in spec and not any(same_scalar(v, value) for v in spec["enum"]):
            errors.append(path + ":enum")
        if value is None:
            return errors
        if type(value) is dict:
            props = spec["properties"]
            errors += [path + "." + k + ":missing" for k in props if k not in value]
            errors += [path + ":extra" for k in value if k not in props]
            for k in value.keys() & props.keys():
                errors += walk(value[k], props[k], path + "." + k)
        elif type(value) is list:
            if not spec.get("minItems", 0) <= len(value) <= spec.get("maxItems", math.inf):
                errors.append(path + ":length")
            for i, item in enumerate(value):
                errors += walk(item, spec["items"], path + "[" + str(i) + "]")
        elif finite_number(value):
            if not spec.get("minimum", -math.inf) <= value <= spec.get("maximum", math.inf):
                errors.append(path + ":range")
        return errors
    return walk(data, schema, "$")

def reject_constant(name):
    raise ValueError("非有限常量: " + name)

def unique_object(pairs):
    out = {}
    for key, value in pairs:
        if key in out:
            raise ValueError("重复键: " + key)
        out[key] = value
    return out

def parse(raw):
    if type(raw) is not str or len(raw.encode()) > 8192:
        raise ValueError("文本类型或大小不合法")
    return json.loads(raw, parse_constant=reject_constant, object_pairs_hook=unique_object)

SCHEMA = {"type": "object", "properties": {
    "name": {"type": ["string", "null"]},
    "price": {"type": ["number", "null"], "minimum": 0},
    "in_stock": {"type": ["boolean", "null"]},
    "evidence": {"type": "string"}},
    "required": ["name", "price", "in_stock", "evidence"], "additionalProperties": False}
gold = {"name": "机械键盘", "price": 99, "in_stock": True, "evidence": "机械键盘售价99元，现货。"}

def bounded_validate(raws, expected, attempts=2):
    if type(attempts) is not int or attempts <= 0:
        raise ValueError("次数须为正整数")
    feedback = []
    for i, raw in enumerate(raws):
        if i >= attempts:
            break
        try:
            candidate = parse(raw)
        except (ValueError, RecursionError):
            feedback.append({"attempt": i + 1, "errors": ["parse"]})
            continue
        errors = validate(candidate, SCHEMA)
        if not errors and candidate != expected:
            errors = ["business_gold"]  # 仅固定人工gold，不是通用事实判断器。
        if not errors:
            return {"status": "verified", "data": candidate, "attempts": i + 1, "feedback": feedback}
        feedback.append({"attempt": i + 1, "errors": errors})
    return {"status": "exhausted", "feedback": feedback}

assert validate(gold, SCHEMA) == []
assert validate(dict(gold, price=True), SCHEMA)
assert validate(dict(gold, price=math.nan), SCHEMA)
assert validate(dict(gold, price=math.inf), SCHEMA)
assert validate(dict(gold, extra=1), SCHEMA)
assert validate({k: v for k, v in gold.items() if k != "price"}, SCHEMA)
unknown = {"name": None, "price": None, "in_stock": None, "evidence": "未说明商品信息。"}
assert validate(unknown, SCHEMA) == []  # 未知不是0元/无库存。
for raw in ('{"price":NaN}', '{"price":99,"price":100}'):
    try:
        parse(raw)
    except ValueError:
        pass
    else:
        raise AssertionError("非有限常量/重复键须拒绝")
bad_schema = deepcopy(SCHEMA)
bad_schema["properties"]["name"]["pattern"] = ".*"
try:
    validate(gold, bad_schema)
except ValueError:
    pass
else:
    raise AssertionError("本地不支持pattern，不可静默跳过")
assert validate(True, {"type": "integer"})
assert validate(1, {"type": "number", "enum": [1.0]}) == []
assert validate(1.0, {"type": "number", "enum": [1]}) == []
assert validate(True, {"type": "boolean", "enum": [1]})
assert validate(1, {"type": "number", "enum": [True]})
for enum_value in ({"x": [True]}, [True], math.nan, math.inf):
    try:
        validate(1, {"type": "number", "enum": [enum_value]})
    except ValueError:
        pass
    else:
        raise AssertionError("嵌套/非有限enum必须在使用schema前拒绝")
fixed = bounded_validate([json.dumps(dict(gold, price="99")), json.dumps(gold)], gold)
assert fixed["status"] == "verified" and fixed["attempts"] == 2 and fixed["feedback"]
assert bounded_validate([json.dumps(dict(gold, price=100))] * 3, gold)["status"] == "exhausted"
assert bounded_validate([json.dumps(unknown)], unknown)["status"] == "verified"
print("严格局部schema：bool/非有限数/额外键/缺失/未知关键词/重复键拒绝，null与有界反馈通过")
print("标量enum：1与1.0相等、bool不等数字；嵌套/非有限enum预先拒绝通过")
```

这个重试例使用预先给定的候选，并保存准确错误；没有模型接收反馈或自动改正。source mock 仅按 attempt 返回固定值，打印错误不能称已把错误反馈给模型。客户端真正接入时，把错误和原输入版本传给下一次生成，并重新校验字段与证据；达到次数/时间上限返回 typed failure，不把猜出的默认值包装为成功。

## 10. 抽取契约、schema变更与练习

缺信息时应在 schema 中定义 `null/unknown` 或明确失败；数字0、布尔false都具有业务含义，不能作为“保守猜测”。额外 `_extraction_notes` 必须事先属于契约，否则会破坏禁止额外字段。嵌套深度、数组长度和字段顺序需按任务与接口验证，不从手写百分比、固定5–15%延迟或“最可靠提供商”排名推导。

1. **组合约束**：`oneOf` 要恰好一个子schema通过，`anyOf` 至少一个；本例均不支持，必须拒绝。需要完整规范时使用相应验证器，并区别服务端解码支持范围。
2. **schema diff**：先指定生产者/消费者方向。新增必填字段、允许额外键、nullable和枚举变化对不同方向的兼容性不同，不能给“删required”套一个无条件结论；迁移需版本和旧样本回归。
3. **约束生成**：复用前文有限前缀机的多字符token、EOS和incomplete测试。源码末字符启发式没有读schema，也没有跟踪转义/栈，不把它扩写成伪通用grammar compiler。
4. **抽取评价**：在独立gold上分别测解析、形状、字段值、覆盖与证据支持；未知、矛盾、否定及边界样本单列。源码固定商品输出不等于已经完成50条真实商品评测。
5. **字段可信度**：票比或token概率不是事实正确率。同一个错价出现三次仍错；证据核验、独立校准和弃答策略各有作用，不能用self-report confidence跳过原文。

源 quiz 中“each token independent”不正确：自回归token条件依赖前文；结构模式也可以做复杂抽取，不能把推理与 JSON mode 当互斥选择。原 Python number/bool混淆、未处理NaN、未知关键词跳过，自制TypeScript DSL忽略extra/接受Infinity，以及先对dict做哈希查表的错误，都以局部合同和反例纠正，未宣称改造了上游源码。

## 11. 引用支持与发票的业务核验

2026-10-08 再核[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) 的支持子集、引用、递归及 incomplete 段：当前支持 `$defs/$ref` 与符合子集的嵌套 `anyOf`，根对象不能是 `anyOf`；`allOf/not/if/then/else` 等不能直接假定受支持。原 Phase13 的“一律禁止 ref”“仅五层”“strict 只剩 refusal”不沿用。支持的完整非拒绝输出提供结构保证；输出预算耗尽、服务错误和错误事实仍要处理。Pydantic/Zod 负责定义或解析类型，框架是否启用约束解码需要另查；不能把一个 `.parse` 调用或原课自制 validator 当服务端采样约束。

发票能说明四层检查的区别。两行商品为 `2×49.99 USD` 和 `1×120.00 USD`，正确小计之和是 **219.98 USD**。相同 number 类型下，把单位标 EUR、把 total 写219.99、重复第一行证据或漏第二行，都仍是业务错误。原课 __REFUSAL__ 是模拟标记，非发票输入也不一定产生供应商的安全拒绝；应用可返回 `input_mismatch`。安全 refusal 不应通过自动换更强模型绕过。

金额应说明币种与最小货币单位。此例只支持 USD/EUR 的 cent，以整数 `unit_minor/total_minor` 表示：2×4999+12000=21998，避免二进制浮点小数累加。不是所有币种都有两位小数；跨币种求和需要明确汇率、日期、来源和舍入政策，本例直接拒绝币种不一致。税、折扣、运费和退货也不在本例合同，不能默认为零。

### 完整离线例：形状正确但总额、单位或证据错误

输入候选与独立 SOURCE fixture 分开。每行绑定 evidence_id，对照 SKU、数量和单价；分别从候选行计算候选总额、从 SOURCE 自有行计算来源总额，再核覆盖、重复、customer/source/currency与声明总额。候选把数量改为3且自洽合计26997，只报证据不符，不能把候选错误归成来源内部冲突。来源自己冲突时返回 conflict，不能偷偷改原文使候选通过。SOURCE 是固定教学 gold，不是开放文本事实验证器；没有运行真实抽取模型或财务系统。

```python
from copy import deepcopy

SOURCE = {
    "id": "invoice-fixture-1", "currency": "USD", "customer": "Acme",
    "rows": {"row-1": ("ABC-123", 2, 4999), "row-2": ("XYZ-9", 1, 12000)},
    "declared_total_minor": 21998,
}

def check_invoice(value, source):
    errors = []
    expected = {"customer", "currency", "line_items", "total_minor", "source_id"}
    if type(value) is not dict or set(value) != expected:
        return ["$:fields"]
    if (type(value["customer"]) is not str or not value["customer"]
            or len(value["customer"]) > 200):
        errors.append("$.customer:type_or_length")
    if type(value["currency"]) is not str or value["currency"] not in {"USD", "EUR"}:
        errors.append("$.currency:enum")
    if type(value["total_minor"]) is not int or not 0 <= value["total_minor"] <= 10**9:
        errors.append("$.total_minor:integer_range")
    rows = value["line_items"]
    if type(rows) is not list or not 1 <= len(rows) <= 20:
        return errors + ["$.line_items:array_length"]
    total, evidence_ids = 0, []
    for i, row in enumerate(rows):
        path = f"$.line_items[{i}]"
        if type(row) is not dict or set(row) != {"sku", "qty", "unit_minor", "evidence_id"}:
            errors.append(path + ":fields"); continue
        if (type(row["sku"]) is not str or not row["sku"]
                or type(row["qty"]) is not int or not 1 <= row["qty"] <= 10000
                or type(row["unit_minor"]) is not int or not 0 <= row["unit_minor"] <= 10**7
                or type(row["evidence_id"]) is not str):
            errors.append(path + ":typed_range"); continue
        total += row["qty"] * row["unit_minor"]
        eid = row["evidence_id"]
        evidence_ids.append(eid)
        if source["rows"].get(eid) != (row["sku"], row["qty"], row["unit_minor"]):
            errors.append(path + ":evidence_mismatch")
    if len(evidence_ids) != len(set(evidence_ids)):
        errors.append("$.line_items:duplicate_evidence")
    if set(evidence_ids) != set(source["rows"]):
        errors.append("$.line_items:coverage")
    if total != value["total_minor"]:
        errors.append("$.total_minor:sum_mismatch")
    if (value["source_id"] != source["id"] or value["customer"] != source["customer"]
            or value["currency"] != source["currency"]):
        errors.append("$:source_identity_or_unit")
    source_total = sum(qty * unit for sku, qty, unit in source["rows"].values())
    if source["declared_total_minor"] != source_total:
        errors.append("$:source_internal_conflict")
    return errors

good = {"customer": "Acme", "currency": "USD", "source_id": SOURCE["id"],
        "line_items": [{"sku": sku, "qty": qty, "unit_minor": unit, "evidence_id": eid}
                       for eid, (sku, qty, unit) in SOURCE["rows"].items()],
        "total_minor": 21998}
assert check_invoice(good, SOURCE) == []
for field, bad_value in (("total_minor", -1), ("total_minor", True),
                         ("total_minor", 21999), ("currency", "EUR"),
                         ("source_id", "invented")):
    assert check_invoice(dict(good, **{field: bad_value}), SOURCE)
for key, bad in (("qty", True), ("unit_minor", float("nan")), ("evidence_id", "row-2")):
    changed = deepcopy(good); changed["line_items"][0][key] = bad
    assert check_invoice(changed, SOURCE)
missing = deepcopy(good); missing["line_items"].pop()
assert "$.line_items:coverage" in check_invoice(missing, SOURCE)
wrong_candidate = deepcopy(good)
wrong_candidate["line_items"][0]["qty"] = 3
wrong_candidate["total_minor"] = 26997  # 3×4999+12000；候选自洽，但不符合来源。
assert check_invoice(wrong_candidate, SOURCE) == ["$.line_items[0]:evidence_mismatch"]
assert "$:source_internal_conflict" not in check_invoice(wrong_candidate, SOURCE)
contradictory = deepcopy(SOURCE); contradictory["declared_total_minor"] = 22000
assert "$:source_internal_conflict" in check_invoice(good, contradictory)
print("发票：2×4999+1×12000=", good["total_minor"], "USD cents；候选26997自洽但证据不符，来源总额独立核验；金额/币种/覆盖反例通过")
```

核对输出应为21998 USD cents。`currency=EUR`仍是合法枚举，却与来源USD不一致；换source_id、复用另一行evidence、漏行与原文声明合计冲突都不能成功。数字0和false不是unknown。
