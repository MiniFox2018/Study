# 10｜案例方法论

`self-llm` 的几个案例比“照着命令部署模型”更有长期价值，因为它们展示了如何从真实需求反推数据和训练方案。

## 1. 角色风格模型

角色模仿类案例的核心不是 LoRA，而是：

> **怎样把角色特征转化为可学习数据。**

数据需要覆盖：

- 语言习惯；
- 语气；
- 场景；
- 人物关系；
- 拒绝边界；
- 多轮一致性。

### 风险

如果只抽取经典台词，模型容易：

- 复读；
- 模板化；
- 无法泛化到新场景。

需要把原始语料转换成“任务—回答”训练样本。

## 2. 领域问答

例如数学类领域模型。

需要区分：

- 领域知识；
- 解题过程；
- 最终答案；
- 格式。

如果知识需要经常更新，RAG 可能比参数微调更合适。

如果需要形成稳定推理格式，SFT / RL 才更有价值。

## 3. 个人数字分身

个人表达风格建模核心在数据。

需要特别关注：

- 隐私；
- 数据授权；
- 身份冒充；
- 敏感记忆；
- 删除机制。

工程上应把：

```text
稳定人格/表达 → 参数
动态个人事实 → Memory / RAG
```

分开。

## 4. 综合应用系统

复杂案例通常会组合：

- Prompt；
- RAG；
- Agent；
- SFT；
- UI / API。

这说明真实系统不应强行用单一技术解决所有问题。

## 5. 案例设计模板

### 目标

要改变什么？

### 基线

原模型哪里不够？

### 数据

需要什么样本？

### 方法

Prompt / RAG / LoRA / Full FT / DPO / RL？

### 评测

如何证明改进？

### 部署

实际怎么用？

### 迭代

Bad Case 如何回流？

## 6. 最重要结论

不要从：

> “我想学 LoRA”

开始项目。

而要从：

> “我的系统在哪些可重复场景下失败？”

开始。

然后选择最小、最可验证的改动。
