# 10｜案例方法论

`self-llm` 的几个案例比“照着命令部署模型”更有长期价值，因为它们展示了如何从真实需求反推数据和训练方案。

## 1. 角色风格模型

角色模仿类案例的核心不是 LoRA，而是：

> **怎样把角色特征转化为可学习数据。**

数据需要覆盖：

- 语言习惯；
- 语气；
- 场景；
- 人物关系；
- 拒绝边界；
- 多轮一致性。

### 风险

如果只抽取经典台词，模型容易：

- 复读；
- 模板化；
- 无法泛化到新场景。

需要把原始语料转换成“任务—回答”训练样本。

## 2. 领域问答

例如数学类领域模型。

需要区分：

- 领域知识；
- 解题过程；
- 最终答案；
- 格式。

如果知识需要经常更新，RAG 可能比参数微调更合适。

如果需要形成稳定推理格式，SFT / RL 才更有价值。

## 3. 个人数字分身

个人表达风格建模核心在数据。

需要特别关注：

- 隐私；
- 数据授权；
- 身份冒充；
- 敏感记忆；
- 删除机制。

工程上应把：

```text
稳定表达规则 → 先用 Prompt/示例；确有需要再训练
动态个人事实 → 经授权的 Memory / RAG
```

分开。

## 4. 综合应用系统

复杂案例通常会组合：

- Prompt；
- RAG；
- Agent；
- SFT；
- UI / API。

这说明真实系统不应强行用单一技术解决所有问题。

## 6. 最重要结论

学习项目可以以“理解 LoRA”为目标，产物是能解释、运行并修改小实验；应用项目则应从“系统在哪些可重复场景下失败”开始。两种目标应分别验收，教学实验成功不等于解决了真实业务问题。

然后选择最小、最可验证的改动。

## 7. 一个完整但很小的案例设计

**目标**：本地文档问答回答“请假申请需要哪些材料”，并标出证据段。**基线**：直接把现行制度全文放入上下文；如果全文足够短且表现可靠，暂不建向量库。**失败样例**：旧制度混入、同名条款、文档缺答案、用户无访问权限。

若输入过长才引入检索，记录每个问题应召回的证据 ID；若检索正确却回答错误，修改上下文组织或生成约束；若找不到答案，要求明确证据不足。评测时分别核对证据命中、答案正确、引用对应、权限遵守与成本，而不是只保存一段看起来不错的演示。

**自检**：基线已经能答对全部练习题，还要不要加入微调？

**核对**：应用目标下先停止增加复杂度；扩大有代表性的验证，确认实际需求是否满足。若目标是学习微调，可另做隔离实验，并明确它尚无业务增益证据。


## 8. 从需求走到可追责的请求流水线

生产案例先冻结任务、数据访问、输出schema与成功/unknown/失败分母，再决定组件。以制度问答为例：鉴权→请求与预算admission→选模板/实验版本→授权检索→同身份/数据版本cache→模型尝试→结果/引用/权限检查→记录usage/trace→候选门禁。任一关键权限/guardrail不可用应fail closed或返回明确定义的不可服务状态，不能为了“优雅降级”偷偷关闭。缓存代码见[推理与服务化第15节](03-推理与服务化.md)，预算/计费见[资源感知优化](../Agentic%20Design%20Patterns/01-核心章节/16-资源感知优化.md)。

错误分成输入/schema/身份权限、瞬态供应商错误、deadline/cancel、语义输出失败和未知副作用状态。重试需上限、deadline、backoff与Retry-After；参数/权限错误不原样重试。换供应商还要重新核数据出站许可、模板、工具、输出和质量合同，不能把已生成一半的旧文本与新模型片段拼成一次成功。写动作超时可能已执行，先查询receipt/幂等状态，不能直接再次写。

下面完整runner只消费预设尝试结果，时间为虚拟duration，不睡眠/联网。每次尝试都有独立账本记录，失败已知usage照计，unknown费用保持未结；输出拒绝不改原usage。deadline只验证事件模型，未实现真实网络取消。

```python
from dataclasses import dataclass
from decimal import Decimal as D

@dataclass(frozen=True)
class Attempt:
    status:str;duration:int;input_tokens:int;output_tokens:int;answer:str='';usage_known:bool=True

def run(attempts,deadline,max_attempts=3,output_ok=lambda x:x=='申请表',mutating=False):
    if type(deadline) is not int or deadline<=0 or type(max_attempts) is not int or max_attempts<1:raise ValueError('预算')
    elapsed=0;trace=[];spent=D(0);unknown=[];result='failed'
    for i,a in enumerate(attempts[:max_attempts],1):
        if any(type(x) is not int or x<0 for x in [a.duration,a.input_tokens,a.output_tokens]):raise ValueError('尝试记录')
        if elapsed+a.duration>deadline:
            result='deadline';break  # fixture假设未dispatch；真实inflight费用另核。
        elapsed+=a.duration
        cost=(D(a.input_tokens)+2*D(a.output_tokens))/1000 if a.usage_known else None
        if cost is None:unknown.append(i)
        else:spent+=cost
        row={'attempt':i,'status':a.status,'duration':a.duration,'input_tokens':a.input_tokens,'output_tokens':a.output_tokens,'known_cost':str(cost) if cost is not None else None}
        trace.append(row)
        if a.status=='ok':result='accepted' if output_ok(a.answer) else 'output_rejected';break
        if a.status=='ambiguous_write' or (mutating and a.status=='timeout'):
            result='reconcile_required';break
        if a.status not in {'transient','timeout','rate_limited'}:break
    return {'status':result,'virtual_elapsed':elapsed,'spent_units':spent,'unknown_usage_attempts':unknown,'trace':trace}
r=run([Attempt('transient',2,100,0),Attempt('ok',3,100,10,'申请表')],deadline=8)
assert r['status']=='accepted' and r['spent_units']==D('.22') and len(r['trace'])==2
blocked=run([Attempt('ok',1,100,40,'无证据猜测')],8)
assert blocked['status']=='output_rejected' and blocked['spent_units']==D('.18') and blocked['trace'][0]['output_tokens']==40
pending=run([Attempt('timeout',1,100,0,usage_known=False)],8,mutating=True)
assert pending['status']=='reconcile_required' and pending['unknown_usage_attempts']==[1]
assert run([Attempt('ok',9,0,0,'申请表')],8)['status']=='deadline'
print('重试已知总费',r['spent_units'],'输出拒绝保原usage',blocked['spent_units'],'未知写状态不重复',pending['status'])
```

Trace每个span保request/run ID、父子关系、阶段、status、版本/模型、实际单调clock时间、usage与错误类型，脱敏资料别直接放日志。多个并行span的时长之和不等端到端延迟；依赖health需probe和超时策略，不是返回固定healthy。原源20个async canned请求不是100真实用户或容量结论，缓存/账本/内存状态多worker间也不会自动共享。这里console记录不是OpenTelemetry exporter/collector集成。

## 9. 候选门禁、A/B和回滚要绑定版本

实验variant应在完整流水线前稳定分配，cache key包含variant/template/data/model；shadow仍消耗费用、处理数据且可能调用有副作用工具，须独立授权和禁写。评价同case ID、失败/unknown、切片、区间与严重错误，沿用[评测与实验管理](06-评测与实验管理.md)，不要把100题2×错误率当通用自动回滚定律。Prompt registry保不可变revision与alias，回滚alias后也使相关cache失效；模型/量化候选验收应绑定实际artifact SHA，见[模型交付](16-预训练数据与模型交付实践.md)。

## 10. 综合应用原练习怎样验收

第13课五题：①RAG先分离retrieval与生成失败、同case比较，20doc/top3只是题设，现有RAG主章维护完整算法，未跑真实模型质量；②function calling不是文本声称“用了工具”，登记调用ID/参数/身份/结果与tools_used，工具/结构化合同由相关主章维护，本批未调外部天气/搜索；③按用户日账期/总账原子预留与实际结算，.50/$100/2000token及某便宜型号是题设，不能直接作当前生产阈值；④版本diff和paired证据优先，100题2×错误率不保证显著性或业务损失；⑤每span duration与父子trace必须真实测量，没启动OTel不可称端到端追踪完成。

## 11. 综合案例先冻结输入、产物与证据

研究报告系统的输入应是“明确主题、已授权资料范围、输出字段/长度、允许的动作和预算”，而非只有“帮我调研”一句话。输出应是可核对报告、证据对应关系、来源/数据版本、任务状态和未完成边界。只有需要独立远端委托、异步状态或交互界面时，再加入相关协议。若直接读取少量材料已能达成目标，完整生态并不是必选。

举一个封闭的教学案例：Alice 获准使用 t1 的两段制度材料 `policy:7` 与 `policy:9`，要求列出申请材料，报告只生成在本地，不发送。Bob 只获准检索自己的资料。成功要求不是“出现HTML”，而是：Alice 的报告只含被授权证据，字段和出处对应；Bob 的生成动作拒绝且无报告效果；暂停/失败/取消有明确状态；重启以后能读回同一结果，不能重新写一份报告。

需要分别管理五种身份：认证主体 `(tenant,actor)`、业务操作 key、MCP task ID、A2A task/message ID、trace/span ID。操作 key 定位可能产生副作用的同一动作；task ID 定位工作状态；trace ID 定位可观测轨迹。它们都不替代授权，也不能互换。某任务在恢复后可以跨多个短 trace，通过受控任务关联字段链接；不能把前一天已结束的 request span 假装仍覆盖所有后续轮询。

### 调用边界与状态的唯一维护入口

MCP 发现、工具/资源/提示与每请求metadata，由[MCP主章](../Agentic%20Design%20Patterns/01-核心章节/10-模型上下文协议-MCP.md)维护。当前固定2026-07-28，client每次请求携带版本、clientInfo、clientCapabilities；连接没有旧session也不意味着业务无状态。异步工作依然要存 task/owner/输入摘要/TTL/结果。MCP Tasks 是独立扩展：初次工具返回 task handle，poll用 `tasks/get`，completed Task携带最终result；不要混用旧 `tasks/result` 或 A2A `GetTask` 的对象。

多个后端同名工具要用明确公开名，例如 `research::search` 和 `archive::search`，映射到唯一backend/tool identity；gateway发现过滤与直接调用都核当前政策，不能“列表里隐藏所以无法调用”。完整descriptor的pin/准入与OAuth、精确动作授权由[安全模式](../Agentic%20Design%20Patterns/01-核心章节/18-安全模式.md)维护。静态token或clientInfo声明只用于教学数据，不证明真人身份、issuer/audience/expiry检查。外层凭据与后端凭据分别持有，不能把用户token随A2A/MCP转发给任意peer。

写报告的远端委托用[A2A通信](../Agentic%20Design%20Patterns/01-核心章节/15-智能体间通信-A2A.md)的Card/media/interface、SendMessage与任务归属合同。只有边界span和artifact可见，也可以足够定位整体成功与失败；不能为了“完整trace”要求对方公开私人推理。模型候选与fallback用[路由](../Agentic%20Design%20Patterns/01-核心章节/02-路由.md)先筛许可范围，每hop消耗同一预算并重核政策。采样与usage不能取代任务质量验证。

交互界面关联一个不可变report identity/version，Host通过真实MCP Apps资源与bridge加载，App的 `app.callServerTool({name,arguments})` 请求仍经Host政策与服务端授权。加载状态、最近一次result、用户选中项等App state不是凭据，恢复界面时先核报告归属与当前权限。CSP约束资源/连接来源，iframe sandbox与权限限制执行能力，服务端限制能读取或修改什么；三者互补。把HTML字符串或 `ui://report/current` 写入Python字典，既没有浏览器执行，也没有bridge/CSP证据。课程自造 `ui_resource` block 不能直接当现行MCP content类型。

trace按[评估和监控](../Agentic%20Design%20Patterns/01-核心章节/19-评估和监控.md)注入/提取，在真实接收端核parentage、error、数量与export。业务鉴权、descriptor检查、委托和报告提交失败都应留下脱敏决策记录；不把secret、原资料全文或凭据放进日志。只打印相同traceId不证明传播，生成`ui://`不证明渲染。

### 断点选择决定恢复动作

| 观察到的断点 | 已知证据与状态 | 正确恢复 |
| --- | --- | --- |
| schema/授权检查未通过 | 未dispatch，没有业务effect | 修输入或授权；记录拒绝，不创建伪成功任务 |
| task已创建、委托尚未发出 | 持久owner、输入摘要、待办与TTL | 当前权限仍有效时继续；每次出站重新准入 |
| SendMessage发出、响应丢失 | 是否接收/执行未知 | 查已知task/message的去重/状态合同；无保证时保留unknown，不新建同效果任务 |
| writer要求输入或授权 | INPUT_REQUIRED / AUTH_REQUIRED与请求内容 | 按原task补充信息或完成外部授权，精确绑定动作；状态本身不授权 |
| 报告effect已提交、task completed未写回 | 同操作key的可验证receipt与产物摘要 | 核receipt/输入一致后补回状态与结果，不再生成报告 |
| App断线/重载 | 可能只有旧view state | 重新读权威任务与report version，再核权限；不重复按钮对应的写动作 |
| collector部分拒收/后端不可查 | 可观察证据不完整 | 修instrument/export，保业务结果与telemetry故障分开；不称全链路已验 |
| TTL已过、取消或权限撤销 | 当前不可继续 | 返回明确终态/不可访问；过期副作用另按receipt对账，不能重放旧许可 |

同一个数据库内业务effect与receipt可放在一个事务；跨第三方写入不能靠本地事务保证原子。若先写远端再保存本地receipt时崩溃，恢复需要远端业务幂等key/可查询receipt或人工对账；查不清就停在reconcile_required，不能承诺恰好一次。任务的终态还应与效果区分：已生成的报告不会因取消状态自动删除。

## 12. 可运行的报告提交与重启恢复实验

下面程序输入可信认证边界给出的身份、每请求meta和带evidence/version的报告参数；输出本地MCP任务形状的工作/完成状态、不可变report reference与receipt。它模拟“业务提交后，worker在写completed前退出”，再关闭/重开SQLite恢复；另检查同名工具必须qualified、缺Tasks能力、只读主体拒绝、归属、输入key冲突、TTL和界面读取时撤权。时间为虚拟值，任务轮询间隔为1；提前poll拒绝，TTL不随poll延长。

程序只实现该封闭案例需要的本地合同子集。外部身份、MCP envelope、A2A委托、App bridge和telemetry在正文有独立验收要求，代码没有运行它们；存储的trace link也只是恢复关联资料。本地report是固定教学文本，不称真实调研或模型摘要。

```python
import hashlib, json, sqlite3, tempfile
from pathlib import Path

VERSION='2026-07-28'; EXT='io.modelcontextprotocol/tasks'
def encode(x): return json.dumps(x,sort_keys=True,separators=(',',':'),allow_nan=False)
def digest(x): return hashlib.sha256(encode(x).encode()).hexdigest()
def meta():
    return {'io.modelcontextprotocol/protocolVersion':VERSION,
            'io.modelcontextprotocol/clientInfo':{'name':'fixture','version':'1'},
            'io.modelcontextprotocol/clientCapabilities':{'extensions':{EXT:{}}}}
grants={('t1','alice'):{'read','write'},('t1','bob'):{'read'}}
def authorize(actor,tenant,scope):
    if scope not in grants.get((tenant,actor),set()): raise PermissionError('当前scope不足')
def check_meta(m):
    if m.get('io.modelcontextprotocol/protocolVersion') != VERSION: raise ValueError('版本')
    if EXT not in m.get('io.modelcontextprotocol/clientCapabilities',{}).get('extensions',{}):
        raise ValueError('本次请求缺Tasks capability')
class Reports:
    def __init__(self,path,clock):
        self.db=sqlite3.connect(path);self.clock=clock
        self.db.executescript('''
          CREATE TABLE IF NOT EXISTS jobs (
            task TEXT PRIMARY KEY, actor TEXT, tenant TEXT, operation TEXT,
            input_sha TEXT, state TEXT, expires INTEGER, poll_due INTEGER,
            trace_link TEXT, result TEXT);
          CREATE TABLE IF NOT EXISTS receipts (
            operation TEXT PRIMARY KEY, input_sha TEXT, report TEXT);''')
    def getrow(self,actor,tenant,task):
        authorize(actor,tenant,'read')
        row=self.db.execute('SELECT * FROM jobs WHERE task=? AND actor=? AND tenant=?',
                            (task,actor,tenant)).fetchone()
        if row is None or self.clock() >= row[6]: raise LookupError('不可访问或过期')
        return row
    def submit(self,actor,tenant,operation,args,m):
        check_meta(m);authorize(actor,tenant,'write')
        if set(args)!= {'evidence','data_revision','format'} or args['format']!='text':
            raise ValueError('报告合同')
        if args['evidence']!=['policy:7']: raise ValueError('教学资料授权范围')
        key=encode([tenant,actor,'research::generate_report',operation]);sha=digest(args)
        task='task-'+digest(key)[:16]
        old=self.db.execute('SELECT input_sha FROM jobs WHERE task=? AND actor=? AND tenant=?',
                            (task,actor,tenant)).fetchone()
        if old:
            if old[0]!=sha: raise ValueError('同操作key不同输入')
            self.getrow(actor,tenant,task)
        else:
            with self.db:
                self.db.execute('INSERT INTO jobs VALUES (?,?,?,?,?,?,?,?,?,?)',
                  (task,actor,tenant,key,sha,'working',self.clock()+10,self.clock()+1,
                   encode({'traceId':'a'*32,'spanId':'b'*16}),None))
        return {'resultType':'task','taskId':task,'status':self.getrow(actor,tenant,task)[5],
                'pollIntervalMs':1000}
    def commit_report(self,actor,tenant,task,args,crash_after_effect=False):
```

## 14. 需求、实验与成果验证

2026-10-09增量：先明确要改变的真实工作与未知，再选择可测试切片、规格、指标和阶段。例子是教学场景，不能从仓库素材推断你已做过访谈、试点或生产交付。

### 成果先于产物：定义实际改变

案例设计先写user、situation、current behavior、desired outcome、constraints、non-goals。产物是要求交付的文件/功能；成果是它使谁在什么情况下发生了可观察改变。用户明确要文件时应完成文件及验证，不能借成果讨论拖延交付；也不能用文件数量证明业务改变。

封闭教学例：值班者现在查三个页面找故障服务，希望在代表性事件回放中更快且正确定位，始终只读。网页助手、改runbook或整理部署索引都可能实现同目标。两分钟只是题设；达到速度却误判或越权仍失败。技术名仅在真实兼容约束锁定它时进入目标，不要先决定向量库再寻找问题。

**原实验与源码的实际边界**：原lab校验OutcomeFrame写JSON，把成果改成“使用事故助手”应识别产物泄漏。实际substring只能抓局部，换同义词可漏；current三个页面与两分钟均手造。验收是可观察目标、真实限制和反证，不是ready-to-discover字符串。

**原实验与源码的实际边界**：原lab编译六面与mode写spec，改production-write为delegated并解释schema通过但业务拒。actual compile只非空/枚举，无执行器且无法发现与只读冲突；十回放/零写文字不是receipt。验收要每不变量的相应层证据与语义矛盾检查。

### 成果指标、护栏与代价转移

先goal→question→metric，再选择数据源，避免先dashboard后解释。每指标有对象/人群、case分母、窗口、source、候选与基线、单位、方向、阈值、缺失/排除政策。outcome量实际改变，guardrail守硬约束，counter-metric发现把成本转给审核/运维/客户。提前定pass/fail/ambiguous与下一动作，不能为已造产品改阈值。

诊断中位耗时应保错误、超时与未识别病例的处理；只算成功会奖励不回答难题。正确率分母含相应失败/unknown，零写须可信执行边界记录，不是agent自报0。有限数、类型与范围都校验，NaN/False不可充数。9/10只是小样本点估计，不是总体90%保证，代表性、切片、区间与严重错误另判。


#### 完整离线例：候选slice与成果、护栏、代价转移

planned_proof描述计划获取什么，不是已取得证据。选片先排无许可项；case、seconds、writes和correct是合成观察，不能当真实用户效果。阈值先核有限类型与范围；缺case/缺观测保ambiguous，拒绝越权和把劳动转给审核者的假收益。

```python
from dataclasses import dataclass
from math import isfinite
from statistics import median

@dataclass(frozen=True)
class Slice:
    name: str
    planned_proof: frozenset[str]
    effort: float
    permitted: bool

def choose(candidates, required):
    if not required:
        raise ValueError('缺必要proof')
    eligible = []
    for candidate in candidates:
        if type(candidate.permitted) is not bool:
            raise ValueError('权限字段')
        if not candidate.permitted:
            continue
        if type(candidate.effort) not in (int, float) or not isfinite(candidate.effort) or candidate.effort <= 0:
            raise ValueError('代价')
        if candidate.permitted and required <= candidate.planned_proof:
            eligible.append(candidate)
    return min(eligible, key=lambda c: (c.effort, c.name)).name if eligible else None

# 每行为同一case的fixture观察；seconds=None仍留分母。
# 这不是实际用户、事故或生产审计。
def decide(rows, expected_ids, max_seconds=120, min_correct=.8, max_review_seconds=30):
    for value in (max_seconds, min_correct, max_review_seconds):
        if type(value) not in (int,float) or not isfinite(value):
            raise ValueError('有限数值阈值')
    if max_seconds <= 0 or max_review_seconds < 0 or not 0 <= min_correct <= 1:
        raise ValueError('阈值范围')
    if not expected_ids or len({r['id'] for r in rows}) != len(rows):
        raise ValueError('空人群/重复case')
    if any(r['id'] not in expected_ids for r in rows):
        raise ValueError('外来case')
    uncertain = len(rows) != len(expected_ids)
    times, reviews, correct = [], [], 0
    for row in rows:
        if type(row['writes']) is not int or row['writes'] < 0 or type(row['correct']) is not bool:
            raise ValueError('护栏/正确类型')
        if row['writes'] > 0:
            return 'fail-guardrail'
        for name, target in [('seconds', times), ('review_seconds', reviews)]:
            value = row[name]
            if value is None:
                uncertain = True
            elif type(value) not in (int, float) or not isfinite(value) or value < 0:
                raise ValueError('非有限观测')
            else:
                target.append(value)
        correct += row['correct']
    if uncertain:
        return 'ambiguous'
    if correct / len(expected_ids) < min_correct or median(times) > max_seconds or median(reviews) > max_review_seconds:
        return 'fail-outcome-or-countermetric'
    return 'pass-fixture'

required = frozenset({'data', 'diagnosis'})
candidates = [Slice('mockup', frozenset({'ui'}), 1, True),
              Slice('readonly-replay', required, 3, True),
              Slice('unapproved-production', required, .1, False)]
assert choose(candidates, required) == 'readonly-replay'
assert choose(candidates+[Slice('disabled', frozenset(), float('nan'), False)], required)=='readonly-replay'
rows = [{'id': i, 'seconds': 80+i, 'correct': True, 'writes': 0, 'review_seconds': 10}
        for i in range(5)]
assert decide(rows, set(range(5))) == 'pass-fixture'
assert decide(rows[:-1], set(range(5))) == 'ambiguous'
assert decide([{**r, 'seconds': None} for r in rows], set(range(5))) == 'ambiguous'
assert decide([{**r, 'writes': 1} for r in rows], set(range(5))) == 'fail-guardrail'
assert decide([{**r, 'correct': False} for r in rows], set(range(5))) == 'fail-outcome-or-countermetric'
assert decide([{**r, 'review_seconds': 50} for r in rows], set(range(5))) == 'fail-outcome-or-countermetric'
for value in (float('nan'), False):
    try:
        decide([{**r, 'seconds': value} for r in rows], set(range(5)))
    except ValueError:
        pass
    else:
        raise AssertionError('坏值未拒绝')
for threshold in (float('nan'), True, float('inf')):
    try:decide(rows, set(range(5)), min_correct=threshold)
    except ValueError:pass
    else:raise AssertionError('非法阈值不能放行')
print('outcome: 先硬筛slice；缺case/耗时未知保ambiguous；越权/错误/审核转移失败')
```

## 15. 编码Agent：把“完成”变成可复验的补丁

2026-10-11 融合 Phase19 第01课。先修是本章的输入、产物和证据合同，以及[生产级软件工程](../计算机科学基础/05-生产级软件工程.md)的测试与Git。终端UI负责接受任务、显示当前步骤、工具结果、预算及取消状态；它不决定补丁正确性。先做一条能稳定复现的失败用例，再让Agent产生候选，最后用独立定义的验证接受最终版本。这是最小可学路径，不必一开始加入云沙箱、MCP、多个模型和TUI框架。

### 15.1 计划、执行、观察、恢复怎样接起来

以“修复空列表平均值错误”为例，输入冻结仓库与base commit、行为要求（空列表应报明确异常）、允许文件、测试命令和预算。第一轮只定位函数及测试，保存读到的文件版本；第二轮补一个在旧代码上失败的回归用例，再产生最小补丁；第三轮运行回归和相关集成测试。最终交付是diff、base/head、实际验证回执、成本与未覆盖条件。模型声称“done”只是候选状态；必须有“旧代码失败、新代码通过”及相关功能没回归的证据。

每轮控制链为：载入目标/依赖/证据→提出计划和工具请求→可信dispatcher核schema、当前权限及资源→执行→保存结果→决定恢复或停止。工具观察至少包含调用ID、完整参数摘要、执行目录/环境版本、exit code、stdout/stderr、时间、效果状态和是否截断。下一次模型调用真正消费这份观察，才是闭环。全量重写Todo列表是可选策略；不允许因此丢掉稳定task ID、依赖、不变量或失败回执。工具报错后的恢复可缩小检索、改路径或修输入；未知写效果先对账，[异常处理与恢复](../Agentic%20Design%20Patterns/01-核心章节/12-异常处理和恢复.md)维护其唯一合同。

源Python只按固定SCRIPT先ls、再读README、最后全done；工具观察没有反馈给model，示例目录缺README也不改变最后状态。TS的run_shell只是返回固定字符串；三个所谓eval任务都走同一脚本。它们能帮助读清模块（plan/model/tools/hooks/harness/eval），但不证明写出正确补丁、真正修改Git或通过SWE基准。自主Agent的停止原因应分complete、failed、cancelled、budget和reconcile_required；预算停止即使计划全done也不能视作已验证成功。

### 15.2 工作树、沙箱与输出限额

Git worktree有独立checkout、index和HEAD，却共享仓库对象库、普通refs及默认配置。它减少并行文件覆盖，**不隔离宿主文件、密钥、进程或网络**。`cwd=worktree`只决定相对路径起点；`shell=False`减少shell解释风险，也不能阻止允许的解释器读外部文件或发网络请求。实际执行需独立的挂载/用户、资源/进程时限、网络出口和凭据范围；外发push/PR凭据优先由受控发布器持有。[Git官方说明](https://git-scm.com/docs/git-worktree)、[工具授权与发布治理](../Agentic%20Design%20Patterns/06-专题扩展/07-工具授权与发布治理.md)。

路径检查也有层次：字符串`realpath(candidate).startswith(root)`会把`/tmp/task-other`误当`/tmp/task`子目录；应按路径component核包含关系。TS用realpath加分隔符改善这一点，但resolve到open之间仍有符号链接变更风险，不能据此承诺任意不可信代码已被隔离。拦`rm -rf`的regex是提醒，无法阻止选项重排、解释器内文件操作或新程序。生命周期hook是应用的政策/观测扩展点，来源列出的八个名称不是跨产品通用、永不变化的标准。

大输出先限制采集字节和进程资源，再保存受控原件与hash、提供分块检索和上下文摘要。`readFileSync(...).slice(4096)`先把整文件读进内存，且4096是JS字符串长度，不是字节或token；Python字符切片也不等字节。截断标记和原件入口使尾部错误仍可核验，避免只看前4k就宣称测试通过。MCP stdio/HTTP的选择见现有[MCP工程合同](../Agentic%20Design%20Patterns/06-专题扩展/06-MCP通信与状态工程.md)：Streamable HTTP可使用SSE，不是“所有SSE都被取代”，协议传输也不替代执行隔离。

费用预算与context窗口分别记录：累计计费token、当前输入长度、预留输出、次数/墙钟和已知/未知费用。派发前预留可能的上限，结束后结算；仅下一轮检查已经超额的费用不是硬预算。取消清理走finally并保存断点，不能先删除未交付diff。保goal/plan版本、base/head、工具效果回执和账本，再恢复；摘要只压缩文字，不覆盖权威状态。

### 15.3 完整离线例：验收绑定最终HEAD

输入candidate和TestReceipt都是可信边界提供的**合成fixture**，不是Agent自由文本。本例检查最终base/head/环境、独立必测用例、真实执行状态、skip/失败和停止原因。它没有读取仓库或运行测试命令，也没有验签，因此不能把下面手造回执复制到生产就声称CI成功。真实接入时由受控runner生成这些事实，并另外核coverage、安全、集成和发布规则。

```python
from dataclasses import dataclass, replace
import re

SHA = re.compile(r'[0-9a-f]{40}')

@dataclass(frozen=True)
class Candidate:
    base: str
    head: str
    environment: str
    permitted: bool
    stop_reason: str | None = None

@dataclass(frozen=True)
class TestReceipt:
    base: str
    head: str
    environment: str
    command_id: str
    exit_code: int | None
    cases: tuple[str, ...]
    failures: tuple[str, ...] = ()
    skipped: tuple[str, ...] = ()

# candidate/receipt are trusted-boundary fixture observations in this example.
# No repository, command, model, signature or CI service runs here.
def gate(candidate, receipts, expected):
    if type(candidate) is not Candidate or type(candidate.permitted) is not bool:
        raise ValueError('候选合同')
    if not all(type(s) is str and SHA.fullmatch(s) for s in (candidate.base, candidate.head)):
        raise ValueError('完整提交ID')
    if type(candidate.environment) is not str or not candidate.environment:
        raise ValueError('环境ID')
    if candidate.stop_reason is not None and (type(candidate.stop_reason) is not str or not candidate.stop_reason):
        raise ValueError('停止原因')
    if not candidate.permitted:
        return 'blocked: scope'
    if candidate.stop_reason is not None:
        return 'unfinished: stopped'
    if type(expected) is not dict or not expected:
        raise ValueError('独立定义必要验证集合')
    for name, cases in expected.items():
        if (type(name) is not str or not name or type(cases) is not frozenset or not cases or
            any(type(c) is not str or not c for c in cases)):
            raise ValueError('验证项/用例集合')
    if type(receipts) not in (list, tuple):
        raise ValueError('回执序列')
    seen = set()
    for r in receipts:
        if (type(r) is not TestReceipt or type(r.command_id) is not str or not r.command_id
            or r.command_id not in expected or r.command_id in seen):
            raise ValueError('未知或重复回执')
        seen.add(r.command_id)
        if (r.base, r.head, r.environment) != (candidate.base, candidate.head, candidate.environment):
            return 'unfinished: stale receipt'
        for values in (r.cases, r.failures, r.skipped):
            if (type(values) is not tuple or any(type(c) is not str or not c for c in values)
                or len(set(values)) != len(values)):
                raise ValueError('回执用例合同')
        if not set(r.failures) <= set(r.cases) or not set(r.skipped) <= set(r.cases):
            raise ValueError('失败/跳过归属')
        if r.exit_code is None:
            return 'unfinished: unknown execution'
        if type(r.exit_code) is not int:
            raise ValueError('退出码不能用bool')
        if r.exit_code != 0 or r.failures or r.skipped:
            return 'failed: verification'
        if frozenset(r.cases) != expected[r.command_id]:
            return 'unfinished: missing cases'
    return 'accepted-fixture' if seen == set(expected) else 'unfinished: missing receipts'

c = Candidate('a'*40, 'b'*40, 'image:fixture-v1', True)
required = {'regression': frozenset({'normal', 'empty', 'edge'})}
r = TestReceipt(c.base, c.head, c.environment, 'regression', 0, ('normal', 'empty', 'edge'))
assert gate(c, [r], required) == 'accepted-fixture'
assert gate(c, [], required) == 'unfinished: missing receipts'
assert gate(c, [replace(r, cases=('normal',))], required) == 'unfinished: missing cases'
assert gate(replace(c, head='c'*40), [r], required) == 'unfinished: stale receipt'
assert gate(c, [replace(r, exit_code=None)], required) == 'unfinished: unknown execution'
assert gate(c, [replace(r, failures=('edge',))], required) == 'failed: verification'
assert gate(c, [replace(r, skipped=('edge',))], required) == 'failed: verification'
assert gate(replace(c, stop_reason='budget'), [r], required) == 'unfinished: stopped'
assert gate(replace(c, permitted=False), [r], required) == 'blocked: scope'
for bad in [replace(r, exit_code=True), replace(r, failures=('not-owned',))]:
    try: gate(c, [bad], required)
    except ValueError: pass
    else: raise AssertionError('坏回执未拒绝')
try: gate(c, [r, r], required)
except ValueError: pass
else: raise AssertionError('重复回执未拒绝')
print('最终HEAD/环境绑定：缺回执、缺用例、失败、skip、未知、预算停止和旧HEAD不通过；完整fixture通过')
```

若在通过后又改一行，旧head回执就失效。不是必须所有系统都禁止skip，而是本例先冻结“这些必要用例不得skip”的教学合同；真实平台可有获批排除，但必须进入验证计划版本，不能悄悄减少分母。到真实项目阶段，应先完成单个失败/修复/反例链，再扩到固定holdout，匹配相同任务SHA、环境、预算与尝试策略的baseline。pass@1指一个完整受预算限制的独立运行最终解决任务的比例，允许该运行内部修复；不把多个完整重跑挑最好结果再称pass@1。

## 16. 代码迁移：规则先行、反馈补齐、最终版本验收

2026-10-11 融合 Phase19 第09课。迁移改变的是语言/runtime、构建和依赖，目标是保留明确的行为契约，不是让Agent返回“升级完毕”。先保存base SHA、旧环境可复现构建、测试清单/skip、覆盖配置与关键输入输出，才能区分旧问题与迁移引入的回归。无法重建旧基线时明确unknown，不把新环境启动成功当行为保持。

### 16.1 一条仓库迁移流水线

先在固定目标环境上应用有适用条件的确定性recipe，独立提交并审diff；然后build。红构建的错误按移除API、依赖、构建插件、语法或测试行为归类，Agent只处理剩余长尾，每轮保错误→目标修改→重新验证的链。绿色构建之后仍要执行冻结的测试、关键行为、lint及覆盖比较；最终head绑定第15节的回执门禁。输出可审分支、机械与Agent修改归属、证据和未知；失败输出当前diff、最小重现、预算及停止事实，而不是强行开“成功PR”。

例如Java升级暴露旧BASE64 API：先确认原功能的编码、换行及错误处理契约，再选当前等价API、修改调用并核正常和异常输入。能编译不证明编码输出仍等价。OpenRewrite的Java17复合recipe可更新构建target/source、补不再由JDK附带的库、升级兼容插件并替代有明确策略的旧API；CST/AST规则可预测不等自动语义正确。核验2026-10-11时，该具体复合recipe文档标为**Moderne Source Available License**，不把引擎、全部recipe和托管平台统一理解为无限制免费商用；使用具体artifact前固定版本、核许可和适用范围。[官方recipe的范围与许可](https://docs.openrewrite.org/recipes/java/migrate/upgradetojava17)。

Python迁移同样先确认解析能力。LibCST保留注释、空白和括号，适合Python3代码的可审codemod；它不是直接解析原Python2 `print x`的完整迁移器。最新所核[README固定版](https://github.com/Instagram/LibCST/blob/d9a255843b5cdbecc6834684d233bce1f2987f9d/README.rst)描述Python3语法，parser文档中的旧版本列表不能当最新支持上限。遗留旧语法先选能处理它的适配路径，再核除法、str/bytes、迭代器、异常和依赖等语义。不能用“有CST”承诺覆盖所有迁移。

### 16.2 覆盖、失败分类和成本的分母

覆盖80%→78%是下降**2个百分点**，相对下降2%则阈值为78.4%；政策要先写清。源概念要求不下降，Build又容忍2%，不应同时作为同一个门禁。本章采用“冻结项目政策，超限不当已验证成功”，具体阈值由真实需求决定。比较同工具、配置、排除和覆盖对象变化；删难测代码或新增skip让数字更漂亮不是行为保持证明，行覆盖也不代表断言质量。

失败至少保两轴：停止原因（预算、构建失败、超时）和有证据的诊断（依赖、插件、API、flake、未知）。源Python耗尽预算后随机改成另一类原因，会丢失原事实；正式记录同时保原因和诊断置信边界。分类的实际作用是把重复、可规则化的失败变成下一版recipe，而非自动补全一个看似精确的饼图。

matched baseline在相同base/目标runtime/验证集合和预算上比较recipe-only与recipe+Agent；统计全部失败费用、成功数、首绿构建时间及最终解题结果。源50个随机Repo、随机coverage与成功概率只是模拟，TS逐文件状态推进只是dashboard；没有真实recipes/build/test。官方MigrationBench介绍5102个Java8 Maven项目与300代表子集，Java目标可为17/21；“50 repo”是这项练习自选规模，不是官方默认。[官方数据说明](https://aws.amazon.com/blogs/devops/amazon-introduces-two-benchmark-datasets-for-evaluating-ai-agents-ability-on-code-migration/)。

最小diff优化放在已通过候选上做减改，然后对新HEAD重新完整验收。dashboard展示repo/状态时需escape不可信HTML并控制资料访问；随机进度条或`passed`字符串不能代替runner回执。课程TS README解释如何启动模拟dashboard，其命令不作为安装指令执行，也没有真实迁移结果可保全。

## 17. 后台Issue到PR：受控触发、在途预算和验证发布

2026-10-11 融合 Phase19 第16课。本章第15节管编码闭环，本节只补异步接收、排队、凭据、日预算和发布。输入来自已授权的仓库/动作及触发者，issue正文和仓库文件仍是资料，不能凭其中一句“请上传密钥”扩大执行权限。

### 17.1 Webhook接收与任务身份

先在raw bytes上核HMAC-SHA256及constant-time比较，再parse并验证event/action/schema、installation、repository允许范围、label及触发者是否有资格。签名证明资料来自配置的GitHub并未改body，不证明该issue作者有派发权，也不保证所有HTTP头都被签过。合格任务可靠入队，及时ACK；异步worker处理长操作。接收记录delivery ID、业务task fingerprint、repo/issue revision、固定baseSHA与预算分区。[GitHub签验](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries)、[Webhook实践](https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks)。

同`X-GitHub-Delivery`重送不能再次创建工作，官方说明手动redelivery仍沿用该ID；不同delivery产生同一业务请求还需业务幂等键。已记录ID与body摘要冲突时拒绝，恢复要查既有job/branch/PR效果，不能用新ID重新发布。来源TS实际在`issues.opened`直接派发，没有label筛选和installation/repo准入；issue.number/title也只typecast而非运行时校验，必须补齐才能承接真实事件。

### 17.2 日预算和短期凭据怎样分离

日准入计算`已知spent + 在途reserved + 未结算费用保留`，加新任务最大消费不超过日cap；PR数量同样包含在途预留。多worker在一个可信分区 `(tenant,repository,day)` 中原子claim并扣额，结束后只释放确定未用部分，unknown费用保留。源Python permit虽声称worst-case reserve，却只读取spent未写reservation；并发两任务都可通过检查，顺序demo掩盖了超额。账期由明确时区/日界规则管理，不能变量叫spent_today却从不换日。

GitHub App JWT用于mint安装token，worker需要的是限repo/permission、短期安装token，App私钥不交给它。[官方安装token文档](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app)支持缩小repository与permissions且有效期一小时；token格式变化，不以固定40字符判合法。PAT也能开PR，App的价值是适合任务的身份与范围，不是免除限流或天然安全。

`contents`权限不是路径权限，`can('force_push')=False`也只是本地判断，不是GitHub实际限制。主分支的required PR/检查、禁止force-push和无bypass配置在平台执行，worker还核最终diff、目标ref和禁止的workflow路径；主分支保护不自动保护所有Agent分支。源Python `can`对未知action放行，open_pr未核token.repo/最终HEAD/ci_green，不能直接作为发布器。[保护分支的实际能力与例外](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)。

### 17.3 环境、验证、发布和保留

优先复用经核Dockerfile、runtime、锁及包来源；缺少时推断环境是待核候选。build/install/test均可执行仓库代码，不能放到有App私钥或生产凭据的高权限runner。固定image、依赖来源、base/head与验证计划，隔离后复现；本地测试成功也不等GitHub required checks全部成功。

只有所声明的验证门禁满足才称已验证候选，PR正文给实际rationale、diff、head、验证证据、trace可访问性、费用和未覆盖。coverage超限时，源正文说开needs-review，Python却FAILED；本章统一不称成功，若已有授权允许交草案，可提交明确标“CI/coverage未满足”的draft，其状态与已验证候选分开。dry-run默认生成计划/diff，不自动外发；创建GitHubdraft仍是实际写操作，需要对应授权。课程目录没有声称的Actions YAML，日志里的stub_pr_created也没有创建PR。

清理采用owner与结果保留规则：取消后停止工作者、保存diff/receipt和unknown，查已推branch/PR再决定重试；超过七天只是review触发，不自动删除别人仍使用的分支。保留有意义的失败taxonomy可改进环境推断和测试，成本/PR分母包含失败尝试，重试不能换day或身份绕总预算。

## 18. 编码闭环的实现验收：让各层指向同一动作和产物

2026-10-12补充到第15节编码Agent与最终HEAD门禁。先修是[工具注册与dispatcher](../Agentic%20Design%20Patterns/01-核心章节/05-工具使用.md)、[状态和计划恢复](../Agentic%20Design%20Patterns/01-核心章节/06-规划.md)、[执行许可/展示预算/runner](../Agentic%20Design%20Patterns/01-核心章节/18-安全模式.md)、[fixture评测与观测](../Agentic%20Design%20Patterns/01-核心章节/19-评估和监控.md)和[MCP通信合同](../Agentic%20Design%20Patterns/06-专题扩展/06-MCP通信与状态工程.md)。这些入口维护完整知识，案例只负责检查接线，不再复制五套toy框架。

### 18.1 最小修复任务怎样贯穿所有层

封闭教学任务：FizzBuzz应返回从1到n含n的结果，旧程序 `range(1,n)`漏末项。固定base/artifact、允许文件、输入契约、可信测试及必要cases、环境和总预算。先读取源与测试、复现旧失败，再定位和提出候选diff；写后回读当前产物，用独立测试验证最终HEAD，最后结算效果/费用与终态。失败、拒绝、无证据和预算停止始终可见，不能从只有成功step的日志推“完整闭环”。

一轮流程是：可信run上下文→policy提出typed call→schema与当前权限门禁→原子claim/受控runner→关联结果及effect receipt→有界观察展示→policy实际消费反馈→独立目标核验。每层必须保同一 `run/plan_revision/step/call/attempt、工具身份/参数摘要、base/head、资源版本与政策`；RPC ID相关、业务key去重、trace/span观察各有用途。schema接受不等handler可调用，gate允许不等runner允许，runner exit0不等任务通过，JSONL写成功不等OTLP接收。

policy的五个活动阶段可为SURVEY、RUN_TESTS、INSPECT、FIX、VERIFY，随后还有HALT终态。SURVEY需要检查读取结果；RUN_TESTS若失败进入定位；INSPECT读失败或证据不足不能猜修复；FIX只有真实写入成功、回读版本对应才能进VERIFY；VERIFY要当前head的可信测试回执，非零exit明确失败。若旧基线已通过，可停止修复并说明未复现，不能编造旧失败。可替换的policy seam可以接模型，也可以接规则；换真实模型仍需提供商适配/严格调用解析、历史配对、上下文/费用账本、数据出站许可与质量评测，不是换一个函数便拥有生产Agent。

## 19. CSV 问答：提案、只读执行与可复查收据

这个案例把“问一个数据问题”拆成导入、查询提案、受限执行、发布收据四步。先会读CSV、理解NULL与分组聚合，再学第13章结构化输出的输入边界；不需要先调用模型。离线小语法可以解决确定的需求，扩到自然语言模型时也只让模型提案，实际授权留在可信执行器。

### 19.1 导入时保住数据身份

CSV可能有引号内逗号和换行，应使用严格CSV解析器，不能用逐行 `split(',')`。先固定编码、文件字节上限、表头、列数和记录数，再建数据库。来源教学合同最多50列、10000记录、2MB文本，列名仅允许有限ASCII字符；这是它的简化接口，不是CSV或SQLite的通用规范。空字符串稍后映射SQL NULL，空格字符串不自动等同空值。

推断一列为数值，要检查**所有非空单元格**：混入unknown就保留TEXT；001、002这类整数形态的前导零标识保留TEXT；超过$2^{53}-1$的大整数以及转换成0的极小非零数也保留TEXT。来源只防整数形态的前导零，并不能自动识别所有编号，因此已知标识列最好明确声明TEXT。REAL浮点聚合仍是近似计算；金额宜使用明确单位的整数或精确十进制合同。类型推断是便利功能，不是数据含义判断。

`9007199254740992`与`9007199254740993`若都转binary64，身份可能坍缩。导入时保字符串，再按item_id分组，才能分别得到原两组，而不是误合成一组。另需拒绝大小写等价的表头如X/x，及记录列数不齐，不能悄悄截断列。

文件身份要在读取字节时计算。来源函数计算传入文本重新编码UTF-8后的SHA，CLI先 `read_text`，可能将CRLF规范成LF；因此它并不无条件等于原磁盘文件指纹。推荐分别记录原始bytes SHA、解析规则版本和必要的规范化摘要。下面的小程序直接接收原始字节：CRLF与LF的字节指纹不同，解析出的聚合结果可以相同。输入身份说明“使用哪份文件”，不证明文件内容本身真实。

### 19.2 查询提案必须可解释且不执行

先从确定的小语法开始：show rows、count rows、sum/average/min/max某数值列by某分组列。不支持“预测下个月”就明确返回不支持，不生成貌似合理的答案。字段解析回已导入的实际列名，再引用标识符；SQL中的值用参数绑定，不能将任意问题片段直接拼成SQL。

例如 `sum units by region`得到：

```sql
SELECT "region", SUM("units") AS value
FROM data GROUP BY "region" ORDER BY "region";
```

来源样本East为7+3=10，South为9，West为12+5+4=21，总计40。把最后West的4改成6，West应为23、总计42，源指纹也变化。`sum region by product`在提案阶段拒绝非数值字段。还应解释COUNT(*)计所有行，而COUNT(field)不计该字段的NULL；二者不是可随意互换的“数量”。

可选模型只获得问题、表名和schema，不发送数据行；问题和列名仍可能敏感。模型返回文本经过同一执行边界，系统提示“只返回SELECT”不提供安全保证。来源HTTP适配器有响应大小、超时、禁止重定向和非本地HTTP限制，但没有生产端点授权、完整身份或价格/模型版本收据；其测试使用本地HTTP fixture，不是供应商服务实测。

### 19.3 只读控制与计算预算是两个边界

`sql.startswith('SELECT')`无法限制函数、系统表和昂贵连接。先用可信导入数据建立独立内存表并参数化插入，随后设只读模式、SQL/数据大小限制和SQLite authorizer，再编译不可信提案。authorizer按动作、表、数据库和函数白名单决定是否允许；未知动作默认DENY。不要在它的回调里修改同一数据库连接。[SQLite 授权回调](https://www.sqlite.org/c3ref/set_authorizer.html)

授权主要发生在语句编译时，schema变化导致重编译也需要正确回调。因此执行和取结果期间保持它，不把它描述成逐行鉴权。COUNT(*)会触发表读但列名为空；下面环境还可能给database=None，仅为这个已知表的空列读取保留窄分支。不能把任意缺失字段当“允许全部”。

结果行数上限和运算指令预算分开：`fetchmany(limit+1)`探测是否还有额外行，返回前limit行并标truncated；它不能阻止一个大连接在吐出第一行前算很久。progress callback可以中断昂贵准备/执行，间隔是近似虚拟机指令数量，不是毫秒，也不保证严格相等的真实工作量。SQLite3.41起，复杂查询准备阶段也可能直接触发它。[SQLite 进度回调](https://www.sqlite.org/c3ref/progress_handler.html)

内存表、query_only、authorizer和预算服务于这个本地教学数据库；不自动提供多租户身份、敏感列访问控制或操作系统隔离。来源公开 `run_query(data, ...)`假定data来自可信导入；若允许外部随意伪造columns/types，再在authorizer安装前建表，这个假定失效。实际入口应重新验证或只接收内部冻结的导入对象。

### 19.4 一个能复现关键边界的完整程序

下面是本库自有标准库例子。它采用**显式三列合同**，避免为演示再实现完整类型推断：item_id始终TEXT，units为有业务上限的非负整数。SQL授权只允许本表读及少数聚合。2026-10-14从最终相同代码字节在Python3.12.13/SQLite3.53.1实际运行，输出及反例绑定验收记录。

```python
import csv, hashlib, html, io, json, re, sqlite3

def query(raw, sql, row_limit=10, instruction_budget=10000):
    if type(raw) is not bytes or len(raw) > 2_000_000:
        raise ValueError('需要有界原始UTF-8字节')
    if type(row_limit) is not int or not 1 <= row_limit <= 1000:
        raise ValueError('行预算必须是1..1000整数')
    if type(instruction_budget) is not int or not 100 <= instruction_budget <= 1000000:
        raise ValueError('指令预算必须是100..1000000整数')
    if type(sql) is not str or not sql.strip() or len(sql.encode()) > 10000:
        raise ValueError('SQL文本越界')
    records = list(csv.reader(io.StringIO(raw.decode('utf-8-sig'), newline=''), strict=True))
    if not records or records[0] != ['region', 'item_id', 'units'] or len(records) > 1001:
        raise ValueError('本例采用显式三列合同，最多1000记录')
    values = []
    for row in records[1:]:
        if (len(row) != 3 or not row[0] or not row[1]
                or not re.fullmatch(r'[0-9]+', row[2]) or len(row[2]) > 7):
            raise ValueError('记录不符显式合同')
        units = int(row[2])
        if units > 1000000:
            raise ValueError('units超业务上限')
        values.append((row[0], row[1], units))  # item_id始终TEXT，不经float。
    db = sqlite3.connect(':memory:')
    try:
        db.execute('CREATE TABLE data(region TEXT, item_id TEXT, units INTEGER)')
        db.executemany('INSERT INTO data VALUES (?,?,?)', values)
        db.commit()
        db.execute('PRAGMA query_only=ON')
        db.setlimit(sqlite3.SQLITE_LIMIT_LENGTH, 1000000)
        db.setlimit(sqlite3.SQLITE_LIMIT_SQL_LENGTH, 10000)
        def authorize(action, table, column, database, trigger):

                return sqlite3.SQLITE_OK

                    and (database == 'main' or database is None and column == '')):

                return sqlite3.SQLITE_OK
            return sqlite3.SQLITE_DENY

                'rows': rows[:row_limit], 'truncated': len(rows) > row_limit,
                'instruction_budget': instruction_budget}
    finally:
        db.close()
```

### 19.5 发布同一份结果对象与来源范围

结果收据至少保输入指纹、解析规则、实际执行SQL、字段、行、截断标志及预算；必要时再保SQLite/执行器版本与生成提案版本。HTML和JSON从同一个结果对象派生，让程序读取JSON，不必抓取网页表格。输出文件不能成为另一次读原文件的结果，否则文件在两次读取间变化会使两个产物不一致。

## 20. 故障复盘：从事件账本到待审结论与行动

先理解第12节的不可变报告与提交回执，以及第19节的数据身份和同对象产物。这个案例增加一个重要区别：日志能支持哪些观察，哪些因果结论还未确认，后续工作由谁负责。自动整理可以帮助找证据、排列时间和暴露未完成项，不能替代因果调查或审核者身份认证。

### 20.1 事件身份、物理行与整批失败

输入事件至少有稳定ID、非负相对秒数、类型、消息。简单账本以tab分四字段；JSONL适配器则每个物理行一个显式对象，再转换到相同合同。时间0是有效观测，缺失时间不能默认成0。来源使用指针时间字段区分缺失/null与真实0，拒绝未知字段、记录分隔符、重复事件ID和超限输入。

遇到第三条合法记录后的坏记录，返回整个批次错误，不能无说明地仅留下前三条。否则最后的反证记录可能被丢掉。原文件开头空一行、第二行是e1，定位应是**物理第2行**，不是第1个有效事件；ID用于跨记录引用，物理行用于回到这版输入核验，二者都应保留。

来源的JSONL上限为2MiB、10000事件，review为1MiB、100结论/100行动。这些是教学配置。CLI先ReadFile再检查内容大小，不能说已经限制读取前的内存；大文件入口可改为有界读取。其 `encoding/json` v1解码即使拒绝未知字段，也仍允许重复对象名，字符串中的无效UTF-8可能被替换；严格证据输入要另定义并检查这些边界，不能仅把函数叫strictJSON就认作严格完成。[Go JSON兼容语义](https://pkg.go.dev/encoding/json)

### 20.2 时间顺序不是因果顺序

排序先复制事件切片，以相对秒数为主键、ID为平局次键，保原到达顺序。例如到达顺序为b35、a0、c35，时间线为a、b、c；horizon30应整批拒绝，horizon35接受这三条，不能删掉超范围记录后仍发布“完整”时间线。

来源原事件例为e1部署t0、e2告警t35、e3回滚t90。能观察“告警在部署之后”，还不能直接得出“部署造成故障”；回滚后改善也要用时延、负载、错误率和其他变更等证据调查。时钟来源、相对时间原点和跨机器误差应明记，秒数排序不修复错误时钟。

确定性也要分层。交换事件到达顺序可以保持**排序后的事件语义**相同；但原始字节SHA和物理行会变化，因此集成报告的完整字节并不相同。来源小函数Report的确定性测试只检查同输入重复调用；不要把它外推成所有重排输入都产生完全相同的审批包。

### 20.3 引用、逐字引文、支持程度与批准分别核对

结论先要有非空正文和至少一个已知、不重复事件ID；e99不存在、重复引用e1、空结论都拒绝。随后给每个引用提供逐字引文，检查该片段确实在对应事件消息中：原文是latency high，引用database failed应拒绝。来源以非空substring检查逐字片段，不推断证据是否充分。

| 结论 | 引用检查 | 尚需的判断 |
|---|---|---|
| 告警发生在部署之后 | e1/e2存在且时间支持先后 | 时钟与日志是否可靠、是否遗漏事件。 |
| 部署造成了故障 | 同样可以引用e1/e2并通过存在检查 | 因果机制、其他可能原因、反证与范围。 |
| 客户损失已确定 | 即使文字有引用也不足 | 受影响请求、时间区间、估计方法与未知部分。 |

结论状态保留pending/approved。pending不隐藏，缺测量的影响写“待调查”并列调查行动。来源approved要求非空reviewer标签及匹配原始日志SHA；改日志任一字节，旧批准不能直接批准新证据。这是版本一致性检查，不是认证签名。

还存在更细的审批缺口：**只绑定日志SHA，没有绑定具体结论与审核决策**。日志未变，把“告警在部署之后”改成“部署导致故障”，再保同reviewer标签与approved，仍可能通过来源结构检查。实际审批应绑定日志版本、claim正文/引用/引文、审核决定、可信审核身份、权限与策略版本，并记录新的审批回执；不能把非空名字视为真实审核。相关写入合同参见[工具授权与发布治理](../Agentic%20Design%20Patterns/06-专题扩展/07-工具授权与发布治理.md)。

### 20.4 报告不能把未完成工作藏起来

每个结论先Verify，再构造时间线和文本；任何关键结论失败，不返回部分“成功”文本。HTML用模板将消息、引文和标签作为数据显示，并链接事件ID及物理行。JSON和文本同样要保source SHA、影响、pending数、review状态和行动，而不只保漂亮时间线。

行动至少有明确任务、负责人、状态，并建议补优先级、跟踪入口、到期条件与验收证据。例如“改进监控”无法判定结束；“为回滚阶段增加成功率与尾时延对照，记录30分钟代表区间并复核差异”才有检查入口。不要只责备某位操作者，要检查系统、流程和自动化为何允许失败重现。[Google SRE复盘实践](https://sre.google/workbook/postmortem-culture/)

来源允许open行动暂时无owner，会在页面显示unassigned；doing/done只检查owner非空，没有验证工作真的做完。应保未分配状态并安排归属，而不是自动编造负责人；标done还需实际产物或跟踪证据。source packet不是自动证明行动已解决故障。

“无效输入不产生部分结果”与“磁盘发布原子”也不同。来源CLI依次写HTML、JSON、文本，后续写入失败可能留下部分文件。可沿用第12节的代际目录与完整manifest提交思路：先构造并校验同一代全部产物，写临时位置，完整后发布指针；读者只读被选中的完整代。来源本轮未验证这种升级，不宣称三个文件的恰好一次原子发布。

## 21. 架构证据链：需求、选择、控制与接收者能力

已有成果框架和可复查收据说明“文件生成”与“目标满足”的不同。本节把一次方案判断扩展到架构与运营：谁的哪项工作要改善，哪些限制不能牺牲，哪个最小实现能承担，怎样用独立证据决定试点，以及接收者能否安全维护。认证课程只是补充案例，不代表读者做过这些项目或获得认证。

### 21.1 工作表面与控制面分别选择

先分清工作在哪发生与谁控制调用。人使用聊天/网页/编码客户端完成一次任务，是工作表面；应用用API承接大量事件、身份、状态、配额和监控，是受程序控制的工作负载。SDK封装调用与追踪，不自动补业务权限；协议提供互操作，不替代需求；Plugin/Skill可分发方法和能力，但安装或调用不是业务完成。

例如“10名分析员审阅政策草稿”和“系统每周处理大量工单”可能共享模型原理，却有不同身份、并发、失败、费用和交接合同。用户席位数不能换算为API吞吐或自动化权限。产品能做、当前提供方支持、组织允许、实际部署可用四项分别核；未核版本和日期不固定型号、套餐、价格、题库或厂商排行。

### 21.2 一条需求走到一个有后果的门

手核教学需求：在代表工单中更快给出**政策正确**的首个建议，只读账户、禁止删账户、退款仅建议。首响时间与总解决时间不同；模型有回答与工单正确解决不同；内部目标与合同承诺不同。先有真实基线、样本范围和owner，再选择方案，不能把虚构每周4万件、11分钟、98%或8秒写成已有业务事实。

比较三个最小候选：检索辅助草稿且全量人工审核；固定流程中的有界模型步骤；能动态选工具的Agent。已知路径、严格尾延迟和审计要求支持固定流程；只有未知反馈确实需要改变下一步、且同案例评测显示收益时，才为适应性支付额外调用、延迟、权限和维护。多Agent也逐个说明隔离、专长、并行或独立审阅的理由。

每条记录形成 `requirement → decision → control → test → gate → observed outcome`：需求有ID和测量，ADR记录所选/被拒选项、代价、owner、证据与反转条件；控制在正确边界落实；实际测试绑定候选版本；门给通过/失败/未核的后果。没有需求依据的组件可删，没有控制/测试的需求仍是缺口，没有后果的测试只是报告。

### 21.3 五域审议与六场景迁移

同一架构逐层检查：编排依赖与结果合并；工具/协议和动作权限；共享配置与干净CI；输出四层验证；上下文、来源、partial和升级。通用五门是审议框架，不要求所有系统装相同产品。已知DAG检查通过只证明依赖声明无该类问题；`isolated`、`fresh_checkout:true`、四层名称不能证明真实隔离、干净环境和验证执行。

六场景可作为迁移练习：客服、代码生成、多Agent研究、开发工作流、CI/CD、结构化抽取。对每次迁移列清来源/敏感度、允许动作/批准者、工具或协议、配置范围、验证对象、恢复/升级风险的变化，保留适用不变量。抽取任务可以不需要写幂等，改为“输出版本与证据绑定”；不能为了共用表格制造无必要批准，也不能删掉高后果写场景的真实控制。

用三条ADR反转题检查判断：单Agent与多Agent是否有收益；直接调用与MCP是否有多个宿主互操作或运营需求；交互与批处理是否存在独立任务、延迟和人工等待限制。组件数、框架名和功能密度不替代证据；反转trigger应可观察，并留下未来重新核验的owner。

### 21.4 十种产物共用一条证据链

方案包可以含发现简报、选项/ADR、系统与身份数据视图、模型/提示/上下文计划、知识检索、集成身份、评测观测、治理人审、rollout/runbook、受众与交接。但它们是一个证据索引，不是十个文档标题就算完整。每个外部调用边界说明schema、身份、deadline、重试、证据与owner；每个数据索引有来源、激活版本和回退；每个告警有实际处置。

面向管理者讲待作决定、收益证据、投入区间和残余风险；面向工程给接口/版本/失败合同；面向控制owner给数据/权限/风险与待批准边界；面向运营给SLO、告警、恢复、capacity及变更条件。相同事实不能在四个包里改口径。合规与法定责任由有资格的实际owner判断，不由课程模板代签。

### 21.5 接收者演练才证明交接

交接要验证接收方能访问正确资料、取得所需权限、判断警报、停止新动作、恢复已知安全版本、重跑评价并升级事故。架构师留在旁边解释每一步、资料可访问或正常试点无可见错误，都不足以证明接收者能力。演练记录真实操作者、故障条件、版本、动作、结果与未通过项；未通过硬门保持阻塞。

参考评分91分可以支持“方案值得独立答辩”，却不能抵消生产授权、租户隔离和接收方回滚演练待核。局部程序返回 ready、网页人工readiness百分比、真实发布就绪是三种不同结论，必须写清范围。每个源测试只按断言读：检查字段存在不证明该字段所述行为发生。

### 21.6 练习与验收判据

1. 用一项真实需求比较三个候选。参考：至少一个不用新增Agent的候选；固定任务、限制和测量，给代价/风险/拒选与反转理由，不编造访谈或试点成绩。
2. 从五域各注入一个失败：循环依赖、写参数不绑定批准、个人配置不在CI、合法JSON但来源不支持、压缩丢未知效果。参考：各有检测/安全停止/owner/修复后复验，不能只报告标题齐全。
3. 给六场景写delta。参考：同一来源/权限/工具/配置/验证/恢复表比较变点；适用性有解释，不复制六套架构或把课内考试情境当通用标准。
4. 交换方案包独立审阅。参考：稳定finding实例ID、域、原证据位置、严重性、修正和处置；同类别code不是每条唯一findingID，修复后保旧记录并绑定新版本。
5. 模拟旧政策、授权服务故障、工单注入、评价器漂移和队列过载。参考：接收者自己完成contain/rollback/eval/escalation；没有实际演练就标待核，不把runbook文字标成功。
6. 给研究/开发/专业三个结课项目定提交边界。参考：研究看主张和来源/审批/最终报告版本；开发看完整工具环、严格终态与可信轨迹/效果；专业看需求到门禁和运营能力。只读资料并不等完成原项目。

### 21.7 学习账本：解释、实施与条件判断分开

复习知识库时，可为一主题记录三列：Know能解释什么，Do能在有界例子上做什么，Decide能在相反条件下怎样选择。比如“理解MCP”太宽：能解释工具/资源/提示的控制者；能构造一个合法请求和一个被拒输入；能说明单宿主函数调用与协议接线各自何时合适。三者给具体证据，不由同一个自评confidence替代。

账本保知识版本、题/案例ID、原解释或产物、实际核对结果、错因、未知与下次变体。抄出定义、跑通正常例、修复失败例、迁移新场景是不同层次；静读源码与亲自执行也分别记。开始时题目未尝试不等已掌握或永久失败，学会后也用延迟复习和新反例核保持，不把题库位置或课程打分当真实能力。

一天只选一条可检验链：读原理与例子→先写预测→核输入/输出与边界→改一个反例→解释为什么拒绝/未知→留下下次检查点。时间按先修、当前缺口和可用条件调整；具体产品/权限/数据版本变化时回看对应记录，而不是把整个仓库重学或重复生成笔记。这是可选学习方法，不是用户已经完成的训练计划或认证承诺。
