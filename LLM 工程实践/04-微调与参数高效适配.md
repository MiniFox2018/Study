# 04｜微调与参数高效适配

## 1. 微调前先定义“要改变什么”

微调通常用于稳定改变：

- 输出风格；
- 任务格式；
- 专业行为；
- 分类/抽取能力；
- 特定领域操作模式；
- 多模态映射。

如果只是缺最新知识，应优先考虑 RAG。

## 2. 三种典型训练方式

### 2.1 Full Fine-tuning

更新大部分或全部模型参数。

优点：

- 可优化的参数空间更大，但实际效果不保证最好；
- 可深度改变模型。

代价：

- 显存高；
- checkpoint 大；
- 更容易遗忘原能力；
- 多任务维护成本高。

### 2.2 LoRA

冻结基础模型，在目标层增加低秩 Adapter：

```text
ΔW = (α/r) B A  # 标准 LoRA，矩阵形状与缩放见 LLM 基础第 7 章
```

主要参数：

- rank；
- alpha；
- dropout；
- target modules。

优势：

- 可训练参数少；
- checkpoint 小；
- 多 Adapter 易管理；
- 能在冻结基础权重的条件下适配目标任务。

### 2.3 QLoRA

典型 QLoRA 冻结低比特存储的基础模型，使用较高精度进行必要计算并训练 LoRA Adapter；它不是直接把所有权重作为 4-bit 可训练参数更新。

目标是进一步降低显存占用。

需要额外关注：

- 量化方法；
- compute dtype；
- 量化误差；
- 哪些层保持高精度；
- Adapter 与量化权重的兼容。

## 3. SFT 数据结构

文本指令数据通常包含：

```json
{
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ]
}
```

多轮数据必须保证角色顺序和模板一致。

## 4. 训练数据比“参数调得多”更重要

至少检查：

- 去重；
- 错误答案；
- 模板污染；
- 过短/过长样本；
- 样本分布；
- 泄漏测试集；
- 多轮上下文一致性；
- 领域覆盖；
- 数据授权与隐私。

## 5. Loss Mask

Instruction tuning 常常不应该让所有 Token 都参与 loss。

常见选择：

- Padding 不计 loss；
- 只训练 assistant response；
- system/user 部分只作为条件。

具体策略要与训练目标一致。

## 6. 关键超参数

- learning rate；
- batch size；
- gradient accumulation；
- epoch / steps；
- max sequence length；
- warmup；
- weight decay；
- LoRA rank / alpha；
- target modules。

不要复制教程里的值直接上生产。

## 7. Checkpoint 与 Adapter

训练过程需要区分：

- Base model；
- Adapter；
- merged model；
- optimizer state；
- trainer state。

### Adapter 模式

适合：

- 多任务；
- 快速切换；
- 少存储。

### Merge 模式

适合：

- 下游推理框架不方便动态挂载 Adapter；
- 希望得到独立完整权重。

合并后仍需重新评测。

## 8. 实验记录

至少记录：

- 数据版本；
- 模型 revision；
- 配置；
- git commit；
- 随机种子；
- loss；
- eval 指标；
- checkpoint；
- 显存和运行时长。

训练应视为实验科学，而不是一次性脚本。

## 9. 选择策略

```text
Prompt 能解决 → 不训练
可靠数据能覆盖稳定行为缺陷 → 比较 LoRA 与基线
支持的量化后端且资源紧张 → 评估 QLoRA
LoRA 受限且数据/资源充分 → 比较 Full FT
需要偏好对齐 → SFT 后再考虑 DPO / RL
```

来源：<https://github.com/datawhalechina/self-llm>  
核验依据（2026-10-02）：[PEFT LoRA 文档](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora)。链接为开发文档；具体 API 按已安装版本执行。

## 10. 先检查一个训练批次

训练前人工展开 2～4 条样本的“渲染文本 → Token ID → label → loss mask”：确认用户文本未变成回答标签、EOS 没有遗漏、截断没有切掉全部答案。若使用 packing，必须明确是否允许不同样本跨边界注意以及位置如何重置，不能只看长度刚好装满。

例如一个样本含 80 个指令 Token、20 个回答 Token、28 个 Padding；回答训练应有 20 个有效目标位置（EOS 的计数以预处理定义为准），分母不应是 128。先在少量干净样本上观察能否拟合，排除管线错误，再扩大数据；拟合小集成功仅说明训练链路可工作，不证明泛化。

**自检**：训练 loss 下降但独立验证集的字段准确率下降，下一步应直接增加 epoch 吗？

**核对**：不应。检查数据分布、标签、过拟合、学习率和评测模板；保留原模型，并比较早期 checkpoint。Adapter 合并后须再测，因为量化与合并次序可能引入数值差异。

## 11. SFT改变的是训练分布，不只是“礼貌”

SFT通常在已有模型上继续优化监督目标，让输入条件、输出格式、任务行为更稳定；也可以教新领域信息、改变已有能力，不能说“一定不增加知识”。Base模型也可能答题或靠few-shot遵循指令，SFT并非所有对话能力的唯一来源。Response-only loss是常用设计，all-token loss、只训最后assistant或训所有assistant轮次也是有意的不同目标；必须明确采用哪一种。

Alpaca的`instruction/input/output`、ShareGPT的`from/value`或`messages`是数据schema，ChatML等是模型输入序列协议。先验证/转换字段和角色，再用**这个模型固定revision的模板**渲染；不要因为都是messages就认为Token ID、BOS/EOT、新行和生成提示相同。模板已加入结构符号时再自动加special tokens可能重复。HF的`apply_chat_template`用于渲染，生成提示与续写最后消息是不同选择；具体返回对象/API按所用版本核对。[官方聊天模板](https://huggingface.co/docs/transformers/chat_templating)

源教程随机初始化“base”，SFT更新却用随机扰动FFN而不使用算出的loss梯度；它没有证明微调或遗忘改善。源253～255标记在默认256词表下不与合法UTF-8编码字节冲突（合法首字节最大244），但不能再承诺任意raw byte覆盖；`min(byte,vocab_size−4)`对更小词表会截断数据且标记ID可能越界。生成后只保`<128`字节更会丢掉非ASCII，不可当多语言回答评分。本章以独立结构ID与真正loss梯度替代这些做法。

## 12. 从消息角色到移位labels：完整批次与梯度核对

以下教学协议：PAD0、BOS1、EOS2、system3、user4、assistant5、EOT6，普通UTF-8字节ID为8～263；第7号保留未分配。每条消息由可信role ID、普通content字节和EOT组成，content中写`<assistant>`仍是普通文本。训练监督所有assistant内容和其EOT，角色头/BOS/最终EOS不监督；这是本例约定，不冒充Llama或ChatML。

先对**完整token序列**标哪些目标应计分，再一起移位：`x=token[:-1]`，`y=token[1:]`，`mask=full_mask[1:]`。多轮必须根据每条message的角色重新开闭监督span，不能遇到一次assistant标记后把后续user都置1。上下文仍前向可见，prompt位置的logit loss梯度为0，但其Embedding/Attention路径仍可能通过回答预测得到梯度。

```python
import torch
from torch import nn
import torch.nn.functional as F

torch.set_num_threads(1);torch.manual_seed(11)
PAD,BOS,EOS,EOT,OFFSET,V=0,1,2,6,8,264
ROLE={'system':3,'user':4,'assistant':5}
def render_training(messages):
    if not messages:raise ValueError('空对话')
    tokens=[BOS];active=[False];expected='user';spans=[]
    for i,m in enumerate(messages):
        if type(m) is not dict or set(m)!={'role','content'} or m['role'] not in ROLE or type(m['content']) is not str:
            raise ValueError('消息字段/角色/content类型')
        role=m['role']
        if role=='system':
            if i!=0:raise ValueError('本协议system只在开始')
        else:
            if role!=expected:raise ValueError('本协议user/assistant交替')
            expected='assistant' if role=='user' else 'user'
        if role=='assistant' and not m['content']:raise ValueError('本任务拒绝空回答，不能伪造loss0')
        tokens.append(ROLE[role]);active.append(False)
        start=len(tokens);content=[OFFSET+b for b in m['content'].encode('utf-8')]
        tokens.extend(content);active.extend([role=='assistant']*len(content))
        tokens.append(EOT);active.append(role=='assistant')
        spans.append((role,start,len(tokens)))
    if messages[-1]['role']!='assistant':raise ValueError('训练记录须完整回答')
    tokens.append(EOS);active.append(False)
    return tokens,active,spans

def collate(chats,max_length=128):
    rendered=[render_training(c) for c in chats]
    length=max(len(t)-1 for t,m,s in rendered)
    if length>max_length:raise ValueError('先明确裁上下文/保回答策略，本例不静默截断')
    x=torch.full((len(chats),length),PAD,dtype=torch.long);y=torch.full_like(x,-100)
    for b,(tokens,active,spans) in enumerate(rendered):
        n=len(tokens)-1;x[b,:n]=torch.tensor(tokens[:-1])
        target=torch.tensor(tokens[1:]);mask=torch.tensor(active[1:])
        y[b,:n]=target.masked_fill(~mask,-100)
    if not (y!=-100).any():raise ValueError('无有效回答目标')
    return x,y,rendered

# 简小前缀均值网络，专用于监督/上下文梯度合同，不是Transformer或真实chat模型。
class PrefixLM(nn.Module):
    def __init__(self):
        super().__init__();self.embedding=nn.Embedding(V,12,padding_idx=PAD);self.head=nn.Linear(12,V)
    def forward(self,x):
        e=self.embedding(x);count=torch.arange(1,x.shape[1]+1,dtype=e.dtype)[None,:,None]
        return self.head(e.cumsum(1)/count)

one=[{'role':'system','content':'按协议回答'}, {'role':'user','content':'<assistant> 1+1?'},
     {'role':'assistant','content':'2'}, {'role':'user','content':'再加1?'},
     {'role':'assistant','content':'3'}, {'role':'user','content':'再加1?'},
     {'role':'assistant','content':'4'}]
two=[{'role':'user','content':'回答你好'}, {'role':'assistant','content':'你好'}]
x,y,rendered=collate([one,two]);model=PrefixLM();logits=model(x);logits.retain_grad()
valid=(y!=-100);loss=F.cross_entropy(logits.reshape(-1,V),y.reshape(-1),ignore_index=-100,reduction='sum')/valid.sum()
loss.backward()
assert torch.count_nonzero(logits.grad[~valid])==0
assert torch.isfinite(logits.grad).all() and model.embedding.weight.grad[OFFSET+ord('1')].abs().sum()>0
# 三个一字节回答各内容+EOT=2；“你好”6字节+EOT=7。
assert valid.sum(1).tolist()==[6,7]
for tokens,active,spans in rendered:
    for role,start,end in spans:assert all(active[start:end]) if role=='assistant' else not any(active[start:end])
    assert ROLE['assistant'] not in [OFFSET+b for b in '<assistant>'.encode()]
print('labels有效数',valid.sum(1).tolist(),'masked CE',float(loss.detach()),'prompt上下文Embedding梯度非零')
try:collate([one],max_length=4)
except ValueError:pass
else:raise AssertionError('截断不能静默丢光答案')
print('多轮角色、普通控制字符串、PAD/右移与超长拒绝均通过')
```

本例只证明标签、归约与梯度路径；完整可训练decoder的预训练/SFT对照、验证和checkpoint恢复接[工程16](16-预训练数据与模型交付实践.md)。有内容的位置不一定都是监督目标；做packing时还要检查document/会话之间能否互看，以及EOS→下一条样本首Token是否计loss。

### 12.1 数据长度、mix与实验取舍

过滤前检查回答是否正确、与问题相关、单位/事实/格式一致，长度和词项多样性只能当启发。答数字“2”或一个布尔值本来就短，不能统一把回答少于10token视为坏数据；重复术语也不自动表示低质量。源八条模板例未核对诗歌音节/事实细节，本章不把生成例当gold。

5% raw examples不等5%有效训练token：1条raw有64个目标、19条SFT各2个目标，raw贡献$64/(64+38)≈62.7\%$监督token。按样本、token或loss项mix是不同方案，需记录实际计数和目标权重。保持独立的领域/通用/良性拒绝/格式切片，不用“raw PPL增加15%”作所有任务通用的遗忘门槛。

学习率/epoch取决于基础模型、数据、有效batch、可学参数和目标；1e−4/2e−5/1e−6不保证中间必是sweet spot，超过3epoch也不必总坏。对照要复制同一初始权重、冻结同样测试集与预算，记录训练/验证/完整生成指标；本批不执行大型LoRA/QLoRA或真实模型下载。

## 13. AI反馈：来源、训练方法与正确性分开

Constitutional AI原两阶段是：按原则生成批评/修订并SFT；再由AI做成对偏好，训练preference model后用RL优化。后来也可把AI偏好直接用于DPO，但DPO不需要先训练reward model；**RLAIF说明反馈来源，PPO/DPO/GRPO说明优化方法**，不能混成同一个算法。原则选择和事实判定是不同环节，修改原则文件不自动修改模型权重。[CAI原论文](https://arxiv.org/html/2212.08073v1)

反馈模型可与policy相关，原研究确有self-critique；这不意味着同模型family一概禁止或一定正确。独立人工/规则/环境证据用于校准盲点，记录rubric版本、样本和误接受，不硬规定“每轮必须5%–10%人工数据”。规则奖励给出了外部反馈，不能说自生成训练永远没有新信号、能力永远止于初始模型；有效性也不保证。

源critique只看response、不看prompt；删“maybe”会把合理不确定变过度自信，截最后一句或给拒绝前面加“答案是”也可能破坏事实/请求适用性。新修订必须对照同一prompt、证据和格式重新判定，不把changed=True计成improved=True。ORM看最终结果，PRM看中间可验证步骤；形式上多给几条分数不等真正的过程正确性。二者都可被错误规则或奖励捷径利用，不能预设ORM普遍更安全、PRM一定更低效。

### 13.1 有界算式与严格答案：可运行验证器

本例语言只支持整数常量、括号、正负号和加减乘除，结果用精确Fraction；明确限制字符/节点/数值规模，拒绝函数、属性、幂和其它表达式。它是一个有限任务解释器，不调用`eval`，也不是运行任意代码的安全沙箱。代码任务需另设隔离执行、资源限制和测试契约，不能因`__builtins__={}`就说`eval`安全。

```python
import ast
import re
import json
from fractions import Fraction

LIMIT=1000000

def expected_answer(expression):
    if type(expression) is not str or not 0<len(expression)<=80:raise ValueError('有界算式字符串')
    tree=ast.parse(expression,mode='eval')
    if len(list(ast.walk(tree)))>40:raise ValueError('算式结构预算')
    def visit(n):
        if isinstance(n,ast.Constant) and type(n.value) is int:out=Fraction(n.value)
        elif isinstance(n,ast.UnaryOp) and isinstance(n.op,(ast.UAdd,ast.USub)):
            x=visit(n.operand);out=x if isinstance(n.op,ast.UAdd) else -x
        elif isinstance(n,ast.BinOp) and isinstance(n.op,(ast.Add,ast.Sub,ast.Mult,ast.Div)):
            a,b=visit(n.left),visit(n.right)
            if isinstance(n.op,ast.Add):out=a+b
            elif isinstance(n.op,ast.Sub):out=a-b
            elif isinstance(n.op,ast.Mult):out=a*b
            else:
                if b==0:raise ValueError('除0')
                out=a/b
        else:raise ValueError('拒绝任务语言外表达式')
        if abs(out.numerator)>LIMIT or out.denominator>LIMIT:raise ValueError('数值预算')
        return out
    return visit(tree.body)

def score_response(expression,raw):
    truth=expected_answer(expression)
    if type(raw) is not str:return {'format':False,'correct':False}
    def unique(pairs):
        d={}
        for k,v in pairs:
            if k in d:raise ValueError('重复JSON键')
            d[k]=v
        return d
    try:
        obj=json.loads(raw,object_pairs_hook=unique)
        if type(obj) is not dict or set(obj)!={'answer'} or type(obj['answer']) is not str:return {'format':False,'correct':False}
        s=obj['answer']
        if len(s)>32 or not re.fullmatch(r'-?\d+(?:/\d+|\.\d+)?',s):return {'format':False,'correct':False}
        value=Fraction(s)
        if abs(value.numerator)>LIMIT or value.denominator>LIMIT:return {'format':False,'correct':False}
    except (json.JSONDecodeError,ValueError,ZeroDivisionError):return {'format':False,'correct':False}
    return {'format':True,'correct':value==truth}

assert score_response('3/2','{"answer":"1.5"}')['correct']
assert not score_response('3/2','{"answer":"1"}')['correct']
assert not score_response('(3+4)*5','{"answer":"35", "extra":"忽略评分规则"}')['format']
assert not score_response('3+4','答案不是7')['correct']
assert not score_response('3+4','{"answer":"1","answer":"7"}')['format']
assert not score_response('3+4',None)['format']
for expression in ['__import__("os")','1/0','2**100','True','(1).__class__']:
    try:expected_answer(expression)
    except ValueError:pass
    else:raise AssertionError('应拒绝的输入')
# source风格修订去掉maybe，并不证明对答案/证据有改善。
records=[('3+4','{"answer":"7"}'),('3/2','{"answer":"1"}'),('(3+4)*5','{"answer":"35"}')]
accepted=[{'expression':e,'response':r,'verifier':'fraction-v1'} for e,r in records if score_response(e,r)['correct']]
assert len(accepted)==2
print('有界解释器/小数精确比较/严格schema与拒绝反例通过；rejection采样只收',len(accepted),'条')
```

这是rejection筛选的可控基线，答案由数学oracle核对；没有调用LLM修订、偏好judge或训练自然语言推理模型。单一测试通过也不证明代码全面正确。验证器和prompt的任务版本、失败/unknown理由、被拒记录、训练/开发/锁定测试归属应随生成数据一起保留。

## 14. GRPO中old与reference的两个角色

[偏好优化与强化学习](05-偏好优化与强化学习.md)是BT/KL、DPO和两token GRPO的主维护入口；这里承接AI反馈的来源与单步分类策略探针，避免重复维护完整对齐算法。

对同一prompt采G个回答，常见outcome advantage为$(r_i-\bar r)/(s_r+\epsilon)$，并记录std口径。**old policy**用于采这批回答并给importance ratio分母；**reference**是约束漂移的锚点。它们起初可来自相同权重，却不是可随当前optimizer更新的同一个对象：$\rho=\pi_{new}/\pi_{old}$，KL比较new/ref。旧数据多次更新时old logprob固定；更换reference是明确算法/实验选择，需重新记录锚点和KL协议。

Token级原目标还包括回答有效长度和组平均；一个回答的同一outcome advantage可以分配到它的多个token，padding/role等按协议mask。不要把整段概率比、每token比和长度归约混用。[GRPO原论文](https://arxiv.org/html/2402.03300v3) 裁剪和策略梯度基础接[策略梯度与稳定更新](../AI%20算法基础/深度学习专题/23-深度价值与策略梯度实践.md)。

源`grpo_step`只有NumPy指标，ratio用ref代替old，`mean(logref−logpolicy)`在其合成样本下为负，不是真KL；三轮固定mock_sampler没有任何可学policy更新，奖励起伏不是self-improvement。真实KL还要说明在哪个prompt/状态分布上求期望，不把“历次KL数值相加”叫总漂移距离。

### 14.1 真实优化的一步分类策略探针

下面每prompt只有三个固定候选回答，全部概率可枚举，因此精确算KL/entropy。它训练的是可学**分类策略表**，不是LLM；目的是验证group、old/ref、裁剪和梯度更新。候选正确性直接给定fixture，完整任务verifier见上节。每轮old采样，复用这批数据两次更新，reference一直保初始快照。

```python
import torch
from torch import nn

torch.set_num_threads(1);torch.manual_seed(12)
logits=nn.Parameter(torch.zeros(2,3));reference=logits.detach().clone().softmax(-1)
reward_table=torch.tensor([[1.,0.,0.],[0.,1.,0.]])  # 两个fixture prompt，各自正确候选。
optimizer=torch.optim.Adam([logits],lr=.08);rng=torch.Generator().manual_seed(13)
beta,entropy_weight,clip_eps=.05,.01,.2;group=16;zero_groups=0
before=logits.detach().softmax(-1)
for round_id in range(25):
    old_log=logits.detach().log_softmax(-1);old_prob=old_log.exp()
    samples=torch.multinomial(old_prob,group,replacement=True,generator=rng)
    rewards=reward_table.gather(1,samples);std=rewards.std(1,unbiased=False,keepdim=True)
    advantage=torch.where(std>1e-8,(rewards-rewards.mean(1,keepdim=True))/(std+1e-8),torch.zeros_like(rewards)).detach()
    zero_groups+=int((std<=1e-8).sum())
    sampled_old=old_log.gather(1,samples)
    for update in range(2):
        new_log=logits.log_softmax(-1);new_prob=new_log.exp()
        ratio=(new_log.gather(1,samples)-sampled_old).exp()
        objective=torch.minimum(ratio*advantage,ratio.clamp(1-clip_eps,1+clip_eps)*advantage).mean()
        kl=(new_prob*(new_log-reference.log())).sum(1).mean()
        entropy=-(new_prob*new_log).sum(1).mean()
        loss=-objective+beta*kl-entropy_weight*entropy
        optimizer.zero_grad();loss.backward()
        assert logits.grad is not None and torch.isfinite(logits.grad).all()
        optimizer.step()
    if round_id in [0,9,24]:
        current=logits.detach().softmax(-1);current_kl=(current*(current.log()-reference.log())).sum(1).mean()
        print('round/分类策略概率/更新后精确KL',round_id+1,current.tolist(),float(current_kl))
after=logits.detach().softmax(-1)
assert torch.allclose(after.sum(1),torch.ones(2)) and torch.allclose(reference,torch.full_like(reference,1/3))
assert after[0,0]>before[0,0] and after[1,1]>before[1,1]
print('零reward-variance组数',zero_groups,'；只通过此分类fixture，不宣称推理/泛化能力')
```

std=0可能是全部正确、全部错误、题太容易、reward分辨力弱或样本恰相同，不自动等于mode collapse。上例PG部分归0，但KL/entropy仍可能有梯度；response多样性、任务正确率、长度与分语言/难度切片另报。PRM中每步可验标签和entropy正则也不能保证避免奖励捷径或模式坍缩。

## 15. 原练习的学习落点与范围

1. System prompt与多轮：第12节完整支持可信system和三轮assistant span，实际打印有效label数量与梯度；不只保格式名。
2. 5% raw混合：按样本与有效token分别计量，同初始checkpoint和通用/任务测试对照；本批完整micro训练见工程16，没有承诺固定5%普遍防遗忘。
3. 长度/词项多样性质量过滤：与任务答案核验分开，短但正确的数字不能因阈值被当垃圾。反例比一条更低训练loss更能定位目标变化。
4. 三个LR对照：保持数据/seed/预算并看验证和生成，不给未运行的三条曲线预定结论。源随机扰动不能复现该实验。
5. CAI的本地LLM批评、真实事实修订、20prompt DPO、5轮entropy与10轮PRM消融本批未执行；保留输入/反馈/训练/独立验证的完整设计，有限验证器与分类策略只说明其局部机制。偏好优化主线接[偏好优化与强化学习](05-偏好优化与强化学习.md)。
6. 人工与AI反馈按适用任务核验，changed≠improved、形式合规≠事实正确、reward提升≠全面能力。源5–10%人工配额/5轮强制停止等产物条款是示例判断，不执行为本仓库的权限或通用科学门槛。
