# 04｜微调与参数高效适配

## 1. 微调前先定义“要改变什么”

微调通常用于稳定改变：

- 输出风格；
- 任务格式；
- 专业行为；
- 分类/抽取能力；
- 特定领域操作模式；
- 多模态映射。

如果只是缺最新知识，应优先考虑 RAG。

## 2. 三种典型训练方式

### 2.1 Full Fine-tuning

更新大部分或全部模型参数。

优点：

- 可优化的参数空间更大，但实际效果不保证最好；
- 可深度改变模型。

代价：

- 显存高；
- checkpoint 大；
- 更容易遗忘原能力；
- 多任务维护成本高。

### 2.2 LoRA

冻结基础模型，在目标层增加低秩 Adapter：

```text
ΔW = (α/r) B A  # 标准 LoRA，矩阵形状与缩放见 LLM 基础第 7 章
```

主要参数：

- rank；
- alpha；
- dropout；
- target modules。

优势：

- 可训练参数少；
- checkpoint 小；
- 多 Adapter 易管理；
- 能在冻结基础权重的条件下适配目标任务。


### 2.2.1 矩形层、初始化梯度与真正的小适配实验

对 W∈R^(d_out×d_in)，标准 LoRA 的 A∈R^(r×d_in)、B∈R^(d_out×r)，可训练参数为 r(d_in+d_out)，不是只有正方形矩阵才成立。相对原权重的比例为 r(d_in+d_out)/(d_in*d_out)；总模型比例还取决于目标层、Embedding、MLP、偏置等，参数比例不能直接换成显存比例。动态图 lora-params 只计算每层 q/v 两个正方形投影的 2r/d，未计算整个模型或激活。

PyTorch Linear 对批次行向量执行 xWᵀ，因此这里用 xAᵀBᵀ*(α/r)。来源程序把 A/B 存成 [in,r]/[r,out]，再将 (AB)ᵀ 合入 weight；那是另一套一致的命名方向，不可只改一个转置。B=0 时适配路径初始为零；第一步 A 的梯度也为零，B 通常可收到梯度，随后 A 才开始参与。α/r 是前向缩放，不等同于优化器 learning rate。

下面用一个已知低秩线性教师构造训练和独立测试输入，实际反传、优化 A/B；不下载预训练模型。保存文件只包含自己的 Tensor/基础配置，恢复时核对同一基础权重及 rank/alpha，合并后再比输出。该实验验证低秩适配的机制，不能证明真实语言任务的能力。

```python
import copy, hashlib, tempfile
from pathlib import Path
import torch
from torch import nn
from torch.nn import functional as F

torch.set_num_threads(1)
torch.manual_seed(17)
DTYPE=torch.float64

def base_hash(base):
    h=hashlib.sha256()
    for name, value in sorted(base.state_dict().items()):
        h.update(name.encode());h.update(str(tuple(value.shape)).encode())
        h.update(str(value.dtype).encode());h.update(value.detach().cpu().numpy().tobytes())
    return h.hexdigest()

class LoRALinear(nn.Module):
    def __init__(self, base, rank=2, alpha=4):
        super().__init__()
        if type(rank) is not int or not 0<rank<=min(base.in_features,base.out_features):
            raise ValueError('本例rank须为有效正整数')
        if not isinstance(alpha,(int,float)) or isinstance(alpha,bool) or not 0<float(alpha)<float('inf'):
            raise ValueError('alpha须为有限正数')
        self.base=copy.deepcopy(base)
        self.base.requires_grad_(False)
        self.rank,self.alpha=rank,float(alpha)
        self.A=nn.Parameter(torch.randn(rank,base.in_features,dtype=base.weight.dtype,device=base.weight.device)*.02)
        self.B=nn.Parameter(torch.zeros(base.out_features,rank,dtype=base.weight.dtype,device=base.weight.device))
    def forward(self,x):
        return self.base(x)+(x@self.A.T@self.B.T)*(self.alpha/self.rank)
    def adapter(self):
        return {'rank':self.rank,'alpha':self.alpha,'base_sha256':base_hash(self.base),
                'A':self.A.detach().clone(),'B':self.B.detach().clone()}
    def restore(self,state):
        if set(state)!={'rank','alpha','base_sha256','A','B'} or state['rank']!=self.rank or state['alpha']!=self.alpha or state['base_sha256']!=base_hash(self.base):
            raise ValueError('适配器配置或基础权重不匹配')
        for key in ('A','B'):
            value=state[key];target=getattr(self,key)
            if not isinstance(value,torch.Tensor) or value.shape!=target.shape or value.dtype!=target.dtype or not torch.isfinite(value).all():
                raise ValueError('适配器Tensor合同')
        with torch.no_grad():
            self.A.copy_(state['A']);self.B.copy_(state['B'])
    def merged(self):
        layer=copy.deepcopy(self.base)
        with torch.no_grad():layer.weight.add_((self.alpha/self.rank)*(self.B@self.A))
        return layer

base=nn.Linear(6,3,dtype=DTYPE)
model=LoRALinear(base)
assert model.A.numel()+model.B.numel()==2*(6+3)
x=torch.randn(128,6,dtype=DTYPE)
ta=torch.randn(2,6,dtype=DTYPE)*.2;tb=torch.randn(3,2,dtype=DTYPE)*.2
with torch.no_grad():y=base(x)+x@ta.T@tb.T
train,test=x[:96],x[96:];yt,ytest=y[:96],y[96:]
assert torch.equal(model(x),base(x))
original={k:v.clone() for k,v in model.base.state_dict().items()}
loss=F.mse_loss(model(train),yt);loss.backward()
assert torch.count_nonzero(model.A.grad)==0 and model.B.grad.abs().sum()>0
assert all(p.grad is None for p in model.base.parameters())
analytic=float(model.B.grad[0,0]);eps=1e-6
with torch.no_grad():
    model.B[0,0]+=eps;plus=float(F.mse_loss(model(train),yt))
    model.B[0,0]-=2*eps;minus=float(F.mse_loss(model(train),yt))
    model.B[0,0]+=eps
assert abs(analytic-(plus-minus)/(2*eps))<1e-9
initial=float(loss.detach())
with torch.no_grad():initial_test=float(F.mse_loss(model(test),ytest))
opt=torch.optim.Adam([model.A,model.B],lr=.04)
for _ in range(260):
    opt.zero_grad();current=F.mse_loss(model(train),yt);current.backward()
    assert torch.isfinite(model.A.grad).all() and torch.isfinite(model.B.grad).all()
    opt.step()
with torch.no_grad():final=float(F.mse_loss(model(train),yt));final_test=float(F.mse_loss(model(test),ytest))
assert final<initial*.01 and final_test<initial_test*.01
assert all(torch.equal(v,model.base.state_dict()[k]) for k,v in original.items())
with tempfile.TemporaryDirectory() as folder:
    path=Path(folder)/'own-adapter.pt';torch.save(model.adapter(),path)
    state=torch.load(path,weights_only=True)
    restored=LoRALinear(base);restored.restore(state)
    assert torch.allclose(restored(x),model(x),atol=1e-12,rtol=1e-12)
    bad=dict(state,alpha=8)
    try:restored.restore(bad)
    except ValueError:pass
    else:raise AssertionError('缩放不同不能静默恢复')
    changed=copy.deepcopy(base)
    with torch.no_grad():changed.weight.add_(1)
    try:LoRALinear(changed).restore(state)
    except ValueError:pass
    else:raise AssertionError('基础权重不同不能恢复')
merged=model.merged()
assert torch.allclose(merged(x),model(x),atol=1e-12,rtol=1e-12)
print('矩形LoRA参数',model.A.numel()+model.B.numel(),'训练/测试MSE',initial,final,initial_test,final_test)
print('B初始梯度、有限差分、冻结、实际优化、恢复和合并等价通过；仅人工线性教师')
```

本例6→3、rank=2时Adapter有18个参数，与原weight的18个相同；它是机制探针，不宣称参数节省。矩形层要满足 r<d_in*d_out/(d_in+d_out) 才比原weight少。rank=2恰好覆盖所造教师残差的秩，不能推广为语言任务最佳rank。真实模型要锁定目标模块路径、设备/dtype、dropout、偏置策略、基础模型 revision、模板及 Adapter 配置；不同量化后端也不一定支持直接合并。合并与恢复等价是必要实现检查，独立任务评价另见第 6 篇。

### 2.3 QLoRA

典型 QLoRA 冻结低比特存储的基础模型，使用较高精度进行必要计算并训练 LoRA Adapter；它不是直接把所有权重作为 4-bit 可训练参数更新。

目标是进一步降低显存占用。

需要额外关注：

- 量化方法；
- compute dtype；
- 量化误差；
- 哪些层保持高精度；
- Adapter 与量化权重的兼容。


### 2.3.1 量化误差探针不等于低比特训练驻留

来源 quantize_to_nf4 实际用 absmax/7 的均匀整数格点，再存为 int8；不是具有非均匀格点的 NF4。quantize_model 随即解量化，将浮点 Tensor 放回模型，整数副本还在另一字典中，因此其打印的内存估算不是训练进程实测。NF4、double quantization与paged optimizer在下一小节完整解释；[训练资源与数值量化实现](15-训练资源与数值量化实现.md)维护一般格式、均匀量化与GPTQ/AWQ，不承担缺失的NF4主线。

这个可独立运行的探针只验证分块、尾部 padding、零块与反量化误差。codes 仍为一字节整数，未打包成4-bit；scales 的体积要一起计入，小数组未必节省。

```python
from array import array
import math

def uniform_blocks(values,block=3):
    if type(block) is not int or block<=0 or not values or not all(math.isfinite(v) for v in values):
        raise ValueError('非空有限权重和正整数block')
    original=array('f',values);codes=array('b');scales=array('f')
    for start in range(0,len(original),block):
        part=list(original[start:start+block]);part+= [0.]*(block-len(part))
        scale=max(map(abs,part))/7
        scales.append(scale)
        # 使用实际保存的float32 scale，保持编码与解码的同一合同。
        saved=scales[-1]
        codes.extend(max(-7,min(7,round(v/saved))) if saved else 0 for v in part)
    decoded=[codes[i]*scales[i//block] for i in range(len(original))]
    return original,codes,scales,decoded
w,c,s,d=uniform_blocks([0.,.13,-.31,.9,-1.,.05,0.])
assert len(c)==9 and len(d)==7 and len(s)==3
assert all(abs(a-b)<=s[i//3]/2+1e-7 for i,(a,b) in enumerate(zip(w,d)))
assert uniform_blocks([0.,0.,0.])[3]==[0.,0.,0.]
print('均匀量化MSE',sum((a-b)**2 for a,b in zip(w,d))/len(w))
print('float32元素字节',len(w)*w.itemsize,'整数+scale字节',len(c)*c.itemsize+len(s)*s.itemsize,'；非NF4/非4-bit驻留')
```

真实 QLoRA 将冻结基础权重以低比特形式驻留，并通过必要的较高精度计算向 LoRA 反传；NF4、double quantization 与 paged optimizer 是不同机制。PEFT 官方量化示例先 prepare_model_for_kbit_training 再挂 Adapter，QLoRA-style 配置可覆盖 all-linear；不能把 q_proj/v_proj 或“7B必在6GB训练”当通用保证。实际用法还需匹配本机库、模型和后端，本批未执行 SDK/下载训练。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)、[PEFT 官方说明](https://huggingface.co/docs/peft/main/en/developer_guides/quantization)。

### 2.3.2 NF4、二级常数与分页状态：从索引到可重建权重

NF4 的4-bit值是固定16级非均匀 codebook 的索引，不是“符号位+指数+尾数”的普通浮点数，也不是均匀INT4。它按零中心正态分布的分位数思路配置数值：正态概率质量集中在0附近，所以靠近0的格点更密，尾部间距更大；构造还专门保留精确0和归一化端点−1/+1，正负侧并非完全镜像。它的优势以分布假设和实际任务为条件；分块absmax归一化后的有限样本、明显偏斜/多峰或强离群权重不自动服从标准正态，不能宣称所有分布上误差最小。[QLoRA第3节与附录E](https://arxiv.org/html/2305.14314v1)。

对一个权重块，先算 s=max|w_i|，再归一化 u_i=w_i/s，选使 |u_i−C[j]| 最小的索引 j∈{0,…,15}；解码为 ŵ_i=s*C[j]。零块单独编码为0的索引，避免除0。s属于量化状态，4-bit索引本身不能恢复绝对数值。下面采用“第一索引高4位、第二索引低4位”的教学打包约定，末尾奇数补零索引并保留原长度；不声称与某个后端的内存布局、边界tie或矩阵内核逐字节一致。

手算块 [−2,0,.32,1.44,2]：s=2，u约为[−1,0,.16,.72,1]，最近索引为[0,7,9,14,15]。解码第三项为2*.1609302≈.3218604，第四项为2*.7229568≈1.4459136；端点与0在不压缩s时准确恢复。用本文位序得到07 9e f7三字节，最后的7是补位，不是第六个权重。

以下标准库程序使用附录E及官方代码中的固定16个数，验证nearest、实际nibble打包、零块、尾部与解码。后半段使用均匀signed-int8仅演示“先压缩scale，再恢复scale”的二级合同和误差；它不是bitsandbytes的实际8-bit动态codebook或真实QLoRA训练。

```python
from array import array
import math

NF4=(-1.0,-0.6961928009986877,-0.5250730514526367,
     -0.39491748809814453,-0.28444138169288635,-0.18477343022823334,
     -0.09105003625154495,0.0,0.07958029955625534,0.16093020141124725,
     0.24611230194568634,0.33791524171829224,0.44070982933044434,
     0.5626170039176941,0.7229568362236023,1.0)
ZERO=7

def pack_nibbles(ids):
    if not ids or any(type(i) is not int or not 0<=i<16 for i in ids):raise ValueError('非空4-bit索引')
    return bytes((ids[i]<<4)|(ids[i+1] if i+1<len(ids) else ZERO) for i in range(0,len(ids),2))
def unpack_nibbles(raw,n):
    if type(n) is not int or n<=0 or type(raw) is not bytes or len(raw)!=(n+1)//2:raise ValueError('长度/打包合同')
    if n%2 and raw[-1]&15!=ZERO:raise ValueError('本协议补位必须是零索引')
    return [(raw[i//2]>>4) if i%2==0 else (raw[i//2]&15) for i in range(n)]
def encode_nf4(values,block=64):
    if type(block) is not int or block<=0 or not values or any(type(v) not in (int,float) or not math.isfinite(v) for v in values):raise ValueError('非空有限输入/块大小')
    weights=array('f',values)
    if not all(math.isfinite(v) for v in weights):raise ValueError('本例仅支持可表示的float32输入')
    scales=array('f');ids=[]
    for start in range(0,len(weights),block):
        part=weights[start:start+block];scale=max(map(abs,part));scales.append(scale)
        for v in part:
            ids.append(ZERO if scale==0 else min(range(16),key=lambda i:(abs(v/scale-NF4[i]),i)))
    return {'n':len(weights),'block':block,'packed':pack_nibbles(ids),'scales':scales},list(weights)
def decode_nf4(state):
    n,b=state['n'],state['block'];ids=unpack_nibbles(state['packed'],n);scales=state['scales']
    if type(b) is not int or b<=0 or len(scales)!=(n+b-1)//b or any(not math.isfinite(s) or s<0 for s in scales):raise ValueError('scale状态合同')
    return [scales[i//b]*NF4[j] for i,j in enumerate(ids)]

state,w=encode_nf4([-2,0,.32,1.44,2],block=5) # 小手算块，不是SDK的受支持块尺寸承诺。
ids=unpack_nibbles(state['packed'],state['n']);decoded=decode_nf4(state)
assert ids==[0,7,9,14,15] and state['packed'].hex()=='079ef7'
assert decoded[0]==-2 and decoded[1]==0 and decoded[-1]==2
assert all(abs(v/s-NF4[j])<=min(abs(v/s-c) for c in NF4)+1e-15 for v,j,s in zip(w,ids,[2]*5))
zero,_=encode_nf4([0.,0.,0.],block=2);assert decode_nf4(zero)==[0.,0.,0.]
try:unpack_nibbles(bytes([7,158,240]),5)
except ValueError:pass
else:raise AssertionError('非零补位须拒绝')
assert len(state['packed'])==3 and len(state['scales'])*state['scales'].itemsize==4

def scale_int8_probe(scales,group=2):
    if type(group) is not int or group<=0 or not scales or any(not math.isfinite(s) or s<0 for s in scales):raise ValueError('scale输入')
    offset=sum(scales)/len(scales);codes=array('b');level2=[]
    for start in range(0,len(scales),group):
        residual=[s-offset for s in scales[start:start+group]];t=max(map(abs,residual));level2.append(t)
        codes.extend(round(r/t*127) if t else 0 for r in residual)
    restored=[offset+codes[i]/127*level2[i//group] for i in range(len(scales))]
    return codes,level2,offset,restored
s=[2.,2.5,3.,6.];q,t,offset,restored=scale_int8_probe(s)
assert len(q)==4 and len(t)==2 and offset==3.375
assert all(abs(a-b)<=t[i//2]/254+1e-15 for i,(a,b) in enumerate(zip(s,restored)))
# 相同NF4索引下，scale误差传播为 |s-s_hat|*|C[j]|，零code不受影响。
value=NF4[9]
assert math.isclose(abs(s[1]*value-restored[1]*value),abs(s[1]-restored[1])*abs(value),abs_tol=1e-15)
assert s[1]*NF4[ZERO]==restored[1]*NF4[ZERO]==0.
plain=32/64;double=8/64+32/(64*256)
assert plain==.5 and double==.126953125 and math.isclose(plain-double,.373046875)
print('NF4索引',ids,'打包',state['packed'].hex(),'解码',decoded,'载荷+scale字节',3+4)
print('二级scale偏移',offset,'索引',list(q),'恢复',restored,'；仅uniform-int8机制探针')
print('64/256常数开销bits/weight',plain,double,'差',plain-double,'；offset/尾部/元数据另计')
```

**Double quantization压缩的是一级scale，不是对权重再训练两遍。** 假设每64个权重保存一个32-bit scale，常数开销为32/64=.5 bits/weight。将这些scale以8-bit编码保存，再对每256个scale保存一个32-bit二级常数，理想摊销为8/64+32/(64*256)=.126953125≈.127 bits/weight，少约.373。权重索引的4 bits另加；tensor级offset、codebook、shape/dtype、尾部块、对齐与分配开销也另计，小张量不保证划算。

一种重建合同是先保存全scale均值μ，对r_b=s_b−μ按二级块量化；恢复ŝ_b=μ+t_g*D[k_b]，再用ŝ_b*C[j_i]恢复权重。μ负责居中，t_g是二级常数，k_b是8-bit索引，D是二级codebook。库的QuantState还保留state2/offset，解码先恢复absmax并加offset，再解码NF4权重。二级量化引入额外scale误差：w−ŝ*C[j]=(w−s*C[j])+(s−ŝ)*C[j]；因|C[j]|≤1，其附加误差至多|s−ŝ|，端点会受影响，而精确零code仍为0。这里的uniform-int8探针仅便于手算，不能冒称复现库的二级编码。[bitsandbytes固定版本的codebook与nested状态实现](https://github.com/bitsandbytes-foundation/bitsandbytes/blob/833649043474794b8fe7a4136e0c40faf077b2e0/bitsandbytes/functional.py)。

**Paged optimizer管理状态驻留位置，未减少逻辑状态总量。** 它利用支持的CPU/GPU unified memory按页管理优化器状态，GPU压力出现时可把状态页迁到CPU RAM，需要更新时再迁回。Adam的一阶/二阶状态仍存在，CPU内存、GPU内存与传输都要计量；PCIe/互联迁移、缺页和工作集抖动可能降低吞吐，不能保证任意机器无OOM或免费加速。Activation checkpointing减少保存的前向激活并在反向重算，属于“存什么/重算什么”；显式CPU offload由训练系统安排某类Tensor的迁移/更新，属于不同调度策略。三者可组合，但分页不会替代激活、权重或临时workspace的全部容量需求。

在真正QLoRA中，冻结基础权重的低比特存储、较高精度解码计算、LoRA梯度和优化器状态各有角色。本例只有CPU标量编码/解码与状态算术，没有bitsandbytes内核、GPU unified memory、paged optimizer、BF16矩阵训练或预训练模型质量/显存验证。2026-10-07新增本块实际执行；已验证的LoRA与uniform探针保持原SHA，不重复运行。

## 3. SFT 数据结构

## 10. 先检查一个训练批次

训练前人工展开 2～4 条样本的“渲染文本 → Token ID → label → loss mask”：确认用户文本未变成回答标签、EOS 没有遗漏、截断没有切掉全部答案。若使用 packing，必须明确是否允许不同样本跨边界注意以及位置如何重置，不能只看长度刚好装满。

例如一个样本含 80 个指令 Token、20 个回答 Token、28 个 Padding；回答训练应有 20 个有效目标位置（EOS 的计数以预处理定义为准），分母不应是 128。先在少量干净样本上观察能否拟合，排除管线错误，再扩大数据；拟合小集成功仅说明训练链路可工作，不证明泛化。

**自检**：训练 loss 下降但独立验证集的字段准确率下降，下一步应直接增加 epoch 吗？

**核对**：不应。检查数据分布、标签、过拟合、学习率和评测模板；保留原模型，并比较早期 checkpoint。Adapter 合并后须再测，因为量化与合并次序可能引入数值差异。

## 11. SFT改变的是训练分布，不只是“礼貌”

SFT通常在已有模型上继续优化监督目标，让输入条件、输出格式、任务行为更稳定；也可以教新领域信息、改变已有能力，不能说“一定不增加知识”。Base模型也可能答题或靠few-shot遵循指令，SFT并非所有对话能力的唯一来源。Response-only loss是常用设计，all-token loss、只训最后assistant或训所有assistant轮次也是有意的不同目标；必须明确采用哪一种。

Alpaca的`instruction/input/output`、ShareGPT的`from/value`或`messages`是数据schema，ChatML等是模型输入序列协议。先验证/转换字段和角色，再用**这个模型固定revision的模板**渲染；不要因为都是messages就认为Token ID、BOS/EOT、新行和生成提示相同。模板已加入结构符号时再自动加special tokens可能重复。HF的`apply_chat_template`用于渲染，生成提示与续写最后消息是不同选择；具体返回对象/API按所用版本核对。[官方聊天模板](https://huggingface.co/docs/transformers/chat_templating)

源教程随机初始化“base”，SFT更新却用随机扰动FFN而不使用算出的loss梯度；它没有证明微调或遗忘改善。源253～255标记在默认256词表下不与合法UTF-8编码字节冲突（合法首字节最大244），但不能再承诺任意raw byte覆盖；`min(byte,vocab_size−4)`对更小词表会截断数据且标记ID可能越界。生成后只保`<128`字节更会丢掉非ASCII，不可当多语言回答评分。本章以独立结构ID与真正loss梯度替代这些做法。

## 12. 从消息角色到移位labels：完整批次与梯度核对

以下教学协议：PAD0、BOS1、EOS2、system3、user4、assistant5、EOT6，普通UTF-8字节ID为8～263；第7号保留未分配。每条消息由可信role ID、普通content字节和EOT组成，content中写`<assistant>`仍是普通文本。训练监督所有assistant内容和其EOT，角色头/BOS/最终EOS不监督；这是本例约定，不冒充Llama或ChatML。

先对**完整token序列**标哪些目标应计分，再一起移位：`x=token[:-1]`，`y=token[1:]`，`mask=full_mask[1:]`。多轮必须根据每条message的角色重新开闭监督span，不能遇到一次assistant标记后把后续user都置1。上下文仍前向可见，prompt位置的logit loss梯度为0，但其Embedding/Attention路径仍可能通过回答预测得到梯度。

```python
import torch
from torch import nn
import torch.nn.functional as F

torch.set_num_threads(1);torch.manual_seed(11)
PAD,BOS,EOS,EOT,OFFSET,V=0,1,2,6,8,264
ROLE={'system':3,'user':4,'assistant':5}
def render_training(messages):
    if not messages:raise ValueError('空对话')
    tokens=[BOS];active=[False];expected='user';spans=[]
    for i,m in enumerate(messages):
        if type(m) is not dict or set(m)!={'role','content'} or m['role'] not in ROLE or type(m['content']) is not str:
            raise ValueError('消息字段/角色/content类型')
        role=m['role']
        if role=='system':
            if i!=0:raise ValueError('本协议system只在开始')
        else:
            if role!=expected:raise ValueError('本协议user/assistant交替')
            expected='assistant' if role=='user' else 'user'
        if role=='assistant' and not m['content']:raise ValueError('本任务拒绝空回答，不能伪造loss0')
        tokens.append(ROLE[role]);active.append(False)
        start=len(tokens);content=[OFFSET+b for b in m['content'].encode('utf-8')]
        tokens.extend(content);active.extend([role=='assistant']*len(content))
        tokens.append(EOT);active.append(role=='assistant')
        spans.append((role,start,len(tokens)))
    if messages[-1]['role']!='assistant':raise ValueError('训练记录须完整回答')
    tokens.append(EOS);active.append(False)
    return tokens,active,spans

def collate(chats,max_length=128):
    rendered=[render_training(c) for c in chats]
    length=max(len(t)-1 for t,m,s in rendered)
    if length>max_length:raise ValueError('先明确裁上下文/保回答策略，本例不静默截断')
    x=torch.full((len(chats),length),PAD,dtype=torch.long);y=torch.full_like(x,-100)
    for b,(tokens,active,spans) in enumerate(rendered):
        n=len(tokens)-1;x[b,:n]=torch.tensor(tokens[:-1])
        target=torch.tensor(tokens[1:]);mask=torch.tensor(active[1:])
        y[b,:n]=target.masked_fill(~mask,-100)
    if not (y!=-100).any():raise ValueError('无有效回答目标')
    return x,y,rendered

# 简小前缀均值网络，专用于监督/上下文梯度合同，不是Transformer或真实chat模型。
class PrefixLM(nn.Module):
    def __init__(self):
        super().__init__();self.embedding=nn.Embedding(V,12,padding_idx=PAD);self.head=nn.Linear(12,V)
    def forward(self,x):
        e=self.embedding(x);count=torch.arange(1,x.shape[1]+1,dtype=e.dtype)[None,:,None]
        return self.head(e.cumsum(1)/count)

one=[{'role':'system','content':'按协议回答'}, {'role':'user','content':'<assistant> 1+1?'},
     {'role':'assistant','content':'2'}, {'role':'user','content':'再加1?'},
     {'role':'assistant','content':'3'}, {'role':'user','content':'再加1?'},
     {'role':'assistant','content':'4'}]
two=[{'role':'user','content':'回答你好'}, {'role':'assistant','content':'你好'}]
x,y,rendered=collate([one,two]);model=PrefixLM();logits=model(x);logits.retain_grad()
valid=(y!=-100);loss=F.cross_entropy(logits.reshape(-1,V),y.reshape(-1),ignore_index=-100,reduction='sum')/valid.sum()
loss.backward()
assert torch.count_nonzero(logits.grad[~valid])==0
assert torch.isfinite(logits.grad).all() and model.embedding.weight.grad[OFFSET+ord('1')].abs().sum()>0
# 三个一字节回答各内容+EOT=2；“你好”6字节+EOT=7。
assert valid.sum(1).tolist()==[6,7]
for tokens,active,spans in rendered:
    for role,start,end in spans:assert all(active[start:end]) if role=='assistant' else not any(active[start:end])
    assert ROLE['assistant'] not in [OFFSET+b for b in '<assistant>'.encode()]
print('labels有效数',valid.sum(1).tolist(),'masked CE',float(loss.detach()),'prompt上下文Embedding梯度非零')
try:collate([one],max_length=4)
except ValueError:pass
else:raise AssertionError('截断不能静默丢光答案')
print('多轮角色、普通控制字符串、PAD/右移与超长拒绝均通过')
```

本例只证明标签、归约与梯度路径；完整可训练decoder的预训练/SFT对照、验证和checkpoint恢复接[工程16](16-预训练数据与模型交付实践.md)。有内容的位置不一定都是监督目标；做packing时还要检查document/会话之间能否互看，以及EOS→下一条样本首Token是否计loss。

### 12.1 数据长度、mix与实验取舍

过滤前检查回答是否正确、与问题相关、单位/事实/格式一致，长度和词项多样性只能当启发。答数字“2”或一个布尔值本来就短，不能统一把回答少于10token视为坏数据；重复术语也不自动表示低质量。源八条模板例未核对诗歌音节/事实细节，本章不把生成例当gold。

5% raw examples不等5%有效训练token：1条raw有64个目标、19条SFT各2个目标，raw贡献$64/(64+38)≈62.7\%$监督token。按样本、token或loss项mix是不同方案，需记录实际计数和目标权重。保持独立的领域/通用/良性拒绝/格式切片，不用“raw PPL增加15%”作所有任务通用的遗忘门槛。

学习率/epoch取决于基础模型、数据、有效batch、可学参数和目标；1e−4/2e−5/1e−6不保证中间必是sweet spot，超过3epoch也不必总坏。对照要复制同一初始权重、冻结同样测试集与预算，记录训练/验证/完整生成指标；本批不执行大型LoRA/QLoRA或真实模型下载。

## 13. AI反馈：来源、训练方法与正确性分开

Constitutional AI原两阶段是：按原则生成批评/修订并SFT；再由AI做成对偏好，训练preference model后用RL优化。后来也可把AI偏好直接用于DPO，但DPO不需要先训练reward model；**RLAIF说明反馈来源，PPO/DPO/GRPO说明优化方法**，不能混成同一个算法。原则选择和事实判定是不同环节，修改原则文件不自动修改模型权重。[CAI原论文](https://arxiv.org/html/2212.08073v1)

反馈模型可与policy相关，原研究确有self-critique；这不意味着同模型family一概禁止或一定正确。独立人工/规则/环境证据用于校准盲点，记录rubric版本、样本和误接受，不硬规定“每轮必须5%–10%人工数据”。规则奖励给出了外部反馈，不能说自生成训练永远没有新信号、能力永远止于初始模型；有效性也不保证。

源critique只看response、不看prompt；删“maybe”会把合理不确定变过度自信，截最后一句或给拒绝前面加“答案是”也可能破坏事实/请求适用性。新修订必须对照同一prompt、证据和格式重新判定，不把changed=True计成improved=True。ORM看最终结果，PRM看中间可验证步骤；形式上多给几条分数不等真正的过程正确性。二者都可被错误规则或奖励捷径利用，不能预设ORM普遍更安全、PRM一定更低效。

### 13.1 有界算式与严格答案：可运行验证器

本例语言只支持整数常量、括号、正负号和加减乘除，结果用精确Fraction；明确限制字符/节点/数值规模，拒绝函数、属性、幂和其它表达式。它是一个有限任务解释器，不调用`eval`，也不是运行任意代码的安全沙箱。代码任务需另设隔离执行、资源限制和测试契约，不能因`__builtins__={}`就说`eval`安全。

```python
import ast
import re
import json
from fractions import Fraction

LIMIT=1000000

def expected_answer(expression):
    if type(expression) is not str or not 0<len(expression)<=80:raise ValueError('有界算式字符串')
    tree=ast.parse(expression,mode='eval')
    if len(list(ast.walk(tree)))>40:raise ValueError('算式结构预算')
    def visit(n):
        if isinstance(n,ast.Constant) and type(n.value) is int:out=Fraction(n.value)
        elif isinstance(n,ast.UnaryOp) and isinstance(n.op,(ast.UAdd,ast.USub)):
            x=visit(n.operand);out=x if isinstance(n.op,ast.UAdd) else -x
        elif isinstance(n,ast.BinOp) and isinstance(n.op,(ast.Add,ast.Sub,ast.Mult,ast.Div)):
            a,b=visit(n.left),visit(n.right)
            if isinstance(n.op,ast.Add):out=a+b
            elif isinstance(n.op,ast.Sub):out=a-b
            elif isinstance(n.op,ast.Mult):out=a*b
            else:
                if b==0:raise ValueError('除0')
                out=a/b
        else:raise ValueError('拒绝任务语言外表达式')
        if abs(out.numerator)>LIMIT or out.denominator>LIMIT:raise ValueError('数值预算')
        return out
    return visit(tree.body)

def score_response(expression,raw):
    truth=expected_answer(expression)
    if type(raw) is not str:return {'format':False,'correct':False}
    def unique(pairs):
        d={}
        for k,v in pairs:
            if k in d:raise ValueError('重复JSON键')
            d[k]=v
        return d
    try:
        obj=json.loads(raw,object_pairs_hook=unique)
        if type(obj) is not dict or set(obj)!={'answer'} or type(obj['answer']) is not str:return {'format':False,'correct':False}
        s=obj['answer']
        if len(s)>32 or not re.fullmatch(r'-?\d+(?:/\d+|\.\d+)?',s):return {'format':False,'correct':False}
        value=Fraction(s)
        if abs(value.numerator)>LIMIT or value.denominator>LIMIT:return {'format':False,'correct':False}
    except (json.JSONDecodeError,ValueError,ZeroDivisionError):return {'format':False,'correct':False}
    return {'format':True,'correct':value==truth}

assert score_response('3/2','{"answer":"1.5"}')['correct']
assert not score_response('3/2','{"answer":"1"}')['correct']
assert not score_response('(3+4)*5','{"answer":"35", "extra":"忽略评分规则"}')['format']
assert not score_response('3+4','答案不是7')['correct']
assert not score_response('3+4','{"answer":"1","answer":"7"}')['format']
assert not score_response('3+4',None)['format']
for expression in ['__import__("os")','1/0','2**100','True','(1).__class__']:
    try:expected_answer(expression)
    except ValueError:pass
    else:raise AssertionError('应拒绝的输入')
# source风格修订去掉maybe，并不证明对答案/证据有改善。
records=[('3+4','{"answer":"7"}'),('3/2','{"answer":"1"}'),('(3+4)*5','{"answer":"35"}')]
accepted=[{'expression':e,'response':r,'verifier':'fraction-v1'} for e,r in records if score_response(e,r)['correct']]
assert len(accepted)==2
print('有界解释器/小数精确比较/严格schema与拒绝反例通过；rejection采样只收',len(accepted),'条')
```

这是rejection筛选的可控基线，答案由数学oracle核对；没有调用LLM修订、偏好judge或训练自然语言推理模型。单一测试通过也不证明代码全面正确。验证器和prompt的任务版本、失败/unknown理由、被拒记录、训练/开发/锁定测试归属应随生成数据一起保留。

## 14. GRPO中old与reference的两个角色

[偏好优化与强化学习](05-偏好优化与强化学习.md)是BT/KL、DPO和两token GRPO的主维护入口；这里承接AI反馈的来源与单步分类策略探针，避免重复维护完整对齐算法。

对同一prompt采G个回答，常见outcome advantage为$(r_i-\bar r)/(s_r+\epsilon)$，并记录std口径。**old policy**用于采这批回答并给importance ratio分母；**reference**是约束漂移的锚点。它们起初可来自相同权重，却不是可随当前optimizer更新的同一个对象：$\rho=\pi_{new}/\pi_{old}$，KL比较new/ref。旧数据多次更新时old logprob固定；更换reference是明确算法/实验选择，需重新记录锚点和KL协议。

Token级原目标还包括回答有效长度和组平均；一个回答的同一outcome advantage可以分配到它的多个token，padding/role等按协议mask。不要把整段概率比、每token比和长度归约混用。[GRPO原论文](https://arxiv.org/html/2402.03300v3) 裁剪和策略梯度基础接[策略梯度与稳定更新](../AI%20算法基础/深度学习专题/23-深度价值与策略梯度实践.md)。

源`grpo_step`只有NumPy指标，ratio用ref代替old，`mean(logref−logpolicy)`在其合成样本下为负，不是真KL；三轮固定mock_sampler没有任何可学policy更新，奖励起伏不是self-improvement。真实KL还要说明在哪个prompt/状态分布上求期望，不把“历次KL数值相加”叫总漂移距离。

### 14.1 真实优化的一步分类策略探针

下面每prompt只有三个固定候选回答，全部概率可枚举，因此精确算KL/entropy。它训练的是可学**分类策略表**，不是LLM；目的是验证group、old/ref、裁剪和梯度更新。候选正确性直接给定fixture，完整任务verifier见上节。每轮old采样，复用这批数据两次更新，reference一直保初始快照。

```python
import torch
from torch import nn

torch.set_num_threads(1);torch.manual_seed(12)
logits=nn.Parameter(torch.zeros(2,3));reference=logits.detach().clone().softmax(-1)
reward_table=torch.tensor([[1.,0.,0.],[0.,1.,0.]])  # 两个fixture prompt，各自正确候选。
optimizer=torch.optim.Adam([logits],lr=.08);rng=torch.Generator().manual_seed(13)
beta,entropy_weight,clip_eps=.05,.01,.2;group=16;zero_groups=0
before=logits.detach().softmax(-1)
for round_id in range(25):
    old_log=logits.detach().log_softmax(-1);old_prob=old_log.exp()
    samples=torch.multinomial(old_prob,group,replacement=True,generator=rng)
    rewards=reward_table.gather(1,samples);std=rewards.std(1,unbiased=False,keepdim=True)
    advantage=torch.where(std>1e-8,(rewards-rewards.mean(1,keepdim=True))/(std+1e-8),torch.zeros_like(rewards)).detach()
    zero_groups+=int((std<=1e-8).sum())
    sampled_old=old_log.gather(1,samples)
    for update in range(2):
        new_log=logits.log_softmax(-1);new_prob=new_log.exp()
        ratio=(new_log.gather(1,samples)-sampled_old).exp()
        objective=torch.minimum(ratio*advantage,ratio.clamp(1-clip_eps,1+clip_eps)*advantage).mean()
        kl=(new_prob*(new_log-reference.log())).sum(1).mean()
        entropy=-(new_prob*new_log).sum(1).mean()
        loss=-objective+beta*kl-entropy_weight*entropy
        optimizer.zero_grad();loss.backward()
        assert logits.grad is not None and torch.isfinite(logits.grad).all()
        optimizer.step()
    if round_id in [0,9,24]:
        current=logits.detach().softmax(-1);current_kl=(current*(current.log()-reference.log())).sum(1).mean()
        print('round/分类策略概率/更新后精确KL',round_id+1,current.tolist(),float(current_kl))
after=logits.detach().softmax(-1)
assert torch.allclose(after.sum(1),torch.ones(2)) and torch.allclose(reference,torch.full_like(reference,1/3))
assert after[0,0]>before[0,0] and after[1,1]>before[1,1]
print('零reward-variance组数',zero_groups,'；只通过此分类fixture，不宣称推理/泛化能力')
```

std=0可能是全部正确、全部错误、题太容易、reward分辨力弱或样本恰相同，不自动等于mode collapse。上例PG部分归0，但KL/entropy仍可能有梯度；response多样性、任务正确率、长度与分语言/难度切片另报。PRM中每步可验标签和entropy正则也不能保证避免奖励捷径或模式坍缩。

## 16. LoRA 消融与适配器验收

原课五项练习统一落到同一实验协议：rank对照2/4/8/16/32/64须复制同一基础权重、数据划分和预算，不能每轮重新随机造不同base后归因rank；target module对照也固定初始状态并记录实际可学参数。量化block大小对照报告误差、scale/padding和真正存储，而非把uniform探针叫NF4。双Adapter用同一base/revision/template训练，先验证独立恢复再验证交换；复制两套基础模型并不验证共享驻留服务。合并前后在同输入/dtype比较输出，再单独测同工作量下的速度；浮点容差须合理，不承诺固定1e−5与普遍加速。
