# 04｜微调与参数高效适配

## 1. 微调前先定义“要改变什么”

微调通常用于稳定改变：

- 输出风格；
- 任务格式；
- 专业行为；
- 分类/抽取能力；
- 特定领域操作模式；
- 多模态映射。

如果只是缺最新知识，应优先考虑 RAG。

## 2. 三种典型训练方式

### 2.1 Full Fine-tuning

更新大部分或全部模型参数。

优点：

- 表达能力最强；
- 可深度改变模型。

代价：

- 显存高；
- checkpoint 大；
- 更容易遗忘原能力；
- 多任务维护成本高。

### 2.2 LoRA

冻结基础模型，在目标层增加低秩 Adapter：

```text
ΔW ≈ A · B
```

主要参数：

- rank；
- alpha；
- dropout；
- target modules。

优势：

- 可训练参数少；
- checkpoint 小；
- 多 Adapter 易管理；
- 当前仍是非常主流的 PEFT 方法。

### 2.3 QLoRA

在低比特量化基础模型上训练 LoRA Adapter。

目标是进一步降低显存占用。

需要额外关注：

- 量化方法；
- compute dtype；
- 量化误差；
- 哪些层保持高精度；
- Adapter 与量化权重的兼容。

## 3. SFT 数据结构

文本指令数据通常包含：

```json
{
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ]
}
```

多轮数据必须保证角色顺序和模板一致。

## 4. 训练数据比“参数调得多”更重要

至少检查：

- 去重；
- 错误答案；
- 模板污染；
- 过短/过长样本；
- 样本分布；
- 泄漏测试集；
- 多轮上下文一致性；
- 领域覆盖；
- 数据授权与隐私。

## 5. Loss Mask

Instruction tuning 常常不应该让所有 Token 都参与 loss。

常见选择：

- Padding 不计 loss；
- 只训练 assistant response；
- system/user 部分只作为条件。

具体策略要与训练目标一致。

## 6. 关键超参数

- learning rate；
- batch size；
- gradient accumulation；
- epoch / steps；
- max sequence length；
- warmup；
- weight decay；
- LoRA rank / alpha；
- target modules。

不要复制教程里的值直接上生产。

## 7. Checkpoint 与 Adapter

训练过程需要区分：

- Base model；
- Adapter；
- merged model；
- optimizer state；
- trainer state。

### Adapter 模式

适合：

- 多任务；
- 快速切换；
- 少存储。

### Merge 模式

适合：

- 下游推理框架不方便动态挂载 Adapter；
- 希望得到独立完整权重。

合并后仍需重新评测。

## 8. 实验记录

至少记录：

- 数据版本；
- 模型 revision；
- 配置；
- git commit；
- 随机种子；
- loss；
- eval 指标；
- checkpoint；
- 显存和运行时长。

训练应视为实验科学，而不是一次性脚本。

## 9. 选择策略

```text
Prompt 能解决 → 不训练
需要稳定行为 → LoRA
资源紧张 → QLoRA
任务改变较大且资源足 → Full FT
需要偏好对齐 → SFT 后再考虑 DPO / RL
```
