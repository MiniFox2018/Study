# 02｜模型获取与环境管理

## 1. 模型不是一个权重文件

一个可正常运行的模型通常依赖一组一致资产：

- 权重；
- config；
- tokenizer；
- processor（多模态常见）；
- generation config；
- chat template；
- 自定义代码（部分模型需要）；
- 模型许可证和使用约束。

只复制权重、不保留配置，常常无法可靠恢复。

## 2. 模型来源

常见来源包括：

- Hugging Face；
- ModelScope；
- 官方仓库或对象存储；
- 企业内部模型仓库。

工程上需要记录：

- 模型唯一标识；
- revision / commit；
- 下载时间；
- 校验信息；
- 本地缓存路径。

### 为什么要固定 revision

如果只写：

```text
download latest
```

同一脚本几个月后可能拿到不同文件。

需要复现实验时，应固定具体 revision。

## 3. 环境隔离

建议每个独立工程维护明确的：

- Python 版本；
- PyTorch 版本；
- Transformers / 推理框架版本；
- CUDA / ROCm / CANN 等运行时；
- 关键依赖锁定文件。

### 不要把“能安装”理解成“兼容”

常见冲突来自：

- PyTorch 与 CUDA；
- 推理框架与 Transformers；
- Flash Attention 与编译器；
- Triton 与 GPU 架构；
- NPU 插件与基础框架；
- MLX-LM 与 Transformers。

## 4. 环境记录的最低要求

建议每个实验记录：

```text
OS
Python
Framework
Accelerator runtime
GPU/NPU/Apple Silicon 型号
Driver
Model revision
Training/inference framework version
```

## 5. 缓存与磁盘

大模型工程会同时产生：

- 原始权重；
- 量化权重；
- Adapter；
- checkpoint；
- optimizer state；
- dataset cache；
- tokenizer cache；
- eval 输出。

因此磁盘规划也属于工程设计。

## 6. 安全注意

不要把：

- API Key；
- Hugging Face Token；
- ModelScope Token；
- 云平台密钥；

写入 Notebook、Markdown 或 Git。

统一通过：

- 环境变量；
- Secret Manager；
- 本地不入库配置；

管理。

## 7. 当前规则

具体 `pip install` 命令、镜像地址、CUDA/CANN/ROCm 版本属于高时效信息，本知识库不固化。

执行时必须重新核验模型官方说明和框架当前兼容矩阵。
