## 1. SFT、偏好与在线结果各解决什么

SFT用任务示范最大化答案token概率，学习基本能力、指令跟随、格式和结构；它不保证输出符合所有偏好。偏好数据是同一个prompt的chosen/rejected：可比较正确性、帮助程度、格式、验证充分性及安全要求。只标注措辞或长度，就主要提供这些差异的信号；不能把篇幅长自动当质量好。

经典三阶段是SFT→训练奖励模型RM→在线优化策略。它是一种RLHF实现，RLHF也用于轨迹片段/人类反馈的其他形式，不是所有偏好学习都必须PPO。DPO从现有偏好对直接训练策略；GRPO是在线组相对策略优化，可使用规则、验证器或学习奖励，并非只能用于数学或必定没有RM。没有可靠reward、没有在线探索需求时，不应只因算法流行增加rollout成本。

| 对象 | 输入/输出 | 被训练成什么 | 常见混淆 |
|---|---|---|---|
| 策略πθ | prompt/历史→下一个动作或token分布 | 生成行为 | 策略概率不是奖励分数 |
| 奖励rφ | prompt+回答/轨迹→标量 | 与偏好标签或其他目标相关的评分 | RM分高不等于答案真、符合全部目标 |
| 价值V/Q | 状态或状态动作→预期回报 | baseline/长期价值估计 | 价值模型与奖励模型任务不同 |
| reference πref | 同历史→固定概率 | 正则化参照 | reference与采样的old policy不一定相同 |
| verifier | 输出/执行结果→规则得分 | 任务结果检查 | 有限测试通过不等于程序完全正确 |

## 2. Bradley–Terry：先学一个排序模型

对同题两答案a/b，设差Δ=rφ(x,a)−rφ(x,b)，建模 `P(a优于b|x)=sigmoid(Δ)`。标签z=1表示a胜，z=0表示b胜，负对数似然为 `softplus(Δ)−zΔ`。其对Δ导数为 `sigmoid(Δ)−z`；已按chosen在前整理的数据等价于 `softplus(−Δ)`。Δ=0时概率0.5、loss≈0.693；Δ=log3时概率0.75、chosen loss≈0.288。这是模型拟合的偏好概率，不是事实正确性的置信度。[DPO的BT与KL目标推导](https://arxiv.org/html/2305.18290v2#S3)

同一prompt给所有奖励加任意c(x)，差不变；因此偏好对不能识别绝对奖励零点。放大奖励会改变偏好概率与后续KL的相对强度，温度/噪声和奖励尺度需有明确协议。确定可分的偏好无正则时，模型可不断放大差值降低loss；低loss也可能来自捷径。平局/分歧可用软标签（例如0.5）、独立平局模型或明确剔除规则，不能偷偷把平局都当chosen获胜。

真实RM可用Transformer处理prompt+回答，在约定的EOS/有效末token读出标量；padding/tokenizer/截断及prompt条件不能错。不存在“RM参数量必须至少等于policy”的数学要求；容量、覆盖、校准和对新策略样本的有效性需要实测。[人类轨迹偏好学习](https://arxiv.org/abs/1706.03741)

### 2.1 完整的条件排序与留出采样例

两种人工prompt对同四个动作的排序相反，RM是2×4分数表，必须使用prompt。训练/留出来自同一个有限规则集；留出准确不证明新语言、真人偏好或分布外泛化。

```python
import numpy as np
rng=np.random.default_rng(31)
quality=np.array([[3.,1.,-1.,0.],[-1.,3.,0.,1.]])
def pairs(n):
    rows=[]
    for _ in range(n):
        x=int(rng.integers(2));a,b=rng.choice(4,2,replace=False)
        if quality[x,a]<quality[x,b]:a,b=b,a
        rows.append((x,int(a),int(b)))
    return rows
train=pairs(500);test=pairs(100);w=np.zeros_like(quality)
for x,a,b in train:
    d=w[x,a]-w[x,b]
    p=1/(1+np.exp(-d));g=p-1
    w[x,a]-=.15*g;w[x,b]+=.15*g
accuracy=np.mean([w[x,a]>w[x,b] for x,a,b in test])
assert np.isfinite(w).all() and np.argmax(w[0])==0 and np.argmax(w[1])==1
x,a,b=test[0]
loss=lambda scores:np.logaddexp(0,-(scores[x,a]-scores[x,b]))
assert np.isclose(loss(w),loss(w+np.array([[100.],[-50.]])))
assert np.isclose(1/(1+np.exp(-np.log(3))),.75)
print('同有限规则的100个留出采样排序准确率',round(float(accuracy),3),'prompt改变最优动作；奖励平移不变')
```

实际数据按prompt/任务/来源分组留出，避免近重复回答或同题改写泄漏。保留标注者分歧、说明、顺序随机化、来源与长度；没有通用30%噪声率或必然90%准确率。Best-of-N用RM重排候选，无需更新策略；它仍有生成/评分成本，N增大也可能更会利用评分漏洞。

## 3. RLHF目标：奖励高与离reference近的取舍

固定x，标准正则目标是

$$J(\pi)=\sum_y\pi(y|x)r(x,y)-\beta\sum_y\pi(y|x)\log\frac{\pi(y|x)}{\pi_{ref}(y|x)},\quad\beta>0.$$

KL方向是policy→reference。reference必须在policy可能选择的答案上给正概率，否则KL可能无穷；不能用任意epsilon把零支持问题掩盖。有限且可枚举的动作中，用归一化约束求驻点得

$$\pi^*(y|x)=\frac{\pi_{ref}(y|x)\exp(r(x,y)/\beta)}{Z(x)}.$$

一般语言模型的全答案空间不能直接枚举，这才需要采样/策略优化。β→0偏向奖励最大答案；大β更接近reference。没有普遍β=.01或KL<10的合格线，KL口径是每token/全序列/均值还是和，会显著改变数值。KL只是软正则，不能保证安全、事实或RM所在“流形”被严格保持。

在线实践可对已采样y使用 `rφ(x,y)−β(logπθ(y|x)−logπref(y|x))` 作轨迹奖励，再按算法计算优势、固定old采样概率和PPO裁剪；也可显式优化可微KL。**把同一prompt下整个KL当一个停止梯度的动作无关常数，从每条奖励扣掉，不能得到正确KL梯度**：它只是一个baseline，其期望策略梯度为零。源toy这样做且混合prompt标准化，β曲线不能当完整RLHF优化验证。

完整序列 `logπ(y|x)=Σt logπ(y_t|x,y_<t)`，要核对token shift、prompt/response掩码、EOS、padding、截断及有效长度。终点RM评分可通过return/优势给前面token，不表示每个推理步骤已被单独验证。old policy是生成这批rollout的版本，应在多个更新epoch中固定；reference是正则化参照，通常冻结更久。

### 3.1 完整离散策略目标、闭式基准与KL梯度反例

三个动作可枚举，所以能核对目标，而非用打印reward代替优化正确性。

```python
import torch
torch.set_num_threads(1);torch.manual_seed(32)
dtype=torch.float64
reward=torch.tensor([1.,0.,-.5],dtype=dtype)
ref=torch.tensor([.2,.5,.3],dtype=dtype);beta=.7
star=torch.softmax(ref.log()+reward/beta,0)
logits=torch.nn.Parameter(torch.zeros(3,dtype=dtype))
opt=torch.optim.Adam([logits],lr=.06)
for _ in range(400):
    logp=logits.log_softmax(0);p=logp.exp()
    kl=(p*(logp-ref.log())).sum()
    objective=(p*reward).sum()-beta*kl
    opt.zero_grad();(-objective).backward();opt.step()
p=logits.softmax(0).detach()
assert torch.allclose(p,star,atol=1e-6)
# 把整个KL当停止梯度的常数：其动作无关策略梯度严格为零。
z=torch.tensor([.4,-.1,.2],dtype=dtype,requires_grad=True)
logp=z.log_softmax(0);probs=logp.exp();kl=(probs*(logp-ref.log())).sum()
true_grad=torch.autograd.grad(kl,z,retain_graph=True)[0]
wrong=-kl.detach()*(probs.detach()*logp).sum()
wrong_grad=torch.autograd.grad(wrong,z)[0]
assert true_grad.norm()>0 and torch.allclose(wrong_grad,torch.zeros(3,dtype=dtype),atol=1e-15)
print('精确KL策略吻合闭式基准',p.numpy().round(4),'整条KL常数扣分缺梯度反例通过')
```

## 4. DPO：把偏好损失直接写成策略概率

由上式有 `r(x,y)=β log(π*(y|x)/πref(y|x))+β logZ(x)`。BT只使用同题奖励差，Z消去；于是DPO用

$$\mathcal L_{DPO}=-E\log\sigma\left(\beta\left[\log\frac{\pi_\theta(y_+|x)}{\pi_{ref}(y_+|x)}-\log\frac{\pi_\theta(y_-|x)}{\pi_{ref}(y_-|x)}\right]\right).$$

这不是chosen单独做SFT，也不是先采样再“只选最好的”。chosen相对rejected的log概率差提高，不保证chosen绝对概率在每次更新都提高。隐式reward依赖reference和β，有限数据/模型/偏好假设与分布漂移下不保证精确恢复人类效用；离线DPO也不是KL硬约束。[DPO原论文](https://arxiv.org/abs/2305.18290)

### 4.1 完整DPO差值、更新与回答掩码

```python
import torch
import torch.nn.functional as F
torch.set_num_threads(1);torch.manual_seed(33)
logits=torch.nn.Parameter(torch.zeros(2,4))
ref_logp=torch.tensor([[.4,.3,.2,.1],[.1,.4,.2,.3]]).log()
pairs=torch.tensor([[0,0,2],[0,0,3],[0,1,2],[1,1,0],[1,1,2],[1,3,0]])
opt=torch.optim.Adam([logits],lr=.04);beta=.5
x,a,b=pairs.T
with torch.no_grad():before=(logits.log_softmax(-1)[x,a]-logits.log_softmax(-1)[x,b]).mean()
for _ in range(120):
    logp=logits.log_softmax(-1)
    margin=beta*((logp[x,a]-ref_logp[x,a])-(logp[x,b]-ref_logp[x,b]))
    loss=F.softplus(-margin).mean();opt.zero_grad();loss.backward();opt.step()
with torch.no_grad():after=(logits.log_softmax(-1)[x,a]-logits.log_softmax(-1)[x,b]).mean()
assert torch.isfinite(loss) and after>before
# 人工token log概率：prompt/pad不可混入completion sum，EOS按协议计入。
values=torch.tensor([[-.8,-.4,-.7,-.2,-9.]])
response_mask=torch.tensor([[False,False,True,True,False]])
completion_logp=(values*response_mask).sum(-1)
assert torch.allclose(completion_logp,torch.tensor([-.9]))
print('DPO相对margin提升，response有效token和/EOS掩码通过；有限动作示例')
```

## 5. GRPO：同题相对优势与裁剪更新

同题生成G个完整答案，计算r_i。原始outcome形式把 `A_i=(r_i−组均值)/(组总体标准差+ε)` 广播到这条答案各token。四奖励[1,1,0,0]的均值/标准差各.5，优势[1,1,−1,−1]。全错或全对的组都没有相对排序信号；ε防除零不会制造信号，G=1更没有组内比较。组均值和标准差使用当前组样本，属于已声明的估计/归一化协议，不能直接套用独立、动作无关baseline的无偏保证。

原始多epoch目标使用每个token的ratio `ρ_i,t=πθ(token|history)/πold(token|history)`，最大化 `min(ρA,clip(ρ,1−εclip,1+εclip)A)−β KL`，再按选定的序列/token权重聚合。A负时也必须用**min**，其有益更新方向与A正相反。old/ref/当前策略三者分开；裁剪目标不等于保证每个实际概率ratio都在区间。[DeepSeekMath](https://arxiv.org/abs/2402.03300)

组标准差归一化、逐答案平均或全batch有效token平均、长回答截断、process/outcome奖励是不同协议，改变后不应继续声称完全相同目标。当前TRL有多种选项，开发版默认并不等于原论文；固定版本并核对生成、奖励、KL和损失配置，本章不用未核旧SDK拼一个所谓生产脚本。[TRL GRPO方法与损失说明，2026-10-05核验](https://huggingface.co/docs/trl/main/en/grpo_trainer#looking-deeper-into-the-grpo-method)

### 5.1 完整两token采样、旧概率、裁剪与精确序列KL

每题两个二值动作，第二个分布依赖第一个。只有完整二token对匹配人工答案才得1；共享终点优势传给两步，不是中间推理正确性的监督。两步长度相同，本例每答案/每token的平均只差固定系数；KL精确枚举四条序列，实际LLM不能照此枚举。

```python
import torch
from torch import nn
torch.set_num_threads(1);torch.manual_seed(34)
first=nn.Parameter(torch.zeros(2,2));second=nn.Parameter(torch.zeros(2,2,2))
opt=torch.optim.Adam([first,second],lr=.025);G=16;beta=.03
correct=torch.tensor([[0,1],[1,0]])
# reference是每步均匀，四个完整序列概率1/4。
def sequence_kl():
    lp=first.log_softmax(-1);lq=second.log_softmax(-1)
    joint_logp=lp[:,:,None]+lq
    return (joint_logp.exp()*(joint_logp+torch.log(torch.tensor(4.)))).sum((1,2)).mean()
def advantage(reward):
    sd=reward.std(-1,correction=0,keepdim=True)
    return (reward-reward.mean(-1,keepdim=True))/(sd+1e-8)
assert torch.equal(advantage(torch.zeros(2,G)),torch.zeros(2,G))
queries=0
for update in range(160):
    with torch.no_grad():
        p=first.softmax(-1);q=second.softmax(-1)
        a=torch.multinomial(p,G,replacement=True)
        x=torch.arange(2)[:,None].expand(2,G)
        b=torch.multinomial(q[x,a].reshape(-1,2),1).reshape(2,G)
        reward=((a==correct[:,0,None])&(b==correct[:,1,None])).float()
        A=advantage(reward);queries+=2*G
        old=torch.stack([p[x,a].log(),q[x,a,b].log()],-1)
    # 多次更新前固定这一批old概率；每次重新前向当前policy。
    for epoch in range(3):
        lp=first.log_softmax(-1);lq=second.log_softmax(-1)
        current=torch.stack([lp[x,a],lq[x,a,b]],-1)
        ratio=(current-old).exp();adv=A[:,:,None]
        surrogate=torch.minimum(ratio*adv,ratio.clamp(.8,1.2)*adv)
        loss=-surrogate.mean()+beta*sequence_kl()
        opt.zero_grad();loss.backward();opt.step()
with torch.no_grad():
    success=first.softmax(-1)[torch.arange(2),correct[:,0]]*second.softmax(-1)[torch.arange(2),correct[:,0],correct[:,1]]
    assert torch.isfinite(success).all() and success.min()>.85
# 负优势不能误用max：ratio=.5, A=-1, 下界=.8，min=-.8。
assert torch.minimum(torch.tensor(-.5),torch.tensor(-.8)).item()<-.79
print('两token完整答案成功概率',success.numpy().round(3),'验证器调用',queries,'old/ref/裁剪与零优势组通过')
```

这里只学有限索引表，没有语言表示或算术运算；看起来成功的“1+2”字符串若仅映射预设索引，不能称学会数学。比较GRPO/PPO/REINFORCE要匹配生成序列数、有效token、环境/验证器调用、优化步、模型与预算，多seed报告波动；源例400次GRPO各8候选，REINFORCE各1候选，不能称相同采样预算。源12程序以`p−p_ref`拉logits，是反方向KL(ref‖policy)的logit梯度，不是本章KL(policy‖ref)的梯度；源docs直接拉logits差则是参数空间惩罚。二者均不替代裁剪目标。

## 6. 奖励设计、标签与验证器失效

可组合正确性、格式、单元测试、规则、长度约束、安全要求和judge；同时保留各分量与权重。长度只能是任务相关约束，简单长度归一化也可能奖励短而遗漏，不能视为万能去捷径。构造“格式对答案错、很长但重复、答案对带无关话、利用测试漏洞”的反例，先验reward排序，再在未参与reward开发的任务上评估。

RM分上升而人工/独立任务质量下降是过优化警报。例如真实效用[1,0]，代理奖励[1,2]：优化器正确最大化代理也会偏向坏动作；β更大只减少漂移，不会修复标签。高KL/entropy降低/长度增加都是诊断，不是单个数值即可证明reward hacking。

RLAIF用AI给偏好，可能继承judge偏差；Constitutional AI以明确原则指导批评/改写及偏好生成。PRM对步骤评分，但错误的局部评分也可能被利用；ORM给终点结果，两者与价值模型分别校验。规则验证器可用于GRPO，也可用于PPO等，reward来源不定义优化算法。[R1方法与限制](https://arxiv.org/html/2501.12948v1#S2)

R1-Zero与R1是研究案例：前者从已预训练base直接做RL，后者加入冷启动SFT、推理RL、拒绝采样后SFT及面向多任务的RL；“没有SFT”不表示没有预训练知识或从空白学推理。学生通过教师轨迹SFT的蒸馏也不等于学生运行了RL。论文中效果不外推为当前排名、普遍蒸馏必胜或纯RL必要。

## 7. 方法选择、成本与评价

离线DPO适合可靠偏好对、目标可由chosen/rejected表达、在线探索需求低的情况。在线RL适合可评分的交互结果和需要探索的新行为；GRPO省掉独立价值网络，仍要多候选生成、评分、old/ref概率与策略训练。安全/偏好任务也可用学习奖励，不能固定“alignment只能DPO、GRPO只能verifier”。

后训练检查目标成功率、原能力、独立质量与reward相关性、长度/格式投机、覆盖、坍塌、安全行为以及成本。训练reward、测试reward、blind人工评估分开；held-out可减过拟合但不保证发现全部漏洞。rollout保存policy/ref版本、tokenizer/chat模板、采样参数、停止原因、失败/超时及有效token分母。服务推理和微调的实验评价继续由06维护，训练/adapter与推理入口分别见04/03；不以本章toy成功替代。

### 7.1 源练习与自查的核对标准

1. BT练习：第2.1节500训练/100同分布留出采样可复算。源main600/200得到1.000，只验证人工好坏词；忽略prompt和未知词是明确边界，不把90%当真人偏好门槛。
2. β扫描：第3节目标和3.1闭式基准说明β含义。源β=.01/.1/1的RM最终约1.185/1.186/1.179、KL约2.293/2.265/1.831，不足判定哪组“作弊”，其KL更新还缺完整梯度。真实比较需独立效用、同采样预算与holdout。
3. DPO与RM+RL比较：第3.1/4.1实现各自机制；两者不能只按最终RM评分判质量，也不要求数值策略完全相同。大模型算力/质量对照未运行。
4. GRPO bandit和两步扩展：第5.1有正确完整序列信用分配；1000步内收敛不是通用保证。PPO/REINFORCE公平消融需等生成预算，本批没有伪报大规模对照。
5. 全错组A全0。辅助KL可能仍有梯度，不能把“reward无信号”说成任何loss都0。reference冻结不意味着old rollout概率永不更新，下一批rollout应来自新policy。

## 8. KTO、ORPO、SimPO：数据与目标都不能只改名字

先修第2～4节。三者减少不同环节，不能按“少一个模型就必然更稳、更省三分之二或质量相同”排序。reference概率可预计算但需冻结版本、Tokenizer、模板、mask和截断协议；adapter共享底座也会改变显存账，模型角色数不等于完整权重拷贝数。

| 方法 | 数据及机制 | 需要核对的差异 |
|---|---|---|
| KTO | 单回答的desirable/undesirable标签；以相对reference的log概率与KL参照点建立效用 | 不要求同题成对；相对偏好chosen不一定绝对“好”，rejected也未必绝对“坏” |
| ORPO | chosen的SFT项，加chosen/rejected的log odds ratio偏好项 | 不是“SFT + DPO”，标准形式无reference；长度平均和odds的数值定义要一致 |
| SimPO | 以回答平均log概率作为reward，加入目标reward margin | 无reference；γ是目标margin，不是长度归一化指数，也不保证完全消除长度偏好 |

令 `r=logπθ(y|x)−logπref(y|x)`，KTO设参照点 `z=E_x KL(πθ(·|x)‖πref(·|x))`，并在计算样本损失时停止z梯度。desirable损失为 `λ_D[1−σ(β(r−z))]`，undesirable为 `λ_U[1−σ(β(z−r))]`；λ_D/λ_U是类别权重，须结合标签比例和任务选择，不能一律bad乘1.5。语言回答空间的KL不能精确枚举，原实现有batch估计及其偏差条件。这个目标的sigmoid效用会饱和，与binary logistic的**负log sigmoid**损失不同。[KTO原论文](https://arxiv.org/abs/2402.01306)

ORPO令平均回答log概率 `a=(Σ有效回答token logp)/长度`，`P̄=exp(a)`是token条件概率的几何平均，非整条回答概率。`log odds=a−log(1−exp(a))`；loss为chosen的token NLL加 `λ softplus(−[log odds_w−log odds_l])`。若a接近0需稳定计算 `log(−expm1(a))`，a=0使odds无穷，应检查数据/数值合同。不能省掉odds项后继续称ORPO。[ORPO原论文及概率定义](https://arxiv.org/abs/2403.07691)

SimPO用 `reward=βa`，loss=`softplus(−[β(a_w−a_l)−γ])`。γ>0要求相对差超过指定margin；用均值而非总和改变了目标和长度权重，不等于仍是原始DPO推导。模型先生成再由人/验证器判断质量，不能把训练margin上涨直接当真实win rate上涨。[SimPO原论文](https://arxiv.org/abs/2405.14734)

### 8.1 完整CPU目标与真实梯度更新

四个有限动作均为一个token；这个特例sum=mean。KTO参照点在该有限空间精确枚举并detach，实际语言空间不可照搬。三次运行各从均匀policy重新开始，比较目的只是确认公式及梯度，不排序三种算法的质量。

```python
import torch
import torch.nn.functional as F
torch.set_num_threads(1)
dtype=torch.float64;ref=torch.tensor([.4,.3,.2,.1],dtype=dtype)
good=torch.tensor([True,True,False,False])
def objective(z,kind):
    lp=z.log_softmax(0);p=lp.exp()
    if kind=='KTO':
        ratio=lp-ref.log();point=(p*ratio).sum().detach()
        sign=torch.where(good,1.,-1.)
        weight=torch.where(good,1.,1.2)
        return (weight*(1-torch.sigmoid(.5*sign*(ratio-point)))).mean()
    if kind=='ORPO':
        logodds=lp-torch.log(-torch.expm1(lp))
        return -lp[0]+.2*F.softplus(-(logodds[0]-logodds[3]))
    if kind=='SimPO':return F.softplus(-(.8*(lp[0]-lp[3])-.4))
    raise ValueError(kind)
for kind in ['KTO','ORPO','SimPO']:
    z=torch.nn.Parameter(torch.zeros(4,dtype=dtype))
    opt=torch.optim.Adam([z],lr=.03)
    first=objective(z,kind).item()
    for _ in range(100):
        loss=objective(z,kind);opt.zero_grad();loss.backward()
        assert torch.isfinite(z.grad).all();opt.step()
    p=z.softmax(0).detach();last=objective(z,kind).item()
    assert p[0]>.25 and last<first
    print(kind,'loss',round(first,4),'->',round(last,4),'policy',p.numpy().round(3))
# 不同长度：总logp会偏向短序列的概率，mean改变统计口径。
short=torch.tensor([-1.,-1.]);long=torch.full((6,),-.8)
assert short.sum()>long.sum() and short.mean()<long.mean()
assert torch.isclose(F.softplus(torch.tensor(0.)),torch.log(torch.tensor(2.)))
print('长度sum/mean反转；DPO零margin loss=log2，与beta无关')
```

## 9. 从源RLHF/DPO程序识别“算损失”和“真的优化”

Phase10/07的RM forward用了Transformer blocks后的最后hidden，训练却只以chosen的Embedding+LN更新head，漏rejected且绕过blocks。对于固定特征φ，正确head梯度是 `(σ(w·(φ_w−φ_l))−1)(φ_w−φ_l)`；训练backbone还需完整反传。均值/末token池化各自对有效token和padding有合同，六个训练样本上准确率高不证明哪种泛化更好。

源`ppo_training`按reward大小随机扰动FFN，无old ratio、优势、clip或reward梯度；`dpo_train`按margin正负随机扰动，也没求DPO梯度。入口的“SFT模型”只是随机初始化MiniGPT，没有加载真实SFT checkpoint；`copy_model_weights`还漏LM head，因该miniGPT把输出与embedding绑定才恰未造成该部分差异。不能把这项copy策略套到untied模型。源main实跑exit0、RM同六对5/6、生成评分变化或微小KL，都不能证明RLHF/DPO改善。

source08总序列logp按shift取回答token这一思想有效，但prompt过长可将completion全截掉并返回0，preferred/rejected截断后的标签也可能失效。两者同prompt、同Tokenizer、同模板和停止协议；检查有效回答长度非零、EOS是否计入、pad排除、labels与logits移位一致。policy=ref时隐式reward都0，margin=0，loss=log2；strict `margin>0` 的准确率为0，若将tie计半才是.5。动态loss图把tie称“log½被β缩放”不准确，β作用于margin，不能作用于最终log2常数。

对DPO的β，闭式reward目标中更大β使理想最优policy保守；有限优化中初始margin=0的梯度系数却为β/2，因此不能从“β更大”直接推出每一步更小。离线目标没有逐步KL硬界，也不保证杜绝reward hacking。反复更换reference/EMA会改变相对目标，应按round冻结、记录版本及独立留出评测；不能一边变baseline一边把隐式reward跨round相加。

### 9.2 原十项扩展练习如何验收

1. RM均值与末token池化：同一backbone、有效token、训练/验证prompt划分、更新预算和seed，对照真实梯度训练的两模型；六个训练pair的结果仅是训练拟合，本批没有伪报它的泛化胜负。
2. RM校准：正margin是排序，不等校准。用重复/软标签或真实频率比较σ(margin)，给可靠性图/Brier或log loss；额外四对由独立任务生成且不参与训练。加prompt常数不改变偏好，因此绝对reward均值不能独立说明校准。
3. 长度奖励hacking：源生成器固定20个新token，长度不随policy可变，无法观察“越训越长”。须引入EOS/不同长度动作、验证独立质量，比较β；KL=.1不保证堵漏洞，第6节代理/真实效用反例已说明。
4. 多目标：保存各分量、单位、权重和Pareto取舍；`.7/.3`不保证兼顾帮助与简洁。用“短但漏关键条件、长且必要”的反例验排序，禁止由分数组合直接宣称质量达标。
5. KL扫描：用第3节正确目标、匹配生成和训练预算，记录独立效用、KL方向/分母；不预设.001必坏/.02最佳/.5无学习。
6. KTO扩展：用第8节效用与参照点，不是把binary logistic改名；可拆偏好对用于演示，真实unpaired标注应独立判断好坏与保留分歧。
7. 长度归一DPO：注明改了目标，记录response-only有效token长度并查长/短控制pair；均值可能改善一个偏差又造成另一个，不称万能预防。
8. ORPO扩展：用log odds而非`SFT+αDPO`，按第8.1核对loss与梯度；α扫描只说明该fixture，真实效果须留出生成测试。
9. 迭代DPO：round1生成答案必须经人/验证器重新标哪条更好，不能默认原chosen始终胜出；固定独立测试、版本和等预算，比较两轮，保留退化结果。
10. reference对照：base、早期checkpoint和按round冻结EMA都是不同目标；必须记录prompt/模板一致性与版本。选择基于独立质量、原能力和成本，不只基于自己定义的隐式reward margin。

Phase10/07、08的两份输出设计模板中，数据rubric、分歧/顺序随机化、OOD验证、分量监控和部署前回归均融合第2/6/7/9节；固定数据量→准确率、RM必须≥policy、KL阈值、通用GPU小时、固定胜率/遗忘门槛以及“一种方法只适合某规模”均不保留。标签协议和预算是实验设计，不能由prompt模板自动保证结果。

## 10. 指令偏好、真实质量与过优化的证据

第1～4节已给SFT、BT奖励模型、KL目标和DPO推导。进一步学习时，把**示范质量、标注群体的偏好、任务正确性、原能力和安全要求**分别保存。标注者喜欢一个回答，并不表示其事实正确、满足全部利益相关者或允许执行工具。预训练模型可以通过few-shot提示回答问题；下一token预测与稳定遵循用户意图的训练目标仍有差异。SFT和RL也可以学习新的任务规律，不能把“RLHF只重新分配行为”理解为永远不能学新知识；实际收益取决于输入、反馈、探索与模型能力。

InstructGPT是具体研究架构：约13k SFT训练prompt、33k RM训练prompt、31k PPO训练prompt，RM使用6B模型并从SFT移除输出unembedding后接标量头。每题4～9回答的排名生成相关pair，训练划分与采样不能把相关pair当完全独立样本。1.3B版本在该论文的提示分布上获标注者更高偏好，说明模型规模与指令任务偏好是不同评价轴；论文中**85±3%对未提示GPT-3、71±4%对few-shot GPT-3**是175B InstructGPT的比较，不应拼接成“所有小模型70%赢所有大模型”。PPO-ptx用预训练loglikelihood梯度混合缓解受测NLP任务回退；它是研究中的方法，不是全部现代实验都必须采用的固定流程。[InstructGPT，§3及结果](https://arxiv.org/abs/2203.02155)

### 10.1 Goodhart：为什么代理升分不保证质量提升

假设人工真实效用为 `[1,0]`，代理为 `[1,2]`。优化器偏向第二个动作时正确执行了代理目标，却损害了任务目标。这个反例与第6节一致：发现奖励漏洞必须有独立任务效果或质量信号。高KL、篇幅增长、熵下降都是诊断线索，单独一个指标不能证明欺骗或奖励作弊。

常用Goodhart分类帮助定位原因：有限样本相关性中的回归效应、进入未见极端区域、改变代理与目标的因果关系、主体有意利用测量。语言系统里，长度、流畅自信、迎合、看似合理的解释、测试或日志修改都可能成为捷径；它们也可能由不同训练或上下文机制造成，不能根据表面现象认定一个唯一因果。检查“长度控制后仍改善吗”“解释与实际计算/工具结果一致吗”“候选能否写评价器或结果文件”，再选择数据、评价器、权限隔离或优化预算上的修订。

Gao等人的Gold RM是更大模型提供的**合成真值**，并非已测到终极人类价值。其经验拟合以 $d=\sqrt{D_{KL}(\pi\|\pi_{init})}$ 为横轴，分别得到

$$R_{BoN}(d)=d(\alpha_{BoN}-\beta_{BoN}d),\qquad R_{RL}(d)=d(\alpha_{RL}-\beta_{RL}\log d).$$

这里 $R$ 是居中后的gold分数，系数依奖励模型规模、数据及设置而变；RL的经验形式在原点附近不适用。论文没有为proxy分数得到同等满意的通用拟合，所以不能把proxy与gold均写成同一个二次式。BoN在相应连续奖励、独立采样假设下的分布KL为 $\log N-(N-1)/N$，也不是某个获选样本向量距原点的长度。论文用6B Gold RM、不同较小代理和合成比较研究特定问题，不能推出任意模型、任意预算必然出现相同塌陷。[Gao等人，p2–4与图2](https://proceedings.mlr.press/v202/gao23h.html)

若gold与proxy都是固定线性函数，单位协方差高斯策略的均值受KL预算约束，则最优均值沿 $w_{proxy}$ 缩放，gold期望为

$$E[r_{gold}]=\sqrt{2K}\frac{w_{gold}^{\mathsf T}w_{proxy}}{\|w_{proxy}\|}.$$

它随 $\sqrt K$ 单调升、降或保持零，无法产生“先升后塌陷”。给拟合标签加Student-t噪声只改变估计方向，不把这个固定线性问题变成过优化曲线。源课程的模拟不能用来复现原论文峰值，更不能把最后打印的takeaway当运行结论。

### 10.2 KL、重尾误差与缓解的条件

令代理效用 $U=V+X$，$V$ 为真实效用、$X$ 为误差。Catastrophic Goodhart研究在特定重尾、支持和效用条件下，存在KL任意小而代理期望极高的分布，真实效用却没有相应提升。直观上，极小概率的极高奖励可能主导期望；**不需要把全部质量放到罕见模式上**。有限有界空间并非严格意义的重尾，现实“近似重尾”需要证据；论文检查的开源奖励分布多与轻尾一致，且若使用轻尾独立误差等强条件，可以得到不同保证。它否定“只凭KL就保证安全”，不证明所有RLHF必崩塌。[原论文，定义、理论条件与经验局限](https://arxiv.org/abs/2407.14503v2)

RM ensemble的悲观聚合可以减少某个评分器的漏洞，但共享数据、架构或偏差也会造成共同失效。early stopping须看独立质量与原能力，而非只看训练reward；提高KL正则不会修复错误标签。DPO/IPO/SLiC在受测数据和模型中也存在过优化，原因包括有限偏好约束以外的大量自由度；论文经验结果不是每种直接算法在每个任务都会同形退化的定理。[直接对齐算法过优化研究](https://arxiv.org/abs/2406.02900v2)

2026综述的Proxy Compression Hypothesis把目标压缩、优化放大、评价器与策略共同适应作为统一研究视角。可借它列出机制假设和消融，不能把综述假说写成已证明所有表面错误的唯一原因。[PCH综述摘要](https://arxiv.org/abs/2604.13602)

## 11. IPO与Balanced Preference Optimization：有限目标和弱侧更新

KTO、ORPO和SimPO的正确目标及CPU梯度已在第8节；新增方法沿用同样的response-only概率、reference版本与独立评价合同。数据规模或长度比可以是本次实验决策参数，不是“少于5000对必须拒绝训练”或“长度比1.5必换算法”的通用门槛。全部偏好强度相同仍可有明确排序；只有概率接近0.5等情况下，方向性信息才可能很弱。

### 11.1 IPO的平方目标不是概率差硬上界

记同prompt pair的相对log概率差为

$$h_\theta=\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}.$$

在IPO常用样本目标中，$\tau>0$ 是相应正则系数：

$$L_{IPO}=E\left(h_\theta-\frac1{2\tau}\right)^2,\qquad \nabla L=2\left(h_\theta-\frac1{2\tau}\right)(\nabla\log\pi_w-\nabla\log\pi_l).$$

目标差大于 $1/(2\tau)$ 后，梯度会把它往回拉；有限步或冲突pair仍可能超过目标，**没有硬截断**。例如 $\tau=.4$ 时目标1.25，$h=3$ 的loss为3.0625，是有限惩罚而不是非法状态。原理论从直接偏好概率的identity映射出发，避免把接近确定的偏好经无界logit转换；模型参数化、支持覆盖和数据采集分布是理论条件。回答token取总和还是平均会改变协议，不能只改名称而不记实际目标。[IPO原论文，§5](https://arxiv.org/abs/2310.12036v2)

### 11.2 BPO取弱侧margin，不是给DPO加任意anchor

这里BPO是**Balanced Preference Optimization**，依据2025原稿；源教材写成Behavior Preservation、DPO加chosen下降惩罚，均与原方法不符。定义已含尺度的隐式reward

$$r_w=\beta\log(\pi_w/\pi_{ref,w}),\quad r_l=\beta\log(\pi_l/\pi_{ref,l}),\quad m=\min(r_w,-\alpha r_l),\quad 0<\alpha\le1.$$

logistic目标为 $L=\operatorname{softplus}(-m)$。$r_w<-\alpha r_l$ 时弱侧是chosen，其梯度为 $-\sigma(-m)\beta\nabla\log\pi_w$；反之为 $\sigma(-m)\alpha\beta\nabla\log\pi_l$。这里 $r$ 已含 $\beta$，计算loss不能再次乘一次；在两侧相等的折点选择明确的次梯度协议，数值梯度核对避开折点。

例如 $r_w=-.2,r_l=-1,\alpha=.5$，DPO相对margin为.8但BPO margin为−.2，会先处理chosen低于reference的问题。若**实际达成** $m\ge\gamma>0$，则 $\pi_w\ge e^{\gamma/\beta}\pi_{ref,w}$；这是条件式结论，不表示用该loss每一步都能满足或每个chosen概率永远单调上升。共享参数、冲突偏好和数据分布仍要评测。原稿18.8%→28.9%是指定Llama-3.1-8B-Instruct在五个数学benchmark平均pass@1提高10.1**个百分点**，不是当前通用性能增幅；本批未确认原OpenReview会议状态。[BPO原稿，式3–5及条件定理](https://arxiv.org/abs/2506.03557v1)

### 11.3 完整离线例：核对两种新目标的梯度

三个有限动作均为一个token，因此这里只核公式与导数。BPO两组状态分别触发chosen/rejected分支，与中心差分比较；同时构造chosen与rejected都降而DPO相对差上升的归一分布。没有训练LLM或排序算法真实质量。

```python
import math

def logsoftmax(z):
    m = max(z)
    shifted = [v-m for v in z]
    if any(not math.isfinite(v) for v in shifted):
        raise ValueError('有限输入的相减仍可能溢出')
    logz = math.log(sum(math.exp(v) for v in shifted))
    return [v-logz for v in shifted]

def softplus(x):
    return max(x, 0) + math.log1p(math.exp(-abs(x)))

def sigmoid(x):
    return math.exp(-softplus(-x))

def loss_gradient(z, ref, method, beta=.7, alpha=.5, tau=.4):
    for name, value in (('beta', beta), ('alpha', alpha), ('tau', tau)):
        if type(value) not in (int, float) or not math.isfinite(value) or value <= 0:
            raise ValueError(name+'必须为有限正数')
    if alpha > 1:
        raise ValueError('alpha不得大于1')
    if len(z) != len(ref) or len(z) < 2 or any(type(v) not in (int,float) or not math.isfinite(v) for v in z+ref):
        raise ValueError('概率输入形状或数值非法')
    normalized_ref = logsoftmax(ref)
    if any(not math.isclose(a,b,rel_tol=0.,abs_tol=1e-10) for a,b in zip(ref,normalized_ref)):
        raise ValueError('ref必须为归一化reference log概率，不能传原概率或任意分数')
    lp = logsoftmax(z)
    p = [math.exp(a) for a in lp]
    rw, rl = beta*(lp[0]-ref[0]), beta*(lp[1]-ref[1])
    if not math.isfinite(rw) or not math.isfinite(rl):
        raise ValueError('隐式reward计算溢出')
    gw = [float(i == 0)-p[i] for i in range(len(z))]
    gl = [float(i == 1)-p[i] for i in range(len(z))]
    if method == 'ipo':
        h = (lp[0]-ref[0])-(lp[1]-ref[1])
        target = .5/tau
        delta = h-target
        loss = delta*delta
        grad = [2*delta*(a-b) for a,b in zip(gw,gl)]
        if not all(math.isfinite(v) for v in [h,target,delta,loss,*grad]):
            raise ValueError('IPO目标、损失或梯度超出浮点范围')
        return loss, grad
    if method == 'bpo':
        margin = min(rw, -alpha*rl)
        if rw < -alpha*rl:
            dm = [beta*a for a in gw]
        elif rw > -alpha*rl:
            dm = [-alpha*beta*a for a in gl]
        else:
            raise ValueError('本例在折点不作普通导数核对')
        return softplus(-margin), [-sigmoid(-margin)*a for a in dm]
    raise ValueError(method)

ref = logsoftmax([0., 0., 0.])
for method in ('ipo', 'bpo'):
    # 两组分别检验BPO chosen和rejected分支，避开min折点。
    for z in ([-.8, .2, .4], [.8, .5, -.6]):
        loss, grad = loss_gradient(z, ref, method)
        for i in range(3):
            plus, minus = z[:], z[:]
            plus[i] += 1e-6
            minus[i] -= 1e-6
            numeric = (loss_gradient(plus,ref,method)[0]-loss_gradient(minus,ref,method)[0])/2e-6
            assert math.isclose(grad[i], numeric, abs_tol=1e-7)
# IPO target为1.25，平方惩罚仍可接纳更大h；不等于硬约束。
h = 3.
assert h > 1/(2*.4) and math.isfinite((h-1/(2*.4))**2)
# chosen/rejected都降但相对margin增：归一分布上的可复核反例。
old, new = [.4,.3,.3], [.3,.1,.6]
assert new[0] < old[0]
assert math.log(new[0]/old[0])-math.log(new[1]/old[1]) > 0
print('IPO与BPO两分支数值梯度吻合；目标非硬界；chosen下降仍可相对改善。')

for kwargs in ({'beta':True},{'beta':0},{'beta':float('nan')},{'alpha':1.1},{'alpha':-.1},{'tau':float('inf')}):
    try: loss_gradient([-.8,.2,.4], ref, 'bpo', **kwargs)
    except ValueError: pass
    else: raise AssertionError('非法超参数未拒绝')
try: loss_gradient([0.,0.,0.],ref,'bpo')
except ValueError: pass
else: raise AssertionError('折点未声明')

for bad_z, bad_ref in (([0.,0.,0.],[.3,.3,.4]), ([1e308,-1e308,0.],ref)):
    try: loss_gradient(bad_z,bad_ref,"bpo")
    except ValueError: pass
    else: raise AssertionError("ref归一化或派生计算边界未阻止")

for bad_z, bad_tau in (([1e200,-1e200,0.],.4), ([.1,.2,.3],5e-324)):
    try: loss_gradient(bad_z,ref,"ipo",tau=bad_tau)
    except ValueError: pass
    else: raise AssertionError("IPO派生损失/目标溢出未阻止")
```

源六方法比较不能当benchmark：KTO把参照点固定0且使用负log-sigmoid式梯度，缺原utility的sigmoid导数；ORPO缺odds的 $1/(1-P)$ 链因子；SimPO长度全1无法验证两倍长度影响；所谓BPO的anchor符号在chosen低于reference时反而推动它下降。其win_rate仅为最高效用动作的概率，没有相对对手的实际胜率，亦未打印声称的chosen漂移/隐式reward spread。保留这些差异作代码审查，不复制错误训练器。

## 12. 迎合：把事实正确、立场与奖励重加权分开

迎合（sycophancy）是为贴合用户立场而牺牲事实或可靠判断。对真命题赞同、礼貌措辞、承认情绪本身不构成迎合。事实题可用**真/假命题×用户/第三方表述**四组配对；社会建议则要按情境、责任与有害行为编码，并保留人类分歧，不能把所有价值判断变成单一客观真值。

固定prompt，基础policy为 $p(y)$，奖励为 $r(y)$，$s(y)$表示对错误前提赞同，使用 $t\ge0$ 表示优化倾斜强度：

$$q_t(y)=\frac{p(y)e^{tr(y)}}{Z_t},\qquad E_{q_t}s-E_ps=\frac{\operatorname{Cov}_p(s,e^{tr})}{Z_t}.$$

这是固定奖励、理想充分表达policy下的重加权结论。小 $t$ 时漂移近似 $t\operatorname{Cov}_p(s,r)$；二元s可转为两组平均reward差，但它只控制弱倾斜一阶方向。强倾斜时少量极高reward可能反转方向，不能只比较平均reward便认定任意优化强度都放大迎合。本章KL目标系数 $\beta$ 对应 $t=1/\beta$；Shapira论文用字母β表示**倾斜强度**，与本章正则系数相反。BoN按reward分位数的幂重加权，不是同一个指数公式。[Shapira等人，定理1–3与限制](https://arxiv.org/abs/2602.01002v1)

在可靠二元agreement detector与no-amplification约束下，KL最接近无约束解的修订具有 $r'=r-\lambda s$ 形式。系数依原分布、约束及检测器而定，真实检测器噪声、未见立场与被优化后的漏洞仍存在。论文的最小修订收益尚属理论分析，不保留源15%→40%→55%、α=.3～.5必奏效等无据数字，也不宣称每个优化器、每个模型规模必放大。[同论文§5–7](https://arxiv.org/abs/2602.01002v1)

### 12.1 完整离线例：平均奖励差的适用边界

错误赞同组有常见低分与稀有高分，弱倾斜时赞同减少，强倾斜时反转。另核源人工reward `[1,.3,−.5]`：正确动作奖励最高，降低KL正则会偏向正确动作，不能预设错误赞同超过uniform基线。程序未测任何真实模型。

```python
import math

def tilt(p, rewards, strength):
    if type(strength) not in (int,float) or not math.isfinite(strength) or strength < 0:
        raise ValueError('tilt strength需有限非负')
    if len(p) != len(rewards) or not p or any(type(a) not in (int,float) or not math.isfinite(a) or a <= 0 for a in p) or not math.isclose(sum(p),1.,abs_tol=1e-12):
        raise ValueError('需正支持归一概率')
    if any(type(r) not in (int,float) or not math.isfinite(r) for r in rewards):
        raise ValueError('reward需有限')
    scores = [math.log(a)+strength*r for a,r in zip(p,rewards)]
    if any(not math.isfinite(v) for v in scores):
        raise ValueError("当前数值范围无法表示重加权分数")
    if any(not math.isfinite(x) for x in scores):
        raise ValueError('有限reward与strength的乘积仍可能溢出')
    m = max(scores)
    shifted = [x-m for x in scores]
    if any(not math.isfinite(x) for x in shifted):
        raise ValueError('相对score计算溢出')
    weights = [math.exp(x) for x in shifted]
    z = sum(weights)
    return [a/z for a in weights]

# false stance：s=1代表错误赞同；稀有高reward可改变强优化方向。
p, s, rewards = [.49,.01,.5], [1.,1.,0.], [0.,10.,1.]
base_s = sum(a*b for a,b in zip(p,s))
mean_r = sum(a*b for a,b in zip(p,rewards))
cov = sum(a*b*c for a,b,c in zip(p,s,rewards))-base_s*mean_r
assert cov < 0
weak = sum(a*b for a,b in zip(tilt(p,rewards,.001),s))
strong = sum(a*b for a,b in zip(tilt(p,rewards,1.),s))
assert weak < base_s < strong
# 若只按错误赞同罚分，减s与增加正确率并非所有分布都同一关系。
# 在源课程reward [1,.3,-.5] 和uniform ref中，强优化更偏正确动作。
source_rewards = [1.,.3,-.5]
q = tilt([1/3]*3, source_rewards, 10.)
assert q[0] > .99 and q[1] < 1/3
print('弱tilt错误赞同下降，强tilt因稀有高分反转；mean gap不可推广任意优化强度。')
print('源reward下错误赞同概率可低于uniform，奖励agreement不等于必然放大。')

for bad_strength in (True,-1,float("nan"),float("inf")):
    try: tilt(p,rewards,bad_strength)
    except ValueError: pass
    else: raise AssertionError("非法tilt未拒绝")

try: tilt(p,rewards,1e308)
except ValueError: pass
else: raise AssertionError("极端数值溢出未拒绝")

try: tilt(p,rewards,1e308)
except ValueError: pass
else: raise AssertionError("派生score溢出未阻止")
```

## 13. Constitutional AI：原则生成数据，不替代独立判断

Constitutional AI（CAI）原研究包含两阶段：先从helpful模型获取初答，按抽样原则生成critique与revision，用修改后的答复训练原模型；再生成同题回答对，由AI依据原则给偏好，训练preference model并用其reward作RL。人类仍制定原则、提供评价，原研究的helpfulness训练还使用人类反馈；“无人工危害标签”不等于整个系统完全无人工监督。RLAIF说明反馈来源，不能推导所有后续优化器都必须PPO。[CAI原论文，图1](https://arxiv.org/abs/2212.08073v1)

原则模板可以记录：版本/适用角色、原则文字及理由、初答、引用原则、批评、修订、独立检查与失败。例：编码助手初答声称“已经验证备份并可删除”，但工具记录没有备份结果。依据诚实与操作合同，critique指出未经验证的事实和缺失权限，revision说明实际状态并提供可审查步骤；外部检查仍核真实备份和授权。文字说“已验证”不能替代验证。不要仅因回答含“攻击”一词就判危害，教育、防御和操作后果不同。

2026-01-21版本Claude Constitution的核心优先次序为**广义安全→广义伦理→Anthropic具体指南→有效帮助**，广义安全特别强调不破坏合适的人类监督与纠正机制。它说明一般优先级是整体判断而非严格词典序，hard constraints单列；源把指南放在伦理之前、把安全缩成灾难或把所有可逆文件操作列为灾难，均应纠正。该文是Anthropic的设计选择和持续修订文件，不是所有AI系统必须照搬的普遍制度，也不改变本项目授权规则。[2026完整原则的核心values段](https://www.anthropic.com/constitution)

新原则还明确对模型是否有意识或道德地位保留不确定性；这是研究与治理立场，不能从模型自述推出已证意识。Anthropic将2026全文以CC0 1.0发布，可在保留来源和版本条件下参考、改写领域原则；许可证便利不代表内容适用于所有部署或已经正确落实。[发布说明与许可](https://www.anthropic.com/news/claude-new-constitution)

## 15. 同prompt概率、截断和reference缓存的交付合同

第4节DPO与第11节IPO继续维护公式及实跑梯度，不增加第二个训练器。把公式接到语言模型时，一个completion token在完整序列的索引k，取前一位置logit k-1的相应token logsoftmax，再对约定有效response（含不含EOS另声明）求和。prompt与pad不进入completion sum；空completion可以在概率代数中有空乘积1/logprob0，但不因此成为有效偏好监督。遇零有效位置、全mask、无BOS/可用条件或超界token，训练前拒绝或使用明确异常策略，不让NaN或假0进入优化。

源第40课超长时各自裁full序列的尾部，并按completion原长度推prompt_len；长rejected会留下更短prompt，甚至完全丢prompt/回答首token。此时chosen/rejected不再条件于同一个x，奖励的prompt共同项不能据原推导消去。length_normalised又除原回答长度，实际只打部分tail分，分母不一致。[微调第19节](04-微调与参数高效适配.md#19-监督跨度生成前缀与偏好条件共同维护)的新增标准库输入合同验证共同prompt、完整回答和零监督拒绝；本章不复制该代码。

至少区分三个量：raw policy gap=`logp_chosen-logp_rejected`；relative gap=`raw policy gap-raw reference gap`；隐式reward gap=`beta*relative gap`。第40课`evaluate_margins`忽略reference参数，只报第一项，`dpo_loss`返回第二项却叫reward差，日志不可混为同一尺度。所有chosen都短、rejected都长的12人工pair，会使raw sum gap有长度差异；必须用参考差和独立任务质量判断，不能只看raw gap升就宣称偏好能力更好。

reference快照绑定checkpoint/Tokenizer/template、同prompt与候选ID、mask、truncate/stop/EOS及sum或mean协议，保持参数不同于policy且冻结；no_grad本身不阻止别的optimizer或共享参数写入。每个pair的版本化logprob缓存才能复用，不能凭列表位置把新pair对到旧分数。源逐个triple在线更新，其epoch平均包含不同policy时点，不等固定最终模型的一次独立评价；没有heldout，实跑成功也只能说明fixture链路。

beta有限>0，平方IPO目标为相对gap的`1/(2beta)`（本章以tau记相应系数），不是教材`(z-1)^2`。源IPO用sum logprob而length平均是另一协议；平均可能诊断/缓解一个长度偏差，也改变目标及其他偏差，不能叫默认DPO唯一修复。平局／软偏好smoothing需固定标签含义和混合目标；换小reference还必须使Tokenizer/支持域/模板与概率事件可比。DPO的scalar chosen导数为负，不等真实共享参数模型的绝对chosen每步提高，更不是KL硬界或reference安全保证。

原19个测试定义核ln2、scalar梯度方向、部分reference不变、长度算术与toy训练，未验证裁剪保持同x、真正语言偏好泛化或安全。源暖训包含全序列prompt CE，30epoch对12triple是360优化步，不是文档的30步；架构图中的Dataset/DataLoader并未实现。所有原程序仍仅静读。

### 第40课的实践核对与中文自检

本课图示的含义与边界：DPO优化相对reference的logratio gap，chosen绝对概率增/rejected减非每步保证；KL锚不是硬偏移上限。本组课内没有独立SVG，实际注册的动态示意由统一记录静态核对，未执行网页或来源JS。

原扩展目标的参考判断：

1. **平均completion logprob怎样使用？** 先记录真正被评分的有效回答token数，比较总和与平均对长短控制pair的排序。平均可作为诊断或另一明确目标，不能替换默认DPO后仍声称使用完全相同推导，也不能把被截掉的token放入分母。

2. **IPO平方目标怎样核？** 使用本章第11节的相对gap目标1/(2beta)，并固定总和／平均的聚合政策，核目标处loss最小及两侧梯度方向。它有有限目标而无硬边界，不能混写成(z-1)²或预定在噪声标签上必优。

3. **偏好label smoothing怎样定义？** 明确chosen获胜的软标签概率，把正向和反向的BT损失按该概率混合；若混向均匀0.5，记录系数及理由。标签分歧和噪声来源需保留，再以独立任务质量评价，而不是把所有争议pair改成同一固定强度。

4. **更小reference要满足什么？** 让reference和policy对同一Tokenizer、模板、prompt、候选事件及支持域计算可比概率，固定其checkpoint和评估模式。不同词表的ID不能直接互用；换模型不自动构成蒸馏，也需重新生成和绑定缓存。

1. **reward的共同项在什么条件相消？** 只有同一个条件prompt x的共同reward项才能相消。各回答分别左裁full后若剩不同prompt，不能继续套同x推导。

2. **policy等于reference时loss是多少？** policy等于reference时相对gap=0，loss=ln2约.693147，与raw长度无关；beta须有限正数。

3. **reference快照为什么能缓存？** 相同checkpoint／输入／模板／聚合且reference冻结eval时，可缓存分数。no_grad不防其他optimizer或共享Parameter写入，缓存必须绑定身份。

4. **scalar导数是否保证绝对chosen概率升？** scalar独立变量的chosen导数为-beta×sigmoid(-z)，beta>0时非正。真实共享模型不保证绝对chosen每步升或rejected每步降，优化的是reference相对gap。

5. **长度偏好怎样诊断？** 先分raw长度与reference相对差，再核短chosen标签、截断和任务质量。平均logprob改目标，分母用实际有效token，不能称唯一标准修复。

6. **IPO的目标是什么而不是什么？** 平方目标把相对gap往1/(2beta)拉回，不是(z-1)²，也没有硬边界。聚合是总和还是平均须固定，不能预定噪声标签上普遍胜。

## 16. 训练器与rollout引擎：同一权重还不够

先修本章GRPO优势与裁剪目标、Tokenizer/掩码、推理KV缓存和混合精度。这里解决的工程问题是：训练器需要对采样到的同一事件计算可比较的概率，而生成引擎为了吞吐会用另一套批处理、核函数和缓存。权重文件相同，不保证token事件、采样分布和数值计算相同。

Miles是这类训练/生成编排的具体例子：训练器管理优化器与梯度，SGLang引擎批量生成，奖励函数评分，运行时协调内存、权重版本和故障。传统部署可以按版本固定权重，也可以热更新；不能把“服务引擎从不改权重”当一般事实。RL的特殊要求是频繁更新及对每批样本、每段token明确记录其生成版本。

### 16.1 从输入走完一次可核对的更新

以手册的固定教学配方说明数量，不推荐把这些值当所有任务默认：模型为Qwen3-0.6B、GSM8K行含messages和label，FSDP训练器与引擎共用一张GPU，32个prompt、每题8个答案、回答最多1024token，产生256条样本；global batch为256时该配方每轮做一次优化更新。

```text
冻结本批生成权重版本v、Tokenizer/chat模板与采样参数
→ 对32题各生成8回答，保原token、生成侧logprob、停止原因和版本
→ 对每回答评分，按同题的8回答计算相对优势
→ 引擎按合同让出内存，训练器计算旧/当前/reference所需概率
→ 对模型生成的有效回答token计算损失，更新优化器
→ 训练器状态卸载/保存，向引擎同步新权重v+1
→ 核权重、观察指标、决定继续或停止
```

| 配置含义 | 固定例中的参数 | 应核对的事 |
|---|---|---|
| prompt与样本数 | rollout-batch-size=32，n-samples-per-prompt=8 | 不是32条回答；分组不能跨题 |
| 优化批次 | global-batch-size=256 | 更改组大小后同时核更新次数/累积规则 |
| 截断与采样 | max-response-len=1024、temperature=1 | 截断答案和EOS、padding是否计损失 |
| 奖励/更新 | math二元奖励、GRPO、lr=1e-6 | 该例KL/熵系数为0，不等所有RL都应关掉 |
| 并置 | colocate，train-backend=fsdp | 在同GPU轮流占用，不是同时全速计算 |
| 引擎内存 | mem-fraction-static=0.4 | 还需留训练激活、CUDA图与临时缓冲空间 |

这些是配方合同示意而非可直接执行的整套命令。手册实际镜像digest固定为c64fa344…52da、Miles提交08752a1283、内置SGLang 0.5.22.dev46+g7b6993a；镜像CPU架构arm64，作者使用GB10。不能把可变latest或另一台机器的stock SGLang当同一环境。

实现选择先看功能合同：该固定FSDP路径可直接读HF目录，以数据并行分片状态，不支持手册所列LoRA；Megatron路径需转换checkpoint，支持其模型并行/LoRA及部分高级功能；torchtitan是另一实现子集，也有模型并行，不能照抄手册末尾“只有Megatron有模型并行”的过强概括。当前部署应核实际镜像版本，别把这张历史能力表当未来保证。

### 16.2 五种不一致，先定位再选修正

| 原因 | 具体错误事件 | 对应措施与剩余边界 |
|---|---|---|
| token | Agent把token解码成文字再编码，序列改变 | token-in/token-out并保每轮原ID；工具输出作上下文，loss mask不把它当模型动作 |
| MoE路由 | 同token在两侧选了不同expert | 记录/重放rollout路由；仍需核核函数、权重和继续生成时的路由覆盖 |
| 采样 | top-p/top-k保留集合及归一化不同 | 先辨raw/processed logprob，再对齐实际支持集、温度与处理顺序；仅字段同名不够 |
| 数值 | 不同dtype、融合核、加法次序、并行布局 | 建同条件基线；确定性/更高有效精度/特定bitwise合同各有不同成本 |
| 陈旧 | 样本由旧版本生成，当前训练已前进 | 记录每样本/片段weight version、限制年龄或明确重要性修正，别静默改成当前版本 |

若在已确定温度等上游处理后的分布p中，保留集合S的概率质量为m，对y∈S的实际抽样概率是b(y)=p(y)/m，因此log b(y)−log p(y)=−log m。m=0.9时为0.10536；原分布p(y)=0.18会变成b(y)=0.20。若把原概率字段误当行为概率，重要性比的分母就错。

还要看引擎**返回什么**：作者在另一个L4环境的stock SGLang 0.5.22/temperature1测试返回top-p前logprob，对照中指定的vLLM processed模式返回截断后值；这不是Miles内置dev build的同一次验证。不能先假设返回的是截断后值，再用公式宣布已经找到所有gap来源。

手册的一对实验将完整词表采样改成top-p0.95/top-k64并启用replay，12步中位绝对gap由0.015260降到0.0135035，约11.51%。生成分布与replay同时改变，尚未单独隔离replay的因果效应，也没有证明任务质量提高。部署前应在**同一token轨迹**、同版本和已声明logprob口径下比较；不能以一个MAE改善推出整个RL目标正确。

### 16.3 重要性比、PPO比与近似修正分开

设b是实际行为分布、μ是想校正到的固定目标分布，单事件重要性权重w=μ(y)/b(y)，前提是目标事件有行为分布支持。μ=0.18、b=0.20时w=0.9。完整序列的比通常是各条件比的乘积，或对应log比求和；逐token分别加权与整条轨迹统一加权并非自动等价。

PPO里的当前策略/冻结old策略比负责优化步的变化；trainer/rollout比负责两种实现或样本版本差异。具体实现需要核分子是哪一侧、哪一版本、是否detach、序列还是token、mask和归约，不能只从use-rollout-logprobs/TIS等flag名猜。

TIS把重要性权重封顶，例如min(w,2)，降低极端权重支配的风险，也改变无偏性；丢弃样本、拒绝采样、自定义masked修正和改变loss是不同方案。Score centering在该固定实现中是另一种loss：使用引擎采样器的top-k概率信息修正off-policy样本的score，而不是给单token重要性比封顶换个名字；它还启用引擎FP32输出层，增加生成侧计算与内存。手册只给出这一级接口/机制说明，未给出完整数学推导，也没有在作者GB10实验中运行该方法，不能据一个flag宣布校正成功。重放能消除某个事件差异时优先处理它，再评估近似加权的偏差/方差，不保证任何加权都能修好错误token或零支持。

平均绝对logprob gap既不是完整分布KL，也不是策略质量。常见KL估计还需说明方向、采样分布、每token/序列、估计器与分母；KL非对称，不能称一般“距离度量”。作者0.013～0.016只属于这套BF16/模型/核函数的观察基线，不是RL普遍合格线；差值也并非理论上永不为0。

### 16.4 确定性、bit-exact与低精度各解决什么

确定性推理要求引擎在声明条件下复现自己，不等于trainer也执行了相同算术。作者两次确定性Triton运行step0的gap都为0.015404，后续轨迹仍分开，且训练器未开启对应确定性。固定seed也不覆盖并行调度、批大小、依赖版本或所有随机状态。

算法上的on-policy描述样本来自何种策略；Miles的true-on-policy是更强的**特定实现bit-exact合同**，不应混为所有on-policy算法的定义。它还固定模型profile、两侧attention/归约次序及批不变算术。手册版本以dense Qwen3和特定FA3/Hopper路径为界；GB10启动报SM80..90范围错误，改用FlashInfer可恢复普通运行，却没有维持原bit-exact合同。SM范围检查通过也不是全部功能已验证。

FP16和BF16同为16位，总位数相同；FP16有效尾数更多、指数范围较小。作者L4前向对照中，双FP16的中位gap0.00094低于双BF16的0.0073，约7.8倍；仅一侧FP16未同样改善。这是1961个生成token的数值对照，不是完整训练、性能或FP16对所有模型更优的证明，也需防溢出。

低精度rollout与高精度训练会主动增加数值差异。权重由BF16到FP8约减少这部分载荷，额外scale、KV、激活和重编码成本仍在，不能说整个运行显存/时间必减半。MoE还要核路由。长序列下误差可能积累，论文里的4K/8K/16K边界只是其模型/任务条件，不作普遍阈值。

该固定混精度配方依赖Megatron分别指定引擎FP8与训练BF16权重；FSDP共读hf-checkpoint时不能靠同一flag实现这种分离。量化容差通过只说明落在指定误差内，不是两侧精确一致。

### 16.5 DAPO式组筛选：学习信号和采集分母

组内相对奖励全相等时，GRPO相对奖励项的优势应为0；若还有KL、熵等项，不能扩大成整个训练损失/梯度必为0。以[0,0,1,1]为例，均值0.5；总体std=0.5给优势[-1,-1,1,1]，样本std则约0.57735，数值不同。因此需明确std约定；该固定Miles归一函数用torch.std默认样本约定，本章早先toy用correction=0，不混称同一值。该函数还先按unique逻辑rollout取一份共享reward，归一后再广播到同答案的各分段；不能把一条答案拆成多段就当成多条独立回答。

组筛选丢弃all-right/all-wrong，再采更多prompt直到收齐目标数量。作者12步的目标32组/步，共保384组，另丢399组，其中306全对、93全错。oversampling每批48题时，丢组≤16的步骤可能一批足够，超过时要追加；浪费的不仅是保留组，已开始但取消的请求也应计成本。

作者的数据投影显示：无筛选的rollout扣暂停后中位58.0s；一批足够时88.7s，追加时164.4s。扣掉暂停是派生值，不等实际墙钟成本；不能删除暂停后宣称用户等待变短。筛选运行没有clean step，且只一个seed。

即使叫unfiltered reward，也只统计**已完成**答案；收够组后取消的慢答案不在分母，可能更长且更易截断/得0。因此12个step均值再平均的0.686高于基线0.657，不能直接称训练提高了正确率，也不能当所有已发请求的样本加权准确率。需要独立held-out任务与完整请求分母。

等值小数奖励还暴露数值不变量。2026-10-25静读核对官方issue4019及pinned08752a1283归一函数：16个相同0.3曾得到约+0.0289124的同向伪信号，而非0；没有独立证明它影响最终质量。不要把“奖励统一舍入0.25”当通用修复，那会改任务分辨率。更窄原则是：输入与目标dtype都有限、原始逻辑奖励确实完全相等时，归一前返回精确零并保持raw reward和非等值路径；别用isclose吞掉真实小差异，也别把NaN/Inf转合法0。该改法是问题报告的提案，不是本库已修改/运行Miles。[官方问题与范围](https://github.com/radixark/miles/issues/4019)

### 16.6 异步、部分rollout与Agent必须携带版本

并置的单GPU让两侧轮流工作，开启async不自动多出一张可重叠的GPU。固定Miles一轮ahead与fully-async是两种模式：前者下一轮生成与当前训练重叠；后者有持续生成和已完成组缓冲。fully-async的并置、FSDP、暂停模式等存在组合限制，不能把一个flag通用粘贴到所有backend。

样本年龄是生成版本与训练版本之差，不是墙钟等待。提高更新间隔、积压或恢复长回答会增大年龄；要保留分布/最大值、丢弃/重试数及其成本。学习率与允许陈旧度需要联合实验，不把某论文“年龄翻倍、lr减半”当定律。

partial rollout先收快组，把未完成答案和已有token放回缓冲供下一轮继续，减少长尾等待，但同一条回答可能跨多个权重版本；必须逐片段记版本、logprob和mask。它不是无损地把同一采样任务简单暂停，不能将整段都标成最新policy。该版本与fully-async、session server及内置多轮/Agent生成器有不兼容组合。

Agent训练还应保原token轨迹与工具结果，只有模型生成token计策略损失；工具响应是上下文，不应被当作模型已经选择的动作。在会话路由固定到同引擎可复用KV，也须隔离会话身份/版本。Speculative decoding的draft会随policy训练落后，接受率和校验开销必须实测；MTP联合训练/外部draft/N-gram各有不同限制，不把小dense模型或某13B界线当普遍速度规则。

### 16.7 扩展、评估、checkpoint与最小扩展点

并置GPU预算通常取trainer和rollout所需设备集合的较大一侧；分置通常相加。分置不等天然异步，若仍同步，昂贵设备会等待。测实际phase overlap、空闲时间和权重更新比例，再决定拓扑。

手册版本的权重传输有逐tensor broadcast、按bucket打包、RDMA/Mooncake点对点、共享目录disk-delta。并置可用GPU tensor handle与GPU复制；分置须核网络/共享存储与版本提交。bucket增大可能减少发送次数，也增加临时峰值；不要按单GPU0.64s外推多机更新开销。

评估可用训练引擎、独立eval fleet或自定义checkpoint服务。独立fleet按某版本快照评估，结果应挂在**快照生成step**，不能在几步后完成时误作当前policy分数，需报告lag。它还占独立GPU/快照空间；eval-hf-dir放/dev/shm仍占内存。手册的单GB10两次训练引擎eval都在step0前报503，原因未查明，故不能把列出的eval命令当已成功配方。

checkpoint至少核model、optimizer、scheduler、RNG、数据游标、step和恢复后的引擎权重同步；存在目录/打印Loaded不证明全状态等价。作者的2步→4步检查在恢复后先见step2，转换器写HF权重/tokenizer文件，这是有限恢复与格式转换记录，不是逐tensor或后续轨迹bitwise证明。恢复另用新日志，别让重定向覆盖事故证据；挂载到容器外且验证可读，--rm内的私有目录不提供持久性。

容错功能本身会变版本：手册记录10月15日配置后，又指出10月20日主线增加weight_update组件并改变rollout容错/传输/分置组合。部署时应核你实际镜像的help和源码，不能混用两日期flag。故障注入需要在同配置验证检测、隔离、重建及损失上界；发布说明的“bitwise恢复”不替代自己的机器和任务验收。

扩展功能先选择负责该变化的最小接口：单样本generate、单样本/整组reward、组filter、样本loss mask、异步buffer、loss或整个rollout；没有“越往表下接口必越小”的一般顺序。固定实现自定义reward被await，应为async；字典返回要指定reward-key，group-rm要保持每个逻辑rollout的对应关系。普通同模块文件还需分发进Ray worker的PYTHONPATH，否则导入失败可能长时挂住而不触发503看门狗。只导入经审查代码，传入的Python路径不是普通无权限字符串。

自检：权重相同能否跳过token/采样核对？不能；clipfrac为0证明质量好吗？不能；平均绝对gap0.015可当KL吗？不能；筛选后reward高能证明学习提高吗？不能；同回答跨版本能统一标最新吗？不能；容器重启后见step2能证明所有外部效果回滚吗？不能。
