## 工程主线

```text
需求
→ 模型选择
→ 模型/权重
→ 基线推理
→ 数据与微调
→ 评测
→ 量化/推理优化
→ 服务化
→ 系统扩展
→ 监控/实验/反馈
```

具体 CUDA/CANN/ROCm 版本、模型名、API 参数和云产品能力变化快，执行前重新核验；主库只保留稳定工程角色与决策原则。

## 从无需部署的小练习开始

建议先掌握 [LLM 基础](../LLM%20基础/README.md) 的数据流、损失和缓存。工程学习可以按任务走，不必按目录顺序立刻做 SFT/RL。

| 阶段 | 章节 | 交付物与自检 |
|---|---|---|
| 建立可比较基线 | 01、02、06 | 一个任务定义、正常/边界样本、期望答案、环境记录 |
| 理解服务与资源 | 03、09、11 | 手算延迟和权重/KV 容量；解释测量口径 |
| 针对失败选择方法 | 04、05、10 | 说明为何需要训练、选哪类数据、怎样防止指标投机 |
| 专项实践 | 07 或 08 | 只选检索或多模态之一，检查样本、标签与评价方式 |

运行练习从已有可用环境中的最小样本开始，先确认正确，再扩大。硬件未确定时不预设模型或开通云服务；可先完成本文的数值计算、数据设计与失败分析。每章附带例子和核对答案，实际模型训练、压测和部署需要另记运行环境与结果。

2026-10-02 修订明确了“文档能力核验”和“本机运行验证”的区别。当前正文的教学场景不是已经完成的模型实验，框架 main/latest 文档也不是安装版本锁定文件。

## 从小模型训练走到可复核交付

不必先租GPU或下载大模型。沿下表运行合成小例，解释输入、目标与输出，再改一个条件观察失败：

| 次序 | 主要入口 | 要能独立核对的结果 |
|---|---|---|
| 编码契约 | [基础02](../LLM%20基础/02-文本-Tokenizer与Embedding.md) | 中文、NUL、emoji往返；普通文本与可信结构ID分开；snapshot与模型ID上界一致 |
| 数据到训练 | [16数据与交付](16-预训练数据与模型交付实践.md)、[基础05](../LLM%20基础/05-预训练-损失与文本生成.md) | 划分、去重、移位/mask与有效token分母；真实全图更新；保存恢复后的下一步一致 |
| 指令与评测 | [04微调](04-微调与参数高效适配.md)、[06评测](06-评测与实验管理.md) | 回答span监督正确；评测集独立；任务分数、生成失败和指标口径可追查 |
| 偏好目标 | [05偏好优化](05-偏好优化与强化学习.md) | 区分标签、old/reference与真正梯度；能比较DPO、KTO、ORPO、SimPO的不同目标 |
| 资源与数值 | [15资源量化](15-训练资源与数值量化实现.md)、[并行训练](../AI%20算法基础/深度学习专题/06-计算性能与并行训练.md) | 静态状态与峰值分开；打包/反量化正确；重计算保持输入及参数梯度、RNG和buffer合同 |
| 推理和架构 | [14推理设计](14-Transformer推理与规模设计.md)、[03服务化](03-推理与服务化.md)、[基础09](../LLM%20基础/09-现代语言模型架构与生成.md) | 缓存/采样/树mask正确；参数和KV预算写全条件；服务协议与模型分布保证分开 |

有限CPU程序是机制验证。真实语料训练、GPU/多卡、服务压测与用户实际学习效果另行记录；合成loss下降或单次输出不能代替这些结果。2026-10-05～06的增量补强沿用原章节和来源，逐项边界见[五站进度](../维护/五站吸收/进度与续接.md)。

## 把一次模型请求接成可检查的小应用

先在[13结构化输出](13-结构化输出与对话状态.md)定义字段、未知状态和失败；需要证据时读[12检索管道](12-文本检索与RAG文档工程.md)，比较独立改写、多查询/拆解、HyDE/Step-back和两阶段重排，再用原文版本及跨度核对每个必需事实。检索向量训练和真实bit packing由[07](07-Embedding与检索模型训练.md)维护，LoRA梯度、合并及NF4/二级常数由[04](04-微调与参数高效适配.md)维护。

应用上线前按[06](06-评测与实验管理.md)保留全部案例、失败、重复协议与评分版本；再按[03](03-推理与服务化.md)区分业务答案缓存、前缀KV和单请求KV，核撤权/版本/TTL失效。[10案例方法论](10-案例方法论.md)接通尝试账本、重试/未知副作用、trace、候选/实验版本和回滚。缓存与压缩要服从任务、证据和权限合同，不能用更高命中率代替正确性。

上述例子可先在CPU合成输入运行，不需要真实模型API。工具执行、上下文总预算、MCP、人工恢复与框架机制进入[Agent学习路线](../Agentic%20Design%20Patterns/README.md#从小闭环开始学习)。先解释并改一个边界，保留实际输出，再决定是否需要SDK/模型/服务实验；2026-10-07新增范围及未完成项见[五站进度](../维护/五站吸收/进度与续接.md)。


页面图像和跨模态资料接[07多向量与MaxSim](07-Embedding与检索模型训练.md#11-页面多向量与maxsim的输入合同)及[12页面/跨模态证据](12-文本检索与RAG文档工程.md)，前端结构由[OCR文档合同](../AI%20算法基础/感知与多模态专题/08-OCR视觉语言与可靠管道.md#10-文档解析先保留结构与出处)维护。先核encoder/preprocess revision、有效向量与实体/出处，再谈压缩、融合或多hop；新source ID不一定提供新事实。回链新增于2026-10-08。

## 把自主研究与长期运行接回实验管理

[06评测](06-评测与实验管理.md)继续维护长任务成功概率、趋势外推的前提和自主研究的证据链。先定义任务、固定评测条件与可核验结果，再让系统生成候选实验；实验脚本能退出、论文能排版和研究结论得到支持是三种不同的结果。重复用于候选选择的集合是验证集，最终测试集须独立保护。

候选算法与脚手架的搜索、反思数据与权重训练回到[09学习](../Agentic%20Design%20Patterns/01-核心章节/09-学习和适应.md)和[17推理](../Agentic%20Design%20Patterns/01-核心章节/17-推理技术.md)；跨重启恢复、预算与安全治理沿[长任务学习路线](../Agentic%20Design%20Patterns/README.md#长任务受控改进与安全证据)进入。先能复查一个失败与一个被拒绝的候选，不把模型自评、政策名称或合成输出当实际研究成果。
