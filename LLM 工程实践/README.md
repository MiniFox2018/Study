## 工程主线

```text
需求
→ 模型选择
→ 模型/权重
→ 基线推理
→ 数据与微调
→ 评测
→ 量化/推理优化
→ 服务化
→ 系统扩展
→ 监控/实验/反馈
```

具体 CUDA/CANN/ROCm 版本、模型名、API 参数和云产品能力变化快，执行前重新核验；主库只保留稳定工程角色与决策原则。

## 从无需部署的小练习开始

建议先掌握 [LLM 基础](../LLM%20基础/README.md) 的数据流、损失和缓存。工程学习可以按任务走，不必按目录顺序立刻做 SFT/RL。

| 阶段 | 章节 | 交付物与自检 |
|---|---|---|
| 建立可比较基线 | 01、02、06 | 一个任务定义、正常/边界样本、期望答案、环境记录 |
| 理解服务与资源 | 03、09、11 | 手算延迟和权重/KV 容量；解释测量口径 |
| 针对失败选择方法 | 04、05、10 | 说明为何需要训练、选哪类数据、怎样防止指标投机 |
| 专项实践 | 07 或 08 | 只选检索或多模态之一，检查样本、标签与评价方式 |

运行练习从已有可用环境中的最小样本开始，先确认正确，再扩大。硬件未确定时不预设模型或开通云服务；可先完成本文的数值计算、数据设计与失败分析。每章附带例子和核对答案，实际模型训练、压测和部署需要另记运行环境与结果。

2026-10-02 修订明确了“文档能力核验”和“本机运行验证”的区别。当前正文的教学场景不是已经完成的模型实验，框架 main/latest 文档也不是安装版本锁定文件。

## 从小模型训练走到可复核交付

不必先租GPU或下载大模型。沿下表运行合成小例，解释输入、目标与输出，再改一个条件观察失败：

| 次序 | 主要入口 | 要能独立核对的结果 |
|---|---|---|
| 编码契约 | [基础02](../LLM%20基础/02-文本-Tokenizer与Embedding.md) | 中文、NUL、emoji往返；普通文本与可信结构ID分开；snapshot与模型ID上界一致 |
| 数据到训练 | [16数据与交付](16-预训练数据与模型交付实践.md)、[基础05](../LLM%20基础/05-预训练-损失与文本生成.md) | 划分、去重、移位/mask与有效token分母；真实全图更新；保存恢复后的下一步一致 |
| 指令与评测 | [04微调](04-微调与参数高效适配.md)、[06评测](06-评测与实验管理.md) | 回答span监督正确；评测集独立；任务分数、生成失败和指标口径可追查 |
| 偏好目标 | [05偏好优化](05-偏好优化与强化学习.md) | 区分标签、old/reference与真正梯度；能比较DPO、KTO、ORPO、SimPO的不同目标 |
| 资源与数值 | [15资源量化](15-训练资源与数值量化实现.md)、[并行训练](../AI%20算法基础/深度学习专题/06-计算性能与并行训练.md) | 静态状态与峰值分开；打包/反量化正确；重计算保持输入及参数梯度、RNG和buffer合同 |
| 推理和架构 | [14推理设计](14-Transformer推理与规模设计.md)、[03服务化](03-推理与服务化.md)、[基础09](../LLM%20基础/09-现代语言模型架构与生成.md) | 缓存/采样/树mask正确；参数和KV预算写全条件；服务协议与模型分布保证分开 |

有限CPU程序是机制验证。真实语料训练、GPU/多卡、服务压测与用户实际学习效果另行记录；合成loss下降或单次输出不能代替这些结果。2026-10-05～06的增量补强沿用原章节和来源，逐项边界见[五站进度](../维护/五站吸收/进度与续接.md)。

## 把一次模型请求接成可检查的小应用

先在[13结构化输出](13-结构化输出与对话状态.md)定义字段、未知状态和失败；需要证据时读[12检索管道](12-文本检索与RAG文档工程.md)，比较独立改写、多查询/拆解、HyDE/Step-back和两阶段重排，再用原文版本及跨度核对每个必需事实。检索向量训练和真实bit packing由[07](07-Embedding与检索模型训练.md)维护，LoRA梯度、合并及NF4/二级常数由[04](04-微调与参数高效适配.md)维护。

应用上线前按[06](06-评测与实验管理.md)保留全部案例、失败、重复协议与评分版本；再按[03](03-推理与服务化.md)区分业务答案缓存、前缀KV和单请求KV，核撤权/版本/TTL失效。[10案例方法论](10-案例方法论.md)接通尝试账本、重试/未知副作用、trace、候选/实验版本和回滚。缓存与压缩要服从任务、证据和权限合同，不能用更高命中率代替正确性。

上述例子可先在CPU合成输入运行，不需要真实模型API。工具执行、上下文总预算、MCP、人工恢复与框架机制进入[Agent学习路线](../Agentic%20Design%20Patterns/README.md#从小闭环开始学习)。先解释并改一个边界，保留实际输出，再决定是否需要SDK/模型/服务实验；2026-10-07新增范围及未完成项见[五站进度](../维护/五站吸收/进度与续接.md)。


页面图像和跨模态资料接[07多向量与MaxSim](07-Embedding与检索模型训练.md#11-页面多向量与maxsim的输入合同)及[12页面/跨模态证据](12-文本检索与RAG文档工程.md)，前端结构由[OCR文档合同](../AI%20算法基础/感知与多模态专题/08-OCR视觉语言与可靠管道.md#10-文档解析先保留结构与出处)维护。先核encoder/preprocess revision、有效向量与实体/出处，再谈压缩、融合或多hop；新source ID不一定提供新事实。回链新增于2026-10-08。

## 把自主研究与长期运行接回实验管理

[06评测](06-评测与实验管理.md)继续维护长任务成功概率、趋势外推的前提和自主研究的证据链。先定义任务、固定评测条件与可核验结果，再让系统生成候选实验；实验脚本能退出、论文能排版和研究结论得到支持是三种不同的结果。重复用于候选选择的集合是验证集，最终测试集须独立保护。

候选算法与脚手架的搜索、反思数据与权重训练回到[09学习](../Agentic%20Design%20Patterns/01-核心章节/09-学习和适应.md)和[17推理](../Agentic%20Design%20Patterns/01-核心章节/17-推理技术.md)；跨重启恢复、预算与安全治理沿[长任务学习路线](../Agentic%20Design%20Patterns/README.md#长任务受控改进与安全证据)进入。先能复查一个失败与一个被拒绝的候选，不把模型自评、政策名称或合成输出当实际研究成果。


协调评测沿[06](06-评测与实验管理.md)区分唯一成果、每人贡献、完成率与每里程碑成本；预算和失败费用使用同一任务口径。框架/供应商案例用来提出候选架构，不能把历史数字变成当前模型保证。具体分工、消息、共享黑板、共识和市场机制沿[Agent协调路线](../Agentic%20Design%20Patterns/README.md#从分工走到协调共识与激励)进入；真实MARL训练回到[RL15](../AI%20算法基础/深度学习专题/15-强化学习进阶与世界模型.md)。


## 生产推理与运营的学习顺序

先用[14推理设计](14-Transformer推理与规模设计.md)理解token预算、KV页、投机验证和TTFT/ITL/合格吞吐，再用[15数值量化](15-训练资源与数值量化实现.md)核格式、真实架构载荷和质量。模型能载入后，沿[11系统设计](11-AI推理与ML系统设计.md)建立容量/排队/扩缩容与完整费用预算；[09跨硬件](09-跨硬件部署.md)比较引擎、精度、硬件配置与冷启动关键路径。

[03服务化](03-推理与服务化.md)统一多副本、地域/KV合同、两层缓存、PD、卸载与网关失败预算；离线请求沿[02-1 API](02-1-API调用密钥与失败处理.md)逐item对账，模型准入与级联成本沿[路由02](../Agentic%20Design%20Patterns/01-核心章节/02-路由.md)。最后用[06评测](06-评测与实验管理.md)区分影子、金丝雀、随机实验与负载测量，用[19观测](../Agentic%20Design%20Patterns/01-核心章节/19-评估和监控.md)解释缺失数据/费用分母，并按[生产工程](../计算机科学基础/05-生产级软件工程.md)、[18安全](../Agentic%20Design%20Patterns/01-核心章节/18-安全模式.md)和[16资源](../Agentic%20Design%20Patterns/01-核心章节/16-资源感知优化.md)处理值班、停止条件、审计职责与共享费用。

学习检查：能手算一个容量/KV例子，解释一个缓存miss，核对一份乱序Batch结果，区分一次部署回退与实验结论，并把失败调用费用计入业务任务总账。仓库CPU例子验证机制，真实GPU、云、供应商账单与生产效果仍需另做相应实验。


## 对齐、执行安全与治理的学习顺序

先在[05偏好优化](05-偏好优化与强化学习.md)核奖励代理、KL、DPO/IPO/BPO、迎合与原则反馈；然后进入[17对齐失效与安全论证](17-对齐失效与安全论证.md)，区分人工后门、环境诱发策略、训练相关伪装、弱到强监督及整个控制协议的证据与分母。前沿政策、模型福利和双重用途放在论证范围内解释，机构图不代替独立验证。

[安全18](../Agentic%20Design%20Patterns/01-核心章节/18-安全模式.md)维护自适应红队、IFC、漏洞入口/权限/渲染、内容审核与跨地区规则；[评测06](06-评测与实验管理.md)区分危险知识、拒绝、覆盖与现实帮助。[负责任AI13](../AI%20算法基础/深度学习专题/13-负责任AI.md)进一步学习社会伤害、公平比例、反事实、DP后处理与会计边界、水印及签名溯源，[数据伦理01](../数据科学基础/01-数据科学问题框架与伦理.md)维护数据/模型/系统卡和数据来源/后续权利；稀疏激活解释接[AE20](../AI%20算法基础/深度学习专题/20-自编码器与对抗生成实践.md)。

学习检查：能解释一次奖励升分但真实效果下降，核对一张分组混淆矩阵，区分DP证明与隐私攻击审计、缓存/签名与真实性，并用主张、假设、证据和反例写一个限定范围的安全论证。真实模型、攻击、防护和法律认证有各自验证条件，本库合成CPU例不能替代。


## 综合项目：从算法示例接到可复验交付

编码、迁移与后台Issue→PR沿[10案例方法论](10-案例方法论.md)核最终HEAD、环境、验证计划和费用；团队集成沿[协作07](../Agentic%20Design%20Patterns/01-核心章节/07-多智能体协作.md)，运维提案沿[生产工程](../计算机科学基础/05-生产级软件工程.md)。工作树、真实执行隔离、审批与平台限制分别判断，模拟done/green不当交付。

[12RAG](12-文本检索与RAG文档工程.md)接通索引代际、授权语料、引用与流式会话，[OCR管道](../AI%20算法基础/感知与多模态专题/08-OCR视觉语言与可靠管道.md)把页身份、几何与真实显示分开。[08多模态](08-多模态模型工程.md)补语音轮次/实际已听和视频原时间，[04微调](04-微调与参数高效适配.md)补报告/数据/产物DAG，[14推理](14-Transformer推理与规模设计.md)按同target/流量核采样和收益。观测、安全、MCP、研究预算和学习记录沿各现有主题交叉进入，不新建一套按来源编号的项目目录。

先解释一条从输入到真实终态的完整链，给版本与回执及失败/未知状态，再扩大案例。源码tests只检查其覆盖范围；标准库合同算例不等已部署项目、真实模型成绩或人类学习效果。


综合项目的学习顺序继续沿统一主题：[Tokenizer与窗口](../LLM%20基础/02-文本-Tokenizer与Embedding.md)→[Transformer构件与加载](../AI%20算法基础/深度学习专题/19-Transformer实现与训练实践.md)→[分类与SFT](04-微调与参数高效适配.md)／[同条件偏好](05-偏好优化与强化学习.md)→[独立评测与自建harness](06-评测与实验管理.md)。[数据与恢复](16-预训练数据与模型交付实践.md)、[学习率时钟](../AI%20算法基础/深度学习专题/17-初始化优化器与学习率实践.md)、[AMP与稳定范数](15-训练资源与数值量化实现.md)、[累积及DDP/FSDP](../AI%20算法基础/深度学习专题/06-计算性能与并行训练.md)接真实更新合同。已有代码、正文与新合同反例合用，不将教学stub、上游输出或形式通过当模型效果。


## 联合重排与多模态评价的学习顺序

先在[07第13节](07-Embedding与检索模型训练.md#13-联合编码重排的学习计算与训练目标)核对query与doc共享attention、有效mask、训练/留出分组和损失，再到[12第15节](12-文本检索与RAG文档工程.md#15-分块融合重排与评价的练习和测验)用原文span、候选身份和多facet真值解释端到端成败。重排不能补未召回证据，N=K仍能改变名次。图文任务转到[08第7节](08-多模态模型工程.md#7-评测)，先确认独立数据和单/多正分母，再算VQA与BLEU；不要把训练loss或预设动画当真实成绩。


评测进一步进入[06第27节](06-评测与实验管理.md#27-自建评测harness任务adapter指标与结果身份)：先冻结实际case、模板和指标协议，再核完整计划、所有失败/缺失及配对身份，最后解释NLL、校准和排名区间。CPU账本例展示共同已评分子集改善而全计划政策差为0，能用它检查分母；候选代码的真实隔离、模型概率与provider性能仍需独立实证。
