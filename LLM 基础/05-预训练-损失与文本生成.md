# 05｜预训练、损失与文本生成

## 1. 预训练目标

自回归 LLM 通过 next-token prediction 学习：

```text
输入上下文 → 下一个 Token
```

模型不是直接学习“答案”，而是在大量文本中不断学习条件概率分布。

## 2. Logits 与概率

模型最后输出 logits。

对 logits 使用 softmax：

```text
logits → probability distribution
```

训练时关心目标 Token 的概率是否足够高。

## 3. Cross-Entropy Loss

交叉熵用于衡量预测分布与真实 Token 之间的差异。

直观上：

- 正确 Token 概率越高 → loss 越低；
- 正确 Token 概率越低 → loss 越高。

训练目标就是最小化平均 loss。

## 4. Perplexity

Perplexity 常由平均交叉熵指数化得到：

```text
PPL = exp(按有效目标 Token 平均的负对数似然)  # 使用自然对数时
```

它可理解为模型在每一步面对的“有效不确定候选数”。

在相同测试文本、Tokenizer、预处理、上下文和计分方式下，越低通常表示预测更好。不同 Tokenizer 下的每 Token PPL 不能直接横比；PPL 也不能代表所有下游能力。

## 5. Train / Validation

训练集 loss 下降并不等于模型真的泛化。

必须同时看 validation loss。

典型过拟合现象：

```text
train loss ↓
val loss ↑
```

小数据教学实验尤其容易出现记忆训练文本。

## 6. 训练循环

基础训练循环包括：

1. 前向传播；
2. 计算 loss；
3. 清空梯度；
4. 反向传播；
5. 参数更新；
6. 定期在验证集评估；
7. 保存模型状态。

## 7. 解码不是训练

训练完成后，生成阶段需要从概率分布里选 Token。

这属于 decoding，而不是重新训练模型。

## 8. Greedy Decoding

每次选择概率最大的 Token。

优点：

- 在 logits 相同、并列值处理一致时确定；
- 简单。

缺点：

- 容易重复；
- 多样性低；
- 局部最优不一定带来整体最好序列。

## 9. Temperature

Temperature 对 logits 进行缩放。

直观规律：

- 较低温度 → 分布更尖锐、更确定；
- 较高温度 → 分布更平、更随机。

Temperature 控制的是采样随机性，不是模型知识量。

## 10. Top-k

Top-k 只在概率最高的 k 个 Token 中采样。

作用：

- 剔除低概率长尾 Token；
- 可能减少低概率输出，但不保证事实正确；
- 同时保留一定多样性。

## 11. 模型权重

训练后要保存：

- 模型参数；
- 必要时保存优化器状态；
- 配置与 Tokenizer 信息。

只保存一个权重文件而缺少配置，往往无法可靠复现模型。

## 12. 长期结论

评估一个预训练模型时，应分开看：

- 训练是否稳定；
- 验证 loss；
- 生成行为；
- 下游任务表现；
- 推理成本。

不能用一段“看起来很顺”的生成文本代替系统评估。

来源：<https://github.com/rasbt/LLMs-from-scratch/tree/main/ch05>

## 13. 算得出的损失与采样

两个目标 Token 获得概率 `0.5` 和 `0.25`，平均负对数似然为 `−(ln 0.5 + ln 0.25)/2 ≈ 1.0397`，困惑度为 `exp(1.0397) ≈ 2.828`。Padding 不应进入分母；若框架接收 logits，通常使用数值稳定的 log-softmax/交叉熵实现，避免先 softmax 再取对数造成下溢。

温度采样为 `p_i = softmax(z_i/T)`，其中 `T>0`；`T=0` 通常是接口约定的贪心模式，不应真的除以零。给分布 `[0.6, 0.3, 0.1]`，top-k=2 会去掉最后一项，并重新归一化为 `[2/3, 1/3]`。采样参数改变选择规则，不会验证事实。

**自检**：把所有 logits 加 100，softmax 是否改变？生成时温度为 0，是否保证整个部署重复运行完全一致？

**核对**：加同一常数不改变分布；但后端非确定性、浮点误差和版本变化仍可能改变 logits，因此“贪心”不等于跨环境可复现。

## 14. 温度、预训练与能力的区别

温度改变给定logits的选择分布，不增加权重知识；下一token训练也不等于网页逐句读取或全部事实验证。可核对例子与证据边界见[常见误解](../AI%20算法基础/19-AI常见误解与证据边界.md)。

## 15. 正确的损失、梯度与验证分母

一个因果LM把整段token作输入，在位置t输出对下一token的分布。训练需要同时正确设置**因果注意力、右移目标、有效目标mask**：它们分别限制可见信息、确定预测对象、确定哪些预测计分。把labels复制为当前input而不移位，会让模型直接看见答案；只删PAD loss也不等屏蔽PAD作为注意力key。不同模型封装可能内部移位，不能预处理移一次、模型再移一次。

设有效标志$m_{bt}$，目标$y_{bt}$，logits为$z_{btv}$：

$$L=\frac{\sum_{bt}m_{bt}[-z_{bt,y}+\log\sum_v e^{z_{btv}}]}{N},\quad N=\sum_{bt}m_{bt}.$$

稳定实现先减同位置最大logit，或直接用框架cross-entropy。梯度为$\partial L/\partial z_{btv}=m_{bt}(p_{btv}-1[v=y_{bt}])/N$。N=0是无有效监督，需报无效/跳过且计数，不能loss0又继续更新。一次batch内多条回答长度不等时，全token平均和每样本先平均再等权平均是不同目标；记录选择，不能只叫“平均loss”。梯度累积也按总有效token归约，不能对有效数差异很大的micro-batch简单各除累积次数。

例如两个batch各有1/9个有效token，平均NLL分别2/1；整体NLL是$(1×2+9×1)/10=1.1$，不是$(2+1)/2=1.5$；对应PPL约3.004而非4.482。每token PPL依Tokenizer；可辅以同一规范化测试文本的NLL/UTF-8字节换算bits-per-byte（除ln2），仍要声明EOS、初始上下文和覆盖token。PPL不是事实正确性/指令遵循分数，随机**均匀预测**的PPL才精确等于V，任意随机初始化logits不保证每次都均匀。

固定窗口和滑动窗口计分还有差异：独立截块会让每块开始处丢失前文；滑动重叠应让context-only前缀不重复计loss，只计新目标，确保每个指定测试target恰计一次。更长context有时给模型更多信息，但未保证任何模型/任务PPL都严格下降。记录测试完整文档、窗口/stride、BOS/EOS与计分mask，不能只用随机几个验证batch冒称全验证集。

完整数据/训练/恢复/验证代码接[预训练数据与模型交付实践](../LLM%20工程实践/16-预训练数据与模型交付实践.md)，训练基础的反向和梯度检查接[前向反向与损失实现](../AI%20算法基础/深度学习专题/16-前向反向与损失实现.md)。

## 16. 核对是否真的训练了整个模型

“loss下降”只说明某次被测目标数值变化，不说明所有预期参数都得到正确梯度。冻结权重时，模块仍可能需要把对输入的梯度传回更早的可学模块；冻结参数和断开输入Jacobian不是同一操作。Tied Embedding同时用于输入查表和输出投影，梯度要累加两条路径，详见[完整Transformer与共享权重](../AI%20算法基础/深度学习专题/19-Transformer实现与训练实践.md)。

源第04课docs的训练片段只有forward/loss没有update；实际Python主程序虽更新部分FFN、ln2、最终LN与Embedding输出路径，却跳过attention与ln1反向、position更新及Embedding输入路径。这样还会改变更早FFN的梯度，不只是“少训几个参数”。Rust版本明确只有前向和随机生成；其随机数右移33位只得到31bit，却按32bit上界归一，导致uniform范围约[0,.5]，不能拿它的采样当正规随机分布。这些源码可帮助读前向结构，不能当完整GPT预训练/语言能力证据。

2026-10-06另用D8、两层、固定`abcde`的一步源实现探针核对：首层FFN某权重的完整forward有限差分约.077521，实际应用梯度约.080789；输入字节97的一项tied Embedding完整梯度约−.304745，源仅输出路径应用约.002345。这个可重复反例说明漏输入Jacobian会影响实际梯度，不只影响参数更新清单；不将探针当原124M训练。

训练前检查参数清单、grad是否存在且有限、共享对象是否唯一登记；再对少数权重用有限差分核对完整forward目标，见数学梯度专题。grad数值可能恰为0，所以“所有grad都非零”也不是通用正确性要求。正式程序应有全图backward/optimizer.step、可解释数据划分与验证，源码200步的演示输出不能包装成124M模型在真实语料上的成绩。

### 16.1 参数量：先写清bias、FFN与共享头

GPT-2式D宽、FFN宽4D、两次带scale/bias的LayerNorm、QKV/输出Linear均带bias时，每block参数为$12D^2+13D$；最终LN为2D。V词表、L层、可学位置长度T、tied输出且无输出bias时，总参数为$VD+TD+L(12D^2+13D)+2D$。改变heads而保持D不变不会自动增加这组投影参数，仍需D整除heads；固定每头维度再增加heads会改变D，属于另一个实验。

```python
def count_gpt(V,D,L,T,attention_bias=True):
    if any(type(x) is not int or x<=0 for x in [V,D,L,T]):raise ValueError('正整数配置')
    per_block=12*D*D+9*D+(4*D if attention_bias else 0)
    return V*D+T*D+L*per_block+2*D
full=count_gpt(50257,768,12,1024)
simplified=count_gpt(50257,768,12,1024,attention_bias=False)
assert full==124439808 and full-simplified==12*4*768
print('含完整bias+tied GPT-2式参数',full,'源无attention bias变体',simplified)
print('同D增层/同层倍D',count_gpt(50257,768,24,1024),count_gpt(50257,1536,12,1024))
```

这些是配置公式，不分配124M权重。源表格把per-block省bias的算式与含bias的总数混用，并遗漏最终LN；应按实际对象重算。原始GPT-2结构包含QKV/输出bias、tanh近似GELU及tied头。[原始模型代码](https://github.com/openai/gpt-2/blob/master/src/model.py) ReLU、精确erf-GELU和GPT-2近似GELU是不同函数，能作实验但不能把替换版叫逐项复现。Residual提供$I+J_F$路径，不保证所有深度都永不梯度消失/爆炸；解释与条件见注意力主章。

KV-cache/Prefill/Decode、GQA缓存参数与位置偏移由[Transformer推理与规模设计](../LLM%20工程实践/14-Transformer推理与规模设计.md)统一维护：KV heads不能拿Q heads替代，内存公式还要batch、上下文与dtype。读/写缓存的等价性和真实性能分别检验，不保固定GPU毫秒数、decode永远纯内存瓶颈或加cache必快某个倍率。

## 17. 温度、top-k与top-p的正确操作次序

先确定允许的token集合，再做温度缩放；top-k保分数最高的k项；若随后做top-p，应对**top-k后剩余项重新归一化**再累计。不同实现若在原分布上同时取两个约束，会得到不同结果，须明确协议。例原概率[.6,.2,.1,.1]，k=2后为[.75,.25]，p=.7应只保第一项；若仍累计原概率，.6未达.7，会多留第二项。源互动图使用后一种累计却写成前一种流水线，正文按明确顺序纠正。

```python
import numpy as np

def sampling_distribution(logits,temperature=1.,top_k=0,top_p=1.):
    z=np.asarray(logits,dtype=float)
    if z.ndim!=1 or not len(z) or np.isnan(z).any() or np.isposinf(z).any() or not np.isfinite(z).any():raise ValueError('需有合法有限候选logit')
    if type(temperature) is bool or not np.isfinite(temperature) or temperature<0:raise ValueError('温度须非负有限数')
    if type(top_k) is not int or not 0<=top_k<=len(z):raise ValueError('top-k整数，0代表关闭')
    if type(top_p) is bool or not np.isfinite(top_p) or not 0<top_p<=1:raise ValueError('本契约top-p在(0,1]')
    order=np.argsort(-z,kind='stable')  # 并列按原ID顺序。
    if temperature==0:
        result=np.zeros(len(z));result[order[0]]=1.;return result
    finite=order[np.isfinite(z[order])]
    if top_k:finite=finite[:top_k]
    scaled=(z[finite]-z[finite].max())/temperature
    p=np.exp(scaled);p/=p.sum()
    keep=min(len(p),int(np.searchsorted(np.cumsum(p),top_p,side='left'))+1)
    out=np.zeros(len(z));out[finite[:keep]]=p[:keep]/p[:keep].sum()
    return out

z=np.log([.6,.2,.1,.1])
assert np.array_equal(sampling_distribution(z,top_k=2,top_p=.7),[1.,0.,0.,0.])
assert np.allclose(sampling_distribution(z,top_k=2),[.75,.25,0,0])
assert np.array_equal(sampling_distribution([1.,1.,0.],temperature=0),[1.,0.,0.])
assert sampling_distribution([-np.inf,2.,0.],top_p=.9)[0]==0
for temperature in [.5,1.,2.]:print('temperature',temperature,sampling_distribution(z,temperature))
try:sampling_distribution([-np.inf,-np.inf])
except ValueError:pass
else:raise AssertionError('无有效候选须失败')
print('重新归一化、并列greedy、非法候选与边界通过')
```

这是可控分布变换，没有训练语言模型或验证事实。真实生成还需维护prefix、EOS、最大新token数与上下文；一条batch序列EOS后不能继续把它的PAD算新内容。`T=0`是接口约定的greedy分支，不能直接除0或用极小正数声称完全等价。生成非法UTF-8字节时应记录解码失败或明确展示替换字符，不能像源SFT示例只保ASCII后再评语言质量。[官方TopP/TopK实现](https://github.com/huggingface/transformers/blob/main/src/transformers/generation/logits_process.py)

## 18. Beam search：累计概率、EOS与贪心的局限

对前缀$s$，生成下一token概率$p(v|s)$，序列分数为$\sum_t\log p(v_t|v_{<t})$。Greedy只选当前最大概率，未保证整个序列概率最大；beam每轮展开候选并保留B条高分路径，B=1按规定并列/EOS规则退化greedy。Beam宽度、按长度归一/惩罚和终止策略都可能改变结果，不保更宽更正确、事实更可靠或总算力严格只按B线性变化。

下面是**归一概率的有限状态toy**，用于理解搜索。起点A=.6、B=.4；A之后EOS/x各.5，B之后EOS=.99/y=.01。Greedy走A→EOS的概率.3，beam2可找到B→EOS的.396。已完成EOS路径保存且不再展开；预算未结束路径不会冒称完成。

```python
import math

def next_probs(prefix):
    if not prefix:return {'A':.6,'B':.4}
    if prefix==('A',):return {'<EOS>':.5,'x':.5}
    if prefix==('B',):return {'<EOS>':.99,'y':.01}
    return {'<EOS>':1.}

def beam_search(width,max_steps):
    if type(width) is not int or width<1 or type(max_steps) is not int or max_steps<1:raise ValueError('正整数预算')
    beams=[((),0.,False)]
    for _ in range(max_steps):
        candidates=[]
        for seq,score,done in beams:
            if done:candidates.append((seq,score,True));continue
            probs=next_probs(seq)
            if not probs or any(not math.isfinite(p) or p<0 for p in probs.values()) or not math.isclose(sum(probs.values()),1):raise ValueError('概率合同')
            for token,p in probs.items():
                if p>0:candidates.append((seq+(token,),score+math.log(p),token=='<EOS>'))
        candidates.sort(key=lambda x:(-x[1],x[0]))
        beams=candidates[:width]
        if all(done for _,_,done in beams):break
    return [{'tokens':s,'logprob':lp,'probability':math.exp(lp),'completed':d} for s,lp,d in beams]

greedy=beam_search(1,3)[0];beam=beam_search(2,3)[0]
assert greedy['tokens']==('A','<EOS>') and math.isclose(greedy['probability'],.3)
assert beam['tokens']==('B','<EOS>') and math.isclose(beam['probability'],.396)
assert not beam_search(1,1)[0]['completed']
print('greedy',greedy,'beam2',beam)
```

源beam图在每节点重复一组未归一固定“log-probs”，其最佳序列随步数固定、不体现真实条件模型或质量提升。本toy把概率/条件/EOS写全；一般beam仍可能剪掉最终最优前缀，长度偏好也需按任务处理。面向代码、JSON等还可能叠加语法约束，见[约束解码](../LLM%20工程实践/13-结构化输出与对话状态.md)。

## 19. 练习与中文维护提示

1. 同宽增加layers与增加heads：前者增block参数；后者在D固定且整除时只改变分头方式。倍宽的D²项约四倍，Embedding项约两倍，要重新计算。
2. GELU/ReLU替换的比较必须真正反向更新相应模型，固定数据/初始化/预算并评验证；源docs未update、Python局部梯度不能给“500步某激活必优”答案。
3. Cache测试先同位置/前缀/精度核对logits，再预热和测时；滑动裁旧上下文与learned position重置是不同协议。本章未跑200token硬件缓存基准。
4. top-k=50/top-p=.95是采样选项，不是质量阈值；上面的分布反例核对组合次序，生成事实另验。
5. 1,000步训练曲线不必三阶段、plateau不等证明过拟合。过拟合要独立验证变差等证据，不能说mini model和GPT-4曲线永远同形。
6. PPL的分母、窗口与Tokenizer冻结；平均batch均值、PAD/EOS计分或重复重叠目标会改变答案。完整micro训练/恢复只按[工程16](../LLM%20工程实践/16-预训练数据与模型交付实践.md)的合成协议报告。
