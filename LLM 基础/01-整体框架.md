# 01｜整体框架

## 1. LLM 的基本任务

自回归大语言模型的核心训练目标很简单：

> 给定前面的 Token，预测下一个 Token。

训练时，输入序列与目标序列通常只错开一个位置。例如：

```text
输入：  t1  t2  t3  t4
目标：  t2  t3  t4  t5
```

模型不断学习条件概率：

```text
P(t_next | t_1, t_2, ..., t_current)
```

复杂的语言能力、知识表达和生成行为，建立在这个基本目标之上。

## 2. 从文本到输出的完整数据流

一个 GPT 类模型可以理解为以下流水线：

1. 原始文本被 Tokenizer 切分为 Token；
2. Token 映射为整数 ID；
3. Token ID 映射为连续向量；
4. 加入位置信息；
5. 经过多层 Transformer Block；
6. 每一层进行注意力和前馈变换；
7. 最终输出每个词表位置的 logits；
8. 将 logits 转为下一个 Token 的概率分布；
9. 根据解码策略选出下一个 Token；
10. 将新 Token 加回上下文，重复生成。

## 3. 训练生命周期

下面是常见训练阶段，不是每个模型都必须依次执行的固定流水线：

### 3.1 预训练

目标：让模型学习语言结构、模式与一般知识。

对本章讨论的自回归文本模型，目标标签由文本右移自动产生，因此更准确地叫“自监督训练”。其他模型也可能采用掩码预测或多模态目标。

### 3.2 监督微调

目标：把通用模型调整到具体任务或行为。

例如：

- 分类；
- 指令跟随；
- 特定领域表达；
- 特定输出格式。

### 3.3 对齐与偏好优化

目标：使输出更符合人类偏好、规范和任务要求。

可使用偏好数据和 DPO 等方法进一步优化。

## 4. 参数与上下文是两类不同能力来源

需要区分：

- **参数中的知识**：训练后固化在模型权重中；
- **上下文中的信息**：推理时临时提供给模型。

很多工程问题不需要重新训练模型，通过 Prompt、RAG、工具或 Agent 就能解决。

当有足够可靠数据、固定评测集，且上下文或工具方案仍不能达到目标时，再评估训练的收益；需要稳定行为并不自动意味着必须训练。

## 5. 从“从零实现”能学到什么

从零实现小型 GPT 的价值不在于训练出一个生产级模型，而在于理解：

- Tokenizer 为什么影响上下文和成本；
- Attention 为什么能利用上下文；
- 为什么要做 causal mask；
- 为什么 Transformer 要有残差、归一化与 FFN；
- cross-entropy 在训练什么；
- 生成时 temperature、top-k 在改变什么；
- 微调为什么可以只更新部分参数；
- KV cache 为什么能加速生成。

这些概念对理解更大的现代模型仍然成立。

## 6. 不应误解的地方

- 小模型的教学代码不代表生产级训练系统；
- “从零实现”强调可理解性，不代表最佳性能实现；
- 当前主流模型会使用更复杂的注意力、归一化、激活函数、MoE、长上下文等结构；
- 但基础的数据流和训练目标仍然具有长期解释价值。

## 7. 把一轮生成走通

用教学词表 `{我:0, 爱:1, 学习:2, EOS:3}`，输入“我 爱”，对应 ID 为 `[0, 1]`。模型最后一个位置输出下一词分布 `[0.05, 0.05, 0.8, 0.1]`。贪心解码选择“学习”，新输入逻辑上变成 `[0, 1, 2]`；下一轮再决定继续还是输出 EOS。这个例子不代表任何真实模型的词表。

训练时则用已知文本 `[我, 爱, 学习, EOS]`：输入前三项，目标为后三项。三个位置的损失可以一次前向并行计算，但因果掩码使每个位置只能利用此前信息。推理时后面的词还未知，因此通常逐步产生。

**自检**：给模型提示“今天项目版本是 v2”，会永久改写权重吗？为什么训练可以同时计算三个位置，而生成不能提前读到第三个答案？

**核对**：普通推理只改变当前上下文；除非显式训练，否则不更新权重。训练已知完整样本，靠掩码防泄漏；生成的后续输入依赖前面的输出。
