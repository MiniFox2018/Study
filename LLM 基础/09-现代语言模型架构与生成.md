# 09｜现代语言模型架构与高级生成

## 1. Transformer 之后仍在优化什么

核心问题始终是：

- 表达能力；
- 长上下文成本；
- KV cache；
- 训练/推理吞吐；
- 参数利用率；
- 生成质量与可控性。

## 2. Encoder / Decoder / Encoder-Decoder

三种经典结构：

- encoder-only：双向表征，适合理解；
- decoder-only：因果生成，现代通用 LLM 常用；
- encoder-decoder：输入输出分离，适合条件生成。

BERT、GPT、T5 是理解三种范式的代表。

## 3. Position

没有位置特征或位置相关mask的self-attention对输入排列等变。位置向量、相对偏置、RoPE或结构性mask可以加入顺序信息；causal mask本身已有前后约束，不能与完全无顺序结构的系统混为一谈。

可分为：

- absolute positional embedding；
- relative position bias；
- rotary position representation。

关键不是记某个公式，而是理解“顺序信息如何进入 attention”。

## 4. MHA、MQA、GQA

标准 Multi-Head Attention 为每个 head 使用各自的 Q/K/V 投影。自回归推理通常缓存历史 K/V，而不是历史 Q。

推理优化常减少 K/V head：

- MQA：多个 query head 共享一组 K/V；
- GQA：多个 query head 分组共享 K/V。

目标是减少 KV cache 和内存带宽。

## 5. MLA 等低秩 KV 思路

另一类方法通过低维潜表示压缩 key/value 状态，再在需要时映射到 attention 空间。

长期抽象：

> 推理瓶颈不只在 FLOPs，KV state 的存储和搬运同样关键。

## 6. MoE

Mixture of Experts 使用 router 为每个 token 选择少量 expert。

特点：

- 参数总量可以很大；
- 每 token 激活参数较少；
- 训练/部署增加路由、负载均衡和通信复杂度。

## 7. State Space Models

在状态维度等条件固定时，SSM 通过状态递推可实现随序列长度线性增长的计算，并以压缩状态保留历史信息；这不等于能无损保留任意长文本的全部细节。

Mamba 等模型的长期意义是：

> Transformer 不是唯一能高效建模长序列的架构。

重点理解 recurrence、state compression 与 parallel scan，而不是追逐型号。

## 8. Decoding

从 logits 到文本还需要解码策略：

- greedy；
- beam search；
- temperature；
- top-k；
- top-p；
- repetition control。

生成质量是“模型分布 + 解码策略”的共同结果。

## 9. Sampling 的概率本质

Autoregressive generation：

```text
p(x_1, ..., x_T)
= ∏ p(x_t | x_<t)
```

逐 token 采样本质是 ancestral sampling。

## 10. 高级生成

除了自回归，还有：

- iterative refinement；
- non-autoregressive generation；
- text diffusion。

这些方法尝试改变“必须从左到右一个 token 一个 token 生成”的计算结构。

## 11. Evaluation

语言模型评估至少分：

- intrinsic：loss/perplexity；
- task benchmark；
- preference / pairwise evaluation；
- factuality / safety；
- latency / cost；
- long-context reliability。

单一 benchmark 不能代表整体能力。

## 12. 架构判断框架

看到新架构时，优先问：

1. 它减少了什么瓶颈？
2. 牺牲了什么？
3. 训练和推理是否都受益？
4. 改变的是 attention、FFN、state、routing 还是 decoding？
5. 优势来自算法还是硬件/实现？

来源：Compendium Chapter 07 后两节；具体模型版本不固化。

## 13. 生成策略的实际区别

给下一词分布 `[0.5, 0.3, 0.15, 0.05]`：贪心选第一项；top-k=2 留下前两项；top-p=0.9 留下累计概率首次达到阈值的前三项，再归一化采样。Top-p 留下的候选数量随分布变化，不能理解成固定保留 90% 的词表。

Beam Search 同时保留若干得分较高的部分序列；它优化指定的序列评分，并不保证最符合人的偏好。多轮迭代或扩散生成改变生成过程，需单独比较总计算量、串行步数、质量与硬件利用率，不能仅按“非自回归”判断快慢。

**自检**：模型写着“总参数很多、激活参数少”，能否据此确定一张显卡能装下？固定大小递推状态是否保证可以精确找回历史中的任意一句话？

**核对**：不能，驻留权重、量化、KV、工作区和分片都会影响内存；固定状态压缩了历史，精确回忆能力须用任务测试，不能由复杂度直接推出。

先读懂一种 Decoder-only 架构及其形状，再把新架构按“状态如何存、计算如何做、输出如何选”与它比较；无需把本章名词一次背完。

## 14. 从配置读架构：尺寸、参数与部署条件

先修[注意力形状、Norm与FFN](../AI%20算法基础/深度学习专题/04-注意力机制与Transformer.md)第14～18节。读一个checkpoint，先固定官方repo/revision、config、实现和Tokenizer；型号简称不能代替版本。把字段分别映射到词表V、hidden D、层数L、FFN宽F、Q/KV头及头宽、位置/窗口、专家和共享关系，再查每个模块真实张量。

RMSNorm分母是root mean square，不是std，也不是省掉“一次矩阵乘法”；SwiGLU的gate/up/down三矩阵按实际F计数。Pre-norm常用，不是所有模型只有两次前置norm，例如Gemma 2含额外post norm。最大位置字段可表示配置上限或缩放后的范围，不自动证明预训练长度和长文本可靠性；某家族原版与后续revision的8K/128K也不能合并。六个“旋钮”是一种检查目录，未覆盖位置/激活之外的所有架构，更不证明下一代只有六种选择。

对无bias的标准GQA、每头d，四投影参数为 `2D Hq d + 2D Hkv d`；SwiGLU FFN为 `3DF`；每层两个可学RMS gamma为2D，final为D。输入embedding为VD；若输出head未绑定还需VD。GPT-2的bias、learned position table、LayerNorm beta及不同FFN需另算。模型声明的Hq不总等D/d：MLA有独立qk_nope、qk_rope与v维，不能一律用D/Hq。

KV缓存是runtime状态。普通GQA为 `2BNLHkv d × bytes`；局部层可保留 `min(N,W)`，全局层仍N。half local/half global、同头维在N=8192,W=4096时，缓存相对全global为 `(N+W)/(2N)=.75`，省25%，前提是内核真的截缓存。训练激活峰值还受batch/长度、checkpoint粒度、Flash实现、mask、dtype、FFN临时张量、反向与优化器影响，config本身不能给精确峰值。

### 14.1 完整无权重参数审计：Qwen字段与DeepSeek主干

2026-10-05读取[Qwen2.5-72B官方config](https://huggingface.co/Qwen/Qwen2.5-72B/blob/main/config.json)、[DeepSeek-V3官方config](https://huggingface.co/deepseek-ai/DeepSeek-V3/blob/main/config.json)和[官方MLA/模型实现](https://github.com/deepseek-ai/DeepSeek-V3/blob/b15f0dbbbe6a4bc403306175698439ef380f5fb5/inference/model.py)。以下只做整数计算，不创建大矩阵或下载权重。Qwen模型的Q/K/V bias另计、head未绑定；不把代码常量当所有revision通用配置。

```python
def dense_gqa(D,F,L,V,Hq,Hkv,d,tied,qkv_bias=False):
    if min(D,F,L,V,Hq,Hkv,d)<1 or Hq%Hkv or D!=Hq*d:
        raise ValueError('本例标准GQA合同；MLA不能套用')
    attn=2*D*Hq*d+2*D*Hkv*d
    bias=(Hq+2*Hkv)*d if qkv_bias else 0
    return V*D*(1 if tied else 2)+L*(attn+bias+3*D*F+2*D)+D
qwen=dense_gqa(8192,29568,80,152064,64,8,128,False,True)
print('给定Qwen配置参数',qwen,'约',round(qwen/1e9,3),'B')
def v3(experts=256,topk=8,rank=512):
    D,H,qrank,nope,rope,v,F,ef,L,nd,V=7168,128,1536,128,64,128,18432,2048,61,3,129280
    if not 1<=topk<=experts or rank<1:raise ValueError('专家/top-k/rank合同')
    # Q两投影；KV下投影含共享RoPE键；KV上投影；输出；低秩两norm。
    attn=D*qrank+qrank*H*(nope+rope)+D*(rank+rope)+rank*H*(nope+v)+H*v*D+qrank+rank
    expert=3*D*ef;dense=3*D*F;router=D*experts+experts

    total=common+(L-nd)*(expert*(experts+1)+router)
    active_estimate=common+(L-nd)*(expert*(topk+1)+router)
    cache=L*(rank+rope)*131072*2
    return total,active_estimate,cache,attn,expert
```

这个主干约671.026B可由公开尺寸复算，不含MTP、FP8量化scale和非参数buffer；差额不需要猜未公开bias。约37.552B是**把完整embedding/head也计入**的结构性active估算；embedding实际每token只查相应行，参数口径不等每token FLOPs、读取字节或显存。论文37B是其报告口径与舍入，不能为了拟合这个整数随意增删模块。所有专家权重仍需驻留/分片，8/256只表示路由专家块比例，不能称总模型显存只用3.125%。

## 15. MLA：共享latent与解耦RoPE键

对位置t，hidden x_t经下投影得 `c_t=W_DKV x_t`，每头的内容key/value由c上投影；另有共享、已施RoPE的键 `k_t^R`。内容query与RoPE query分别参与内积，score为 `(q_i^C·k_t,i^C + q_i^R·k_t^R)/sqrt(d_nope+d_rope)`。压缩缓存需保存c和k^R，不能只存c后丢位置分支。[DeepSeek-V3第2.1.1节](https://arxiv.org/html/2412.19437v2#S2.SS1.SSS1)

按行向量，`k_i=c U_K,i`，于是 `q_i k_iᵀ=(q_i U_K,iᵀ)cᵀ`，把内容key上投影吸收到query。value同理：`Σ a_t(c_t U_V,i)=(Σa_t c_t)U_V,i`，先聚合latent再上投影，最后WO。位置相关旋转不能随意吸收到与位置无关的同一个矩阵，所以保留解耦k^R；真实实现还有norm、RoPE/YaRN缩放和分片约定。

V3官方latent512、RoPE键64，61层、N=131072、batch1、BF16缓存为 `61×N×(512+64)×2`，约8.578GiB/9.211GB。假想同61层GQA(8KV,128维)约30.5GiB，尺寸比576/2048=.28125，约省71.875%。这里仅对该假想基准，不证明MLA任何模型小于MQA。rank512→256时保留64位置分支，缓存576→320，减少44.44%而非50%；表达与质量损失要重新训练/评测。

### 15.1 完整CPU展开与latent聚合等价

本例输入是已按约定构造的内容query、latent和位置query/key，核对代数及causal前缀；不声称完整V3前向或模型压缩质量。

```python
import numpy as np
rng=np.random.default_rng(53);T,H,c,dk,dr,dv,D=6,3,4,3,2,3,8
C=rng.normal(size=(T,c));KR=rng.normal(size=(T,dr))
Q=rng.normal(size=(T,H,dk));QR=rng.normal(size=(T,H,dr))
UK=rng.normal(size=(H,c,dk));UV=rng.normal(size=(H,c,dv));WO=rng.normal(size=(H*dv,D))
def softmax(s):
    p=np.exp(s-s.max(-1,keepdims=True));return p/p.sum(-1,keepdims=True)
expanded=[];absorbed=[];mask=np.tril(np.ones((T,T),dtype=bool))
for h in range(H):
    K=C@UK[h];V=C@UV[h]
    se=(Q[:,h]@K.T+QR[:,h]@KR.T)/np.sqrt(dk+dr)
    sa=((Q[:,h]@UK[h].T)@C.T+QR[:,h]@KR.T)/np.sqrt(dk+dr)
    assert np.allclose(se,sa)
    A=softmax(np.where(mask,se,-np.inf))
    expanded.append(A@V);absorbed.append((A@C)@UV[h])
e=np.concatenate(expanded,axis=-1)@WO;a=np.concatenate(absorbed,axis=-1)@WO
assert np.allclose(e,a)
# query位置3的压缩路径只需前4个latent/位置键。
h=0;t=3
s=((Q[t,h]@UK[h].T)@C[:t+1].T+QR[t,h]@KR[:t+1].T)/np.sqrt(dk+dr)
single=(softmax(s)@C[:t+1])@UV[h]
assert np.allclose(single,absorbed[h][t])
print('展开/吸收矩阵/causal前缀一致，max差',np.max(np.abs(e-a)))
print('toy压缩缓存元素',C.size+KR.size,'展开K/V元素',T*H*(dk+dr+dv))
```

## 16. V3路由：选专家的bias与输出gate不同

先把每expert亲和score设为sigmoid，选择时用 `score+bias`；只在所选专家间归一**原score**作为gate，再乘配置route scale。batch过载专家减bias、欠载增bias，是另一个状态更新规则，不把这份bias混进输出权重。作者还有组/节点受限选择以约束通信，不能只写全局top-k就称完整V3router。[官方Gate实现](https://github.com/deepseek-ai/DeepSeek-V3/blob/b15f0dbbbe6a4bc403306175698439ef380f5fb5/inference/model.py#L535)

“auxiliary-loss-free”指主要负载调节机制；V3论文仍保留很小的**sequence-wise辅助平衡loss**，不是主训练目标完全没有任何辅助loss。top-k离散、门对所选score可微；基础MoE容量/overflow、负载损失与通信的完整程序由[推理与规模设计](../LLM%20工程实践/14-Transformer推理与规模设计.md)维护。本章只核对V3与一般softmax路由差别。

例如原score[.9,.8,.2]、bias[−1,0,1]、top1，第三expert胜出，但gate仍由.2归一，不用1.2参与加权。增加专家256→512、top8和每专家宽保持，专家计算预算近似不变，总存量增大；router的D×E参数、评分、通信/负载仍变化，所以active不能严格说一点不变。更多容量可能帮助不同token分工，也可能难训练，没有由稀疏率推出能力胜负的定理。

DualPipe属于训练调度，MTP属于训练目标及草稿用途，MLA属于attention状态，MoE属于FFN与路由；它们不是四个相互替代的模型。训练调度与FP8详见系统实践；仅config不能证明真实集群效率。V3/R1/NSA/DSA及未来版本要分别核对原报告与实现，不把名字相似或来源中的预测当架构证据。

## 17. 顺序MTP：额外预测必须在输入token之后

主干位置i已见t₀…t_i，预测t_{i+1}。第k个额外模块将前一深度h_i^{k−1}和 `Emb(t_{i+k})` **分别RMSNorm后concat**，用2D→D投影及一个causal Transformer block生成h_i^k，输出共享head预测 **t_{i+k+1}**。第1模块吃t_{i+1}后预测t_{i+2}；不能吃了t_{i+1}又用它作同位置target。[V3原公式21～25](https://arxiv.org/html/2412.19437v2#S2.SS2)

loss为 `L_main + (λ/D_extra)Σ_k L_k`，D_extra是额外深度数；每深度尾部没有target的位置排除。V3报告v2公式24是 `L_k=−(1/T)Σ_{j=2+k}^{T+1} log P_j^k[t_j]`，T为原输入长度；公式25再按λ/D_extra跨深度平均。本节教学代码按各深度**有效target数量**分别求均值，因此深度间权重与论文固定1/T的分母不同，不能称完全同一loss。λ是额外loss权重，与DIFF做差的λ无关。前一深度hidden不要detach，否则切断辅助loss对主干的学习信号。Emb和Out分别与主干共享，**不表示Emb与Out彼此绑定**；V3官方tie_word_embeddings=false。

### 17.1 完整CPU两深度MTP：正确移位、梯度与未来扰动

输入为循环token规则、短序列；主干和每模块都是causal attention+FFN，结合用RMSNorm。未加入V3的MLA/MoE或位置扩展。训练结果只验证人工循环与loss合同，不能称语言建模能力或真实推测接受率。

```python
import torch
from torch import nn
import torch.nn.functional as F
torch.set_num_threads(1);torch.manual_seed(54)
V,D,H,DEPTH=5,12,3,2
class RMS(nn.Module):
    def __init__(self):super().__init__();self.scale=nn.Parameter(torch.ones(D))
    def forward(self,x):return x*torch.rsqrt(x.square().mean(-1,keepdim=True)+1e-6)*self.scale
class Block(nn.Module):
    def __init__(self):
        super().__init__();self.n1=RMS();self.n2=RMS()
        self.a=nn.MultiheadAttention(D,H,batch_first=True,dropout=0.)
        self.f=nn.Sequential(nn.Linear(D,2*D),nn.GELU(),nn.Linear(2*D,D))
    def forward(self,x):
        z=self.n1(x);T=x.shape[1]
        # nn.MultiheadAttention中True是禁止，与SDPA相反。
        future=torch.triu(torch.ones(T,T,dtype=torch.bool),diagonal=1)
        x=x+self.a(z,z,z,attn_mask=future,need_weights=False)[0]
        return x+self.f(self.n2(x))
class Extra(nn.Module):
    def __init__(self):
        super().__init__();self.nh=RMS();self.ne=RMS()
        self.mix=nn.Linear(2*D,D,bias=False);self.block=Block()
    def forward(self,h,e):return self.block(self.mix(torch.cat([self.nh(h),self.ne(e)],-1)))
class Model(nn.Module):
    def __init__(self):
        super().__init__();self.emb=nn.Embedding(V,D);self.main=Block()
        self.out=nn.Linear(D,V,bias=False);self.extra=nn.ModuleList([Extra() for _ in range(DEPTH)])
    def forward(self,ids):
        T=ids.shape[1];h=self.main(self.emb(ids));pred=[self.out(h[:,:-1])]
        for k,module in enumerate(self.extra,1):
            n=T-k-1
            if n<1:raise ValueError('每深度至少一个有效target')
            h=module(h[:,:n],self.emb(ids[:,k:k+n]))
            pred.append(self.out(h))
        return pred
    def loss(self,ids):
        pred=self(ids)
        losses=[F.cross_entropy(p.reshape(-1,V),ids[:,k+1:k+1+p.shape[1]].reshape(-1)) for k,p in enumerate(pred)]
        return losses[0]+.2*torch.stack(losses[1:]).mean(),losses
model=Model();ids=(torch.arange(14)[None,:]+torch.arange(4)[:,None])%V
loss,parts=model.loss(ids);initial=loss.item();loss.backward()
assert all(m.mix.weight.grad.norm()>0 for m in model.extra)
assert model.emb.weight.grad.norm()>0 and model.out.weight is not model.emb.weight
opt=torch.optim.Adam(model.parameters(),lr=.015)
for _ in range(100):
    loss,parts=model.loss(ids);opt.zero_grad();loss.backward();opt.step()
final,parts=model.loss(ids);assert final<initial
with torch.no_grad():
    # k=1、位置i=3只可见到token4；target5及以后不能改变该预测。
    changed=ids.clone();changed[:,5:]=(changed[:,5:]+2)%V
    assert torch.allclose(model(ids)[1][:,3],model(changed)[1][:,3],atol=1e-6)
    pred=model(ids);assert [p.shape[1] for p in pred]==[13,12,11]
unique={id(p):p.numel() for p in model.parameters()}
assert sum(unique.values())==sum(p.numel() for p in model.parameters())
print('main/MTP1/MTP2有效长度',[p.shape[1] for p in pred],'loss',round(initial,4),'->',round(final.item(),4))
print('两模块有梯度，未来target未泄漏，共享Emb/Out与彼此untied合同通过')
```

辅助模块每个新增concat投影2D²、Transformer block和norm；标准dense MHA+SwiGLU宽F近似 `6D²+3DF+norm`，若F≈8D/3则约14D²。h8192为939,524,096加norm，不等V3 MoE模块。真实发布文件的MTP额外存储/共享方式需核对tensor标识，不能仅靠dense估计解释14B，也不把MTP计入普通主干37B每token激活量。

训练时模块吃真实下一token；推理草稿时吃已生成/草拟token，有分布变化。主干可以丢弃MTP正常生成，也可将其作draft。并行MTP的不同offset头缺少相互条件关系，仍可用于**自推测解码候选**并由主干验证，原Gloeckle论文已经演示；“不能做推测”是错误。无论draft类型，保持目标采样分布还需接受比、残差分布与prefix/cache回滚，见工程14；argmax一致率不是随机采样接受率，50%命中也不证明复现论文速度。MTP不是免费增加吞吐：模块前向、验证、拒绝、缓存和batch调度都收费。

## 18. SSM、Jamba与Mamba-3：递推、压缩状态与混合账目

先从离散线性系统 `s_t=A s_{t−1}+B x_t, y_t=C s_t` 学起。state固定维度时decode无需保存全部历史，单步成本对**序列长度**是常数，但仍依赖state/feature维及投影；训练时的中间态、反向和parallel scan与decode缓存分开。对稳定LTI系统可展开成卷积；输入相关的selective系数不能直接沿用固定卷积核。Mamba-1常以输入决定B/C和步长Δ，A是学习的固定对角参数，经Δ离散后transition可随输入变，不是所有A/B/C都原样动态预测。

固定有限状态压缩历史，不能保证任意原句精确检索；Transformer的KV也只是表示而非原文本完整无损记忆。混合层将SSM状态与少量attention的增长缓存一起维护，同时可在某些FFN层加MoE；attention比例、KV头、state宽、MoE频率是各自独立的选择。

2026-10-05读[Jamba-v0.1官方config](https://huggingface.co/ai21labs/Jamba-v0.1/blob/main/config.json)：32层、attention period8/offset4，所以attention在0-based的4/12/20/28，28个Mamba层；expert period2/offset1，即16层MoE，16专家/top2。Q32头、KV8头、d128；不是源SVG的“Mamba七层后attention”与MHA32KV的真实配置。它没有显式位置/RoPE；“Jamba1.5加RoPE”在本次可访问作者材料中未核实，不写为事实。1:3是1attention+3Mamba，1:15是1+15；源练习写成4+1与14+1错误。

缓存公式为 `2BN L_att Hkv d × bytes + B L_ssm D_inner(state_size+conv_width)×bytes`。Mamba-1还需卷积状态，D_inner可为expand×hidden；state精度可能高于KV，应分开计。原Jamba形状batch1,N262144,BF16的KV为4GiB；用MHA32KV的**假想**hybrid则16GiB。同假想32层MHA基准128GiB、GQA8基准32GiB不可混。论文“单80GB GPU”依赖int8等权重/配置，不是52B BF16权重104GB能因少KV自动装下。[Jamba原论文](https://arxiv.org/abs/2403.19887)

[Jamba-1.5原报告第2节](https://arxiv.org/html/2408.12570v1#S2)的Large使用9个8层块、D8192、Q64/KV8和1:7比例，同256K/BF16的KV为9GiB。它在350M/1.3B、100B训练token的特定消融中发现Mamba-1+attention优于Mamba-2+attention，因而选Mamba-1；作者将Mamba-2较大state优势在混合中不那么显著作为假设。这个证据来自2024年8月的1.5报告，不能移到2024年3月Jamba原论文第3节，也不外推为所有混合模型定律。

### 18.1 完整CPU递推、复数旋转与混合缓存

这个标量state小例核对指数梯形递推与复数/二维实数等价，不是完整Mamba-3训练；用合成输入核对代数和内存单位。

```python
import math
import numpy as np
rng=np.random.default_rng(55);xs=rng.normal(size=12)
def recurrence(x):
    # 指数梯形toy：current/previous input均参与，lambda=.5，dt=.2。
    dt=.2;a=math.exp(-dt);s=0.;previous=0.;out=[]
    for value in x:
        s=a*s+(1-.5)*dt*a*previous+.5*dt*value
        out.append(s);previous=value
    return np.array(out)
y=recurrence(xs)
for i in range(len(xs)):assert np.isclose(recurrence(xs[:i+1])[-1],y[i])
# exp((a+i*b)*dt)=exp(a*dt)乘旋转；两实坐标可存一个复数。
z=.3+.4j;pair=np.array([.3,.4]);theta=.7;decay=.9
R=np.array([[math.cos(theta),-math.sin(theta)],[math.sin(theta),math.cos(theta)]])
for _ in range(5):z*=decay*np.exp(1j*theta);pair=decay*R@pair
assert np.allclose([z.real,z.imag],pair)
N,D,L,Hkv,d,state,conv,expand=262144,4096,32,8,128,16,4,2
def memory(attn_layers):
    kv=2*N*attn_layers*Hkv*d*2
    ssm=(L-attn_layers)*(D*expand)*(state+conv)*2
    return kv,ssm
assert memory(4)[0]==4*2**30 and memory(32)[0]==32*2**30
for la in [32,8,4,2,0]:
    kv,ss=memory(la);print('attention层',la,'KV GiB',kv/2**30,'SSM+conv MiB',ss/2**20)
la=4
cross=(L-la)*D*expand*(state+conv)/(2*la*Hkv*d)
print('所述同dtype缓存交点N',cross,'复数/实旋转与prefix递推通过')
```

对上例交点N=560，N更大时attention缓存占主要部分；加入权重/分片、batch和不同state精度会改预算。1:7来自特定模型消融，不能固定16K以下禁hybrid、1:15以下一定失败；以真实长度分布、检索/状态追踪/任务质量、TTFT/decode与并发检验，而非先指定赢家。

Mamba-3改进三处：指数梯形离散让transition之外还加入前一输入项；复数state update相当于衰减加数据相关旋转；MIMO把rank-one输入/输出更新拓展为多输入、多输出矩阵。简化递推 `s_t=α_t s_{t−1}+β_t B_{t−1}x_{t−1}+γ_t B_t x_t` 中，α=exp(ΔA)、β=(1−λ)Δα、γ=λΔ；λ=1恢复指数Euler输入项。复数指数实部控制缩放、虚部控制phase，两实坐标旋转是等价存储，不能因“复数”直接推断计算翻倍。其输入相关累计角与普通固定位置RoPE也不同。[Mamba-3方法](https://arxiv.org/abs/2603.15569)

已读[作者Mamba-3模块](https://github.com/state-spaces/mamba/blob/33e2849ff046f72d60db8b17dbf47b7c949ff8c1/mamba_ssm/modules/mamba3.py)中的dt/decay、angle、MIMO投影及state缓存合同；完整方法还涉及B/C bias、QK norm、门、kernel与初始化，以上小例只隔离可解释的一部分。作者缓存另存累计角、上一B/输入与FP32 SSM state，不能用上面Mamba-1的BF16卷积预算冒充Mamba-3内存。论文阶段速度/质量在特定规模、state与硬件下成立，不能固定“当前最佳SSM”或预测下一代混合比例。Jamba2024原论文早于Mamba-2论文，不能照源练习编造“第3节比较后故意选择Mamba-1”的理由。

## 19. 架构四课练习与输出模板的核对标准

1. config计数：用14.1的Qwen输入复算untied head与QKV bias；不要把source14输出71.5B当精确参数或以“head rounding”猜差额。上游V3/14约665.9B、/20约664.5B，与自称476～490B也不一致；15节和公开尺寸给出可核算修正。
2. 256专家/top8比例8/256=3.125%，Mixtral的2/8=25%；前者更稀疏，原“denser sparse”用词反了。全模型active还含attention、共享expert/router/词表层，不把8/256当整体37/671。
3. 405B类部署题：先取精确checkpoint配置再代14节缓存公式；即使一字节405B权重，640GB减权重后仍需runtime/分片开销，不能以总节点内存相加便承诺并发数。BF16纯权重810GB已超过640GB，不能算负余量继续服务。此为原始载荷算术，不是某部署实测。
4. half窗口/half全局缓存省25%见14节；N/W/层布置、是否evict必须明确。找新架构时用固定revision分别核对，不维护当前能力榜单；原未来release预测淘汰。
5. MLA rank减半缓存并非减半；UK吸收到Q、UV移到latent聚合之后由15.1核对，RoPE键保留。更多experts不免费，router/内存/通信变化见16节；FP8只原始载荷减半，不等训练全状态减半。
6. MTP原程序先用h^{k−1}预测t_{i+k}再执行module，最后module的输出根本未用于loss；D=1下loss完全不依赖module，不能验额外预测。原a+b配D×D矩阵不等concat配2D×D，每模块少计D²；其单token attention权重恒1，QK score没有作用。源SVG先吃target又预测它，存在off-by-one泄漏描述。17.1改为module后预测t_{i+k+1}并验两模块梯度；降低随机hidden噪声的打印曲线无优化更新，不能称训练收敛。
7. 对dense70B估额外MTP，用2D²+block+norm，模块数D另乘；V3模块是MoE不是dense替身。每depth有效target按真实边界排除，D=2第二模块预测i+3。parallel/sequential公平对照需匹配预算与质量，不预言后一种必胜；本次未训练平行大模型或运行推测接受率实验。
8. 混合缓存：同head共享条件下把attention层从32变4，KV缩为1/8；换成真实Jamba的8KV再得4GiB。32层纯Mamba的SSM和卷积缓存按实际inner/state算，不是源SVG“小于1MB”。绘ratio曲线只证明内存函数，不证明检索质量。
9. 比较Jamba398/94与V3 671/37的active比例，可算94/398≈23.62%、37/671≈5.51%，但专家数、FFN频率、SSM/attention公共部分与报告口径不同，不能据比例定性能或推所有hybrid必更密。选Mamba版本先查发布时间与真实消融，复数旋转按18.1两实坐标核对，MIMO仍需作者kernel验证。
10. 源四种输出模板的有效部分是组件审计、真实内存账、质量/成本协议、版本与回退触发，已融14～18节。固定30B/24GB拒绝、无特定字段即“不是DeepSeek”、拒绝精确计数、1B/2K MTP禁令、70%接受线及假想未来型号不成为知识或审批规则。
