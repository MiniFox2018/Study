# 06｜微调、指令跟随与偏好优化

## 1. 微调的本质

预训练得到的是通用 next-token predictor。

微调是在较小、目标更明确的数据上继续训练，使模型形成特定行为。

## 2. 两类典型微调

### 2.1 任务微调

例如分类：

```text
文本 → 模型表示 → 分类头 → 标签
```

可选择：

- 冻结大部分模型；
- 只训练分类头；
- 解冻后几层；
- 全量微调。

训练参数越多，适应能力越强，但成本和过拟合风险也越高。

### 2.2 指令微调

训练数据一般组织为：

```text
Instruction
+ Optional Input
→ Desired Response
```

目标是让模型学习“按照指令完成任务”的行为模式。

## 3. 数据格式一致性

指令微调对数据模板非常敏感。

训练和推理的 Prompt 格式应尽量一致，包括：

- 指令边界；
- 输入字段；
- 回答起始位置；
- 特殊 Token；
- 对话角色。

## 4. Padding 与 Loss Mask

不同样本长度不一致时，需要 Padding。

但 Padding Token 不应参与训练损失。

因此通常使用 loss mask 或 ignore index，把无意义位置从 loss 中排除。

进一步还可以只对 Response 部分计算 loss，而忽略 Instruction 部分。

## 5. 数据质量比单纯数据量更重要

指令数据要关注：

- 正确性；
- 覆盖范围；
- 去重；
- 格式稳定；
- 难度分布；
- 是否存在互相矛盾的示例。

低质量合成数据可能把错误稳定写入模型。

## 6. 评估指令模型

不能只看训练 loss。

还要评估：

- 是否遵循指令；
- 是否回答正确；
- 是否遵守格式；
- 是否拒绝不该完成的任务；
- 是否在未见过的任务上泛化。

可使用：

- 规则验证器；
- 标准答案；
- 人工评估；
- LLM-as-a-Judge；
- 任务型 benchmark。

## 7. Preference Tuning

监督微调告诉模型“理想答案是什么”。

偏好优化则提供：

```text
Prompt + preferred answer + rejected answer
```

模型学习哪一种回答更符合目标偏好。

## 8. DPO

Direct Preference Optimization（DPO）绕过显式奖励模型，直接利用偏好对优化策略。

核心思想不是“背一个公式”，而是：

> 在保持参考模型约束的同时，提高偏好回答相对于非偏好回答的概率。

它是偏好对齐的一种方法，不代表所有对齐问题都应该使用 DPO。

## 9. 什么时候不该微调

如果目标只是：

- 给模型最新知识；
- 查询私有文档；
- 调用外部系统；
- 动态改变规则；

优先考虑：

- RAG；
- Prompt；
- 工具；
- Agent Workflow。

微调更适合需要稳定改变模型行为或内部能力的场景。
