# 08｜语言学与经典 NLP

> 本章是语言问题与任务的入口。先理解“语言学单位、模型 token、实体提及、真实对象”的区别，再沿文中链接进入算法实现；不要求先读完语言学教材才能学习 Transformer。

## 1. 为什么 LLM 仍需要 NLP 基础

Transformer 改变了建模方法，语言的结构与歧义仍存在。NLP 基础帮助定义输入、监督标签、输出与评价单位：一个模型能写流畅文本，不代表它正确分词、消解指代或理解否定；一份看似正确的 JSON 也不代表关系符合原文。

以“张三在北京大学读书。他昨天回了合肥”为例：分词决定 token 边界，POS 描述“读书”的语法角色，NER 定位“张三”“北京大学”“合肥”，依存关系连接“谁在哪里做什么”，共指将“他”和前文提及联系，实体链接再把“北京大学”映射到特定知识库 ID。摘要选择哪些信息，NLI 检查材料是否支持某个结论。每一步都有自己的合同与错误，不应把它们统称为“模型理解了文本”。

## 2. 形态学 Morphology

形态学研究词如何由词素组成：词根/词干、前缀/后缀、屈折与派生。英语 `walked` 中 `-ed` 表达过去时，`unhappy` 中 `un-` 改变意义；屈折通常改变语法形式，派生可能产生新词或新词类。中文的构词方式不同，不应照搬英语后缀规则。

形态变化影响词表规模、稀有形式与翻译。模型的 BPE/SentencePiece 切分由统计和编码目标决定，不保证恰好得到语言学词素。认识这个区别，可以避免把某个子词合并直接解释为“模型学会了语法”。

## 3. 句法 Syntax

句法研究词怎样形成短语与句子。成分句法用嵌套短语树表达层级，如名词短语与动词短语；依存句法用有向带标签的词间边表达核心词与从属词。词性 POS 是单个词的类别，依存关系是两个位置之间的关系，不能混用。

“张三喜欢李四”和“李四喜欢张三”词集合相同，主宾关系不同。被动句、省略、并列、否定、控制结构也使固定“主语→动词→宾语”模板不充分。不同树库的标签、root/标点处理与分词协议不同；工具的 `.dep_` 不必等于 Universal Dependencies 的标签。

LLM 可以隐式学习句法模式，不必每次构造树；attention 权重也不是直接可读的可靠句法树。具体 POS/HMM、CRF 与可检查依存树实现见[序列标注与实体消歧第 2～4 节](../AI%20算法基础/语言与文本专题/04-序列标注与实体消歧.md#2-特征词典与hmm的概率假设)。

## 4. 语义 Semantics 与语用 Pragmatics

语义讨论字面和组合意义，语用讨论上下文、意图与会话含义。“这台电脑真轻”是重量，“这个处分真轻”是程度；相同字词有不同词义。“这里有点冷”可能报告温度，也可能请人关窗，这需要情境与意图。

组合语义特别重视角色、否定、量词和范围：“所有人没来”和“不是所有人都来了”不能随便视为同义。语用推断通常可被后续上下文撤销，不能用固定规则把含蓄请求都标成确定命令。长上下文虽然提供更多信息，也可能包含矛盾、过期或无关内容。

自然语言推断区分蕴含、矛盾与信息不足；是给定文本的支持关系，不能直接证明世界真值。完整反例和评估见[摘要推断与文本评价第 3 节](../AI%20算法基础/语言与文本专题/05-摘要推断与文本评价.md#3-nli文本支持与世界真值的边界)。

## 5. 音系学 Phonology

音系学研究特定语言的音位与组合规则；语音学关注实际发音的声学/生理实现。音位对立、连读、变调与韵律影响语音识别和 text–speech 对齐。普通文字并不完整记录发音、语调或停顿，语音信号也不能由字符数精确预测长度。这里作为语音语言学习背景，声学与语音模型由[感知与多模态专题](../AI%20算法基础/感知与多模态专题/README.md)维护。

## 6. Tokenisation 与位置合同

常见单位为词、字符、子词；现代子词编码控制词表大小、组合稀有词并降低固定词表 OOV，但不保证所有语言都同等高效。词通常更接近语言意义，字符词表小但序列长，子词在二者间折中。UNK 与 PAD 含义不同；字符、Unicode code point、字节、UTF-16 code unit 也不能等同。

标注任务必须保留原文半开字符区间 `[start,end)` 与 token 的 offset。规范化、清理空白或改大小写后位置可能变化，需要映射回原文。NER 的子词 supervision 要明确只标首子词还是传播至全部子词，特殊 token 和 PAD 通常不计损失。生成任务另需 BOS/EOS 和目标移位；完整输入合同见[Tokenizer](02-文本-Tokenizer与Embedding.md)及[序列标注](../AI%20算法基础/语言与文本专题/04-序列标注与实体消歧.md)。

## 7. N-gram：有限上下文基线

N-gram 近似为 $p(x_t\mid x_{<t})\approx p(x_t\mid x_{t-n+1:t-1})$。训练以计数估计条件概率；未见事件需要平滑、回退或插值，使模型不会因一个零概率把整段概率归零。上下文长度增长会提高稀疏性，不能仅靠增大 n 无限改进。

它提供简单可解释的语言模型基线，适合检查新模型是否真的改善预测；分词、BOS/EOS、UNK 处理与训练/测试拆分仍影响结果。联合概率和 PPL 的定义/手算由[序列模型第 1 节](../AI%20算法基础/深度学习专题/03-序列模型与机器翻译.md#1-序列分词与语言模型)维护，计数与平滑实现见[文本表示与检索](../AI%20算法基础/语言与文本专题/01-文本预处理与稀疏表示.md)。

### 7.1 可解释自动补词：从计数到编辑动作

前面的N-gram可落成一个完全本地的单词候选器：只从作者提供的语料学习词频、最多两个词的历史及来源ID，给前缀提供候选。它不调用托管LLM，不补知识事实，不会推导未见词，更不把候选计数当语言质量或事实置信度。

**训练合同。** 输入是唯一非空id及非空text的语料数组。文本NFC规范化并小写，token为Unicode字母/数字串，可含内部直/弯撇号。按ASCII句号、问号、叹号或换行切句，不跨这些边界建立转移。词频words[w]累加；对每个位置分别记录前一词和前两词的JSON编码键→后继词计数；sources[w]是出现过该词的去重来源ID。

```text
输入：Garden club shares seeds. Garden club grows herbs.
词频：garden=2, club=2, shares=1, seeds=1, grows=1, herbs=1
历史["garden","club"]：shares=1, grows=1
没有 seeds→garden 转移，因为中间有句号。
```

使用无原型字典或Map避免constructor等合法词与对象原型相撞。这个分词器没有中文分词、词形还原或完整句子检测：连续中文可能是一整个token，中文句号没有被列为句界；组合标记即使NFC后仍可能残留而被切断。英文小例成立不等于对所有语言同样适用。

**候选证据与排序。** 对前缀同样NFC/小写，筛词表中startsWith的词；每个候选独立找最长可用历史：先前两词，再前一词，否则用全局词频。按order降序、该order的count降序、词的localeCompare排序，limit为0..50的整数，默认5。

例如词表seed=5、shade=10、share=2；两词garden/club后share出现1次，一词club后shade出现2次。前缀s、历史garden/club时share(order2,count1)排在shade(order1,count2)、seed(order0,count5)前。历史unknown时均退到order0，shade先于seed、share；前缀zzz返回空，不能补造远程答案。

返回的`score=order×1000000+count`是展示编码，真实排序先分别比较order/count。count若超过一百万，单独按score排序会违背原先层级，不能把这个编码当通用可排序数；它也不是归一概率，未实现平滑或对不同候选使用同一条件分母。不要用它计算困惑度或声称候选有某个正确率。

全样本的Garden club后shares计4、grows计2；输入`Garden club sh`的prefix=sh、history=[garden,club]，唯一相符shares用order2/count4。接受后为`Garden club shares `；这时native用order2/count2，seeds和tools各order2/count1。界面列出的来源是词的**全语料**来源，未细分“这个两词历史→该词”出现在哪一段，因此不能从sources直接证明每个条件转移的出处。

**编辑状态不能只按可见字数截断。** completeText只取最后句界后的尾段；若末尾是字母/数字/撇号，把最后token作为未完前缀弹出，其余最多两个词作历史；尾随空格表示当前词已完成，prefix为空。acceptSuggestion核候选是单个规范词，并确认当前原文仍以旧prefix结尾，再替换该后缀并加一个空格，保留前面原文。不能把shares直接接到sh后生成shshares。

来源仅处理文本末尾，不支持光标中间、选择区、IME组合输入或撤销事务。规范化还可能改变长度：原文用分解形式e+组合重音，tokenize产出é，但accept比较未规范化原后缀与é会拒绝；改成按规范后长度截原文又可能删错。正确扩展需保存原文偏移映射和编辑版本，围绕光标计算，并核输入法组合结束。末尾悬空撇号也需单独合同，不能直接套普通词例。

**可携带模型与安全输出。** JSON含schemaVersion=1、words、histories、sources。import核规范单词、正安全整数、history键解析为1或2个已有词、条件计数不超过相应词频、来源数组为非空字符串项，并返回深复制。它没验证来源ID实际存在、频率能由某份语料重建、全部历史的跨项一致性或编辑权限；空来源数组也不被拒。JSON“结构有效”与“训练证据真实”仍是两项验收。

网页调用同一套分词/候选/接受函数，把词、order、count和sources用textContent呈现，下载模型与写作文本；将模型嵌入脚本时另转义分隔符。模型可能暴露私人词汇和来源ID，本地并不等于适合公开上传。CLI顺序写模型、suggestions和HTML，未提供整包原子发布与来源版本绑定，点击候选也不会自动重新训练模型。

四图的第一/第三只用ASCII字母正则，第二显示分数，第四只比较单个条件count与总数；不替代核心Unicode、整份模型校验或编辑状态处理。本次没有执行来源浏览器JS或真实键盘操作。

## 8. TF-IDF：词面特征与稀疏检索

TF-IDF 结合篇内词频和跨文档稀有度。例如教学定义 $\mathrm{IDF}(w)=\ln(N/\mathrm{df}(w))$，三篇文档中“苹果”出现两篇、“显卡”出现一篇，则 IDF 为 $\ln(3/2)$ 和 $\ln3$；同词频下“显卡”权重更高。实际实现可用加一平滑、sublinear TF 和 L2 归一化，必须报告具体公式。

它适合稀疏检索、可解释文本特征、低成本基线，却无法单独识别角色、同义替换和复杂否定。词表与 IDF 只能在训练集拟合，不能把测试集偷偷纳入词频统计。详细实现由[文本表示与检索](../AI%20算法基础/语言与文本专题/01-文本预处理与稀疏表示.md)维护，检索与 RAG 管道由[文本检索与文档工程](../LLM%20工程实践/12-文本检索与RAG文档工程.md)维护。

## 9. POS、NER、共指与实体链接

- **POS**：给已定义的 token 标词性，如名词、动词；同一词可因上下文改词性。
- **NER**：定位文本中的实体提及并给类型，如人、组织、地点。标签集合必须来自任务协议，“PRODUCT”不一定属于所有模型。
- **共指**：把同文档中指向同一对象的多个提及连成簇，包括名字、名词短语和代词；“车”和“车轮”的关联是 bridging，不必是同一对象。
- **实体链接**：将提及映射到某一版本知识库的规范 ID，并处理候选不足、歧义和 NIL。两段相同文字不必是同一实体，同一实体可以有多个别名。

NER 的 token F1 与完整 span/type F1 不同；共指簇与实体链接 ID 评价也不同。先做 BIO 边界与精确实体匹配，再做消歧。完整算法、例子、CRF/共指评价/候选召回见[序列标注与实体消歧](../AI%20算法基础/语言与文本专题/04-序列标注与实体消歧.md)。

## 10. 词向量与上下文表示

Word2Vec/GloVe 把离散词映射到连续向量，利用分布上下文学习表示。静态词表一般让同一个“苹果”在水果和手机语境使用同一向量；上下文编码器会生成随位置/周围文本变化的表示，但不同表示不自动保证正确消歧。

词向量的邻近只是训练数据中的统计关联，不等于百科事实、逻辑蕴含或无偏语义。向量平均也会丢掉次序。词向量/子词/上下文机制由[Tokenization 与词嵌入](02-文本-Tokenizer与Embedding.md)维护，候选检索与 reranker 是不同处理阶段，不能用随意加实体标记的通用 encoder 冒充特定预训练链接模型。

## 11. RNN、LSTM、GRU 与 TextCNN

RNN 用递归状态表示历史；LSTM/GRU 用门调节储存与更新，缓解某些长依赖训练困难，但不保证无限长度记忆。TextCNN 在 embedding 上学习局部窗口特征，并聚合用于分类。前者可携带流式状态，后者容易计算局部触发模式；现代 Transformer 可因果流式生成，不能把它说成必须等待全部未来输入。

用这些小模型可以学会序列状态、BPTT、padding、pooling 和 causal/offline 的区别。完整门控公式、packed BiLSTM 与严格窗口 mask 例统一在[序列模型第 2～3 节](../AI%20算法基础/深度学习专题/03-序列模型与机器翻译.md#2-rnnbptt-与门控状态)，这里不重复维护实现。

## 12. Seq2Seq、Attention 与任务评价

Encoder–decoder 编码源序列，再逐步生成目标，可用于翻译、摘要、ASR；Attention 让解码步按当前需求读取源位置，缓解固定 context 的读取瓶颈。训练 teacher forcing 用真实前缀，推理只可用自己的输出；EOS、PAD、目标移位、结束状态和 beam 缓存必须分别处理。实现见[序列模型第 4～7 节](../AI%20算法基础/深度学习专题/03-序列模型与机器翻译.md#4-注意力按解码需求读取输入)，通用 Transformer 结构见[Transformer 架构](04-Transformer与GPT架构.md)。

翻译/摘要的词面指标 BLEU、chrF、ROUGE 与语义/人工评价衡量不同目标。高 ROUGE 不保证数字或关系正确，NLI支持不保证前提真；完整协议与手算例见[摘要推断与文本评价](../AI%20算法基础/语言与文本专题/05-摘要推断与文本评价.md)。

## 13. 学习顺序与自检

先拿两句短文本标出词、字符位置和歧义，再运行 TF-IDF 或有限上下文基线；随后做 BIO/CRF 和 packed 序列模型；最后比较摘要/翻译错误。每一步写出输入输出、标签与无效位置，不以“知道名词”作为完成。

1. BPE 子词就是语言学词素吗？**答**：不是，分词优化目标与语言学构词分析不同。
2. 静态 embedding 会自动为两个“苹果”提供不同向量吗？**答**：标准静态词表通常不会；上下文表示会变但可能仍误判。
3. 一个代词没被 NER 识别，是否不需要共指？**答**：不是；代词通常不是命名实体，却是重要提及。
4. 提及找不到 KB 候选，能否立即证明真实对象不存在？**答**：不能，可能是检索失败、别名缺失或版本限制。
5. 相同词袋能否证明两句语义一致？**答**：不能，次序/角色/否定/范围可能不同。
6. 正确 token F1 能否证明实体完整恢复？**答**：不能，一个边界错可能破坏整个实体。
7. 本章与算法专题如何分工？**答**：这里定义术语和关系；专题维护完整机制、代码、评价和边界，避免重复版本冲突。
