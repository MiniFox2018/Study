# 09 真实世界应用与项目实践

## 1. 行业应用的共同结构

不同领域表面差异很大，但数据科学项目通常遵循同一模式：

```text
业务/研究问题
→ 数据化
→ 清洗与表示
→ 统计/模型
→ 验证
→ 决策或产品
→ 反馈
```

## 2. 典型行业

### 物流
路线、天气、交通、时限和历史配送数据可用于路线预测与调度优化。

### 城市交通
出租车、公交、地铁等轨迹与运营数据可用于理解需求、拥堵、收入与可靠性。

### 体育
用于球员评估、战术、伤病、票务、场馆和粉丝运营。

### 金融
用于风险建模、欺诈检测、客户细分、预测与推荐。

### 医疗
用于医学影像、基因组学、药物研发、患者风险、资源调度与疾病监测。

这些领域共同要求：高数据质量、严格评估，以及对错误代价的理解。

## 3. 科研：不仅追求性能

研究型数据科学同时关注：

- 新方法能否产生新洞察；
- 在真实使用条件下是否有偏差和副作用。

Gender Shades 是典型案例：研究价值不在于“又训练一个更高分模型”，而在于改变评估方式——从总体准确率转向关键子群体表现。

## 4. 数字人文

数据科学可用于：

- 文本分析；
- 情感分析；
- 网络分析；
- 空间分析；
- 信息可视化；
- 历史资料结构化。

典型流程：

```text
获取文本
→ 清洗
→ 构造结构化数据
→ 统计/可视化
→ 文本或情感分析
→ 回到人文学问题解释
```

技术结果必须与学科语境结合。

## 5. 可持续发展

地球观测、生态、气候等任务往往涉及：

- 海量空间数据；
- 时间序列；
- 遥感；
- 分布式存储；
- 云端计算；
- 地理空间分析。

关键挑战不是单个模型，而是如何让大规模数据可发现、可查询、可计算并形成决策支持。

## 6. 一个可执行的学生项目模板

### 选题
选择一个明确问题，而不是“做一个数据分析”。

### 数据
记录：

- 来源；
- 许可；
- 时间范围；
- 字段说明；
- 样本偏差。

### EDA
至少完成：

- 质量检查；
- 单变量分布；
- 分组比较；
- 关系分析；
- 异常检查。

### 假设
写出 2–5 个可以被数据支持或反驳的问题。

### 结果
包含：

- 图；
- 表；
- 指标；
- 不确定性；
- 限制。

### 复现
让别人只看仓库就能重新得到结果。

## 7. 项目评价标准

一个好的入门项目不看“模型多复杂”，而看：

- 问题是否清楚；
- 数据理解是否扎实；
- 清洗是否有依据；
- 统计方法是否匹配；
- 图表是否诚实；
- 结论是否过度；
- 是否可复现；
- 是否考虑伦理与偏差。

## 8. 最终检查

提交前问：

1. 结论能由数据直接支持吗？
2. 有没有把相关写成因果？
3. 有没有只展示支持观点的切片？
4. 是否说明了样本和时间范围？
5. 是否有不确定性？
6. 是否有敏感数据风险？
7. 是否能复现？
8. 如果读者据此行动，最坏后果是什么？

这八个问题比增加一个复杂模型更能提升项目质量。
