# 数据版本、缓存与流式处理

先修：文件/JSON、训练验证测试的分工。本章连接[数据质量](./02-数据类型-来源与质量.md)、[存储查询](./04-关系型-非关系型存储与查询.md)和[模型资产](../LLM%20工程实践/02-模型获取与环境管理.md)，重点是“下次还能找到并解释同一批输入”。

## 1. 数据管理是一条可追溯链

```text
任务与许可 → 来源及固定版本 → 获取/校验 → 原始输入
→ 字段/清洗规则 → 划分 → 训练/评估 → 产物与反馈
```

这条链同时承担源教程图中的下载、缓存、格式转换和切分功能。缓存只节省获取成本，不能代替数据版本、备份或授权记录。

先判断任务需要文本分类、问答、检测、语言建模还是其他标注，再选数据；“某著名数据集”不是自动适合当前任务。核对标注单位、字段、语言、人群、时间、许可、访问限制和评估口径。

## 2. 四种格式怎样选择

| 格式 | 表达与访问特点 | 适用 | 代价 |
|---|---|---|---|
| CSV | 行列文本，类型常需额外解释 | 小表、表格交换 | 嵌套、日期、空值语义易丢失 |
| JSON/JSONL | 嵌套对象；JSONL 每行一个记录 | 文本样本、事件、API | 类型和schema仍需检查；整份JSON不自动可逐行读 |
| Parquet | 列式、schema、压缩和分组统计 | 分析型持久存储，按列读取 | 小文件/复杂对象不一定占优 |
| Arrow | 标准列式内存/交换表示，也有IPC文件 | 批量处理、库间交换 | 并非全部操作零拷贝，转换可产生副本 |

不能把 Parquet 叫作“压缩CSV”就结束解释：类型、列裁剪和结构不同。哪种更小/更快须用同一数据、压缩参数和所需查询测量，不能无条件排名。

转换后检查行数、主键、类型、空值、编码、时间/时区与至少几条边界样本。浮点小数格式变化或CSV空字符串处理可能改变结果。

## 3. 一个自包含的版本与切分例子

以下虚构数据只练习管理流程；不是推荐真实任务都做随机切分。保存为脚本，从新练习目录运行：

```python
import hashlib
import json
import random
from pathlib import Path

out = Path("data-lab")
out.mkdir(exist_ok=True)
rows = [{"id": i, "text": f"样本{i}", "label": i % 2} for i in range(100)]
raw = b"".join((json.dumps(r, ensure_ascii=False) + "\n").encode("utf-8") for r in rows)
(out / "input.jsonl").write_bytes(raw)
ids = list(range(len(rows)))
random.Random(42).shuffle(ids)
splits = {"train": ids[:70], "validation": ids[70:85], "test": ids[85:]}
a, b, c = (set(splits[k]) for k in ("train", "validation", "test"))
assert not (a & b or a & c or b & c)
assert a | b | c == set(range(100))
manifest = {
    "输入sha256": hashlib.sha256(raw).hexdigest(),
    "记录数": len(rows), "种子": 42,
    "样本ID": splits, "分组计数": {k: len(v) for k, v in splits.items()},
    "许可": "自构造教学数据", "处理": "未做特征拟合",
}
(out / "manifest.json").write_text(json.dumps(manifest, ensure_ascii=False, indent=2), encoding="utf-8")
print(manifest["分组计数"])
```

输出 `70、15、15`；三组互斥且完整覆盖。清单存实际 ID，不仅存种子。种子固定但输入顺序、算法或库版本变化，切分仍可能改变；有需要时按稳定排序或持久 ID 明确输入集合。

现实中同一患者/用户/文档、重复内容不能跨组泄漏；时间预测常需按时间切。构造了一个新ID不等于内容独立。小样本分类检查每类数量，必要时分层，但不能先破坏分组/时间约束。

## 4. Hugging Face 的加载、配置与版本

`load_dataset` 的逻辑是来源ID或文件类型 + 可选配置 + split + revision；同一仓库可有不同语言/子集配置。首次加载会获取数据或元数据，再形成缓存；后续命中缓存也要依照版本和权限检查，不承诺立即加载或永久可离线。

可选实践（需要安装与项目兼容的 `datasets`，本次未下载在线训练集）：

```python
from datasets import load_dataset

local = load_dataset("json", data_files="data-lab/input.jsonl", split="train")
assert len(local) == 100
print(local.column_names)
```

使用在线仓库时把实际 dataset ID、配置、固定 revision、split 和访问条件写入清单，不机械复制源站旧ID。必要登录时使用当前 Hub 客户端所支持的认证流程，不把 token 写进加载代码。

常见任务可以对应：情感分类看评论+标签；跨度问答看问题/上下文/答案位置；图像分类看图像+类别；检测看框/类别/坐标约定；语言建模看文本来源与时间。名称只能帮助发现数据，不能代替字段与许可核查。

## 5. 流式读取是受约束的懒执行

JSONL 本地迭代示例，不把全部记录追加进内存：

```python
import json
from pathlib import Path

count = 0
with Path("data-lab/input.jsonl").open(encoding="utf-8") as stream:
    for line in stream:
        record = json.loads(line)
        count += 1
        if count <= 3:
            print(record["id"])
print("总记录：", count)
```

前3个ID为0、1、2，总数100。改成 `all_rows.append(record)` 就会重新占用随记录数增长的内存。单条记录太大、预取、缓存、shuffle buffer、批次和并行worker同样占内存，因此不能宣称“streaming内存永远常量”。

在线接口 `load_dataset(..., streaming=True)` 通常得到 `IterableDataset`，不能假定支持随机索引或廉价精确长度。`take(N)` 可做小样本检查，有限缓冲 shuffle 不是全数据均匀打乱；多worker需正确分片，不能让每个worker重复读取同一遍。

网络断开后如何恢复要按数据格式、可用检查点和来源能力设计。只记录“已读1000行”不足以在数据版本变化后恢复同一位置。

## 6. 缓存和模型下载

Hub 单文件下载可用于配置检查，完整snapshot下载用于需要的模型资产。固定 revision、下载方式和校验信息；如果原文的模型ID已不存在或无授权，不用同名近似资源静默替代。

模型缓存与数据缓存是不同目录体系，默认位置还可能被环境变量和版本改变。运行前显示当前配置的缓存根、估计需求与剩余空间，避免把默认目录当作固定永恒路径。

模型权重、tokenizer、config 和聊天模板共同形成一致资产。仅有权重不能保证正确推理。清理缓存前核对它是否是离线唯一副本、是否还被实验依赖；原文的“一键删缓存”不作为盲目解决磁盘问题的步骤。

## 7. ignore、LFS、DVC 与数据可恢复性

| 方式 | Git 保存什么 | 适合什么 | 仍须做什么 |
|---|---|---|---|
| `.gitignore` | 不保存被忽略的新文件 | 可重新获取的缓存/大产物 | 固定来源、版本与校验值；它不是备份 |
| Git LFS | 跟踪指针，内容由LFS存储 | 需要随代码关联的大文件 | 上传内容、核对配额/权限；只有指针不够 |
| DVC | 数据/管道元数据与校验标识 | 数据版本和实验依赖 | 配置可访问的remote并保存实际对象 |

DVC 的最小工作流示意：

```bash
dvc init
dvc add data/training.parquet
git add data/training.parquet.dvc data/.gitignore .dvc/
git commit -m '记录训练数据版本'
# 再配置你有权限的实际remote，并按需要dvc push。
```

上述是示意，要求已经准备实际输入；不意味着本仓库初始化了 DVC 或开通存储。上传完成后另一环境需要同时取得 Git 元数据和实际数据对象。

在 Study 中保留小型自包含练习即可；默认不提交大型数据/模型和整套原始仓库。源站固定LFS免费配额、租用价格和“10GB以上一定上云”等阈值不进入主干。

## 8. 哈希能证明什么

对全输入字节计算哈希可检测同一字节是否改变；若数据拆为多个文件，还要记录全部文件列表和顺序/分片关系。只对前100行计算的“指纹”只能检测那部分样本，不能当作完整数据校验。

哈希不证明来源可靠、许可有效、标签准确或样本代表性。DataFrame重新输出时顺序和序列化规则变化也会改变哈希，因此记录它作用于“原始文件”还是“规范化记录”。

## 9. 练习与答案

1. 将数据改为10个用户、每用户10行，能继续按行随机划分吗？答案：若评估新用户，应按用户分组再划分，并检查互斥。
2. Parquet 比 CSV 大，是否转换错误？答案：未必，小文件元数据、压缩配置和数据类型都会影响大小，正确性要看数据内容。
3. 能从某条缓存读取数据，是否说明原站明天消失后还能复现实验？答案：还需持久保存许可允许的实际输入及版本；缓存可能被清理。
4. 第一阶段取20%测试，余下80%中取12.5%验证，总比例是多少？答案：训练70%、验证10%、测试20%，不是80/10/10。
