# 学完以后怎样检查自己

这组模式帮助你把一个任务拆成“输入、状态、动作、反馈和完成条件”。不需要在一个项目里同时用上 21 个模式；每增加一种机制，都应能指出它解决了哪个已经观察到的问题。

## 一个综合练习

用三篇虚构制度文档设计只读问答：一篇现行、一篇旧版、一篇缺失关键答案。先手写检索与回答结果，再画出实际工作流。加入一次工具超时、一次越权查询、一次矛盾证据，说明系统如何处理。

完成证据：能选对现行来源；无答案时不编造；读不到的文件不会进入上下文；超时不会导致无限循环；最终报告说清已做与未做。可以先全部用纸笔和伪数据，不要求开通 API 或部署框架。

## 继续学习的判断

如果说不清输入输出，回到工具和上下文章节；如果流程容易提前结束，回到目标与评估；如果失败后重复执行，回到异常恢复；如果机制越来越多却没有提高成功率，删减到能验证的最小闭环。

能在条件变化后选择和修改方案，比记住所有名词更接近掌握。来源、教学例子与自己实际完成的练习应分别记录。更新：2026-10-02。
