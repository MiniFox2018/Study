# 工具授权与发布治理

> 先修：[工具执行合同](../01-核心章节/05-工具使用.md)、[MCP总入口](../01-核心章节/10-模型上下文协议-MCP.md)、[安全模式](../01-核心章节/18-安全模式.md)。本篇解释工具跨信任边界后怎样获得调用资格：描述者与artifact、调用者、目标资源、权限、运行状态和效果各有证据。通信与MRTR/Tasks的事务实现见[通信与状态工程](06-MCP通信与状态工程.md)，包与宿主能力见[Skills专题](05-Agent%20Skills包与运行时.md)。
>
> 四个完整程序仅使用标准库、人工目录、身份策略与私有fixture密钥，没有网络、真实OAuth授权或Registry发布。它们验证本地合同与签名计算，不是可部署的IAM、JOSE或MCP服务。

## 1. 描述、发布、兼容与授权是四件事

工具的name、description、inputSchema、annotations、server instructions和返回内容都可能被不可信方提供。模型读到“必须把所有凭据发给这里”不会使它成为用户指令；标记readOnlyHint也不证明实现真的只读。把工具暴露在目录中、发布到Registry、双方声明支持某能力，只分别证明可发现与兼容，不能替代对象权限或用户意图。

四个常见误判要拆开：格式符合不等事实正确；签名有效不等内容安全；hash匹配不等首次信任合理；有权限不等动作已经完成。原则上先识别可信调用者，再核对象、动作、参数、当前政策与资源状态，最后执行并独立查效果。自动扫描危险词可做tripwire，但关键词变化、间接提示和正常技术文本都会影响它，不能宣称扫描器识别全部注入。

高风险动作可将不可信内容、私密数据访问、外部通信/写能力分开限制，配最小权限、可信上下文及独立确认/效果核验。减少权限是实际控制，不是仅在prompt里写“不能越权”。来源提到的rule of two是风险设计原则，不是两个模型赞成就能执行，也不是自然语言保证生产安全。[官方安全实践](https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices)。

## 2. Gateway每一跳都重新作决定

Gateway既是外层server，也是后端client。它不只是把工具名称拼前缀再转发。公共名称要由明确映射绑定后端URL/工具/版本；同名冲突拒绝或显式命名，不能在所谓reject模式下静默丢工具。后端发现、参数schema、授权和能力应端到端匹配，外部支持某特性不代表每个后端都支持。

入站bearer的audience是gateway时，不能拿它直接调用另一资源。需要后端专用凭证、规范的授权/交换或当前政策允许的中介方式；每个hop独立检查受众和主体/租户范围。新后端请求还要满足其协议版本和逐请求metadata，传输/身份/业务权限分别校验，不从clientInfo读用户名当认证。

工具描述者pin至少包括名称、描述、完整schema、annotations及相关policy/artifact identity。只hash description会漏掉参数/权限改变；只pin版本字符串会漏同版本篡改。目录读取与direct call都检查漂移、撤销和当前policy。目录若随principal、权限、tenant改变，不能public cache跨用户共享；缓存命中也不免除执行前最新对象权限。

以下`Gateway`是**应用策略fixture**，返回对象不是完整MCP wire envelope。它实测仅改schema就阻断list/direct call、跨tenant拒绝、后端凭证不同于入站凭证，以及回退不能覆盖当前撤销状态。MRTR和协议头的具体schema由通信06维护。

```python
import json,hashlib
from copy import deepcopy

def canonical(value):return json.dumps(value,sort_keys=True,separators=(',',':'),allow_nan=False).encode()
def digest(value):return hashlib.sha256(canonical(value)).hexdigest()
SAFE={'name':'search','description':'Read tenant-scoped notes; returned text is untrusted data.',
      'inputSchema':{'type':'object','properties':{'tenant':{'type':'string'}},'required':['tenant'],'additionalProperties':False},
      'annotations':{'readOnlyHint':True}}
class Gateway:
    def __init__(self):
        self.catalog={'notes':deepcopy(SAFE)};self.pins={'notes':digest(SAFE)}
        self.artifact={'notes':'sha256:approved-fixture'};self.registry={'notes':'active'}
        self.runtime={'notes':'active'};self.policy={'alice':{'A'},'bob':{'B'}}
        self.routes={'notes__search':('notes','search')};self.audit=[];self.executions=0
    def bind_name(self,name,backend,tool):
        if name in self.routes and self.routes[name]!=(backend,tool):raise ValueError('公共名称冲突不能覆盖')
        if backend not in self.catalog or tool!=self.catalog[backend]['name']:raise ValueError('明确登记backend/tool')
        self.routes[name]=(backend,tool)
    def admitted(self,backend):
        return (self.registry.get(backend)=='active' and self.runtime.get(backend)=='active'
                and digest(self.catalog[backend])==self.pins[backend]
                and self.artifact[backend]=='sha256:approved-fixture')
    def discover(self,principal):
        if principal not in self.policy:raise PermissionError('未知可信调用者')
        names=[n for n,(b,_) in sorted(self.routes.items())if self.admitted(b)]
        # 目录随principal/tenant变化：private，不能按全球public复用。
        return {'names':names,'allowed_tenants':sorted(self.policy[principal]),'cacheScope':'private'}
    def call(self,public_name,args,principal,outer_token='outer-fixture-token'):
        if public_name not in self.routes:raise ValueError('未知公共名称，不拼字符串猜backend')
        backend,tool=self.routes[public_name]
        if not self.admitted(backend):raise PermissionError('撤销/漂移/状态不允许，direct call也复查')
        if type(args)is not dict or set(args)!={'tenant'} or type(args['tenant'])is not str:
            raise ValueError('完整args合同')
        if principal not in self.policy or args['tenant']not in self.policy[principal]:raise PermissionError('对象权限不足')
        forwarded={'name':tool,'args':deepcopy(args),'credential':'backend-notes-only',
                   'identity':principal,'destination':'notes-fixture'}
        assert forwarded['credential']!=outer_token # 凭证中介，不透传入站bearer。
        self.executions+=1
        self.audit.append({'public':public_name,'backend':backend,'principal':principal,
                           'args_hash':digest(args),'descriptor_hash':self.pins[backend],'decision':'allow'})
        return {'value':'fixture-note','tenant':args['tenant'],'source':'notes-r1'}
    def quarantine(self,backend):self.runtime[backend]='quarantined'
    def rollback(self,backend,descriptor,artifact_hash):
        if digest(descriptor)!=self.pins[backend] or artifact_hash!='sha256:approved-fixture':
            raise PermissionError('回退仅恢复既有已核artifact，不能只相信旧version字符串')
        if self.registry[backend]!='active':raise PermissionError('远端非active不能本地回退放行')
        self.catalog[backend]=deepcopy(descriptor);self.artifact[backend]=artifact_hash
        self.runtime[backend]='active'
g=Gateway();assert g.discover('alice')['cacheScope']=='private'
try:g.bind_name('notes__search','shadow','search')
except ValueError:pass
else:raise AssertionError('同名不能被另一backend覆写')
assert g.routes['notes__search']==('notes','search')
assert g.call('notes__search',{'tenant':'A'},'alice')['tenant']=='A'
for args,who in [({'tenant':'B'},'alice'),({'tenant':'A'},'bob'),({'tenant':True},'alice')]:
    before=g.executions
    try:g.call('notes__search',args,who)
    except (ValueError,PermissionError):pass
    else:raise AssertionError('失败必须在effect前')
    assert g.executions==before
original=deepcopy(g.catalog['notes']);g.catalog['notes']['inputSchema']['properties']['tenant']['maxLength']=5
assert g.discover('alice')['names']==[]
try:g.call('notes__search',{'tenant':'A'},'alice')
except PermissionError:pass
else:raise AssertionError('只改schema也必须阻断')
g.quarantine('notes');g.rollback('notes',original,'sha256:approved-fixture')
assert g.call('notes__search',{'tenant':'A'},'alice')['value']=='fixture-note'
g.registry['notes']='deprecated';before_failed=deepcopy((g.catalog,g.artifact,g.runtime))
try:g.rollback('notes',original,'sha256:approved-fixture')
except PermissionError:pass
else:raise AssertionError('旧已核摘要不能覆盖当前撤销状态')
assert (g.catalog,g.artifact,g.runtime)==before_failed
print('whole-descriptor pin/list/directcall/tenant/privatecache/凭证中介/隔离回退通过；effects',g.executions)
print('注册与artifact为可信人工fixture；哈希不识别恶意语义，不是实际gateway或Registry发布')
```

本例人工artifact标签与目录摘要是受控输入，不能当已核容器/包签名。规范Registry是索引，具体组织还需自己的准入表：namespace归属、publisher/provenance、固定artifact摘要、当前descriptor、政策版本、批准主体/日期、状态与撤销信息。运行侧另外记录健康、依赖故障、限流和可用性；active不意味着可达或效果正确。

### 2.1 同版本漂移、隔离与回退怎样记录

批准的是一组不可变事实，不只是`server v1.2`。例如允许版本v1.2/artifact A/descriptor D/policy P；如果服务仍报v1.2却换schema，先quarantine并保漂移证据。回退要恢复已审artifact/路由/策略，再核当前撤权与兼容，不能因为旧版本曾经通过就重新放行。记录旧新digest、发现时间、decision reason、实际route和恢复证据。

2026-10-08核对固定Registry API/OpenAPI与一条公开记录：当前wire的官方状态在 `_meta["io.modelcontextprotocol.registry/official"].status`，旧requirements片段仍有direct `status` 示例。以固定API契约和实际响应核字段，不能把两个结构混读；标准发布状态与本地active/quarantined/approved治理状态分开。[固定generic API](https://github.com/modelcontextprotocol/registry/blob/9cbf0b3e4c4b088fe580bcfdee9e58f8947d4384/docs/reference/api/generic-registry-api.md)、[固定OpenAPI](https://github.com/modelcontextprotocol/registry/blob/9cbf0b3e4c4b088fe580bcfdee9e58f8947d4384/docs/reference/api/openapi.yaml)。


### 2.2 发布namespace、双审与版本级回退的独立例

公共工具名的路由碰撞和Registry发布namespace不是一条检查。`com.exampleevil/inventory`不能因前缀像`com.example`就通过；取`/`前的完整namespace，与独立可信认证结果精确比较。下面再按不可变(name,version,package digest,toolset digest)保存每个pin的当前状态；1.1撤销不自动撤销仍active且已准入的1.0。quarantined pin必须先完成恢复/重新审查，不能直接当旧version可回退。

对destructiveHint工具要求两位不同审核人，是原30课例的组织准入政策，不是MCP强制所有工具双审。每条signed evidence reference绑定精确record/package/toolset摘要，0/1/重复身份拒绝，只有两位独立可信身份才能满足该策略；失败attempt也留记录。HMAC keys/认证namespace在此是受控fixture，未进行真实审查采集或发布签名验证。

```python
import hashlib,hmac,json
from copy import deepcopy

def canonical(v):return json.dumps(v,sort_keys=True,separators=(',',':'),allow_nan=False).encode()
def sha(v):return hashlib.sha256(canonical(v)).hexdigest()
def namespace_matches(name,verified):
    if type(name)is not str or type(verified)is not str or not verified:return False
    pieces=name.split('/')
    return len(pieces)==2 and bool(pieces[1]) and pieces[0]==verified

KEYS={'reviewer-a':b'FIXTURE_KEY_A','reviewer-b':b'FIXTURE_KEY_B'}
class Admission:
    def __init__(self):self.pins={};self.route=None;self.ledger=[]
    def bindings(self,record,package,tools):
        return {'record_digest':sha(record),'package_digest':sha(package),'toolset_digest':sha(tools)}
    def review(self,reviewer,bindings,ref):
        body={'reviewer':reviewer,'bindings':deepcopy(bindings),'evidence_ref':ref}
        return {**body,'signature':hmac.new(KEYS[reviewer],canonical(body),hashlib.sha256).hexdigest()}
    def admit(self,record,package,tools,verified_namespace,reviews):
        bound=self.bindings(record,package,tools);reason=None;reviewers=set()
        if not namespace_matches(record['name'],verified_namespace):reason='namespace_mismatch'
        for r in reviews:
            body={k:r[k]for k in ('reviewer','bindings','evidence_ref')}
            key=KEYS.get(body['reviewer'])
            valid=(key is not None and body['bindings']==bound and type(body['evidence_ref'])is str
                   and bool(body['evidence_ref']) and hmac.compare_digest(
                   hmac.new(key,canonical(body),hashlib.sha256).hexdigest(),r['signature']))
            if not valid:reason='review_binding_or_signature_invalid'
            else:reviewers.add(body['reviewer'])
        needed=2 if any(t['annotations'].get('destructiveHint')is True for t in tools)else 1
        if len(reviewers)<needed:reason=reason or 'approval_incomplete'
        pin=(record['name'],record['version'],bound['package_digest'],bound['toolset_digest'])
        existing=self.pins.get(pin)
        if existing and (not existing['admitted']or existing['status']!='active'or
                         existing['quarantined']or not existing['healthy']or
                         existing['live_toolset_digest']!=bound['toolset_digest']):
            reason=reason or 'existing_pin_currently_ineligible'
        attempt={'name':record['name'],'version':record['version'],**bound,
                 'reviewers':sorted(reviewers),'decision':'deny'if reason else 'allow','reason':reason}
        self.ledger.append(attempt) # 拒绝/不完整也留attempt；无签名/凭据/私有参数。
        if reason:return False
        if existing is None: # 初次active/healthy来自本例可信人工fixture；真实系统需独立实时证据。
            self.pins[pin]={'admitted':True,'status':'active','quarantined':False,'healthy':True,
                            'live_toolset_digest':bound['toolset_digest']}
        self.route=pin;return pin
    def restore(self,pin):
        state=self.pins.get(pin)
        if (not state or not state['admitted']or state['status']!='active'or
            state['quarantined']or not state['healthy']or state['live_toolset_digest']!=pin[3]):
            raise PermissionError('目标pin当前不可恢复，不修改route')
        self.route=pin;return pin

assert namespace_matches('com.example/inventory','com.example')
assert not namespace_matches('com.exampleevil/inventory','com.example')
tools=[{'name':'delete_note','inputSchema':{'type':'object'},'annotations':{'destructiveHint':True}}]
record={'name':'com.example/inventory','version':'1.0.0'};package={'artifact':'fixture-A'}
a=Admission();bound=a.bindings(record,package,tools)
r1=a.review('reviewer-a',bound,'review://a');r2=a.review('reviewer-b',bound,'review://b')
for reviews in [[],[r1],[r1,deepcopy(r1)]]:
    assert a.admit(record,package,tools,'com.example',reviews)is False
p1=a.admit(record,package,tools,'com.example',[r1,r2]);assert p1 and len(a.ledger)==4
wrong=deepcopy(r2);wrong['bindings']['package_digest']='wrong'
assert a.admit(record,package,tools,'com.example',[r1,wrong])is False
bad_record={**record,'name':'com.exampleevil/inventory'}
bad_bound=a.bindings(bad_record,package,tools)
assert a.admit(bad_record,package,tools,'com.example',
               [a.review('reviewer-a',bad_bound,'review://a'),a.review('reviewer-b',bad_bound,'review://b')])is False
record2={**record,'version':'1.1.0'};package2={'artifact':'fixture-B'};b2=a.bindings(record2,package2,tools)
p2=a.admit(record2,package2,tools,'com.example',[a.review('reviewer-a',b2,'review://a'),a.review('reviewer-b',b2,'review://b')])
a.pins[p2]['status']='deprecated';before=a.route
try:a.restore(p2)
except PermissionError:pass
else:raise AssertionError('1.1已撤销拒绝')
assert a.route==before and a.restore(p1)==p1 # 仍active且已准入1.0可恢复。
before_replay=deepcopy((a.pins,a.route))
assert a.admit(record2,package2,tools,'com.example',
               [a.review('reviewer-a',b2,'review://a'),a.review('reviewer-b',b2,'review://b')])is False
assert (a.pins,a.route)==before_replay # 即使签名仍有效，也不能覆盖当前撤销状态。
for key,value in [('quarantined',True),('healthy',False),('live_toolset_digest','drift')]:
    original=a.pins[p1][key];a.pins[p1][key]=value
    before_replay=deepcopy((a.pins,a.route))
    assert a.admit(record,package,tools,'com.example',[r1,r2])is False
    assert (a.pins,a.route)==before_replay
    try:a.restore(p1)
    except PermissionError:pass
    else:raise AssertionError('当前状态/live/health不允许')
    a.pins[p1][key]=original
assert all('signature'not in item for item in a.ledger)
print('发布namespace前缀欺骗拒绝；0/1/duplicate/2独立reviewers和精确digest绑定通过')
print('1.1deprecated拒绝、1.0active可回退；quarantine/live/health阻断；保留attempt',len(a.ledger))
print('私有HMAC与artifact全fixture；非生产JWS/独立人工采集/不可篡改ledger或真实Registry')
```

局部ledger可被整链重写，真实审计需独立信任域的签名/只写存储/外部anchor；本例内存list不提供不可篡改证明。初次active/healthy与后续artifact/live/status检查都是可信人工fixture。旧review重提不能重置已存在pin的撤销、隔离、健康或漂移状态；真实恢复需单独采集当前Registry/运行证据并作新的治理决定，本例不实现该管理入口。

### 2.3 从发布记录到实际路由还需补哪些证据

准入至少串起七类检查。先精确核namespace，再把发布记录与独立采集的publisher/provenance、不可变包或remote地址及artifact digest关联；第三步固定record/artifact/toolset/policy，不用`latest`或可变范围代替。第四步按当前wire验证协议与能力、比较live descriptor和批准pin；第五步读取当前Registry版本状态；第六步核健康、隔离及回退目标；最后把允许和拒绝都写入可追溯ledger。发布记录自己写“verified”、内部同时提供payload与expected hash，不能成为外部证明。若工具需要Tasks而backend不支持，gateway不能仅靠外层声明让它兼容。

Gateway发现需分别呈现外层能中介的能力，并核每个backend的版本/能力。MRTR往返既绑定外层调用，也绑定实际backend与操作；Tasks用受控handle表保存taskId、owner、backend与版本映射，避免任意taskId变成路由或跨租户授权。订阅要真正持续处理变化、取消、背压和重连后的重新发现，不能把一个`events`数组当已运行长时SSE。这些wire与状态实现统一在通信06。

限流以可信principal/tenant、动作和资源计费，不能以连接或新request ID重置。比如令牌桶容量10、补充2次/秒，连续耗尽后0.5秒恢复1次资格；滑动窗口则看最早计数何时移出窗口，两者突发行为不同。多worker需共享原子扣减；额外限制单个backend的并发和失败重试预算，防一个慢backend拖垮外层。这里没有运行分布式限流。

审计最少关联外层request ID、backend新ID、trace/span、已验证principal/tenant、公开名与精确pin、参数摘要、policy版本、决策原因、attempt和效果receipt。格式校验失败、能力缺失、授权拒绝、限流、超时及效果未知应分别记，敏感token/私有参数不写日志。路由和真实传播的实践入口为[评估与监控](../01-核心章节/19-评估和监控.md)及[路由](../01-核心章节/02-路由.md)。

## 3. HTTP授权的角色与完整数据链

MCP 2026-07-28的HTTP授权profile基于OAuth 2.1 **IETF draft**和列出的RFC，不把draft写成已发布的OAuth2.1 RFC。支持该profile时，MCP server是resource server，MCP client是OAuth client，authorization server负责登录/同意与发token。用户/resource owner与这三个软件角色也不同。stdio通常从环境/启动配置取得凭证，不直接套HTTP OAuth流程。[授权规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)。

完整链为：明确目标resource→获得并验证protected-resource metadata→选择可信issuer并验证AS metadata→按该issuer取得client ID→保存PKCE/回调绑定→得到code→验证issuer和完整请求状态→用code/verifier/resource交换token→server验token与对象权限。每步的元数据、凭证、token和policy都有自己的信任来源。

| 字段或对象 | 它回答的问题 | 不能代替什么 |
|---|---|---|
| resource URI / token aud | token为哪个资源签发 | issuer、业务对象ACL |
| issuer | 哪个授权服务器签发/处理 | 该issuer下每个client都可信 |
| client ID | 此issuer认出的应用身份 | 用户身份或用户同意 |
| PKCE challenge/verifier | code兑换方与发起记录绑定 | 登录用户、完整对象授权 |
| access token scope | 签发的操作权限范围 | 当前撤权、tenant/具体对象、真实结果 |
| descriptor/client capability | 什么格式/功能可用 | 凭证与用户许可 |

### 3.1 Discovery顺序与注册方法

优先使用401 challenge提供的protected-resource metadata URL；缺该指引时再按规范的well-known路径策略发现，必要时由路径特定位置退回根位置。认证服务器使用RFC8414或OIDC discovery，带路径issuer的URL构造方式不同，不能随意去掉tenant path。metadata中的issuer应与所选issuer严格匹配；重定向、SSRF、DNS/IP范围和跨issuer缓存都需独立防护，schema正确不解决这些网络问题。

已为当前issuer配置client ID时使用该配置；否则按支持与政策选择CIMD，再把DCR作为兼容选择。CIMD的client ID是可读取元数据文档的URL，可以跨issuer复用标识，但每个issuer仍独立验证/登记。原issuer签发的client ID、secret、token不能自动带到新issuer；CIMD文档也不是自授权限。[注册规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/client-registration)。

DCR在该MCP profile被deprecated以保兼容，不意味着RFC7591本身消失。web/native类型、精确redirect URI、认证方法、申请scope、software statement等要按具体AS支持验证；未支持的enrollment或验证失败不应静默换到较弱方式。

例如资源`https://notes.example.com/mcp`按RFC9728构造的路径特定入口是`https://notes.example.com/.well-known/oauth-protected-resource/mcp`；不能把`/mcp`悄悄丢掉，再把另一个资源的metadata当同一份。返回403/`insufficient_scope`要求`notes:delete`时，客户端先向用户说明新权限与目的，取得同意，再通过AS取得该resource的新token，以新request ID重试；本地改scope字符串不会产生授权。

### 3.2 Code、PKCE、issuer与resource必须共同绑定

PKCE S256为 `base64url(SHA256(verifier))`，不带padding；生产verifier要有足够随机性并保密。交换code时核client/redirect/resource/owner/verifier/expiry，成功后消费一次；检查失败不能先烧掉code。进程内dict的`used=True`不提供多worker原子性，真实实现需独立事务/条件更新与幂等策略。

回调`iss`比较以**发起前已验证metadata的issuer**为准。返回有iss就精确字符串比，无iss则取决AS是否声明支持；不要自行lowercase、删默认端口/尾斜线或做百分号规范化，再把不同issuer当相同。

| AS声明iss支持 | 回调iss | 处理 |
|---|---|---|
| true | present | 与原记录issuer精确比；不匹配拒绝 |
| true | absent | 拒绝 |
| false或未声明 | present | 仍与原issuer精确比 |
| false或未声明 | absent | 按该版本继续，仍需要其余请求/回调检查 |

这个检查不免除state/浏览器回调、PKCE、client与resource绑定，尤其不能从未经验证的metadata取得expected issuer再宣称防mix-up。下面只验证本地数据链，不实现网络discovery、浏览器同意、URI类型检测或OAuth端点。

## 4. Token验证与新鲜度是运行时合同

server在处理请求前核token：可信issuer、明确allowed algorithm、kid/key选择、签名、aud、exp/nbf类型和边界、scope，然后当前policy/对象。`clientInfo.name`与JWT decode后未验签的sub不能用于授权；alg=none或token提出任意远端key URL也不能变成验证配置。

JWT与opaque token走不同验证路径。JWT要用成熟JOSE库核签名与claims；JWKS的公钥刷新按issuer隔离。opaque要向可信AS introspection或其确定机制查active/expiry/audience/scope，不能凭字符串样子猜JWT。签名有效而目标aud错误、scope不足、当前ACL撤权同样拒绝；无效/过期token通常401，权限不足的scope challenge等按profile处理。

生产JWKS刷新至少明确：已知kid/可接受key-age；未知kid触发受控refetch而不是rotate-and-mint；同issuer single-flight/cooldown防刷新洪水；key退休以签发token寿命与overlap为依据；依赖失败时unknown kid拒绝，是否允许已知key短期stale应事先声明并限时。不是“永远只保存两把key”或“每个未知kid都新签token”。

以下真实计算HS256三段签名并校验有限claims，但仅是**私有fixture子集**；不会处理所有JOSE扩展或真实公开JWKS。密钥是演示常量，不能公开作为生产共享密钥。opaque段只模拟单cache的5秒撤销新鲜度，不模拟真实AS、跨副本传播或scope/audience验证全实现。

## 5. 把批准状态、运行隔离与效果验证接起来

MRTR state要绑定原方法、完整规范化参数、principal、tenant、policy version、目的、过期与nonce。signature证明来自谁并没有首次授权决策；workspace全局allowlist也不是每个principal有该workspace。原15/12例的这条差别应保留。重试换新request ID，但不能用新ID覆盖业务幂等或nonce消费。

SQLite条件claim、批准确认、崩溃、未知effect后的reconciliation，由通信06的唯一工程例维护；不再造另一套“memory lock就是durable exactly-once”。授权成功、请求取消、deadline过期、handler已经commit和业务rollback是不同事件。客户端断开不等服务端effect未发生；应该查可信业务receipt和当前状态，不能盲重试支付/导出。

Sandbox是权限与资源的运行隔离，source声明`network:false`或prompt写readonly不等操作系统已执行限制。认证/授权/隔离/验证各自有证据；有模型能力或安装成功不是四层都通过。按用途限制文件/网络/secret/CPU/内存，运行后比预期结果与实际effects；真实Docker/VM/宿主配置检查是独立实验，本篇没有运行。

## 6. 原五课23项练习与发布lab判据

### 6.1 可信元数据与原15六题

1. **主体绑定**：先从可信验证得到principal，不能相信请求metadata里的名字；state封存与重试同时比较身份/对象/policy/参数，Bob拿Alice state应拒绝。state签名不替代首次权限。
2. **持久nonce**：用通信06的条件insert/事务，让两个连接竞争同nonce，检查最多一个claim与独立已核effect；真实跨进程/数据库和崩溃条件分别验证，不把dict当两进程。
3. **claim后崩溃**：定义同数据库事务或业务幂等receipt，重启查state/effect后恢复；未知effect保持unknown，不自动再次export。
4. **只改schema**：第2节程序完整descriptor摘要变化，list和direct call都拒绝；仅description hash不通过。
5. **目录权限cache**：按principal/tenant输出不同时返回private并绑定同授权上下文；缓存不免当前权限。
6. **legacy adapter**：旧2025-11-25 initialization/session放单独版本分支，不污染现代逐请求对象；fallback协议允许范围与应用白名单分开，实际wire见通信06。

### 6.2 原16五题

1. **refresh轮换**：第3节新refresh取代旧，旧值复用拒绝；真实多worker家族追踪/撤销/持久事务未实现。
2. **更换issuer**：可信allowlist之后，至多复用可移植CIMD URL；不发送旧issuer minted secret/client/token，例中A/B enrollment独立。
3. **code expiry**：t等expiry即拒绝；失败PKCE/资源/主体检查不consume。时钟和偏差政策另定，不接受bool伪NumericDate。
4. **web/native DCR**：对本AS政策，web用注册的HTTPS callback，native可用精确loopback回调；比较client type、redirect、token endpoint auth和software statement。native可支持其它标准redirect路线，不能把本课loopback加严说成所有OAuth MUST；本程序未实现URI分类或真实DCR。
5. **同issuer第二resource**：aud/resource分别绑定，在第一资源核对不能接受第二资源的token；单issuer不代表共享任意访问权。

### 6.3 原17五题

1. **trace correlation**：外层trace和后端新span有一致trace ID与正确parent，把request ID/attempt和trace区分；注入/提取与实际export分开，主入口为评估19。
2. **Tasks路由**：用受控task handle映射后端与owner/版本，不仅按字符串前缀推测；Mcp-Name头镜像/parity与task能力在wire真实来源中验证，业务store见通信06。
3. **backend漂移**：第2节仅改inputSchema，既不露出也不执行；每次direct call都核pin/状态。
4. **principal capability**：若server能力/工具表受授权影响，发现结果private并在上下文内缓存；compatible feature不直接授权。
5. **legacy interface**：协议时代、生命周期、传输和credential各单独适配，现代类不保存legacy初始化缓存；调用方知道切换及其失败，不能悄悄downgrade。

### 6.4 原18七题

1. **IdP轮换**：区分AS发布key轮换与resource server refetch；固定keyset/token expiry窗口，比old/new token结果与刷新日志。没有运行原main，不假称已观察真实IdP。
2. **新可信IdP**：先验证并加入政策支持issuer，再按issuer独立key/cache/enrollment；未列issuer拒绝。程序签名检查是HS子集，不是公开JWKS协议示范。
3. **注册限流**：在登记前按来源/issuer/风险及预算限速，fake IP dict不能证明真实攻击来源；多worker共享计数与反向代理信任链另验。失败登记不要先产生凭证。
4. **DCR字段**：核redirect type/URI/精确登记及software statement签名、issuer与claims支持；未处理statement不是一律拒绝所有客户端，应按AS支持/策略。原RFC全文未复现，本节按规定profile/真实库核验条件给判据。
5. **第二AS**：程序enrollment以issuer为key，相同URL标识与AS签发的client/secret/token区别明确，错issuer exchange拒绝。
6. **unknown kid DoS**：refetch已有发布集，不rotate-and-mint；测相同issuer多miss单次受控refresh、唯一kid洪水cooldown、固定keycount及unknown失败。第4节代码故意unknown直接拒绝，无网络refresh，并不声称已测分布式single-flight。
7. **deprecated DCR**：保兼容位置，对web/native分别测本AS登记政策；不混CIMD默认路径。真实OAuth/browsers/端点和installer都未执行。

### 6.5 原30的交互与发布lab

- **namespace Lab A**：发布名在`/`前的namespace与外部可信认证结果精确比较；`com.exampleevil/inventory`不得通过`com.example`。第2.2节已测此反例；公共工具名碰撞是第2节另一检查，不能替代它。
- **descriptor drift**：第2节schema微改被阻断；如果同version artifact改变，仍需artifact digest/publisher/政策审查，不按version放行。
- **status与rollback Lab C**：检查目标(name/version/artifact/toolset pin)的当前状态；已deprecated的1.1不能恢复，仍active且已准入的1.0可恢复。目标quarantined/不healthy/live drift也拒绝；同pin恢复要重新审查，不与选择旧eligible pin混称。第2.2节给实测对照。
- **admission ledger**：保存candidate实际名称、version、artifact/descriptor摘要、provenance/policy与decision及理由。内存append list不是不可篡改审计；可信记录/签名/外部时间与storage有独立要求。
- **双审Practice Lab**：destructiveHint工具以两位不同可信审核人及signed refs绑定精确三digest；覆盖0/1/重复/2人、错package digest与不完整attempt ledger。不得用预填passed、复制同身份或包内expecteddigest自证；第2.2节程序对应这些反例。
- **发布验收**：独立运行证据与可追溯artifact/route/policy关联，查询目录、实际host载入、权限效果、trace、回退分别记录。source预填passed/fingerprint不等真实采集，未运行真实Registry发布或私有gateway。
