# 共识与协商机制

多 Agent 的角色分工见[多智能体协作](../01-核心章节/07-多智能体协作.md)，远端消息和任务见[A2A](../01-核心章节/15-智能体间通信-A2A.md)。本专题关注另一个问题：成员意见怎样聚合，何时足够一致，什么证据支持接纳，以及报价和任务授标怎样遵守约束。先修是集合交集、概率与误差、图、状态机和基本成本/效用。读者不需要先部署区块链或真实模型。

## 一致、有效、正确和完成是四个判断

五个成员投票选了 42%，只能说明意见一致，原资料仍可能是 4.2%。协议的 **agreement** 要求诚实成员对相同内容作一致决定；**validity** 约束可接纳内容来自哪个集合、满足哪些合法条件；**liveness** 要求协议在条件满足时最终继续或结束。事实正确性还要查来源或执行验证，业务成功还要确认需求和效果回执。

因此一个日志共识系统可以一致保存错误报告，一个语言投票可以选出真实数值却未形成可恢复的协议，一个任务可以被授标却仍未完成。把前者的成功率当后者指标，会让“BFT”“多数票”和“成交率”具有它们没有的保证。

### PBFT 的法定人数为什么是这种形状

Practical Byzantine Fault Tolerance 是确定性状态机复制协议，处理请求排序、状态与回复，不是“给若干模型答案取多数”。设最多 $f$ 个副本任意作恶，下面的推导**固定 $n=3f+1$** 个副本，每个确认集合有 $2f+1$ 份有效确认。两个这样的集合交集至少为

$$|Q_1\cap Q_2|\geq(2f+1)+(2f+1)-(3f+1)=f+1.$$

至多 $f$ 个作恶，交集至少包含一个诚实副本，再配阶段、序号、消息摘要和不签冲突内容的协议规则，才能保护不相容决定不会同时被诚实副本接纳。例如 $f=1,n=4$ 时三票集合相交至少两人，其中至少一人诚实。只收两票则可能让 `{A,B}`、`C,D` 分别接纳冲突值；若扩充到 $n>3f+1$，不能仍沿用 $2f+1$：法定人数 $q$ 须满足 $2q-n>f$，例如在 $n\geq3f+1$ 条件下选择 $q=n-f$。成员变动另需固定 epoch 与交接合同；改变权重也必须重新证明交集，不能沿用原人数结论。

[Castro 与 Liskov 原文 §2–§3](https://pdos.csail.mit.edu/6.824/papers/castro-practicalbft.pdf) 提到独立节点失效，并建议多实现、多管理员减少共同故障；同节允许强攻击者协调坏节点，§3 也允许坏客户与坏副本串通。源课程把 independent faults 解释成“Byzantine 节点不会串通”是错误的。安全不依赖已知网络时限，活性另需通信最终及时等条件；密码学防伪和有效成员身份也属于前提。复制服务接纳请求后仍可能保存客户的垃圾数据，访问控制与业务合法性不能由共识自动补齐。

## 语言答案投票怎样定义而不借用协议保证

多数票先定义答案等价：数字、单位、时段、对象、肯定/否定、允许误差均是 schema 的一部分。删空格/标点或 embedding 相近不证明等价，`4.2%`、`42%` 或“没有改善”必须分开。先保存独立候选，再按合同归组；无法确定等价时保留多个主张。

成员身份与候选 ID 要固定，一位成员重复提交不能增加票数。弃权与未响应单独记录，不作为“I don't know”答案簇；分母用全部 eligible 成员还是有效票必须预先约定，并设置最低参与覆盖率。否则只有一个作恶者响应，也会变成“100% 共识”。平票、全弃权、无充分票数都明确返回 held/escalated，不以列表先见次序暗中选一个。

给第 $i$ 位成员权重 $w_i\geq0$，某答案簇 $C$ 的权重 $W_C=\sum_{i\in C}w_i$。用 $W_C/\sum_iw_i>\tau$ 作为一种**自定义聚合规则**时，严格大于和大于等于必须一致，参与覆盖门与权重门也分开。自报置信度不是校准概率，恶意者可自报 1，错误模型也可能高度自信。需要留出题检查校准、错误相关性、高置信错和错误共识，不能只看 agreement 上升。

同模型多次采样可能覆盖不同推导，错误也可能相关；换模型、来源、工具或角色可能增加差异，也增加新盲点。异构并不保证统计独立或一定更好。固定输入、留出题与同一预算，比初始单答、self-consistency、有限辩论、外部工具核验；已有同步快照、错误共识和精确边计数例直接见[多智能体协作](../01-核心章节/07-多智能体协作.md)，本专题不再重建一套。

### 三项研究方案的实际机制与前提

几何中位数在 $d$ 维中是最小化 $\sum_j\|z-x_j\|_2$ 的点。二维评分向量中的中位位置与“哪个文本出现次数最多”不同；一维退化为普通中位数。鲁棒统计控制异常评分影响，并不识别事实真值；DecentLLMs 的原文也展示评分可靠性限制。课程 `decentllms()` 实际按同文本簇的自报置信度离散程度打分，不能当 GM 或原论文实现。

### 一个拒绝平票、保留误判的完整离线例

下例使用整数答案与有固定名单的虚拟投票者，精确分数防阈值舍入。它刻意得到一个**高置信错误共识**并由独立 gold 检出，再演示确定报价只能依据自己的预算形成，数字仍要经独立约束门。本例整数题的 gold=4 是独立合成题，不把4当成原论文的4.2%。该程序不是 PBFT/CP-WBFT/DecentLLMs、真实训练或谈判效果复现。

```python
from decimal import Decimal
from fractions import Fraction

def weight(text):
    if type(text) is not str:
        raise ValueError('权重使用十进制文本')
    try:
        d = Decimal(text)
    except Exception as exc:
        raise ValueError('权重格式无效') from exc
    if not d.is_finite() or not 0 <= d <= 1:
        raise ValueError('权重必须有限且在0到1之间')
    return Fraction(d)

def aggregate(roster, votes, threshold=Fraction(1, 2)):
    if (type(roster) not in (list, tuple) or not roster or
        any(type(r) is not str or not r for r in roster) or
        len(set(roster)) != len(roster)):
        raise ValueError('成员名单须为非空唯一字符串的list/tuple')
    if type(threshold) is not Fraction or not Fraction(1, 2) <= threshold < 1:
        raise ValueError('阈值必须为有效精确Fraction')
    seen, clusters = set(), {}
    active = 0
    for actor, answer, confidence in votes:
        if type(actor) is not str or actor not in roster or actor in seen:
            raise ValueError('未知或重复投票者')
        seen.add(actor)
        w = weight(confidence)
        if answer is None:
            if w != 0:
                raise ValueError('弃权不得附有效权重')
            continue
        if type(answer) is not int:
            raise ValueError('本例只接纳整数答案')
        active += 1
        clusters[answer] = clusters.get(answer, Fraction(0)) + w
    if active * 4 < len(roster) * 3 or not clusters:
        return None
    total = sum(clusters.values())
    if not total:
        return None
    top = max(clusters.values())
    winners = [a for a, w in clusters.items() if w == top]
    return winners[0] if len(winners) == 1 and top > threshold * total else None

def offer(budget_text, turn, max_turns):
    if type(turn) is not int or type(max_turns) is not int or not 0 <= turn <= max_turns or max_turns < 1:
        raise ValueError('报价轮次无效')
    if type(budget_text) is not str:
        raise ValueError('预算用十进制文本')
    budget = Decimal(budget_text)
    if not budget.is_finite() or budget <= 0:
        raise ValueError('预算无效')
    return budget * (Decimal('0.5') + Decimal('0.5') * Decimal(turn) / Decimal(max_turns))

roster = ('a','b','c','d','e')
wrong = [('a',42,'0.70'),('b',42,'0.68'),('c',42,'0.72'),
         ('d',4,'0.85'),('e',4,'0.82')]
assert aggregate(roster, wrong) == 42
assert aggregate(roster, wrong) != 4  # 外部已知答案，本例必须承认误判
assert aggregate(('a','b'), [('a',4,'1'),('b',42,'1')]) is None
assert aggregate(roster, [('a',42,'1')]) is None
assert aggregate(('a','b'), [('a',None,'0'),('b',None,'0')]) is None
for config, threshold in [('ab', Fraction(1,2)), ([True], Fraction(1,2)),
                          ([''], Fraction(1,2)), (roster, .75), (roster, True),
                          (roster, Fraction(1,4)), (roster, Fraction(1,1))]:
    try:
        aggregate(config, [], threshold)
        raise AssertionError('非法名单或阈值应拒绝')
    except ValueError:
        pass
for invalid in [[('a',4,'1'),('a',4,'1')], [('x',4,'1')],
                [('a',True,'1')], [('a',4,'NaN')], [('a',None,'0.3')], [('a',4,'bad')]]:
    try:
        aggregate(roster, invalid)
        raise AssertionError('无效投票应拒绝')
    except ValueError:
        pass
assert offer('100', 0, 4) == Decimal('50')
assert offer('100', 2, 4) == Decimal('75')
assert offer('100', 4, 4) == Decimal('100')
for args in [('NaN',1,4), ('100',True,4), ('100',5,4), ('100',0,0)]:
    try:
        offer(*args)
        raise AssertionError('无效预算或轮次应拒绝')
    except ValueError:
        pass
print('错误共识42被外部答案否定；平票/低覆盖/全弃权拒绝；预算报价50/75/100核对通过')
```

本例的 75% 最低参与率和严格过半权重是教学选择，不是通用最优阈值。0 权重但有答案的成员计入响应覆盖，体现“回复了”和“信任它”是两层口径；业务也可要求最低有效权重成员数，但须明确合同。名册和 actor 假定已由外部身份边界确认，不能依模型填写的名字当认证；报价的格式、金额单位/精度、最终私有保留价检查和授权提交仍需业务层处理。

## 拓扑实验不能只换连线再写成功率

[Self-consistency v4](https://arxiv.org/abs/2203.11171v4) 对同模型采样多条推导、聚合最终答案，是必要基线；[Should we be going MAD? v3](https://arxiv.org/abs/2311.17371v3) 比较准确、时间和成本，说明辩论不稳定优于 self-consistency，调整协议参数可改变结果，不能简单断言所有辩论总有优势或总无用。

[MultiAgentBench v1 §4.3](https://arxiv.org/abs/2503.01935v1) 在 Research 场景比较 star/tree/graph/chain，graph 整体表现好，star 与 graph 的任务分数相近，tree 较差。摘要的 3% 提升是认知演进规划策略，不应转写成“graph 比第二拓扑高 3%”。该实验没有证明所有任务必须 graph、star 不适合研究、四个成员是普适拐点或三个模型必胜五个副本。学习重点是 TS（任务）与 CS（协作）分开、任务设置和预算一致，具体选择依实证。

课程第 15 课脚本只采 Bernoulli 正误和预定 wrong bias：star 不调用 hub 推理却收 hub 的 400 Token；tree 将两组结论平票时总选左组；graph 以固定 0.4 概率复制多数，没有研究环境、工具、理由、真实 Token 或延迟。它为 N=7、两轮计 5600，而 star N=3 计 1200，比值约 4.67，并非输出宣称的约 7 倍。`steps` 是假设次数，不能当 wall-clock，也不能用于复现 MARBLE 或 AgentVerse 行为。

[Can AI Agents Agree? v2 §3–§4](https://arxiv.org/abs/2603.01213v2) 则是无奖励的标量共识游戏：Qwen3-8B/14B、同步全连接、初始诚实值范围 `[0,50]`，至少 2/3 成员投 stop，且诚实成员最终同值、来自初始诚实提议才算 valid。恶意模型不能伪造身份、发送不同副本消息或丢消息，主要失败是超时/活性；不是源文所谓“多前沿模型的 Mixture-of-Agents 被拉偏 40 个百分点”。研究经验与可证明协议假设必须分别学习。

## 报价：把数字机制和语言表达分开

两方买卖中买方最大愿付 $B$，卖方最低愿收 $S$，可成交区间 ZOPA 为 $[S,B]$，当 $S>B$ 时为空。现实中双方通常只知道自己的保留价和 BATNA（未成交时的替代方案），不能像源脚本一样读取双方私值。区间外的初次报价不一定违反规则，也不一定应拒收；最终接纳必须满足自身预算、数量/币种与保留条件，不通过要求知道对手秘密来实现验证。

[OG-Narrator v3 §6.1、Table4](https://arxiv.org/abs/2402.15813v3) 把 Action 和 Talk 分开：规则先形成报价，LLM 根据报价与历史写说明。原规则是预算从 0.5 到 1 的线性递增，$p_t=(0.5+0.5t/t_{\max})B$；$t$ 的起点和最大轮数要固定，$B=100,t_{\max}=4$ 时 t=0/2/4 分别报价 50/75/100。它不是源文宣称的 Zeuthen 风险策略或 Rubinstein 均衡。示例从自己的预算生成数值，不需要知道对手保留价；对方报价低于当前可接受价时按规则接纳，也不自动保证最优收益。

有限轮数结束可回 BATNA 或找协调者，no-deal 有时是正确结果。应分别记录规则有效率、成交率、个体效用、联合剩余、违规率与僵局；更高成交率可能以亏损或私值泄漏换来。论文中的旧型号和 26.67%→88.88% 摘要数字只描述其特定基准，正文 Table4 按型号和 mutual/conflicting interest 分组，不能作为任意买方、任意商品或当前模型的预期收益。

语言层不修改结构金额：宿主保存规范 Action，要求 Talk 金额与之相符；无法确认、泄漏风险或对方改字段时暂缓。仅靠 regex 检出金额不保证秘密不会隐喻泄漏；私有状态首先不应给对手，日志/trace 与 narrator 上下文也按需要最小化。XML 的 `<private>` 名称本身不限制读取。

[NegotiationArena v1 §4](https://arxiv.org/abs/2402.05863v1) 的 persona 收益依具体对手、轮次和游戏设置，不能当普遍“装急迫可提升20%”操作建议。[180k 谈判比赛 v3](https://arxiv.org/abs/2503.06416v3) 使用特定 GPT-4o-mini 和参与者提示，warmth、僵局等同样影响结果；隐藏推理是在该系统消息解析/提示机制中的观察，不能说所有赢家凭标签获得真正私有通道，或把其中 prompt injection 当获准实践。

## Contract Net：先筛可行报价，再授标，再确认成果

Contract Net 是任务分配机制：manager 发 `cfp`（描述、约束、版本、响应期限）；候选 `propose` 或 `refuse`；选择者向赢家发 `accept-proposal`，向其他人发 `reject-proposal`。接纳后的执行、失败与完成报告仍需跟踪，授标不是交付回执。FIPA performative 是交互语义，不能仅打印这些词就声称线协议合规或可靠市场已经部署。

具体任务“30 分钟内处理获准的日志，预算 10 units”中，报价先检查成员身份、任务版本、价格与 ETA 的类型/单位/有限范围、期限、可用容量、数据访问权和执行 scope。再按预先定义的评价规则比较候选，例如经独立历史题核验的质量下限与成本；源 `confidence / price` 依自报值且对负价/非法 ETA 缺少检查，不能当真实最优分配。

简化伪代码是：

```text
发布不可变 task_id/version、授权 scope、预算/完成标准与 CFP 截止时间
只接收注册成员签名或已认证通道的当前版 bid
验证金额/ETA/能力/权限/有效期/容量，未知或不可行单独记录
在合格集合内按预先公布的 rubric 排序；无合格项则 no_award
原子绑定 task_version、winner、bid_digest、award_id 与资源保留
向 winner 发 accept、其余发 reject；同 award_id 重发返回原决定
执行期间续租/超时与完成报告分别处理；验收成果和目的端 receipt
```

租约或资源保留用于防同一工作者同时接超容量任务；若报价/任务变更需新版本重新判断，不能复用旧“批准”。低价、高质量、多赢家或反向拍卖的机制不同，不借一个 bidder 列表默认。任务市场与钱包/资源效果的提交边界沿用[资源感知优化](../01-核心章节/16-资源感知优化.md)和[工具授权与发布治理](07-工具授权与发布治理.md)。本段是有限合同设计，真实并发事务和跨系统授标未运行。

## 开放协作中的贡献、竞买与采购

先修是效用、概率和任务评测。多个代理共同产出时，需要区分谁贡献了多少、谁买资源、谁提供服务。闭合团队不一定需要代币或区块链；指标、验证与任务分配可以先独立建立。

### Shapley：相对空联盟的边际价值

固定参与者集合 $N$、价值函数 $v:2^N\to\mathbb R$。$v(S)$ 是在相同任务、资源和评价设置下，联盟 $S$ 能产生的价值。贡献为

$$
\phi_i=\sum_{S\subseteq N\setminus\{i\}}\frac{|S|!(n-|S|-1)!}{n!}\,[v(S\cup\{i\})-v(S)].
$$

等价地，枚举不同加入顺序，把每次加入的价值增量求平均。效率是 $\sum_i\phi_i=v(N)-v(\varnothing)$，空联盟基准不是零时必须扣掉。贡献可以负；评价函数操纵、联盟资源不同或重复身份都会改变归属，公理不保证现实公平或抗串谋。

排列法成本约 $n!$ 次顺序，子集公式约 $2^n$ 个联盟；价值函数昂贵时缓存与抽样更重要。抽样每条排列的总边际价值仍会相消，所以总和正确不证明每个人准确。比较各人误差与区间，固定评价器、环境、版本和随机性，不能只套“六人以上一律抽样”。

### 同样是第二价格，付款方向不同

竞买一个名额时，每人报价表示自己得到名额的价值，最高价者获得，向卖方付第二高价；服务采购时，每个供应者报价表示成本，最低价者中选，采购方向它支付第二低价。都要固定相同货币/积分单位、独立竞标者、平价规则和参与者身份。经典真实报价性质依赖私有价值、准线性效用、无串谋等；预算约束、收益外部性和质量不确定会改变问题。质量分最高不是经济报价最高，奖励和权限也不是同一件事。

[Google 的 token auction](https://research.google/blog/mechanism-design-for-large-language-models/) 则逐 token 聚合多个概率分布并计算付款。理论假设分布真实报告，并有偏好、单调聚合、稳定采样和额外条件；它不是选一个最高报价答案的三行函数。

下面完整标准库程序用教学积分，核空联盟基准与两种付款方向。值表只定义两个参与者，排列法刻意保持小规模；没有真实付款、钱包、DID 或市场接入。

```python
from decimal import Decimal
from itertools import permutations

def allocate(values, players):
    if (type(players) is not tuple or not players
            or len(set(players)) != len(players)
            or any(type(x) is not str or not x for x in players)):
        raise ValueError('参与者须唯一且非空')
    out = {p: Decimal(0) for p in players}
    count = 0
    for order in permutations(players):
        coalition = frozenset()
        for player in order:
            expanded = coalition | {player}
            old, new = values[coalition], values[expanded]
            if any(type(x) is not Decimal or not x.is_finite() for x in (old, new)):
                raise ValueError('联盟价值须为有限Decimal，允许负贡献')
            out[player] += new - old
            coalition = expanded
        count += 1
    return {p: score / count for p, score in out.items()}

def auction(bids, direction):
    # 所有值的单位均为同一笔教学积分；此函数没有真实付款。
    if direction not in {'purchase_slot', 'procure_service'} or len(bids) < 2:
        raise ValueError('方向须明确，至少两个独立报价')
    if any(type(p) is not str or not p for p in bids):
        raise ValueError('报价者ID非法')
    if any(type(v) is not Decimal or not v.is_finite() or v < 0 for v in bids.values()):
        raise ValueError('报价须为同单位非负有限数')
    ordered = sorted(bids, key=lambda p: ((-bids[p] if direction == 'purchase_slot' else bids[p]), p))
    winner, price = ordered[0], bids[ordered[1]]
    payer = winner if direction == 'purchase_slot' else '采购方'
    receiver = '名额卖方' if direction == 'purchase_slot' else winner
    return winner, price, payer, receiver

values = {frozenset(): Decimal(2), frozenset({'A'}): Decimal(5),
          frozenset({'B'}): Decimal(3), frozenset({'A', 'B'}): Decimal(8)}
shares = allocate(values, ('A', 'B'))
assert shares == {'A': Decimal(4), 'B': Decimal(2)}
assert sum(shares.values()) == values[frozenset({'A', 'B'})] - values[frozenset()]
bids = {'A': Decimal(42), 'B': Decimal(88), 'C': Decimal(61)}
slot = auction(bids, 'purchase_slot')
service = auction(bids, 'procure_service')
assert slot == ('B', Decimal(61), 'B', '名额卖方')
assert service == ('A', Decimal(61), '采购方', 'A')
try:
    auction({'A': Decimal('NaN'), 'B': Decimal(1)}, 'purchase_slot')
except ValueError:
    pass
else:
    raise AssertionError('非法报价未拒绝')
print('贡献分配', shares, '合计6，扣除了空联盟基准2')
print('竞买名额', slot, '；采购服务', service)
```

### 信誉需要验证、探索和身份边界

简单信誉可用 $R_{t+1}=\alpha R_t+(1-\alpha)q_t$，$0\le\alpha<1$，$q_t$ 是按固定标准核过的质量。保存任务种类、样本量、代码/评价版本和时间；没有被试过的代理不能默认满分，否则错误冷启动先验会主导路由。只用高信誉者会使其他人永远没有数据，需有合法探索与风险限额。衰减、最低分和处罚幅度都按任务决定，非固定常数。信誉路由表示经验偏好，不能授予原本没有的权限。

[DID Core](https://www.w3.org/TR/did-core/) 定义标识主体、控制者和证明控制的材料。持有多个 DID 不证明多个独立运营者，控制私钥也不证明诚实或输出质量；抗伪身份、身份转移、处罚与验收分别设计。源示例只是字符串 ID 与指数平均，没有 DID、显式处罚或链上验证。

[The Agent Economy v1](https://arxiv.org/abs/2602.14219v1) 提出物理基础设施、身份、认知工具、结算、治理的五层区块链参考架构，不是所有自主代理的必需组件，也不证明已经具有法律人格。[AAMAS 2025 p2896](https://www.ifaamas.org/Proceedings/aamas2025/pdfs/p2896.pdf) 是 Blue Sky Ideas 提案，图 3/4 将跨组织原数据访问与协调分开、增加交易日志，提到 Shapley 作为归属原则；不是现成十人算法或生产免操纵证明。本批不采用未核实网络的生产等级、资产价格、支付宣传和法律判断。

### 原课 21 的五项练习与参考判断

以下为中文重述与参考方法，未表示学习者已经完成原练习。

1. **怎样检查 Shapley 的效率性质及价值函数修改？** 先核空联盟基准。效率性质是贡献总和等于 v(N)−v(空集)，并非总是 v(N)。修改联盟值后核对效率、对称性和无贡献者，允许负贡献；评价函数可被操纵时，公理不能保证现实中的公平。

2. **四参与者下，怎样评价抽样贡献估计？** 固定四参与者全部联盟的价值表，用不同样本数与随机种子比较单人误差、最大绝对误差、区间与评价成本。每一条排列的边际贡献都会望远镜求和，所以总和准确不证明个体估计准确。

3. **允许组队竞标后，是否一定帕累托改进？** 先定义组队成本、可转移收益、组内分配、形成顺序以及重复身份与串谋条件。小规模穷举可比较稳定性和帕累托关系；Shapley 分配不保证位于核心，合并竞标也不保证每个人更好。

4. **Google token auction 的哪些假设不能随意去掉？** Google 的模型假设各代理真实报告 token 分布，并对分布偏好、单调聚合和稳定采样作条件限制。经典二价竞买还依赖私有价值、准线性效用等。任意改变分布、引入其他参与者收益的外部性或串谋，都不能只凭“第二高价”声称真实报价保证。

5. **十参与者能否按 AAMAS 原文直接复现 Shapley？** AAMAS 2025 的 p2896 是 Blue Sky Ideas 提案，提出跨组织隐私与贡献记录，提到 Shapley 原则，没有提供可直接复现的十人算法。可以独立建立十人合成价值函数，缓存 2^10 个联盟，再比较精确子集计算与抽样；实际用时须运行后记录，不能称论文实验。
