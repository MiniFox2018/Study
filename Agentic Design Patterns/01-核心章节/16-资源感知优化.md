## 来自《深入理解 AI Agent》的增量吸收

- 资源优化首先发生在上下文层：KV Cache/Prompt Cache 友好设计、上下文压缩和子 Agent 隔离都会直接影响成本与时延。
- 模型选择不能只看单次能力，应结合任务成功率、调用成本、执行时延和失败重试成本。
- 生产环境应记录 token、工具调用、模型调用和轨迹长度，把成本分析纳入评估体系。
- 优化目标不是单纯“更便宜”，而是在质量、可靠性、时延和成本之间取得可验证的权衡。

## 来自《动手学大模型应用开发》的增量吸收

- RAG 优化也要算**检索成本**：更大的 top-k、更长的 chunk、更多 Query 改写和多路检索都会增加延迟、Embedding/LLM 调用和最终上下文 Token。
- Query 改写、HyDE、Multi-Query、Step-Back 等增强策略应按失败类型选择，而不是每个请求都执行。
- Embedding 模型选择应把效果、向量维度、输入长度、部署资源、隐私和成本放在一起评估。
- 最有效的资源优化通常不是“统一降配”，而是保留直接检索的快速路径，只在基线不足时升级到更复杂的检索流程。
