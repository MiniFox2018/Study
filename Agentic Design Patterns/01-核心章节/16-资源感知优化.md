## 本章定位

在成本、时延、算力、令牌和任务质量之间进行动态权衡与资源调度。

## 先定义单位成功任务的代价

成本不仅是一次模型调用，还包括输入输出 Token、检索、工具、重试、存储、人工复核和等待时间。只有把成功标准固定，才可比较两个方案的资源效率。不能通过漏做步骤让系统看起来更便宜。

## 具体例子：快速路径与升级路径

方案 A 每次成本 1 个教学单位，成功率 80%；方案 B 成本 2，成功率 95%。若失败后无限独立重试且成功概率恒定，期望成本粗算为 `成本/成功概率`，分别 1.25 和约 2.11；但现实失败常相关、重试有上限，因此实际应按完整任务记录计算，不能照搬这个理想模型。

一种可测策略是：能用本地规则完成的请求走快速路径，缺证据时升级检索，复杂任务才增加模型/工具预算。用同一题集比较成功率、尾延迟和总成本，并单列升级后仍失败的请求。

缓存要区分单次生成的 KV 复用、跨请求相同前缀复用和业务结果缓存。业务缓存需要键、版本、权限隔离和失效条件；旧政策答案即使命中缓存也可能已经错误。

## 自检与核对

**问题**：每次调用便宜一半，但平均调用次数变成三倍，总成本是否更低？

**核对**：只算模型调用时反而是原来的 1.5 倍；还应检查成功率与时延。优化必须按完整任务计账。

## 缓存账本：写入溢价、首次复用与TTL

设可复用前缀P个token，基准输入单价b，写倍率w、读倍率r；初写一次后实际命中R次，前缀成本为Pb(w+Rr)，不用缓存为Pb(1+R)。严格更便宜需$R>(w-1)/(1-r)$。新后缀/输出、miss重复写、存储/检索与外部工具另计，不用单一hit rate乘总账单估节省。

题设w=1.25、r=.1时，初写+首次reuse为1.35基准单位，对照2，**一次复用就已节省**；不是必须两次。w=2、r=.1时一次为2.1而对照2，需两次复用才节省。1h写2×相对base是100%增价；5m写1.25×是25%增价，溢价部分1/.25=4倍，完整写价2/1.25=1.6倍。源quiz将“50%增价”和“两次reuse”写成答案均需纠正。

这些倍率在本程序只是固定假设。[Claude官方prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)于2026-10-07核对了5m/1h、命中刷新TTL和逐模型倍率差异；不把.1当所有当前型号价格。其TTL从写/读请求开始计，读刷新窗口；源simulator未刷新written_at会高估重复write。存储缓存须积算每个实际存活周期，不能只算最后仍在字典的entries。

```python
from fractions import Fraction as Q

def cost(request_times,ttl,w,r):
    if ttl<=0 or w<0 or not 0<=r<1 or request_times!=sorted(request_times):raise ValueError('有序时间/费用假设')
    deadline=None;writes=reads=0;total=Q(0)
    for now in request_times:
        if deadline is None or now>=deadline:writes+=1;total+=w
        else:reads+=1;total+=r
        deadline=now+ttl  # 本假设命中刷新；固定TTL缓存应采用不同规则。
    return dict(writes=writes,reads=reads,prefix_units=total)
assert Q(5,4)+Q(1,10)<2 and 2+Q(1,10)>2 and 2+2*Q(1,10)<3
assert (Q(2)-1)/(Q(5,4)-1)==4 and Q(2)/Q(5,4)==Q(8,5)
sliding=cost([0,250,500,750],300,Q(5,4),Q(1,10));assert sliding['writes']==1 and sliding['reads']==3
boundary=cost([0,300,600],300,Q(5,4),Q(1,10));assert boundary['writes']==3
print('5m首次reuse',Q(5,4)+Q(1,10),'对照2；1h两次reuse',2+2*Q(1,10),'对照3')
print('命中刷新TTL',sliding,'边界重新写',boundary)
# 假设输入1500token、$2.5/M；只演示单位，不是供应商报价。
per_call=Q(1500)*Q(5,2)/10**6
assert per_call*10**6==3750
print('题设百万请求输入费用',float(per_call*10**6),'不是3.75')
```

## 预算应先预留，再对实际尝试结算

Token bucket限制短时速率，其refill不代表每天/每月金额配额。告警只是观察，circuit breaker还需原子admission。按身份与明确账期维护spent、reserved和未结usage；并发先检查再分别consume有竞态。预留是估计上界，不是取消就退款：请求可能已被供应商处理，usage缺失时保pending，最终对每次尝试结算。超过预留的实际费用仍如实入账并阻止新任务，不能为保持“预算成功”删账。

```python
from decimal import Decimal as D
import threading

class Ledger:
    def __init__(self,limit):
        if type(limit) is bool:raise ValueError('bool不是金额')
        self.limit=D(limit);self.spent=D(0);self.pending={};self.done=set();self.lock=threading.Lock()
        if not self.limit.is_finite() or self.limit<=0:raise ValueError('预算')
    def reserve(self,call_id,maximum):
        if type(maximum) is bool:raise ValueError('bool不是金额')
        amount=D(maximum)
        if type(call_id) is not str or not call_id or not amount.is_finite() or amount<0:raise ValueError('调用身份/上界')
        with self.lock:
            if call_id in self.pending or call_id in self.done:raise ValueError('重复调用ID')
            if self.spent+sum(self.pending.values(),D(0))+amount>self.limit:return False
            self.pending[call_id]=amount;return True
    def settle(self,call_id,actual):
        if type(actual) is bool:raise ValueError('bool不是金额')
        actual=D(actual)
        if not actual.is_finite() or actual<0:raise ValueError('实际费用')
        with self.lock:
            if call_id not in self.pending:raise ValueError('未预留或重复结算')
            del self.pending[call_id];self.done.add(call_id);self.spent+=actual
ledger=Ledger('1.00');barrier=threading.Barrier(2);accepted=[]
def attempt(i):
    barrier.wait(timeout=5);accepted.append((i,ledger.reserve(str(i),'.60')))
threads=[threading.Thread(target=attempt,args=(i,)) for i in range(2)]
for t in threads:t.start()
for t in threads:t.join(timeout=5);assert not t.is_alive()
assert sum(ok for i,ok in accepted)==1
winner=next(str(i) for i,ok in accepted if ok);assert len(ledger.pending)==1
ledger.settle(winner,'.40');assert ledger.reserve('next','.60');ledger.settle('next','.70')
assert ledger.spent==D('1.10') and not ledger.reserve('over','.01')
print('并发只接受一个.60预留；实际超额如实记1.10并阻止后续，无真实费用')
```

这只验证同进程一个账期的admission，不含分布式账本、日/月切换、供应商硬上限或真实计费退款。上线还要用户/项目分别锁账、账期边界与时区、price revision、cached/write/ordinary/output字段、provider receipt和unknown保守规则。不得将本fixture金额当实际花费。

成本路由应比较同task切片的质量、失败、尾时延和完整总费用；无验证的“便宜模型”可能破坏JSON/隐私/证据要求。压缩保实体、否定、单位、出处，重试/额外judge/ANN存储也有成本。源固定50–95%收益、启动公司必因费用失败、短词路由普遍正确不予保留。状态存储与缓存不是免费的长期记忆：容量、失效、删除授权与长期数据留存分别管理。

## 多时间窗成本控制：账本总额与短时速度同时限制

预算不是事后报一个费用数字。外部控制层在 dispatch 前预留最大合理成本、原子检查可用额，再按每次实际尝试结算；pending/unknown 不能因超时自动退款。已有前文并发 Ledger 解释这些基础；这里补时间窗、恢复与计费口径。

| 限制 | 怎样计数 | 覆盖的风险 |
| --- | --- | --- |
| 单请求输出/token上界 | 输入、输出限制含义分开；不是总任务费用 | 单次生成异常大 |
| 同一业务 task 的金额/token | 所有重试、子任务、恢复、judge、工具计入 | 总任务拖长或频繁重启 |
| 每工具/迭代/墙钟上界 | 分清 model turn、tool call、并行操作与等待 | polling、失败重试和工具循环 |
| 近 W 秒支出 | 明确 `(now-W,now]` 边界，包含未完成预留 | 快速烧费，不能等月cap |
| 日/月额度与增长告警 | 固定账期/时区 vs滚动窗口分别定义 | 慢漏、发布回归与真实需求增长 |

窗口“10分钟累计最多50美元”与“已观察窗口平均速率5美元/分钟”只在完整固定窗口时可对应；warm-up 用实际 elapsed 会改变规则。不能用首个样本的累计金额去减全部，从而漏掉第一个调用。并发/在途预留也占预算，unknown可跨窗持续保留；短窗限制自身不恢复总额度。设置金额与阈值基于真实任务风险和成本估计，源数字不是默认配置。

2026-10-09 [Claude SDK cost tracking](https://platform.claude.com/docs/en/agent-sdk/cost-tracking)明确：`max_budget_usd/maxBudgetUsd`计当前调用自己的花费，resume 带入的旧session费用不占该 cap，`/clear`会重置当前预算；报告总额又可能包含 resume 旧费用。不能把此选项当跨夜业务 task 的总硬上限。usage字段还区分主loop与子Agent、同response ID重复消息、结果累计与逐步估计；`total_cost_usd`是客户端估计，不是账单。外部账本需保存 call/session/task身份、价格版本、输入/输出/cache write/cache read/工具费用，缺字段标未知而非记零；累计结果不可逐条无条件相加。

源第 13 课的模拟每 30 秒一轮，正常 2500、loop 8000 token，假定 `$0.003/千 token`，最高单轮0.024美元，长期最高速率约 **0.048美元/分钟**，远低默认5美元/分钟；200轮时 iteration cap 先触发，不是练习声称 velocity。即使跑完 10000轮，29轮正常加9971轮loop合计 **239.5215美元**，到不了500美元月cap。这个价格也不作为任何“Sonnet-class 当前混合价”；input/output并非一价。源 `$1200→$4800` 是4倍、增加300%，不是 tripled，且未取得可核的一手事故记录，不写成真实案例。

缓存减少部分重复前缀计费，并非近零总成本；write可能有溢价、miss/新后缀/output仍收费，公式已在前文。压缩与条件路由必须同时检查质量、回归和总费用，本任务不因教程示例变更选定模型。成本不足时停止新 dispatch并保状态/已发生效果、告警与授权重启路径；不靠删除账目或“取消成功”归零。

### 完整离线例：短窗预留、未知费用和总任务额度

程序用 Decimal 和单线程事件模拟精确规则：W=60 秒短窗最多0.30、task最多1.00，正常0.02，loop0.20；所有金额是教学单位。未知请求仍占预留，窗口边界刚好60秒的已结算记录被排除。settle用当前模拟时刻登记事件；真实服务须区分可信调用发生时间、结算到达时间与账期，不能借迟到结算改写历史窗口。它不接计费API，也不声称同进程锁解决分布式恢复；生产复用前文原子admission并把记录持久化。

```python
from decimal import Decimal as D

class WindowBudget:
    def __init__(self, total='1.00', window='60', velocity='0.30'):
        if any(type(x) is bool for x in (total, window, velocity)):
            raise ValueError('bool不是额度或时间')
        self.total, self.window, self.velocity = map(D, (total, window, velocity))
        if any(not x.is_finite() or x <= 0 for x in (self.total, self.window, self.velocity)):
            raise ValueError('限额必须有限正数')
        self.now = D(0)
        self.spent = D(0)
        self.pending = {}
        self.events = []
        self.done = set()
    def reserve(self, call_id, now, maximum):
        if type(now) is bool or type(maximum) is bool:
            raise ValueError('bool不是时间或金额')
        t, cost = D(now), D(maximum)
        if not t.is_finite() or t < self.now or not cost.is_finite() or cost < 0:
            raise ValueError('单调时间和有限非负费用')
        if not isinstance(call_id, str) or not call_id or call_id in self.pending or call_id in self.done:
            raise ValueError('必须是唯一非空调用ID')
        self.now = t
        held = sum(self.pending.values(), D(0))
        recent = sum(c for ts, c in self.events if t - self.window < ts <= t)
        if self.spent + held + cost > self.total:
            return 'task_cap'
        if recent + held + cost > self.velocity:
            return 'window_cap'
        self.pending[call_id] = cost
        return 'accepted'
    def settle(self, call_id, actual):
        if type(actual) is bool:
            raise ValueError('bool不是费用')
        cost = D(actual)
        if not cost.is_finite() or cost < 0 or call_id not in self.pending:
            raise ValueError('有效pending与实际费用')
        del self.pending[call_id]
        self.done.add(call_id)
        self.spent += cost  # 超额也如实记，不删账
        self.events.append((self.now, cost))

b = WindowBudget()
for turn in range(1, 7):
    amount = '.02' if turn <= 4 else '.20'
    verdict = b.reserve(str(turn), str(turn * 30), amount)
    if verdict != 'accepted':
        assert turn == 6 and verdict == 'window_cap'
        break
    b.settle(str(turn), amount)
assert b.spent == D('.28') and not b.pending
u = WindowBudget(total='.50')
assert u.reserve('unknown', '0', '.20') == 'accepted'
assert u.reserve('later', '1000', '.20') == 'window_cap'  # unknown不随窗自动消失
u.settle('unknown', '.35')  # 实际超预留依然结算
assert u.reserve('next', '1100', '.20') == 'task_cap'
e = WindowBudget()
assert e.reserve('first', '0', '.30') == 'accepted'; e.settle('first', '.30')
assert e.reserve('boundary', '60', '.30') == 'accepted'
try: WindowBudget(total=True)
except ValueError: pass
else: raise AssertionError('拒绝bool额度')
for bad in ('NaN', 'Infinity', '-1'):
    try: e.reserve('bad'+bad, '61', bad)
    except ValueError: pass
    else: raise AssertionError('拒绝无效费用')
print('第6轮短窗先拒绝，已结0.28；未知不释放，超额如实结算，总额和边界核对通过')
```

## FinOps归因：调用账本、共享费用与业务结果

2026-10-10 融合Phase17第27课。沿用前文预留/结算与时间窗代码，不重复实现预算。FinOps把技术使用量、可核账单和业务价值连起来；[FinOps Foundation](https://www.finops.org/wg/finops-for-ai-overview/)说明传统价格×数量、资源tag和承诺折扣仍适用，AI还增加API分摊、GPU容量和复杂SKU问题，不能说传统FinOps“失效”或成本只有token。

调用创建时绑定可信tenant/user/task、业务route、call/attempt/provider-response身份与价格版本；重试、子Agent和judge都保自己事件再归到父任务。不要以模型返回的tenant值做账，也不要把同一次累计usage和逐消息usage都相加。至少区分“估算”“已结算”“账单确认”“未知”；usage丢失保待核，不能记0；trace可能采样，provider账单可能有税、折扣、最低费和迟到调整，必须对账而非声称trace join天然最准。

业务输入可解释为system/user、工具结果、检索/历史，输出另计；它们是**互斥语义分组**，工具/记忆通常仍是供应商input，不能和input_total再加一遍。截断、模板及tokenizer后实际发送的token才可分摊，还须分普通输入/cache read/cache write/output等计费类别；重叠/不可得时给估计与误差，不制造精确四层比例。模型token、外部工具/检索/存储、网络、GPU空闲与运维共享成本均入TCO。

单位经济性 = 同范围全部成本 / 已定义业务成功数。例100张票、总成本10教学货币单位、实际解决80张，成本/解决=.125；失败20张的调用费用也在分子。若优化后总额7、只解决40，变为.175，虽然账单下降反而每结果更贵。无成功时该比率未定义而非0；质量、时延和人工接管必须同时报告。

共享GPU/网关/存储可按可解释驱动分配：如同窗口租户实际GPU秒、请求资源量或固定预留容量，保“未归属”桶和空闲容量。采样外推适合总体趋势，稀有大额异常/低量租户可能偏差巨大；不能据采样估算硬拦截或客户结算。历史归因可用已存在request账单/认证日志恢复部分，不一律认为无效，但将缺失和模型估计与真实事件分开。

### 完整离线例：费用事件去重、分摊与失败分母

金额是教学单位。仅已知费用进入本例，status记录的是该教学任务的观察终态；unknown表示任务结果未定，不表示未知费用可记零。每个任务只展示一个终态事件，真实多次尝试的费用与任务终态应分别建表，未结usage由前文pending管理。程序使用Decimal、调用身份和事件幂等冲突检查，将同事件重投忽略、不同内容同ID拒绝，共享费按给定权重分摊；没有供应商账单或模型API。分摊权重是题设，不证明实际GPU成本。

```python
from decimal import Decimal as D
from dataclasses import dataclass

@dataclass(frozen=True)
class CostEvent:
    event_id: str
    tenant: str
    task: str
    amount: str
    status: str

def aggregate(events,shared,weights):
    if type(shared) is not str: raise ValueError('金额用十进制字符串')
    fee=D(shared)
    if not fee.is_finite() or fee<0: raise ValueError('共享费')
    seen={}; costs={}; success=set(); failed=set()
    for e in events:
        if any(type(v) is not str or not v for v in (e.event_id,e.tenant,e.task,e.amount)) or e.status not in ('success','failed','unknown'):
            raise ValueError('有效费用事件')
        money=D(e.amount)
        if not money.is_finite() or money<0: raise ValueError('费用')
        if e.event_id in seen:
            if seen[e.event_id]!=e: raise ValueError('同ID内容冲突')
            continue
        seen[e.event_id]=e
        costs[e.tenant]=costs.get(e.tenant,D(0))+money
        if e.status=='success': success.add((e.tenant,e.task))
        if e.status=='failed': failed.add((e.tenant,e.task))
    if success & failed: raise ValueError('任务终态冲突；尝试状态不能冒充任务终态')
    if set(weights)!=set(costs) or any(type(v) is not int or v<=0 for v in weights.values()):
        raise ValueError('所有租户有明确正权重')
    total_weight=sum(weights.values()); allocations={}
    names=sorted(costs)
    allocated=D(0)
    for t in names[:-1]:
        allocations[t]=fee*D(weights[t])/D(total_weight)
        allocated+=allocations[t]
    allocations[names[-1]]=fee-allocated  # 固定余额规则，守恒
    for t in names: costs[t]+=allocations[t]
    ratios={t:(costs[t]/D(sum(x[0]==t for x in success)) if any(x[0]==t for x in success) else None) for t in names}
    assert sum(allocations.values(),D(0))==fee
    return costs,ratios

a=CostEvent('call-1','A','ticket-1','.04','success')
b=CostEvent('call-2','A','ticket-2','.06','failed')
c=CostEvent('call-3','B','ticket-3','.02','failed')
costs,ratios=aggregate([a,b,c,a],'.03',{'A':2,'B':1})
assert costs=={'A':D('.12'),'B':D('.03')}
assert ratios=={'A':D('.12'),'B':None}
try: aggregate([a,CostEvent('call-1','A','ticket-1','.05','success')],'.03',{'A':1})
except ValueError: pass
else: raise AssertionError('费用身份冲突')
try: aggregate([a],'.03',{'A':True})
except ValueError: pass
else: raise AssertionError('bool权重')
print('去重+共享分摊',costs,'每成功任务',ratios,'B没有成功故未定义')
```

三层控制各有职责：限流管理请求/资源速度，账期预留与结算维护金额上界，异常检测找偏离预期的变化。硬预算不能只“alert+tighten”：新dispatch必须原子查额度，在途和unknown继续占用；先发现已超额就如实记账并停后续。z=(当前−历史均值)/历史标准差是一个信号，需相同窗口、星期/业务季节、新租户基线和极端值处理；近零标准差不能任意用1货币单位替代，z>4也不普遍等欺诈或有固定假警报率。请求少/租户少一样可超预算，不能按少于10租户禁用限制。

cache、batch、routing可能作用于不同费用块/请求子集，不总能把四个折扣相乘；hit/miss、等待、备份容量、重试和gateway自身成本需核，同质量/SLO下做逐杠杆及组合比较，不能保证“节省到5–10%”。

### 第27课：五项原练习与六题参考

1. **kill何时触发、阈值怎么选？** 源按至少五天历史z>4才pause；rate_limit/minute_count没执行，每日cap只打印告警不拒绝，abusive租户25倍从第一天就存在，历史基线也含它，不能声称固定会kill。结合实际账期与基线选异常阈值、A-A/历史回放检假警报，但硬预算独立工作。
2. **首五个视图。** 租户已结/预留/未知与预算、任务完整成本/成功、用户使用分布、cache各计费量及质量、模型/route/重试分布；每项有时间窗、范围、账单对账差和未知桶，不能只画总费用。
3. **大租户经济性差怎样改？** 先修无效重试/重复和不必要输入，再在质量边界内做cache/批处理/条件路由，最后调整服务额度/产品能力/合同；顺序依业务影响和用户授权，省费不以降低必要成功标准实现。
4. **每票3M token、每天800票费用怎样算？** 缺输入/输出/cache读写比例、价格版本、重试与实际解决数，不能算唯一GPT价格结果。设每票费用C，由真实各计费项量×单价相加，则日模型费800C，成本/解决=全范围成本/实际解决量；本批不用过期价格填空。
5. **历史归因何时可用？** 有可信request/身份/账单关联可恢复部分，没关联可用估计做规划但显示误差与未归属；不能凭估计给客户精确账单或当实时硬限制。

六题：①价格×数量和tag仍适用，API共享服务需额外记录。②user/task/tenant来自可信调用身份，route/attempt/price也保留。③四语义层不要重复加到provider input。④z>4是源示例，金额cap独立。⑤成功结果为分母且含失败/共享费，无成功未定义。⑥trace到账单关联需完整性/采样/迟到调整核验，并非“最高准确率”保证。
