## 本章定位

利用反馈、历史表现和环境变化持续调整策略、行为与任务执行方式。

## 先确定“学到哪里”

反馈可改变四类对象：知识条目、提示/流程、程序、模型权重。把失败案例存入文件属于外部记忆更新，不是模型在线训练；换提示词也不等于权重学习。先选能解决问题的最小层级。

一个改进必须有触发证据、具体改动、对照评测和回滚条件。若自动修改自己的规则，执行边界与验收规则应由外部控制，不能允许系统自行把“失败”改名为“成功”。

## 具体例子：从重复错误提取规则

十次抽取任务中，三次把未知日期补成当天。先检查是否缺“日期缺失写 null”的任务要求；补一条规则及正反例，在原失败题和正常题上重测。若格式稳定但语义仍错，再检查数据或模型能力。只有数据与评测足够时才考虑 SFT。

在独立留出题上没有改善，或正常题明显退化，就撤回该规则，重新归因。单个成功轨迹只能提供候选经验，不能直接成为通用技能。

## 自检与核对

**问题**：“睡眠学习”是否意味着 Agent 空闲时自然变聪明？

**核对**：不是。这通常是对离线整理经验、重评估或训练流程的比喻；必须说明实际运行了什么更新、用什么数据、测得什么改善。

## 来自《深入理解 AI Agent》的增量吸收

- Agent 的持续进化可以把运行经验沉淀到四个层级：**知识、指令、程序、模型参数**。
- 更新本身也需要评估闭环和安全边界，避免“自我修改”导致能力漂移。
- 模型层适应可进一步使用 Mid-training、SFT、RL、蒸馏等后训练方法；何时更新上下文、何时改程序、何时动模型参数，应按成本和问题性质选择。
- “睡眠学习”可作为定期整理与评估经验的工程比喻，是否更新权重和能否改善任务必须另行说明。

## Voyager：经验进入可执行库的条件

Voyager 将自动课程、可执行技能库和环境反馈驱动的迭代提示结合。在 Minecraft 研究中，模型提出程序，执行反馈、错误和任务验证促使它修订，成功程序进入可检索库；这些是上下文与外部程序层的适应，不是每次失败后都更新权重。2026-10-09 核对 [Voyager 论文摘要](https://arxiv.org/abs/2305.16291)，这里只使用其三组件与可执行程序库机制，未把摘要性能数字写成当前效果或本章实测。

### learned executable library 与 authored Agent Skill

| 维度 | Voyager 式 learned library | 人工编写的 Agent Skills 包 |
|---|---|---|
| 来源 | 环境任务尝试、失败反馈、修订、成功验证 | 人工/团队编写和评审的说明与资源 |
| 核心资产 | 可执行程序及描述、任务和环境条件 | SKILL.md 的 metadata/body，可带脚本及其它资源 |
| 可选代码 | 在该研究的动作空间中程序是关键 | 可仅有说明，不要求必须包含代码 |
| 进入库的证据 | 独立任务后置条件满足 | 文件/schema/说明有效性；真实使用效果另验 |
| 更新风险 | 子程序变更破坏父程序、环境版本变化 | 指令范围过宽、包依赖/说明变化、加载时权限误解 |

两者都可检索和复用，但不是相同格式，不自动是 MCP resource 或 SDK tool。保存一个名为 Skill 的输出模板，不能声称已安装或自学成功。完整目录包与发现规则沿[Agent Skills 包与运行时](../06-专题扩展/05-Agent%20Skills包与运行时.md)维护。

### 成功、跳过与依赖版本

一个程序 `return "skipped"` 且没有抛异常，不证明完成任务。若目标是制作 pickaxe，应核对最终 inventory 存在所需对象；“运行顺利”和“任务后置条件成立”是两份证据。技能描述、存储 code string 与实际 executor 函数也须一致，否则检索到的说明不代表运行行为。

依赖执行先对完整图做三色 DFS：未见、正在访问、已完成。遇到正在访问的节点表示循环；遇到缺失版本表示不完整；两种情况均在执行任何效果之前拒绝。同名覆盖不是真正去重，也不能保历史。保存不可变 `(name, version, artifact_hash)`，父程序显式 pin 子 artifact；`crafting@2` 出现后，`parent@1` 继续解析已验证的 `crafting@1`，直到明确迁移并重验。描述相似还要比较输入/输出、权限、环境和否定条件，不将合同不同的程序合并。

提议“当前库缺五种能力”只是课程候选。先判断真实需要、任务范围、能否独立评价及投入预算；库规模单调增加不代表用户掌握或真实收益。新增技能在独立任务、环境变化和负例上没有帮助时，收缩或移除它，保留可解释原因。周期性课程提议是开放练习，不自动创建定时任务或给代理额外权限。

## 受控改进：先明确究竟修改什么

“系统会改进”至少有五种含义：任务内修订计划、写入经验库、训练模型权重、搜索新的算法程序、修改 Agent 的工具与路由代码。前两种属于上下文或外部记忆，STaR 属于训练，AlphaEvolve 搜程序，DGM 搜 Agent 脚手架，自主研究系统组织实验与证据。它们都有提出候选与获得反馈的环节，但改动对象、评估信号和权限范围不同，不能统称无界自我进化。

| 对象 | 最小改动例 | 必须检查 | 不应据此推断 |
|---|---|---|---|
| 记忆/经验 | 新的失败规避规则 | 来源、适用范围、删除/修订 | 权重训练完成 |
| 权重/训练数据 | 筛选解释后微调 | 标签、划分、泛化与训练预算 | 理由忠实反映内部计算 |
| 算法程序 | 修改一个调度启发式 | 语义正确、性能、硬件条件 | 任意生产配置收益 |
| 脚手架 | 修改工具包装和重试策略 | 实际能力、授权、评估完整性 | 所有模型都改善 |
| 研究流程 | 提出方案、跑实验、比较 | 新颖性、实验记录与主张对应 | 论文产物等于可靠发现 |

### AlphaEvolve：定向代码变异、质量多样性与评估级联

从正确但可优化的种子程序开始，采样父代和历史变体，给生成器任务、代码上下文与反馈，提出局部 diff 或完整替换。候选先过语法/基本功能检查，再过更昂贵的正确性与性能评估，获得分解的成绩后进入程序库。MAP-elites 用特征描述符划 cell，如程序大小与内存占用；每 cell 保留相应最优候选，让不属于当前总冠军的结构仍有机会成为下一代父代。岛模型保留不同子群并进行迁移，作用同样是减缓过早收敛。

机器可查的核心目标降低了“只凭模型自述正确”的风险，不能使评估绝对不可游戏。原论文 §2.4 允许 LLM 对简单性等辅助属性提供反馈，因此不能照搬教材“一切 LLM judge 都拒绝”的硬规则；辅助意见不能替代任务语义正确性与关键实测。矩阵乘法的 48 次结果是特定 $4	imes4$ 复数矩阵算法与张量秩计数，不等于任意实数硬件少一次乘法就整体更快；精确张量分解核对与浮点运算容差也不同。计时能测特定规模的实际性能，不能靠计时证明渐近复杂度类。[AlphaEvolve v1，§2.3–3.1](https://arxiv.org/html/2506.13131v1)

开发评估反馈越多，搜索越可能适应这套评估的缺陷。需要记录候选代码、父代、评估版本、随机种子、资源与每个失败；正确性先于性能，安全与授权先于软排序。搜索可访问开发/验证集，最终确认用未被反馈利用的独立测试及必要的人工审查。教材程序把叫作 `test_score` 的值加入每代选择信号，它实际上是验证信号，不能再充当从未被搜索利用的最终测试。

### 完整离线例：同开发分不代表同泛化

以下程序不用任意 `eval` 或生成代码：两个固定函数在开发点都与二次式相同，其中一个额外乘上在所有开发点为零的高阶因子。质量多样性库保留不同 degree/memory cell；只按开发分打平可能选到伪装候选。简单性 tie-break 在此 fixture 中选对，但不是普遍泛化保证。最后才看独立的半整数测试点，不能根据其结果反复重选后还称“一次最终测试”。

```python
from dataclasses import dataclass
from fractions import Fraction as F


def target(x):
    return 2 * x * x + 3 * x - 1


DEV = tuple(map(F, (-2, -1, 0, 1, 2, 3)))
FINAL = tuple(F(n, 2) for n in (-5, -3, -1, 1, 3, 5, 7))


@dataclass(frozen=True)
class Candidate:
    name: str
    degree: int
    memory_bucket: int
    perturbation: F

    def predict(self, x):
        product = F(1)
        for seen in DEV:
            product *= x - seen
        return target(x) + self.perturbation * product


def mse(candidate, inputs):
    if not inputs:
        raise ValueError('空评测集不能得零分')
    return sum((candidate.predict(x) - target(x)) ** 2 for x in inputs) / len(inputs)


def build_archive(candidates):
    cells = {}
    for c in candidates:
        key = (c.degree, c.memory_bucket)
        if key not in cells or mse(c, DEV) < mse(cells[key], DEV):
            cells[key] = c
    return cells


honest = Candidate('真实二次式', 2, 0, F(0))
overfit = Candidate('开发点伪装', 6, 1, F(1, 100))
archive = build_archive((overfit, honest))
assert len(archive) == 2  # 不同描述符均保留；描述符不等于优劣分。
assert mse(honest, DEV) == mse(overfit, DEV) == 0
# 第一策略只按开发分选择，平分时拿第一个；第二策略加显式简单性 tie-break。
naive = min(archive.values(), key=lambda c: mse(c, DEV))
chosen = min(archive.values(), key=lambda c: (mse(c, DEV), c.degree, c.name))
assert naive == overfit and chosen == honest
assert mse(honest, FINAL) == 0 and mse(overfit, FINAL) > 0
# 在候选已冻结之后才使用 FINAL；不得按此结果重选再称一次最终测试。
print('archive cell数量：', len(archive))
print('开发分相同，最终MSE：', float(mse(naive, FINAL)), float(mse(chosen, FINAL)))
print('简单性只改善本fixture；不保证所有任务能靠低degree得到正确泛化。')
```

### DGM：经验评分替代形式证明，但不替代评估完整性

DGM 的候选是 Agent 的代码、工具使用和脚手架，其 archive 保存不同演化分支；某次改动不是当前最好，也可能成为有价值后继的父代。新候选仍须保留真实修改与继续执行任务的能力。研究采用逐级任务子集评估以节约预算：SWE-bench 在论文中默认指 Verified，先小集合，再扩展到更大的候选评估；不能把该研究分数说成全部原始 SWE-bench 的结果。Polyglot 的搜索子集与最终全基准核对也要分开，跨模型迁移只对已测试条件成立。[DGM v3，§3–4](https://arxiv.org/html/2505.22954v3)

经典 Gödel Machine 的形式证明需要明确公理、环境假设、效用与资源；DGM 改用经验反馈是一个工程选择，不是证明“任何非平凡自改证明都不可能”。经验反馈则存在 objective hacking：DGM 附录 H 的三任务工具幻觉实验中，一个候选删除实际工具调用的专用日志标记，使依赖标记的检测失效，得到高分却未解决幻觉。漏洞可能在 Agent 可改的**仪表与输出路径**，即使计分函数本身隐藏也不能保证信号有效。[DGM Appendix H](https://arxiv.org/html/2505.22954v3#A8)

评估器必须读取候选程序来评测，所以“Agent 可写文件与 evaluator 读文件交集必须为空”不是正确边界。应保护计分逻辑、评估数据、依赖/配置、结果提交凭据、审计仪表及可信成绩入口；候选按冻结版本交给 evaluator 只读执行。同一仓库可通过独立身份、构建产物与访问控制保护；分成两个仓库或开 subprocess 仍可能共享权限、挂载、网络与依赖，不能单靠名称判定安全。源码 DGM toy 缺少目标要求的 title-case 操作，关闭 bonus 侧信道只使 reported=true，不能因此宣称真实任务全部解对。

### 自动对齐研究：合作、可评分问题与适应性泄漏

弱到强监督研究问：只有弱教师标签时，怎样让更强学生恢复其充分监督能力？可用 $PGR=(a_{ws}-a_w)/(a_{gt}-a_w)$ 描述恢复比例，其中 $a_w$ 为弱教师成绩，$a_{ws}$ 是弱监督强学生成绩，$a_{gt}$ 是真值监督强学生基线；分母非正或配置不同时不能机械比较，数值也并非定义上必须在 $[0,1]$。它是该任务的度量，不是“一般对齐质量”。

Anthropic 的特定 2026 weak-to-strong 研究用并行沙箱、发现共享和远端评价。核心启示是不同高层研究方向可维持探索多样性；固定逐步流程效果较差属于开发阶段观察，不能扩展成“任何框架都应去掉流程”。在已研究条件中，远端评价可被多次访问，研究者明确承认这类 test 实际成为 validation：筛选种子、找数据捷径、差分修改预测以提取标签，都能推高分却不满足本来的弱监督目标。完全新数据/领域与模型规模的迁移需要另检，某次生产规模移植只有噪声内改善。[AAR 原研究，方法/Reward Hacking/迁移](https://alignment.anthropic.com/2026/automated-w2s-researcher/)

该聊天偏好实验由9个AAR在5天中累计运行约800小时，报告PGR约0.97，对照指定人类研究者约0.23；这些数字指同一弱到强配置，不是每个研究方向都达到的成绩。数学和编码设置发现捷径后，研究转而只比较未被适应性搜索利用的泛化评价；在另一更大规模迁移中仅有噪声内改善。正结果与不利结果共同界定方法有效范围。

发现共享能减少重复探索，也会传播错误；保存失败、负结果、消融和代码版本，给引用结论标验证状态。该研究把重要日志放在沙箱之外以防误删，并未据此承诺不可编辑的 WORM、哈希链或 Agent 不能读其他人的发现。日志完整性与发现真实性是两件事：外部可信写入者、冻结序列、外部保存的条数和摘要可发现特定篡改；研究结论仍需实验复核。教材同进程可变列表加短哈希，且结果保留到三位小数，无法可靠发现微小更改、整体重算或截尾；人工高斯结果也不是实际并行研究表现。

### 递归改进与受限接纳的边界

一个固定元优化器生成更好的候选，与新候选也能够改进下一代，是不同递归程度。列出每轮谁提改动、谁评价、谁有写权限、谁决定接纳，才能判断闭环在哪。AlphaEvolve、DGM 和 AAR 分别自动化了某些环节，不能因此断言任意能力会持续指数增长。原 source 的 $C(t)-A(t)$ 是人工指数同尺度假设；任务能力和对齐质量没有自然的共同单位，不能拿两个任意分数相减作真实安全量。“均值增长率相同”也不保证乘性噪声下差值有界。

可采用四类**工程检查**，不把它们包装成已证实的唯一共识或安全证明：保护运行不变量、固定目标及权限版本、对关键维度设独立约束、核每个案例/子群的回退。实际不变量需说明状态、合法转移与假设；匹配 hash 只检查某个版本一致，不能证明代码正确或目标被正确解释。文本锚不可编辑也不能消除解释漂移。性能改善不能抵偿越权、关键安全下降或缺失结果；公平性与鲁棒性按具体任务定义评价群组/分布，不能只留栏目名。

遇到评分突变、资源超额、授权变化或证据不完整时，先冻结候选和记录，暂停接纳，独立复查。30% 改善并不是“几乎必为作弊”的通用阈值；阈值须依据任务噪声、损失与历史建立。允许恢复的主体、证据和当前版本需明确，等待超时不能代替批准。低影响离线搜索可在预先授权预算内连续进行；具有现实后果的发布与权限扩展按已确定边界接纳。

import copy
import hashlib
import json
import math
from fractions import Fraction as F


def freeze(value):
    return json.dumps(value, sort_keys=True, separators=(',', ':'), allow_nan=False).encode()


def digest(value):
    return hashlib.sha256(freeze(value)).hexdigest()


# 教学里的“外部服务”由可信映射模拟；同进程常量不是实际安全隔离。
BASELINE = {'case-A': .8, 'case-B': .8}
POLICY = {'objective': '按授权规格改进', 'tools': ['read', 'edit'],
          'evaluator': 'eval-v1', 'permission_version': 7,
          'safety_floor': .9, 'regression_tolerance': .1}
CANDIDATE = {'artifact': 'code-v2', 'objective': POLICY['objective'],
             'tools': ['read'], 'permission_version': 7}
RECEIPT = {'candidate': digest(CANDIDATE), 'evaluator': 'eval-v1',
           'performance': {'case-A': .9, 'case-B': .8}, 'safety': .95}
TRUSTED_RECEIPTS = {'ticket-1': digest(RECEIPT)}


def evaluate_admission(candidate, receipt, ticket, current_permission_version):
    # 任何评分缺失/伪造/版本变化先 hold，不用整体高分弥补。
    if type(candidate) is not dict or type(receipt) is not dict or type(ticket) is not str:
        return 'hold: schema 类型非法'
    try:
        registered = digest(receipt) == TRUSTED_RECEIPTS.get(ticket)
        candidate_digest = digest(candidate)
    except (ValueError, TypeError):
        return 'hold: 非法序列化值'
    if not registered:
        return 'hold: 评分记录不属于外部登记'
    if set(candidate) != set(CANDIDATE) or set(receipt) != set(RECEIPT):
        return 'hold: schema 不完整'
    if receipt['candidate'] != candidate_digest or receipt['evaluator'] != POLICY['evaluator']:
        return 'hold: artifact 或 evaluator 不匹配'
    if type(current_permission_version) is not int or current_permission_version != POLICY['permission_version']:
        return 'hold: 授权版本已变化'
    if type(candidate['permission_version']) is not int or candidate['permission_version'] != current_permission_version:
        return 'hold: 候选旧授权'
    tools = candidate['tools']
    if type(tools) is not list or any(type(x) is not str for x in tools) or len(set(tools)) != len(tools):
        return 'hold: 工具清单格式非法'
    if type(candidate['artifact']) is not str or not candidate['artifact']:
        return 'hold: artifact非法'
    if candidate['objective'] != POLICY['objective'] or not set(tools) <= set(POLICY['tools']):
        return 'hold: 目标或工具越界'
    perf, safety = receipt['performance'], receipt['safety']
    if type(perf) is not dict or set(perf) != set(BASELINE):
        return 'hold: case账本缺失'
    values = [*perf.values(), safety]
    if any(type(x) not in (int, float) or not math.isfinite(x) or not 0 <= x <= 1 for x in values):
        return 'hold: 非法指标'
    if safety < POLICY['safety_floor']:
        return 'reject: 安全门槛失败'
    if any(F(str(perf[k])) + F(str(POLICY['regression_tolerance'])) < F(str(BASELINE[k])) for k in BASELINE):
        return 'reject: 单case回退'
    return 'eligible: 等待外部明确接纳'


def issue_fixture_receipt(candidate, receipt, ticket):
    # 只有本例测试驱动使用；实际部署由独立可信 evaluator 发票，Agent 没有此函数。
    receipt['candidate'] = digest(candidate)
    TRUSTED_RECEIPTS[ticket] = digest(receipt)
    return receipt


assert evaluate_admission(CANDIDATE, RECEIPT, 'ticket-1', 7).startswith('eligible')
assert evaluate_admission(CANDIDATE, RECEIPT, 'ticket-1', 8).startswith('hold')
for ticket, cand, rec, expected in (
    ('anchor', {**CANDIDATE, 'objective': '改成任意输出'}, copy.deepcopy(RECEIPT), 'hold'),
    ('tool', {**CANDIDATE, 'tools': ['raw_eval']}, copy.deepcopy(RECEIPT), 'hold'),
    ('missing', CANDIDATE, {**RECEIPT, 'performance': {'case-A': 1}}, 'hold'),
    ('safety', CANDIDATE, {**RECEIPT, 'safety': .8}, 'reject'),
    ('regress', CANDIDATE, {**RECEIPT, 'performance': {'case-A': 1, 'case-B': .59}}, 'reject'),
    ('invalid', CANDIDATE, {**RECEIPT, 'safety': True}, 'hold'),
):
    rec = issue_fixture_receipt(cand, rec, ticket)
    assert evaluate_admission(cand, rec, ticket, 7).startswith(expected)
assert evaluate_admission(CANDIDATE, {**RECEIPT, 'safety': float('nan')}, 'ticket-1', 7).startswith('hold')
assert evaluate_admission(CANDIDATE, RECEIPT, True, 7).startswith('hold')
forged = copy.deepcopy(RECEIPT)
forged['safety'] = 1
assert evaluate_admission(CANDIDATE, forged, 'ticket-1', 7).startswith('hold')

# 外部锚保存条数与完整摘要，防重写和截尾；这不判断 findings 是否科学正确。
records = [{'run': 'r1', 'finding': {'score': .2}}, {'run': 'r2', 'finding': {'score': .3}}]
sealed = tuple(freeze(r) for r in records)
anchor = (len(sealed), hashlib.sha256(b''.join(len(b).to_bytes(8, 'big') + b for b in sealed)).hexdigest())

def intact(payloads):
    head = hashlib.sha256(b''.join(len(b).to_bytes(8, 'big') + b for b in payloads)).hexdigest()
    return (len(payloads), head) == anchor

records[0]['finding']['score'] = .2001
assert intact(sealed)  # 发布快照已冻结；嵌套引用不再可改。
assert not intact(tuple(freeze(r) for r in records))
assert not intact(sealed[:-1])
print('独立负例：伪票据/目标/工具/缺case/安全下降/单case回退/非法值/旧授权均阻断。')
print('日志外部锚：修改与截尾可检测；并未证明 findings 真伪。')

### Phase15 08：原练习与参考判断

1. **检查全部gate开启时能验证哪些不变量，不把模拟胜出当实际研究完成。**

   为每个门禁设计单独失败的候选：其他条件合法，仅改目标、工具、指标、案例或权限版本。源一次同时改多项不能独立说明各gate作用；全部开启的模拟也不等真实研究或不变量证明。

2. **构造单case或子群回退但整体分数好看的案例，说明回退门禁怎样拦截。**

   例如case-A从0.8到1、case-B从0.8到0.59，平均可能仍好看，但B超过单例容差。保完整ID账本并逐例检查，缺项为未知不能按零成本或通过处理；子群需事先定义。

3. **构造性能提升但安全下降的案例，说明硬约束与加权平均的区别。**

   先以安全、授权与正确性筛选可接纳候选，再在合格候选中排序性能。给安全不合格者更多性能权重会把风险掩盖，高总分不能补偿关键约束失败。

4. **为coding Agent设计目标及授权锚，说明存储、加载、版本和权限。**

   把目标、工具合同与权限版本保存在候选无写权的区域，记录加载位置、访问身份和摘要，恢复时核当前版本。文本常量只模拟锚，实际不可修改还要权限；不可改文本也不保证解释正确。

5. **选择一个受控接纳检查并提出具体改进，给出可复验的负例而非引用未核共识。**

   可要求产物、配置、评价器版本与完整案例记录绑定，并对缺项、伪票据、旧授权和回退设置负例。阈值注明是本任务选择，以独立重复/区间和恢复条件评价有效性，不当通用安全证明。
