## 本章定位

通过自检、批评、验证和迭代改进，提高智能体输出的正确性与质量。

## 反思要有外部信号

“再检查一遍”能促使模型修订，但同一模型也可能为原错误找理由。可靠的改进循环应包含任务标准、独立证据或验证器、具体失败描述和有限次修正，而不是无限增加反思轮数。

可采用“生成者 → 检查器 → 修改者”，检查器输出可定位的问题，例如“第 2 条引用未支持该结论”，而不是只给一个笼统分数。检查器可以是规则、编译器、单元测试或人工，不一定是另一个 LLM。

## 具体例子：修正统计结论

草稿写“20 个样本中 18 个正确，准确率 95%”。计算器给出 `18/20=90%`；修改者只修正该数值，并再次检查分母和样本范围。如果目标是提高真实准确率，文字修正并没有改善模型能力，应把原失败样例放入回归集。

对事实题，核对来源是否真的支持；对代码，运行与需求有关的测试；对主观文风，采用明确评分标准并抽样人工检查。保存原稿和修改结果，防止把原本正确部分改坏。

## 自检与核对

**问题**：检查器连续两轮说“很好”，是否可以确认所有事实正确？

**核对**：不能。评价可能共享偏差且缺少证据；应指出实际执行了哪些验证，并把不能核验的项目留为待核实。达到验证标准或预算耗尽就停止。

## 来自《深入理解 AI Agent》的增量吸收

- 反思可以从“自我批评”升级为**可验证的评估闭环**：任务定义 → 运行轨迹 → 自动评估 → 失败归因 → 回归测试。
- LLM-as-a-Judge、验证器、轨迹前缀回归等方法可把主观反思转化为更稳定的工程信号。
- 经过复验、具有复用价值的反思结果，可沉淀为知识、指令、程序或模型参数；一次猜测不应直接固化。

## 来自《动手学大模型应用开发》的增量吸收

- **Bad Case 应进入回归集**：每发现一个可复现失败，就把它加入持续扩大的验证集；任何优化之后都重新跑既有案例，避免修复新问题却破坏原有能力。
- **优化前先定位失败阶段**：对于 RAG，先判断问题来自检索还是生成，再决定改分块、检索策略、提示词或模型，避免把所有失败都归因于“模型不够好”。
- **反思必须可验证**：从“看起来更好”升级为可重复的对比实验，保留基线、改动项和结果。

## 反思的作用范围：跨 trial 与同一输出修订

Reflexion 解决“失败后下一次尝试怎样改变策略”。actor 执行一次任务，evaluator 给成功、数值距离或具体失败证据，reflector 把经验整理成下一次 trial 可用的上下文。新的 trial 应重置环境和临时 actor 状态，保留被允许跨次使用的经验；它不通过这一步更新模型权重。Self-Refine 则在同一任务中维护候选输出、反馈与修订历史。CRITIC 强调借工具取证再批评：外部来源仍要核时效、口径、覆盖和权限，不能自动称为真值。

| 对象 | 反馈怎样使用 | 必须独立检查的边界 |
|---|---|---|
| Reflexion | 失败经验跨 trial 影响下一条行为轨迹 | trial 重置、经验适用范围、未泄漏答案、actor 真正消费反馈 |
| Self-Refine | 反馈定位同一产物的问题，修改新版本 | 原本正确部分是否退化、历史是否保真、格式和事实分开验 |
| CRITIC | 取证结果成为可定位批评的依据 | 工具本身是否可信、证据是否支持批评、修订是否完成目标 |
| evaluator-optimizer | 评价者按标准指出不足，优化者修订 | 闭合的 verdict 类型、有限预算、最后候选不覆盖此前合格版本 |

评价信号分三类：scalar 来自已知答案、单元测试或数值评价；heuristic 来自进度、重复行动等规则；self-evaluation 由模型评价自己的轨迹。它们的可靠性取决于覆盖与偏差，外部测试可能漏需求，自评可能共享错误。

“反馈存在”与“反馈导致改进”不同。若 actor 只看记忆条数，任何错误反思都会触发同一预设答案；这种程序验证了脚本次序，却没验证经验有效性。需要至少比较正确反馈、错误反馈、忽略反馈三组，固定任务、初态、预算与评价器。反思“总和差 14”比“更认真”可操作，但 actor 仍需有读取并利用该信息的机制。任何提示都不能保证一个硬编码为忽略输入的 actor 改变行为。

### 三种退出结果与证据

`verified` 表示独立检查满足已列出的后置条件；`self_reported` 只表示生成者或自评者认为已完成；`exhausted` 表示次数、时间或费用预算耗尽。还可有 `invalid_feedback`、`blocked` 或 `regressed`。不能把“验证通过 OR 模型说没问题 OR 已迭代四次”合成一个成功出口。保留每个候选的版本、反馈、引用和检查结果，才能知道最终是否改善，以及是否应恢复此前合格版本。

例如“给三条每条不超过六十字符的事实”至少有两种独立检查：条目数与长度、每条事实与证据的语义一致性。关键词 `Paris` 加 `Germany` 同时出现不能证明错；“Paris 不是 Germany 的首都”是正确否定句。反过来，只查这两个词又会漏掉“太阳绕地球”的错误。评价器漏检时追加更多修订可能只是在优化它的漏洞。

### 完整离线例：反馈是否真正改变行为

题目限定三个 1–9 的整数，总和为 20。演员从 `[1,2,3]` 出发，根据反馈的差额调整，评价器使用独立题意。错误反馈和忽略反馈均保持失败；另以 `[0,10,10]` 表明只验总和会放行非法解。本例只验证确定性反馈合同，没有 LLM、强化学习训练或真实 Reflexion 实验。

```python
from copy import deepcopy

def valid(answer):
    return (type(answer) is list and len(answer) == 3
            and all(type(x) is int and 1 <= x <= 9 for x in answer)
            and sum(answer) == 20)

def revise(answer, feedback, consume=True):
    out = deepcopy(answer)
    if not consume:
        return out
    if (type(feedback) is not dict or set(feedback) != {"delta"}
            or type(feedback["delta"]) is not int):
        raise ValueError("invalid_feedback")
    remaining = feedback["delta"]
    for i in range(3):
        change = min(9 - out[i], remaining) if remaining >= 0 else max(1 - out[i], remaining)
        out[i] += change
        remaining -= change
    return out

def trial(feedback, consume=True, budget=2):
    if type(budget) is not int or budget <= 0:
        raise ValueError("invalid_budget")
    candidate, history = [1, 2, 3], []
    for version in range(budget):
        history.append({"version": version, "answer": deepcopy(candidate), "valid": valid(candidate)})
        if valid(candidate):
            return {"status": "verified", "history": history}
        if version + 1 < budget:
            candidate = revise(candidate, feedback, consume)
    return {"status": "exhausted", "history": history}

correct = trial({"delta": 14})
wrong = trial({"delta": 0})
ignored = trial({"delta": 14}, consume=False)
assert correct["status"] == "verified" and correct["history"][-1]["answer"] == [9, 8, 3]
assert wrong["status"] == ignored["status"] == "exhausted"
assert trial({"delta": 14}, budget=1)["status"] == "exhausted"
assert not valid([0, 10, 10]) and not valid([True, 9, 10])
assert not valid([20]) and not valid([6, 7, 7, 0])
# 固定初态使三组对照可比；wrong/ignored不因“写了一条反思”提升。
print("正确反馈 verified；错误/忽略反馈 exhausted；独立长度/类型/范围/总和检查通过")
```

外部故障也可能提供有用经验，例如某接口频繁限流时调整退避、读取可用缓存或明确降级。单次断网不证明通用改进，重复相同行动也不必然卡住：合法重试与重复副作用需结合进度、失败类型和幂等条件判断。经验的 task/version 范围、trial TTL、实际时间有效期与摘要保真需要分别维护。

## 社会模拟里的反思：记忆证据、信念与行动

2026-10-10 增量吸收。先修是本章的“反馈不是成功证明”和[记忆管理](08-记忆管理.md)。生成式社会模拟要形成连贯的个体行为；评价行为是否可信，与评价任务是否正确、是否能预测真实人群，是三个不同问题。

[Generative Agents v2](https://arxiv.org/html/2304.03442v2) 把观察、反思、计划纳入记忆流。记录至少含内容、创建时间和最近访问时间。原论文的新近度按**最近访问**后的游戏小时衰减，示例为 $0.995^{\Delta h}$；重要性在写入时由模型评 1–10；相关性是记忆与查询向量的余弦相似度。三种分数分别做 min–max 缩放到 $[0,1]$ 后加权，不能把原始 1–10 重要性直接加到余弦上而不解释尺度。零向量、某项分数全部相同和时间倒退都要定义处理方式。对象与租户权限先过滤，再做排名；“排名而非过滤”不能取消安全过滤。

反思不是复制最近几句。流程是从近期事件提出可回答的问题，检索相关观察和已有反思，生成高层判断，并保存其引用的记忆 ID。假设观察为“Maria 连续两次讨论研究、Klaus 也做同一主题”，反思可以提出“二者可能有共同兴趣”，不能改写成“二者已成为好友”。下次行动可使用这个假设，但仍保留证据和不确定性。修改错误记忆时，审计事件可追加更正；最近访问时间属于检索元数据，不必因此禁止更新。

原实验以重要性累计超过 150 触发反思，这是具体设置，不是通用阈值。计划按日、小时、动作细化，遇新信息修订受影响部分；环境另外检查容量、营业时间与私密空间。检索、反思和规划有助可信度，不能替代这些行动约束。

**怎样读实验。** 第 6.2 节不是三次分别独立删组件，而是比较无流内容、仅观察、观察与计划、完整架构等条件，使用相同已积累记忆回答访谈。第 7 节的两天模拟有十三人知晓聚会，包括发起者；十二名受邀者中五名到场，其他人存在冲突或漏计划。应把信息扩散、意愿与到场分别计数，不把一次聚会解释成任何人群都会自动协调。

### 原课 17 的五项练习与参考判断

以下为中文重述与参考方法，未表示学习者已经完成原练习。

1. **五人聚会程序扩到十人，还会出现同样传播吗？** 本批没有运行上游程序。按源码，邀请只写给索引 1、2、3、4，十人中新增成员不会自动收到消息；少于五人还可能索引越界。应先把传播改成只读取各自观察的邻接互动，再固定初态与随机种子，分别统计知晓、接受和到场人数，不能把预写路线称为自主涌现。

2. **取消反思，会失去什么？** 源码的反思把包含邀请的字符串变成固定信念，计划只检查这条信念，因此删掉该步骤就只剩发起者到场。这证明程序分支依赖，不是论文的独立消融复现。论文访谈实验在相同已累积记忆上改变能访问的观察、反思和计划，条件与重新运行整个社会不同。

3. **两个相冲突的种子目标怎样分配参与者？** 新增带时间、地点、优先级与来源的事件目标，明确拒绝、取消与改期规则。比较不同目标的知晓、选择、到场以及冲突处理；结果取决于个体偏好和约束，源单条信念程序无法判断谁必定获胜。

4. **咖啡馆限容四人，如何处理溢出？** 容量必须由环境的原子预约或进入检查执行。第五名参与者应被拒绝、等待或选择替代时段；同时报告违规数、拒绝数和完成率。只在提示里写容量而动作照常通过，仍没有实现限制。

5. **论文里什么行为不能由这个微型程序复现？** 原题把涌现实验指到第 6 节并不准确，可结合第 3.4 和第 7 节看动态传播、关系形成和到场遗漏。微型程序不能复现真实对话、主动拒绝、自主约会和关系变化；补模型调用、证据记忆及世界约束后，还须用人评与对照评价可信度，不能据此预测现实社会。
