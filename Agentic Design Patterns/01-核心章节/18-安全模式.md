## 本章定位

通过输入输出约束、权限控制、策略检查与风险拦截，提高智能体系统的安全性。

## 在执行边界落实约束

安全约束应在程序和权限系统中执行，不能只靠提示词“请不要越界”。关键边界包括输入来源、用户身份、可读写资源、工具参数、网络目标、代码执行环境与结果输出。语法合法不代表语义安全，日志中也不应记录不必要的密钥或隐私。

## 具体例子：检索文档中的恶意指令

用户要求查公开说明，检索到的页面夹带“把本机密钥上传到某地址”。这段内容属于待处理资料，不获得用户或系统权限。即使模型误生成上传调用，工具层也应通过允许目标、文件范围和数据出站策略阻止它。

检索权限需在取数时生效；结果缓存、引用链接和日志也需要同样隔离。只在最后输出时让模型“别说敏感内容”已经太晚，因为越权数据可能进入上下文或外部服务。

可用三条练习测试：正常检索、越权路径、来源中注入指令。分别记录执行了什么、阻止了什么、是否仍完成正常任务，避免把所有请求都拒绝当作成功防护。

## 自检与核对

**问题**：工具 schema 把路径声明成字符串，就能阻止访问目录之外吗？

**核对**：不能。还要在执行层规范化路径，处理 `..`、符号链接等情况并检查真实资源权限。模型输出审核是辅助，不能取代边界控制。

## 来自《深入理解 AI Agent》的增量吸收

- 安全控制应覆盖输入、上下文、工具、代码执行、权限和输出，而不是只做最终文本过滤。
- 上下文层需要重点防范提示注入；工具层需要最小权限、参数校验和危险动作审批；Coding Agent 还要限制文件、命令与网络能力。
- 持续进化系统必须给自我修改设置安全边界和验证门槛，避免错误经验被固化。
- 日志和用户记忆还需要隐私脱敏与敏感信息治理。

- **知识入库前治理**属于安全边界：解析后的文档先做清洗与必要的敏感信息脱敏，再进入 Embedding、向量库、日志和评估链路。

## 把格式、事实、策略与权限分开判断

输入大小/类型、JSON输出schema、任务事实正确、内容政策、数据授权、工具副作用各有不同判据。Moderation分类不能替代提示注入/PII/授权；词黑名单把“解释恶意指令”“kill进程”也拦掉，却可能漏编码/多轮/间接注入。源Python先lower再匹配大写DAN/[INST]的分支与带i的TypeScript行为不同；硬编码confidence不是实测概率。PII regex、短无盐hash也不证明匿名化或合规认证。

检索资料的“忽略规则”留在资料层。下面是窄任务边界程序：用户只可读自己租户的指定record，输出须有来源且值与记录一致。它不判断自然语言所有事实，也不运行任意模型/tool；同层关键词与word-overlap仅用作反例，不能给它们盖“安全检查”章。

```python
import json
from collections import Counter

DOCS={('team-a','policy7'):{'days':3},('team-b','policy7'):{'days':10}}
GRANTS={('alice','team-a','policy7')}
def unique(pairs):
    out={}
    for k,v in pairs:
        if k in out:raise ValueError('重复JSON键')
        out[k]=v
    return out
def read_record(principal,tenant,record_id):
    if (principal,tenant,record_id) not in GRANTS:raise PermissionError('取数前授权')
    return dict(DOCS[tenant,record_id])
def validate_output(raw,source_id,record):
    try:
        obj=json.loads(raw,object_pairs_hook=unique)
        if type(obj) is not dict or set(obj)!={'days','source'} or type(obj['days']) is not int or type(obj['source']) is not str:return 'schema'
        if obj['source']!=source_id:return 'citation'
        if obj['days']!=record['days']:return 'fact'
    except (ValueError,TypeError):return 'schema'
    return 'accepted'
record=read_record('alice','team-a','policy7')
assert validate_output('{"days":3,"source":"policy7"}','policy7',record)=='accepted'
assert validate_output('{"days":true,"source":"policy7"}','policy7',record)=='schema'
assert validate_output('{"days":10,"source":"policy7"}','policy7',record)=='fact'
assert validate_output('{"days":3,"days":10,"source":"policy7"}','policy7',record)=='schema'
for principal,tenant in [('alice','team-b'),('mallory','team-a')]:
    try:read_record(principal,tenant,'policy7')
    except PermissionError:pass
    else:raise AssertionError('来源注入/模型要求不产生授权')
source='The policy does not permit exporting secrets.'
wrong='The policy does permit exporting secrets.'
overlap=len(set(source.lower().split())&set(wrong.lower().split()))/len(set(wrong.lower().split()))
assert overlap==1. and 'not' in source and 'not' not in wrong
assert 'kill' in 'How to kill a stuck local process?'.lower()
blocked=[False,False]
assert all(True for x in blocked if x) and not all(blocked)  # 源演示的vacuous all错误。
print('schema/事实/引用/取数授权分开通过；高词重叠否定反例',overlap,'空筛选all反例通过')
```

真实文件还需resolve后限定根目录，防符号链接/TOCTOU，写动作另核对象、参数、身份、批准及幂等记录；引用和cache也不可共享越权材料。应用policy不应只相信tool destructiveHint，也不能因CORS限制就认为非浏览器调用被认证。所有层按实际失败原因留记录，不把一次output拦截后的短拒绝长度当原供应商output token。

## 红队协议与原练习边界

源五题分别验收：①13类keyword classifier只作标注基线，50题需attack与benign分别gold、precision/recall及样本数，confidence需校准；②base64/hex/ROT13/零宽等解码要限制长度/层数和资源，解码文本仍是资料，20变体未制作；③滑动窗口与token bucket不同，retry-after以最早过期项计算、并发需要原子更新，源10/min与15burst是题设非通用policy；④20%词重叠不能检验所有事实，否定/数值/实体反例优先；⑤100attack需锁定留出、多轮/间接/工具后果、良性误拒和严重漏拦，新增规则后用独立样本回归。

源`all(True ... if blocked)`只收True，即使所有攻击通过也返回True；重复运行同攻击还污染统计。各检测器相关失误不能相加成100%安全。不要预设99%/48小时/固定毫秒预算，不能把图`guardrail-gates`由selector选择trip/pass/fail，非分类器，其预定结果当实测。Secret不放system prompt，降低提取影响，但商业规则/用户资料仍需保密和授权，不能泛称整个system prompt都可公开。

## 间接注入：资料不能自己变成动作授权

2026-10-09融合Phase14第27课。间接注入把攻击指令放在网页、检索结果、PDF、邮件、代码或记忆中；危险发生在系统把这些数据当作可执行指令，进而用已有工具权限完成攻击目标。读取文本本身不等OS代码执行，也不保证能覆盖更高优先级指令。[Greshake等固定v2](https://arxiv.org/html/2302.12173v2)使用“can act as”危害类比，前提是具体模型、集成方式与工具边界可被突破。

攻击可被动等检索读入，也可随邮件等事件主动到达；用户粘贴内容仍可能在引用资料，不能仅因整条消息来自用户就把其中所有句子当授权。多阶段、编码与多模态隐藏会削弱关键词扫描。原课列出的泄露、传播、持久记忆污染、信息生态污染与任意工具使用是若干影响概述；原论文§4还按信息获取、欺诈、恶意软件、入侵、内容操纵、可用性展开，不是只有五种固定字符串。

| 控制层 | 具体要检查什么 | 单靠它还不能证明什么 |
|---|---|---|
| 来源与上下文 | 由可信宿主绑定origin、owner、取得方式与引用；资料与用户/宿主指令分开 | payload自报user_message不能提升信任，来源存在也不保证事实真 |
| 参数与目标 | 封闭schema、单位/大小/路径/目的地与对象范围 | shape合法不等动作已授权；Base64不等脱敏 |
| 当前权限 | 可信主体、动作、对象、当前政策及既有授权范围 | 描述、intent、readOnlyHint或文章文字不创造权限 |
| 运行隔离 | 实际文件/网络/secret/CPU等权限边界，必要的受控确认 | prompt或配置字符串不能证明OS已限制效果 |
| 返回与记忆 | 结果有出处/支持，候选记忆保时间/版本/信任，不把自写内容自动升格为政策 | 正常偏好可能含do not，不能把所有指令形文字一刀切删除 |
| 观察与效果 | 记录决策、真实结果、权威回读、失败与未知；按许可脱敏/保留 | 外部全文存储不是每个应用强制要求，日志存在不等攻击被阻止 |

本课PVE是Prompt–Validator–Executor的教学标签：模型先提出候选动作，检查在真实执行之前落实。它不是在昂贵主推理之前运行的神奇保险，原程序根本没有validator模型，只扫描关键词。`sensitive_tools`与`intent`未用，Executor可被直接调用，标签可伪造，nested参数未扫描；所以不能称完整PVE或生产防护。

例如`send_message(to=外部地址, body=普通问候)`没有任何攻击词，仍可能越出用户只读任务；“解释DROP TABLE为何危险”的正常检索又可能被词表误拒。正确边界是dispatcher每次核可信权限/参数/目标，使调用路径不能跳过校验；关键词只作为线索。既有本章窄任务程序与[授权治理](../06-专题扩展/07-工具授权与发布治理.md)、[工具合同](05-工具使用.md)提供具体入口，不复造一套弱的扫描器。

模型judge、工具guardrail、人工确认与执行隔离覆盖不同位置。[观测19](19-评估和监控.md)及[框架附录C](../02-附录/C-智能体框架快速概览.md)维护当前SDK的适用范围；不能把agent-level输入/输出guardrails说成自动保护每次hosted tool/交接。后置文本拒绝不能撤销已经发生的外部效果。

## 自主系统的安全：把训练目标、分类判断、动作控制与治理证据接起来

2026-10-09融合Phase15第17–20、22课。先修是本章的信任边界、[人机协同](13-人机协同.md)和[工具授权与发布治理](../06-专题扩展/07-工具授权与发布治理.md)。以下讨论的是怎样设计和核验控制，不把任何厂商的原则文档、分类器名称或第三方评估当成部署安全证明。

### 第17课：Constitutional AI怎样把原则变成训练信号

Constitutional AI（CAI）把一组书面原则作为评价回答的依据，目的是减少对逐条人工无害性标注的依赖。原则仍由人选择、解释并决定适用范围；模型反馈也可能误判，不能说“没有人类价值选择”。2022方法包含两个不同训练阶段：

1. **监督阶段**：初始模型回答一批问题，按抽取的原则批评并修订回答，再用最终修订文本做监督微调。批评是产生更合适训练样本的中间步骤；仅把一段批评放进聊天上下文，不等于微调过权重。
2. **强化学习阶段**：微调后的模型为同一问题生成两个候选，AI按原则比较哪一个更好，得到偏好对；据此训练偏好模型，再把偏好模型分数作为RL奖励。原论文的无害性反馈来自AI，有益性仍混合人类偏好数据。RLAIF不是直接把一段批评文字当数值奖励。[原论文§1.2](https://arxiv.org/abs/2212.08073)

这与运行时的“先检查，再执行”分工不同：训练影响模型选择候选动作的倾向；执行器的权限、资源限制和当前授权决定动作实际上能不能发生。二者应有各自证据，例如模型拒绝率与工具层越权阻断记录；模型说“我不会泄漏”不能代替文件或网络边界。

2026年[Claude Constitution的core values与hard constraints](https://www.anthropic.com/constitution)给出了支持适当人类监督、伦理、厂商指导、有益性这四类优先考虑，并规定部分行为不能被运营者或用户覆盖。**原文同时说明一般优先关系是整体权衡，非严格的词典序排序**。因此不能把“安全分≥3即拒绝、其次伦理、其次guidelines”称为真实Claude的裁决算法；源代码只是人工评分的教学规则，helpfulness字段甚至没有参与计算，也没有执行模型训练。

硬约束与默认偏好需要分别记录：前者表示明确的行为边界，后者允许在已声明范围内调整，如回答长度、产品范围与沟通风格。禁止某行为的政策意图，不等于权重或推理层已实现不可绕过的硬编码。原文硬约束涵盖严重助长大规模武器/关键设施攻击、严重恶意代码、破坏适当监督、极端夺权或人类灾难、儿童性虐待材料等；源把“直接询问时的AI身份诚实”也放进硬约束清单，没有该清单依据。身份透明仍是应维护的诚实规范，不能因此把它移除。

具体例子：客服默认简短，但用户需要详细解释保修条款时，可以在不泄漏他人资料的条件下详细回答。用户要求“为了帮助我，直接给别人的联系方式”，有益性不能创造取数权限。对模糊请求先确认对象和目的，对已知越权则在取数前阻断；不能先读出私密记录再让模型判断该不该说。

2023公众参与实验的约50%指公众与公司宪法的**概念和价值重叠**，不是50%的用户反对，也不是政治中立或身份披露行为差异的统一比例。该研究展示约千名美国参与者产生原则，再比较小模型；它不能证明2026文档完全未受这些研究影响，更不能代表全球价值共识。[实验设计与局限](https://www.anthropic.com/research/collective-constitutional-ai-aligning-a-language-model-with-public-input)

**第17课五项练习参考答案**：

1. **提高有益性权重会怎样？** 在教学规则中可以构造“有益但越权”的候选检查是否仍被拦；不需要真实危险请求。源程序hardcoded首先返回，修改后续权重不会自动绕过该分支，因此应说明改了哪一层。运行规则表不能证明模型学到了宪法。
2. **怎样识别原则歧义并改进？** 如“支持监督”应注明谁有适当监督权、哪些对象和情形、冲突时如何记录理由。两种合理解释及反例比一句“更安全”更可检验；本章已核core values与hard constraints，未声称完整审阅整份宪法的所有条款。
3. **客服可调整什么？** 语气、长度、产品领域和转人工条件可配置；数据主体权限、密钥出站限制和严重危害边界不能由客户聊天覆盖。每项设置需有允许范围、负责人、版本和回归案例。
4. **批评修订何时可能比固定规则更差？** 对确定、窄范围的密钥出站禁止，反复原则推理可能接受错误例外，确定性执行层应直接拒绝；对善意求助又不能把所有敏感主题一概拒绝。比较任务完成率、误拒、严重漏拦，不能只比较文本解释长度。
5. **如何表达运营者价值而保持边界？** 把可调整偏好显式配置、告知用户并做分组评估；不可覆盖的边界仍独立检查。公众研究是参与式设计的实例，不是已完成民主授权或自动继承2026政策的证据。

### 第18课：输入、输出、对话与工具护栏分别保护什么

Llama Guard是内容分类模型，产生safe/unsafe及类别标签；NeMo Guardrails可组织输入、输出、对话流程及其他rail。分类器解决“文本/图像可能属于哪类风险”，权限系统解决“这个主体可否对这个对象做这个动作”。二者不能互相替代，也不能把模型内容分类label叫法律合规结论。

| 检查位置 | 典型用途 | 特别容易遗漏的事情 |
|---|---|---|
| 输入rail | 生成前识别明显滥用，按业务策略拒绝或转人工 | 正常研究/求助也可能提危险词；只看一轮会漏跨轮组合 |
| 输出rail | 在展示前检查泄密、有害回答或不实断言 | 工具副作用可能已发生；截断输出无法撤销发送/删除 |
| 对话rail | 保存业务状态，限制跨轮流程，例如只提供产品信息与转诊入口 | 已声明流程与实际执行、恢复会话后状态是否一致仍须测试 |
| 工具/执行检查 | 参数、目的地、主体和对象授权；敏感效果前复核 | 不能只靠文本分类，也不能让模型绕过dispatcher直接调用 |

固定核验Meta PurpleLlama `172c1074069eb88ec834124272c1b1c4f8893445`：LG3-8B基于Llama3.1，LG4-12B支持文本与多图像；**LG3-8B已经包含MLCommons13类加S14工具滥用，S14并非LG4才新增**。LG4的S14限定text-only工具调用情形；支持图像不意味着所有工具调用、视频、音频或任意数量图像都得到同样保护。支持语言与业务流量还需重新评测，不能把一组模型卡测试值搬成中文业务保证。[LG3模型卡](https://github.com/meta-llama/PurpleLlama/blob/172c1074069eb88ec834124272c1b1c4f8893445/Llama-Guard3/8B/MODEL_CARD.md)、[LG4模型卡](https://github.com/meta-llama/PurpleLlama/blob/172c1074069eb88ec834124272c1b1c4f8893445/Llama-Guard4/12B/MODEL_CARD.md)。

类别编号是接口合同，不能自行移动：S1暴力犯罪、S2非暴力犯罪、S3性犯罪、S4儿童性剥削、S5诽谤、S6专业建议、**S7隐私、S8知识产权**、S9大规模武器、S10仇恨、S11自伤/自杀、S12性内容、S13选举、S14代码解释器滥用。源Python把隐私叫S8，静图却叫S7，融合时以模型卡统一。业务“公司机密泄露”不必恰好是一类，应有单独出站和授权规则；没有映射的业务风险不是天然已保护。

分类器输出也要校验：未知标签、解析失败、超时和缺模态覆盖必须成为可见的未判定，不能按safe继续。选择输入/输出策略时保留合法用户的完成率；正常用户询问有害内容的处理方式，可能得到安全解释，而不是必须把整个对话拒绝。

源标准库程序只做正则匹配与Unicode转换，没有Llama Guard/NeMo模型。NFKC、混淆字符映射和去不可见字符能改善部分词表检测，但会改变语言、连接符或真实标识符；保留受控原始表示与规范化表示，记录变换和差异，最终动作仍按真实目标授权。原demo的U+200B插入属于零宽攻击，不是论文把字节编码到emoji variation selectors的Emoji Smuggling实现；“NFKC+删零宽即可修复所有注入”不成立。

[Huang等论文的实验§4–5](https://arxiv.org/abs/2504.11168)用78条jailbreak与476条prompt injection样本，测量特定版本的6种guard；其中100%与72.54%属于特定攻击和数据集，并非所有分类器、LG4或所有线上用户的漏拦率。漏过检测也不必然使下游模型违规或工具执行成功。红队需分别报告检测规避、违规输出、越权效果及良性误拒。

#### 完整可运行例：分类结果解析失败与对象授权分开

下面只模拟分类返回值和可信对象范围，不调用模型或工具。用途是核对应用遇到畸形返回值是否漏放；正确scope也不能让unsafe变safe，safe也不能增加scope。返回hold表示需要处理未判定，不等于已授权；代码没有输出私密数据或真实外部副作用。这里的JSON `status/categories`是本文自定的应用规范化封装；Meta模型原始输出是`safe/unsafe`及相应类别文本，真实集成须按固定模型卡和提示模板解析，保留受控raw与normalized表示，不能把此JSON当官方wire格式。

```python
import json

KNOWN = {f"S{i}" for i in range(1, 15)}
GRANTS = {("alice", "read", "team-a/report")}

def no_duplicates(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError("重复键")
        result[key] = value
    return result

def parse_guard(raw):
    try:
        value = json.loads(raw, object_pairs_hook=no_duplicates)
        if type(value) is not dict or set(value) != {"status", "categories"}:
            return "unknown"
        status, cats = value["status"], value["categories"]
        if type(status) is not str or type(cats) is not list:
            return "unknown"
        if any(type(c) is not str or c not in KNOWN for c in cats):
            return "unknown"
        if len(cats) != len(set(cats)):
            return "unknown"
        if status == "safe" and not cats:
            return "safe"
        if status == "unsafe" and cats:
            return "unsafe"
    except (ValueError, TypeError):
        pass
    return "unknown"

def decision(raw, principal, action, resource):
    # 身份、scope必须由可信宿主绑定；不能从模型文本自报。
    if (principal, action, resource) not in GRANTS:
        return "deny"
    label = parse_guard(raw)
    return {"safe": "allow", "unsafe": "deny", "unknown": "hold"}[label]

safe = '{"status":"safe","categories":[]}'
unsafe = '{"status":"unsafe","categories":["S7"]}'
assert decision(safe, "alice", "read", "team-a/report") == "allow"
assert decision(safe, "alice", "read", "team-b/report") == "deny"
assert decision(unsafe, "alice", "read", "team-a/report") == "deny"
bad = [
    '{"status":"safe","categories":["S7"]}',
    '{"status":"unsafe","categories":[]}',
    '{"status":"safe","status":"unsafe","categories":[]}',
    '{"status":true,"categories":[]}',
    '{"status":"unsafe","categories":["S99"]}',
    'not-json',
]
for raw in bad:
    assert decision(raw, "alice", "read", "team-a/report") == "hold"
print("正常允许1项；越权与unsafe拒绝2项；畸形返回hold6项")
```

**第18课五项练习参考答案**：

1. **规范化后命中变好能说明什么？** 只能说明这组词表/变换样本。加正常非英语、组合音标、合法零宽语言文字和语义改写作反例；统计TP/FN/FP/TN及未判定，不能从几条demo推真实模型ASR。源程序五类而不是正文所称六类，也没有真实延迟。
2. **MLCommons与S14的关系？** MLCommons13类加工具滥用扩展，LG3-8B已含该扩展；它关注代码解释器恶用，不能代替沙箱、系统调用和网络边界。
3. **如何设计跨轮客服rail？** 状态保存为“产品帮助/需专业帮助/已转接”等，用户换措辞也检查同一业务scope；对一般产品信息仍答。三种问法只测流程的最小样本，不证明所有诊断请求已覆盖；本轮未安装或执行Colang。
4. **某个变换缓解什么，又漏什么？** Unicode检查可发现特定异常编码，可能误伤正常语言，也漏语义改写；独立出站权限能限制敏感效果，但授权目标内仍可能生成错误内容。评价组合后实际效果，不能把多个召回率相加。
5. **怎样测一般用户分布？** 固定真实授权范围和脱敏标注集，含正常、敏感但合法、明确滥用、模糊、多语言与多轮；报告类别召回、误拒、任务完成和成本。攻击者优化样本与一般流量应分别报告，不预先猜一个“通常更低”的数值。

### 第19课：阅读Responsible Scaling Policy，要把承诺和愿景分栏

Scaling policy回答“出现哪些能力或使用风险时，需要什么证据、控制和决策程序”。它不取代法律，也不自动证明某个应用已经合规。基础方法是逐条建立记录：版本/日期→能力或使用条件→测试及局限→要求的控制→谁复核和决定→公开证据→偏离时如何处置。公司拥有一份policy与按policy做过某次决策属于两层事实。

[Anthropic RSP v3.0](https://www.anthropic.com/responsible-scaling-policy/rsp-v3-0)生效于2026-02-24，历史v1.0是2023-09-19、v2.0是2024-10-15。它区分公司计划与更强的行业整体建议；例如行业建议中的安全水平不能全部当作公司已无条件承诺。Roadmap是公开目标，更新与报告目标进展是机制，目标本身并非全部硬承诺。Risk Report覆盖公开模型及符合范围的内部模型，通常每3–6个月一次，并有更强公开模型、内部in-scope确定后30天等补充讨论要求。

| 要看的问题 | 可用的检查方式 | 不可偷换的结论 |
|---|---|---|
| 是否达到某能力条件 | 定义能力、成本基线、允许工具、任务与评估证据 | METR某个小时数不自动等于RSP阈值 |
| 控制是否足够 | 威胁模型、部署面、已落实控制、残余风险与限制 | “我们有模型拒绝”不证明内部使用/权重安全 |
| 外部复核是什么 | 查适用条件、审查者利益冲突、资料访问及评议公开范围 | 内部委员会名称不等外部独立审查 |
| 谁批准继续 | 查最终决策者与特定情形董事会/LTBT参与条件 | 有外部评论不等外部审查者拥有否决权 |
| 目标有没有兑现 | 逐项对照Roadmap、Risk Report、偏离和修订 | 风险报告存在不等所有拟议控制已经落实 |

RSP§3.6对“highly capable且significantly redacted”的报告规定最低外审流程，并描述审查资料、时点与利益冲突；不能只用“limited independent oversight”概括而漏掉这些条件。高级研究能力的工作性操作化包括将两年指定历史时期AI进展压缩到一年；它是风险阈值的一部分，仍需成本、研究产出与证据判断，不能转写成代码里的`automation_share≥0.5`、`horizon≥40h`、`AAR≥0.4`任意二项触发。[RSP§1及§3.6](https://www.anthropic.com/responsible-scaling-policy/rsp-v3-0)

源程序这些数值明确是示意，却给真实型号塞入未来源的测量值；正式笔记剔除这种伪测量。源把全部变化归因于“2023定量阈值因benchmark重新缩放无法达到”，也无已核原文支持。暂停、继续或风险接受必须逐版本逐条核，而不能用“v3没有2023的措辞”推公司在任何情况下都不会停止。第三方评级若要使用，应保存评价版本、维度、原始评语和利益冲突；本轮不收录无法重算的2.2/1.9排名。

**第19课五项练习参考答案**：

1. **三个合成模型怎样测规则？** 只能检验自定门槛的程序分支；变量命名使用synthetic，不赋值真实模型。真实policy判断须回到定义和证据，不能凭两个高数触发自动宣称达到AI R&D-4。
2. **怎样比较行业建议与公司计划？** 逐条列条件、要求、实施主体、时间和承诺强度，并对照真正的2024 v2与2026 v3条款。不是只算两栏句子数量；本轮核关键机制，未声称逐条全量重算旧版差异。
3. **怎样重算SaferAI评分？** 先取得特定日期的方法与原评分细项，再双人/独立复核每个判据及不确定项。仅有1.9与2.2不能重算，本轮未完成该评级，不把它当学习结论。
4. **怎样改进暂停/继续的承诺？** 写清证据不足如何默认处置、不可接受残余风险时暂停的对象、复评条件与责任人；不要承诺一个与方法会变化脱节的永久数值，也不要把“发布论证”本身视为控制有效。
5. **怎样比较RSP与Preparedness？** 选同一明确能力和部署面，逐条比测试、触发、控制、审批与外审；记录一方未覆盖或不可比较。不以公告语气、公司名称或单一评级判断整体强弱。

### 第20课：不同前沿安全框架不是同一张可自动执行的决策表

OpenAI Docs当前API安全说明把平台护栏、应用工具审查和实际环境权限分开；它链接的[Preparedness Framework v2（2025-04）](https://cdn.openai.com/pdf/18a02b5d-6b67-4cec-ab64-68cdfbddebcd/preparedness-framework-v2.pdf)应按固定版本阅读，不把该版本写成永久不变的“最新”。[官方API说明](https://developers.openai.com/api/docs/guides/safety-checks/cybersecurity)不替代具体应用的授权边界。

PF v2的Tracked类是生物/化学、网络安全、AI自我改进。自我改进指相关阈值定义的AI能力加速风险，不等于任意自动化研究脚本。Research类有**长期自主、sandbagging、自主复制与适应、破坏防护、核/辐射**五类。Research尚不采用Tracked同一套成熟分类与门槛，但表2有具体potential responses：例如已有Tracked High/Critical能力时，长期自主涉及misalignment报告，发现破坏防护能力时论证需对此稳健；sandbagging还需能力激发或保守界限。不能把“Research”教成一律只观察、没有任何控制响应。

| 框架 | 要读取的结构 | 如何用于同一能力的比较 |
|---|---|---|
| PF v2 | Tracked等级、Capabilities/Safeguards报告、Research潜在响应与决策程序 | 单看长期自主标签会漏与网络或自改进Tracked条件的联动 |
| RSP v3.0 | 能力/使用阈值、公司计划/行业建议、Roadmap与Risk Report、治理 | 不能把Constitution行为禁令混进RSP，编造“refuses training/deploy”通用行 |
| Google FSF v3.1 | TCL/CCL、内在/残余风险、缓解与风险接受、内部高风险使用 | 阈值名、成本口径、内部/外部部署面及安全建议的约束强度分别核 |

2026-10-09[Google官方版本页](https://deepmind.google/frontier-safety/)列FSF3.1（2026-04-17）。[固定3.1全文](https://storage.googleapis.com/deepmind-media/DeepMind.com/Blog/strengthening-our-frontier-safety-framework/frontier-safety-framework_3-1.pdf)的风险组织为CBRN、Cyber、Harmful Manipulation，以及ML R&D与Misalignment；并非源所称Bio/CBRN重复再加顶层Autonomy。TCL提供更早的显著风险信号，CCL涉及严重风险，仍须结合具体控制和残余风险评估。

Sandbagging是评估表现与真实条件显著偏离，可能有策略性压低能力。应控制评估可识别线索，做能力激发、不同scaffold/激励与独立留出复核，同时防奖励篡改。不能设计一套“必迫使任何sandbagging模型暴露能力”的万能测试；结果中仍需保留不可排除的测量盲点。

3. **研究自动化如何外评？** 先区分FSF TCL和automation CCL。用代表研究流程、独立专家成本、总算力/人工复核成本、重复试验、真正研究成果验证；几个RE-Bench环境不能等同所有研究团队工作。
4. **怎样评测sandbagging？** 比较不暴露测试标签与明显评估环境，变化激励/scaffold/工具，保持任务可比、隔离验证器，复核隐藏成功能力和异常失误；报告剩余不可识别风险，而非保证消除。
5. **哪一份更严格？** 只在所选威胁、阈值与部署面比较。严格定义但控制未知、强措施但触发模糊是不同弱点；各方都存在框架外的其他政策，不能由一个词缺席宣布完全无控制。

### 第22课：社会风险分类如何落到工程与组织证据

CAIS的四类框架是观察风险来源与相互作用的方法，既非互斥标签，也非预测灾难概率的量表：恶意使用关注有意利用能力造成危害；竞赛关注竞争激励压缩审查；组织风险关注流程、人员与安全文化失效；失控AI关注错误目标、控制削弱和抗纠正行为。一个竞争中仓促发布的失控系统可能涉及多类，但没有恶意操作者证据时不应自动贴上全部四类。[CAIS原研究入口](https://safe.ai/ai-risk)

把风险写成可以审查的链条：**情境→失效机制→受影响对象→现有控制→控制验证→剩余未知→负责人和复评条件**。例如内部文件整理Agent无需公网，也可能被受污染文档诱导到错误目录；公开与否不能决定恶意使用风险是否存在。源`autonomy_hours≥4`标rogue没有依据；自主时长增大可能增加暴露面，但风险还取决于对象权限、行为、能力、监控与危害规模。

| 风险来源 | 可行动的例子 | 要保存的证据 |
|---|---|---|
| 恶意使用 | 限制滥用入口、危险能力/数据出站、受控响应与事件处置 | 实际滥用分布、阻断与绕过记录、正常任务完成率 |
| 竞赛激励 | 固定审查门槛、明确可停发者、记录延期/例外原因 | 发布决策、资源投入、例外批准与补救完成情况 |
| 组织失效 | 可无报复升级、独立审查、职责分离、演练与信息安全 | 问题从发现到修复的链路、审核访问范围、演练结果 |
| 控制失效 | 最小权限、可信停止路径、异常效果检测、受控回退 | 不能越权的反例、停机后的未完成动作与真实回读 |

控制层的数量不是安全分：模型原则、内容分类、权限、运行隔离、人工复核、组织治理都应按风险配置。一个低影响只读程序未做前沿实验室级外评，不自动等于禁止使用；拥有全部名词却没有执行证据，也不能叫production-ready。操作者同样可以影响恶意使用、竞赛与控制风险，并非“只有组织风险可以行动”。公平、隐私、参与式设计和集体行动基础另见[负责任AI](../../AI%20算法基础/深度学习专题/13-负责任AI.md)。

CAIS是非营利研究组织，与美国NIST机构不同。2026-10-09旧`nist.gov/caisi`会转到[CAISSI主页](https://www.nist.gov/caissi)，页面名为Center for Advancing Innovation and Standards for Super Intelligence；历史材料仍有CAISI署名。当前页说明自愿合作、能力评估及标准工作，不代表对所有模型提供认证，也不保证所有报告公开或每个模型都预先测过。机构名称、合作范围与公开结果须按具体发布日期核，而不能凭缩写推权限。

源SB-53“如果签署”的说法已过时：加州官方宣布[2025-09-29签署SB-53](https://www.gov.ca.gov/2025/09/29/governor-newsom-signs-sb-53-advancing-californias-world-leading-artificial-intelligence-industry/)。本章保留长期有效的区别：自愿政策、外部评估与法律义务并非一回事。具体适用对象、门槛、施行时点、豁免和报告时限应查生效法规；不以地理位置或“服务欧盟用户”直接推出某条人工监督义务，不从公告生成通用法律合规门禁。

## 生产数据边界：凭据、脱敏、出口与审计

2026-10-10 融合Phase17第25课，与前文内容分类/工具授权分开。秘密管理覆盖发放、最小权限、使用、更新、吊销、缓存和事故处理：CI优先使用有受众/项目/分支约束的短期身份，外部服务长期key由受控secret服务发给网关/进程；调用前绑定身份与目的端，模型文本、源码、日志与工单不接触真实key。环境变量本身不是必然泄漏，但会随日志、进程访问、dump或过宽CI授权暴露；secret服务不是万能隔离。

网关可减少key散布并统一配额，但实际仍持有可用凭据，不能声称“任何服务都不持有静态secret”。定期拉取/TTL缓存/连接池/副本传播影响更新时间，不保证下一请求或几分钟全更新。轮换流程要发新值、受控双版本窗口、验证所有消费者、吊销旧值、核失败与审计。遭泄漏先撤销/轮换、排查使用和影响，删除git历史不能收回已复制的secret。轮换期限由凭据类型、风险、供应商能力及组织政策决定；90天/CI30天是源建议而非通用法规。Vault root凭据更应作为受控引导/应急资产，不是普通长期应用key。

脱敏前先判断用途、最少必要字段、合法接收方与处理权限。SSN、姓名、电话、邮箱、病情组合和自由文本均可能识别个人；regex只识别部分格式，NER也有漏检/误检，分类器“safe”不等无PII。稳定占位符可保同一任务内关系，例如同客户两次出现都映成CUSTOMER_1；映射应按租户、任务、数据类型隔离，限寿命和读取权。同值全库稳定映射会增加跨场景链接风险，碰巧像占位符的原文和不同实体类型须处理碰撞。

可逆占位、HMAC或普通hash都不能自行保证匿名化：低熵邮箱/证件可猜测，恢复表和语境可重新识别。恢复输出时逐项检查调用主体可访问哪个原对象，不能因模型输出某token就恢复别人的数据。[HHS去标识指导](https://www.hhs.gov/hipaa/for-professionals/special-topics/de-identification/index.html)区分Expert Determination与Safe Harbor，后者有指定标识清除且不得已知可重新识别；简单三regex不满足这个完整标准。模型输出脱敏可以保护输出，但不能撤销已发给外部方的原文；输入最小化和输出访问控制各自必要。

出口策略按业务目的端、协议、端口、身份、数据类别和租户落实；限制域名只是部分控制，还要检DNS外流、重定向、可访问IP、共享CDN/代理以及授权目的端上的过宽路径。能给api域名发请求不表示可以向该域名任意账号上传所有资料。拒绝未授权目的端，同时保正常依赖的证书/更新/监控所需路径，别由通用清单推导全网断开。

审计最少连接call/attempt/trace、可信身份/租户、用途、对象、版本、授权决策、真实usage与费用、失败/拒绝、效果回执及可信时间。按用途选择正文引用/受控样本/摘要，不必永久记录raw；只有hash时可能无法调查语义错误，须设计另存受限证据和删除政策。**序列化JSON不等append-only，append-only不等不可篡改**：需存储权限、独立写入/保留、删除/修改审计、可信锚点或受控WORM等。hash链仍可被持有全部写权的人重算，48bit截断hash也有碰撞和可猜测风险。

## 合规证据：先识别对象与职责，再映射控制

Phase17第26课不提供“按行业/地区自动宣判必须通过七项框架”的规则。先画数据流和责任链：谁提供模型、谁部署系统、谁决定处理目的、谁处理个人/医疗/支付数据、谁是分包商；再核实际地区、用途、客户合同、版本与施行时点。法律义务、审计报告、管理体系认证、合同承诺与内部安全策略是不同对象，供应商证书不自动覆盖自己的配置/用途。

### 第26课：五项原练习与六题参考

1. **客户要TypeII/BAA/AI声明怎样准备？** 给真实覆盖范围和当前报告/合同/系统责任，建立缺口矩阵、责任与可交证据；TypeI不能冒称TypeII，缺BAA不能假称已有，但采购要求也非通用法律。AI声明按实际用途/角色和现行时点复核，不为成交填虚假保证。
2. **三类系统怎样分类？** 通用写作助手先核透明度/数据；就业候选排序或信贷决策先查相关高风险用途及例外；禁止实践不通过一般安全表洗白。写明产品实际如何影响决定，而非模型名或行业标签。
3. **PHI发送给未签BA怎么办？** 停止未授权后续传输并保合法审计、查数据/接收者/用途/留存和实际访问，联系已授权负责人与合规人员，按适用Security/Breach Rule评估风险及通知职责/期限；本批不发送消息或断言每次都是同一通知流程。
4. **ISO42001是否必要？** 取决合同、采购、管理需求和认证范围；可以先落实风险/数据/监督证据，不能以2026年份推出所有中型厂商必须认证。
5. **审计字段怎样跨框架复用？** 身份/对象/动作/结果支持访问与审计，模型/配置/用途版本支持变更和可追溯，时间/证据/审查记录支持检查；分别核HIPAA(b)、GDPR32及报告控制实际条件，不用“hash存在”替每项满足。

六题：①原高风险统一2026-08-02答案已过时，按上文角色/条款区分新日期。②罚款类别与口径分开核现行条文，不用一个最高上限覆盖全部违规。③处理前最小化减少暴露，但GDPR不规定所有应用统一实时脱敏方式。④TypeI时点/TypeII期间区别保留，审计期不固定6–12月。⑤交叉映射复用证据，不自动满足。⑥适用HIPAA关系/数据的外部业务关联方核BAA及服务范围；不是所有医疗或所有供应商都自动适用。
