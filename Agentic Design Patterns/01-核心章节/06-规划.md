## 本章定位

把高层目标分解为可执行步骤，处理依赖、顺序、资源与执行过程中的动态调整。

## 计划是可更新的依赖图

可执行计划至少包含目标、步骤、前置条件、预期产物、验证方式和停止条件。“先分析、再优化、最后完善”无法直接验收；“找到错误函数、复现失败输入、修改并通过该输入和回归测试”才可观察。

环境有变化时，只修订受影响步骤，并保存已经确认的事实。不要在未观察结果前假定工具成功，也不要用写出计划替代真正执行。

## 具体例子：整理一个文件夹

目标为“按已有规则给 8 个文件改名，并保留可恢复映射”。先列出现有文件 → 生成旧名/新名映射 → 检查重名与非法字符 → 执行允许的改名 → 回读目录核对 8 项。若出现目标文件已存在，应停在冲突项并更新映射，不能无声覆盖。

任务简单而规则稳定时，固定程序工作流更容易验证；只有下一步取决于未知反馈时，动态规划才有明显价值。开放任务也需要迭代预算和阶段成果。

## 自检与核对

**问题**：执行到第 3 步收到“目录已变化”，是否从头重做全部计划？

**核对**：先重读受影响状态，保留仍有效结果，重新核对依赖后继续；盲目重做可能重复副作用。状态和结果才是继续执行的依据。

## 来自《深入理解 AI Agent》的增量吸收

- 规划需要区分**确定性工作流**与**自主 Agent**：前者按预设步骤执行，后者根据环境和中间结果动态决定下一步。
- Coding Agent 展示了典型规划循环：理解任务 → 搜索/定位 → 修改 → 执行/验证 → 失败恢复 → 继续迭代。
- 长程机器人任务进一步强调任务分解、世界状态更新和局部动作控制之间的层级规划。

## ReWOO：先规划依赖，再取证求解

ReWOO 把 planner、workers 和 solver 的职责拆开。planner 在尚未读取本轮工具观察时提出计划；workers 执行取证，不一定是 LLM；solver 使用问题、计划、证据及明确错误求解。观察会改变下一步的任务可加入 replanner，但要限制次数并记录计划版本。初始输入不完整仍可拟候选计划；是否值得先规划取决于工具依赖、环境变化与实际成本，不取决于任务是否超过三十步。

### 类型化 DAG 的静态与运行检查

把节点写成 `id/tool/args/deps/output_type/precondition`。证据引用使用结构化 `Ref(node, expected_type)`，不对 `str(args)` 做正则替换。静态预检要拒绝重复 ID、未知工具、缺失依赖、循环、引用未声明为依赖、类型不兼容与对象无权限；运行时才知道输出值是否满足业务约束。已有上游 `failed` 或 `effect_unknown` 时，下游不是拿错误字符串当正常输入，而是 `dependent_blocked`。没有得到证据的 solver 也不能凭最终文本宣布目标完成。

例如 fixture：E1 给城市名称，E2 依赖它取人口，E3 依赖 E2 取整。图中额外画 E1→E3 并不等于实际需要该边；取证口径还要明确市区或都会区及日期。源例 Paris/11.2M 是人工表，不支持当日人口事实。

独立且无资源冲突的就绪节点可以并行；链式依赖不能。两个层各有三个调用时，理想总时间是两层分别取最大耗时后求和，还要计调度、限流和序列化。一个工具调用不必对应一次模型调用。若每步新输入长度约为 a，并重复发送全部历史，单次第 n 步长度为 O(n)，累计为 a·n(n+1)/2，即 O(n²)；缓存、摘要、工具 schema、推理项与输出会改变实际账单，字符数不能当 token usage。

### 有限重新规划与继续执行

失败后保存 `plan_version、已确认结果、对象版本、效果状态、剩余预算`。只调整受影响节点；已确认读取可按有效期重用，写入已发生或未知则先回读，不能盲目重做。限制 replan 次数并检查新的 DAG，结束时使用独立目标核验。比如“发布含迁移的功能”不能因为测试标记为真就完成，还必须有迁移执行证据及最终状态。

## HTN：方法选择与回溯的保证范围

HTN 将 compound task 通过 method 分解为子任务，到 primitive operator 才执行前置条件与效果。domain 描述、初态、方法语义与执行器都正确时，符号计划才有相应可靠性；仅知道工具名称和 schema，无法证明现实效果或政策满足。LLM 提议是待验证候选方法，不能直接授予操作权限。

同一任务可有多个适用 method。第一个方法在后续前置条件或最终目标失败时，应尝试下一个，且 depth/node/time 预算贯穿递归。模拟回溯可复制字典；现实中的付款、发布、文件覆盖不能靠恢复内存字典撤销，需要明确补偿、效果回读或新计划。缓存应绑定 state pattern、domain/operator/policy 版本、适用前置条件，且在整个分解和目标核验成功后才写入；下次使用仍检查当前状态。

### 完整离线例：类型化依赖与有限方法回溯

DAG 例只验证规划前置合同，不提供任意执行器；未知工具、类型、缺依赖、循环或未授权都在任何效果之前拒绝。HTN 例只用不可变事实集合模拟“代码、测试、迁移”，先试不满足迁移目标的方法，再回溯到完整方法，有限预算不足时报告失败。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Ref:
    node: str
    kind: type

def check_plan(nodes, catalog, allowed):
    if type(nodes) is not list or not nodes:
        raise ValueError("empty_plan")
    by_id = {}
    for node in nodes:
        if (type(node) is not dict or set(node) != {"id", "tool", "args", "deps"}
                or type(node["id"]) is not str or not node["id"]):
            raise ValueError("invalid_node")
        if node["id"] in by_id:
            raise ValueError("duplicate_id")
        tool = node["tool"]
        if type(tool) is not str or tool not in catalog:
            raise ValueError("unknown_tool")
        if tool not in allowed:
            raise ValueError("forbidden")
        if (type(node["args"]) is not dict or type(node["deps"]) is not tuple
                or any(type(d) is not str or not d for d in node["deps"])
                or len(node["deps"]) != len(set(node["deps"]))):
            raise ValueError("invalid_node")
        if set(node["args"]) != set(catalog[tool]["input"]):
            raise ValueError("invalid_args")
        by_id[node["id"]] = node
    colors, order = {}, []
    def visit(nid):
        if nid not in by_id:
            raise ValueError("missing_dependency")
        if colors.get(nid) == 1:
            raise ValueError("cycle")
        if colors.get(nid) == 2:
            return
        colors[nid] = 1
        node = by_id[nid]
        for dependency in node["deps"]:
            visit(dependency)
        for field, value in node["args"].items():
            expected = catalog[node["tool"]]["input"][field]
            if isinstance(value, Ref):
                if value.node not in node["deps"] or value.node not in by_id:
                    raise ValueError("undeclared_reference")
                if value.kind is not expected or catalog[by_id[value.node]["tool"]]["output"] is not expected:
                    raise ValueError("reference_type")
            elif type(value) is not expected:
                raise ValueError("input_type")
        colors[nid] = 2
        order.append(nid)
    for nid in by_id:
        visit(nid)
    return order

catalog = {"city": {"input": {}, "output": str},
           "population": {"input": {"city": str}, "output": int}}
plan = [{"id": "E1", "tool": "city", "args": {}, "deps": ()},
        {"id": "E2", "tool": "population", "args": {"city": Ref("E1", str)}, "deps": ("E1",)}]
assert check_plan(plan, catalog, set(catalog)) == ["E1", "E2"]
for broken, error in [(plan + [plan[0]], "duplicate_id"),
                      ([dict(plan[1], deps=("absent",))], "missing_dependency"),
                      ([dict(plan[0], deps=("E2",)), plan[1]], "cycle"),
                      ([plan[0], dict(plan[1], args={"city": Ref("E1", int)})], "reference_type")]:
    try:
        check_plan(broken, catalog, set(catalog))
        raise AssertionError("accepted_invalid_plan")
    except ValueError as exc:
        assert str(exc) == error
try:
    check_plan(plan, catalog, {"city"})
    raise AssertionError("permission_bypass")
except ValueError as exc:
    assert str(exc) == "forbidden"

OPERATORS = {"code": (frozenset(), "coded"),
             "test": (frozenset({"coded"}), "tested"),
             "migrate": (frozenset({"tested"}), "migrated")}
METHODS = {"ship": (("code", "test"), ("code", "test", "migrate")),
           "wrap": (("ship",),)}
GOAL = frozenset({"coded", "tested", "migrated"})

def htn(root_task="ship", max_depth=2, max_nodes=12):
    if any(type(x) is not int or x <= 0 for x in (max_depth, max_nodes)):
        raise ValueError("invalid_budget")
    remaining, attempts = [max_nodes], []
    def expand(tasks, state, path):
        if not tasks:
            return (state, path) if GOAL <= state else None
        (task, depth), rest = tasks[0], tasks[1:]
        if depth > max_depth:
            return None
        if remaining[0] == 0:
            return None
        remaining[0] -= 1
        if task in OPERATORS:
            pre, effect = OPERATORS[task]
            if not pre <= state:
                return None
            return expand(rest, state | {effect}, path + (task,))
        for method in METHODS.get(task, ()):
            attempts.append(method)
            # 只给当前compound的children加深；余下siblings保持自己的层级。
            children = tuple((child, depth + 1) for child in method)
            result = expand(children + rest, state, path)
            if result is not None:
                return result
        return None
    result = expand(((root_task, 0),), frozenset(), ())
    return {"status": "verified" if result else "search_failed_or_budget",
            "result": result, "attempts": attempts, "used": max_nodes - remaining[0]}

result = htn()
assert result["status"] == "verified" and len(result["attempts"]) == 2
assert result["result"][1] == ("code", "test", "migrate")
assert htn(max_nodes=2)["status"] == "search_failed_or_budget"
assert htn(root_task="wrap", max_depth=1)["status"] == "search_failed_or_budget"
assert htn(root_task="wrap", max_depth=2)["status"] == "verified"
METHODS["pair"] = (("ship", "ship"),)
assert htn(root_task="pair", max_depth=2, max_nodes=30)["status"] == "verified"
assert htn(root_task="pair", max_depth=1, max_nodes=30)["status"] == "search_failed_or_budget"
print("DAG 重复/缺依赖/循环/引用类型/权限拒绝；HTN 两方法回溯、迁移目标与总节点预算通过")
```

这个局部 validator 只支持一层参数、单类型引用和前置权限集合；没有 nested schema、撤权、并发执行、缓存或 replan 实现。HTN 对每个待办保存自己的层级：展开当前 compound 只让其子项深一层，余下兄弟任务保留原深度。共同节点预算不会因分支回溯复原，表示真实搜索成本；所有效果是教学事实集合，不能代表已经运行真实测试或迁移。

### 进化搜索的评价器不能随候选改写

seed→mutate→evaluate→select 可用于优化有机器评价的候选。正确性先于速度：排序需保持元素多重集且有序，SQL 需语义等价及权限合法，再评价固定负载中的时间或成本。训练集 fitness 变好不能证明留出集泛化。固定代数系数对十一点拟合和真实 AlphaEvolve 的程序搜索是不同实验，达到十二代也不等于收敛。噪声测量可以重复估计，确定性和速度是工程选择；候选不得修改独立 oracle、预算或验收集合。

## 五种工作流的选择条件

| 模式 | 要解决的问题 | 容易漏掉的合同 |
|---|---|---|
| 提示链 | 中间结果可验证，下一步按预定规则继续 | 中间 gate 与输出 schema；失败不继续 |
| 路由 | 不同任务应进入不同处理路径 | 合法候选、校准阈值、弃权/未知处理；标签不授权动作 |
| 分片/投票 | 独立部分汇总，或同题多个候选比较 | 真正并发、ID、覆盖、缺票、平票、单位与独立验证 |
| orchestrator-workers | 子任务集合取决于当前输入 | 动态任务分解、各 worker 状态/权限/预算、合并核验 |
| evaluator-optimizer | 清楚标准下反复改善产物 | 具体反馈、版本、有限迭代、最好合格产物保留 |

预定图可以有状态、循环、变长路径；动态 Agent 也受宿主图、权限和预算控制。不是“两步必须工作流、三步必须 Agent”。先以同一任务集建可解释基线，再增加有收益的动态选择或恢复机制；代码行数不能衡量框架价值或维护成本。完整路由、并行与通信合同分别沿已有[路由](02-路由.md)、[并行化](03-并行化.md)、[多智能体协作](07-多智能体协作.md)维护，本节只解释模式选择与缺失 gate。

### 02 的 Build / Use / Ship 与图示边界

**Build 的输入与预期**：France→Paris→人口→取整；源码实际有三步，人口 11.2M 与11M为人工都会区表，无日期。

**源码审读与失败反例**：依赖由 str(args) 正则抽取，但仅顶层字符串 resolve；重复 ID 会覆盖，工具失败字符串仍进下游，执行顺序且无并发。

**静态和动态含义**：静态 DAG 的 E1→E3 与实际只依赖 E2 不一致；动态图只计一次 planner+一次 solver 对比逐步调用，不是 token、延迟或端到端质量测量。

**Use / Ship 的开放判据**：按依赖/环境反馈选择静态取证或有限 replan。输出 planner 模板的 acyclic/引用/工具承诺需实际 validator；本章自写局部例不提供线上 executor。

## 部分观察下的计划：对他人信念建模

2026-10-10 增量吸收，承接本章的前置条件、计划修订和任务验收。自己知道的事实、他人看到的事实、自己对他人信念的推测，需要三个独立字段。

Sally 把物体放在 A，离开后 Anne 将它移到 B。世界事实是 B；若 Sally 没看到搬动，她的信念仍可能是 A。第一阶模型是“我认为 Sally 相信在 A”；第二阶是“我认为 Sally 认为 Anne 相信在 A”。不要把这些说法混为世界状态，也不要从一个动作唯一推断内心信念。

| 记录层 | 微型例子 | 使用边界 |
|---|---|---|
| 可观察世界 | token-1 现在在箱 B | 由可信环境回读更新 |
| 局部观察 | Sally 只见过它在 A | 保存观察时间与来源 |
| 一阶信念假设 | 我预测 Sally 会去 A | 可能存在其他解释，允许未知 |
| 二阶假设 | 我认为 Sally 以为 Anne 也只见过 A | 主体链、证据和更新时间要保持绑定 |

对协调计划有用的不是嵌套数量，而是**哪些行动取决于对方可获得的信息**。新消息到来时更新对应主体的假设，再重算受影响目标，不能顺便覆盖真实事实。多主体状态应保留身份、命题、证据、有效时间和未知/置信状态；过长链条增加身份混淆与推断误差，需要预算与停止规则。

[Li 等 v3](https://arxiv.org/abs/2310.10701v3) 在三代理部分观察的拆弹文字游戏中用显式信念状态改善规划与有效动作，结论限定于该模型、游戏和信息协议。[Riedl v4](https://arxiv.org/abs/2510.05174v4) 的群体猜数实验比较普通提示、个体角色、角色加“考虑他人行动”：普通条件也有时序信息协同，角色提示可形成稳定差异，增加 ToM 提示改善目标互补。高阶结构、正确预测和最终任务收益要分别测；提示引起的效果并不自动是假的，也不证明具有人的心理机制。

源三箱实验让 ToM 组预先看到他人的箱子偏好，而对照不看，差异同时包含额外信息。公平检查应采用四组：有/无信念跟踪，各自有/无偏好信息。同一初态、随机种子和观察权限下测冲突、完成率、回合与成本；再注入错误信念和延迟证据。信息分解需要目标、时滞、估计器和置换对照；成功率差不能直接叫 PID 高阶协同。此处不索取模型内部推理文本。

### 原课 18 的五项练习与参考判断

以下为中文重述与参考方法，未表示学习者已经完成原练习。

1. **把代理和箱子从三增加到五，怎样检查所谓七倍改善？** 不要预设七倍改善。原 ToM 组独享其他人的箱子偏好，而对照组没有这些信息。应比较“使用信念跟踪器/不使用”与“提供偏好信息/不提供”的四组合，同初态和观察权限，报告每次行动冲突、完成率与回合数。扩展到五箱后重新校验信息和统计分母。

2. **怎样实现并评价二阶心智模型？** 二阶状态可写为“我认为 B 认为 C 相信某事实”，保存主体、命题、来源和未知状态。需要设置 B 的行动确实依赖 C 信念的任务；比较预测准确性、任务收益、成本与身份绑定错误。加深嵌套本身不保证更好。

3. **每回合随机翻转一条信念，如何衡量退化？** 只扰动代理的外显信念，不改变真实环境；明确翻转概率、命题范围和目标主体，与相同随机种子的无扰动组比较行动误判、冲突和恢复回合。结果需实际运行取得，不能沿用源未实测百分比。

4. **把回合上限从十增到三十，能复现长上下文退化吗？** 不能。三个箱子每回合至少被一个尚未完成者取走一个，最多三回合即可收完，改上限不会制造论文中的上下文问题。应新增延迟证据、状态变化与长任务，并区分遗漏、身份绑定错误和状态幻觉；真实模型实验仍待做。

5. **怎样按 Riedl 的方法测高阶信息协同？** 需指定预测目标、时间间隔、离散化、偏差校正与部分信息分解方法，再做身份置换和时间置换对照。小程序的成功率差不是高阶信息协同统计量。提示引起的可重复结构变化可以有效，但结论必须限定干预与任务，不能把“依赖提示”自动判成虚假。
