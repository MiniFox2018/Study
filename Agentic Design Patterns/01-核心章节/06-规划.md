# 第 6 章：规划

## 本章定位

把高层目标分解为可执行步骤，处理依赖、顺序、资源与执行过程中的动态调整。

## 计划是可更新的依赖图

可执行计划至少包含目标、步骤、前置条件、预期产物、验证方式和停止条件。“先分析、再优化、最后完善”无法直接验收；“找到错误函数、复现失败输入、修改并通过该输入和回归测试”才可观察。

环境有变化时，只修订受影响步骤，并保存已经确认的事实。不要在未观察结果前假定工具成功，也不要用写出计划替代真正执行。

## 具体例子：整理一个文件夹

目标为“按已有规则给 8 个文件改名，并保留可恢复映射”。先列出现有文件 → 生成旧名/新名映射 → 检查重名与非法字符 → 执行允许的改名 → 回读目录核对 8 项。若出现目标文件已存在，应停在冲突项并更新映射，不能无声覆盖。

任务简单而规则稳定时，固定程序工作流更容易验证；只有下一步取决于未知反馈时，动态规划才有明显价值。开放任务也需要迭代预算和阶段成果。

## 自检与核对

**问题**：执行到第 3 步收到“目录已变化”，是否从头重做全部计划？

**核对**：先重读受影响状态，保留仍有效结果，重新核对依赖后继续；盲目重做可能重复副作用。状态和结果才是继续执行的依据。

## 来自《深入理解 AI Agent》的增量吸收

- 规划需要区分**确定性工作流**与**自主 Agent**：前者按预设步骤执行，后者根据环境和中间结果动态决定下一步。
- Coding Agent 展示了典型规划循环：理解任务 → 搜索/定位 → 修改 → 执行/验证 → 失败恢复 → 继续迭代。
- 长程机器人任务进一步强调任务分解、世界状态更新和局部动作控制之间的层级规划。
