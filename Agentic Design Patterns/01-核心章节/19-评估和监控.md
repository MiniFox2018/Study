## 本章定位

建立指标、测试集、运行监控与反馈闭环，对智能体质量和稳定性持续评估。

## 定义一次尝试与一次成功

评测数据应包含任务、环境初始状态、允许操作、期望结果及验证器。保存足以复现问题的外部轨迹，例如工具参数、状态与产物；不必收集模型内部推理文本，也不应无限保留敏感原始数据。

## 具体例子：区分可靠性与候选能力

同一任务最多生成 3 个候选，只要一个通过就算 `pass@3` 成功；连续执行 3 次都成功，衡量的是另一种可靠性。若每次成功率为 p 且独立，前者为 `1−(1−p)^3`，后者为 `p^3`。p=0.8 时分别为 0.992 与 0.512。真实尝试可能相关，不能机械套用独立公式。

一个系统要替用户自动执行一次任务，应重点看一次成功率、是否越权、是否可恢复和真实成本；不能用“多试很多次后总能挑到一个”的指标代替。

## 自检与核对

**问题**：对同一个固定测试集反复改提示，分数上升后能否证明泛化？

**核对**：不能，它已经成为开发/验证集。应保留从未用于调参的测试任务，按任务类型分组报告样本数与失败原因，并估计重复运行的不确定性。

## 来自《深入理解 AI Agent》的增量吸收

- 评估应从“单个答案打分”升级为对**任务、环境、轨迹、工具调用和最终结果**的系统评估。
- 指标需要区分能力上限与业务可靠性，例如 Pass@k 与连续成功概率关注的目标不同。
- 自动化评估可组合验证器、LLM-as-a-Judge、失败归因、端到端回归和轨迹前缀回归。
- 生产监控还应包含统计显著性、成本分析、可观测性、A/B 测试、消融实验、特性开关和隐私感知分析。
- 仿真环境既可用于评估，也可进一步作为后训练环境。

## 来自《动手学大模型应用开发》的增量吸收

### RAG 必须拆开评估

一个错误答案至少可能来自两类问题：

1. **检索失败**：正确证据没有进入上下文；
2. **生成失败**：证据已经检索到，但模型没有正确使用。

因此不能只看最终回答。应同时保留：

- **检索层**：Recall@k / Hit Rate、MRR、nDCG 等与业务相匹配的指标；
- **生成层**：正确性、相关性、基于证据的忠实度、引用质量；
- **端到端层**：最终任务成功率、用户结果、时延与成本。

### 从 Bad Case 建自己的评估集

- 先用少量真实问题建立基线；
- 把线上或测试中发现的 Bad Case 持续加入回归集；
- 同时保留 Easy/Good Cases，防止针对困难样例优化后出现能力退化；
- 每次修改分块、Embedding、Query 策略、top-k、Prompt 或模型后都重新跑同一评估集。

### 参数必须跟结果一起记录

RAG 实验至少记录：

- 分块方法、chunk size / overlap；
- Embedding 与索引配置；
- 检索策略和 top-k；
- Query 是否经过改写/分解；
- 生成模型与 Prompt 版本；
- 评估器版本。

否则分数变化无法归因，也无法复现。

### 评估驱动优化

不要预设“语义分块一定优于递归分块”或“多 Query 一定更好”。把每项改动视为假设，通过统一评估集验证后再进入生产。

## 从失败结果定位到调用边界

质量评测回答“完成任务了吗”，运行监控还要回答“时间花在哪里、哪个权限或数据边界失败了”。一个文档助手先生成工具调用，再检索证据，再合成答案；若用户看到 30 秒延迟，仅记录最后一次模型耗时无法区分模型排队、工具冷启动、重试或等待人工输入。先用前文的 case 与验证器判断结果，再用 trace 解释可观察的路径；trace 不能单独证明答案正确。

### Trace 的共同祖先与 Span 的直接父亲

一次 Trace 包含互相关联的操作。`traceId` 识别共同轨迹，`spanId` 识别某段操作，`parentSpanId` 指向直接父操作；共享 traceId 而父 ID 不存在，仍是断裂的树。每段要记录开始/结束、状态与版本，错误分支也必须结束 span。跨度包含等待响应与重试的逻辑时长；不得只计成功的最后一次尝试，抹掉先前的 timeout。

例如虚拟时间（毫秒）下，Agent 根区间 `[0,100]`，模型调用 `[2,20]`，工具调用 `[22,82]`，其 MCP 客户端 `[25,80]`，远端处理 `[28,75]`。工具的直接父亲是 Agent，MCP 客户端的父亲是工具，远端 server 的父亲是 MCP client。这里既有父子包含，又有不同操作；若已由 MCP instrumentation 充分覆盖同一次 tool call，不再为同一执行重复创建一个独立 GenAI 工具 span。不同的排队、传输、服务端处理可以分别测量，但不能把重复观测当两次业务调用。

远端调用通常是 CLIENT，接收请求的处理是 SERVER，同进程工作通常是 INTERNAL。GenAI `invoke_agent` 的远端调用可为 CLIENT；本地调用为 INTERNAL，不能给所有 Agent 根固定 INTERNAL。跨进程实际墙钟可能存在偏差，所以严格区间包含是本地受控实验的断言；真实分布式检查先核因果 parentage、结束完整性与时钟偏差。延迟用各自单调时钟测量，事件关联再保 wall-clock 时间。

并行两个子操作 `[10,50]` 与 `[10,70]` 时，持续时间和是 100ms，而经过时间只有 60ms。找端到端瓶颈应查看关键依赖路径、排队和重叠，不能简单累加所有 span duration。长任务等待人工一天不等于模型计算了一天；任务状态持续时间与执行 span 要分别记录。

### 固定 GenAI 约定，按字段适用性记录

2026-10-08 核验的官方 GenAI 资料已迁到 `open-telemetry/semantic-conventions-genai`，本次固定 `06ec68e722c45a7218e23ea1bc1339fe4e21ecae`。整体与本章涉及的 GenAI span/metric/event 仍为 **Development**，不能沿用来源“v1.37+ stable”的说法。OTel 核心协议稳定性与 GenAI 字段稳定性也不同。实施时一起固定 instrumentation、schema/semconv 与 exporter 版本，并在升级前比较字段和仪表盘。[官方 GenAI 入口](https://github.com/open-telemetry/semantic-conventions-genai/blob/06ec68e722c45a7218e23ea1bc1339fe4e21ecae/docs/gen-ai/README.md)。

| 操作 | 本次固定约定与填写方法 | 常见错因 |
| --- | --- | --- |
| 客户端推理 | `gen_ai.operation.name`、`gen_ai.provider.name` 为 required；request model 在可用时 conditionally required；response model、response ID、usage 按相应推荐/适用要求记录 | 把所有属性都叫必需，或把请求 alias 当实际服务的 model |
| 工具执行 | `execute_tool {gen_ai.tool.name}`，operation 与 tool name 为 required；tool call ID 可用时推荐；错误时记录 error.type | 用缺失的 provider/model 填假值，或把同一工具包装两次计数 |
| Agent 调用 | operation `invoke_agent`，按远端/本地选 kind；记录适用的 Agent identity | 根据框架名字决定跨进程与否 |
| 错误 | 结束 span，标 ERROR 与低基数 `error.type`，如 timeout/permission_denied；异常内容先脱敏 | 只有日志异常而 span 永不结束，或把完整秘密放进异常文本 |
| 指标 | `gen_ai.execute_tool.duration` 为 histogram，单位秒；样本与同一执行 span duration 一致 | 继承旧 `gen_ai.tool.execution.duration` 名字，或用毫秒样本写成秒 |

推理 span name 推荐 `{operation} {request.model}`；客户端不同供应商的 provider.name 值应按固定约定填写，例如官方示例含 `gcp.gen_ai` / `gcp.vertex_ai`，不要自创一个笼统 google 作为通用标准值。token 数以供应商 usage / 本地实际 tokenizer 为依据；`len(text)//4`、随机数只是教具。逻辑操作可包括全部自动重试，再用具体传输/尝试记录定位，费用账本仍需每次 attempt 的真实 usage。[客户端推理](https://github.com/open-telemetry/semantic-conventions-genai/blob/06ec68e722c45a7218e23ea1bc1339fe4e21ecae/docs/gen-ai/client-inference.md)、[工具与内容](https://github.com/open-telemetry/semantic-conventions-genai/blob/06ec68e722c45a7218e23ea1bc1339fe4e21ecae/docs/gen-ai/gen-ai-spans.md)、[指标](https://github.com/open-telemetry/semantic-conventions-genai/blob/06ec68e722c45a7218e23ea1bc1339fe4e21ecae/docs/gen-ai/gen-ai-metrics.md)。

### 跨边界传播：发送注入，接收提取

W3C version 00 的 `traceparent` 是 `00-{32位小写hex trace-id}-{16位小写hex parent-id}-{2位hex flags}`；两个 ID 均不能全零。出站 parent-id 是**本次发送操作的 span ID**，不是永远写根 span ID。接收方校验后以它为 remote parent 创建新的 server span。sampled 位用位运算读，`01` 是已采样示例，但采样标记不保证后端一定存到。[W3C Trace Context](https://www.w3.org/TR/trace-context/)。

MCP 传播层在创建 JSON-RPC 请求/通知时，通过配置的 propagator 注入 `params._meta.traceparent`，接收端从同一位置提取；`tracestate` 和需要的 baggage 也由相应传播器处理。固定官方 semconv 已明确无前缀的这三个键，不是“未来 roadmap”。同时保留 MCP 核心要求的 namespaced protocolVersion/clientCapabilities/clientInfo；HTTP 传输 trace 与单条 MCP trace 的父子/links 关系分别处理，stdio 没有 HTTP header 并不意味着不能传递 `_meta`。不要只给本地 span.attrs 写 traceparent 然后声称服务端已收到。[MCP context propagation](https://github.com/open-telemetry/semantic-conventions-genai/blob/06ec68e722c45a7218e23ea1bc1339fe4e21ecae/docs/gen-ai/mcp.md#context-propagation)。

该 semconv 的旧 initialize/session 示例不覆盖 MCP `2026-07-28` 核心契约；协议请求以[MCP 主章](10-模型上下文协议-MCP.md)的固定版本为准。无效 context 应丢弃并按策略新建 trace，不拒绝本来合法的业务请求；本例 parser 抛异常便于检查，生产 propagator 不可被直接替换为它。只支持 00 的教学 parser 也不是完整未来版本、tracestate 或 baggage 实现。

### OTLP 编码与接收证据

OTLP 是 **OpenTelemetry Protocol**。gRPC 使用 Protobuf；OTLP/HTTP 使用同一 schema 的二进制 Protobuf 或 JSON 编码。OTLP JSON 的 kind/status 枚举用整数，64位时间通常序列化为十进制字符串，属性是 typed key/value 列表，外层还要 resourceSpans 与 scopeSpans。A2A ProtoJSON 的枚举字符串不能机械搬到 OTLP JSON。[OTLP 官方规范](https://opentelemetry.io/docs/specs/otlp/)。

证据分四步：本地构建合法记录 → 实际序列化并发出 → collector 接收并校验 → 查询最终 backend。exporter 返回成功或 collector 的 Export 回应，只保证相邻节点的接收语义，不能证明最终 backend 已可查询；partial success 要读 rejected count/错误，不能把 HTTP 200 一概视为全成功，也不能收到 partial success 后盲目重发整批。最终集成至少在接收端核 traceId、spanId、parentSpanId、错误与记录数量，再检查后端查询和丢弃/队列指标。

### 可运行的传播、区间与模拟回执实验

输入是 version00 carrier 和虚拟事件区间，输出是五个 span、一个工具耗时样本，以及明示为 `fake` 的内存接收回执。client 请求经过 JSON serialize/parse，server 再 extract，因而确实跨过了本地数据表示边界；两者仍在同进程，未跨进程通信。测试故意传入全零、大写、错误长度/版本的 traceparent，并注入一个 timeout。typed payload 仅实现本例用到的标量属性，未用官方 proto 解码器做全面 OTLP conformance。

```python
import copy, json, re

def extract00(value):
    if not isinstance(value, str): raise ValueError('traceparent 类型')
    match = re.fullmatch(r'00-([0-9a-f]{32})-([0-9a-f]{16})-([0-9a-f]{2})', value)
    if not match: raise ValueError('本例只接受 version00 标准长度')
    trace, parent, flags = match.groups()
    if int(trace,16) == 0 or int(parent,16) == 0: raise ValueError('零ID')
    return trace, parent, bool(int(flags,16) & 1)
def typed(k, v):
    if type(v) is str: value = {'stringValue':v}
    elif type(v) is int: value = {'intValue':str(v)}
    elif type(v) is bool: value = {'boolValue':v}
    else: raise ValueError('本例只编码 str/int/bool')
    return {'key':k, 'value':value}
trace = 'a'*32
def span(i, name, kind, start, end, parent=None, attrs=None, error=None):
    row = {'traceId':trace, 'spanId':f'{i:016x}', 'name':name, 'kind':kind,
           'startTimeUnixNano':str(start*1_000_000), 'endTimeUnixNano':str(end*1_000_000),
           'attributes':[typed(k,v) for k,v in (attrs or {}).items()]}
    if parent: row['parentSpanId'] = parent['spanId']
    if error:
        row['status'] = {'code':2}
        row['attributes'].append(typed('error.type',error))
    return row
root = span(1,'invoke_agent fixture',1,0,100,attrs={'gen_ai.operation.name':'invoke_agent'})
llm = span(2,'chat fixture-model',3,2,20,root,
           {'gen_ai.operation.name':'chat','gen_ai.provider.name':'fixture',
            'gen_ai.request.model':'fixture-model'})  # fixture 是本地自定义 provider
tool = span(3,'execute_tool notes.search',1,22,82,root,
            {'gen_ai.operation.name':'execute_tool','gen_ai.tool.name':'notes.search'})
client = span(4,'tools/call notes.search',3,25,80,tool)
carrier = {'jsonrpc':'2.0','id':1,'method':'tools/call','params':{
    'name':'notes.search','_meta':{
      'io.modelcontextprotocol/protocolVersion':'2026-07-28',
      'io.modelcontextprotocol/clientCapabilities':{},
      'io.modelcontextprotocol/clientInfo':{'name':'fixture','version':'1'},
      'traceparent':f"00-{trace}-{client['spanId']}-01"}}}
received = json.loads(json.dumps(carrier))  # 模拟序列化，不是网络
remote_trace, remote_parent, sampled = extract00(received['params']['_meta']['traceparent'])
server = span(5,'tools/call notes.search',2,28,75,error='timeout')
server['traceId'], server['parentSpanId'] = remote_trace, remote_parent
spans = [root,llm,tool,client,server]

def check(rows):
    ids = {r['spanId']:r for r in rows}
    assert len(ids) == len(rows)
    assert len([r for r in rows if 'parentSpanId' not in r]) == 1
    for row in rows:
        start,end = int(row['startTimeUnixNano']),int(row['endTimeUnixNano'])
        assert 0 <= start < end
        if 'parentSpanId' in row:
            parent = ids[row['parentSpanId']]
            assert row['traceId'] == parent['traceId']
            assert int(parent['startTimeUnixNano']) <= start < end <= int(parent['endTimeUnixNano'])
    return True
assert check(spans) and sampled and server['parentSpanId'] == client['spanId']
for bad in [f"00-{'0'*32}-{client['spanId']}-01", f"00-{trace}-{'0'*16}-01",
            carrier['params']['_meta']['traceparent'].upper(), 'ff-'+trace+'-'+'1'*16+'-01', 'short']:
    try: extract00(bad)
    except ValueError: pass
    else: raise AssertionError('应丢弃无效 context')
broken = copy.deepcopy(spans); broken[-1]['parentSpanId'] = 'f'*16
try: check(broken)
except KeyError: pass
else: raise AssertionError('相同 traceId 不代表父子有效')
metric = {'name':'gen_ai.execute_tool.duration','unit':'s','value':(82-22)/1000,
          'attributes':{'gen_ai.tool.name':'notes.search'}}
payload = {'resourceSpans':[{'resource':{'attributes':[typed('service.name','fixture')]},
                            'scopeSpans':[{'scope':{'name':'study-fixture'},'spans':spans}]}]}
class FakeCollector:
    def __init__(self): self.received = []
    def accept(self, encoded, reject=0):
        batch = json.loads(encoded)['resourceSpans'][0]['scopeSpans'][0]['spans']
        if type(reject) is not int or not 0 <= reject <= len(batch): raise ValueError('拒收数')
        self.received.extend(copy.deepcopy(batch[:len(batch)-reject]))
        return {'fake':True,'accepted':len(batch)-reject,'rejected':reject}
fake = FakeCollector(); receipt = fake.accept(json.dumps(payload))
assert receipt == {'fake':True,'accepted':5,'rejected':0} and check(fake.received)
partial = FakeCollector().accept(json.dumps(payload),reject=1)
assert partial['rejected'] == 1 and partial['accepted'] != len(spans)
print('5 spans；remote parent、错误终结、区间通过；工具样本',metric['value'],'s；fake receipt',receipt)
```

### 隐私、采样与可评判指标

默认不记录 prompts、outputs 或完整工具参数，必要时明确 opt-in。当前约定中内容可放 `gen_ai.system_instructions`、`gen_ai.input.messages`、`gen_ai.output.messages` 或受独立访问控制的外部存储引用；部分 SDK span 属性尚不支持复杂对象，应按固定约定处理结构化 event 或 JSON string，不能把旧 `gen_ai.content.prompt/completion` 当永久标准名。来源自定义 `OTEL_CAPTURE_CONTENT` 与 semconv stability opt-in 也不是同一开关。

脱敏应在数据离开执行内存之前完成，秘密、凭据和私有文件不能先导出再由 dashboard 隐藏。trace ID 不作为身份或权限凭证；baggage 可能传播给第三方，应限制允许键与数据。避免把用户全文、task ID、每次 response ID 当 histogram 的标签；这些高基数值适合受控 trace 关联，不适合生成海量 metric time series。

时延至少区分端到端、等待首块、完整响应、工具与重试。p95 必须附时间窗口、样本数和任务切片，小样本分位数不能当稳定 SLA。错误率分母保留失败、拒绝、取消与 unknown；质量验证器独立记录。head sampling 节约记录成本但可能漏掉稀有错误，tail sampling 可按完整 trace 后的规则选样，但增加缓冲、等待和资源成本。没有采样权重或完整计数时，不用 sampled traces 直接估全流量错误率、总 token 或账单；总账由独立请求账本维护。

## 原课五项练习的答案与证明层次

1. **数 span/kind**：源码实际是 1 root + 2 LLM + 3 tool + 3 MCP = **9**，CLIENT 5、INTERNAL 4；没有 subagent，文档“两工具/一次MCP”和 SVG“11 spans”不符。动态 waterfall 的 5 条预设 row 另属教学图，不能当运行计数。本轮未运行原 emitter。

### 第23课：独立observer不等于执行门禁或导出门禁

SDK `add_trace_processor`是新增独立observer，保留默认出口；`set_trace_processors`替换processor集合。固定SDK会捕获一个processor的callback异常并继续调用其他processor，所以“先注册redactor，失败raise”不保证后面的exporter拿不到原数据。若导出以脱敏成功为条件，应在同一个应用拥有的exporter中序列化/复制→脱敏→仅交付脱敏副本，失败时丢弃batch、固定错误提示，不打印原payload/异常。替换设置要在运行前，不能删除旧processor已缓存的数据。

同理，执行前policy成功才可调tool；output guardrail可拒绝输出，却不能撤回已完成tool副作用；observer看日志后失败也不能叫执行前拦截。本地模拟把三者分开，输入含fake sensitive内容但只打印计数与固定消息，无SDK、网络或外部动作。

```python

def notify(processors, row):
    errors = 0
    for proc in processors:
        try: proc(row)
        except Exception: errors += 1  # 独立observer失败不阻止后续observer
    return errors

def export_owned(rows, destination, redactor):
    try:
        copies = json.loads(json.dumps(rows, allow_nan=False))  # 固定JSON子集，原对象不改
        safe = []
        for row in copies:
            cleaned = redactor(row)
            if set(cleaned) != {'trace_id','span_id','status'}: raise ValueError('字段白名单')
            if not re.fullmatch('[a-f0-9]{32}', cleaned['trace_id']): raise ValueError('trace ID')
            if not re.fullmatch('[a-f0-9]{16}', cleaned['span_id']): raise ValueError('span ID')
            if cleaned['trace_id'] == '0'*32 or cleaned['span_id'] == '0'*16: raise ValueError('全零ID无效')
            if cleaned['status'] not in {'ok','error'}: raise ValueError('status')
            safe.append(cleaned)
    except Exception:
        return {'status':'dropped', 'count':0}  # 不带异常/原数据
    destination.extend(safe)
    return {'status':'delivered_locally', 'count':len(safe)}

row = {'trace_id':'a'*32, 'span_id':'b'*16, 'status':'ok', 'prompt':'fake-sensitive-input'}
received = []
def failing_observer(_): raise RuntimeError('模拟observer失败')
assert notify([failing_observer, received.append], row) == 1
assert received[0]['prompt'] == row['prompt']  # 演示错误组合仍收到原内容
owned = []
allow = lambda r: {k:r[k] for k in ('trace_id','span_id','status')}
assert export_owned([row], owned, allow)['count'] == 1 and 'prompt' not in owned[0]
assert 'prompt' in row  # 脱敏只改副本
before = len(owned)
assert export_owned([row], owned, failing_observer)['status'] == 'dropped'
assert export_owned([dict(row, trace_id='private-user-name')], owned, allow)['status'] == 'dropped'
assert export_owned([dict(row, trace_id='0'*32)], owned, allow)['status'] == 'dropped'
assert export_owned([dict(row, span_id='0'*16)], owned, allow)['status'] == 'dropped'
assert export_owned([dict(row, extra=float('nan'))], owned, allow)['status'] == 'dropped'
assert len(owned) == before

effects = []
def guarded_tool(allowed):
    if type(allowed) is not bool or allowed is not True: raise PermissionError('只接受明确布尔allow')
    effects.append('fake_effect')
    return 'candidate'
try: guarded_tool(False)
except PermissionError: pass
assert effects == []
for malformed in ('false', 1, None, {}, float('nan')):
    try:guarded_tool(malformed)
    except PermissionError:pass
    else:raise AssertionError('truthy值不能代替明确许可')
assert effects == []
candidate = guarded_tool(True)
output_accepted = False  # 后置拒绝不会撤回effects
assert not output_accepted and len(effects) == 1
print('独立observer继续分发；自有出口失败丢批且不泄露；前置拒绝0副作用、后置拒绝保留1个fake副作用')
```

### 从人类完成时间到成功概率曲线

METR的task-completion time horizon用专家人类完成任务的时间表达任务难度，再找Agent在所测分布达到某成功概率的难度。**2小时的50% horizon不是Agent运行2小时的时钟上限，也不是任意2小时任务都恰有50%成功概率**。不同任务可能始终成功、始终失败或随机成功；拟合曲线概括这些混合结果。[官方方法与FAQ](https://metr.org/time-horizons/)

一个可理解的模型是：

$$
P(\text{success}\mid t)=\sigma(w\ln t+b),\qquad
\sigma(z)=\frac1{1+e^{-z}},\qquad w<0.
$$

这里`t>0`是固定单位的人类任务时间（下面用小时），`w`控制难度增大后成功率下降速度，`b`是截距。换成分钟会改变截距，不能混用单位。给定成功率`0<p<1`，解交点得到：

$$
t_p=\exp\!\left(\frac{\ln[p/(1-p)]-b}{w}\right).
$$

若`w=-1,b=ln(2)`，0.5、2、8小时任务的预测成功率分别为0.8、0.5、0.2；90%交点约0.222小时，50%为2小时，10%为18小时。**高可靠性对应更短任务，低可靠性容忍度对应更长任务**，源把10%叫conservative、90%叫optimistic，方向相反。90%交点不能不带条件就叫生产门槛，具体损失可能需要更高可靠性，也可能根本不允许自主执行。

这一逻辑只有在数据覆盖与拟合合理时成立。成功率几乎不随时间变化时，跨度交点可能无意义；斜率为正可能提示样本难度、预算或分布混杂；全部成功/失败可能导致不可辨识或分离；数据没覆盖交点则是外推，不是实测过那种任务。不能把函数返回的一个有限大数当“模型已经完成了这么长的任务”。

### 实验怎样构建，哪些口径不能混淆

1. **固定任务单元**：任务要有相关步骤、清楚初始条件与后置结果。连续做1000个独立一小时题仍是大量一小时任务，不是一个1000小时长任务。多步调试才可能体现持续状态与依赖。
2. **建立人类基线**：同样材料与可用条件下记录成功人类的完成时间与专业背景；通常合并使用几何平均。已有项目熟悉者与低上下文外包专家不同，基础难度估计也有误差。
3. **能力激发与留出**：在开发集选择scaffold/工具和合理预算，再在独立测试集运行；不得把反复调过的任务当未见评估。
4. **重复与评分**：留每任务多次尝试、真实产物、费用和效果。检查奖励漏洞、评分器篡改、预算不足和基础设施故障；重启与重评分要记录，不能静默删除失败。
5. **拟合与不确定性**：用完整成功/失败数据拟合，报告任务权重、区间、跨模型/设置差异。重复同一任务不是新增独立任务；不确定性估计要考虑任务聚类、人类基线误差和样本覆盖。

HCAST、RE-Bench和较短的软件任务覆盖的是软件工程、机器学习和网络安全为主的分布，不自动代表客服、设计、管理、真实研究协作或所有经济工作。自动评分干净任务与真实用户的模糊要求、背景信息、沟通及难以编码的验收条件不同；部署既可能更难，也可能因已有上下文、专用工具与人工协助更容易。时间跨度不能教成有数学保证的部署上界，更不能固定打10–40%或5–30%折扣来生成业务可靠性。

[RE-Bench原始研究](https://metr.org/blog/2024-11-22-evaluating-r-d-capabilities-of-llms/)包含**7个研究工程环境，而非源写的71项任务**：优化微调运行、优化GPU kernel、修复embedding、推断scaling law、受限架构语言建模、RL微调问答、编程题scaffolding。它比较预算内可取得的优化分数，允许把总电脑时间分配到多个尝试；多数环境可择优`score@k`，Scaling Law的反馈机制不同。它不是二值pass@1，也不代表自动化全部科研、论证研究新颖性或实验结论有效性。

另一种测量是monitor能否发现Agent执行未请求的旁任务，以及Agent能否规避monitor。应把旁任务成功、monitor检出、误报与真实后果分开；找到一类规避不等所有监控无效，未找到规避也不证明可忽略独立权限限制。实验中的sandbagging、奖励投机与评分数据污染也需分别定义。

### 如何读公开数字，如何建立自己的判断

2026-10-09官方time-horizons页标最后更新2026-09-08，并声明不再主动更新；页面还提醒当前任务集对16小时以上测量不可靠。源把某型号的2月更新数字写成1月TH1.1发布时的结果，不能继续使用。正式比较应记录数据发布日期、套件和模型/scaffold版本、成功率定义、区间及外推范围，不需要记住一个会变化的“14小时”。[官方更新记录](https://metr.org/time-horizons/#updates)

“多年趋势约每若干月翻倍”是对指定历史窗口的回归描述，窗口不同会给不同斜率；它不是未来保证，也不能算出某项安全实践还能安全使用多久。模型发布覆盖有缺口，外评者独立也不代表可访问所有模型、内部训练或所有风险场景。公开能力测量、厂商自评和当前应用的部署效果应分别保存。

实践上选自己的代表任务：如修复本项目bug，记录修复前状态、允许工具、文件范围、测试与人工语义审查，按人类难度和任务类型分层；不只选能自动评分的简单修复。对拟投产流程另外测正常完成、越权、严重失败、人工介入、真实时间和成本。低于公开horizon的任务也可能因分布不同失败，高于horizon也不一定一律做不到；把公开结果当背景信息，再用本地数据决定用途。

### 完整可运行例：拟合曲线、可靠性方向与外推标记

此例仅用3个合成分组的成功计数拟合logistic曲线。它验证数学方向、输入检查和外推提示，不含真实模型、METR数据、置信区间或生产验收。合成计数恰对应示意曲线，不能用它证明实际采样能精确恢复真值。

```python
import math


def finite_number(value):
    return type(value) in (int, float) and math.isfinite(value)


def sigmoid(z):
    if z >= 0:
        return 1 / (1 + math.exp(-z))
    e = math.exp(z)
    return e / (1 + e)


def fit(groups):
    # (人类时间小时, 成功次数, 总尝试次数)，二项负对数似然。
    if not groups:
        raise ValueError("没有样本")
    total = successes = 0
    checked = []
    for t, k, n in groups:
        if not finite_number(t) or t <= 0:
            raise ValueError("时间需为正有限数")
        if type(k) is not int or type(n) is not int or n <= 0 or not 0 <= k <= n:
            raise ValueError("计数无效")
        checked.append((math.log(t), k, n))
        total += n
        successes += k
    if successes in (0, total) or len({x for x, _, _ in checked}) < 2:
        raise ValueError("数据无法识别递减成功曲线")
    w, b = 0.0, 0.0
    for _ in range(10000):
        dw = db = 0.0
        for x, k, n in checked:
            error = n * sigmoid(w * x + b) - k
            dw += error * x
            db += error
        w -= 0.1 * dw / total
        b -= 0.1 * db / total
    if not finite_number(w) or not finite_number(b) or w >= -1e-8:
        raise ValueError("不是可识别的递减曲线")
    return w, b


def horizon(w, b, p, observed):
    if not all(finite_number(v) for v in (w, b, p)) or w >= -1e-8 or not 0 < p < 1:
        raise ValueError("参数或成功率无效")
    lo, hi = observed
    if not all(finite_number(v) for v in (lo, hi)) or not 0 < lo <= hi:
        raise ValueError("观测范围无效")
    log_t = (math.log(p) - math.log1p(-p) - b) / w
    try:
        t = math.exp(log_t)
    except OverflowError:
        raise ValueError("交点超过浮点表示范围") from None
    if not math.isfinite(t) or t <= 0:
        raise ValueError("交点不在正有限范围")
    return t, lo <= t <= hi


groups = [(0.5, 8, 10), (2.0, 5, 10), (8.0, 2, 10)]
w, b = fit(groups)
assert abs(w + 1) < 1e-6 and abs(b - math.log(2)) < 1e-6
values = {}
for p in (0.9, 0.5, 0.1):
    t, covered = horizon(w, b, p, (0.5, 8.0))
    values[p] = t
    print(f"成功率 {p:.0%}: {t:.3f} 小时；观测范围内 {covered}")
assert values[0.9] < values[0.5] < values[0.1]
assert horizon(w, b, 0.5, (0.5, 8.0))[1]
assert not horizon(w, b, 0.1, (0.5, 8.0))[1]

invalid_groups = [[], [(0, 1, 2)], [(1, True, 2)],
                  [(1, 2, 2), (2, 2, 2)],
                  [(1, 1, 10), (2, 9, 10)]]
for bad in invalid_groups:
    try:
        fit(bad)
    except ValueError:
        pass
    else:
        raise AssertionError("无效数据未拒绝")
for p in (0, 1, float("nan"), True):
    try:
        horizon(w, b, p, (0.5, 8.0))
    except ValueError:
        pass
    else:
        raise AssertionError("无效成功率未拒绝")
print("5类无效数据与4类无效成功率拒绝；外推未伪装成观测")
```

源模拟用随机翻转失败为成功，演示的是**人为改动观测标签**如何改变拟合结果；它没有测到模型识别评估环境、sandbagging或部署差距。原fit没有空集、无效时间、样本类型、同类结果等完整校验，近零斜率异常处理也不能解决所有不可识别问题。真实代码应做收敛诊断、任务权重/相关性处理和不确定性评估；不能机械拿这个最小教学函数替代METR分析实现。

### 第21课五项练习参考答案

1. **合成真值与时间网格怎样核？** 看拟合误差、随机种子/样本数、预算和覆盖；有限伯努利样本不保证恰回真值。把所有人类时间除2会把相同结果的跨度单位缩半，不是模型能力突然变弱；改变采样网格则可能因覆盖与权重影响估计。
2. **TH1.1哪些任务高/低可靠性？** 要看对应套件、模型/scaffold和逐任务重复数据，不从聚合50%推出所有任务相同。源只给研究主页入口，未提供逐任务结果；本轮未下载/运行真实逐任务测量，不能编造某型号最难任务排名。
3. **HCAST怎样用于自己业务？** 用软件工程、ML、网络安全等任务类型对照业务，增加欠覆盖的上下文、协作与验收；写清分组权重与来源。内部客服任务与HCAST差异大时，不能以重新赋权就假称有等价horizon。
4. **把约20%失败翻成成功会怎样？** 这是标签污染敏感性实验：同一真实任务不变、观察成功变多，曲线可能右移或形状改变。量的是拟合对失真数据敏感，而不是自动得到“20%gaming造成固定提升”；应复核评分器与真正产物。
5. **怎样设计内部跨度评估？** 选代表bug而非只选可自动测题、独立人类基线、固定权限/预算、开发与测试分开、每任务重复、盲审后置效果、区间和外推标记。给真实正常/严重失败单独指标；外部排名或模型的某小时数字不能代替投产证据。

**图示、使用与交付边界**：静态成功曲线、50%交点以及人为“gaming”右移用来理解坐标含义；注册动态图是预设点与Bezier，没有真实logistic拟合或区间。右移不等已观察某模型欺骗，固定折扣与增长预测不采纳。可交付的是有版本的任务/基线、评分及产物账本、拟合与区间、局限和业务验证；源Skill的“过一年数字必失效”“固定部署折价”和production拒绝条件不是统计规律或本任务门禁。
