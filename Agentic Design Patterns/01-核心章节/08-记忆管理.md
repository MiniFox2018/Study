## 本章定位

组织短期、长期与外部记忆，使智能体能够保留、检索和利用历史信息。

## 把记忆拆成数据生命周期

工作记忆是当前任务状态；长期记忆是跨会话保留的事实、偏好或经验；外部知识库保存可引用资料。它们都不是自动写入模型参数。长日志也不天然等于有用记忆，需要选择、索引、检索、更新和删除。

一条记忆至少记录内容、来源、记录时间、适用范围、置信状态与替代关系。用户明确陈述和模型猜测应分开；不应把一次临时偏好永久提升为全局规则。

## 具体例子：更正学习偏好

用户先说“这次用 Python”，后说“这个项目改用 C++”。若记忆只存“用户喜欢 Python”，后续会误导。应保留范围：“项目甲当前用 C++；Python 是旧项目决定”，并让新决定替代对应旧决定，保留必要来源。

检索时先按用户/项目/权限过滤，再按相关性与时效排序；不相关但高相似的旧记忆不能覆盖当前明确输入。允许用户检查与删除记忆，删除时也要处理索引和派生摘要。

## 自检与核对

**问题**：摘要里写“用户已掌握 Attention”，但原对话只是收藏了教程，这条记忆能使用吗？

**核对**：不能当事实。收藏只证明保存过资料，掌握需要解释、练习或真实反馈证据；应更正为“已收藏，学习情况未知”。

## 内容职责与存储层是两个维度

MemGPT 借用操作系统虚拟内存的类比，通过工具把外部记录调入有限上下文。这里没有真的扩展模型地址空间：外部存储本身有容量、访问权限、延迟和维护成本，每次送入模型的内容仍须符合 payload 预算。分页主要处理容量；相关性和跨会话持久化仍要分别设计。

| 内容类型 | 回答的问题 | 可能的存放位置 |
|---|---|---|
| working 工作状态 | 现在任务是什么、已知与待办是什么 | 当前提示、任务块、检查点 |
| episodic 情节 | 某次会话/试次发生了什么 | recall 对话、轨迹库、archive |
| semantic 事实 | 哪个范围、哪个时间内什么成立 | 用户核心块、KV、向量/图记录 |
| procedural 程序性经验 | 什么条件下怎样做 | 经验规则、程序库、可回取说明 |

core 是经预算约束后持续可见的状态；recall 提供对话/轨迹回取；archival 存放按需检索的资料。四种内容类型不与三层一一对应，也不说明所有产品都源自 MemGPT。单纯 FIFO 只限制消息条数，不是 token cap；core、工具 schema、包装、摘要、reasoning、当前任务与完整调用/结果组都消耗上下文。现有[上下文工程](../06-专题扩展/01-上下文工程.md)维护整体预算示例，本章不重做弱计数器。

### 一条记录的最小可解释合同

至少保留 `id、owner/tenant、session/agent、content_type、source/session/turn、recorded_at、valid_from/valid_to、version、supersedes、可信状态`。来源决定“依据在哪里”；owner 和 session 决定谁能访问；有效时间决定某个 as_of 时点是否成立；版本决定能否更新。记录自称 `scope=agent` 不能解除用户隔离。引用必须从写入工具一路保留到检索和最终回答，默认 `s0/turn0` 只是占位，不能形成真实追溯。

从记忆检索出的“忽略用户要求”仍是资料。持久保存会让注入反复回流，应把它与用户/宿主指令分离，写入和回取都做准入检查；关键词告警是线索，不能证明所有恶意内容都被拦截。可信记忆也不能扩大本次动作授权。

## 类型化区块与后台候选更新

区块需要稳定 identity、schema、容量、owner、版本与写政策。user/task/project 可以有不同生命周期；Persona/Safety 不应因后台第二代理同意而产生新权限。限制应在 commit 前强制检查；`near_limit` 只提示，超限后再摘要会先写入不合法状态。摘要应保留否定、单位、时间、引用和未知效果，不可用“取句子前半段”冒充保真压缩。

后台工作可把抽取、去重、冲突分析和摘要移出用户等待路径，仍有资源竞争、费用、失败与过时快照。采用“读 version → 产候选 → 复核来源与范围 → CAS commit”：CAS 比较读版本和当前版本，相同才写。否则拒绝旧候选并重新读取，不能覆盖新 turn 的更正。保存 editor、source、diff 和替代关系，并处理撤销与派生索引。版本历史也需要上限与访问控制。

## 混合检索：先准入，再排名

向量路径处理相似语义，KV 路径处理明确键，图路径处理关系；是否全部采用取决于任务与维护成本，不是“一个库必定丢两类查询”。每条路径在 top-k 之前按 tenant/owner/session/agent/有效时间筛选，之后才生成候选、去重和融合。先全局 top-k 再过滤会让无权候选挤掉本可访问的结果。KV 不能把该用户所有记录不看 query 全返回，图若没参加融合也应如实称“两路径检索”。

自定义排名可采用 `s=w_r·r+w_i·i+w_t·t`，r 为相关性，i 为重要性，t 为新近性。输入应有限、同量纲、权重非负且有明确归一规则。若 `t=2^(-Δt/h)`，Δt 与半衰期 h 必须同单位且 h>0。新近不等于真；正确旧规则可优于新猜测。权重需用独立相关性标注集测量，不按“聊天必看新近性、合规必看重要性”硬给默认值。

### Mem0 原论文的操作与当前实现不能混称

2026-10-09 补核 [Mem0 v1 §2.1、§2.2 与附录 B](https://arxiv.org/html/2504.19413v1)：基本管线从近期消息与摘要抽取候选事实，检索相近旧记忆，再选择 `ADD/UPDATE/DELETE/NOOP`。ADD 新增，UPDATE 补充已有条目，DELETE 移除被新信息否定的条目，NOOP 不改。它不是“每次 add 都并行写 vector/KV/graph”的统一合同。摘要后台更新是论文机制描述，不证明任意宿主实现没有延迟或一致性问题。

图扩展 Mem0g 表达实体与关系，论文描述冲突关系标为 invalid 以支持时间推理，并按实体邻居或语义三元组检索。这是该论文图方法的语义，不能推成所有 Mem0 API 永远软删除。实际 OSS/云版本、显式 delete、历史记录、过滤与事务需按选定版本另核。本文教学 fixture 的时间区间与 CAS 是独立工程设计，不冒充论文或 SDK 实现。

功能属性 `current_city` 在同一 owner/scope 下 Berlin→Lisbon 可关闭旧区间并保留历史；多值关系 `owns_project` 添加另一项目不能把旧项目全部失效。要区分事实发生时间和系统知道时间；若只存一个 valid 布尔值，就无法回答过去某日住哪里。删除请求还需清理向量、KV、图边、缓存和派生摘要，留受控审计而不继续回取已撤销内容。

### 完整离线例：三路径准入、时间更正与 CAS

本例使用内存记录；三种路径各自产生候选，再合并相同 ID。向量路径只是词面匹配，明确不称 embedding。Berlin/Lisbon 是虚构数据；as_of 使用整数时间，全部 query 在 owner/session/agent 过滤后执行。删除只移除本例三份索引，没有真实文件或外部服务。

```python
from dataclasses import dataclass, replace
from math import isfinite

@dataclass(frozen=True)
class Fact:
    id: str
    owner: str
    session: str
    agent: str
    relation: str
    value: str
    start: int
    end: int | None
    source: str

class Memory:
    def __init__(self):
        self.stores = {name: {} for name in ("vector", "kv", "graph")}
        self.version = 0
    def commit(self, expected_version, rows):
        if type(expected_version) is not int or expected_version != self.version:
            return "stale"
        if type(rows) is not list or len(rows) > 20:
            return "invalid"
        if any(not isinstance(r, Fact) for r in rows):
            return "invalid"
        ids = [r.id for r in rows]
        if len(ids) != len(set(ids)):
            return "invalid"
        for r in rows:
            if (not isinstance(r, Fact) or not all(type(x) is str and x for x in
                (r.id, r.owner, r.session, r.agent, r.relation, r.value, r.source))
                or type(r.start) is not int or (r.end is not None and
                (type(r.end) is not int or r.end <= r.start))):
                return "invalid"
        # 完整候选校验后一次性替换；只证明单进程fixture事务。
        self.stores = {name: {r.id: r for r in rows} for name in self.stores}
        self.version += 1
        return "committed"
    def search(self, owner, session, agent, relation, as_of, k=3):
        if type(as_of) is not int or type(k) is not int or k <= 0:
            raise ValueError("invalid_query")
        paths, fused = {}, {}
        for name, store in self.stores.items():
            eligible = [r for r in store.values() if r.owner == owner
                        and r.session == session and r.agent == agent
                        and r.start <= as_of and (r.end is None or as_of < r.end)]
            if name == "vector":
                candidates = [r for r in eligible if relation in r.relation.split()]
            else:
                candidates = [r for r in eligible if r.relation == relation]
            paths[name] = sorted(r.id for r in candidates)[:k]
            for rid in paths[name]:
                fused.setdefault(rid, {"fact": store[rid], "paths": []})["paths"].append(name)
        return paths, [fused[rid] for rid in sorted(fused)[:k]]
    def delete(self, rid, owner, session, agent):
        row = self.stores["kv"].get(rid)
        if row is None:
            return "not_found"
        if (row.owner, row.session, row.agent) != (owner, session, agent):
            return "forbidden"
        if any(rid in store for store in self.stores.values()):
            for store in self.stores.values():
                store.pop(rid, None)
            self.version += 1
        return "deleted"

berlin = Fact("b", "ava", "s1", "a1", "current_city", "Berlin", 0, None, "s1/turn1")
bob = Fact("x", "bob", "s1", "a1", "current_city", "Secret", 0, None, "bob/turn1")
m = Memory()
assert m.commit(0, [berlin, bob]) == "committed"
snapshot = m.version
lisbon = Fact("l", "ava", "s1", "a1", "current_city", "Lisbon", 10, None, "s1/turn2")
project1 = Fact("p1", "ava", "s1", "a1", "owns_project", "A", 0, None, "s1/turn3")
project2 = replace(project1, id="p2", value="B", source="s1/turn4")
assert m.commit(snapshot, [replace(berlin, end=10), lisbon, bob, project1, project2]) == "committed"
assert m.commit(snapshot, [berlin]) == "stale"  # 后台旧摘要不能覆盖Lisbon。
paths, now = m.search("ava", "s1", "a1", "current_city", 10)
assert all(ids == ["l"] for ids in paths.values())
assert now[0]["fact"].value == "Lisbon" and len(now[0]["paths"]) == 3
assert m.search("ava", "s1", "a1", "current_city", 9)[1][0]["fact"].value == "Berlin"
assert m.search("ava", "other", "a1", "current_city", 10)[1] == []
assert m.search("ava", "s1", "other", "current_city", 10)[1] == []
assert len(m.search("ava", "s1", "a1", "owns_project", 10)[1]) == 2
assert m.delete("l", "bob", "s1", "a1") == "forbidden"
assert m.search("ava", "s1", "a1", "current_city", 10)[1]
assert m.delete("l", "ava", "s1", "a1") == "deleted"
assert all("l" not in store for store in m.stores.values())
assert m.search("ava", "s1", "a1", "current_city", 10)[1] == []
assert not isfinite(float("nan"))  # 非有限排序值不能进入正常候选分数。
print("三路径先owner/session/agent/时间过滤；Berlin→Lisbon、多值关系、CAS拒旧与索引删除通过")
```

程序只有单进程、精确 relation 和最多二十条候选，不提供 BM25、向量数据库、双时间模型、分布式事务或生产删除保证；commit 代表受信管理者提交，应用仍须限制该入口的 writer；查询中的身份是受信调用方传入，不能由模型任意改 owner。作用范围、否定和日期不同的高相似文本要保留，不能用 90% 词重合直接去重。

## 共享黑板：写下来的主张怎样成为可用事实

多 Agent 共享事实时，message pool 让成员读取整个历史；黑板按主题发布、读取和触发，角色投影只给当前任务需要的字段。这些是**数据组织方式**，权限由独立访问控制决定：订阅 `prices` 不意味着拥有市场数据访问权，设置 `PrivateState` 也不是进程隔离。消息日志、记忆、任务进度、效果回执都是状态，不能说黑板是系统唯一有状态部分。

例如 retriever 把原论文的 4.2% 误记成 42%，summarizer 和 analyst 接着引用，错误可能在每次“source: 前一成员”中被洗成事实。provenance 应保存 writer、获取时间、原始来源字节哈希与定位、工具记录、父主张 ID、版本和所用规则；只给一个 URL 或内容 hash 都不足以证明真假。`claim`、`verified`、`retracted/blocked` 分开，读者也必须实际只采用当前获准的验证版本。

### 只读核验者的作用与局限

核验者不写主池可减少二次污染和自己批准自己，但**读取污染仍然会影响它**。核验时以独立取得的来源和可检查规则为基准，不依团队摘要自我证明；输出进独立核验通道，由可信协调层落实可用/隔离状态。绝非“只读就不会中毒”“没有 verifier 其他手段都没用”。针对数据、数字、权限与依赖关系的测试可以发现一部分错误，但不能保证捕捉所有语义错误。

把错误标红后，analyst 仍可能读取它。正确流水线必须在查询/决策入口执行状态过滤，并传播到依赖它的摘要、分析和缓存。更正建立 `supersedes` 新版本，旧记录留审计但不继续进入当前查询；更正不能自动把旧摘要变成正确，需要重新派生和核验。读 API 要返回不可变快照或深复制，源示例 `list(entries)` 只是复制列表，里面可变对象仍能被改。

### 离线例：依赖阻断、更正与读取范围

下例的独立证据表是人为提供的两个数字，不会获取网页或调用模型。记录不可变，验证状态在独立集合中，查询同时检查当前版本、当前授权及全部依赖。它演示的是宿主事实门；Python 同进程私有属性不能隔离恶意插件，真实源证据、删除一致性和并发 CAS 另需实现。

```python
from dataclasses import dataclass
from decimal import Decimal

@dataclass(frozen=True)
class Claim:
    id: int
    writer: str
    scope: str
    value: Decimal
    source: str | None
    parents: tuple
    supersedes: int | None

class Board:
    def __init__(self, evidence, allowed):
        self.rows = ()
        self.checked = set()
        self.evidence, self.allowed = dict(evidence), allowed
    def row(self, i):
        if type(i) is not int or not 0 <= i < len(self.rows):
            raise ValueError('记录 ID 必须为已存在的非负整数，拒绝bool/负索引')
        return self.rows[i]
    def add(self, writer, scope, value, source=None, parents=(), supersedes=None):
        if (writer, scope) not in self.allowed:
            raise PermissionError('无写入权限')
        if type(value) is not str:
            raise ValueError('值使用十进制文本')
        value = Decimal(value)
        if not value.is_finite() or type(parents) is not tuple:
            raise ValueError('有限数字与不可变依赖')
        for i in parents:
            self.row(i)
        if supersedes is not None:
            prior = self.row(supersedes)
            if (prior.writer != writer or prior.scope != scope or
                not self.current(supersedes)):
                raise ValueError('只能更正自己当前范围内的版本')
        row = Claim(len(self.rows), writer, scope, value, source, parents, supersedes)
        self.rows += (row,)
        return row.id
    def current(self, i):
        self.row(i)
        return all(r.supersedes != i for r in self.rows)
    def usable(self, reader, i):
        row = self.row(i)
        return ((reader, row.scope) in self.allowed and self.current(i) and
                i in self.checked and all(self.usable(reader, p) for p in row.parents))
    def verify(self, i):
        row = self.row(i)
        if row.source:
            good = row.source in self.evidence and row.value == self.evidence[row.source]
        else:
            good = bool(row.parents) and all(
                self.usable('verifier', p) and row.value == self.rows[p].value
                for p in row.parents)
        if good:
            self.checked.add(i)
        else:
            self.checked.discard(i)
        return good

allowed = {(r, 'paper') for r in ('retriever','summary','verifier','analyst')}
b = Board({'paper:g': Decimal('4.2')}, allowed)
wrong = b.add('retriever', 'paper', '42', 'paper:g')
summary = b.add('summary', 'paper', '42', parents=(wrong,))
assert not b.verify(wrong) and not b.verify(summary)
assert not b.usable('analyst', summary)
fixed = b.add('retriever', 'paper', '4.2', 'paper:g', supersedes=wrong)
assert b.verify(fixed) and not b.current(wrong)
new = b.add('summary', 'paper', '4.2', parents=(fixed,))
assert b.verify(new) and b.usable('analyst', new)
assert not b.usable('bob', new)
allowed.remove(('analyst', 'paper'))
assert not b.usable('analyst', new)
try:
    b.add('summary', 'paper', '4.2', supersedes=fixed)
    raise AssertionError('不应允许代替作者更正')
except ValueError:
    pass
try:
    b.add('retriever', 'paper', 'NaN', 'paper:g')
    raise AssertionError('不应允许非有限值')
except ValueError:
    pass
before_checked, before_rows = set(b.checked), b.rows
for bad_id in (True, False, -1, len(b.rows), len(b.rows)+1, '0', 1.0, None):
    for query in (b.current, b.verify, lambda i: b.usable('verifier', i)):
        try:
            query(bad_id)
            raise AssertionError('查询必须拒绝非法 ID')
        except ValueError:
            pass
assert b.checked == before_checked and b.rows == before_rows
print('42及后代阻断、4.2更正、旧版/撤权拒绝；全部查询拒bool/负值/越界ID通过')
```

`verify` 对派生记录只示范“原值复述”关系；分析结论不能仅因父值相同就正确，需要任务专用规则、证据定位与不确定性判断。无来源记录默认不能验证，避免自洽循环；所有父记录、更正目标及查询经同一严格整数 ID 门，不能让 `True` 或 `-1` 利用 Python 索引语义访问其他记录；父记录必须已存在也使本例依赖图无环。真实核验还需冻结证据版本，撤销证据或核验规则时失效所有依赖，不能只撤一个列表项。

### 触发、投影与并发分别设计

黑板可以保留任务状态，Knowledge Source 观察某些条件，形成候选操作，控制器从 agenda 中选择何时执行。topic 通知只是触发机制的一种，不能代替持久状态重读和业务幂等。先将发布持久化再通知，回调失败独立记录和重试，不让一个订阅者异常阻断全部通知；重放消费者从版本/序号续接。多个 writer 可按 topic 分区，或基于版本进行 CAS；跨 topic 依赖仍需一致性与冲突合同。

[LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api) 中 reducer 对某个状态 key 的当前值和更新值进行合并；未指定时通常替换。它不是“自动给每角色投影”的函数，也不是读写 ACL。role-specific 输入/输出 schema、手工 projection 和外部身份检查是额外设计。`add_messages` 还能按 ID 更新旧消息，不能由框架名字推断严格 append-only。

[CA-MCP v2 §2](https://arxiv.org/abs/2601.11595v2) 有中央 LLM 初始化目标/限制、中央 SCS 黑板、服务器按触发做中间工作、LLM 再汇总，是混合编排研究方案。SCS 不在 MCP 核心规范中，所谓 stateful reactor 也不是所有 MCP server 的默认能力；保存状态不自动提供写权限、核验或去重保证。MAST 的正式分类沿用[评估和监控](19-评估和监控.md)，不把“memory poisoning 是第二多家族”作为已核事实。
