# 维护与更新说明

遵循[Study 项目规则](../../PROJECT_RULES.md)。当前阶段优先修正已有内容、补必要例子与验证，不因看到新资料就增加主题。

## 每次修改的最小记录

```text
更新日期：
修改位置：章节/小节
修改原因：原句哪里错、缺什么或什么条件已变化
修改内容：新的表述与适用范围
核验依据：原始 URL、论文版本或软件版本
验证方式：手算/脚本/实际运行/仅查文档
验证结果与限制：实际结果、未核实项
```

提交标题、更新备注、检查提示和待办说明使用中文；例如“修正 DPO 参考策略说明并补充数值例子”。保留 API 名称、错误码和代码标识，避免翻译破坏可检索性。

不要把“读过目录”写成“读完正文”，不要把“文档中有功能”写成“已在本机验证”。教程代码运行后记录环境、命令与结果；教学例子标明是示例，自己的学习完成状态只能依据实际练习填写。

正文改动后检查相对链接、标题、公式和代码块；涉及一个概念的修正，搜索其他章节是否存在矛盾。来源保全保留来源上下文，主库在原章节修订，避免同时维护两份解释。协议/API 变化时更新对应主章节和核验记录，不能只在首页加“可能过时”。
