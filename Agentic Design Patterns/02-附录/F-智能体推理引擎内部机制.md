# 附录 F：智能体执行循环内部机制

这里的“引擎”指 Agent 编排程序，不是 LLM 内核或不可见的内部思维。LLM 推理性能另见[推理与服务化](../../LLM%20工程实践/03-推理与服务化.md)。

```text
读取目标与已确认状态
→ 构造本轮上下文
→ 调用模型
→ 解析答案或工具请求
→ 校验权限与参数
→ 执行并记录观察
→ 检查完成条件/预算/等待状态
→ 继续、等待、失败或结束
```

一次循环至少保存任务 ID、当前状态、已确认产物、待处理调用及可恢复检查点。循环上限只是资源控制；达到上限应标为“未完成/需继续”，不能自动视为成功。模型声称“完成”后仍需运行外部验收。

**练习**：工具请求发出后进程崩溃，重启时不知道是否已经执行。**核对**：恢复程序先查询任务/幂等键对应状态，再决定重试；不能直接再次执行有副作用的动作。可观察外部轨迹用于排障，不要求记录内部推理文本。
