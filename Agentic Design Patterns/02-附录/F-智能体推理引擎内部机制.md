# 附录 F：智能体执行循环内部机制

这里的“引擎”指 Agent 编排程序，不是 LLM 内核或不可见的内部思维。LLM 推理性能另见[推理与服务化](../../LLM%20工程实践/03-推理与服务化.md)。

```text
读取目标与已确认状态
→ 构造本轮上下文
→ 调用模型
→ 解析答案或工具请求
→ 校验权限与参数
→ 执行并记录观察
→ 检查完成条件/预算/等待状态
→ 继续、等待、失败或结束
```

一次循环至少保存任务 ID、当前状态、已确认产物、待处理调用及可恢复检查点。循环上限只是资源控制；达到上限应标为“未完成/需继续”，不能自动视为成功。模型声称“完成”后仍需运行外部验收。

**练习**：工具请求发出后进程崩溃，重启时不知道是否已经执行。**核对**：恢复程序先查询任务/幂等键对应状态，再决定重试；不能直接再次执行有副作用的动作。可观察外部轨迹用于排障，不要求记录内部推理文本。

延伸：[目标设定](../01-核心章节/11-目标设定和监控.md)、[异常恢复](../01-核心章节/12-异常处理和恢复.md)。更新：2026-10-02。


## 一个能手核的Agent循环：比较两个月账单

以4月12400、5月15500的合成账单为例，需求是增额与增幅。检索把两张对应账单及来源ID放入上下文，记忆只提供“货币用USD、同时给百分比”的偏好；模型提出计算请求，运行时先查参数与工具权限，再调用并把结果作为观察返回；下一轮模型据观察作答，外部检查器核数字和引用，最后输出明确状态。

增额15500−12400=3100；相对4月增长是3100/12400=25%，不是除以5月得到的20%。问题若反过来问5月到4月下降，基数改为15500，下降20%。先声明比较方向和分母，再选计算器；工具成功返回一个数不代表分母符合问题。

该来源的机械动画用八张卡表示上下文、四轮上限表示控制器、三次工具尝试表示局部重试；真正model是固定分支脚本，检索也是英文月份关键词过滤，没有调用LLM、向量库或真实网络。卡槽只是条数上限，不是token预算；图中时间是事件的预设代价累加，不是推理性能测量。原参考程序未在本次执行。

| 情景 | 脚本过程 | 最终状态的含义 |
|---|---|---|
| 正常 | 检索两账单→提出工具→schema/权限→算3100与25%→复核 | verified，仅在声明的窄检查范围内 |
| 无检索、保验证 | 先猜15%→无依据被退回→明确无法计算 | declined，不伪造账单 |
| 无检索、也无验证 | 猜15%直接离开 | unchecked，未核不等于已证错或已证对 |
| 一次超时 | 首次失败→等500ms→第二次成功 | 局部有界恢复 |
| 一直超时、保验证 | 3次失败，退避500/1000ms→脚本心算20%→检查指错分母→25% | 修正后的数值通过窄检查 |
| 一直超时、无验证 | 20%直接离开 | unchecked，示例恰好是错的 |
| 参数把12400写成带币符字符串 | schema拒绝→错误回到下一轮→重新用number | 参数修复不等于绕过权限 |
| 关闭工具 | 权限拒绝，不执行计算器→脚本草稿仍须核数字 | 不把格式合法当获准调用 |

健康轨迹是intake、memory、retrieve、model、schema、permit、execute、observe、model、verify、exit，共11事件/2模型轮/1工具提议/1实际尝试。把预设计时20+30+180+900+2+1+40+5+900+12+5相加是2095个虚拟毫秒；一次超时再加2000+500为4595。它们只用来核状态模型的账，不是某模型的延迟、费用或SLO。calls统计工具提议，格式被拒的提议也计入；attempts才是进入执行重试的次数。

上下文在条数超8时优先丢最早非request/doc卡片，可能先丢记忆/反馈，而不是智能决定哪些事实最重要。实际系统应按token、任务状态和证据保留合同管理，不能机械照搬卡槽规则。turn上限耗尽返回failed，不把“停止了”当“做完了”。

检查器也有教学限制：它只核结构化money/pct claims与上下文账单，不解析自由文本是否与claims一致；空claims直接允许，未知claim类型未拒。引用仅检查ID都在检索集合且长度至少2，没有验证恰好两张所需账单各一次：重复同一有效ID两遍仍可能过关。正式验收应核所需引用集合、声明类型与文本/结构化结果的一致性，检查证据真伪与版本；不能复述图中“确定性检查能抓错”而省掉它的合同范围。

练习：不跑程序，先画正常与超时轨迹，解释哪一步改变上下文、哪一步决定权限、哪一步验证实际结果；再将引用换为同一ID两次，说明为何当前代码不足。参考判断是：schema负责值形状、policy负责调用权、执行观察负责返回、verifier负责声明范围，四者不能互相替代。动画中无“记忆开关”，记忆始终加载；卡片/秒表/机器外观不代表真实模型内部思维。
