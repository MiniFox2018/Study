## 1. 从单智能体算法到复杂决策系统

强化学习算法本身只是复杂智能系统的一部分。

当任务从 CartPole、Atari 扩展到星际争霸、Minecraft、机器人和开放世界，问题会同时变成：

- 多模态状态表示；
- 结构化动作空间；
- 长时序 credit assignment；
- 模仿学习；
- 多智能体对抗；
- 世界模型；
- 稀疏奖励；
- 大规模并行采样。

EasyRL 的 AlphaStar、LS-Imagine 和 World Models 展示了这种升级。

## 2. AlphaStar：复杂强化学习系统案例

EasyRL 第 13 章把 AlphaStar 拆成环境状态、结构化动作、网络架构、监督学习初始化、强化学习、模仿学习和多智能体/self-play。

它的长期价值不是记住《星际争霸Ⅱ》细节，而是理解：

> 复杂 RL 系统通常不是“一个算法”，而是表示学习、策略学习、价值估计、模仿学习和训练基础设施的组合。

## 3. 多模态状态表示

AlphaStar 的状态包含：

- entities；
- map；
- player data；
- game statistics。

对应不同编码器：

- 标量 → MLP；
- entity sequence → Transformer；
- spatial map → ResNet。

然后再由时序模块融合。

这说明复杂 RL 的第一步不是先选 PPO 还是 DQN，而是先回答：

> 环境信息如何被正确表示？

## 4. 结构化动作空间

AlphaStar 的动作不是一个简单类别，而是多个有关联的子决策：

- action type；
- selected units；
- target；
- queued；
- repeat；
- delay。

因此策略采用自回归式动作生成：前一个动作分量的输出会成为后一个分量的条件。

这种设计适合：

- 超大动作空间；
- 条件依赖动作；
- 指针式对象选择；
- 空间目标定位。

## 5. Human Data + RL

AlphaStar 不是直接从随机策略开始。

EasyRL 总结的训练链路是：

监督学习初始化 → 强化学习 → 模仿学习约束 → 多智能体/self-play。

人类对局数据用于：

- 策略初始化；
- 行为分布约束；
- 统计特征 Z；
- 改善早期探索。

这说明在超复杂任务中，“从零强化学习”并不是唯一合理路线。

## 6. Off-policy Correction 与 V-trace

AlphaStar 使用 actor 采样、learner 更新的异步结构。

当采样策略与学习策略不同，需要对策略梯度做 off-policy correction。

EasyRL 在 AlphaStar 解读中给出的核心形式是截断 importance ratio：

$$
\rho_t
=
\min
\left(
\frac{
\pi_\theta(a_t|s_t)
}{
\pi_\mu(a_t|s_t)
},
1
\right)
$$

这样可以控制重要性权重过大造成的方差。

长期知识是：

> 大规模分布式 RL 中，采样策略和学习策略往往不同，因此需要显式处理 policy lag。

## 7. Self-play 与 League Training

Self-play 的对手可以是当前策略、历史快照或训练种群；最简单的情形是当前策略互相对战。

AlphaStar 更进一步使用 league：

- main agent；
- league exploiter；
- main exploiter；
- 历史 snapshot。

不同角色采用不同的 opponent sampling、snapshot 条件和 reset 策略。

其目标不是只训练一个“最强当前策略”，而是避免：

- 策略循环克制；
- 过拟合单一对手；
- 战术退化。

因此多智能体 self-play 本质上还包含：

> population management + opponent curriculum。

## 8. Visual Reinforcement Learning

EasyRL 第 15 章把 Visual RL 定义为：

> 直接根据图像学习控制策略，而不是依赖人工整理好的低维状态。

这会把 RL 问题与视觉表征学习绑定：

图像观测 → representation → policy / value。

因此视觉 RL 需要同时处理 perceptual representation、temporal dynamics 和 control。

EasyRL 这里只提供方向入口，没有形成完整教材，因此在 Study 中不把它扩成独立大章。

## 9. 世界模型不是普通生成模型

EasyRL 第 16 章强调：

> 生成模型 ≠ 世界模型。

在本章用于规划与控制的世界模型语境中，需要建模动作条件动态，例如：

$$
p(s_{t+1}|s_t,a_t)
$$

也就是动作条件下世界如何变化。更广义文献也使用 world model 指无显式动作输入的环境预测模型；这里强调的是控制用途，不能把本章定义当成整个领域的唯一用法。真实观测未必满足 Markov 性，潜状态常需整合历史。

所以世界模型的核心是：

当前状态 + 动作 → 未来状态 / 未来奖励 / 终止信息。

## 10. 为什么需要世界模型

如果可以学到环境 dynamics，就可以在 learned environment 中进行 imagined rollout。

EasyRL 强调的价值包括：

- 降低真实环境交互成本；
- 避免重复运行昂贵环境；
- 提高样本利用率；
- 在模拟环境中反复训练策略；
- 为现实任务提供 sim / imagination 层。

因此 World Model 把 RL 从“真实环境交互 → 学策略”扩展为：

真实环境交互 → 学世界 → 在世界模型里想象 → 学策略。

## 11. 经典 World Models：V + M + C

EasyRL 第 16 章采用 2018 World Models 的三部分框架。

### V：视觉编码器

使用 VAE 将高维图像压缩为 latent：

$$
x_t
\rightarrow
z_t
$$

作用是减少 dynamics model 需要建模的维度。

### M：Dynamics Model

MDN-RNN 根据：

$$
z_t,\ a_t,\ h_t
$$

预测：

$$
p(z_{t+1}|z_t,a_t,h_t)
$$

不是只预测一个确定值，而是预测下一 latent 的概率分布。

### C：Controller

控制器根据：

$$
[z_t,h_t]
$$

输出动作：

$$
a_t
=
W_c[z_t,h_t]+b_c
$$

这个框架建立了最重要的 World Model 分层：

Representation → Dynamics → Control。

## 12. Model-based RL 的核心分界

有模型强化学习不是简单“知道环境”。

现实中可以：

- 已知真实 model；
- 学习一个 model；
- 在 model 中规划；
- 在 model 中生成 imagined trajectory；
- model 与 model-free policy 混合。

EasyRL 的世界模型章节属于：

> learned model + imagined rollout。

因此它与前面 MDP 中“已知转移概率”的经典 model-based 概念是同一思想在深度学习时代的扩展。

## 13. 世界模型的误差问题

图像/视频生成与世界模型的连接见[视觉生成与视频时序](../感知与多模态专题/09-视觉生成与视频时序.md)。视频条件生成可以学到视觉时序分布；要用于这里的控制闭环，还须检验动作条件、奖励/终止预测、状态覆盖以及规划后真实环境结果。生成的视频看起来连贯，不能据此判定转移动力学或策略可执行。

世界模型可以减少真实交互，但同时引入：

- representation error；
- dynamics prediction error；
- rollout accumulation error。

想象得越长，模型误差越可能累积。

因此 imagination horizon 不能无限增长。

这正是 EasyRL 收录 LS-Imagine 的背景之一：传统 world-model agent 往往只使用较短 imagination，导致长期任务“短视”。

## 14. LS-Imagine：长短期想象

EasyRL 新增的 ICLR 2025 Oral LS-Imagine 面向 Minecraft 开放世界。

它关注的问题是：

- 状态空间巨大；
- 目标稀疏；
- 长期回报重要；
- 短 imagined rollout 看不到远期价值。

核心结构是：

Visual Observation + Language Goal → Affordance Map → Short / Long Transition → Long Short-Term Imagination → Actor-Critic。

## 15. Affordance Map

LS-Imagine 用“功用性图”表示：

> 当前图像中的哪些区域，与语言任务目标更相关、值得探索。

其数据构造过程是：

1. 在观察图像不同区域上做虚拟探索；
2. 形成模拟视觉序列；
3. 使用预训练 MineCLIP 评估视频和任务文本的相关性；
4. 把相关性汇总成空间 map。

随后再训练多模态 U-Net 快速预测该 map。

长期价值是：

> 把开放世界探索从“无方向随机试探”变成目标条件化的空间先验。

## 16. Intrinsic Reward

LS-Imagine 将 affordance map 转成 intrinsic reward。

目的不是替代环境 reward，而是在 sparse reward 条件下给智能体一个更密集的目标导向信号。

这与前面 EasyRL 第 10 章的 curiosity 一样，都属于：

> 外部奖励不足时，为探索构造内部学习信号。

区别是：

- curiosity 偏向“未知”；
- affordance-driven reward 偏向“对当前目标有价值”。

## 17. Short-term 与 Long-term Transition

LS-Imagine 的 world model 同时包含：

### Short-term branch

根据当前状态和动作预测相邻下一状态。

### Long-term branch

直接预测目标导向的跨时间状态转移。

系统还学习：

- jumping flag；
- interval predictor；
- accumulated discounted reward。

于是 imagined trajectory 中，不要求每一步都对应一个真实环境 step。

这是一种重要思想：

> 世界模型可以建模 temporal abstraction，而不只是一帧一帧复制环境。

## 18. Long Short-Term Imagination

智能体在 imagination 时动态决定：

- 做短期一步预测；
- 还是做长期跳跃预测。

然后把两种 transition 混合成 imagined latent sequence，再用 Actor-Critic 学行为。

EasyRL 给出的核心 return 形式把跳跃间隔 $\Delta_t$ 放入 discount：

$$
\gamma^{\Delta_t}
$$

因此跨越多个真实时间步的 imagined transition 仍可进入长期价值估计。

## 19. AlphaStar 与 LS-Imagine 的共同启示

二者表面上差别很大：

- AlphaStar：复杂对战；
- LS-Imagine：开放世界探索。

但底层共同点是：

1. 原始状态过于复杂，必须学习 representation；
2. 动作或时间结构过于复杂，需要 abstraction；
3. 单纯 sparse reward 不够；
4. 训练不能只依赖一个小型在线 loop；
5. human prior / language prior / learned world knowledge 可以帮助探索。

这两个案例说明复杂 RL 任务可能需要系统设计；不代表所有 RL 项目都需要同等复杂度。

## 世界模型误差为什么会累积

真实一维环境为 $s_{t+1}=s_t+a_t$；学到的模型误多了 0.1，变成 $\hat s_{t+1}=\hat s_t+a_t+0.1$。从相同状态出发，执行相同动作序列，10 步后的状态偏差就是 1.0；在非线性环境中还可能被放大。

自查：单步均方误差很小，就可以在模型里无限想象吗？**答案：**不能。应比较多步误差、奖励与终止预测、策略是否利用模型漏洞，并在真实/可信环境中评估策略。

跨时间跳跃也要保持回报单位：若一步模型跳过 3 个真实步，衔接下一状态价值的折扣是 $\gamma^3$；$\gamma=0.9$ 时为 0.729，期间奖励还应按其实际发生时刻累积。

核验（2026-10-02）：[LS-Imagine 原论文](https://arxiv.org/html/2410.03618v3) 及 [ICLR 2025 官方报告](https://iclr.cc/media/iclr-2025/Slides/31740_kmNdVz4.pdf)。保留其长短期想象机制，不把论文所测 Minecraft 任务结果外推为真实机器人能力。


## 23. Markov game与集中训练、分散执行

### 23.1 联合环境可以Markov，单个学习者看到的过程却在变化

设全局状态s、n个智能体的联合动作a=(a1,…,an)、固定转移P(s'|s,a)以及各自奖励r_i。它们构成Markov game，并不因多智能体就自动失去Markov性质。共同奖励是完全合作；两者奖励和0是零和；其余可为一般和。局部观测o_i或历史τ_i未必足以识别s，即部分可观测；策略可用记忆而非把当前o_i硬当完整状态。

单个智能体只条件于自己的a_i时，等效转移为 `P_k(s'|s,a_i)=Σa_-i P(s'|s,a_i,a_-i)π_-i,k(a_-i|s)`。别人策略随训练k改变，等效环境便非平稳；隐藏对手状态/历史又可能导致非Markov局部过程。集中critic提供更多条件，不自动让所有策略同时收敛，动态图的“独立永远转圈、集中必然内螺旋”是预设动画，不能作定理。[MADDPG](https://arxiv.org/abs/1706.02275)

IQL/IPPO把其他智能体当环境，是值得比较的基线，不是耦合紧就必然禁用。源IQL的Q_i其实输入**两者联合位置**，不是局部观测分散执行例；旧replay的对手版本会过时，需要版本/时间、分组或importance方法，按新鲜度加权也不保证修复。

CTDE的合同是：训练可用全局状态/联合动作/其他特权信息，执行每个actor只依赖其可获得的o_i/τ_i及允许的通信。集中critic可以是Q_i(s,a)或V(s)，MAPPO常用集中V，MADDPG用集中Q；IPPO的独立V不因多个actor就成为MAPPO。共享actor参数时可用角色ID区分，也要核对实际执行能否获得ID。[合作任务MAPPO](https://arxiv.org/abs/2103.01955)

### 23.2 联合argmax不能随意拆，QMIX与COMA各解决什么

联合Q表的集中控制选择 `(a1,a2)=argmax Q(s,a1,a2)`。源的 `argmax_ai max_a_-i Q` 不是边缘概率化，也一般不能独立得到相容动作。矩阵 `[[0,1],[1,0]]` 的行/列最大值都[1,1]，两者各自取第一个最大动作0，得到(0,0)奖励0；集中选(0,1)却得1。即使约定一致联合tie-break，仍需全局信息，不能因此声称局部actor合同成立。

QMIX将局部 `Q_i(τ_i,a_i)` 经状态条件mixing network组成Qtot，要求 `∂Qtot/∂Q_i≥0`，在联合合法动作集合为各局部集合的笛卡尔积等标准条件下，各局部argmax组合可达到同状态的联合argmax。非负权重可由绝对值/其他正参数化得到；它是表达限制，不是任意联合Q都能精确表示。上面反协调矩阵中a1的最好选择随a2改变，不能靠同一组局部动作排序完整表示。VDN的求和是更简单分解；必要时用更一般集中actor/分解方案。[QMIX](https://arxiv.org/abs/1803.11485)

COMA对智能体i的优势使用 `A_i=Q(s,a)−Σa_i' π_i(a_i'|τ_i)Q(s,(a_-i,a_i'))`：固定其他人已选动作，只遍历自己的替代动作。基线不依赖这次采到的a_i，策略更新将其作为停止梯度的控制量；适当条件下不会改变策略梯度期望；它比较条件下的贡献，不证明识别了真实因果责任。例π_i=[.25,.75]、固定别人时Q=[2,6]，基线5，两个优势[-3,1]，加权期望0。[COMA](https://arxiv.org/abs/1705.08926)

### 23.3 完整联合critic、局部actor更新与分解反例

一个合作单步游戏，两种角色各选0/1，不同动作得1。同一人工Q矩阵对所有训练样本有效；critic先看四种联合动作拟合奖励，actor只保存本角色logits。本例是精确期望的一步actor–critic机制，不含PPO/GAE、时序/局部传感器或真实MAPPO训练。

```python
import itertools
import torch
from torch import nn
torch.set_num_threads(1);torch.manual_seed(41)
truth=torch.tensor([[0.,1.],[1.,0.]])
critic=nn.Parameter(torch.zeros(2,2));oc=torch.optim.Adam([critic],lr=.06)
for _ in range(140):
    loss=(critic-truth).square().mean();oc.zero_grad();loss.backward();oc.step()
assert torch.allclose(critic,truth,atol=.002)
# 角色局部logits；执行函数不输入联合state或其他角色动作。
a=nn.Parameter(torch.tensor([[.1,-.1],[-.1,.1]]));oa=torch.optim.Adam([a],lr=.04)
for _ in range(140):
    logp=a.log_softmax(-1);p=logp.exp()
    expected=(p[0,:,None]*p[1,None,:]*critic.detach()).sum()
    entropy=-(p*logp).sum()
    loss=-expected-.01*entropy;oa.zero_grad();loss.backward();oa.step()
def local_action(role):return int(a[role].argmax())
actions=(local_action(0),local_action(1));assert truth[actions]==1
# max-marginal各自tie-break能选到不相容联合动作。
wrong=(int(truth.max(1).values.argmax()),int(truth.max(0).values.argmax()))
assert wrong==(0,0) and truth[wrong]==0
# 单调mix允许局部argmax；这里正权重和只是QMIX的最小机制。
q1=torch.tensor([1.,3.]);q2=torch.tensor([2.,-1.])
joint=2*q1[:,None]+.5*q2[None,:]+7
best=max(itertools.product(range(2),repeat=2),key=lambda pair:float(joint[pair]))
assert best==(int(q1.argmax()),int(q2.argmax()))
pi=torch.tensor([.25,.75]);q=torch.tensor([2.,6.]);baseline=(pi*q).sum()
assert baseline==5 and torch.isclose((pi*(q-baseline)).sum(),torch.tensor(0.))
print('联合critic/局部actor动作',actions,'max-marginal反例/QMIX单调/COMA零均值通过')
```

### 23.4 协调、通信与实测评价

共享终点奖励难分配贡献，独立探索也可能从未碰到有效联合动作。给角色/通信、反事实baseline、分解或特定奖励shaping是方案；改变每人的奖励可能改变博弈均衡，不是自动无损。通信必须固定可用内容、频率、延迟、带宽和丢包，执行时不能偷用训练global state；LLM代理互发自然语言也不等于已经运行MARL。

源5×5两角色网格用1500episode，两者greedy固定初态回报均3.00；训练曲线波动与联合动作数量有关。它没有局部观测CTDE、神经critic、自玩或通信，100次同初态确定性评估也不是100种泛化条件。比较同步到达任务先定义已到达者能否等待/吸收、是否有碰撞和时间上限，不把另一个任务的收敛照搬。MAPPO/IPPO实际消融未运行；比较需固定团队/观测、环境步、角色策略、reward与失败率、多seed，并留未参与训练的初态/队伍规模。

## 24. 自玩、MCTS和世界模型的分工

### 24.1 自玩与联赛不是保证递增的Elo阶梯

自玩可以对当前自己、历史快照或种群，不必只有过去版本。纯零和石头剪刀布的最好响应也会循环：只打赢最新快照不等于更强。保留对手池、采样混合、exploiters和固定外部基线，报告交叉胜负矩阵、双边角色/先后手和相同思考预算；非传递强弱关系不能仅用一个Elo数完全表示。

AlphaStar的main exploiter针对主策略漏洞，league exploiter针对联赛种群；不能将main exploiter写成“专门打exploiters”。旧第7节的人类先验、快照/reset和population管理保留，联赛减单一对手过拟合但不证明达到Nash均衡。Elo还依对手和更新顺序，偏好Elo的算法例见[视觉评价](../感知与多模态专题/09-视觉生成与视频时序.md#103-成对偏好draw与elo的解释)。

### 24.2 AlphaZero的搜索目标与符号

在完全可观测、交替行动、已知合法动作/转移的零和棋类中，policy/value网给当前行动者的先验p(a|s)与期望结果v(s)。MCTS重复选择→展开/叶点评估→回传；PUCT选择 `Q(s,a)+cP(s,a)√N(s)/(1+N(s,a))`。P是归一化合法动作先验，N是访问次数，Q是从**父节点行动者**视角的平均价值。相邻层行动者变化时回传价值要反号；一般和、chance、非交替等情况需改合同，不能一律每层取负。

搜索后以 `π(a)∝N(s,a)^(1/τ)` 为策略目标，最终游戏结果z按各状态行动者换视角；训练 `MSE(v,z)−Σa π(a)logp(a)+正则`。root探索噪声和温度增加自玩探索，评估是否关闭须记录。规则、合法动作、胜负条件以及有限棋类假设是先验，不能把“无棋谱示范”说成完全零人类知识。[AlphaZero](https://arxiv.org/abs/1712.01815)

### 24.3 完整的取石子PUCT、自玩与policy/value更新

每次取1或2个石子，拿最后者胜；节点value/W均为该节点行动者视角，所以选择child时取负。这是真实树访问/回传，神经网从随机参数初始化，只有8个合成对局和一次更新；不声称AlphaZero能力或持续单调变强。

```python
import math
import numpy as np
import torch
from torch import nn
torch.set_num_threads(1);torch.manual_seed(42);rng=np.random.default_rng(42)
net=nn.Sequential(nn.Linear(1,16),nn.Tanh(),nn.Linear(16,3))
class Node:
    def __init__(self,n,prior=1.):
        self.n=n;self.prior=prior;self.N=0;self.W=0.;self.children={}
def expand(node):
    if node.n==0:return -1.  # 当前行动者没有石子，上一位已胜。
    with torch.no_grad():out=net(torch.tensor([[node.n/7.]])).squeeze(0)
    legal=min(2,node.n);p=out[:legal].softmax(0).numpy()
    for k in range(1,legal+1):node.children[k]=Node(node.n-k,float(p[k-1]))
    return float(out[2].tanh())
def search(n,simulations=40):
    if type(n) is not int or n<=0 or type(simulations) is not int or simulations<=0:
        raise ValueError('正整数石子和预算')
    root=Node(n)
    for _ in range(simulations):
        node=root;path=[root]
        while node.children:
            def utility(k):
                child=node.children[k]
                q=-child.W/child.N if child.N else 0.
                return q+1.4*child.prior*math.sqrt(node.N)/(1+child.N)
            action=max(node.children,key=utility);node=node.children[action];path.append(node)
        value=expand(node)
        for item in reversed(path):
            item.N+=1;item.W+=value;value=-value
    visits=np.array([root.children[k].N if k in root.children else 0 for k in (1,2)],float)
    if visits.sum()==0:raise ValueError('预算不足以访问一个子节点')
    return root,visits/visits.sum()
root,pi=search(1)
assert pi[0]==1 and pi[1]==0 and root.children[1].W/root.children[1].N==-1
assert root.W/root.N>0  # 父行动者胜；叶行动者负。
records=[];simulations=0
for game in range(8):
    n=7;player=1;trajectory=[]
    while n>0:
        root,pi=search(n);simulations+=40;trajectory.append((n,pi.copy(),player))
        action=int(rng.choice([1,2],p=pi));n-=action
        if n==0:winner=player;break
        player=-player
    records.extend((n,pi,1. if who==winner else -1.) for n,pi,who in trajectory)
s=torch.tensor([[n/7.] for n,_,_ in records]);targets=torch.tensor(np.array([p for _,p,_ in records]),dtype=torch.float32)
z=torch.tensor([v for _,_,v in records]);out=net(s)
legal=torch.stack([torch.ones(len(records),dtype=torch.bool),s[:,0]>=2/7],1)
logp=out[:,:2].masked_fill(~legal,-1e9).log_softmax(-1)
loss=-(targets*logp).sum(-1).mean()+(out[:,2].tanh()-z).square().mean()
opt=torch.optim.Adam(net.parameters(),lr=.01);opt.zero_grad();loss.backward();opt.step()
assert torch.isfinite(loss) and all(p.grad is not None and torch.isfinite(p.grad).all() for p in net.parameters())
print('PUCT合法动作/价值反号/访问目标通过；8合成自玩局，搜索模拟',simulations,'policy/value一次更新')
```

固定simulations为1可能仅展开root无访问，函数明确报错；真实搜索还需缓存、terminal/no-legal状态、root噪声、transposition及温度等合同。此例不把多次搜索当免费：报告环境推进、树扩展、网络叶点评估和采样预算。

### 24.4 MuZero、model-free与GRPO为何不能统称同一个算法

MuZero学习 `h(观察历史)→latent`、`g(latent,a)→下一latent和reward`、`f(latent)→policy/value`，在learned model中搜索，训练展开多步的reward/value/policy目标。它不必重建每个像素或恢复所有物理规则，也仍需要真实环境/游戏提供交互观测和结果，不能称“无sim或环境也能学任何游戏”。合法动作和环境接口仍按任务处理；stochastic MuZero引入机会结果，不应以确定性单轨迹代替全部随机动力学。[MuZero](https://arxiv.org/abs/1911.08265)

旧第9～18节的VAE+MDN-RNN+controller、reward/terminal、多步误差、LS-Imagine与gamma^Δ仍是主入口；MuZero的latent模型侧重决策所需量，不等于世界模型必定使用VAE。model-free可通过真实交互学policy/value而不学习转移；AlphaZero利用已知model做搜索；MuZero利用learned model。搜索可与policy混用，不等于凡用神经网就是model-free。

GRPO对同题采样完整答案、构造组相对优势、做策略优化，没有自动生成MCTS访问分布，也不要求一个对抗玩家。“把验证器替换搜索”只能作非常宽泛的采样/改进比喻，不能替换上述policy训练目标。其完整两token例与old/ref/KL分界由[偏好优化第5节](../../LLM%20工程实践/05-偏好优化与强化学习.md#5-grpo同题相对优势与裁剪更新)维护，不再本章做另一份bandit。

不完全信息扑克不能将不可见手牌输入执行策略或普通完全信息MCTS；可用belief、信息集/CFR等机制，搜索算法需符合信息结构，而非永久禁用任何AlphaZero变体。AlphaTensor/AlphaDev等把算法优化改写成有动作/评分的任务是研究例子，不能证明所有真实问题都有完美sim或低成本可验证reward。

## 25. 本次进阶练习的参考判据

1. 源IQL平均回报>0何时出现？此固定seed的150episode块均值在第6块为.10；它依探索、初始化/环境定义，不是普遍收敛样本界。源joint-Q更早/更晚均不能从一次seed概括优劣。
2. 同时到达怎么改？明确位置吸收/等待、终止定义、碰撞、共享奖励与超时；中央critic仍不能保证局部演员信息足够，先用23.2的矩阵反例检查。
3. CTDE怎样核对？23.3包含联合critic与局部actor的真实参数更新及COMA/QMIX手算；未运行原hard要求的时序MAPPO/IPPO消融，不借该例宣称速度/收敛优势。
4. AlphaZero何为监督目标？搜索访问分布π与按行动者视角的z；网络prior不直接成为自己的唯一标签。24.3检查合法动作、访问与反号，未训练棋类强模型。
5. GRPO公平比较与两步信用怎样做？链接LLM05，匹配真实采样/验证器预算，完整答案优势广播两步；源固定答案索引不是自然语言推理。
6. 固定对手胜率与自玩胜率为何分开？后者对手随训练改变，循环可互相克制；用对手矩阵和外部固定集确认进步，而不是动态图阶梯证明必然增强。
