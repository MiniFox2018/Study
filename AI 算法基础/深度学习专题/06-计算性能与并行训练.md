# 06｜计算性能与并行训练

## 1. 深度学习性能的基本视角

训练速度不是单一 FLOPs 问题，而是：

```text
算法
+ 计算图
+ kernel
+ 内存访问
+ host/device 传输
+ 通信
+ 数据管线
```

任何一层都可能成为瓶颈。

## 2. 命令式与符号/编译执行

命令式执行易调试、控制灵活；图编译/符号执行有机会做：

- op fusion；
- constant folding；
- memory planning；
- kernel selection；
- device scheduling。

现代框架已经越来越趋向“动态图开发 + 编译器优化执行”的混合方式。

## 3. 异步计算

GPU kernel 启动通常异步，CPU 发出任务后不一定立即等待完成。

这意味着：

- 计时必须显式同步；
- Python 代码结束不代表 GPU 已完成；
- host-device copy 可能隐式同步。

错误的 benchmark 很容易把排队时间和执行时间混在一起。

## 4. 自动并行

独立操作可以在不同资源上并行，但实际收益取决于：

- 数据依赖；
- kernel 粒度；
- stream；
- memory bandwidth；
- 调度开销。

“可以并行”不等于“实际更快”。

## 5. 硬件层瓶颈

需要建立 Roofline 式直觉：

- compute-bound：算力限制；
- memory-bound：内存带宽限制；
- communication-bound：多卡通信限制。

矩阵乘法通常更容易利用加速器；大量小 kernel、索引、数据搬运往往效率低。

## 6. 数据并行

最常见多 GPU 训练方式：

```text
复制模型
→ 每卡处理不同 mini-batch
→ 计算局部梯度
→ All-Reduce 聚合
→ 同步更新
```

关键约束：

- 每卡 batch；
- 梯度同步通信；
- load balance；
- 通信与计算重叠。

## 7. 模型并行

当单卡放不下模型时，需要把不同参数/层拆到不同设备。

现代扩展包括：

- tensor parallel；
- pipeline parallel；
- sequence/context parallel；
- expert parallel；
- parameter/optimizer sharding。

D2L 的多 GPU 基础应理解为这些方法的前置概念。

## 8. 参数服务器

Parameter Server 把参数聚合放在中心或分片 server 上，是分布式训练的重要历史架构。

现代大规模 GPU 集群更多使用高效 collective communication，但参数服务器思想仍适用于理解：

- 参数所有权；
- 同步/异步更新；
- stale gradient；
- 带宽瓶颈。

## 9. 内存构成

训练显存不只是参数：

```text
parameters
+ gradients
+ optimizer states
+ activations
+ temporary buffers
+ communication buffers
```

大模型训练中 activations 与 optimizer states 往往非常可观。

## 10. 提升性能的顺序

建议：

1. profiler 定位瓶颈；
2. 提高 batch/算子利用率；
3. 修复数据加载；
4. mixed precision；
5. 减少同步和数据搬运；
6. kernel fusion / compile；
7. 再考虑多卡扩展。

在单卡都没有跑好之前直接堆 GPU，通常只会扩大低效率。

## 11. benchmark 原则

性能测试必须明确：

- warmup；
- synchronization；
- batch size；
- dtype；
- sequence/image size；
- hardware；
- software version；
- 是否含数据加载；
- throughput vs latency。

否则数字几乎不可比较。
