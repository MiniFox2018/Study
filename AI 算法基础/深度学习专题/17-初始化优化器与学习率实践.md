> 先修：[优化与状态](05-深度学习优化.md)、[正则与模式](09-泛化评估与正则化.md)、[浮点稳定](../数学与数值计算专题/08-浮点误差与数值稳定.md)。先观察初始化前向/反向信号，再计算调度端点，最后运行小型CPU训练。全部数据在程序里合成，不需要下载数据集、预训练权重或使用GPU。

## 1. 初始化设定初始函数，不等于实际更新大小

权重初始化选择 $\theta_0$；optimizer与lr控制以后 $\Delta\theta$。初值很小也可能经Adam首步走约lr的距离，初值合适也可能因过大lr、错误loss或未清状态立刻失效。先分别记录初始激活/梯度、真实参数更新量，不能把“std合适”当训练成功保证。

若一个隐藏层中所有神经元具有相同输入权重、偏置和对称的后续连接，普通对称训练使它们计算相同函数并接收相同梯度，宽度的功能会退化。多层全零权重还可能阻断隐藏梯度，但输出偏置仍能学习标签基率。零初始化不是所有模型都错误：凸线性模型可从0学起，随机权重网络的偏置常初始化0；关键是隐藏单元的对称关系和梯度路径。

对称可以用独立随机权重破开；不能只让所有权重共同等于某个随机数。独立分布、正确尺度和架构共同决定传播。检查初始bias、归一化gamma/beta、输出logit尺度与残差分支，不只看最大矩阵。

## 2. fan-in、二阶矩与Xavier/He条件

对 $z=\sum_{j=1}^{n}w_jh_j$，假设权重均值0、权重与输入独立、跨项协方差可忽略、方差同尺度，则：

$$
E[z^2]\approx n\operatorname{Var}(w)E[h^2].
$$

输入中心化时 $E[h^2]=\operatorname{Var}(h)$，否则不能互换。这里是在初始化随机分布下的近似，不保证每个有限网络每层完全相等；训练以后权重与输入也不再独立。

对近线性/适当中心化激活，前向希望权重方差约 $1/fan_{in}$，反向希望约 $1/fan_{out}$。Xavier折中取 $2/(fan_{in}+fan_{out})$；正态std为其平方根，均匀上下界为 $\pm\sqrt{6/(fan_{in}+fan_{out})}$。均匀分布方差是界限平方/3，不能将std当界限。

对关于0对称的 $z$，ReLU输出 $h=\max(0,z)$满足 $E[h^2]=E[z^2]/2$，所以He选 $\operatorname{Var}(w)=2/fan_{in}$维持前向二阶矩。ReLU有正均值，其中心化方差并非恰为 $\operatorname{Var}(z)/2$；不能把公式原封不动解释成所有层中心化std严格不变。LeakyReLU斜率a时因子为 $(1+a^2)/2$，He方差对应 $2/[(1+a^2)fan_{in}]$。

| 情形 | 起始选择 | 边界 |
|---|---|---|
| 线性或合适tanh层 | Xavier/LeCun及相应gain | tanh导数和饱和仍影响深层梯度 |
| ReLU层 | He `fan_in` | 保前向二阶矩近似，非50层必稳定 |
| 更关注反向尺度 | 相应`fan_out`方案 | 前向与反向宽度不同可能不能同时精确保留 |
| LeakyReLU | 使用对应斜率gain | 不能当a=0的ReLU固定公式 |
| GELU/SiLU | 采用已验证架构配方并测信号 | 导数与门控非ReLU精确半截，He可作候选非定理 |
| SELU自归一化配方 | LeCun正态std=$1/\sqrt{fan_{in}}$ | 还依赖输入/层宽等条件及相应Dropout，不只换激活 |
| 残差网络/Transformer | 按分支、深度与归一化设计 | 不能对所有attention/FFN都机械套He |

Sigmoid在0附近导数最多1/4且输出均值约1/2。深层平均激活一直约0.5，可能同时梯度乘积接近0；Xavier不能保证50层Sigmoid训练顺畅。饱和大logit使Sigmoid/Tanh导数小；ReLU连续落在负区的单元也可能没有任务梯度。实测需看前向**及**反向，不仅绝对均值。

对卷积，fan-in通常为每个输出连接的输入通道数×卷积核体积；groups改变实际连接数量，fan-out也需结合连接结构核对。PyTorch Linear权重常为 `[fan_out,fan_in]`，矩阵计算 $xW^T$；若自定义用 $xW$，套初始化函数时要转置或正确计算fan。不要仅凭矩阵第一维就认为fan-in。

## 3. 50层小实验同时测激活与梯度

以下完整NumPy程序用 `[输出,输入]`权重、宽64、32个输入、50层，比较零、过小/过大、Xavier、He与正交候选。`rms`测二阶矩尺度，`std`测中心化波动，`mean_abs`只是另一摘要。反向对输出均值求导，不训练分类器，因此不会给出任务准确率。

```python
import numpy as np

def initialize(rng, shape, strategy):
    fan_out, fan_in = shape
    raw = rng.normal(size=shape)
    if strategy == "zero": return np.zeros(shape)
    if strategy == "tiny": return raw*0.01
    if strategy == "large": return raw
    if strategy == "xavier": return raw*np.sqrt(2/(fan_in+fan_out))
    if strategy == "he": return raw*np.sqrt(2/fan_in)
    if strategy == "lecun": return raw/np.sqrt(fan_in)
    if strategy == "orthogonal":
        u, _, vh = np.linalg.svd(raw, full_matrices=False)
        return np.sqrt(2)*(u@vh)  # 方形ReLU候选；矩形仅一侧能完整正交。
    raise ValueError("未知初始化")

def activation(z, kind):
    if kind == "relu": return np.maximum(z, 0)
    if kind == "tanh": return np.tanh(z)
    if kind == "sigmoid":
        q = np.exp(-np.abs(z))
        return np.where(z >= 0, 1/(1+q), q/(1+q))
    raise ValueError("未知激活")

def probe(strategy, kind, width=64, depth=50):
    rng = np.random.default_rng(42)
    A = rng.normal(size=(32, width))
    caches, stats = [], []
    for _ in range(depth):
        W = initialize(rng, (width, width), strategy)
        z = A@W.T
        A = activation(z, kind)
        if not np.isfinite(A).all(): raise FloatingPointError("前向非有限")
        caches.append((W, z, A))
        stats.append((float(np.mean(np.abs(A))), float(A.std()), float(np.sqrt(np.mean(A*A)))))
    grad = np.ones_like(A)/A.size
    for W, z, out in reversed(caches):
        derivative = (z > 0) if kind == "relu" else (1-out*out if kind == "tanh" else out*(1-out))
        grad = (grad*derivative)@W
    if not np.isfinite(grad).all(): raise FloatingPointError("反向非有限")
    return stats, float(np.sqrt(np.mean(grad*grad)))

configs = [("zero","sigmoid"),("tiny","relu"),("large","relu"),
           ("xavier","sigmoid"),("xavier","tanh"),("he","relu"),("orthogonal","relu")]
for strategy, kind in configs:
    stats, grad_rms = probe(strategy, kind)
    print(strategy, kind, "L1/L10/L50 RMS", [float(f"{stats[i][2]:.3g}") for i in [0,9,49]],
          "L50 std", float(f"{stats[-1][1]:.3g}"), "输入梯度RMS", float(f"{grad_rms:.3g}"))
zero_stats, zero_gradient = probe("zero", "sigmoid")
assert np.isclose(zero_stats[-1][0], 0.5) and zero_gradient == 0
# fan-in改变时，理论增长因子不同；不执行1024宽50层的大矩阵任务。
for fan in [16, 1024]:
    print("fan", fan, "未经缩放线性二阶矩因子", fan, "He+ReLU近似因子", fan*(2/fan)/2)
```

预期零权重Sigmoid绝对均值仍0.5，但输入梯度为0；小ReLU尺度快速消失，大尺度剧增；Xavier+Sigmoid前向看似温和但反向极小。He/正交也有有限宽度与具体随机种子的波动，不能只规定“0.5～2才健康”。曲线异常先查层维度、dtype、非线性、输入与梯度连通，不立即断定全部都是初始化。

本次所测NumPy环境的50层结果如下，便于核对前向摘要与反向不是同一个检查：

| 初始化/激活 | 末层RMS | 末层std | 输入梯度RMS |
|---|---:|---:|---:|
| 全零/Sigmoid | 0.5 | 0 | 0 |
| Xavier/Sigmoid | 0.521 | 0.123 | $3.53\times10^{-36}$ |
| Xavier/Tanh | 0.0855 | 0.0855 | $2.18\times10^{-5}$ |
| He/ReLU | 0.213 | 0.179 | $5.16\times10^{-4}$ |
| 正交/ReLU | 0.431 | 0.343 | $7.76\times10^{-4}$ |

这里梯度还含输出均值的归一化尺度，不是任意训练loss的绝对梯度阈值；表格只对应这组输入、宽度和种子。正交此次值较大也不证明任务学习更好。

原网站方差图把naive因子人为除50便于绘制，并把Xavier/He固定成1；它表达近似递推，不能证明真实50层信号平坦。正交矩阵减少某些线性方向缩放差异，非线性与矩形连接仍会改变信号，不能声称必优于He。

### 3.1 残差缩放与实现默认值

若 $x_{l+1}=x_l+r_l$，方差是 $\operatorname{Var}(x_l)+\operatorname{Var}(r_l)+2\operatorname{Cov}(x_l,r_l)$。只有在适当小协方差/相近分支方差假设下，才能用深度线性增长直觉。缩放残差输出投影或分支可减积累；GPT-2类型配方对部分残差投影按分支数/深度缩放，但不是任意Transformer必须乘同一个 $1/\sqrt{2N}$。

缩放权重与在分支末乘系数，只有对应操作线性且没有其他偏置/非线性改变时才简单对应。下例只测独立加性噪声分支的增长，以明确假设，不冒充真实GPT训练：

```python
import numpy as np
rng = np.random.default_rng(42)
base = rng.normal(size=(2000, 16))
branches = rng.normal(size=(50, 2000, 16))
plain = base+branches.sum(axis=0)
scaled = base+branches.sum(axis=0)/np.sqrt(50)
print("初始/未缩放/缩放方差", round(base.var(), 3), round(plain.var(), 3), round(scaled.var(), 3))
assert scaled.var() < plain.var()
```

这个构造理论近似1→51→2。实际分支与输入相关、Pre/Post-LN、不同投影和深度规则需按架构验证，不保留网站未经来源核对的某大模型固定初始化结论。

PyTorch `nn.Linear`默认参数界限约 $\pm1/\sqrt{fan_{in}}$。它的内部实现可用`kaiming_uniform_(a=sqrt(5))`推导出这个界限，**不等于**显式 `kaiming_normal_(nonlinearity="relu")`的方差 $2/fan_{in}$。不能因为函数名含Kaiming就认为默认已按所有后续激活正确匹配。归一化gamma常设1、beta设0；输出层、Embedding与残差投影分别检查。

## 4. 把学习率时钟定义到每一次更新

设 $t$为已完成optimizer更新数，先明确函数返回第几次更新所用lr：$\eta(t)$可定义t=0为第一次，或t=1为第一次。0起点warmup意味着首步任务更新为0；这仍可能计算矩状态，不能从“lr=0”就说该步完全没变化。AdamW也受lr乘衰减影响。

| 方案 | 定义 | 需要选择和记录的项 |
|---|---|---|
| constant | $\eta_t=\eta_0$ | 有用基线，不因训练超过1小时就失效 |
| step / multi-step | 固定步/epoch后乘gamma | 时钟单位、milestone，跳变不是必然loss尖峰 |
| exponential | $\eta_0\gamma^t$ | 每更新与每epoch的gamma意义不同 |
| linear | 峰值向终点线性衰减 | 总更新数、最低值 |
| cosine | $\eta_{min}+\frac{\eta_{max}-\eta_{min}}2(1+\cos(\pi t/T))$ | 总长度T也是超参数；超过终点是否固定 |
| warmup+decay | 前W步升率，余下按计划减 | W、初始值、峰值、终点与切换连续性 |
| cyclic / one-cycle | 周期升降/一次升降到很低 | 周期长度、升段比例、上下界；可同时调momentum |
| warm restarts | 周期末重新升峰并余弦衰减 | 周期是否增长，重启通常不重置optimizer矩状态 |
| ReduceLROnPlateau | 验证长期无改善时降率 | mode、patience、threshold、factor、cooldown、min_lr |

Warmup在一些深/大batch/预训练场景有益，可能控制早期更新相对初始参数太大、早期矩估计噪声和归一化变化；Adam已经有偏置校正，不能说“零矩必错，所以所有Adam必须warmup”。一个任务较低固定lr就稳定，额外预热反而占预算也可能无收益。

### 4.1 完整调度函数与端点

下面明确采用t=0起点的**教学曲线**，在T外保持指定终值。W=0合法，W>=T拒绝。one-cycle使用可选升段比例，线性升降为最小演示；成熟框架可用余弦、不同终点比和反向动量。

```python
import math

def schedule(t, kind, peak=0.1, floor=0.001, total=100, warmup=10):
    if total <= 0 or not 0 <= warmup < total or not 0 <= floor <= peak or t < 0:
        raise ValueError("检查总步数、warmup、学习率范围与非负t")
    if kind == "constant": return peak
    if kind == "step": return peak*0.1**(int(t)//25)
    if kind == "exponential": return peak*0.99**t
    if kind == "restart":
        progress = (t % 25)/25
        return floor+0.5*(peak-floor)*(1+math.cos(math.pi*progress))
    if kind == "cyclic":
        position = (t % 40)/20
        return floor+(peak-floor)*(1-abs(position-1))
    t = min(t, total)
    if kind == "onecycle":
        up = max(1, int(0.3*total))
        if t <= up: return peak/25+(peak-peak/25)*t/up
        return peak+(peak/10000-peak)*(t-up)/(total-up)
    if kind == "warmcosine":
        if warmup and t < warmup: return peak*t/warmup
        progress = (t-warmup)/(total-warmup)
    else:
        progress = t/total
    if kind in ("cosine", "warmcosine"):
        return floor+0.5*(peak-floor)*(1+math.cos(math.pi*progress))
    if kind == "linear": return peak+(floor-peak)*progress
    raise ValueError("未知调度")

for kind in ["constant","step","exponential","linear","cosine","warmcosine","onecycle","cyclic","restart"]:
    print(kind, [round(schedule(t, kind), 6) for t in [0,10,30,50,100,120]])
assert schedule(0, "warmcosine") == 0
assert math.isclose(schedule(10, "warmcosine"), 0.1)
assert math.isclose(schedule(100, "warmcosine"), 0.001)
assert math.isclose(schedule(120, "warmcosine"), 0.001)
assert math.isclose(schedule(100, "onecycle"), 0.1/10000)
```

原课warmcosine在T后继续余弦回升、one-cycle外推可能负值，本库明确终点行为；周期方案按设计继续循环。框架CosineAnnealingLR的T_max及越界行为要按实际接口核对，不假定与这个教学钳制函数相同。PyTorch OneCycleLR的`final_div_factor`相对**初始率**计算最低率，即`min_lr=max_lr/(div_factor*final_div_factor)`，不是直接`max_lr/final_div_factor`；本节教学函数明确采用后一种简化终点，不把两者混为同一默认实现。原课源程序优化的是Sigmoid输出的平方误差、输出导数相当于半平方损失；本批实际训练改用稳定BCEWithLogits并分清损失缩放。

### 4.2 LR range test和平台期调度

Range test短程让lr按指数从小升大，记录平滑loss、梯度和更新范数，在失稳附近以前挑**候选范围**。训练过程已改变权重与矩状态，因此得到的曲线不是从相同初值对每个lr的独立实验；测试后恢复原模型/optimizer/RNG，不能接着把试探末尾坏状态正式训练。“loss刚开始上升前的值就是最优lr”没有普遍保证，噪声、warmup和目标预算都影响选择。

ReduceLROnPlateau通常在验证后调用`scheduler.step(val_loss)`，mode=min或max匹配指标，不能像普通更新计数scheduler每batch盲目推进。patience和threshold需和验证频率匹配；不要用真正测试指标驱动它。若建立“schedule surgeon”自动换阶段，要定义窗口、最低预算、异常处理和恢复状态，仍是新的训练超参数策略，不保证比预定计划更好。

以下完整标量CPU例记录OneCycle实际每次更新前的lr，以及给定验证序列下平台期降率。它只验证状态调用，不把预造验证序列当真实训练效果。

```python
import torch
p = torch.nn.Parameter(torch.tensor([1.]))
opt = torch.optim.SGD([p], lr=0.1)
cyclic = torch.optim.lr_scheduler.OneCycleLR(opt, max_lr=0.1, total_steps=10,
    pct_start=0.3, div_factor=25, final_div_factor=10000, cycle_momentum=False)
used = []
for _ in range(10):
    used.append(opt.param_groups[0]["lr"])
    p.grad = torch.zeros_like(p); opt.step(); cyclic.step()
assert abs(used[0]-0.1/25) < 1e-10
assert abs(used[-1]-0.1/(25*10000)) < 1e-10
print("OneCycle使用的10个lr", [round(v, 7) for v in used])
opt = torch.optim.SGD([p], lr=0.1)
plateau = torch.optim.lr_scheduler.ReduceLROnPlateau(
    opt, mode="min", patience=1, factor=0.5, threshold=0., threshold_mode="abs")
trace = []
for validation in [1., 0.8, 0.8, 0.8, 0.7]:
    p.grad = torch.zeros_like(p); opt.step()
    plateau.step(validation)
    trace.append(opt.param_groups[0]["lr"])
assert trace == [0.1, 0.1, 0.1, 0.05, 0.05]
print("平台期降率", trace)
```

## 5. 一个完整CPU训练：模式、选轮次与快照

下例circle标签由 $x_1^2+x_2^2<1.5$构造，固定训练/验证/最终测试。比较无正则、Dropout、AdamW衰减及组合；每个配置从同一组初始权重开始，使用相同打乱种子和预算，验证BCE选最佳轮次，冻结后展示测试。这里只作预定方法对照，不拿展示的测试榜单继续调配置。

```python
import copy
import math
import numpy as np
import torch
from torch import nn

torch.set_num_threads(1)
rng = np.random.default_rng(42)
X = torch.tensor(rng.uniform(-2, 2, (360, 2)), dtype=torch.float32)
y = ((X*X).sum(dim=1, keepdim=True) < 1.5).float()
indices = torch.tensor(rng.permutation(len(X)))
train, val, test = indices[:216], indices[216:288], indices[288:]

class Net(nn.Module):
    def __init__(self, p=0.):
        super().__init__()
        self.hidden = nn.Linear(2, 32)
        self.norm = nn.BatchNorm1d(32)
        self.drop = nn.Dropout(p)
        self.output = nn.Linear(32, 1)
    def forward(self, a):
        return self.output(self.drop(torch.relu(self.norm(self.hidden(a)))))

def init_model(model):
    nn.init.kaiming_normal_(model.hidden.weight, nonlinearity="relu")
    nn.init.zeros_(model.hidden.bias)
    nn.init.xavier_normal_(model.output.weight)
    nn.init.zeros_(model.output.bias)

@torch.no_grad()
def evaluate(model, idx):
    model.eval()
    logits = model(X[idx])
    loss = nn.functional.binary_cross_entropy_with_logits(logits, y[idx]).item()
    acc = ((logits >= 0) == (y[idx] >= 0.5)).float().mean().item()
    return loss, acc

torch.manual_seed(1)
base = Net(); init_model(base)
initial = copy.deepcopy(base.state_dict())
criterion = nn.BCEWithLogitsLoss()
configs = [("无额外正则", 0., 0.), ("Dropout", 0.3, 0.),
           ("衰减", 0., 0.01), ("组合", 0.3, 0.01)]
for name, probability, decay in configs:
    torch.manual_seed(7)
    model = Net(probability); model.load_state_dict(initial)
    # 明确偏置/BN参数不衰减，此例规则按Linear权重挑选。
    optimizer = torch.optim.AdamW([
        {"params":[model.hidden.weight, model.output.weight], "weight_decay":decay},
        {"params":[model.hidden.bias, model.output.bias, model.norm.weight, model.norm.bias], "weight_decay":0.}
    ], lr=0.01)
    total_epochs, batch_size = 80, 36
    batches = math.ceil(len(train)/batch_size)
    total_updates, warm = total_epochs*batches, 3*batches
    def factor(completed):
        # 第1次update已有非零小率，completed是已完成的update数。
        if completed < warm: return (completed+1)/warm
        q = min(1., (completed-warm)/(total_updates-warm))
        return 0.1+0.9*0.5*(1+math.cos(math.pi*q))
    scheduler = torch.optim.lr_scheduler.LambdaLR(optimizer, lr_lambda=factor)
    best, best_epoch, best_state, stale, actual_updates = float("inf"), -1, None, 0, 0
    shuffle = torch.Generator().manual_seed(8)
    for epoch in range(total_epochs):
        model.train()
        order = train[torch.randperm(len(train), generator=shuffle)]
        for batch in order.split(batch_size):
            optimizer.zero_grad(set_to_none=True)
            loss = criterion(model(X[batch]), y[batch])
            if not torch.isfinite(loss): raise FloatingPointError("loss非有限")
            loss.backward()
            grad_norm = torch.nn.utils.clip_grad_norm_(model.parameters(), 1., error_if_nonfinite=True)
            optimizer.step(); actual_updates += 1; scheduler.step()
        val_loss, _ = evaluate(model, val)
        if val_loss < best-1e-4:
            best, best_epoch = val_loss, epoch+1
            best_state = copy.deepcopy(model.state_dict()); stale = 0
        else:
            stale += 1
        if stale >= 12: break
    final_epoch = epoch+1
    model.load_state_dict(best_state)
    train_loss, train_acc = evaluate(model, train)
    val_loss, val_acc = evaluate(model, val)
    test_loss, test_acc = evaluate(model, test)
    repeat = model(X[test]).detach()
    assert torch.equal(repeat, model(X[test]).detach())
    print(name, "最佳/实际轮数", best_epoch, final_epoch, "更新数", actual_updates,
          "eval训练/验证/测试acc", [round(a,4) for a in [train_acc,val_acc,test_acc]],
          "测试BCE", round(test_loss,4))
```

无Dropout并非毫无约束：网络仍有BatchNorm、有限宽度、训练计划和早停。与含Dropout配置的随机消耗可能不同，即使种子相同也不等于每个操作完全配对；多种子对照才能讨论稳定优势。恢复最佳快照只恢复此处的模型推理状态，未恢复optimizer/scheduler，所以本程序不冒充中断续训实验。

## 6. PyTorch实际更新和调度恢复核查

这段独立例用标量参数，证明AdamW零任务梯度仍按旧参数衰减；并保存参数、optimizer和scheduler状态后继续一段，和不间断更新比较。它核查数值状态恢复，不含数据加载/随机网络，完整随机训练还要恢复相应RNG和采样器位置。

```python
import copy
import torch

def create(value=2.):
    p = torch.nn.Parameter(torch.tensor([value], dtype=torch.float64))
    opt = torch.optim.AdamW([p], lr=0.1, weight_decay=0.2)
    sched = torch.optim.lr_scheduler.StepLR(opt, step_size=2, gamma=0.5)
    return p, opt, sched

def step(p, opt, sched):
    opt.zero_grad(set_to_none=True)
    (0.5*(p-1).square().sum()).backward()
    opt.step(); sched.step()

p = torch.nn.Parameter(torch.tensor([2.], dtype=torch.float64))
opt = torch.optim.AdamW([p], lr=0.1, weight_decay=0.2)
p.grad = torch.zeros_like(p); opt.step()
assert torch.allclose(p, torch.tensor([1.96], dtype=torch.float64))
print("零任务梯度的AdamW参数", p.item())
a, opt_a, sched_a = create()
for _ in range(3): step(a, opt_a, sched_a)
snapshot = (a.detach().clone(), copy.deepcopy(opt_a.state_dict()), copy.deepcopy(sched_a.state_dict()))
for _ in range(4): step(a, opt_a, sched_a)
b, opt_b, sched_b = create()
with torch.no_grad(): b.copy_(snapshot[0])
# 先建立scheduler对象，再恢复optimizer保存的lr，再恢复scheduler状态。
opt_b.load_state_dict(snapshot[1]); sched_b.load_state_dict(snapshot[2])
for _ in range(4): step(b, opt_b, sched_b)
assert torch.allclose(a, b, atol=1e-12, rtol=0)
print("续训参数一致", True, "最后lr", opt_b.param_groups[0]["lr"])
```

`.grad=None`和显式0梯度不是一回事：一些optimizer跳过没有grad的参数，其衰减/状态也不会按0梯度步走。冻结层时须确认参数组与梯度行为。不同版本、foreach/fused实现和dtype可能有微小舍入差，本例选float64/CPU与明确容差，不以浮点末位差异直接判断公式错误。

## 7. 自查、改动练习与判断标准

1. 全零Sigmoid网络输出0.5说明健康吗？**答案：**不能；本例输入梯度0且单元对称。线性模型0起点和隐藏层全零不是同一问题。
2. ReLU He维持的是方差还是二阶矩？**答案：**推导里的 $E[h^2]$，中心化方差还减去非零均值平方；有限网络与训练后条件都需另查。
3. fan-in16→1024使用固定std1与He差别？**答案：**线性层未缩放二阶矩因子为16与1024；He+对称ReLU近似均为1。矩阵宽度本身仍改变有限样本相关性和计算成本。
4. 增加LeCun或正交候选怎样比较？**参考：**在相同初始输入、层尺寸、激活和种子下记各层mean/std/RMS与梯度，再训练独立验证。正交矩形用 `U@Vh`保持原shape，不直接拿U导致维度变化。
5. 测warmup0%、1%、5%、10%、20%，多少步达到90%？**参考：**把80轮CPU程序改成预定相同预算对照，只看验证目标；若某配置未达阈值报告未达，不补编轮数。当前示例不执行所有比例和十种子发散统计。
6. Adam每坐标有效率都相同吗？**答案：**标量lr相同，分母缩放与一阶矩不同；将缩放系数、梯度步、含衰减总更新分别记录，不能把有符号更新叫lr。
7. 梯度裁剪能保证十种子都无NaN吗？**答案：**不能；可能改善部分大梯度，但先有限值检查、保存首次失败输入/状态，再做可复现多种子统计。
8. AdamW一定比Adam更快缩权吗？**答案：**零任务梯度下可隔离其衰减；有任务梯度、耦合L2和不同状态时总范数不必同排序，需完整对照。
9. cosine与restart有什么不同？**答案：**固定预算余弦到终点，此处保持floor；restart按周期重新升率，通常不清矩状态。OneCycle还需明确升段比例和调度每更新。
10. “自动监测平台期换schedule”可以完全免调参吗？**答案：**不行，窗口、耐心、阈值、最小率和停止规则仍是选择；不得用测试驱动。
