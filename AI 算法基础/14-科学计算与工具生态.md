## 1. NumPy

### ndarray

核心属性：

- shape；
- dtype；
- ndim；
- strides。

关键能力：

- vectorization；
- broadcasting；
- slicing；
- advanced indexing；
- ufunc；
- reduction。

### Broadcasting

从右到左比较维度：

- 相等；
- 或其中一个为 1；

即可扩展。

正确使用广播能避免 Python loop，但错误广播也可能静默产生错误结果。

### View vs Copy

切片常产生 view；高级索引常产生 copy。

这直接影响：

- 内存；
- 原地修改；
- 性能。

## 最容易静默出错的广播

若预测数组形状为 `(3, 1)`，标签为 `(3,)`，直接相减会广播成 `(3, 3)`，而不是期望的 3 个逐样本误差。例如预测 `[1, 2, 3]`、标签 `[1, 2, 4]`，正确残差应是 `[0, 0, -1]`。

动手步骤：先打印两个 `shape`；将两者显式整理为同一约定（都为 `(3,)` 或都为 `(3, 1)`）；再计算残差和均方误差。**应得结果：**$1/3$。

自查：NumPy 广播规则允许这次相减，为什么仍是错误？**答案：**数组运算合法不代表样本语义匹配；必须同时核对轴的含义。pandas 的索引对齐同样需要检查，不能只看行数相等。

核验（2026-10-02）：[NumPy 广播规则](https://numpy.org/doc/stable/user/basics.broadcasting.html)。运行具体库代码时应在学习记录中保存实际版本。

## 14. AI By Doing 增量：Jupyter、TensorFlow 与 PyTorch 的稳定学习抽象

> 对应来源第 49～57、90～96 章。具体框架 API 会更新，因此这里只固化跨版本稳定的概念与可复现习惯。

### 14.1 Jupyter 最危险的是隐藏状态

Notebook 可以不按从上到下顺序执行，因此可能出现：

- 某变量来自早先已删除的 cell；
- 重启 kernel 后无法复现；
- cell 输出与当前代码不匹配；
- 当前工作目录发生变化；
- 随机状态未固定。

最低验收：

1. Restart kernel；
2. Run all；
3. 从第一格到最后一格无人工补步骤；
4. 结果与正文解释一致。

Notebook 是交互环境，不是可复现性的替代品。

### 14.2 TensorFlow 与 PyTorch 的共同结构

两套框架长期都围绕：

- tensor；
- model/module；
- forward computation；
- automatic differentiation；
- loss；
- optimizer；
- dataset/batch；
- checkpoint；
- train/eval behavior。

先理解这些对应关系，再学习框架语法。

### 14.3 Tensor 的三件事

每个 tensor 至少检查：

- shape；
- dtype；
- device。

大量训练错误都来自：

- batch/channel 轴错误；
- float/int 不匹配；
- CPU/GPU 混用；
- label shape 不符合 loss 约定。

### 14.4 自动求导的最小理解

给计算：

$$
z=f_\theta(x)
$$

$$
L=g(z,y)
$$

框架会沿计算图求：

$$
\nabla_\theta L
$$

但仍必须知道：

- 哪些参数要求梯度；
- 梯度何时清零；
- 哪些操作切断计算图；
- 推理时为何关闭梯度；
- train/eval mode 如何影响 dropout / normalization。

### 14.5 从框架训练循环抽象出五步

每个 mini-batch：

1. 取数据；
2. forward；
3. compute loss；
4. backward；
5. optimizer step。

训练外还要：

- validation；
- checkpoint；
- early stopping 或其他停止标准；
- metric；
- error analysis。

具体 API 名称可以变化，五步语义不会改变。

### 14.6 NumPy / pandas / Matplotlib / Seaborn / SciPy 的分工

- NumPy：数组和数值计算；
- pandas：带标签表格与时间序列；
- Matplotlib：底层通用绘图；
- Seaborn：统计可视化的高层接口；
- SciPy：优化、线代、统计、信号等科学计算算法。

工具的价值在分工，不在背 API。实际使用时对照当前官方文档。

### 14.7 一个框架练习的最低标准

对任何“用 TensorFlow/PyTorch 做分类”的练习，至少保存：

- 输入 shape；
- label 编码；
- 模型输出 shape；
- loss 定义；
- 一个 batch 的 forward；
- 一个 batch 的 backward；
- train/validation 曲线；
- 错误样例；
- 运行时依赖版本。

只看到 epoch 日志不等于理解训练过程。
