# 09｜预处理管道与可复现实验

> 先修：训练/验证/测试、缺失值、标准化和类别编码。基础处理入口仍为[主章05](../05-特征工程-评估与无监督学习.md)，表格读取见[Python数据准备](../../数据科学基础/05-Python数据处理与数据准备.md)，Notebook顺序与环境见[可复现分析](../../数据科学基础/11-Notebook实验与可复现分析.md)。本章把处理步骤的学习状态、交叉验证、推理和保存连成一个实际程序。

## 1. 为什么模型文件不够

假设训练时把缺失年龄填30，再按均值40、标准差10缩放。原值50的输入变成1；推理端重新按当前batch均值50、标准差2缩放，同一个人变成0。即使模型权重没变，实际预测函数已经变了。

完整预测函数是 $\hat y=M(T_k(\cdots T_1(x)))$。其中填补器中位数、缩放器均值方差、类别集合、词表、PCA方向、特征选择掩码都是**已学状态**，与模型参数一起保存。固定单位转换不必拟合统计，但也要保留一致规则和版本。

管道帮助按顺序组合，不自动修好错误输入。目标编码泄漏、未来特征、错误实体划分、复用测试调参，即使包进Pipeline也仍错误。它主要保证把正确拟合边界内的预处理与模型作为一个单位调用。

| 方法 | 输入 | 是否学习状态 | 什么时候使用 |
|---|---|---|---|
| `fit` | 训练数据，必要时标签 | 是 | 拟合训练步骤或某折训练部分 |
| `transform` | 新输入 | 不重新学习 | 应用已保存状态到验证/测试/推理 |
| `fit_transform` | 训练数据 | 拟合并应用 | 训练预处理；部分监督编码可能有专用折外逻辑 |
| `predict` | 原始新输入 | 不重新学习 | 管道先transform再由模型预测 |

通常中间步骤须能transform，最后一步是预测器，也可以是最后一个Transformer。scikit-learn Pipeline依次训练中间步骤后拟合最后一步；交叉验证会克隆并重训整个管道。不能在CV之前先对全部数据调用`fit_transform`，再仅把模型放进CV。

## 2. 手写数值管道：用代码看到fit/transform区别

如下完整例只演示连续特征，包含中位数填补、标准化和最小二乘。生产用成熟实现；这个程序不宣称支持完整scikit-learn协议、稀疏矩阵、监督Transformer或多类分类。

```python
import numpy as np

class NumericPrep:
    def fit(self, X):
        X = np.asarray(X, dtype=float)
        if X.ndim != 2 or len(X) == 0 or np.isinf(X).any() or np.isnan(X).all(axis=0).any():
            raise ValueError("训练须为非空二维；无无穷值，不能有整列缺失")
        self.median = np.nanmedian(X, axis=0)
        filled = np.where(np.isnan(X), self.median, X)
        self.mean = filled.mean(axis=0)
        self.std = filled.std(axis=0)
        self.std[self.std == 0] = 1.
        return self

    def transform(self, X):
        if not hasattr(self, "median"):
            raise RuntimeError("请先fit")
        X = np.asarray(X, dtype=float)
        if X.ndim != 2 or X.shape[1] != len(self.median) or np.isinf(X).any():
            raise ValueError("预测字段维度或数值不合法")
        return (np.where(np.isnan(X), self.median, X)-self.mean)/self.std

class LinearLeastSquares:
    def fit(self, X, y):
        self.w = np.linalg.lstsq(np.c_[np.ones(len(X)), X], y, rcond=None)[0]
        return self
    def predict(self, X):
        return np.c_[np.ones(len(X)), X] @ self.w

class NumericPipeline:
    def __init__(self):
        self.prep, self.model = NumericPrep(), LinearLeastSquares()
    def fit(self, X, y):
        self.prep.fit(X)
        self.model.fit(self.prep.transform(X), y)
        return self
    def predict(self, X):
        return self.model.predict(self.prep.transform(X))

Xtrain = np.array([[0., 5.], [1., 5.], [2., 5.], [3., 5.]])
ytrain = np.array([1., 3., 5., 7.])
pipe = NumericPipeline().fit(Xtrain, ytrain)
saved = pipe.prep.mean.copy()
pred = pipe.predict([[4., 5.], [np.nan, 5.]])
assert np.array_equal(saved, pipe.prep.mean)
assert np.allclose(pred, [9., 4.])
print("训练中位数", pipe.prep.median.tolist(), "预测", pred.round(6).tolist())
```

第二列恒定，标准差设1避免除0；训练第一列中位数1.5，所以缺失输入的预测为4。推理没有更新状态。真实“整列训练缺失”需明确政策：丢弃、常量填补或保留空特征，不应悄悄得到NaN。异常缺失模式还应作为输入质量问题监控。

## 3. 混合表格用ColumnTransformer分路处理

数字分支：缺失填补→缩放；类别分支：缺失填补→one-hot；分支按固定顺序拼接→模型。one-hot词表只由训练得出，未知类别可转全0或专用未知/低频桶，**全0不等于模型学会了新类别**。使用`drop`时全0还可能与被丢基准类别混同；应同时记录未知比例。

`ColumnTransformer`按列选择并拼接，`remainder="drop"`明确丢弃未指定列；若选择passthrough，要核对额外列不会把目标或ID带进模型。固定列名不是天然错误，schema契约需要稳定字段；用配置管理列名也仍须校验类型和版本。

### 3.1 完整5折管道及跨进程保存验证

下面生成3数值+2类别特征及二分类标签，先划分开发/测试，再让CV训练完整管道。每一折还检查中位数确由该训练折产生。小数据用密集one-hot，避免某些模型不接受稀疏输出；大类别数据应评估内存和编码方案。

```python
import json
import subprocess
import sys
import tempfile
from pathlib import Path
import joblib
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, train_test_split, cross_validate
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

rng = np.random.default_rng(42)
n = 240
age = rng.normal(35, 10, n)
income = rng.lognormal(10, 0.5, n)
score = rng.uniform(300, 850, n)
city = rng.choice(["合肥", "南京", "杭州"], n)
plan = rng.choice(["基础", "高级"], n)
y = (0.05*(age-35) + 0.00005*(income-25000) + 0.004*(score-600)
     + 0.6*(plan == "高级") + rng.normal(0, 0.6, n) > 0).astype(int)
df = pd.DataFrame({"age": age, "income": income, "score": score, "city": city, "plan": plan})
df.loc[rng.choice(n, 12, replace=False), "age"] = np.nan
df.loc[rng.choice(n, 8, replace=False), "income"] = np.nan
df.loc[rng.choice(n, 6, replace=False), "city"] = np.nan
Xt, Xtest, yt, ytest = train_test_split(df, y, test_size=0.2, stratify=y, random_state=42)

numbers, categories = ["age", "income", "score"], ["city", "plan"]
numeric = Pipeline([("impute", SimpleImputer(strategy="median")), ("scale", StandardScaler())])
categorical = Pipeline([("impute", SimpleImputer(strategy="most_frequent")),
                        ("encode", OneHotEncoder(handle_unknown="ignore", sparse_output=False))])
prep = ColumnTransformer([("num", numeric, numbers), ("cat", categorical, categories)],
                         remainder="drop")
pipe = Pipeline([("prep", prep), ("model", LogisticRegression(max_iter=1000))])
cv = StratifiedKFold(5, shuffle=True, random_state=42)
results = cross_validate(pipe, Xt, yt, cv=cv,
                         scoring={"f1": "f1", "accuracy": "accuracy"}, return_estimator=True)
for (train, _), fitted in zip(cv.split(Xt, yt), results["estimator"]):
    med = fitted.named_steps["prep"].named_transformers_["num"].named_steps["impute"].statistics_
    assert np.allclose(med, Xt.iloc[train][numbers].median().to_numpy())
print("各折F1", results["test_f1"].round(4).tolist())
pipe.fit(Xt, yt)
pred = pipe.predict(Xtest)
unknown = Xtest.iloc[:2].copy()
unknown["city"] = "未见城市"
print("未知类别预测", pipe.predict(unknown).tolist())
print("输出特征数", len(pipe.named_steps["prep"].get_feature_names_out()))

# 只加载本程序生成的可信本地文件；joblib加载会执行pickle协议。
with tempfile.TemporaryDirectory() as directory:
    artifact = Path(directory)/"pipeline.joblib"
    joblib.dump({"pipeline": pipe, "X": Xtest}, artifact)
    child_code = """import json, sys, joblib
bundle = joblib.load(sys.argv[1])
print(json.dumps(bundle['pipeline'].predict(bundle['X']).tolist()))
"""
    output = subprocess.check_output([sys.executable, "-c", child_code, str(artifact)], text=True)
    loaded_pred = np.asarray(json.loads(output))
    assert np.array_equal(pred, loaded_pred)
print("跨进程加载预测一致", True)
```

这段验证同一解释器环境中的5折边界、未知类别不崩溃、完整管道跨进程恢复；它没有自动证明真实业务数据、跨版本、远程API和容器可用。测试标签在此没有参与选择。模型输出可按[评估专题](07-评估指标验证与不平衡学习.md)增加冻结后的F1、概率指标和错误分析。

`sparse_output=False`是所测版本的当前接口，旧教材常见`sparse=False`不能混用；版本发生变化时查对应版本文档。高维稀疏数值特征用标准化时注意`with_mean=False`，否则中心化常破坏稀疏性。选择密集输出也可能把海量one-hot占满内存。

### 3.2 自定义Transformer与监督编码

对scikit-learn自定义步骤，通常继承`BaseEstimator, TransformerMixin`，构造函数只存参数，`fit(X,y=None)`学习状态并返回self，`transform(X)`使用已学状态、保持样本对应关系；状态名用结尾`_`方便检查。不要在构造函数读取全数据。若按标签选择最重要列，该选择也必须在训练折拟合。

二次多项式特征在数字分支填补后构造，再缩放、进入模型；应排除不合适的ID/one-hot乘积和过大特征组合。选“两列最重要”的动作不能事先看验证标签；若两列是预先领域定义，可固定在配置。目标编码须对训练行采用合适折外逻辑，普通Pipeline封装并不能自动防止同一行标签泄入编码。

## 4. 泄漏检查要看状态，不只看分数

训练值 `[0,2]`，测试值 `[100,102]`：训练均值1，全数据均值51。若先全数据缩放再切分，训练变换已含测试分布信息；这足以识别泄漏。即使最终Accuracy恰好相同，边界仍错误。

```python
import numpy as np
from sklearn.preprocessing import StandardScaler
Xtrain, Xtest = np.array([[0.], [2.]]), np.array([[100.], [102.]])
clean = StandardScaler().fit(Xtrain)
leaky = StandardScaler().fit(np.vstack([Xtrain, Xtest]))
print("训练均值/泄漏均值", clean.mean_.tolist(), leaky.mean_.tolist())
assert np.allclose(clean.mean_, [1.]) and np.allclose(leaky.mean_, [51.])
print("同一测试值的两种变换", clean.transform(Xtest[:1]).ravel().tolist(),
      leaky.transform(Xtest[:1]).ravel().tolist())
```

缩放泄漏不保证每次都使分数上升，也没有固定“涨10～30%”幅度。要证实具体影响，固定划分/模型，比泄漏与干净两条链；监督特征选择、目标编码和复制样本常更严重。若当前任务合法允许未标注部署数据参与变换，这属于另行明确的transductive设计，不能悄悄套普通独立测试的解释。

## 5. 训练、推理与输入契约

至少声明字段名、顺序、单位、类型、允许缺失、取值范围、类别状态、预测时点。输入服务应该拒绝缺字段/错误单位，明确多余字段政策，不能把“收入元”与“收入万元”混为数字。按列名选择的DataFrame比裸数组更不易错序，但也要检查同名字段语义。

训练/推理两端共用管道可减少重复实现，仍需核对原始特征采集：离线表连接与在线缓存可能有不同时间窗口，数据库延迟也可能让推理缺信息。要用几条保存的合法原始样本比较两端变换后特征和预测，而不只比较模型文件hash。

检查最低失败集：整列训练缺失、预测新类别、错dtype、额外/缺少列、空batch、极端值、无穷值、长期未知类别比例上涨。未知类别“能预测”不代表预测可靠；数据漂移可能需观察真实标签后的任务效果。

## 6. 可复现记录与实验追踪

种子、依赖、数据、参数是必要部分，还要保存代码提交、切分索引/实体规则、特征契约、运行命令、硬件与线程、外部资源版本、预处理状态、目标定义和结果文件。固定种子不保证跨硬件/并行顺序/框架版本逐bit一致；可区分“同环境完全一致”和“指标在合理容差内稳定”。

最小追踪不需要外部平台，一个本地JSON记录即可。如下是可运行的独立合成记录示例，不写入仓库永久日志：

```python
import hashlib
import json
import platform
import sys
import tempfile
from pathlib import Path
import numpy as np
import scipy
import sklearn
data = np.arange(12, dtype="<f8").reshape(6, 2)
record = {
    "run_id": "教学示例-001", "任务": "演示实验记录，不代表真实效果",
    "数据SHA256": hashlib.sha256(data.tobytes()).hexdigest(),
    "代码版本": "实际项目填写git提交SHA", "切分": {"train": [0,1,2,3], "val": [4,5]},
    "参数": {"seed": 42, "model__alpha": 1.0},
    "环境": {"python": sys.version.split()[0], "numpy": np.__version__,
               "scipy": scipy.__version__, "sklearn": sklearn.__version__,
               "平台": platform.platform()},
    "验证范围": "只验证JSON记录与校验值；此例未训练模型",
}
with tempfile.TemporaryDirectory() as directory:
    file = Path(directory)/"run.json"
    file.write_text(json.dumps(record, ensure_ascii=False, indent=2), encoding="utf-8")
    loaded = json.loads(file.read_text(encoding="utf-8"))
    assert loaded["数据SHA256"] == record["数据SHA256"]
print("记录往返一致", True)
```

数据hash需要明确字节序、行序、dtype、NaN表示和列名等规范；本例固定数组布局，真实表格不能只hash某几列就称整数据版本。JSON参数与种子要包含所有会影响行为的步骤，不能把示例“待填写”当真实代码版本。

MLflow可以记录参数、指标、artifacts和模型，W&B提供相似追踪能力；选择取决于现有环境、账户、数据和团队流程。此批不创建账号或安装追踪服务器。追踪系统保存记录不代表能复现：输入数据、依赖和可执行代码也必须可取得。

### 6.1 数据版本与模型版本

小数据可在许可范围内直接Git管理；大数据通常用对象存储+内容hash/manifest，DVC让Git记录`.dvc`元信息与数据指纹、实际内容保存在cache/remote。`dvc checkout`通常从可用cache恢复工作区；缺cache时需获取对应remote对象，数据被删除、权限失效或外部源变化时不是“Git提交就保证可恢复”。

如下是**操作示例，未在本批执行DVC**，应在实际项目且有数据存储方案后使用：

```bash
dvc init
dvc add data/training.csv
git add data/training.csv.dvc data/.gitignore
git commit -m "记录训练数据版本与校验值"
# 配置授权的remote并上传对象后，换版本时按需要dvc pull与dvc checkout。
```

模型注册应记录不可变版本、训练run、数据、指标和artifact校验；发布时用明确审批/验收把某版本指向当前服务，保留上一版用于回滚。MLflow旧`Staging/Production/Archived` **Model Stages已弃用**，当前可用alias/tag及环境划分表达流程，例如`champion`指向已确认版本。alias可变化，本身不代替审批，也不能自动使正在运行的服务立即切换；部署系统要定义什么时候重载和如何回滚。

## 7. 保存格式、版本与验收

joblib/pickle适合可信本地Python管道，**加载可执行代码，只加载已确认来源的文件**。保存与加载通常需要兼容的Python/依赖；scikit-learn不保证任意跨版本模型加载。自定义类需可导入的模块，Notebook临时类常破坏可移植性；完整管道保存也不能自动保存数据库连接和外部特征服务。

如需非Python推理可评估ONNX等格式，但转换覆盖范围、预处理、数值精度和一致性都要另测；不能仅“导出成功”就称行为一致。保存一份小golden输入和预期输出，在新进程或部署环境复验标签、概率及容差，并记录加载环境。

Notebook迁移顺序可采用：抽取稳定函数→管道→配置与schema→本地记录→必要检查→保存/加载对照→实际部署验收。不要为了教程形式直接加外部平台；数据准备和训练过程可先在一个可复现本地程序中完成。

## 8. 练习与参考答案

1. 为什么预测时不用`fit_transform`？**答案：**会重新学新batch统计、改变原预测函数；推理用已拟合`transform`，需要适应新分布时另有明确更新和验证过程。
2. 3数字+2类别管道5折怎样证明无预处理泄漏？**答案：**CV包整个管道，检查每折imputer/scaler/词表由对应训练索引取得，验证部分只transform；本章断言核对中位数是局部证据，还要检查任务/时间/实体边界。
3. 泄漏版和干净版分数相同，就可用泄漏版吗？**答案：**不能；分数相同不使不合法信息边界变正确，统计状态例已经证明使用了测试数据。
4. 只保存模型权重够吗？**答案：**不够。还需完整已学预处理、字段契约、版本与依赖，并在新进程比较合法原始输入的结果。
5. 年龄与收入二次特征应该放哪里？**答案：**在数字分支填补后构造，再进行合适缩放；选这两列若根据标签决定，也须训练折内完成。
6. 跑5个配置如何比较？**参考：**预定相同CV/指标，保存完整参数、切分、数据/代码版本和运行结果；在本地JSON或授权追踪平台比较。最佳CV值参与选择，另做测试。MLflow UI教程未运行，不标“已搭好”。
7. 种子相同而结果略异怎么办？**答案：**查并发、浮点硬件、库版本、非确定算子、外部输入和运行顺序；先定义需要逐bit还是统计容差复现，不盲目重设更多种子。
8. DVC文件还在但remote对象丢了能还原数据吗？**答案：**元信息本身不能还原内容；需保留可取得的cache/remote和权限。版本管理不是备份替代。
