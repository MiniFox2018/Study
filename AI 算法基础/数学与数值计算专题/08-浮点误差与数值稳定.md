# 08｜浮点误差与数值稳定

> 先修：[微积分与自动微分](06-微积分梯度与自动微分.md)、指数与对数。先运行精度和稳定损失例，再学习混合精度。数值稳定意味着算法在有限精度下尽量可靠，不意味着计算机恢复了精确实数。

## 1. 浮点格式：指数给范围，尾数给精度

二进制规格化浮点数形如 $(-1)^s2^{e-\text{bias}}(1.f)$。符号位确定正负，指数确定数量级，尾数保存有效数字；零、次正规数、无穷与 NaN 有特殊编码，不能用同一条规格化公式解释所有位模式。

| 格式 | 符号/指数/显式尾数位 | 约最大有限值 | 在 1 附近的间隔 `eps` |
|---|---|---|---|
| float64 | 1 / 11 / 52 | $1.80\times10^{308}$ | $2^{-52}\approx2.22\times10^{-16}$ |
| float32 | 1 / 8 / 23 | $3.40\times10^{38}$ | $2^{-23}\approx1.19\times10^{-7}$ |
| float16 | 1 / 5 / 10 | 65504 | $2^{-10}\approx9.77\times10^{-4}$ |
| bfloat16 | 1 / 8 / 7 | $3.39\times10^{38}$ | $2^{-7}\approx7.81\times10^{-3}$ |

float32 有约 7 位十进制有效数字，float64 约 15～16 位，精度是相对数量级的，不是小数点后固定几位。绝对值越大，相邻可表示数间距越大。float16 精度比 bfloat16 高，但范围窄；bfloat16 的指数位和 float32 相同，并不等于两者最大有限值逐位相等。

`eps` 通常定义为 1 与下一个更大可表示数的距离，不是“最小正数”，也不是“最小使 1+x=1 的 x”。IEEE 最近偶数舍入下，约半个 `eps` 的扰动可能已经被舍掉；`tiny` 通常指最小正规格化数，次正规数还能更小。部分硬件会把次正规数冲成零，应看实际运行环境。

```python
import numpy as np

for dtype in (np.float16, np.float32, np.float64):
    info = np.finfo(dtype)
    gap = np.nextafter(dtype(1), dtype(2)) - dtype(1)
    print(dtype.__name__, "eps", info.eps, "间隔", gap,
          "最小规格化数", info.tiny, "最大数", info.max)
    assert gap == info.eps
a = np.float32(1)
assert np.float32(a + np.float32(np.finfo(np.float32).eps/2)) == a
print("半个 float32 eps 在 1 附近被舍入掉")
```

Python `float` 通常是双精度；`math.exp(100)` 在 float64 中有效，`np.exp(np.float32(100))` 会溢出。讲一个数值实验时，必须同时说明操作和数据类型。Python 标量的除零、负数实数对数常抛异常；NumPy 浮点数组常产生 inf/NaN 并给警告，不能混写。

## 2. 三类误差及怎样比较结果

0.1 是无限循环的二进制小数，有限尾数只能舍入，因此 `0.1+0.2` 与存储的 `0.3` 可能相差末位。浮点加法也不结合：

```python
import math

a, b, c = 1e16, -1e16, 1.0
print("两种求和次序：", (a+b)+c, a+(b+c))  # 1.0 与 0.0
assert math.isclose(0.1+0.2, 0.3, rel_tol=1e-12, abs_tol=1e-15)
```

`isclose` 用绝对与相对容差，例如 $|a-b|\le\max(\text{atol},\text{rtol}\max(|a|,|b|))$。近零用绝对容差，大尺度用相对容差；容差由目标精度和问题尺度决定。精确比较零、整数可精确表达值或 sentinel 有时正确，不应机械禁止所有浮点 `==`。

- **上溢（overflow）**：结果过大，成为 inf 或异常。float32 的指数在约 $e^{88.7}$ 附近接近上限。
- **下溢（underflow）**：结果进入低精度次正规区域，最后可能舍入到零；并非一小于最小规格化值就必为零。float16 最小正次正规数约 $5.96\times10^{-8}$，更小数在最近舍入下也可能舍成该值，约小于其一半才趋于零。
- **灾难性相消**：两个接近的大数相减，输入的舍入误差变成结果的大相对误差；不是“减法本身永远不准确”，而是最终小差值难保有效位。

float32 的 $1.0000001-1$ 约为 $1.1920929\times10^{-7}$，相对真实 $10^{-7}$ 偏约 19.2%。先转换到低精度再转高精度，已经丢掉的位无法恢复。

## 3. 求和、方差与输入精度的限制

方差的 $E[x^2]-E[x]^2$ 要相减两个很接近的大数，数据均值大、波动小时容易出错甚至负值。先中心化计算平方偏差，或使用 Welford 在线更新：

$$
n\leftarrow n+1,\quad\delta=x-\mu,\quad
\mu\leftarrow\mu+\delta/n,\quad
M_2\leftarrow M_2+\delta(x-\mu).
$$

总体方差为 $M_2/n$，样本无偏方差为 $M_2/(n-1)$；空数据未定义，样本方差至少需两个样本。下面比较 float32 朴素公式与高精度累计：

```python
import numpy as np

data = np.array([1000000, 1000001, 1000002], dtype=np.float32)
naive = np.mean(data*data, dtype=np.float32) - np.mean(data, dtype=np.float32)**2
count, mean, m2 = 0, 0.0, 0.0
for value in data:
    value = float(value)
    count += 1
    delta = value - mean
    mean += delta/count
    m2 += delta*(value-mean)
stable = m2/count
print("朴素与稳定方差：", naive, stable)
assert abs(stable-2/3) < 1e-12
```

三个整数在 float32 中还可精确保存；若数据已量化为完全相同值，Welford 也无法找回失去的差异。比如在 $10^8$ 附近 float32 间隔已约 8，先以它保存 $10^8+1,10^8+2$ 就会丢掉部分波动。

大量累加时可用更高精度 accumulator、树状/成对求和或补偿求和。Kahan 把上一步丢失的低位作为下一步补偿：

```python
import math

def kahan(values):
    total, compensation = 0.0, 0.0
    for value in values:
        corrected = value - compensation
        next_total = total + corrected
        compensation = (next_total-total)-corrected
        total = next_total
    return total

values = [1e-7]*100000
plain = 0.0
for value in values:
    plain += value
print("逐项累计、Kahan、fsum：", plain, kahan(values), math.fsum(values))
assert abs(kahan(values)-0.01) <= abs(plain-0.01)
```

Kahan 缓解某些累计舍入，不是每种符号混合序列上的最优解；也不能修复输入已溢出或已被舍成零的值。Python 内建 `sum` 和数值库实现可能随版本采用更好的累加策略，所以示例显式使用朴素循环作为对照。

## 4. 稳定 log-sum-exp、softmax 与交叉熵

$$
\operatorname{LSE}(z)=\log\sum_i e^{z_i}
=m+\log\sum_i e^{z_i-m},\qquad m=\max_i z_i.
$$

证明只需把每项写成 $e^m e^{z_i-m}$，把公因子移到对数外。至少一项为 $e^0=1$，其余不大于 1，所以有限 logits 下避免指数上溢且不会整组指数全下溢。softmax 对加同一个常数不变：$p_i=e^{z_i-m}/\sum_j e^{z_j-m}$。

例如 $[1000,1001,1002]$ 先减 1002 得 $[-2,-1,0]$，概率约 $[0.0900306,0.2447285,0.6652410]$。真实类别为 0 的交叉熵约 2.407606；为 2 则约 0.407606。

稳定 softmax 仍可能把极小概率舍成零，因此不能先 softmax 再 log。直接计算

$$
\log p_i=(z_i-m)-\log\sum_j e^{z_j-m},\qquad
L=-\log p_y
$$

更稳。注意先用减过最大值的差计算 log 概率，可减少把巨大共同偏移加回来又减掉的相消。

下面是完整的单向量 NumPy 教学实现。允许 `-inf` 表示不可选类别；全 `-inf` 的 softmax 未定义，必须显式失败，不能制造均匀分布。NaN 与 `+inf` 对 softmax 也拒绝；LSE 的空和定义为 $-\infty$。

```python
import numpy as np

def vector(values):
    z = np.asarray(values, dtype=np.float64)
    if z.ndim != 1:
        raise ValueError("本教学实现仅接受一维 logits")
    if np.any(np.isnan(z)):
        raise ValueError("输入含 NaN")
    return z

def logsumexp(values):
    z = vector(values)
    if z.size == 0:
        return -np.inf
    m = np.max(z)
    if np.isinf(m):
        return float(m)  # +inf 或整组 -inf
    return float(m + np.log(np.exp(z-m).sum()))

def log_softmax(values):
    z = vector(values)
    if z.size == 0 or np.any(np.isposinf(z)) or np.all(np.isneginf(z)):
        raise ValueError("无法归一化：空向量、+inf 或全部类别被屏蔽")
    shifted = z - np.max(z)
    return shifted - np.log(np.exp(shifted).sum())

def softmax(values):
    return np.exp(log_softmax(values))

def cross_entropy(values, target):
    logs = log_softmax(values)
    if not isinstance(target, (int, np.integer)) or not 0 <= target < len(logs):
        raise ValueError("类别索引越界或不是整数")
    return float(-logs[target])

print("稳定概率：", softmax([1000, 1001, 1002]))
print("极端错误预测的损失：", cross_entropy([1000, -1000], 1))
assert cross_entropy([1000, -1000], 1) == 2000
assert np.allclose(softmax([-1000, -999, -998]), softmax([0, 1, 2]))
assert np.isclose(logsumexp([5, 5, 5]), 5+np.log(3))
assert softmax([0, -np.inf])[1] == 0
```

本例对 `[1000,-1000]` 的错误类别保留 2000 的有限 log 损失，虽然概率会下溢为零。如果输入先存成 float32，两个大 logits 本来相差 1 却因量化变为相同值，稳定公式也无法挽回这一输入精度损失。

二分类也可直接从 logit 计算：

$$
\operatorname{BCE}(z,y)=\max(z,0)-yz+\log(1+e^{-|z|}).
$$

`log1p` 专门计算 $\log(1+u)$，$u$ 很小时比先加 1 再 log 精确。sigmoid 则在正负半轴选不同但等价的公式：

```python
import math

def sigmoid(z):
    if z >= 0:
        q = math.exp(-z)
        return 1/(1+q)
    q = math.exp(z)
    return q/(1+q)

def bce_with_logits(z, y):
    if not math.isfinite(z) or not 0 <= y <= 1:
        raise ValueError("logit 需有限，标签需在 [0,1]")
    return max(z, 0)-y*z+math.log1p(math.exp(-abs(z)))

assert sigmoid(-1000) == 0
assert bce_with_logits(-1000, 1) == 1000
assert math.isclose(bce_with_logits(0, 1), math.log(2))
print("稳定二分类计算通过")
```

框架中交叉熵通常接受原始 logits；不要把 softmax 概率重复传入当作 logits。随意给 log、分母加 epsilon 或截断 logits 可能改变目标与梯度；先找等价稳定公式，只有模型明确需要平滑/正则时才引入有解释的 epsilon。

## 5. 梯度检查：既验证正确，也要能识别错误

检查时固定输入和随机种子、关随机噪声、用 float64、小规模参数，并选择可微点。中央差分的误差同时受 $O(h^2)$ 截断和约 $O(\varepsilon/h)$ 舍入影响；过小步长不是更精确。参数有不同尺度时分别调步长。

以下完整例检查 $L(W,b)=\tfrac12\|Wx+b\|^2$ 的六个权重和三个偏置；解析梯度为 $dW=(Wx+b)x^{\mathsf T}$、$db=Wx+b$。

```python
import numpy as np

x = np.array([0.4, -0.7])
params = np.linspace(-0.5, 0.5, 9)

def loss(parameters):
    W = parameters[:6].reshape(3, 2)
    b = parameters[6:]
    z = W @ x + b
    return 0.5 * z @ z

W, b = params[:6].reshape(3, 2), params[6:]
z = W @ x + b
analytical = np.concatenate([np.outer(z, x).ravel(), z])
numeric = np.zeros_like(params)
for i in range(len(params)):
    h = 1e-5*max(1.0, abs(params[i]))
    delta = np.zeros_like(params)
    delta[i] = h
    numeric[i] = (loss(params+delta)-loss(params-delta))/(2*h)
assert np.allclose(analytical, numeric, rtol=1e-6, atol=1e-8)
wrong = analytical.copy()
wrong[0] += 0.1
assert not np.allclose(wrong, numeric, rtol=1e-6, atol=1e-8)
print("线性层梯度正确，故意写错的梯度被识别")
```

再用上一节 `cross_entropy` 对 logits 做有限差分，应得到 $p-\operatorname{onehot}(y)$，所有分量和约为零，因为添加共同常数不改变损失。误差阈值只能结合 dtype、函数尺度、近零梯度和非光滑点判断，不能把 `1e-7` 称为所有问题的“完美正确线”。

## 6. 混合精度、损失缩放与 bfloat16

混合精度让适合的矩阵计算使用低精度，在累加、归一化、损失等敏感位置使用较高精度。常见做法保持 float32 参数/更新或主副本，并由 autocast 按算子策略选 dtype；不是简单把所有前向/反向强制成 float16。性能提升依硬件、算子、访存与工作负载，不给固定倍数承诺。

如果小梯度在 float16 的反向运算中舍成零，令 $L'=SL$，反向得到 $g'=Sg$，更新前恢复 $g=g'/S$。必须**在发生低精度舍入之前**放大；先把梯度舍成零再乘 $S$ 无效。缩放不改变理想更新，但数值量化仍存在，太大 $S$ 又会溢出。动态缩放检测非有限梯度，跳过本次更新并减小尺度，在稳定一段时间后尝试增大。

```python
import numpy as np

g = np.geomspace(1e-9, 1e-3, 1000)  # 覆盖不同数量级
raw = g.astype(np.float16).astype(np.float64)
scale = 1024.0
restored = (g*scale).astype(np.float16).astype(np.float64)/scale
print("未缩放零梯度数量：", np.count_nonzero(raw == 0))
print("缩放后零梯度数量：", np.count_nonzero(restored == 0))
assert np.count_nonzero(restored == 0) < np.count_nonzero(raw == 0)
```

这是 CPU 类型转换模拟，只验证“放大后量化、再恢复”减轻下溢，不证明 GPU 训练效果。bfloat16 范围较宽，通常更少需要为下溢做 loss scaling，但更粗的尾数仍会舍掉小更新；它并不免疫溢出、精度损失或错误损失函数。bfloat16 转换通常有舍入规则，简单截断 float32 尾位只是教学近似。float16/bfloat16 都可用于训练或推理，应据硬件支持、模型稳定与精度验证选择，不能固定成“前者仅推理、后者仅训练”。

### 当前 PyTorch 写法与操作顺序

下面是 **CUDA 环境操作模板，本次仅核对 API，未运行 GPU**。变量由真实训练代码提供，使用当前 `torch.amp` API。裁剪前必须 unscale，否则阈值作用于放大后的梯度。

```python
# 操作模板：需已安装 PyTorch、可用 CUDA 及 model/batch/labels/optimizer。
import torch
import torch.nn.functional as F

scaler = torch.amp.GradScaler("cuda")
optimizer.zero_grad(set_to_none=True)
with torch.autocast(device_type="cuda", dtype=torch.float16):
    logits = model(batch)
    loss = F.cross_entropy(logits, labels)
scaler.scale(loss).backward()
scaler.unscale_(optimizer)
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
scaler.step(optimizer)
scaler.update()
```

`max_norm=1` 只是模板示值，不能替代阈值选择。CPU bfloat16 autocast 可用 `torch.autocast(device_type="cpu", dtype=torch.bfloat16)`，相关硬件/算子支持要核验。旧 `torch.cuda.amp.autocast` 和 `torch.cuda.amp.GradScaler` 已被官方标为弃用；不要继续写入新学习代码。原始未缩放的 NaN 也不能被 scaler 治好。

## 7. 梯度裁剪和归一化能够做什么

按值裁剪各坐标到 $[-c,c]$，可能改变方向；按 L2 范数裁剪 $g\leftarrow g\min(1,c/\|g\|_2)$，有限非零梯度下保持方向。阈值应来自实际梯度尺度和训练效果，源文的 Transformer/RL 固定经验数值不当作标准答案。

```python
import numpy as np

g = np.array([10., 20., 30.])
norm = np.linalg.norm(g)
clipped = g * min(1, 5/norm)
print("原范数、裁剪范数：", norm, np.linalg.norm(clipped))
assert np.isclose(np.linalg.norm(clipped), 5)
assert np.allclose(clipped/clipped[0], g/g[0])
```

若梯度已含 NaN/inf，应定位原因；裁剪不会恢复正确方向。长期大量步骤触发裁剪也可能表示学习率、初始化、数据尺度或模型结构有问题。

LayerNorm 对选定特征轴计算 $\mu,\sigma^2$：

$$
y_i=\gamma_i\frac{x_i-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta_i.
$$

epsilon 在平方根**里面**，不是随意改成 $\sigma+\epsilon$；参数、轴及方差约定由层定义决定。BatchNorm 使用批量/相关空间轴统计并维护训练、评估行为；RMSNorm 用均方根缩放，通常不减均值。它们有助于控制尺度，但可学习 $\gamma,\beta$、极端输入与层间关系仍可能产生大值，不能保证任何网络都不爆炸。初始化也要结合激活和架构，不能把单一分布推荐用于所有 Transformer。

## 8. NaN/Inf 调试：寻找第一次出错的算子

NumPy 中 $0/0,\infty-\infty,0\times\infty$ 通常产生 NaN；`nan == nan` 为假，要用 `isnan`/`isfinite`。不要用 `max` 的结果判断整组无 NaN：它会受值的顺序和比较语义影响。

建议顺序是：输入/标签 → 前向各层范围 → logits → loss → 反向各层梯度 → 参数更新。保存第一个失败批量和更新前参数，缩成可复现的小例子，再判原因。

| 症状 | 需要核实的候选原因 | 怎样区分与修复 |
|---|---|---|
| loss 为 NaN/inf | 非法输入、除零、exp 上溢、log 零、错误索引 | 用有限值检查定位首次异常；改等价稳定公式、修复数据或定义域 |
| loss 突升后参数坏掉 | 步长过大、异常批量、错误梯度 | 查更新前梯度、损失缩放和参数范数；验证梯度，再调整率/裁剪 |
| loss 长期近 $\log C$ | $C$ 类近均匀输出、输入无信息、标签或梯度路径问题 | 不是数值问题的唯一证据；小批量过拟合和检查梯度连接 |
| 层梯度零 | dead ReLU、冻结、未被当前分支使用、损失无依赖、低精度下溢 | 查连接、激活范围、dtype；换精度做对照，再考虑激活或初始化 |
| float32 正常而 float16 失败 | 范围不兼容、低精度敏感算子、下溢 | 查量级、启用合适 AMP/scaling，必要时用 bfloat16 或局部高精度 |
| 验证成绩下降 | 数据划分、评估模式、随机性、模型/训练差异、精度 | 用同输入 float32 对照；不能从下降 1～3% 直接断定 loss scaling 问题 |
| 不同硬件结果略不同 | 并行求和顺序、不同内核、非确定性操作 | 用有根据的容差；确定性模式也不保证跨版本硬件逐位一致 |

调试 NumPy 时可用 `np.errstate(over="raise", invalid="raise", divide="raise")` 将一些警告转异常。在自动微分中，先除零再屏蔽无效输出，反向仍可能走过坏算子；应在计算前对有效元素选取，避免记录无效操作，而不只在结果上蒙 mask。

## 9. 自查与运行验收

1. `[500,501,502]` 的朴素 `math.exp` 在 Python 中是否必溢出？**答案：**不，常见 float64 可表示；float32 会。改用 1000 级别可在 Python `math.exp` 演示溢出。
2. 对 `[5,5,5]`、`[100,1,1]`、`[-1000,-1000]` 计算 LSE。**答案：**$5+\log3$、约 100、$-1000+\log2$；减最大值后与数学式一致。
3. 在 float32 中找最小 $\epsilon$，使它是 1 到下一个更大可表示数的间隔。**答案：**$2^{-23}$，用 `nextafter`/`finfo` 核对，避免把“加后不变”的扰动反称 epsilon。
4. 为中央差分扫 $h=10^{-2},10^{-4},10^{-6},10^{-12},10^{-16}$。**验收：**比较解析导数和绝对/相对误差，解释太大、太小各自的失败，而非只找一个通过数。
5. 把稳定多分类损失梯度故意写成 `p`，遗漏 one-hot。**答案：**检查会失败，且各坐标和约 1 而非 0。能够主动识别这个错误才算验证机制有用。
6. 全部类别 logits 都是 `-inf` 应否给均匀概率？**答案：**不；没有可归一化质量，应处理上游 mask 或显式失败。
7. 所有输入为 5，LayerNorm 的归一化部分是多少？**答案：**均值为 5、方差为 0，分子为 0，正 epsilon 下归一化部分为 0，最终为偏置 $\beta$。
