# 10 · C++20 特性与适用边界

## 1. C++20 的几个核心方向

原书重点介绍四个代表性特性：

1. Concepts
2. Modules
3. Ranges
4. Coroutines

它们分别改善：

- 泛型约束；
- 编译与模块边界；
- 数据处理表达；
- 可暂停/恢复的控制流。

## 2. Concepts

传统模板的问题之一是：模板约束通常隐藏在实例化错误深处，错误信息很长。

Concepts 允许直接声明类型必须满足什么条件。

```cpp
#include <concepts>

template<class T>
concept Addable = requires(T a, T b) {
    { a + b } -> std::convertible_to<T>;
};

template<Addable T>
T add(T a, T b) {
    return a + b;
}
```

## 3. requires

Concept 可使用 requires-expression：

```cpp
template<class T>
concept HasSize = requires(T x) {
    x.size();
};
```

还可约束：

- 表达式存在；
- 返回类型；
- noexcept；
- 类型成员；
- 多个逻辑条件。

## 4. Concepts 与 SFINAE

过去：

```cpp
std::enable_if_t<condition, int>
```

或复杂 decltype/SFINAE 常用于控制模板参与重载。

Concepts 的优势：

- 语义直接；
- 错误消息更明确；
- 可复用；
- 更接近接口契约。

SFINAE 仍存在，但新代码若标准版本允许，concepts 往往更适合表达明确约束。

## 5. Modules

传统头文件机制的问题：

- 重复解析；
- include 顺序依赖；
- 宏污染；
- 大型工程编译慢；
- 接口边界不够明确。

C++20 module interface 示意：

```cpp
export module math;

export int add(int a, int b) {
    return a + b;
}
```

使用方：

```cpp
import math;
```

Modules 不是简单的“更快 include”，而是新的语言级编译单元和可见性模型。

## 6. Modules 的现实工程问题

模块支持依赖具体：

- compiler；
- standard library；
- build system；
- BMI/PCM/IFC 等编译产物机制。

因此 module 的构建方式不能假设为单个普通 `clang++ file.cpp` 命令，需要遵循当前工具链文档。

## 7. Ranges

传统 STL 算法常需要 begin/end：

```cpp
std::sort(v.begin(), v.end());
```

Ranges 把范围本身提升为一级抽象，并提供 view pipeline。

```cpp
auto result =
    values
    | std::views::filter([](int x) { return x % 2 == 0; })
    | std::views::transform([](int x) { return x * x; });
```

## 8. Views

View 是满足特定复杂度要求的范围类型；常见 filter/transform 视图轻量、惰性且可组合。很多 view 非拥有，但“view 必然不拥有数据”不成立，例如有 owning_view；必须按具体类型判断所有权。

因此多个 filter/transform 不一定创建中间 vector。

这种模式很适合：

- 数据流处理；
- 大集合过滤；
- composable algorithms。

## 9. Range 生命周期

因为 view 往往不拥有数据，要特别关注：

- source range 是否仍然存在；
- 临时 range 是否会导致 dangling；
- adaptor 捕获对象的生命周期。

这与 string_view 的生命周期问题有相似性。

## 10. Coroutines

Coroutine 是可暂停和恢复的函数。

函数体中出现以下关键字之一，就进入 coroutine 语义：

- `co_await`
- `co_yield`
- `co_return`

## 11. Coroutine 的用途

常见：

- generator；
- async I/O；
- event loop；
- cooperative task；
- lazy sequence。

## 12. C++20 Coroutine 是低层机制

C++20 提供：

- 语言关键字；
- `<coroutine>`；
- coroutine handle；
- promise protocol。

但没有直接提供通用高级 task/generator 运行时。

例如 generator 需要定义：

- `promise_type`
- `initial_suspend`
- `final_suspend`
- `yield_value`
- coroutine handle 生命周期。

更高层封装通常由库提供；`std::generator` 属于 C++23，实际可用性依标准库实现。本章 C++20 基线不能直接假定可用。

## 13. Contracts 不是 C++20

Contracts 曾进入 C++20 工作草案，但最终在标准发布前移除。  
因此不能把 Contracts 当作 C++20 正式特性。

原书指出其后续继续作为未来标准方向推进。

## 14. Transactional Memory 不是 C++20

Transactional Memory 只存在于 Technical Specification 等标准化实验阶段，并未成为 C++20 正式标准内容。

## 15. C++20 学习优先级

### 高频工程价值
- concepts
- ranges

### 视项目工具链
- modules

### 特定架构价值
- coroutines

学习时不必为“使用新特性”而使用，应从实际问题出发。

## 核心结论

C++20 的重要变化不是小语法糖，而是把 C++ 推向：

- **更可约束的泛型**
- **更明确的模块边界**
- **更组合化的数据处理**
- **更底层可定制的异步控制流**

## 小实验：惰性过滤和变换

```cpp
#include <iostream>
#include <ranges>
#include <vector>
int main() {
    const std::vector<int> values{1, 2, 3, 4};
    auto squares = values
        | std::views::filter([](int x) { return x % 2 == 0; })
        | std::views::transform([](int x) { return x * x; });
    for (int x : squares) std::cout << x << ' ';
    std::cout << '\n';
}
```

C++20 输出 `4 16`（末尾有空格）。这里 values 在视图遍历期间一直有效；构造视图没有立即生成一份 vector。修改底层数据可能影响后续结果，甚至使迭代器失效，因此不要把惰性 view 当数据快照。

自测：使用 `co_await` 就自动开线程吗？答：不会。协程描述挂起/恢复，调度到哪个线程、I/O 如何完成和取消如何处理，由 awaiter 与运行时负责。

本章固定解释 C++20 已有特性；Contracts 等后续标准进度需另查，不能把工作草案内容悄悄当作 C++20 保证。
